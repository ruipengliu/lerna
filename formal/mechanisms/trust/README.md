# 信任、来源与记忆机制验证

本组盘点身份授权、记忆系统和内容来源治理。验证的是形式模型中的规则；没有将真实身份认证、磁盘耐久、强制网络隔离或物理删除列为已证明。完整范围与每个验收行的余项见 [inventory.json](inventory.json)。

库存包含 32 类机制、IA-01～26、MS-01～33 共 59 条原编号验收，以及内容专题 6 条无编号验收（本库存命名 CP-LOCAL-01～06）。首列有中文后缀的追加用例也保留原文及行号。每条区分有限抽象覆盖、尚未形式化的规则、现实运行依赖，完整运行用例通过数为 0。

可达性见证通过刻意否定某个应可达状态取得反例，显示正常发布/删除/提取、拒绝旧缓存/派生使用、来源缺失拒绝、撤权后接收历史事实等路径确实存在。它们不证明所有调度终会成功。本组没有活性命题或公平调度假设；因此也没有关于恢复、清理或提取必然完成的结论。

## Lean 的一般参数证明

[Trust.lean](Trust.lean) 使用 Lean 4.19.0 随附 Std，不依赖 Mathlib。它是与 TLC 人工对照的独立形式化，不是机器证明的跨语言精化。

- `scope_reachable_attenuates`：权限类型任意，任意有限级收缩委派后范围仍不超根范围。
- `gate_reachable_safe`：任意有限合法历史中的已记录使用，在提交当时具有正确主体标志、许可、未撤销/未关闭状态和相同权威版本。历史事件固定当时依据，不因后来撤销而篡改过去事实。
- `revoked_cannot_add_use`、`closed_cannot_add_use`、`stale_cache_cannot_add_use`：相应失效情况下，消费步骤不会新增事件。
- `late_fact_without_new_use_witness`：撤销后能保存历史事实，同时新消费被阻止。
- `closed_dependency_blocks`：闭包中任一依赖关闭，则“全部依赖可用”不成立。这是逻辑辅助引理，不证明真实输入闭包提取正确。

最终 [Lean 输出](evidence/trust-proof.log) 无错误、无警告、无 `sorryAx` 或本机求值公理；打印的依赖仅有 `propext`、`Quot.sound`，部分命题无公理依赖。开发时的解析/证明投影错误保存在 lean-first/second.log，修正后独立编译通过，不是架构反例。

[TrustRules.lean](TrustRules.lean) 另验证三类纯规则。恢复白名单不能授予资源行动、正文读取、委派、确认或其他命令查询；接纳还要求当前绑定、宿主身份、获准子集及新鲜度。离线规则证明：若真实时间确实落在受信区间 `[L,U]` 内，允许使用意味着区间内每个时间均满足开始边界及许可/来源/任务的最早截止；缺时间锚、防回滚依据或预算即不允许。确认规则对任意完整绑定类型和任意有限重试历史归纳：绑定不变、最多签发一次，不同绑定、已消费或拒绝不新签发；正常确认、离线使用和恢复查询均有具体见证。

这些规则不证明 Bool 前提真实、完整绑定编码无遗漏或数据库原子性。[规则编译输出](evidence/trust-rules.log) 无错误、警告或 `sorryAx`；依赖仅为 Lean 标准逻辑公理 `propext`、`Classical.choice`、`Quot.sound`，部分定理无公理依赖。

## 模型边界

授权模型把用户、actor、processor 表示为四种已认证上下文类别；这些类别的建立是现实前提。权限用三个原子权利、单一根与一个子许可表示，操作取两个标识。它没有验证密码、资源规范化、任意参数约束、完整许可链及跨条目组合，也没有把查询历史回执当成外部启动资格。当前门禁中的源版本/撤权/离散到期代表使用权威当前观察；不宣称远端物理启动与撤销零延迟原子发生。拒绝与 indeterminate 的完整错误语义另列余项。

恢复模型只有一个记录、两个快照页、至多两个恢复轮次及两个 owner。版本 1 的变化可不改变可见内容，版本 2 删除记录，因此空过滤区间也须推进连续覆盖。Page 动作代表已经核验属于当前快照的真实页；真实摘要/清单验证、旧快照页身份和日志保留未被证明。增量页先独立排队，再核对轮次、owner 和前序位置；缺口变体能绕过该检查并被发现。ready 仅表示本轮数据已安装，不等于未来持续获准。

来源模型只有两个来源和两个受管产物，其中一个依赖两个来源。登记与关闭在来源权威的原子步骤内裁决，当前来源使用检查与物理清理独立。平台回执作为可信输入：`cleaned ⊆ platformAck` 只证明模型没有无证报告完成，不证明平台真的删除了磁盘。保留用布尔记录表示，没有期限计算、部分跨源登记或备份过期算法。

命令模型固定两个操作、单个记忆及有限修订，保存状态/结果是原子抽象；没有故障注入数据库或多库提交。来源模型固定的四个源 token 展开真实输入闭包，不实现一般 DAG 的循环/容量检测。提取模型固定一个任务、一份独立额度；不覆盖复杂的策略版本键、提交未知和多项候选取消。

检索模型固定两个记录和“创建 1、创建 2、删除 1”三次权威变更，查询匹配所有记录；索引和尾部扫描异步推进，当前权限可以独立关闭。complete 仅证明此有限匹配集合的覆盖，不证明文本/语义召回、排序或一般更新序列。提前停止扫描标 partial，用一次 Publish 作为本地数据出口复核原子边界；跨权威证明的有限时效继续是运行前提。日志模型固定四类消费者、三次变化及一次重建，不含实体索引/页内容；新查询/重建登记保留点与开始读取同属原子抽象，回收不得越过有效消费者最小位置。真实崩溃恢复、代次交换和旧读者释放仍未整体建模。

多个模型分别验证不同规则；把它们都映射到一个验收行，不代表其组合已经验证。显式未形式化的项目仍包括本人管理目录、全文排序/冲突组、通用协议编码、负载公平、旧备份关闭尾部、跨权威和跨模型组合等。可信确认、恢复引导、离线条件和索引日志规则已有抽象证明；真实 presence、签名、时间锚、防回滚和磁盘回收仍需运行验证。运行依赖和可进一步建模的规则在库存中分开列出。

## 复跑

工具与已固定的 [交接验证包](../../handoff/README.md) 相同：TLC 2.19 / TLA+ v1.7.4，Lean 4.19.0。每项配置路径、预期退出码、预期诊断由 checks.json 定义。TLC 使用完整广度优先探索，1 worker、seed 1、fp 0；没有 CONSTRAINT、ACTION_CONSTRAINT、对称约简或随机模拟。关闭一般死锁报警只允许有限实例停留，不被解读为完成保证。正式统一复跑应为每个 Java 进程设置独立 java.io.tmpdir 和 metadir。

源文档与模型均有哈希；调用权限、硬件、数据库、来源提供方、UI、平台清理和真实互操作仍须按原模块验收矩阵运行。
