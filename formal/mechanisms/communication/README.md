# 通信规则与跨机制组合验证

本组扩展既有 [持久交接样板](../../handoff/README.md)，检查连续流、过期清理、用户配额、保留份额及多域资格组合。原始规则、12 条 EC 验收用例和未覆盖细项见 [inventory.json](inventory.json)。完整 EC 运行用例没有执行；模型输入中的认证、持久事实和门禁执行能力仍是前提。

## 模型与实际检查

| 模型 | 参数和检查范围 | 特意错误变体 |
| --- | --- | --- |
| [Stream](Stream.tla) | 单流，安全配置 3 个序号；乱序接收、连续持久前缀与业务交接、目标 ACK、超窗持久缺口、两端载荷清理、恢复回退停止续传 | 以最大已见序号冒充前缀；中继回执冒充目标证明；丢弃未交接载荷；用较旧恢复位置覆盖已知 ACK |
| [Composition](Composition.tla) | 一项行动依赖授权、控制、owner、来源、运行版本五个独立域；准备快照与实际发放分开；每域一次失效；效果与已知事实分开 | 仅信旧快照；失效不递增版本；未知效果自动重发 |
| [Scheduling](Scheduling.tla) | 两用户、两连接、六个固定工作；每用户 ordinary、cleanup、control 各一个保留份额；已接纳责任不淘汰 | 按连接独立计算用户额度；为新工作腾空间而丢弃旧责任 |

全包最终统一复跑见 [最终清单](../evidence/final/manifest.json)，保存实际执行的命令、退出码、日志哈希及统计。`communication-initial`、`communication-complete`、`communication-final` 和 `checked` 目录保留开发与交叉审查前的历史快照，不能作为最终源码的运行证据。错误变体及可达性见证预期退出 12，基准与 Lean 预期退出 0；不能把“符合预期”读成错误模型也满足安全性。

`Stream` 的健康活性配置只启用无丢包、无窗口耗尽、无恢复回退的动作，并对每条消息的接纳、发送、接收、交接及前缀推进使用弱公平性；检查所有固定消息最终交给业务。一般故障配置只检查安全性。`Scheduling` 对每项工作服务动作使用弱公平性后，检查已接纳项最终完成；没有证明实际调度器具备该公平性。`Composition` 不包含活性命题。

正向见证包括流全部交接、窗口缺口、正常行动完成、域失效后仍能记录迟到效果，以及普通工作占满时收尾和另一用户仍能推进。见证只说明存在一条这样的路径。

## Lean 一般参数结论

[TransportProofs.lean](TransportProofs.lean) 仅导入 `Std`，含两个独立归纳模型：

- `TransportPrefix` 对任意自然数序号和任意有限合法历史，证明目标连续前缀中每项均持久存在，ACK 和业务交接不越过该前缀。它是 `Stream` 的前缀核心投影，未在 Lean 中证明窗口、载荷清理和网络配置。
- `AdmissionVector` 对任意可判等的域类型、无界自然数版本和任意有限历史，证明每次发放记录在当时都满足所有依赖域资格。失效会单独递增该域版本；发放仅比较准备时向量与当前向量，证明通过辅助不变量推出实际资格，未直接把“所有历史都安全”作为发放守卫。它不覆盖 `Composition` 的效果、结算或完成分支。

[ProtocolRules.lean](ProtocolRules.lean) 检查已安装扩展判定、请求／响应双方及路径能力、必需输入降级和通用 bind-once 原语：已知可选项的数据仍须合法，声明 required 不可降级，未知必要项拒绝，最终目标能力不可由网关替代，必需输入不能降成纯文字。同一完整绑定的重投返回原绑定，不同绑定拒绝。这些是纯规则证明；输入布尔值代表的真实认证、支持能力、数据合法性和完整业务绑定须由实现提供。

Lean 4.19.0 的实际编译和 `#print axioms` 结果在清单对应日志中。前缀定理依赖 `propext`、`Classical.choice`、`Quot.sound`；向量定理依赖 `propext`、`Quot.sound`；协议规则为 `propext` 或无公理依赖。均为标准逻辑依赖，最终没有 `sorryAx`、自定义公理或原生求值证明。开发第一轮遇到字段关键字和归纳分支绑定语法错误，失败输出保留在 evidence 下；修正没有改变命题或模型前提。

## 关联和剩余边界

Stream 的接收记录与业务交接记录均为持久事实；重启不回滚它们，网络丢失另有动作。历史去重记录在此有限实例中不回收。ACK 只有目标证明生成，错误中继仅用于负面对照；真实来源认证未被证明。`ReportRollback` 只检查发现旧位置时保留当前位置并关闭续传，没有建模修复后如何取得足够依据重新开门。

Composition 的五域向量是**已经应用到同一资源接纳权威的本地证据与屏障**。远端 `AuthorityInvalidate` 与本地 `ApplyInvalidation` 分为两步；传播窗口见证允许远端已撤销、本地尚未收到时仍发放。安全结论要求本地屏障应用与本地接纳串行化，没有证明分布式最新快照或远端撤回零延迟生效。传播截止、有限离线窗口和实际物理执行切点须由具体领域及平台证据限定。已发放效果可在屏障后发生，迟到事实仍接收；`completed` 仅表示此抽象调用的收尾，不是完整任务终态证明。

Scheduling 的独立份额是参考配置抽象；实际 work 收尾仍属于既有 work lane，本模型中的 `cleanup` 是内部保留类别，没有新增线 lane。模型直接假设逐工作服务的弱公平性，没有实现调度选择算法；有条件排空结论不能用来证明调度器本身公平。字节预算、TCP 抢占、真实恢复批次性能及吞吐没有运行证据。

所有模型分别检查特定规则。Lean 与 TLC 由人工对照，没有跨语言精化证明，也没有将各子模型自动合成为完整协议栈。证据分类和每条用例的其余义务保留在库存中。
