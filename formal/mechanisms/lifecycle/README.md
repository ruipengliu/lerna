# 扩展生命周期、交互和评测的形式验证

本包把三个方案模块的 29 个机制族及验证文档的 99 行要求逐一列入 [inventory.json](inventory.json)，并执行了 6 个 TLA+ 模型、2 份 Lean 证明，共 39 项检查。全部检查符合各自预期：7 项正向检查、15 项实现规则变异反例、14 项可达见证、1 项去除公平性后的活性反例、2 项 Lean 编译。

“符合预期”包括负例确实失败，不能读作 99 项产品验收已经通过。清单中 90 行含已验证的抽象子性质，7 行需要运行验证，2 行只核对明确后置或未采用的政策。每行分别列出已验证抽象规则、未建模规则和真实实现依赖。跨组性质复用也只覆盖所列子义务，不证明该模块的实现已经符合共享模型。

## 模型与契约对应

| --- | --- | --- |
| [References.tla](References.tla) | 读取门禁→决定→登记引用；独立领域使用→终态证据→完成→释放；关闭新引用→排空→保存回收计划→删除；计划后崩溃续做 | 2 个引用、1 个版本、一次关闭。关闭新引用仍允许已登记引用启动后继工作；安全停用才禁止新执行。已在途执行可继续接收终态证据。完整持有者发现、实际进程隔离和磁盘删除由实现提供。依据：扩展 contracts.md:120–124 |
| [UI.tla](UI.tla) | 显式开闭意图代次、单个待决请求、迟到响应、会话切换、完整快照/精确基准增量、内容冲突、关闭与正式结果独立 | 2 次意图修订、2 个内容版本。恢复见证记录崩溃时待决的原代次，再由同代次响应恢复显示。Reply 抽象为带当前可用依据的响应；没有模拟独立服务端 presentation 的全部变化、CAS、查询回执过期和 ui.get。依据：interaction-contract.md:71–107 |
| [Input.tla](Input.tla) | 持久接纳→父子映射→首次转交→权威消费→原操作核对；两个竞争输入、两个请求意义版本、进度修订与请求意义分离、迟到 accepted 不回退 applied | 采用允许“接纳后、首次转交前固定映射”的替代实现；每个请求身份最多一个消费者。映射未存不能发送。完整 Schema、任意多用户唯一索引和回执保留窗口未建模。依据：interaction-contract.md:32–64，validation.md:UI-31 |

| [Rollback.tla](Rollback.tla) | 停用与旧版恢复分离；读取依据→决定→提交期间旧版撤回/格式不兼容/未知责任；受阻后另存“仅停用”选择；历史事实不回退 | 以布尔输入代表真实兼容性和可信性。证明这些条件及修订必须当前有效，不证明旧代码真的能读当前账本；真实 C9 回退仍须运行。依据：improvement.md:76–88，extensions installation-and-isolation.md:64–85 |

每个模型保留不同提交或事件之间的交错，负例通过移除具体检查制造错误。使用前登记、当前修订校验和零持有者回收分别在所属提交边界判断；动作守卫没有直接引用 `UseHasPin`、`ExactFreshQualification` 等待证全局不变量。

## 条件活性和证据边界

`refs-live` 检查最终回收，前提是宿主最终持续可用、管理/收尾动作弱公平，且每项在途使用最终能提供真实终态证据（模型中的 `RecordDone` 事件）。未知责任没有终态证据时不能据此释放。该前提不来自模型检查器：现实中的永久未知、失联、长期持有引用都可能使回收保持阻塞。`refs-unfair` 移除这些进展前提后，TLC 找到无限停留的预期反例。

其他模型主要检查安全和非空可达路径，不主张一般性最终成功。Preview 的关闭见证只是“完整旧载荷存在，但来源已关闭且未转交”的可达状态；Input 的恢复见证只表示发生过崩溃后按原操作读到消费事实；Rollback 的恢复见证表示崩溃后重新取得有效依据并恢复旧版。没有用这些更弱见证声称具体丢回复顺序已证明。

`Evaluation` 中目标到期是一个独立外部事件；真实时间可信、离线窗口长度与反回滚时钟算法未建模。独立证据事件的真实性、原始存储与事务正确性、持有者集合完整性、身份/凭据认证、实际沙箱与故障隔离、文件清理和性能均是模型到实现映射时必须核验的条件。

## Lean 一般参数证明

[References.lean](References.lean) 对任意可判等的引用标识类型、任意自然数管理修订和任意有限可达执行，证明运行中引用有保留资格、回收后无持有者、已发生使用历史单调保留。`read`、`decide`、`register` 独立；`recordDone` 与 `finish` 独立；崩溃不删除持有资格。Lean 以每引用布尔谓词表达 TLA+ 中的有限集合和阶段，保守允许更多重复登记事件；二者对应关系已人工核对，尚未证明两份源文件之间的自动精化关系。

[EvaluationRules.lean](EvaluationRules.lean) 对任意样本数和预算证明：必需条件组仅在全部 pass 时为 pass；unknown 留在列表长度中但不增加成功数；成功数不超分母；run 的计划版本和派发预算守恒；原评分不可被重复或冲突结果覆盖；关闭后不重新派发，报告可与迟到费用结算并存。冻结样本索引由 `Fin n` 总函数表示，因此保留分母是该状态表示的结构约束。该证明不包含完整统计方法、保留集独立性、费用真实性或发布门槛算法；空条件组的逻辑合并也不单独构成发布资格。

两份源文件只导入 Std，没有 `sorry`、`admit`、自定义公理或 `native_decide`。编译日志逐项打印依赖，仅出现 Lean 的 `propext`、`Quot.sound` 或空依赖。证明保证的是所写抽象转换；实际数据库、客户端、扩展宿主和评测服务的精化对应尚未建立。

变异包括旧门禁登记、仍运行即释放引用、旧 UI 响应重新显示、错误基准增量、撤回前读到的旧资格提交、候选版本不匹配、目标端忽略撤回/到期门禁、未存父子映射即发送、第二消费者、旧意义输入、停用冒充恢复、回退旧事实、缺必需预览和旧预览。负例均要求 TLC 返回 12 并出现指定不变量名；无公平性活性反例要求 13。可达见证同样使用反向不变量，以预期反例证明路径存在，不能计作发现架构缺陷。

[checks.json](checks.json) 是统一复跑器的输入；[evidence/initial-run.json](evidence/initial-run.json) 保存此次每项完整命令、退出码、检查标记、耗时、版本和源文件 SHA-256；[evidence](evidence/) 保存未经裁剪的全部原始输出。工具来源、发布资产和摘要见 [toolchain-provenance.json](evidence/toolchain-provenance.json)。TLC 固定 seed 1、指纹函数 0、1 worker，并为每次执行隔离 Java 临时目录和 TLC 状态目录。

从仓库根目录运行：

```sh
python3 formal/mechanisms/lifecycle/run_local.py
```

本机工具路径固定在用户缓存中，没有修改全局 PATH：TLC v1.7.4（工具横幅 TLC2 2.19）、Lean 4.19.0、Homebrew OpenJDK 25.0.2。统一复跑器可替换工具路径，但应保存实际版本、命令、摘要、完整日志和全部负例预期。

清单再生成依次运行 `build_inventory.py`、`enrich_inventory.py`。第二步合并共享抽象义务，并保留所有未建模细项；不得只运行第一步后把 pending 草稿当作交付结果。
