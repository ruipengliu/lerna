## Agent Brief

**Category:** enhancement

**Summary:** 在有限任务运行之上实现持久化暂停、取消和明确恢复，分别表达控制接纳与实际落实，阻止新目标工作并依据在途事实完成收尾。

**Current behavior:**
前置 04 已完成脚本 Brain、Worker 领取与续租、原子完成、有限预算、当前执行授权和真实 SQLite 进程恢复。按控制意图、暂停、取消、恢复、终态与在途处置概念检查 TaskService、WorkPort、Runner、SDK、Protobuf 和验证 profile：当前仅有运行失败停止与 context 超时/中断，没有用户控制请求、控制操作回执、持久化控制意图或落实进展。Task 仅有单一 StopReason，不能同时保留暂停和其他等待条件；既有 Worker 提交依赖原任务版本，控制变更后的在途结果需要独立的受控核对路径。未发现相关历史拒绝记录。维护者已确认 enhancement 分类、保持 ready-for-agent 和下述边界。

**Desired behavior:**
有权主体可以通过任务接口提交 PAUSE、CANCEL 或明确恢复为 RUN 的控制操作。主状态、控制意图、控制进展分别保存；暂停不新增 PAUSED 主状态，RECONCILIATION 是等待原因而非成功或失败终态。控制回执描述原操作是否被接纳，查询描述当前落实进展，不能把消息发送、请求持久化或 context 取消等同已停止。

首次控制接纳以稳定 operation_id、目标任务及预期版本为前提，按当前控制权限和主体范围判定。控制意图、任务版本、控制记录、必要处置工作与回执在同一运行持久化单元提交；身份冲突、版本冲突、权限拒绝和结果未知分别表达。原操作重发优先核对原语义并返回原回执，当前权限仍约束披露；操作身份与任务提交、授权管理等既有操作共用占用规则，不允许跨类型或跨目标重新解释。

PAUSE/CANCEL 接纳后立即阻止新目标工作，持久化意图约束领取、重领、决策启动与提案准入。已开始工作按实际能力请求停止并核对；旧 Worker 不能以过期版本或领取资格推进状态，但带来源的迟到事实仍可登记，由当前 Owner 核对后决定如何更新。用于停止和核对的有限处置工作须与目标工作区分，不能借收尾继续规划或绕过授权。

暂停落实后保持 WAITING 和 PAUSE；仍有在途工作时可保持 RUNNING，效果未知时保留 RECONCILIATION。取消仅在必要工作已停止或完成处置、关键效果已核对后进入 CANCELLED。先赢得提交的正式完成结果保持 COMPLETED；取消已受理但随后证据证明既有工作在取消生效前已完成时，应保留实际完成事实并表达取消未能阻止完成。脚本 Brain 的未准入提案不等同已确认外部完成，不凭迟到输出直接绕过控制和版本校验。

恢复是另一次有权操作，只解除暂停意图。重新核对当前授权、任务期限、剩余额度、其他等待条件和在途处置情况；不得清空无关等待原因、退还已用/不确定额度、撤销已接纳取消或重开终态。旧控制回执保持其历史含义，后续恢复或取消不能改写旧操作已经被接纳的事实；尚未落实就被后续控制取代的情况须可解释。

重启沿用原任务、控制意图、处置工作和操作身份。未知提交核对原身份；未知工作效果继续等待证据。进程退出、租约失效或处置超时本身不足以证明外部工作停止。本票以真实脚本 Worker 和可控在途工作夹具验证契约，不发起真实外部副作用。

**Key interfaces:**
- TaskService 控制入口与操作查询：支持暂停、取消、明确恢复，包含稳定操作身份、任务引用、预期版本及有界原因；返回控制接纳回执，提供当前控制进展查询。恢复与取消分别授权，不能从普通任务文本推断控制许可。
- Task 快照与控制记录：分别表达主状态、RUN/PAUSE/CANCEL、接纳与落实进展、可并存的等待原因和必要核对引用；明确原操作回执与当前任务状态的区别。
- RunStore / WorkPort：控制接纳和受约束推进共用原子边界，校验 Owner、epoch、状态版本与适用领取代次。控制变更使旧提案失效；仅核对既有工作事实的入口不能成为任意写终态的后门。
- Runner 与在途工作处置接口：接收持久控制变化，停止新目标调用，对已开始工作提供有限停止请求及状态/事实核对；消费方接口不依赖具体模型、驱动或数据库。通知仅用于加快响应，持久控制状态仍是权威。
- 时间、容量与处置配置：显式限制控制记录、轮询/通知、停止等待、核对次数、调用时限及处置额度；目标预算耗尽不禁止控制和必要核对，处置限额耗尽也不伪造终态。
- SDK、Protobuf 与验证 profile：读取控制意图、接纳与落实状态、并存等待原因及 CANCELLED；保持既有操作去重、当前读取权限、数据兼容和有界消息约束。

**Acceptance criteria:**
- [x] 经 SDK 完成领取前暂停、领取前取消与明确恢复：控制意图、接纳回执、落实进展和任务主状态可分别查询；无在途工作的取消可落实为 CANCELLED，暂停落实为 WAITING/PAUSE。
