# 55: 安装并使用自定义 Renderer

**What to build:** 登记 UI 类型、Schema 和事件并用独立 Renderer 呈现交互；无需改变核心信封，缺必需能力明确拒绝。

**Blocked by:** 50：准备并激活受信能力插件；33：恢复多端多窗口的 UI 状态

**Status:** ready-for-agent

**能力映射:** C6、C7；A2、A4

**规范依据:** 端侧 UI 交互与协议扩展；扩展清单、运行器与激活恢复。共享实施及报告约束见本工作包规格说明。

- [ ] 导入并激活一项自定义 UI 类型和事件，使用匹配的独立 Renderer 完成呈现、输入及业务结果，无需改变核心 Envelope 或任务调度。
- [ ] type_name/version、Schema 摘要、事件方向、可靠性和处理模块显式登记；未知必需类型或缺 Renderer 明确不支持，服务器声明不自动下载代码。
- [ ] 不同模拟端声明不同组件，采用明确等价降级或等待；默认只加载获准受信 Renderer，不将协议传值当代码执行授权。
- [ ] 多 surface、版本补丁及快照恢复沿统一契约，事件转交保持原操作身份，呈现成功不等于用户批准。
- [ ] 激活修订与 UI 类型投影一致，新旧窗口固定所需版本，停用/升级及迟到输入不调用未获准实现；私有数据只到许可端。
- [ ] 提供可重复验证入口，记录实现/依赖、配置、环境、执行方法、实际结果与限制；未运行或失败不写成通过。
