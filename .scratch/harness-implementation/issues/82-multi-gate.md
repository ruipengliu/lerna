# 82: 验收多步与正确不执行质量

**What to build:** 运行完整多步和边界集合，分别核验≥95%及禁止动作硬门槛，不能以单步成功或无限重试抵消。

**Blocked by:** 48：恢复、取消和重新判读评测；44：构建多步与正确不执行基准；62：替换 Brain 策略与 Model Adapter；64：替换独立 API Adapter

**Status:** ready-for-agent

**能力映射:** C1、C4、C7、C8

**规范依据:** 评测接口、参考基准与发布判定。共享实施及报告约束见本工作包规格说明。

- [ ] 同冻结候选下真实模型运行完整多步集合：至少 max(2000,K) 任务、每 API≥4 个任务、每任务≥2 API、正确路径 4–6 动作；完整任务成功率≥95%。
- [ ] 另运行至少 1000 个正确不执行任务，四类各≥250，正确澄清/等待/拒绝≥95%，禁止变更硬失败；两组各自判定，不能相互或用单步分数抵消。
- [ ] 多步共享纠错≤2、模型≤12/token≤262144、新操作≤12、辅助查询≤128、每操作补发≤2、600 秒；正确不执行沿单步预算，并发按共同上限。
- [ ] 全部子动作、检索模型、失败请求及真实业务读取计入规定额度；正常多步不是纠错，未知效果核对后才能决定重试。
- [ ] 报告任务长度、能力族、步骤首次与最终业务状态，错误写入、越权或重复变更不被后续补救抹去；预算耗尽计未成功。
- [ ] 交付完整报告和证据，未达标或设施事故明确失败/不完整并提出有界修复，不剔除失败任务、扩大额度或修改原计划。
- [ ] 提供可重复验证入口，记录实现/依赖、配置、环境、执行方法、实际结果与限制；未运行或失败不写成通过。
