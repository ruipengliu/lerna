# 87: 验证候选的实际改善和回滚

**What to build:** 同条件基线及独立保留集证明主指标改善，满足保护门槛；验证产物兼容、阶段监测、退出与回滚，区分模拟时间证据。

**Blocked by:** 81：验收完整目录的单步 API 质量；82：验收多步与正确不执行质量；83：验收联网问答专项质量；84：验收 GUI 两种观察模式质量；85：验收个性化效果与隐私出口；86：汇总运行恢复与治理完整证据

**Status:** ready-for-agent

**能力映射:** C9、C8、C6、C7；A2、A4

**规范依据:** 评测接口、参考基准与发布判定；能力里程碑与实施依赖。共享实施及报告约束见本工作包规格说明。

- [ ] 对冻结的精确候选和同条件基线取得独立保留确认，所有适用完整 API/专项/契约硬门槛均通过；已有报告必须匹配候选、计划、环境和评分条件。
- [ ] 主单步首次正确率配对差值 95% 区间下界>0且统计适用性已验证；单步/多步成功点分不降，平均 token 与 p95 延迟≤基线110%并满足全部硬预算。
- [ ] 候选来源和保留材料独立，记录最多五候选筛选与反馈历史；推断不可用、证据缺失或未改善保持未通过，不降低门槛或改主指标。
- [ ] 在声明兼容组件中实际使用该改进产物，验证阶段激活、权限边界、监测、故障停止及兼容回滚，保留真实新旧版本及运行效果。
- [ ] 按已确认样本/时间窗口提供实际取得的监测范围；模拟时钟仅证明阶段边界，不能声称已观察真实生产周期；无生产流量不伪造生产效果。
- [ ] 代码类候选保留维护者对精确产物的确认；交付实际改善及回滚证据后才记录 C9 适用成熟度，流程可执行不能替代改善。
- [ ] 提供可重复验证入口，记录实现/依赖、配置、环境、执行方法、实际结果与限制；未运行或失败不写成通过。
