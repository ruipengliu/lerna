## Agent Brief

**Category:** enhancement

**Summary:** 在既有同步执行保障上交付可持久恢复的异步调用、独立取消操作及可信证据核对闭环；句柄丢失、冲突证据和预算耗尽保持明确的不确定性。

**Current behavior:**

CapabilityService 提供 Invoke/GetInvocation/Reconcile；受信 Run 在原子启动登记及单次许可消费之后调用 Driver，Inspect 查询独立目标，报告经 Outbox 交给 Core。稳定操作、任务版本/控制隔离、未知不重发、单机资源串行准入、当前读取授权及有限 I/O 已存在。

当前能力仅同步，执行记录缺少外部作业关联、持久轮询调度和独立取消进展；没有 IN_PROGRESS 与可信进度合并，也没有冲突终局证据保留及后续核对。已有目标用原操作查询，不覆盖只有随机句柄且句柄随响应丢失的接口形态。

**Desired behavior:**

沿用共同执行协调、授权、受控内容和 Core 分工，依赖消费方 Interface；实现细节留在 Adapter。扩展固定能力声明，明确异步、查询、取消、关联恢复及幂等保障的支持范围与限制；原调用固定能力/实现/Schema、目标、语义和权限绑定，不随重启或当前目录版本改变。

Start 可以报告已知未开始、运行中或完成的事实，异步返回关联包含目标身份、原操作及必要的有界不透明句柄。关联与后续恢复工作先持久化，再安排 Inspect；提交失败或未知先核对原提交。句柄是目标定位数据，不是执行授权，不新增通用业务身份。句柄如含敏感数据或凭证性质，按受控保留和使用约束处理，不原样进入公共快照、日志或 Outbox。

提供可重开的有界恢复运行入口，保存原操作、下次可运行条件、已用尝试与工作资格。候选枚举不等于获得执行资格；多个协调实例竞争、租约变化和重启不能重复取得同一恢复工作或重置预算。Inspect 不 Start；运行中的外部作业不能因本地 RPC 返回、进程槽位释放或租约过期而被视为已停止。

有可信原幂等键/业务关联时可以找回丢失句柄；只有随机句柄且无恢复关联时保持 UNKNOWN。查无记录仅在覆盖范围充分且旧请求不可能再生效时形成 NOT_OCCURRED 证据，必须能从模拟目标事实独立验证。幂等保障的作用域、有效期及查询依据固定；键过期或历史被目标清理不授予新的业务动作。本票无需自动重新 Start，默认对可能已发送的操作只核对，不退款、不换身份补做。

CapabilityService.RequestCancel 使用自己的稳定操作身份，引用原调用，固定取消语义与授权，持久保存原回执、控制意图和待处理工作。相同请求重放不重复建立取消工作，异载荷/异目标及跨类型身份复用拒绝。取消接纳与尚未启动动作的登记在同一适用本地边界排序；取消先接纳时阻止该动作首次启动，在途动作交由 Driver.Cancel 或核对。Cancel 外部调用前保存可能发送事实，其提交/回包未知先查原取消与目标状态，不隐式重复取消请求或重做 Start。目标不支持取消时明确报告限制并继续有限核对。

连接 Task 的持久取消处置：已受理 CANCEL 阻止新业务工作，在途调用获得稳定且可恢复的取消交接；重启不能反复创建取消身份或清除控制意图。任务控制与调用取消保持不同操作，直接取消一个调用不自动取消整个任务。暂停、更新和期限变化沿既有控制/旧版本隔离规则处理，不伪造整个外部作业已停止。取消已受理、请求已交付、实际停止、实际效果和 Core 已消费分别可查询，只有可信停止/完成处置证据才解除对应占用。

执行阶段、结果、效果、取消进展及证据可信性分别表达。可信进度入口验证实际来源与原目标/操作/实现关联，使用来源内版本或可核对事实合并，不把不同来源的序号拼成全局顺序。重复事件幂等，旧进度不能覆盖完成，无权或错误关联不能污染记录。两份矛盾终局证据均保留来源和有界受控证据，进入明确的核对状态；不凭最后到达覆盖，也不按“效果已知”直接丢弃。

同步修改执行报告与 Core 消费规则，使 IN_PROGRESS、取消处置、效果未知和矛盾证据不被错误当作完成或已停止；报告及 Outbox 原子提交，重复/乱序交接不重复推进。冲突发生在 Core 完成前时阻止无依据终态；已进入任务终态后发现新冲突，保留可查询的后续核对事实，不能静默改写历史或重开任务继续执行。旧版本效果只结算原工作，不能完成新目标。完成与取消竞态依据既有完成证据和控制截止规则判断，不能只按回包顺序决胜。

调用、取消、核验、事实留存与结果读取使用各自当前权限；撤销业务执行权限后仍可在获准的收尾范围保存迟到事实，但不能借收尾继续 Start 或披露无权读取的快照。输入、结果、句柄和证据沿来源、位置、用途及留存策略处理；正文失效不通过历史报告重现。

业务动作与处置预算分开，后者仅用于取消、核对及交接；核验/取消尝试、操作/工作/证据/报告容量、轮询频率、单次及总等待、Driver/I/O 时限与并发均显式有界。预算消费和恢复进展持久化，重启/重复请求不续额，不配合退出的本地调用仍占住实际槽位。容量不足保留可靠事实/待交接记录并拒绝新增工作，不删除去重历史以继续接纳。已耗尽预算时明确保留待核对或处置受限状态，不伪造取消/失败、回收未知额度或释放仍可能使用的资源。

**Key interfaces:**

- CapabilityService / SDK：Invoke、GetInvocation、Reconcile、RequestCancel，以及取消原回执/进展的获准查询；明确协议兼容与不支持行为。
- ExecutionDriver.Start / Inspect / Cancel：类型化异步事实、持久关联、只读核验及取消支持声明，不暴露供应商 SDK 或数据库对象。
- ExecutionStore.Load / Commit / LookupCommit / ListRecoverable：原子关联与工作、取消登记、恢复资格、计费、证据和 Outbox；未知提交先核对。
- 恢复运行与可信进度接纳接口：有界调度、持久尝试、来源及版本检查、冲突证据留存。
- Core / RunStore / 任务控制及 ExecutionReport：取消交接、执行中与冲突事实、原工作处置和幂等终态判定。
- GrantAuthority / 受控内容接口：当前权限、原业务消费不重复、独立收尾授权及引用保留限制。
- 独立持久模拟目标与具名契约 profile：可关联/仅随机句柄两种恢复条件、可取消/不可取消、迟到与矛盾证据、进程故障及兼容回归。

**Acceptance criteria:**

- [x] 未支持的异步/取消/核验特性、错误目标或版本、非法参数及伪造外部关联明确拒绝；不调用 Start，不静默切换驱动。
