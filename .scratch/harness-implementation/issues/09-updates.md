## Agent Brief

**Category:** enhancement

**Summary:** 接纳有权主体的等待项回答、追加事实、目标修改和预算/期限调整，持久推进任务版本，在保留控制与未知工作事实的前提下重新决策。

**Current behavior:**

任务可持久接纳、查询、领取、运行、暂停/取消和明确恢复。模型生成前预留预算，旧版本提案不能发布，已知用量可幂等结算，未知用量保持占用。任务目标、输入引用及预算目前来自创建时的快照；没有正式更新入口，也没有可由业务输入消费的等待项生命周期。

运行阻塞原因不携带 interaction_id、问题 Schema、回应资格或依赖关系。现有严格版本检查可以挡住旧结果，但不自动建立更新后新决策所需的工作和恢复事实。答案正文已经使用受控内容服务，本票新增输入必须沿用其来源、位置及留存约束。

**Desired behavior:**

TaskService 提供三个语义边界清晰的业务入口及对应 SDK/协议绑定。ProvideInput 只回答指定有效等待项；SubmitUpdate 显式区分追加事实和修改目标/必要约束；AdjustLimits 专门调整执行预算或期限。暂停、取消、恢复和授权决定继续走既有控制/授权入口，不能从普通文本推断为已授权操作。

所有请求携带既有 operation_id、task_ref、预期任务版本及明确类型。真实主体从受信认证绑定解析，不能由载荷冒充；保留事实来源、精确受控内容修订和提交主体。追加事实不自动升级成用户指令；修改目标、回答等待项及调整额度分别要求适用权限。当前本地参考绑定可以保持现有任务主体限制，但须明确支持矩阵；普通输入不能建立新的委派身份或跨主体协作授权。

接纳顺序为认证/适用授权、既有操作身份与语义载荷核对、已知回执重放、新操作状态及版本检查、原子持久提交。相同身份不同载荷或跨操作类型复用必须拒绝；原操作在任务版本推进、等待项关闭甚至任务进入终态后仍按当前回执读取权限核对，不重新应用。新操作的终态更新则明确拒绝，不重开任务。新操作冲突只向有权调用方返回适用的当前版本信息。

等待项由合法 Brain 等待提案或受信模块请求，经 Core 校验后与任务事实原子准入；ProvideInput 不能临时创建自己要回答的问题。等待项有独立 interaction_id、所属任务、结构化问题/答案约束、允许回应主体或范围、有效期限、语义依赖及生命周期。至少区分待回答、已回答、撤销和过期；新问题使用新身份。查询与持久失效事实受权限约束，不把私密问题正文放进普通任务诊断。

同一等待项的多个有效回应竞争时，最多一个新操作完成消费及对应状态转换；其他不同操作得到明确的失效/已处理或版本冲突结果，同一操作重试返回原回执。答案结构、范围、来源和回应资格都要验证。授权批准等待由授权模块掌握权威，本票的任务输入不得消费该类等待或直接签发许可。

更新对等待项的影响依据明确的语义依赖判断：例如目标相关等待项在目标变更后失效，针对一个未变化证据的问题可以保留。创建方声明依赖，更新方不能用“无影响”自述跳过失效检查；不采用模型自由判断或一律撤销全部等待项。追加事实不等于已回答某个问题；只有正确的 ProvideInput 能消费对应等待项。仍有效的等待项在无关版本变化后可以继续回答，但新回应必须使用当前任务版本。

正式更新、输入记录/回执、等待项变化、失效记录及下一步工作安排在任务权威的本地原子边界中提交，并推进决策版本。旧提案严格拒绝，不自动合并进新状态。未发出且不再适用的工作停止调度；已开始的生成尽力取消，在途工作沿已有停止/核对机制收尾。旧操作参数、旧内容准备身份和原发布请求不能被新输入改写；重新生成沿新的合法工作代次取得预留和输出身份。

输入被接纳、旧工作实际停止、用量已核实及下一轮已运行是不同事实。旧生成迟到仍只能结算原预留，不能发布旧答案；无法证明停止时保留在途状态及并发占用，不无界启动替代工作。普通版本更新也应被 Runner 有界感知，不能仅处理暂停/取消的控制身份变化。新决策在当前授权、输入、预算、期限和控制允许且旧工作处置满足要求时才可领取；输入不能清除无关等待原因。

重新组装上下文须让新增事实、已接纳回答和新目标真正影响下一轮，而不是只记一条日志。输入正文经受控内容接口使用，保存和处理新目标也适用来源政策；依赖失效、输入放不下或处理位置不允许时明确停止，不丢弃必需约束、不隐式外发。原答案 Schema 与原脚本路径保持兼容，本票只补充最小等待和重新决策所需能力。

AdjustLimits 使用有权操作设置明确的新上限/期限，区分字段未提供与显式取值，不能通过零值意外放开限制。降低请求/token 上限不得低于已消费加未结算占用，降低步数不得低于已发生的计数；低于这些下限的新调整明确拒绝，保留原约束，调用方在相关工作完成核对后可重新提交新操作。不以截断账本、清空 attempts 或归零未知预留满足新上限。

合法增加预算只恢复可用份额，不扩大授权、突破宿主支持的硬界或重置已冻结的 Worker 重试限制；只有相关阻塞解除后才可能重新调度。缩短期限在接纳后约束后续准入和仍在运行的生成，必要时触发有界停止/核对，已发生消耗和效果继续保留；不能仅修改显示字段，或在已到新期限后继续使用旧租约发起请求。延长期限不能重开终态，也不能解除暂停/取消。当前没有远端委派额度实现时不新增可伪造的“已回收”入口，不宣称完成远端预算回收。

所有新操作、等待项、受控输入引用、回执和必要恢复工作有数量、大小及期限边界。容量不足时明确拒绝，不能通过清理去重历史让旧输入再被应用。用户连续更新可以合并已持久的未消费事实来减少重新决策，但不能丢弃可靠输入，或通过无限更新重置任务预算与并发限制。

**Key interfaces:**

- TaskService.SubmitUpdate / ProvideInput / AdjustLimits 及 SDK/协议绑定：类型化意图、稳定操作、严格版本、当前授权与回执核对。
- Pending Interaction 的准入、查询和生命周期：受信创建、结构约束、语义依赖、有效期、单次消费及局部失效，不混同运行阻塞原因。
- RunStore.Commit / LookupCommit 与业务操作查询：输入、回执、任务版本、等待项和工作变更的原子性；提交不明核对原操作，不依赖进程内消息。
- Brain.Decide / ContextAssembler：有界等待提案与更新后受控快照；保留既有完整答案接口与来源规则。
- Runner 与工作/控制端口：有界感知普通版本失效，取消旧生成、保留在途核对、结算原用量并安排合法后续工作。
- 生成账本与 Constraints：预算调整遵守消耗及未知占用下限，期限变化参与当前准入和收尾，不授予权限或重置工作计数。
- 配置与契约 profile：有界等待/更新数量、内容和回应 Schema 大小、轮询/收尾时限、回执保留及恢复规则；支持的本地身份和绑定组合明确列出。

**Acceptance criteria:**

- [x] 等待项经 Core 合法准入后才可查询和回答，具有持久身份、结构约束、回应资格、依赖及期限；普通输入不能创建问题或批准授权等待。
- [x] 新输入验证实际认证主体与对应权限，追加事实保存来源及主体；仅有追加事实权限不能修改目标、调整预算或冒充其他用户。
- [x] 同操作同载荷重放返回当前授权允许的原回执，不因任务版本或等待项状态推进而重复失败/应用；同身份异载荷及跨类型身份复用明确拒绝。
