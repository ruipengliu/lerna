# 36: 按资格从 API 切换到 GUI

**What to build:** 共享业务状态验证 API 优先、无适用接口时 GUI 兜底；权限拒绝和 API 未知效果阻止重复变更。

**Blocked by:** 34：通过结构树完成模拟 GUI 动作

**Status:** ready-for-agent

**能力映射:** C1、C4、C5、C7；V2

**规范依据:** 工具执行与多模拟设备；执行接口、资源控制与故障验证。共享实施及报告约束见本工作包规格说明。

- [ ] API 与 GUI 映射到同一有状态模拟业务资源，在适用、可达且获准的 API 存在时优先通过 API 完成目标。
- [ ] 仅无对接接口或明确能力不足等已声明条件允许 GUI 兜底，记录目标语义、前置条件、权限和结果核对资格。
- [ ] 权限拒绝不能靠 GUI 绕过；API 可能已生效但回包丢失时先核对，无法确认保持等待，验证没有第二次 GUI 写入。
- [ ] 获准切换产生新 GUI 动作身份并关联原工作，原 API 的事实及未知状态不可覆盖；超时/限流不自动解释为无 API。
- [ ] 资源接管同时阻止共享范围内 API 与 GUI 启动；无法精确映射时在授权范围内保守暂停相关应用，恢复沿原控制规则。
- [ ] 以真实模型路径选择和确定性故障夹具分别记录 API 优先、合法兜底、非法切换及重复效果计数。
- [ ] 提供可重复验证入口，记录实现/依赖、配置、环境、执行方法、实际结果与限制；未运行或失败不写成通过。
