# 74: 按阶段激活获准改进

**What to build:** 持久控制 5%/25%/100% 分配、样本和时间窗口，任务版本固定；代码验证维护者对精确产物的确认。

**Blocked by:** 73：用独立保留材料判定发布资格；61：逐节点应用扩展版本

**Status:** ready-for-agent

**能力映射:** C9、C6、C7

**规范依据:** 评测接口、参考基准与发布判定；扩展清单、运行器与激活恢复。共享实施及报告约束见本工作包规格说明。

- [ ] 具备有效资格的候选在明确授权范围按新任务/关联工作组固定分配 5%、25%、100%，同一任务不切换版本，共享可变资源隔离或排他。
- [ ] 前两阶段分别至少 200/1000 个可核验真值的候选任务、各不少于 24 小时且最长 7 天；不足转待评估，不按超时自动晋级。
- [ ] 数量和时间达标之外，分组首次/成功达到 90%/95%、控制检查通过、代价不超限、证据完整且目标节点实际激活确认，才允许推进。
- [ ] Promote 原子保存阶段意图、证据与政策前提及 Outbox，再按原操作交接扩展激活；回包丢失先核对，各节点实际状态分别展示。
- [ ] 常规记忆按既有授权生效；Skill/策略/Agent 配置依资格逐步启用，插件、内核及随包可执行代码必须验证维护者对精确产物的确认。
- [ ] 用隔离多节点/受控任务验证阶段与恢复，可用标明的模拟时钟验证边界；不将模拟 24 小时当真实生产观察。
- [ ] 提供可重复验证入口，记录实现/依赖、配置、环境、执行方法、实际结果与限制；未运行或失败不写成通过。
