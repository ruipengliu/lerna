# 23: 登记节点并验证双向 TLS 身份

**What to build:** 通过受信管理路径签发公钥绑定证书，校验真实节点与代理主体；禁用、轮换及长连接失效检查保持有效。

**Blocked by:** 06：签发、派生和撤销受限授权

**Status:** ready-for-agent

**能力映射:** C5、C6、C7；A3、A4

**规范依据:** 授权生命周期、凭证与控制接口；内部契约与外部协议映射。共享实施及报告约束见本工作包规格说明。

- [ ] 本地受信管理入口核对绑定节点公钥、目标命名空间及有限期限的加入请求，交付证书；节点私钥留在所属节点，首次信任根通过受信路径配置。
- [ ] 实际 TLS 对端验证链与目标身份，证书字段精确映射受信登记；节点仅在已签发代理关系内代表用户，不能自报任意主体。
- [ ] 业务调用重新检查节点登记和失效状态，已建立连接及恢复 TLS 会话不能跳过禁用检查，不自动采信代理注入身份头。
- [ ] 节点证书轮换重新签发依赖摘要的材料；失钥走受信重登记，签发密钥重叠期有界，发现消息不能创建新信任根。
- [ ] 用两个独立节点目录验证加入、错绑证书、跨命名空间冒用、禁用和轮换；登记及禁用记录按版本持久恢复。
- [ ] 提供可重复验证入口，记录实现/依赖、配置、环境、执行方法、实际结果与限制；未运行或失败不写成通过。
