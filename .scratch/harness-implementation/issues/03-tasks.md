## Agent Brief

**Category:** enhancement

**Summary:** 经当前授权接纳任务，在真实 SQLite 中原子保存任务、回执、执行记录与待处理工作，通过稳定操作身份和内部提交身份完成去重、查询及进程恢复核对。

**Current behavior:**
前置 02 已完成本地身份、策略、有限持续授权、授权管理原子提交及接纳窗口验证；01 提供 SDK、Protobuf 和内存任务契约夹具。按 Task、Submit、RunStore、LookupCommit、ListRecoverable、操作回执及待处理工作等领域概念检查 SDK、协议、契约夹具、授权服务与 SQLite Adapter 后，现有 Submit 仅产生 contract_fixture 结果，没有持久 Task、任务查询或运行存储实现。授权管理的 Store 与 LookupOperation 只覆盖授权变更，不能替代任务运行存储。未发现历史拒绝记录。维护者已确认 enhancement 分类、保持 ready-for-agent，以及本简报的实施边界。

**Desired behavior:**
受信本地入口经认证及当前策略判定，接纳目标、输入引用、约束和稳定 operation_id，返回任务引用与真实持久化受理结果。初始任务为 QUEUED，记录本地 Task Owner、世代及状态版本；创建任务、业务操作回执、内部提交回执、初始执行记录和待处理工作必须在同一运行持久化事务内完成。接纳成功只表示任务与待处理工作已保存，不表示开始执行或完成目标。

TaskService.Get 与 LookupOperation 只披露当前允许访问的结果。原操作重试保持身份、核对语义并返回原任务；并发首次提交也只能形成一个任务和一组初始记录。内部 change_id 标识一次任务级原子提交，与外部 operation_id 保持不同生命周期，不作为新的外部请求字段。

复用 02 的身份与授权能力，通过消费方接口补足任务接纳所需的作用域、窗口核验和结果核对边界。首次接纳与窗口关闭、策略更新或主体失效的竞争必须有明确的生效顺序与可验证的提交约束，不能仅先读授权/窗口再无条件落盘。任务与授权管理不能因分属两个处理模块而让同一命名空间内的同一 operation_id 被解释成两项新操作。无需将全部授权状态合并进运行存储，也不得依赖无法保证原子性的跨库顺序写入来声称接纳完成。

任务未完成时，其操作、内部提交回执及恢复所需记录继续保留，不套用短期授权管理回执的清理规则。进程重启从原 SQLite 文件读取任务和待处理工作；结果未知时核对原 change_id/operation_id，不换新身份猜测重试。本票只提供可恢复候选，不运行 Worker 或 Brain。

**Key interfaces:**
- `TaskService.Submit`：接受获准目标、输入引用、约束和稳定操作身份，返回 task_ref 及持久化接纳证据；不允许客户端指定任意状态、Task Owner 或终态。
- `TaskService.Get` / `TaskService.LookupOperation`：核对当前认证与读取资格，再返回任务快照、版本或业务接纳结果；任务引用和操作身份不构成访问凭据。
- `IdentityVerifier` / `Authorizer` 及任务接纳端口：沿用本地认证与有限持续授权，明确创建资源范围、读取资源范围、动作、用途、位置和时间；由受信映射确定资源归属，不采信请求自报归属。接纳端口封装不透明操作身份的规范编码、受理权威、窗口验证及并发约束。
- `RunStore.Load/Commit/LookupCommit/ListRecoverable`：提供任务级独立快照、受约束原子变更、内部提交核对及有界恢复分页。SQL、数据库连接、事务及驱动错误留在 Adapter 内，调用方不自行协调任务、回执和待处理工作多次落盘。
- `RunChange` / `CommitReceipt` / `CommitStatus`：明确任务引用、稳定 change_id、创建不存在前提或预期版本，以及适用的拥有者/世代约束；错误区分身份冲突、版本冲突、已知拒绝与持久化结果未知。
- SDK、Protobuf 与验证 profile：提供真实任务接纳和查询所需固定消息及受信本地绑定，保持 01 契约样例、02 本地授权的接口语义与证据边界；实际网络服务不在本票实现。

**Acceptance criteria:**
- [x] 使用 02 建立的本地身份、策略和有限持续授权，经可导入 SDK 与真实处理入口提交任务，得到可查询的 QUEUED 任务、持久化接纳结果及初始版本；目标、输入引用和约束按契约保存，未知必需条件或不支持的输入明确拒绝。
- [x] 未认证、自报身份、跨命名空间、无创建权限或权限已失效的提交被拒绝且不留下任务/工作残片。Get 和 LookupOperation 在披露前核对当前权限；知道 task_ref、operation_id 或曾经获准均不能绕过当前限制，不泄露无权访问的目标、回执或隐藏资源。
- [x] 创建资源范围和任务查询范围来自受信映射；任务尚不存在时仍可判定创建权限。主体、动作、用途、位置及期限受 02 的当前策略与授权约束，不把本地安装管理员身份自动当作业务放行依据。
- [x] Task、初始状态与拥有者记录、业务操作回执、内部提交回执、执行记录增量及待处理工作在同一 SQLite 事务提交，创建使用明确不存在前提；任何失败都不能暴露部分已提交组合。
- [x] 相同 operation_id、原主体及同一业务语义的顺序或并发重试只得到原任务，不增加任务或初始工作数量；相同身份改变语义或操作类型被拒绝，换主体不能形成第二个同名操作。授权管理与任务提交之间也验证同名身份不得被重复解释，且未授权调用不能利用冲突响应获得原结果。
- [x] 内部 change_id 不出现在对外协议中，也不与 operation_id 隐式等同。RunStore 对同任务的同 change_id、同内容返回原提交结果，去重先于新提交版本判断；同 change_id 不同内容返回身份冲突，不同新提交的错误预期版本返回版本冲突。
- [x] 操作身份绑定受信命名空间、受理权威和接纳窗口，篡改、替代编码、跨权威重用及过期首次接纳被拒绝。窗口关闭、主体失效或策略变更与首次提交交错时，测试验证已定义的生效顺序，不能出现以失效资格无条件提交的路径；已接纳任务不因窗口关闭被删除或取消。
- [x] 回执与去重记录的保留覆盖仍允许重试和恢复的任务生命周期。未完成任务及其必要记录不会被 02 的短期管理清理删除；关闭窗口或清理管理记录后，原任务仍可按当前权限查询，旧身份不能重新创建任务。若本票不提供任务记录清理，明确声明并拒绝越界清理。
- [x] 通过真实 SQLite 文件和独立进程故障验证提交前中断无部分状态、提交后回包丢失可核对原结果、同操作重试不重复创建。内部通过 LookupCommit、外部通过 LookupOperation 核对；一次未查到或等待超时不能被解释为原提交永远不会成功，不因此分配新身份执行。
- [x] 关闭并重启进程后，通过公开任务接口读取原任务，并通过受信 RunStore 接口核对初始执行记录和待处理工作。ListRecoverable 有明确页大小上限及稳定续页约定，在静态候选集上无遗漏、无重复；并发变化语义明确，返回候选不代表取得 Worker 资格，游标不能突破查询作用域。
- [x] RunStore 不作为普通远程写入接口；外部调用者不能任意写入终态或伪造 owner/epoch。创建之外不属于本票的状态推进明确不支持，不为验证版本竞争而开放任意状态覆盖。已有内部提交入口必须落实其适用的版本和所有权前置条件。
- [x] 新增可重复验证 profile，区分真实持久任务接纳、授权管理和内存契约夹具证据，记录源码/依赖版本、SQLite 运行版本、配置、环境、方法及逐项结果。01 和 02 必需回归通过；必需项失败、未运行或不支持不汇总为通过，不以本票通过声称任务已经执行或整个 M1 已验收。

**Out of scope:**
- Worker 领取、续租、双 Worker 竞争、脚本化 Brain 决策及 QUEUED 之后的实际任务运行，由 04 扩展；本票保留必要拥有者与工作数据，不预实现完整调度系统。
- 暂停、取消、恢复、补充输入、目标修改、预算调整、父子任务协作及跨节点所有权移交。
- 真实模型、业务 API、设备 GUI 或其他外部副作用；输入引用的证据/产物生命周期由后续票实现，引用不能自动授予读取或执行权限。
- 真实 gRPC/WebSocket、节点加入、浏览器登录、跨节点授权、单次许可消费及第二耐久后端。
- 全任务历史清理、归档和迁移系统；本票须明确保留与容量边界，容量不足时拒绝新接纳，不能以删除恢复所需记录释放空间。
