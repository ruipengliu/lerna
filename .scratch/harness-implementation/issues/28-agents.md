## Agent Brief

**Category:** enhancement

**Summary:** 让父任务通过有限决策提案委派串行及并行内部 Agent 子任务，在持久预算、收缩授权和独立任务权威约束下收集结果、处理失败并完成受控收尾。

**Current behavior:**

Brain 可生成有限能力行动提案，Core 已管理任务版本、Worker 资格、生成/行动预算、执行恢复与控制。SubmitUpdate 支持按原操作身份追加受控事实或受权修改目标，授权权威支持派生授权和额度预留，端云通道具备可靠调用与恢复基础。尚无完整内部 Agent 子任务委派契约、父子持久关联、预算交接、结果聚合和所辖子任务收尾门槛。

**Desired behavior:**

Brain.Decide 的有限提案可表达委派，Core 按当前任务版本、owner/epoch、Worker 资格、权限及预算准入。委派固定原操作身份、子目标、接收内部 Agent、输入/结果 Schema、受控输入引用、允许处理及结果位置、收缩授权、预算上限、期限、验收要求、必需性与依赖。子任务有自己的任务引用和唯一 Task Owner，其状态由子端权威推进；不同子任务拥有独立责任，不要求每个任务必须使用不同物理节点或进程。

父端在同一 RunStore 提交中保存委派准入、预算预留、原操作与待发意图。子端按原委派操作幂等接纳并持久绑定子任务及所分额度。重复消息或新消息引用同一委派不创建第二子任务、不再授第二份额度；改变原操作语义明确冲突。父提交或子接纳结果不明时核对原提交/操作，保存未结算预留及恢复进展，不冒充跨任务原子事务。

子端使用自己的权威存储核算预算，继续委派不得超过自身可分配额度与深度；运行预算和授权额度分别满足。父端不得同时把额度留给可能仍在运行的子任务又恢复到自己的余额。额度或并发槽位回收须确认旧接收方不能继续使用并核对历史消耗；失联、超时或已发送取消均不足以回收。目标工作预算耗尽后仍保留另设的有限取消/核对资源，处置预算不足且关键效果未知时保持待核对。

串行分支只在前置验收满足后调度，并行分支受总预算与并发限制。必需子任务明确失败时停止依赖其成功的后续工作，独立分支可继续；可选失败保留缺口，不能临时将必需项改成可选。验证可见的依赖图，拒绝循环和父等子、子又要求父完成的不可满足关系；不可完整探测的跨运行时依赖仍受期限和无进展阈值约束。

子结果携带稳定的任务/委派关联、版本、可见产物或受控引用、Schema、来源、证据、覆盖范围、未解决事项和效果状态。父端验证结构、来源及当前可用/披露条件，再按自己的原目标与验收要求判断。冲突保留各来源并进入获准验证或澄清，不按多数、最后返回者、置信分数或子完成标签直接决定父终态。受控协作消息通过 SubmitUpdate 追加事实，提交主体及来源被保存；普通文字不能直接改变另一任务目标、权威、控制或授权。

父取消或某分支不再需要时，向所辖子任务持久传播取消并核对实际停止及已发生效果。离线、回执丢失或效果未知分别保留待送达/待核对状态。父任务进入终态前，全部所辖子任务及外部操作必须完成、明确未启动或已停止并处置，关键效果无待核对事项；已接纳的父取消先约束尚未发出的委派，迟到接纳关联仍须补齐并处置。默认不允许子任务脱离父任务，失败也不意味着已完成副作用被回滚。

**Key interfaces:**

- Brain.Decide 与有限决策提案：委派类型、受控子目标及契约、依赖与预算；提案本身不授予执行权或直接创建子端权威状态。
- Core/RunStore 准入与恢复：父预留、委派意图、稳定操作映射、子关联、结果事实及控制处置；沿用当前版本和资格检查。
- TaskService.Submit、原操作查询与 SubmitUpdate：幂等子任务接纳、关联恢复和带受信来源的协作事实；不提供任意跨任务状态写入。
- 授权派生与额度端口：限定子主体、接收方、用途、位置、期限及后代范围，复用既有收缩与原操作分配约束。
- 内部 Agent 运行与任务控制：独立拥有者、串并行调度、必需失败依赖处理、取消传播、结果和未知效果核对。
- 既有认证协议绑定与可靠投递：补齐实际委派/结果/控制的支持方法及关联校验，不能仅因传输可用就宣称任务方法已支持；持久回执与业务接纳/完成独立。
- 配置：委派批次、深度、并发、预算、输入/结果大小、依赖图规模、期限、无进展阈值、队列、I/O、重试及处置预算均有有限上限。

**Acceptance criteria:**

- [x] 父任务经实际有限提案及 Core 准入完成至少一条串行和一组并行内部 Agent 子任务；每个子任务具有独立任务身份和唯一 Task Owner，输入/结果 Schema、期限、必需性、依赖及验收条件持久可查询。
- [x] 在父预留/待发意图提交、子接纳及关联回执等边界注入失败和实际进程退出；重启按原操作恢复，重复消息、新消息同委派以及接纳回包丢失均只关联一个子任务和一份额度，语义变化明确冲突。
- [x] 并发委派和后代分配不突破父额度、深度与并发限制；子端独立核算。未知交付/消耗、超时与取消未落实时不回收复用预算或槽位，已知结算才允许相应回收。
- [x] 子任务无法扩大父授权、越过接收方或位置限制；当前撤销、资格失效与暂停/取消仍有效，重启和迟到消息不能恢复旧执行权。输入及结果的保存、使用和披露均受当前策略约束。
- [x] 子结果验证 Schema、来源、任务/委派关联与版本；伪造来源、错关联和不适用迟到结果不驱动父状态。冲突结果保留证据与未解决事项，不按投票或完成标签直接完成父任务；可机械验收场景用独立目标状态核对效果。
- [x] 必需分支失败阻止其依赖分支，独立健康分支仍可完成；可选失败保留缺口而不改变既定必需性。重复和乱序结果不重复结算或覆盖较新事实。
- [x] 父取消覆盖已关联、待提交和接纳结果未知的所辖子任务；断连期间显示待送达/待核对，迟到接纳仍被追踪处置。关键效果未知或所辖工作未处置时拒绝父终态，不静默脱离或虚构停止。
- [x] 协作消息通过 SubmitUpdate 追加带主体与来源的事实，按版本及原操作去重；普通事实不能改目标、控制、权限或直接修改子/父权威。可见循环和不可满足依赖被拒绝，未知跨运行时依赖受期限与无进展限制。
- [x] 委派批次、深度、队列、输入/结果大小、I/O、重试及预算超限有实际拒绝/等待验证；目标预算耗尽不抹去处置义务，处置额度耗尽且效果未知时保持明确等待。普通远程能力调用仍可直接完成，不强制创建子任务。
- [x] 提供可重复验证入口与持久报告，记录冻结代码、依赖、模型/数据配置（适用时）、环境与拓扑、故障点、真实进程退出/恢复、任务关联、预算账目及独立结果证据；运行受影响回归，区分模拟、真实网络/进程、真实模型、失败、基线与未执行范围。

**Out of scope:**

- 外部 Agent 协议生态的完整接入、供应商私有 Agent 会话管理或默认共用可写聊天记录。
- 同一任务的所有权移交、任意跨任务远程存储写入、默认脱离父任务的后台工作。
- 无限委派/重试/处置、未知额度自动退款、仅凭估算承诺精确模型账单硬上限。
- 通用多数投票裁决、自动回滚外部副作用或无授权补偿；有支持的补偿仍是独立受控操作。
- 重开已确认认证/传输/授权决策，扩大 14 号票模型支持与质量结论，或将脚本协作/协议故障检查等同真实模型质量及完整系统验收。
