## Agent Brief

> *This was generated by AI during triage.*

**Category:** enhancement
**Summary:** 通过受控 ContextAssembler 将适用记忆加入回答和 API 决策，并在来源变化后阻止过时提案发布或启动。

**Current behavior:** 现有 Brain.Context 能组装受控任务输入并校验处理位置；长期记忆已有独立授权与修订存储，但没有绑定任务事实、用途、策略及来源依赖的持久上下文结果。

**Desired behavior:**

- Assemble 输入任务事实版本、目标及约束、用途、处理位置、候选来源与预算，输出固定上下文和来源修订清单，以及缺失、不适用、冲突与裁剪状态。使用已登记 Schema 和受信适用性策略；任意记忆文本不能授予权限或覆盖 Core 控制。不得隐式写回记忆或推进任务状态。
- 同一次决策的组装结果固定任务事实、策略版本和依赖修订。只持久化获准保存的正文；其余仅持久化受控引用，重启必须重新获准读取。原快照无法恢复时明确缺失/失效，不能静默用新修订替代。不得用可重放的历史 Get 证明来源仍是当前修订。
- Validate 校验依赖的当前修订、用途、有效时间、当前处理/披露及存储权限；无关记录变化不使快照失效。适用性变化、纠正或撤权使依赖它的提案失效。有界重组仍无法稳定则等待，不能无限调用模型。
- 模型前、返回后、答案发布与新行动启动前均覆盖上下文和 Core 当前控制校验。重启及长期等待后也必须校验。承认跨库和外部效果之间并无全局原子撤销，已发生效果继续按原操作核对。
- 必需目标、用户约束、当前行动事实及必要授权条件保留，超限明确不足；可选记忆裁剪可观察。冲突保留来源差异，不能用单一置信数掩盖相互矛盾的主张。调用方可以据此澄清或采用明确受信策略。

**Key interfaces:** ContextAssembler.Assemble/Validate；消费方定义的来源查询、精确恢复与当前修订校验接口；可替换 SnapshotStore；Brain.Context、答案发布及行动准入/启动的校验接口。SQLite、Memory 与授权具体实现留在 Adapter。

**TDD seams:** ContextAssembler 语义入口、持久快照与来源权限/版本接口、正式回答发布及实际 API 效果边界。先为每个纵向行为建立失败反例，再实现；耐久性使用真实 SQLite 和实际进程退出，内部替身仅负责精确并发/故障边界。

**Acceptance criteria:**

- 通过正式受控路径组装适用记忆，完成一项实际回答和一项有状态 API 行动；记忆对可观察选择的影响由成对输入及独立效果判断。
- 验证适用/不适用、缺失、冲突、必需约束超预算、可选裁剪、不同用途及禁止外发位置；无权来源不得以错误、计数或摘要泄露存在性。
- 暂停模型或准入流程后纠正相关来源，旧答案/新动作被阻止；无关纠正不重启该任务；模型返回后撤权和发布/启动前撤权均有反例。
- 重启从获准正文或受控引用恢复，原快照保持身份；旧引用不可读时明确等待/失效，不能依赖无权摘要。证明已准入/未知效果操作不会因上下文变化换身份重做。
- 首版输入沿 Brain 的 32768 字节硬上限，最多 16 条记忆候选、32 条总依赖；快照最多 64KiB、512 条，达到容量拒绝而非驱逐恢复身份；组装/校验调用最多 5 秒、自动重组最多 2 轮。模型 Adapter 仍单独执行其 token、输出和协议包装容量限制，这些字节限额不能替代 token 预算。
- 真实模型成对小回归分别验证回答与行动，固定公开合成资料、实际服务处理位置、模型版本和预算。最多 8 次真实请求、每次最多 1024 输出 token；记录真实用量及失败，不能将未运行记为通过，也不能据小回归宣称完整 90%/95% 质量达标。
- 提供具名 profile、实际 CLI/SDK 入口、进程恢复证据、完整回归与双轴审查，以及明确的实现/配置/命令/结果/限制。

**Out of scope:** 自动记忆挖掘、删除传播、远程联合检索/同步、全量质量基准及插件市场。不得因此省略本票来源纠正、用途、权限和过时提案控制。

**实施前审查基点:** `304aeb3`（17 票验收归档后的代码状态；后续仅 triage 文档变更）。上述常规实施选择依据用户持续授权接受，不另行等待确认。
