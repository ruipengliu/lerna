**Category:** enhancement

**Summary:** 通过正式能力入口执行并独立确认有状态模拟 API 变更，持久管理原操作、执行许可消费、启动与效果报告，使重复请求和中断恢复不造成未经准入的重复动作。

Harness 已有持久任务及有限 Worker、暂停/取消与旧工作处置、受限签名授权及额度预留、受控证据和产物。现有 Brain/Model 答案路径不会执行 API；允许受信来源报告既有效果的接口也不是完整 Execution 协调器。

授权额度分配与业务侧实际启动尚未接通；缺少固定能力/实现版本的正式调用、执行工作及单次消费账本、发送前恢复事实、独立效果核验和可靠报告交接。现有协议夹具不具备这些保证。10 票建立最小同步执行闭环，11、12 票分别扩展异步/未知效果恢复和共享资源接管。

**Desired behavior:**

CapabilityService 提供正式 Invoke、GetInvocation 及本票所需的有界原操作核对入口，通过可导入 SDK 和类型化协议绑定访问。使用受信登记、固定能力和实现版本及摘要、输入/输出 Schema 的最小能力集合；无需先建设搜索目录或让模型选择 API。示例可由确定性的受控提案或受信调度模块选择能力，再经 Core 和执行准入，不将业务载荷当作可信执行资格。未知能力、版本、Schema、方法或必需保证明确拒绝，不静默选最新实现或切换 GUI。

参考 API 必须改变可查询、有版本前提的业务资源状态。模拟目标与执行账本在逻辑上独立，效果证据来自目标状态/原操作记录等可核验事实，而不是复述 Driver.Start 的返回值或执行器自己写的成功日志。目标状态在真实进程中断后仍可核对，不与 ExecutionStore 的启动提交合为一次事务掩盖外部调用故障。Driver.Start 执行变更，Inspect 只读取原操作事实，不能隐式 Start；Cancel 或异步行为尚未支持时明确报告不支持。

接纳保持稳定 operation_id、任务关联与受信调用主体、目标、精确能力/实现/Schema、受控参数及语义指纹。指纹覆盖所有影响业务含义的字段，规范化规则明确，不依赖 map 顺序、运行时地址或可变默认值。消息重发不改变业务身份；同身份异参数、异目标或跨操作类型复用拒绝。先认证/适用授权，再核对已知操作并返回当前读取权限允许的原回执，新操作才检查接纳窗口和当前版本/资格。原回执、当前可读结果与当前可执行资格分别处理；原操作重放不重新消费或排出第二次动作。

ExecutionStore 与 RunStore 保持逻辑职责分离，按接口依赖具体 SQLite 实现。执行接纳、去重、原回执及待处理工作原子保存；受限的 Load/Commit/LookupCommit/ListRecoverable 表达原操作、预期记录版本及 Worker 资格，不暴露任意远程写库。共享文件不意味着可以覆盖 Task、内容或授权账本，也不承诺与模拟目标/外部效果的跨存储原子事务。提交未知先核对原内部提交及原操作，不能把未收到回执当作未接纳。

实际调用前重新检查认证主体及代理绑定、当前授权/祖先限制和撤销、许可接收方与原操作语义、处理位置、输入来源、任务拥有者/版本/控制、Worker 代次/租约、资源版本前提和任务预算。接纳时获准不保证稍后可启动，单次签名、任务新额度或 Driver 名称都不能替代当前资格。任务更新、暂停、取消、到期或旧 Worker 失效先于启动登记时阻止新动作；已经可能发送的动作保留处置责任，不将事后拒绝伪装成未执行。

授权分配与执行消费分别记录：GrantAuthority 可先持久分配绑定接收方和原操作的额度，执行端随后在同一个 ExecutionStore 原子提交中登记该许可的单次消费及原操作启动。UsePermit 必须经受信来源和当前适用资格验证，普通请求不能伪造一个结构体充当许可。两次 SDK 请求、两个 Worker、重开进程或另一接收方不得复用同一份许可启动第二个动作；分配回包未知先核对，额度不能自动退回或重新分配。适用的共享操作身份规则需明确支持“同一执行操作取得预留后消费”，不能把授权预留误当成另一个冲突业务，也不能放宽到任意跨类型身份复用。

任务执行预算与授权额度独立满足。动作的预算归属、有限预留/使用和原操作绑定必须持久、可核对；不能只计算 Brain 尝试次数却允许该次提案无限发出动作。不同权威交接不明时保留占用，不通过重置已用次数、未知预留或新建操作绕过硬限。需要的当前资格与启动登记在声明的本地原子边界内校验；跨权威/目标的检查新鲜度及无法原子覆盖的窗口如实说明。

参考部署只支持一个可验证执行协调方独占控制的资源范围；目标具备版本前提及拒绝不合法旧请求的机制。独占条件需由受信组装及持久准入/目标前提保证，不能由请求自报或单个进程锁推定。重开多个协调器/Worker 或并发请求不得竞争获得同一启动资格；不具备独占条件、未知在途操作仍可能改写资源或尚未支持共享控制时阻止新的冲突变更。完整多入口资源接管留给 12 票。

在事务外调用 Driver.Start 之前持久记录“准备调用且可能已发送”、固定输入和必要外部关联。该提交失败或结果未知未核清时不调用 Driver。提交后、真正发送前崩溃，也不能仅凭缺少发送成功记录推断未发出。恢复以原操作调用 Inspect；只有目标提供充分覆盖及旧请求不可能迟到的证据，才可认定未执行。证据不足保留 UNKNOWN，不自动 Start、不新建身份补做、不回收未知占用。目标有效幂等保障如用于恢复，须固定适用范围、有效期和证据，不能将本地去重推广为任意外部 exactly-once。

报告分别表达执行阶段 NOT_STARTED/IN_PROGRESS/FINISHED/UNKNOWN、调用结果和效果确认，不能用一个 success 字段覆盖所有事实。同步成功仍须按能力声明核验目标状态及效果证据；成功返回但效果不符/无法确认、输出 Schema 不合约或正文不可保存时，不得报告已确认成功，已经可能发生的效果仍保留。明确未启动、权限/Schema 拒绝、目标前提冲突和未知效果具有可区分且不泄密的结果。
