## Agent Brief

**Category:** enhancement

**Summary:** 在既有认证 WebSocket 通道上完成可靠能力调用，使消息补投、进程重启和记录清理均保持原操作身份及恢复义务。

**Current behavior:**

WebSocket Host/Peer 已具备真实 mTLS、版本/能力协商、双向查询和订阅、有界分块与队列，但消息状态仅存于连接内，不支持可靠变更、PERSISTED 或跨连接补投。Execution.Service 已支持持久接纳、调用去重、有限恢复及外部效果核对。现有 gRPC Journal 专用于调用完整快照；其按操作修订保存的记录不能直接充当可靠流连续前缀。

**Desired behavior:**

发起方通过 SDK/端口提交稳定的能力调用意图，意图与可靠 Outbox 原子保存后发送。接收方持久化原 message_id、认证来源作用域、载荷指纹、可靠流位置及未消费标记后才回复 PERSISTED。持久化回执、业务受理、执行完成与效果确认保持独立含义。业务回复同样可靠保存、投递并确认。

接收后业务处理前退出，重启可继续扫描未消费 Inbox。同 RunStore 的业务处理将操作登记、状态变更、消费标记和回复 Outbox 原子提交；独立 ExecutionStore 等目标按原 operation_id 幂等受理并可查询，核对受理后再完成交接。提交结果未知时查询原提交/操作，外部动作仍在事务外执行；传输重试不创建新的业务意图，也不盲目再次 Start。

可靠流按发送方向独立保存连续确认位置、补投范围与关闭状态；临时进度、心跳和无需重放的回执不占可靠序号。乱序消息可有界暂存，缺口补齐并持久化后才推进前缀；回执丢失从持久接收记录重建，无须递归确认。重发保持原消息身份和业务内容，新查询使用新的消息关联并引用原操作。旧连接失效后不能推进新连接的受控状态。

重连先认证并协商，随后对受影响对象校验当前权限、领取/拥有者资格、控制意图、接纳窗口和原效果。符合条件后恢复该对象工作，无关健康对象仍可运行。游标超出保留范围时明确进入快照/原操作核对，持久关闭旧流及恢复边界，再建立新流位置。证据不足保留 UNKNOWN 或明确等待状态。

复用接纳窗口身份生成和校验：操作身份绑定受信作用域及窗口世代，关闭水位先于明细清理持久化。当前授权允许时，既有操作仍可返回保留结果或继续核对；窗口关闭阻止首次受理旧操作，重连不能续开旧窗口或更换旧操作身份。清理需满足交付、恢复及数据保留约束；队列满不授权丢弃未履约记录，窗口结束也不等于取消已受理的长任务。

**Key interfaces:**

- WebSocket Host/Peer 与 Protobuf Envelope：协商可靠能力、持久接收位置、补投范围、回执及过期恢复状态；延续既有严格结构和动态 Schema 校验。
- SDK 能力调用与查询端口：持久提交原意图，区分持久化/受理/效果状态，查询和重试始终关联原 operation_id。
- RunStore 原子提交边界：容纳适用的发送意图、Inbox 消费、业务状态和回复；存储细节留在 Adapter 内。
- Execution.Service 的 Invoke/GetInvocation/Reconcile/LookupCommit/Recover/Drain：复用原操作受理、提交核对和未知效果恢复；跨 Store 交接保留可扫描进度。
- 授权及接纳窗口端口：复用当前节点/主体/目的地与权限校验、操作身份绑定和关闭水位；保存及发送消息均满足来源与目的地策略。
- 配置：明确持久队列条数/字节、乱序缓存、消息大小、并发、I/O、补投次数及恢复/保留窗口的有限上界；重启保留已消费预算与恢复边界。

**Acceptance criteria:**

- [x] 真实端云双进程通过 mTLS WebSocket 发起并完成有副作用能力调用，独立目标状态证明效果；可靠投递及回执覆盖两个发送方向，保留实际消息和操作关联证据。
- [x] 意图/Outbox 原子保存；接收持久化失败不发送 PERSISTED；Inbox 已落盘、业务尚未处理时强制退出并重启，原消息最终被处理，回执本身不误报业务成功。
- [x] 同 RunStore 消费在故障注入下没有业务状态、消费标记、回复不一致的组合；跨 Store 已受理而交接标记丢失时，重启查询或重复交接原操作，独立目标只产生原操作应有的效果。
- [x] 重复同消息及新消息引用同操作均不重复业务变更；同 message_id 改载荷或同 operation_id 改语义明确冲突。回复重发保留原身份与内容，新查询正确关联原操作。
- [x] 双向乱序、缺口、重复和回执丢失只推进持久连续前缀；临时消息不形成可靠缺口；伪造越界确认被拒绝，乱序缓存与持久队列达到上限时明确背压或拒绝且不丢失已承诺的记录。
- [x] 外部生效后断网、回复丢失、发起端/接收端分别及双方进程重启均核对原操作；无法证实效果时保持 UNKNOWN，不因网络恢复再次启动未知动作。
- [x] 恢复期间撤销权限、禁用节点、失效资格或持久暂停/取消仍生效；旧连接不能绕过新恢复边界。受影响对象等待核对时，无关健康对象可完成工作。
- [x] 游标过期触发明确快照/操作核对并持久关闭旧流；再次重启后关闭状态仍在。窗口关闭后清理明细，再以原消息、新消息同旧操作或修改窗口元数据投递均不能复活旧动作；已受理长任务按自身授权继续核对。
- [x] 消息保存、补投、回复及结果披露遵守当前授权和来源/目的地策略；断连后重启默认重新核验适用的远端权限。大小、队列、重试、I/O 与恢复预算均有超限验证，心跳/控制保有有限发送预算。
- [x] 提供可重复验证入口与报告，记录冻结代码/依赖、配置、环境、故障点、执行方法、真实进程退出/重启和独立效果结果；运行受影响回归，区分新失败、已复现基线失败和未执行项。

**Out of scope:**

- 新增任务所有权迁移、自动故障接管、完整 UI 恢复或记忆同步；保留本票使用的既有资格和控制约束。
- 将全部远程变更方法一次性开放；本票必须完成可靠能力调用及适用 RunStore 原子消费验证，其余未支持方法明确拒绝。
- 外部 exactly-once 保证、未知动作自动换身份补做、无限历史/重试或以新增必需队列服务替代默认单机 SQLite。
- 以模型质量或完整系统验收替代本票实际传输、存储故障和效果核对证据。
