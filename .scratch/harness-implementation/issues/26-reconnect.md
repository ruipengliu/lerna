# 26: 断连重启后恢复可靠端云操作

**What to build:** 持久 Inbox/Outbox、连续确认和原消息补投驱动实际调用；跨 Store 幂等交接，过期窗口不复活旧动作。

**Blocked by:** 25：通过端云通道双向查询和推送；11：恢复异步与未知效果调用

**Status:** ready-for-agent

**能力映射:** C4、C5、C6、C7；A3、A4

**规范依据:** 端云任务所有权与恢复；恢复状态与故障检查表；原生接口与消息目录。共享实施及报告约束见本工作包规格说明。

- [ ] 真实端云链路完成一次有副作用能力调用，发起意图与 Outbox 持久保存，接收端 Inbox 落盘才发 PERSISTED；该回执不代表已执行。
- [ ] 接收后业务处理前重启能扫描未消费 Inbox；同 RunStore 内业务变更、消费标记及回复原子提交，跨 Store 按原 operation_id 幂等交接并核对。
- [ ] 双方只确认持久连续前缀，乱序缓存有界；原消息补发保留 message_id，新查询保持原操作关联，缺口不能跨越确认。
- [ ] 断流、回包丢失和两端重启后先校验资格、权限、窗口及原效果，再开放受影响工作；无关健康对象可继续。
- [ ] 消息游标过期转快照/操作核对，关闭流与接纳窗口水位持久化；记录清理后不把旧动作重新受理。
- [ ] 覆盖重复消息、新消息同操作、外部生效后断网、跨 Store 已受理但交接标记丢失、有界队列耗尽；保留实际恢复结果。
- [ ] 提供可重复验证入口，记录实现/依赖、配置、环境、执行方法、实际结果与限制；未运行或失败不写成通过。
