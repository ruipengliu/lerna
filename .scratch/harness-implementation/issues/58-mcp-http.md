# 58: 验证 MCP Streamable HTTP 双角色

**What to build:** 以独立对端验证无状态 HTTP、严格版本与取消映射；请求断开不取消已持久接纳业务，首期 Tasks 关闭。

**Blocked by:** 56：通过 MCP stdio 调用工具与资源；57：通过 MCP stdio 暴露受控能力

**Status:** ready-for-agent

**能力映射:** C4、C6、C7；A4

**规范依据:** 原生接口与消息目录；扩展清单、运行器与激活恢复。共享实施及报告约束见本工作包规格说明。

- [ ] MCP stdio 既有双角色扩展为 Streamable HTTP 双角色，HTTP 服务端显式 Stateless=true，保持目标 2026-07-28 严格模式及既定 SDK/补丁锁定。
- [ ] HTTP 身份及第三方认证按适配配置映射真实主体，不转交宽权限长期凭证；入站/出站分别验证版本、权限及资源可见范围。
- [ ] 开启请求 context 的取消传播以收束等待，但已持久接纳操作拥有独立生命周期，HTTP 断开不直接改写业务失败或取消。
- [ ] 实际取消经受控请求及效果核对，回包丢失按原关联恢复；严格出站模式不能隐式退旧握手，首期 Tasks 明确未启用。
- [ ] 用独立服务端和客户端分别验证两方向、错误包装、版本拒绝、连接断开及取消，分别记录 stdio 与 HTTP 支持组合，不能只依赖自连。
- [ ] 提供可重复验证入口，记录实现/依赖、配置、环境、执行方法、实际结果与限制；未运行或失败不写成通过。
