## Agent Brief

**Category:** enhancement

**Summary:** 建立跨能力入口的持久资源控制，在 TAKEOVER 接纳后阻止冲突自动化启动，可靠处置在途动作后报告落实；RESUME 经独立授权和新观察重新准入，旧资格不能继续写。

**Current behavior:**

Execution 已按固定能力接纳调用并消费许可，Driver 在启动状态持久化后与独立目标交互；取消、异步关联、可信进度、有限核验和报告 Outbox 可恢复。Core 管理任务控制及原工作处置。未知效果及冲突证据保留占用，取消受理不等于停止。

当前只有单能力账本级 Active 占用，缺少类型化资源控制记录、控制修订和跨入口冲突映射。不同描述符无法直接共用当前账本；现有取消只针对单次调用，无法阻止另一任务从另一 API 入口启动。资源业务版本、任务/Worker 资格和资源控制版本尚未形成可验证的共同准入。

**Desired behavior:**

继续使用能力调用领域和消费方 Interface；资源控制事实由执行协调管理，Task 权威仍由 Core 管理。资源接管不是任务所有权移交，也不要求创建额外任务或全局会话身份。调整现有单描述符存储边界，使不同能力/实现可在相同资源控制范围内协作；各调用仍固定自己的准确版本、Schema、语义、授权及历史报告，不通过删除描述校验或更换旧调用版本来实现共存。

建立受信组装的资源范围与能力入口映射。同一业务资源的同步/异步入口共享控制权威、控制修订及冲突准入；不同独立范围不因一个资源接管而被全局阻塞。参考部署使用同一持久权威下的多个协调实例，不能各自依靠进程锁授予控制。能力声明或宿主映射确定作用范围，普通请求不能自报“不冲突”而绕过检查。别名指向相同资源时统一处理；无法精确映射时仅在权限覆盖内保守扩大范围，超出权限或无法确认控制覆盖时明确拒绝/报告限制。

CapabilityService.RequestResourceControl 接收稳定操作身份、命名空间及已有资源的类型化引用、TAKEOVER/RESUME 意图、预期控制版本和所需授权上下文；GetResourceControl 提供当前获准可见的意图、落实进展、版本及有界阻塞摘要。控制原回执可以核对，原请求重放不重新推进控制版本；新请求才比较预期版本，相同身份不同语义或跨操作类型复用明确拒绝。原操作重放与当前控制查询分开表达，不把新进展伪装成当时的原接纳回执。若提供 RequestTakeover 便捷入口，只解析原调用所属资源并转交同一逻辑操作身份，不另建接管意图。

控制请求接纳、去重/回执、控制意图修订及必要处置工作原子保存。TAKEOVER 接纳与该范围所有入口的首次启动登记在同一适用持久边界排序；接管先提交则后续启动拒绝，先登记的动作进入在途集合，不遗漏已接纳但尚未发送或“可能已发送”的工作。必须覆盖重放、多个任务、两个入口和独立协调实例，不把查询控制后再独立写启动记录的检查窗口当作原子保障。

接管后阻止适用的新业务动作，使用稳定且可恢复的处置交接取消/核对既有调用。资源控制请求、派生取消操作和原执行操作保持不同身份及因果关系；重启不重复创建取消身份、不重发可能已执行的动作、不再次消费原业务许可。控制权威依真实受信主体及适用处置授权协调，不伪造原调用主体，也不以接管为由向请求者披露其他调用的私密结果。

接管落实要求所有适用入口已受约束，在途动作已可靠停止或完成处置，且已排除仍可能改变资源的旧请求。取消已返回、租约/心跳超时、本地槽位空闲、查询不到作业、或只更新本地控制版本都不足以证明这一点。参考目标应提供可以独立验证的旧请求隔离或足够停止证据；控制版本只有在相应目标/执行路径真正核验时才构成隔离。对不可取消、仍未知、证据矛盾或不能保证停止的路径，保留接管待落实及明确限制；收尾预算耗尽不伪造已落实。已发生的效果继续按原操作记录。

已受理与已落实的进展持久可查，迟到完成/停止、重复报告及旧处置 Worker 不能覆盖新的控制意图。资源级处置可以复用 11 票机制，但不得只处理发起者当前的一次调用而漏掉同范围其他工作。可靠控制/交接记录容量不足时拒绝新增请求或保留待处理状态，不静默删除记录。

RESUME 是新的独立授权操作，不能作为超时后的默认动作。恢复前核对未决调用、旧请求隔离条件和当前资源状态，取得有明确来源、范围及版本的观察；观察与最终准入之间发生用户修改或控制变化时，目标版本前提/控制修订必须使旧准入失效或报告明确限制。恢复先获准接纳不意味着自动化已可运行，只有必要条件满足才报告落实。

用户在接管期间对模拟业务资源的修改是独立目标事实，恢复必须重新观察并使用新前提。旧 Worker、旧控制版本、旧业务观察或迟到 RESUME 请求不能继续写；同一已知 RESUME 重放仅返回原回执，不重开此后再次 TAKEOVER 的控制。恢复不重写旧调用资格、不重发未知 Start、不清空 Task 的暂停/取消、输入失效或其他等待原因，由 Core 决定是否有新的合法工作。

控制修订、资源业务版本和任务/Worker 代次分别保留职责。协调方失联时新冲突动作等待或拒绝，不因心跳过期建立第二个可授予控制的权威。Harness 范围外的第三方写入不能被本地锁住；参考目标通过独立变化及前提失败证明这项限制，而非宣称控制了任意外部入口。

所有资源/映射/控制操作/处置工作/在途引用/报告数量、查询页大小、输入及摘要、I/O/轮询/恢复次数和并发均有显式有限配置。业务额度与收尾额度分开，未知份额不回收；多个资源的恢复调度有界且不会被单个未决资源永久挡住。来源、用途、处理位置、留存与读取权限沿用现有受控内容约束，公共控制查询只披露获准的状态及摘要。

**Key interfaces:**

- CapabilityService.RequestResourceControl / GetResourceControl / 原控制回执查询与 SDK：类型化资源、准确控制版本、当前权限、重放及进展语义。
- 受信资源范围映射与共同准入接口：跨能力/实现入口的冲突归属、授权内范围扩大和不同独立资源隔离。
- ExecutionStore.Load / Commit / LookupCommit / ListRecoverable：资源控制修订、原子启动/接管、处置交接、Worker 资格及公平有界恢复。
- ExecutionDriver / 资源观察及隔离接口：同步/异步动作、Cancel/Inspect、原请求隔离证据及恢复所需新观察；不暴露供应商或数据库实现对象。
- Core / RunStore / 任务控制与 ExecutionReport：原调用效果与资源控制分离，保留任务暂停/取消，按原工作幂等处置。
- GrantAuthority / 受控内容：资源控制、恢复、核验和读取的权限边界；原业务许可不重复消费。
- 参考组装与具名 profile：两个不同模拟 API 入口、共同业务目标、独立资源、多协调实例、用户修改、旧请求及真实进程故障。

**Acceptance criteria:**
