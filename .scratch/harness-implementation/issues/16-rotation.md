## Agent Brief

**Category:** enhancement

**Summary:** 在现有凭证密文与受信出口上建立可恢复的主密钥轮换和第三方续期操作，密钥清理同时受现存记录及允许备份约束。

**Current behavior:** 已有独立文件版本化密钥、先持久后交付的 nonce 预留、AES-GCM 目标绑定、单条凭证修订 CAS 和固定出口调用。手动 Generate/Rewrap 可以保留旧钥匙，但没有操作身份关联的批次进度；没有受控第三方续期或备份引用退役流程。

**Desired behavior / Key interfaces:**

- 轮换用稳定的 Operation 身份记录可信绑定、旧/新版本和逐条进展。同一身份重放恢复原工作，载荷冲突拒绝；一次只执行有界批次，不建立隐式无限循环。权限复查先于管理变更及披露。
- KeySource 将新材料准备、校验和激活区分；操作身份使准备与激活可核对，失败、未知提交或重启不能无界产生新版本。所有仍需读取的旧版本保持可用。
- 密文替换及该条轮换进度在同一持久事务中提交；进程退出或提交结果不明时读取原操作与记录，不能仅凭内存游标跳过或重复业务动作。普通新写入与轮换、清理遵守同一版本围栏，不允许已清理版本重新进入数据库。
- 受信提供方 Adapter 固定服务、账号、Driver、主体、用途及位置。续期意图先持久，再执行外部请求；结果丢失时核对原操作。只有提供方证明未发生且其契约允许时才有限补发，相同逻辑续期保持身份；不可核对则明确等待核验，不新建续期逃避未知效果。
- 续期得到的秘密只在受信 Adapter/Broker 路径进入加密库，普通结果仅含受控引用、版本、状态和固定错误码；验证新凭证能在实际目标使用，拒绝旧凭证不被假成功响应遮蔽。
- 允许备份有受信引用记录及密钥版本集合；实际备份材料按私有文件持久化并核对摘要。旧密钥退役检查现存密文、未完成轮换及允许备份；备份处置在实际移除/失效确认后更新引用。引用未处置、旧记录存在或版本不确定时拒绝清理。
- 参考实现保留 Go、SQLite 和独立文件密钥；接口由消费方定义。采用有界持久记录、批次和超时，达到上限明确失败。数据库旧快照/身份克隆仍需受信恢复隔离，不能声称 AEAD 自动证明新鲜；文件保护边界沿 15 票。

**Acceptance criteria / agreed test seams:**

- 通过管理入口或 SDK 驱动完整轮换，从真实 SQLite 重开并依据原操作继续；逐条更新前后退出进程，验证密文与进度一致、并行读写分别使用正确版本、重复身份不产生新密钥。
- 在 KeySource 准备、校验、激活及本地提交边界注入失败；坏材料不激活、未知提交读取原记录、不复用 nonce。缺失旧钥匙和损坏密文导致固定错误，不破坏其他可用凭证。
- 使用独立有状态的本地 HTTP 提供方模拟真实令牌续期、丢失回包和原操作核对；验证续期只产生获准效果、最多两次获准补发、实际后续凭证调用成功，错误/报告无秘密正文。
- 用实际受限备份文件验证旧钥匙仍被引用时不能清除，记录迁移且允许备份处置完才删除；测试并发新写入、重复轮换、恢复旧数据库及恢复隔离的明确边界。
