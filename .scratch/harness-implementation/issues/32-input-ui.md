# 32: 从 UI 回应任务及授权等待

**What to build:** 输入或批准绑定有效等待项及范围，沿同一操作转交；多端竞答、取消与批准竞态不重复消费或越权。

**Blocked by:** 31：呈现并提交无任务 UI 交互；09：接收补充输入并重新决策

**Status:** ready-for-agent

**能力映射:** C5、C6、C7；A4

**规范依据:** 端侧 UI 交互与协议扩展；授权生命周期、凭证与控制接口；决策准入、交互与协作恢复。共享实施及报告约束见本工作包规格说明。

- [ ] UI 展示任务等待项并以原 operation_id/interaction_id 转交 ProvideInput 或 SubmitUpdate，有效输入实际改变后续任务。
- [ ] 授权等待项由授权模块管理，批准绑定真实回应者、原资源/动作/范围和请求版本；回应与授权签发在 AuthorizationStore 原子核验保存。
- [ ] 任务、UI、授权库间以原操作幂等交接；提交回包丢失恢复原结果，不把等待项已消费误作新非法输入。
- [ ] 两端不同操作竞答、旧问题新回应、撤销或过期等待项明确处置，普通呈现或关闭不能自动同意。
- [ ] 任务取消与批准竞争时新授权不能清除任务控制；资源接管/恢复动作沿既有受控模块转交，分别呈现接纳与落实。
- [ ] 具有既有持续授权的工作不再逐次弹窗；隐私字段只呈现给获准端和回应主体。
- [ ] 提供可重复验证入口，记录实现/依赖、配置、环境、执行方法、实际结果与限制；未运行或失败不写成通过。
