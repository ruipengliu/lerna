## Agent Brief

**Category:** enhancement

**Summary:** 在持久任务接纳之上建立有界 Worker 运行闭环，由脚本化 Brain 提出完整结果，Core 以当前授权、版本和领取资格原子提交，并验证竞争与进程恢复。

**Current behavior:**
前置 03 已完成受控任务接纳、QUEUED 状态、初始 decide 工作、内部提交回执和真实 SQLite 恢复查询。按 Worker、领取、续租、租约、Brain、决策提案及状态推进等概念检查任务服务、RunStore、SDK、Protobuf 和持久任务 profile 后，尚无 Worker 或 Brain 实现；RunStore 对既有任务推进明确返回不支持，SDK 仅接受 QUEUED、初始状态版本和拥有者世代。MaxSteps 与 DeadlineUnix 已保存，但尚未落实运行预算。未发现相关历史拒绝记录。维护者已确认 enhancement 分类、保持 ready-for-agent，以及下述运行、恢复和范围边界。

**Desired behavior:**
获准任务从已有持久工作开始，Core 原子领取工作、记录本次运行资格和决策额度，再在存储事务之外调用脚本化 Brain.Decide。Brain 接收版本化任务快照、目标及约束、剩余步数和已有工作摘要，只返回完整结构化结果提案或明确失败；不持有存储写入口，不自行修改任务、生成授权或执行外部动作。Core 验证结果结构、任务版本、当前资格及完成条件后，将结果、COMPLETED 状态、执行记录、工作完成和内部提交回执一起保存，调用者可经原任务查询接口观察。

同一 Task Owner 下可以有多个 Worker，但同一工作只有当前领取代次有权推进。领取带有限有效期；过期重领复用原工作身份并递增代次，原 Worker 迟到续租或提交被拒绝。owner_ref、owner_epoch、state_version、领取代次及适用期限在提交边界共同检查，候选查询和先前授权判断不构成永久执行资格。进程重启恢复原逻辑拥有者，不把进程身份当作新的 Task Owner，也不因连接或进程变化创建第二份任务。

本票运行的是脚本决策，不产生模型费用或外部业务副作用。仍须实际限制决策次数、任务期限、单次调用及重试，恢复不能重置已用或已占用额度。租约到期只允许有条件地重领，不代表旧提案有效或任务已失败。授权失效、预算不足、输入/提案不支持或依赖不可用要形成可解释的有界停止结果；持久化不可用时先停止新工作，不把尚未保存的状态报告为已落盘。

提交结果未知时核对原 change_id；原提交已成功则返回原结果，不重新生成已接纳工作。提案尚未持久准入且无法恢复时，允许在剩余额度内重新调用脚本 Brain，不承诺 Brain 调用恰好一次。任务已有终态或工作已完成时，重启、补发和迟到结果不得使其重新执行。

**Key interfaces:**
- `Brain.Decide`：输入版本化的受控任务快照和本轮有限预算，输出完整结果提案或可辨认的领域失败；脚本实现用于验证，供应商或数据库具体对象不进入接口。
- Core 的运行入口：协调领取、有限决策、提案校验、完成及恢复核对；拥有状态推进权，不能仅凭 Brain 返回成功就无条件写入终态。
- 工作存储的领取、续租和完成接口：以原工作身份、Worker 领取代次、有效期和任务前置条件约束原子更新；重复请求与未知结果保留可核对身份，不能因为回包丢失盲目增加领取代次。
- `RunStore.Commit/LookupCommit/Load/ListRecoverable`：在 03 的创建契约上增加本票必要的受约束推进；任务、结果、工作、决策额度、执行记录及回执保持同一持久化单元，候选查询不授予领取资格。
- 调度选择与 Worker 唤醒接口：分别负责有界候选中的顺序选择和处理触发，可独立替换；任务权威状态、租约、预算和终态不另存于调度器私有内存。
- 时间与运行配置：复用可替换受信时间来源，显式配置有限领取期限、续租规则、决策调用时限、重试上限及并发边界；明确 MaxSteps 对决策尝试的计数规则、配置合法范围和持久化方式。
- TaskService、SDK 与 Protobuf：支持读取本票新增状态、版本、完整结果及停止原因，持续按当前权限披露；保留原 Submit/LookupOperation 的去重和接纳含义，不向外开放任意状态、拥有者或领取凭据写入。

**Acceptance criteria:**
- [x] 通过既有受控入口提交任务，经可运行 Worker 和脚本 Brain 完成 QUEUED → RUNNING → COMPLETED；调用者经 SDK/Get 读取持久化完整结果，关闭并重开原 SQLite 文件后仍可核对。Brain 输出与 Core 正式完成结果明确区分。
- [x] Brain 输入基于领取及额度预留后的任务版本，输出关联该版本；在调用期间任务事实或资格变化时，旧提案不能覆盖新状态。未知必需类型、无效结构、超大输出、非本票支持的动作请求或不满足完成条件的提案不得提交成功终态。
- [x] 领取、续租和完成与相关任务变更共享 SQLite 原子边界，提交检查当前 owner、epoch、state_version、领取代次、有效期及适用当前授权。普通持有提交/读取权限的调用者不能自行制造 Worker 资格；受信运行入口的授权绑定和作用域明确，不使用安装管理员身份自动放行业务。
- [x] 两个独立 Worker 竞争同一工作，只有当前有效代次可推进；用不同数据库句柄交错候选查询、领取、续租及提交，证明资格变化后旧提交被拒绝。不能仅以进程内互斥锁或断言调用次数作为排他性证据。
- [x] 有效期内按规则续租保持同一领取身份；已过期、被重领或已完成的旧领取不能复活。过期重领沿用原工作并递增代次，原 Worker 的迟到提案、续租和完成不能覆盖新领取；领取/续租回包丢失后可核对原提交，不重复产生工作或无依据地提升代次。
- [x] 领取元数据更新与任务决策版本之间的关系写入契约并经过验证：合法续租不得导致同一有效 Worker 必然无法提交，而真正改变任务事实或资格的更新必须使旧提案失效。不能用忽略所有版本变化来规避续租冲突。
- [x] MaxSteps 至少约束脚本决策尝试数，在调用前持久占用额度；成功、失败、超时及崩溃导致的不确定尝试均不因重启或重试免费重置。新调用必须有剩余额度，单次调用、重试和并发均有明确上限，Brain 不得自行放宽约束。
- [x] DeadlineUnix、领取期限、当前主体/授权期限分别判定；期限到达或受信时间异常后不得发起新的受限决策。授权失效与运行提交竞争时重新校验，记录可披露原因且不扩大权限；恢复核对已有提交不会被误当作新的 Brain 调用。
- [x] 为授权不足、预算耗尽、任务到期、无效提案和暂时不可用明确停止原因及 WAITING/FAILED 等适用状态。可恢复条件等待，无恢复路径且已无待核对工作时才失败；采用有界重试，终态不重开。无需本票提供预算调整或用户恢复接口。
- [x] 完成提交原子保存正式结果、任务状态与新版本、工作完成、额度状态、执行记录及提交回执；相同 change_id 同内容重试返回原结果，不同语义返回身份冲突，新提交的旧版本或旧领取明确拒绝。恢复查询不再将已完成工作作为可执行候选。
- [x] 使用真实 SQLite 文件和独立子进程，在领取提交前后、提案生成后准入前、完成提交后回包丢失等位置中断。重启核对原任务、工作和内部提交；未准入提案可在预算内重新生成，已接纳结果不重复发布，不能仅凭一次未查到或超时认定原提交永远不会成功。
- [x] 存储不可用时停止新领取、Brain 调用或无依据重试，不报告尚未持久的 RUNNING/COMPLETED；已有未知提交保留原身份供恢复。Brain 调用位于事务外，停机或调用超时有有界结束机制，迟到返回不得继续推进状态。
- [x] 调度选择、Worker 唤醒和 Brain 通过消费方接口组装，替代实现可独立提供有效行为。内存 Adapter 运行基础共同契约且标明临时状态，真实 SQLite 单独提供进程恢复证据；不把内存测试声明为第二耐久后端。
- [x] SDK、Protobuf 和查询允许本票合法的新状态、递增版本及结果，不再将所有非初始任务快照判为无效；原任务操作身份及当前读取权限继续生效。对旧持久任务和本票新增存储字段给出明确兼容或迁移策略，不通过删除原数据库完成升级。
- [x] 提供具名可重复验证 profile，覆盖成功运行、双 Worker、租约过期重领、迟到提案、版本竞争、预算/期限停止、当前授权失效、存储不可用及真实进程恢复。记录实现/依赖、配置、环境、方法、实际结果和限制；01–03 的适用回归保持通过，旧 profile 的未实现声明只按实际证据更新，不改写既有历史报告。

**Out of scope:**
- 用户暂停、取消、明确恢复及其在途处置由 05 实现；本票仅落实运行所需的停止与资格规则，不预实现完整控制协议。
- 真实 Model Adapter、token/金额用量结算、流式生成和完整上下文/产物生命周期由 07、08 及后续票实现；本票脚本结果不作为真实模型能力或答案质量证据。
- 外部业务 API、设备 GUI、长期记忆写入、子任务委派、多分支工作流及其他外部副作用；不声明外部动作恰好一次。
- 跨节点所有权移交、自动故障接管、远程 Worker 协议、gRPC/WebSocket 服务、完整分布式授权及第二耐久后端。
- 调度性能优化、无界后台服务、动态配置迁移及全量预算调整系统；新增必要字段与现有任务的兼容必须在本票说明和验证。
