# 06: 签发、派生和撤销受限授权

**What to build:** 管理者签发绑定接收方的 ES256 授权，委派只收缩；原操作核对、祖先撤销及配额预留可恢复。

**Blocked by:** 02：初始化本地身份、策略与授权

**Status:** ready-for-agent

**Implementation:** completed

**Category:** enhancement

**能力映射:** C7；C5；A4

**规范依据:** 授权生命周期、凭证与控制接口。共享实施及报告约束见本工作包规格说明。

- [x] Issue/Derive/Revoke/Get 经有权主体执行，授权记录、管理回执、预留及通知原子保存，提交不明核对原操作。
- [x] ES256 JWS 材料固定算法及 Harness 类型/版本，验证 iss/sub/aud/iat/nbf/exp、受信密钥映射与实际出示证书摘要绑定；错误算法、受众、签发者和未知限制拒绝。
- [x] 派生授权对所有祖先的资源、动作、用途、位置、期限、深度与额度取限制；不采信请求自报归属，无法证明收缩则拒绝。
- [x] 签名可在事务外准备，提交时复验策略修订；签名成功但提交冲突或结果未知不交付未获确认材料。
- [x] 配额先持久预留并绑定接收方和原操作，再交付；重复交付不双倍分配，失联或未知消费不释放占用；实际业务消费由处理模块在自身原子边界落实。
- [x] 撤销父授权约束派生授权，分别表达权威提交与远端应用；独立 JOSE/证书绑定夹具核验签名编码与重放拒绝。
- [x] 提供可重复验证入口，记录实现/依赖、配置、环境、执行方法、实际结果与限制；未运行或失败不写成通过。

**Desired behavior:**
策略、Grant 权威记录与签名材料分别表达。Issue/Derive/Revoke/Get 由当前有权主体调用，签发权不能从普通执行权隐式取得。管理请求沿用稳定 operation_id 与修订前提；认证和披露权限先于原操作核对，原操作去重先于新操作版本比较。相同身份的不同语义拒绝，跨管理、任务和控制类型不能重新解释原操作。

签发固定 Harness 类型/版本的 ES256 JWS 材料，明确签发者、主体、目标接收方、代理出示者、授权引用、时间区间及必要限制。验证方从受信配置取得签发者与密钥映射，按当前受信连接上下文核对实际出示证书摘要及代理关系；请求自报主体、证书摘要或远程密钥地址不能建立信任。材料合法只证明特定签名及声明成立，仍须检查当前可知的策略、完整祖先链、撤销与处理端可落实的限制。

Derive 显式引用父授权及其修订，只能在所有祖先的有效范围内授予权利。资源关系来自受信登记，动作、用途、位置、时间区间、代理限制、委派深度与额度均须可判定收缩；等范围仅在原授权允许继续委派时成立。缺失祖先、循环、超深、未知必需限制或无法证明包含关系均拒绝。根签发与委派的管理权限分别核验，不通过多个不相关授权拼出一个更宽的委派。

签名可在事务外准备，但交付前必须原子确认授权记录、对应签名材料或其可恢复记录、管理回执、额度预留及必要通知，并在提交时重新核验当前权限、策略和父授权修订。签名成功不代表签发提交成功；修订冲突、签名不可用或提交结果未知时不交付未确认材料。恢复使用原操作和已确认内容，不能重新分配额度或隐式变成新签发；重签或续期不能修改原授权范围或延长原期限。

受限次数/额度在权威端先预留并绑定接收方，单次许可还绑定目标逻辑操作及语义。管理签发操作与获准业务操作的身份和用途明确区分。父级自用额度及分配给各接收方、各派生授权的额度不能重复花用；多级预留不重置上级余额，重试交付不增加分配，失联、过期或撤销本身不证明未知消费可退还。任务预算和授权额度分别管理，Evaluate 的纯判定不隐式消费。实际业务消费仍由对应处理模块在其启动/业务提交原子边界落实，本票提供可用的绑定及核验契约，并用有状态接收方夹具验证交接语义。

Revoke 原子提交权威撤销与待通知记录。验证父授权已撤销时，其子孙不能再获准新工作；已有实际效果仍由业务模块核对，撤销不代表已取消。Get 分别呈现权威提交、各接收方待应用与已应用，发送成功或持久接收回执不能代替应用事实。本票用受信、可控接收方验证应用确认和重放边界，不建设端云可靠传输或完整同步系统。

**Key interfaces:**
- `GrantAuthority`：Issue / Derive / Revoke / Get 的消费方契约，结合现有管理操作查询提供稳定回执、授权状态和可披露材料。
- `Authorizer` / 签名材料验证入口：保持纯判定，输入受信出示上下文、目标动作及原操作绑定，返回可落实限制与策略/撤销依据；不接受普通业务参数覆盖身份。
- `AuthorizationStore`：在同一权威范围内原子保存 Grant、预留、撤销、回执及待通知状态，保留未知操作恢复和旧接纳窗口防重放语义。
- 签名器、受信密钥来源及出示者上下文：由宿主受控组装，与具体 JOSE 库、存储和未来 mTLS 适配解耦。接收方的受信身份不能由材料自行声明为有效。
- 额度预留及应用确认契约：原接收方、授权链和操作绑定有界可核对，不暴露可任意退还额度或伪造远端应用的管理捷径。
- 配置：签名格式、受信密钥映射、有效期与允许时钟偏差、链深度、求值/存储/材料大小及记录容量均显式有界；缺少必需配置拒绝启用，依赖版本在实施时固定并记录。

**Acceptance criteria:**
- [x] 正式 SDK/本地协议入口可执行 Issue/Derive/Revoke/Get 及原操作查询；当前主体、资源和管理权限约束签发、派生、撤销、材料披露，越权或跨命名空间请求无部分写入。
- [x] 保留现有本地持续授权行为及范围限制；新增签名授权不是任意 LocalGrant 的无条件升级。旧 SQLite 授权和运行记录可读取，升级后原回执及任务/控制恢复保持有效，不删除数据库升级。
- [x] 固定 ES256、Harness 类型/版本及有界编码，实际核验 iss/sub/aud/iat/nbf/exp、授权引用、代理关系、受信 kid 映射和 cnf.x5t#S256。错误算法、篡改、未知签发者/密钥、错误接收方、证书错绑、过期、未生效、未知必需限制均拒绝。
- [x] 独立 JOSE 实现或独立标准向量验证签名编码和互操作，不能仅由同一实现自签自验；证书绑定输入来自夹具验证后的实际证书上下文，不能靠请求自报摘要通过。
- [x] 派生链包含多级祖先，逐维验证资源、动作、用途、位置、完整时间区间、代理范围、深度与额度；扩大任一维度、伪造资源归属、缺失/循环祖先及超限求值均拒绝。

- [x] 所有材料、链、记录、检查和 I/O 有限；超限及存储不可用返回明确错误并保留未知占用。签发私钥不进入普通协议、模型输入、日志或错误文本；受信配置与文件注入不依赖外部密钥服务。
