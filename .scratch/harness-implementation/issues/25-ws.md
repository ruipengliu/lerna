**Desired behavior:**

两个持有独立私钥和持久节点登记的端/云进程建立实际 WebSocket 连接；固定 bootstrap 在开放业务消息前协商主版本、必要/可选能力和有限资源配置。双方可在同一连接上同时发起目录及状态查询，接收准确关联的响应，并仅向已订阅且当前获准的接收者推送可合并进度。连接身份由实际 mTLS 对端与当前登记资格确定，主体代理、命名空间、用途、位置和披露范围经受信宿主绑定与业务授权校验；远端字段不能选择本地凭据或扩大权限。

复用已有领域服务、固定消息及 Schema 注册器，扩展共同 Envelope 所需的最小受支持子集。动态载荷绑定具名类型、版本、Schema 标识及摘要，只使用登记资源校验。WebSocket 帧重组和应用分块分别限制单项与累计资源；控制消息保留有限发送预算，临时进度允许明确合并，可靠类别不能按临时进度规则丢弃。队列耗尽、超时及不支持的行为对调用者可观察。

本票只开放查询和可合并进度。可靠业务变更及持久恢复留给 26 号票；其能力在协商和调用入口均明确不支持。查询响应的连接内交付不宣称持久化回执；断连后可按原目标重新查询、重新订阅，连接关闭不取消任务或改变操作身份。

**Key interfaces:**

- `Envelope` 及固定 bootstrap 消息：明确请求、响应、订阅/事件和必要控制载荷，关联已协商版本、消息、方向独立的流、交付类别及调用上下文；保持既有字段编号和样例兼容性。
- `CapabilityRequest` / `CapabilityResponse`、目录 `List/Search/Describe` 及状态读取接口：按显式支持清单接入同一领域用例；状态查询目标留在方法载荷中，查询自身不伪造变更操作身份。
- `nodetls.Endpoint`、`GrantPresentation` 与业务授权适配：认证实际对端后由宿主构造上下文，并对响应/订阅披露复核当前资格与权限；本地位置限制须按已批准部署范围处理，不能通过把远端请求标成 local 绕过。
- `DynamicPayload` / `schema.Registry`：沿用精确绑定、离线 Schema 资源及严格 JSON 校验，未知必需类型或不匹配版本明确拒绝。
- WebSocket 绑定与 SDK：两方向均可请求、响应和订阅；公开有限连接、请求、流、消息、分块重组、分类队列、窗口及读写/握手等待预算，协商值不得放宽本地硬上限。

**Acceptance criteria:**

- [x] 使用两个独立端/云进程、独立节点目录与私钥，经真实 mTLS WebSocket 完成握手和业务交换；覆盖无证书、不可信对端、自报主体越权及登记禁用。连接建立成功不替代业务授权。
- [x] 固定 bootstrap 验证无共同版本、缺必需能力、可选能力关闭、非法或超限预算、未协商业务消息；配置过期或重连必须重新协商，旧配置不能沿用。
- [x] 同一连接上两端同时执行已授权的目录 List/Search/Describe 和状态查询、订阅进度；与对应进程内用例比较业务结果和错误，精确版本及授权外目录信息不泄露。明确记录实际支持的状态方法和部署位置。
- [x] 请求、响应和事件具有有效 message_id/reply_to 关联；覆盖乱序响应、错误关联、超时后迟到响应。stream_id/seq 按发送方向及流独立处理，进度合并后的缺口语义明确，不冒充可靠连续确认或全局顺序。
