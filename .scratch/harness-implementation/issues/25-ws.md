# 25: 通过端云通道双向查询和推送

**What to build:** 真实 WebSocket 协商版本与能力，双向请求和订阅进度；限制消息、分块和队列，拒绝未知必需类型。

**Blocked by:** 23：登记节点并验证双向 TLS 身份；13：在千级目录中检索准确版本

**Status:** ready-for-agent

**能力映射:** C5、C6、C7；A3、A4

**规范依据:** 内部契约与外部协议映射；原生接口与消息目录。共享实施及报告约束见本工作包规格说明。

- [ ] 两个独立端/云进程经真实 mTLS WebSocket 连接，固定 bootstrap 协商业务主版本、必要能力和有限消息/分块/窗口限制。
- [ ] 每条二进制消息使用共同 Protobuf Envelope，两端可同时发起已授权目录/状态查询并接收关联响应、已订阅进度；自报主体不能建立权限。
- [ ] message_id/reply_to 关联消息，stream_id/seq 按方向独立计数；连接重建不改变业务操作身份，不声称全局顺序。
- [ ] 动态具名载荷绑定版本与 Schema，未知必需类型拒绝；JSON 不作为第二套生产线协议，重组前即限制累计大小。
- [ ] 控制、可靠结果、临时进度及大内容分别受队列和额度约束，慢消费者触发明确背压，必要控制不被静默丢弃。
- [ ] 本切片演示查询和可合并进度；可靠业务变更未具恢复实现时明确不支持，不能提前开放会在断连后丢失的写入。
- [ ] 提供可重复验证入口，记录实现/依赖、配置、环境、执行方法、实际结果与限制；未运行或失败不写成通过。
