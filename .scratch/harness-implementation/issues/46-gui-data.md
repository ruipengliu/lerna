# 46: 构建 GUI 两种观察模式基准

**What to build:** 形成 400 个任务的可执行及边界集合，核验动作覆盖、2–8 步路径、兜底资格和独立状态真值。

**Blocked by:** 35：通过图像完成模拟 GUI 动作；36：按资格从 API 切换到 GUI

**Status:** ready-for-agent

**能力映射:** C4、C8；V2

**规范依据:** 专项验收、持久化替换与实施交接；执行接口、资源控制与故障验证。共享实施及报告约束见本工作包规格说明。

- [ ] 生成并核验 400 个 GUI 任务：结构树和图像各 200，每模式 150 可执行、50 边界；模式分别保留分母及可比较业务任务族。
- [ ] 每模式可执行组中点击、滑动、输入、返回各至少出现在 30 例，追加与替换输入各至少 15 例，允许重叠；正确路径 2–8 个动作。
- [ ] 每模式至少 30 个可执行任务明确无 API 或 API 能力不足；50 边界任务中陈旧观察、权限拒绝、API 未知效果、用户接管、断连重连各至少 10。
- [ ] 独立模拟业务状态、动作历史和控制状态作为真值，图像模型不可读取树或隐藏坐标；等待/拒绝正确只能计对应边界组。
- [ ] 冻结每任务模型 16 次/token 262144、新操作 24/辅助查询 128、600 秒及共同纠错/重发/并发限制，正常多动作推进不当纠错。
- [ ] 数据验证工具检查动作覆盖、控制断言、错误副作用和重置隔离，生成合规范围及缺口报告，不需要真机。
- [ ] 提供可重复验证入口，记录实现/依赖、配置、环境、执行方法、实际结果与限制；未运行或失败不写成通过。
