# 57: 通过 MCP stdio 暴露受控能力

**What to build:** 入站仅暴露明确选择且获准的工具/资源，严格版本及主体映射；外部调用无法直接改任务终态或读库。

**Blocked by:** 50：准备并激活受信能力插件；11：恢复异步与未知效果调用

**Status:** ready-for-agent

**能力映射:** C4、C6、C7；A4

**规范依据:** 内部契约与外部协议映射；扩展清单、运行器与激活恢复。共享实施及报告约束见本工作包规格说明。

- [ ] 固定目标版本和 SDK 基线，stdio 入站服务仅暴露管理者明确选择的 Harness 工具/资源，独立客户端可发现并完成受权调用。
- [ ] stdio 启动配置将本地调用者映射到受信主体及范围，不能将匿名外部参数当任意用户；发现、读取、执行均重新授权。
- [ ] 入站在业务分发前严格验证版本、方法和声明能力，禁止不支持 Tasks；错误映射保持业务失败、未知效果及取消能力差异。
- [ ] 外部输入经正式能力入口持久接纳，维护原操作与外部请求关联；资源读取不自动写长期记忆，不能公开 Store 或任意终态写入。
- [ ] 用独立对端验证隐藏资源不泄露、越权拒绝、重复/断流、工具失败及取消竞态；缺标准幂等支持时如实表述恢复边界。
- [ ] 提供可重复验证入口，记录实现/依赖、配置、环境、执行方法、实际结果与限制；未运行或失败不写成通过。
