## Agent Brief

**Category:** enhancement

**Summary:** 在同一任务身份下完成源 Task Owner 封存与唯一目标激活，持久移交恢复责任，并在进程退出、消息丢失及迟到事实下防止双拥有者调度。

**Current behavior:**

Task 持久保存拥有者和世代；Worker、生成与执行路径检查当前资格，任务控制、效果核对、可靠投递、有限离线授权和内部 Agent 子任务已有实现。普通 RunStore 提交不允许改变拥有者和世代。尚无可执行的同任务所有权迁移状态机、受控检查点传递、唯一激活决定及其崩溃恢复。

**Desired behavior:**

所有权移交保持原 task_ref 和逻辑操作身份，管理阶段与任务业务状态、控制意图分别保存。源端从 ACTIVE 进入 PREPARING 时持久记录原移交操作与唯一目标，停止该任务的新调度、续发执行资格和新委派。其他无关任务仍可运行。既有工作须结束、明确停止或保留待核对记录；封存前须能证明旧执行端不能再启动新动作，不能只依赖源库拒绝提交、本地超时猜测或连接断开。无法证明时有限等待并保留责任。

检查点包含任务事实、目标及输入引用、工作和操作记录、预算及未结算预留、控制意图与进展、有效等待项、父子委派关系、效果待核对项、路由以及适用的接纳窗口/关闭水位和去重信息。仅传递目标获准处理、保存且可恢复的内容；无法合法取得必要恢复资料时拒绝或等待，不绕过驻留与披露策略。检查点摘要针对明确保存的字节，不能假设重新编码天然一致。目标校验并持久准备后仍无业务推进或执行权。

源端在同一本地原子提交中保存 SEALED、唯一目标、新世代和绑定任务、双方、旧/新世代、确切检查点版本及摘要的激活凭据/Outbox。只有确认原封存提交成功后才发送凭据。准备后状态版本变化须重新准备一致检查点；冻结期间迟到结果和控制/输入请求应经受信身份与原操作核对，持久保存转交义务或给出可恢复的明确未受理结果，不能悄悄修改已准备的权威快照或丢弃已受理事实。

目标在当前来源、授权和准备内容匹配时按原移交幂等激活新世代。目标仅在激活提交确认后领取工作；旧 Worker 资格不转化为新执行权。移交不延长原授权、期限或额度，不清除 PAUSE/CANCEL、未知效果及子任务处置义务。父任务迁移只迁移其委派关系、预算责任和结果路由，子任务继续由各自拥有者管理；既有子端绑定必须能核对合法的新父拥有者，而非重建子任务或重发额度。

封存或激活提交结果未知时按原 change_id/移交操作查询，不新建另一移交。重复凭据只返回原结果，不再次增加世代；不同目标、版本或摘要复用原操作明确冲突。源端封存后保留路由和迟到事实转交记录，不能因目标超时、回执丢失或永久不可达回到 ACTIVE。源端未封存且未发有效激活凭据时才可安全取消准备；目标继续移交也遵守同一协议。

参考故障模型覆盖持久存储未回滚的进程和网络故障。旧备份、存储回滚及并行身份克隆须在恢复入口隔离调度并核验权威；缺少排他证据时不开放执行。不能声称仅靠较旧 SQLite 副本中的自述状态即可证明唯一拥有者。

**Key interfaces:**

- Task/RunSnapshot、RunStore：独立管理阶段、原移交身份、完整检查点、唯一封存/激活决定与可查询提交结果；保持任务级原子边界。
- Worker、生成、执行与 DelegationPort：准备/封存阶段停止新工作，实际动作启动检查旧资格失效；已开始工作及子任务继续保留核对责任。
- TaskService 控制、SubmitUpdate、等待项和执行报告：冻结期间已受理事实的持久转交、原操作去重和当前拥有者核验。
- ChildPort、委派报告和路由：父身份移交后保持原子任务、原操作、预算及结果关联，不用重建委派替代路由更新。
- 授权与认证协议绑定：当前移交权限、双方身份、检查点驻留/披露、激活材料校验；传输回执不替代业务封存或激活。
- 有限配置：检查点大小、待转交记录/队列、批次、I/O、重试及核对预算；容量不足保留明确恢复义务，不能清理未履约记录。

**Acceptance criteria:**

- [x] 同一 task_ref 在独立持久存储的源/目标间实际移交；新世代唯一激活，完整恢复任务、操作、预算、控制、等待项、委派关系及接纳水位。父迁移不迁移或重建既有子任务。
- [x] PREPARING 和 SEALED 拒绝源端新领取、续发资格、模型请求、行动与委派；目标仅准备时无法执行。独立动作目标证明旧执行端在封存后不能启动新效果，不能只断言数据库状态。
- [x] 旧执行资格失效无法证明时移交等待；已开始动作和未知效果保留核对，不把停发新动作等同已停止全部工作。无关健康任务仍可推进。
- [x] 封存和唯一激活 Outbox 同事务提交；失败不留下可发送激活凭据。提交结果未知按原提交恢复；重复激活不重复增加世代，不产生第二目标或第二份预算。
- [x] 未准备、错任务/双方/世代/版本/摘要、伪造或当前权限不允许的激活被拒绝；检查点内容不被重编码差异或迟到事实静默替换，驻留及披露限制实际生效。
- [x] 在源准备、目标准备、源封存提交前后、激活投递、目标激活提交前后和回包窗口逐一注入真实进程退出或提交故障/丢包，重启核对原记录；任一窗口最多一个可调度拥有者。区分真实退出与模拟故障。
- [x] 未封存准备可安全取消；源封存后即使目标永久不可达也不自动恢复 ACTIVE，重试不改变唯一目标。目标再次移交仍遵守同一约束。
- [x] 冻结期间迟到结果、控制/输入及子报告的已受理事实可持久转交并按原身份去重；新拥有者核对效果，旧 Worker 不直接推进状态。暂停、取消、待回应项及未知预留在迁移后不消失。
- [x] 已关闭接纳窗口迁移后仍拒绝旧操作首次接纳；既有操作和子任务查询保留原关联，不借路由变化重新执行或分配额度。
- [x] 旧备份/回滚或并行身份克隆恢复进入隔离，无法核验唯一权威时不执行；报告明确不支持仅凭失联、心跳超时或人工强制按钮的自动故障接管。
- [x] 检查点、队列、I/O、重试与核对资源超限有明确拒绝或等待验证，不丢失封存、转交及效果核对义务。
- [x] 提供可重复验证入口与持久报告，记录冻结代码、依赖、配置、环境、拓扑、故障窗口、原移交/任务关联、实际副作用和恢复结果；运行受影响回归，分别列出通过、失败、基线及未执行范围，不以状态桩或旧测试替代移交实证。

**Out of scope:**

- 无排他性证据的自动故障接管、无限重试或目标丢失后的自动反向激活。
- 多主任务权威、共识集群、跨节点数据库原子事务或任意远程 Store 写入接口。
- 默认迁移/取消全部子任务、重新创建任务身份、延长权限或重复派发预算。
- 自动绕过数据驻留与披露策略、复制不必要的签名私钥或独立记忆权威。
- 在受控宿主已被攻破时仅靠本地存储实现防克隆/防回滚的保证。
- 重开已确认架构决策，或把本机进程/网络故障验证等同真实模型质量、生产自动接管和完整系统验收。
