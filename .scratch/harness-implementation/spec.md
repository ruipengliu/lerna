## 每票的完成边界

每张实现票从调用者可观察的行为切入，交付该行为需要的接口/Schema、可运行入口、状态及适用的用户反馈，并用独立结果核对正常与失败路径。无界面需求的行为可由 SDK、CLI 或模拟端验证，不为每项能力强制增加 Web 页面。

先固定该票所需契约、可观察错误和正反例夹具，再实现完整切片。复用已提供的公共基础，尚未支持的行为明确拒绝；不得先开放无授权写入、不可靠重试或隐私外发，等待后续验收票“补安全”。后续协议与替换票补齐适用调用位置的真实绑定及共同验证。

适用实现依赖消费方 Interface，数据库、模型供应商、SDK 和连接对象留在 Adapter 内。首次实现不预建所有远程服务、通用基类或完整市场；后续票沿已固定的能力边界扩展。代码及规范不以具体文件数量验收。

每票必须记录输入条件、所用版本/配置、执行方法、实际输出和限制。独立真实模型效果、模拟状态、进程/协议故障、持久化、统计及实际联网的证据分别表达，不能相互替代。对仅增加可逆文档的本次票据发布只做文档检查，不运行尚不存在的业务测试。

## 已确认的共同约束

| 方面 | 实施要求 |
| --- | --- |
| 定位与部署 | 通用开源架构；Go 核心，单机默认 SQLite，无必需独立数据库/队列/工作流服务；多模拟设备，不要求真机。模型与联网服务按能力配置。 |
| 逻辑责任 | Core 推进任务权威状态，Brain 提出有限决策，Execution 报告事实，Memory 管理受控信息；角色不固定为进程或端云位置。 |
| 协议 | 四个基础领域；进程内 Interface，同侧 IPC 用 gRPC，端云用 WebSocket；Proto 固定结构与 JSON Schema 2020-12 动态参数。UI 契约可扩展且不强制 Task。 |
| 身份与恢复 | 执行调用使用 operation_id，消息关联使用 message_id/reply_to；内部 change_id 独立。当前授权先于结果披露，原操作去重先于新版本比较，关闭窗口水位防止旧操作复活。 |
| 副作用 | 意图/启动状态先持久、外部动作在事务外，未知结果核对原操作；不可用、本地去重或签名不构成外部 exactly-once。控制已受理与已落实分别报告。 |
| 授权 | 主体、资源、动作、用途、位置、期限和委派范围统一判定，祖先限制有效；单次消费在业务原子边界或受控预留交接中落实，未知额度不回收复用。 |
| 记忆与隐私 | 保存、计算、发现、披露、留存分别约束；端侧原文/索引/派生内容及模型、日志、消息、评测出口共同受控；来源失效联动使用及派生资产。 |
| API 与 GUI | API 主路径，GUI 仅在语义及权限满足的兜底条件使用；API 权限拒绝或未知效果不触发重复 GUI 变更。设备状态和模型观察与判定真值隔离。 |
| 扩展 | 精确版本及摘要、受控准备/验证/激活、在途版本固定；普通 Skill 内容与代码分开。MCP/A2A 按既定版本、方向及特性验证，不重开选型。 |
| 自进化 | 已授权普通记忆可自动更新，Skill/策略/Agent 配置经评测逐步启用，代码需维护者对精确资产确认；候选不能控制评分器、保留答案、权限或门槛。 |
| 独立替换 | 两种 Brain 策略与 Model 替换分别留证；Memory 策略替换不同于数据库替换。bbolt 覆盖所选完整配置所需 Store，内存实现不计第二耐久后端。 |

具体依赖基线和完整摘要沿[扩展运行器/SDK 分册](../../docs/architecture/09-extension-contracts-and-activation.md)与[第二后端分册](../../docs/architecture/11-specialized-validation-and-handoff.md)锁定。Go 至少 1.25.0，实际补丁、生成工具及传递依赖在对应实现开始时固定；变更已选依赖需记录依据并保持共同契约，不能运行中自动拉取最新版本。

单步固定 K≥1001 个独立 API、每 API 20 例，首次及成功按逐 API 等权宏平均分别≥90%/95%；多步≥max(2000,K)且满足逐 API 覆盖与 4–6 动作条件，成功≥95%；正确不执行≥1000 例且四类各≥250，正确处理≥95%。V1 固定400/联网120分别逐类验收答案≥90%、引用支持/覆盖各≥95%；V2 共400任务，两模式各可执行150/边界50，分别≥95%；个性化400对，适用回答/行动及四类边界分别≥95%。各组禁止动作、错误副作用、权限和隐私必需断言不能被平均分抵消。

81–85 是一次冻结配置的正式评测和判定交付。形成完整 FAIL 报告可以完成该轮评测记录，但不能作为质量达标依赖；应按诊断增加有界修复票，并以新的受控候选取得所需报告，不能在本票内承诺无限试错直到成功。87 的改善结论和 88 的完整参考版本必须以所有适用门槛通过为前提，而非仅看到上游票已执行完。

每轮最多筛选5候选、冻结1候选后使用独立保留材料。统计默认按适用任务来源族配对重采样10000次、95%区间，先验证假设和边界；不适用明确标记，不能通过换统计方法或样本称已改善。全部门槛、阶段5%/25%/100%及观察窗口按既定规范，不新增更宽松默认值。

## 依赖与实施顺序

88 张票的直接阻塞关系在各文件中列出编号与标题，已去掉重复的传递依赖，无环且阻塞票编号在前。编号分组便于阅读，不为同组制造额外依赖；例如观测、数据工具和后端替换可在其前置完成后提前开展，不必等前面所有票完成。

发布校验修正：80 的验收需要端侧提取、两种 GUI 驱动及兜底、受限运行器的实际证据，因此补入 20、35、36、53 为直接阻塞；34 已经由 35/36 传递覆盖。86 对 36 的直接阻塞因此移除，仍经 80 依赖它。此处只补齐原有能力的执行顺序，不新增票或变更目标，完整专项质量数据与 Wasm 子动作继续按自身票据依赖推进。

ready-for-agent 表示规格可被认领，不表示当前可开始。执行者应核对阻塞票的完成记录、相关能力实际可用及本票必需的输入/配置。01–15 已完成各自限定范围的验收；14 的 Ark 单步包络限制和真实小回归范围另报。18 实施中；19–21 已完成。当前可开始 22、23、34、43、50、67；其他票仍按直接阻塞和实际完成证据判断。无需为已确认的普通实施选择重复请求许可，凭证缺失、真实外部调用费用或维护者发布确认按实际任务授权处理，不伪造条件已满足。

本工作包不更改、重开或关闭原架构决策票。后续实现遇到无法在既定契约内解决的可复现问题时，记录证据和受影响目标，建立有界修复或后续决策；不以新描述隐藏既定需求。
