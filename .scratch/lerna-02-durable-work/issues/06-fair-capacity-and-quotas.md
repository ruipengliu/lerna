# 06: 租户配额、有限队列及控制核对容量

**What to build:** 普通工作饱和时控制、核对和健康租户仍能推进，既有持久责任不会因容量不足被丢弃。

**Blocked by:** 05 — 持久等待与有界扫描

**Status:** ready-for-agent

- [ ] 内部 ordinary／control／reconciliation 类别具有明确独立容量，控制与核对保留正容量；不提前实现未来模型或 Task 服务。
- [ ] 领取并发、租户 lane 配额与公平状态由真实数据库事务保证；在领取和实际处理入口校验资格与额度。多 worker 竞争不超额，不能仅靠进程内 semaphore 声称保证，也不把租约过期当作旧进程已停止。
- [ ] 公平兼顾租户已有分配与等待，有限竞争条件下健康租户在可解释的有界轮次取得进展；普通饱和与正常对照均完成。
- [ ] 有限入队容量在新接纳前生效；临时背压不形成财务 budget_exhausted 或覆盖固定决定，原身份稍后重试仍保持正确裁决。
- [ ] 已有持久责任和原 Job 新修订不因队列满或配额改变被静默删除／忽略；扫描与候选内存均有明确上界。
- [ ] PG／SQLite 共享真实饱和、跨租户、类别竞争及取消／过期 Claim 对照，保留配置、假设、有限截止和实际结果。
