## Question

多模拟设备的状态、观察、动作与故障模型如何定义，工具与设备 Adapter 如何经相同 Interface 验证执行结果，并完整覆盖手机 GUI 的点击、滑动、输入、返回、中断与接管？

用户追加约束：API 调用是主要路径，GUI 用于兜底或无可用 API 对接的第三方应用；支持超过 1000 个 API 的准确调用。因此本票同时决定能力发现与候选选择接口、API 主路径验证及 GUI 切换边界。

## Scope

以用户明确的多模拟设备验证为基线，不要求真实设备或特定操作系统。区分可核对模拟状态的完整行为验证与仅返回成功的桩；覆盖端云断连、重启、取消、权限和未知效果。真实平台 Adapter 留给后续独立验证。

## Expected evidence

给出模拟设备模型、驱动 Interface、观察与动作契约、故障注入方式和能力验收矩阵，明确调用成功与效果确认的区别。

## Comments

本票只解决技术决策或事实调查，不交付业务实现。

验证计划增加多个模拟 UI 端和不同 Renderer 的交互契约验证：聊天输入、表单/卡片、通知动作、自定义组件、能力差异和多窗口路由。与第三方手机 GUI 自动化分开记录；不要求真机或指定 UI 框架。详见 [端侧 UI 交互与协议扩展](../../../docs/architecture/03-ui-interaction-contracts.md)。

恢复方案要求动作开始前核对适用拥有者/Worker 执行资格；旧 Worker 的状态提交被拒绝后，迟到效果仍须作为事实保存和核对。模拟端应覆盖封存/激活、Inbox 已收未处理、双 Worker、取消竞态、临时 UI 最后增量丢失和操作窗口过期。详见 [恢复状态与故障检查表](../../../docs/architecture/04-recovery-state-and-failure-matrix.md)。

已确认端侧记忆挖掘与联合检索按位置及结果披露范围执行；模型、提取和工具 Adapter 的输入、输出、调用参数、日志均需保持数据约束。无本地处理能力时不自动改用云端。模拟节点验证不必使用真实设备。 参见 [记忆设计](../../../docs/architecture/05-memory-and-context.md)。

大脑与协作方案已确认：执行适配须返回可核对的效果，不从半截模型参数执行；目标变更、取消和批次部分失败时保留既有操作身份与实际事实。补偿是另外获准的新操作，不能把失败当作自动回滚。参见 [决策准入、交互与协作恢复](../../../docs/architecture/06-decision-admission-and-collaboration.md)。

### 本轮领取与首轮建议

已领取。本轮读取地图、项目目标、领域词汇及既有执行、协议、恢复和 UI 契约，未重新打开真机选择或核心技术栈。

首轮待用户答复的设计方向：

1. 工具与设备共用能力调用契约，设备观察和动作按能力族扩展；共享执行机制与驱动能力保证分开，公共日志不虚构外部幂等或停止能力。
2. 使用有状态 GUI 模拟环境，覆盖结构化及图像观察配置；测试判定器可核对内部业务状态，大脑只取得公开观察；不要求完整移动操作系统模拟。
3. 同设备 GUI 变更默认串行，不同设备并行；用户接管控制设备范围内所有自动化来源，恢复需明确获准并重新观察，不自动续跑旧动作。
4. 按契约、设备闭环、共享控制、真实协议故障、独立驱动替换和专项能力分别验收；保留多 Renderer 测试及真实联网验证边界，不以单一组合用例代替能力验收。

资产：[工具执行与多模拟设备草案](../../../docs/architecture/07-tools-and-simulated-devices.md)。当前仅记录建议，尚无用户接受本轮建议的答复；详细 Interface、控制生命周期和故障矩阵在方向确认后继续讨论。

### 用户修正：API 为主，GUI 兜底

用户原文：“主要场景还是基于API接口调用，GUI只是作为兜底以及在三方APP无法对接到系统的API生态才使用”。这一执行路径定位已确认，已同步目标 C4、系统结构与执行草案；不视为接受此前全部建议。

相应调整待决建议：主要使用有状态 API 模拟系统验证执行，通过 API/GUI 共用业务状态验证切换及防重复；API 并发按资源和契约控制，不套用整设备 GUI 串行规则；接管还需防止其他 Harness 路径修改同一受控资源。无 API、明确能力不足、暂时错误、权限拒绝及未知效果分别处理，最后两类不能直接触发 GUI 重做。GUI 专项与端侧 UI 交互继续独立验证。

### 用户追加：千级 API 准确调用

用户原文：“效果要求上需要支持1000个以上API能被准确调用”。规模与准确调用效果作为已确认要求同步目标和执行草案；不把这句话解释成用户已确认某个准确率、并发量或真实服务商数量。

待决建议：按独立业务语义的可调用操作计数，千级目录同时参与发现；授权过滤、候选检索与完整 Schema 按需加载；逐层验证候选覆盖、首次语义正确、有界任务成功、正确不执行、副作用和每项覆盖。具体检索接口由本票细化，声明质量和接入生命周期交由扩展票，效果统计和最终里程碑交由评测及实施依赖票。相关资产仍为执行草案，不新建重复问题票。

### 用户确认：调用效果门槛

用户原文：“首次调用正确率要到90%，有限重试后的任务成功率95%”。已将至少 90% 与至少 95% 写入项目目标和执行草案，表示目标门槛，不表示已实测达标。计数、计分、重试预算以及此前架构建议仍待确认。

本轮补充建议：两项独立计分，检索失败和隐藏纠错不能从首次指标排除；错误写入不能靠最后一次正确结果算成功；拒绝类样本单列。验收预算预先固定，具体额度及统计方法由能力评测票确定，且不允许为达标事后放宽。

### 用户接受：计数、分阶段检索与验收原则

用户答复“接受建议”，对应上一轮四项：独立业务操作计数且完整目录同时可用；权限过滤、候选检索及按需加载定义，检索遗漏计错；首次失败不被后续修复改写，错误写入不能靠后来正确动作计成功；评测前固定重试、模型调用及时间预算，有状态 API 验证效果，GUI 单独验证兜底与接管。以上已同步方案。具体接口、共享控制以及前述尚未答复的细节不据此自动标记全部已确认。

### 接口细化轮：待用户答复

资产：[执行接口、资源控制与故障验证](../../../docs/architecture/07-execution-contracts-and-validation.md)。本轮建议：

1. 能力目录提供 List / Search / Describe，先过滤再检索、完整定义按需加载；SQLite 本地目录与可重建文本索引作为起点，语义检索/重排序可替换，按实际千级效果验收；版本、权限和部分覆盖显式表达。

3. API 并发按资源控制、GUI 默认同设备串行。增加资源查询与接管/恢复入口；API 与 GUI 共用受控资源时均受接管约束，恢复重新观察并保持任务已有控制意图。默认由单一可验证的执行协调方管理共享资源，不采用超时抢占；GUI 观察带局部版本，输入区分替换与追加。
4. 两种外部 API 形态通过独立 Adapter 映射同一代表性契约；结构树及图像/坐标设备驱动覆盖 GUI；共同状态验证 API/GUI 切换与接管，UI Renderer 单独验证。通过实际 gRPC/WebSocket 多进程故障注入验证恢复；样本量、聚合统计及固定预算额度交由评测票细化。

## Answer

已形成可据此拆分实现的执行设计，资产为 [工具执行与多模拟设备](../../../docs/architecture/07-tools-and-simulated-devices.md) 和 [执行接口、资源控制与故障验证](../../../docs/architecture/07-execution-contracts-and-validation.md)。

1. API 为主要执行路径，GUI 用于无可对接 API 及适用兜底，仍完整验收 V2。路径切换保留授权、数据位置和效果约束，权限拒绝或未知效果不能触发重复 GUI 动作。
2. 支持超过 1000 项不同业务语义的 API，完整目录同时参与发现；首次调用正确率至少 90%，有限重试后的任务成功率至少 95%。独立计分，候选遗漏计错，错误写入不能因后来执行正确而记成功，评测预算预先固定。
3. CapabilityCatalog 提供 List / Search / Describe，权限与位置过滤后检索候选，按需加载固定版本 Schema。SQLite 目录与嵌入式文本检索为参考起点，语义检索及排序可替换，依据实际效果验证选择；目录与查询遵守端云披露范围。
4. 执行协调管理接纳、准入、去重、恢复和报告；ExecutionDriver 提供 Start / Inspect / Cancel，ExecutionStore 保存执行事实、恢复工作及 Outbox。外部调用不在数据库事务内，异步引用丢失或未知效果须核对；本地去重不产生外部恰好一次保障。
5. GUI 默认同设备串行，API 按业务资源并发。同一受控资源由单一可验证协调方管理；GetResourceControl / RequestResourceControl 表达接管及恢复。接管阻止冲突新动作、处置在途工作后再报告落实；恢复重新观察，保留任务已有暂停或取消。原调用接管转交保持同一操作身份；局部版本不增加全局会话身份。
6. 有状态 API 与 GUI 模拟提供可核对效果；测试判定器与大脑可见观察分开。两种 API Adapter 验证代表性接口替换，结构树及图像驱动分别验证设备能力；同状态 API/GUI 对象验证切换及接管。多 Renderer UI、真实 gRPC/WebSocket 多进程故障及模型效果分别验收，不要求真机。

协议目录、UI 转交语义、系统结构、大脑能力发现、设计约束和领域词汇已同步，目标基线已记录用户追加的规模与效果门槛。后续授权票落实凭证及资源范围权限，扩展票落实声明质量与版本生命周期，评测票固定样本、统计和预算额度，里程碑票收敛各项证据；约束已写入这些票据，不重新打开本轮结论。
