## Question

谁可以推进一个任务及其子任务的状态，端云断连、进程重启与重新连接后如何核对授权、执行记录和外部动作结果？

## Scope

明确任务状态与执行记录持久化、离线执行条件、重复投递与结果不明的处理、取消与远程任务协作。

## Expected evidence

给出拓扑、所有权、状态转移和故障处理表，避免将连接恢复等同于任务恢复。

## Output

计划关联文档：`docs/architecture/04-edge-cloud-and-recovery.md`。

## Comments

已由 Codex 领取，沿用协议、标识与 UI 扩展基线；本票明确所有权及恢复设计，不交付业务实现。

前置内核决策已确认：调度策略及 Worker 机制可替换，但任务生命周期规则归内核；待处理工作与任务变更共同持久化。本票须具体设计节点所有权、领取凭据、旧 Worker 失效和结果未知时的核对机制，区分拒绝旧提交与阻止已发出动作的能力。参见 [Go 内核与本地持久化](../../../docs/architecture/02-runtime-and-state.md)。

协议决策已确认：部署侧进程间 gRPC、端云 WebSocket，固定 Protobuf 信封；可靠消息与临时更新使用不同逻辑流，持久化回执不等于执行确认。本票须落实收发日志、游标与回执保留/过期、双向恢复、背压、连接失效和任务所有权，并验证取消竞态与旧执行者。协议及消息目录已给出应保持的语义。详见 [原生接口与消息目录](../../../docs/architecture/03-contract-message-catalog.md)。

用户已明确同意标识简化，后续设计沿用：执行类 Operation 与调用共用 operation_id，请求关联使用 message_id；Message 与 Operation 仍分层去重，Change 保留内部提交身份。Connection 属于绑定上下文，Interaction 仅在等待输入场景出现。本票需验证原消息补发、新消息引用同一操作、取消目标引用、回执保留不同于执行状态保留等反例。详见 [标识模型简化评估](../../../docs/architecture/03-identifier-model.md)。

UI 扩展要求补入恢复设计：界面快照/增量版本核对（包括末次增量丢失）、surface 重开后的旧消息、多端输入竞争、交互过期/撤销、回执丢失后按原 operation_id 查结果。恢复不可要求所有 UI 交互都绑定 task_ref，也不可将呈现状态当作任务权威。详见 [端侧 UI 交互与协议扩展](../../../docs/architecture/03-ui-interaction-contracts.md)。

## Answer

本决策已完成，形成如下运行契约：

1. 每个任务有唯一逻辑拥有者，端云均可拥有任务；自主工作通过受委派子任务跨节点执行，普通工具调用不强制建立子任务。
2. 离线续跑采用按能力声明的有限期授权，需即时控制的动作在线核验；跨端取消分别表达待送达、受理和落实。
3. 默认支持原拥有者重启与协作移交，先封存旧世代再激活唯一目标；失联不自动强抢，自动故障接管由具备排他性证据的 Adapter 提供。
4. 任务主状态、等待原因、控制意图及进展分开；取消/失败/完成均有相应证据，关键效果未知时保留核对等待。
5. Inbox、业务受理和 Outbox 明确原子边界；跨独立存储通过同一 operation_id 幂等转交与查询恢复，不假定分布式事务。
6. 消息补投有界，业务及提交核对记录覆盖其恢复义务。接纳窗口绑定在操作身份内部，关闭水位先于明细清理持久化，过期旧操作不重新接纳。
7. UI 快照、输入等待项、多端竞争和旧 surface 按各自状态恢复，无须伪造任务；局部故障不阻塞无关工作。

规范见 [端云任务所有权与恢复](../../../docs/architecture/04-edge-cloud-and-recovery.md)和[恢复状态与故障检查表](../../../docs/architecture/04-recovery-state-and-failure-matrix.md)。前置 RunStore 与协议文档已同步，授权材料、可信时间、记忆存储与各 Adapter 实现由已有后续票据承接。

默认故障模型覆盖持久化状态未回滚的进程及网络故障；备份回滚、并行克隆与可选自动接管须另有资格核验和验证证据。本轮仅执行文档链接、一致性及决策依赖检查，未实现运行时或进行故障实验。
