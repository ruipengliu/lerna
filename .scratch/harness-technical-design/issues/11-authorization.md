### 第二轮建议：认证绑定、授权生命周期与凭证实现

研究已完成并整合至 [认证机制报告](../../../docs/research/harness-identity-credentials-and-offline-time.md)；待决方案保存为 [授权生命周期、凭证与控制接口](../../../docs/architecture/08-authorization-lifecycle-and-interfaces.md)。本轮建议：

1. 节点 gRPC/WebSocket 使用 mTLS 与受控登记；浏览器使用同源 HTTPS 服务端会话及 Origin/CSRF 校验，两类认证配置不互相降级。首次本地管理建立信任根，节点加入绑定公钥和命名空间，一次性登录码不放 URL。
2. 采用 ES256 JWS/JWT 的受限签名授权，固定签发者、受众、时间及持有节点证书绑定；签发/验证双方检查委派链收缩、父级撤销及接收方。单次授权绑定原操作并持久消费，持续授权保留范围与期限；签名不代替去重或保密。
3. 有限离线授权按明确时间锚点和期限验证，远端授权在离线重启或时间不确定后等待重新核验；本地权威可在受信本机重新验证，无外部服务启动依赖。不保证未送达撤销即时生效。
4. SQLite 保存 AES-GCM 凭证密文，主密钥由独立受限文件注入以支持本地自动启动，可替换操作系统/外部密钥供应。声明数据库泄漏保护与受控宿主的边界，覆盖轮换、失效及恢复。
5. IdentityVerifier、Authorizer、GrantAuthority、AuthorizationStore 和 CredentialBroker 分工；策略/授权/签名材料分别管理，采用可比较的受限策略表达。管理操作位于任务协作领域，Issue/Derive/Revoke/Policy 更新及 TaskService.AdjustLimits 采用稳定操作身份、版本检查和有权主体；用户确认绑定具体等待内容，既有授权工作不重复询问。

当前五项均为建议，尚待用户答复；未同步为正式协议目录，不关闭授权票。文档检查不代表已完成认证、密码实现或安全实验。

## Answer

已确定身份、授权与凭证的执行位置及生命周期，规范见 [身份、授权与用户控制](../../../docs/architecture/08-authorization-and-user-control.md) 和 [授权生命周期、凭证与控制接口](../../../docs/architecture/08-authorization-lifecycle-and-interfaces.md)。

1. 本地受信管理入口建立身份及信任根，节点加入绑定公钥与命名空间。原生节点间 gRPC/WebSocket 使用 mTLS；浏览器使用独立的同源 HTTPS 会话、Origin/CSRF 校验。原始主体、代理执行者和节点分别验证，身份认证不自动授予业务权限。
2. IdentityVerifier、Authorizer、GrantAuthority、AuthorizationStore 与 CredentialBroker 按接口分工。内嵌 Go 判定及 SQLite 策略/授权记录为参考；资源、动作、用途、位置、期限与委派范围使用可比较的受限表达。已存在的单次/持续授权直接使用，不逐次重复询问。
3. 跨节点采用 ES256 JWS/JWT 受限格式，核对签发者、接收方、时间、类型及实际出示节点证书绑定；签名不替代持久去重、保密或当前资格检查。父子授权保持收缩及祖先撤销约束，签发权不能从执行权隐式产生。
4. 策略、授权、签名材料与单次消费分别管理。签发预留、执行消费、撤销通知和快照/连续变更明确各自本地原子边界；跨节点结果未知保留预留并核对。有限离线授权不保证撤销即时生效；离线重启及时间不确定默认重新核验，单机本地权威无需外部云服务即可按受信环境恢复。
5. 第三方凭证仅经受信执行路径按目标、账号、用途和允许位置使用；普通上下文只取得受控引用。默认 SQLite 存 AES-GCM 密文，独立受限文件注入主密钥，可替换更强密钥供应实现；明确数据库单独泄漏与宿主失陷的保护边界，覆盖轮换和失效恢复。
6. 授权管理属于任务协作领域，签发/派生/撤销、策略更新及 TaskService.AdjustLimits 使用稳定操作身份、授权和版本比较。确认绑定授权模块的原等待项，任务/UI 通过幂等交接消费；不清除任务暂停、取消或未知额度。扩展进程内仅受信代码，其他信任级别必须声明实际隔离保障。

规范已补全单次消费、管理提交、快照/游标、用户确认、节点身份、材料转发和轮换等恢复细节，并同步协议目录、UI、端云恢复、记忆、大脑、执行、结构入口及领域词汇。官方依据来自已完成的 [认证机制研究](15-auth-mechanism-evidence.md)，其报告与分支提交均已记录。

后续扩展票决定可安装隔离实现与扩展生命周期；评测票落实本册故障矩阵、实际拒绝及泄漏检查；里程碑票固定实现/测试配置和证据。具体依赖版本在实现时锁定并验证，期限参数须有限且由受权配置指定。无需另建重复决策票，默认自主发布权限保持。
