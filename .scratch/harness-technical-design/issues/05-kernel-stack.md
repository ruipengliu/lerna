## Answer

本决策已完成，采纳以下方案：

1. Go 内核拥有 Harness 任务状态机；大脑提出行动，执行系统报告事实，调度适配不能另立任务终态。
2. 持久化采用当前状态加执行日志。一次任务变更原子提交状态、记录和待处理工作；版本冲突、重复提交和结果未知分别处理。
3. 核心作为可嵌入 Go 库，由独立入口组装；默认进程内调用，通过远程 Adapter 扩展，并提供单机多进程验证。
4. 运行存储按任务语义提供加载、原子提交、提交核对和恢复扫描接口。实现细节留在 Adapter 内；生命周期校验归内核。
5. 调度策略与 Worker 执行机制可替换；运行存储和工作存储共同保持原子性，旧 Worker 的提交须受资格约束。
6. SQLite 与内存参考实现共跑基础契约；完整部署使用 SQLite，耐久性须实测进程重启。不同持久化后端的互换证据由第二个持久化实现另行提供，不能用内存测试替代。

面向实现的规范见 [Go 内核与本地持久化](../../../docs/architecture/02-runtime-and-state.md)。详细消息 Schema、端云所有权机制与能力里程碑分别交由现有后续票据，本票没有未答复的路线取舍。
