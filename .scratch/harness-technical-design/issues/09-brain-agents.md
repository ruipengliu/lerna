## Question

大脑如何接收上下文、生成行动和委派请求、消费结果并判断任务完成，如何让内部及外部 Agent 保持清楚的运行责任？

## Expected evidence

给出决策循环和协作流程，并明确参考大脑可替换时必须保持的行为。

## Comments

已由 codex 领取；本票只解决技术决策或事实调查，不交付业务实现。

大脑与应用模块可以发布受控交互请求，输入绑定明确等待项；UI Renderer 仅负责呈现与采集。需要支持无任务 UI 交互，不通过伪造任务或直接修改内核终态接入。详见 [端侧 UI 交互与协议扩展](../../../docs/architecture/03-ui-interaction-contracts.md)。

端云任务按唯一逻辑拥有者运行，自主委派建立独立子任务，普通远程工具调用不强制拆子任务。主状态/等待原因/控制意图分离；大脑不得因模型重启或连接恢复清除取消/暂停意图，也不得用不明动作结果判定完成。详见 [恢复状态与故障检查表](../../../docs/architecture/04-recovery-state-and-failure-matrix.md)。

### 第一轮：决策循环、模型替换、Agent 协作与停止条件

方案：[大脑循环与多 Agent 协作](../../../docs/architecture/06-brain-and-agent-collaboration.md)。用户回复“接受建议”，本轮四项方向已确认。

1. 采用有限决策步，由 Brain.Decide 提出结构化下一步，内核校验、持久化并调度；计划可调整，简单问答不强制完整规划。
2. Brain 与 Model 两处独立替换，模型能力和处理位置明确声明；完整提案校验后才能准入，回退不能放宽数据约束。
3. 以父任务协调、子任务自主运行作为参考协作，支持串行、并行和汇总；补充交流通过受控输入，外部 Agent 保留自身运行责任与能力差异。
4. 以目标验收依据及有限预算约束完成和自主运行，完整成功不得掩盖必要分支的失败或未知效果；部分结果可以显式交付。

方向确认后继续细化提案准入与恢复、流式 UI 与用户插入输入、协作失败与取消、父子预算和替换验证。已确认的内核权威、端云和记忆边界不重开。

### 第二轮：准入恢复、持续交互、协作收敛与预算

方案：[决策准入、交互与协作恢复](../../../docs/architecture/06-decision-admission-and-collaboration.md)。用户再次回复“接受建议”，以下四组运行规则已确认。

1. 一个有限提案在所属任务内整体准入，持久化工作与预算预留原子提交；跨任务、外部动作按既定协议独立受理。提交不明先查询，恢复优先继续已准入工作；参考实现严格拒绝旧任务版本提案，大脑升级不抹掉旧工作。
2. 支持运行中正式追加输入和修改目标，持久化后使旧提案失效；已发动作按实际状态取消或核对。参考默认流式展示进度、完整校验后发布答案；可选受控答案预览明确草稿和不可撤回披露的限制。
3. 子任务在委派时明确必需性与验收条件；必要分支失败只停止依赖于它的工作，独立分支可继续。父任务收尾前处置全部所辖子任务；不明效果先核对，不默认脱离父任务继续后台运行。
4. 持久化任务预算与按委派预留的子额度，先分配后使用；未确认停止与结算的额度不回收重用。预算不足可等待明确增加或按既定期限失败，取消和核对使用另设的有界处置额度；无法提供精确计费保证时明确限制。

验证草案覆盖版本竞争、崩溃、输入插入、流式失效、子任务失败与取消、端侧私有结果、离线预算、模型替换；尚未执行运行测试。

## Answer

用户通过两轮实时答复分别接受总体方向和运行细节，本票已解决。

1. 大脑以 Brain.Decide 输出有限结构化提案，内核以任务版本、拥有者和 Worker 资格整体准入，原子保存工作、预算与 Outbox；外部效果和跨任务接纳分别确认。旧版本提案严格拒绝，提交未知先查询，重启恢复既有操作。
2. Brain 与 Model 独立替换，模型能力、处理位置及输出差异经 Adapter 表达。完整输出和临时增量分开；不依赖模型私有会话恢复，不完整工具参数不得执行。决策所用实现与上下文版本可追溯，升级不清除已准入工作。
3. TaskService.SubmitUpdate 接纳正式补充信息及目标修改，沿用操作身份、来源和版本检查；具体等待项仍由 ProvideInput 处理。新输入使旧提案失效，已发生动作仍核对。参考答案完整校验后发布，受控预览明确草稿与披露限制。
4. 以父任务协调、子任务自主运行完成串行、并行和汇总，保留外部 Agent 自身运行责任。委派固定必需性与验收条件；失败按依赖影响，父任务收尾先处置所辖工作。受限端侧推理只返回允许结果，失联不等于无数据或已停止。
5. 预算持久预留、按委派分配、核对后结算，不因重连或未知用量释放额度；离线只能使用已有有效份额。目标工作与必要处置使用分别受限的额度，效果未知时不伪造终态。精确外部账单上限只在 Adapter 可提供相应保证时承诺。
6. 完成基于验收依据与实际效果，部分结果与完整成功分别表达。共同契约验证覆盖替换、恢复、输入竞争、UI 增量、协作失败与预算；模型质量、联网问答和 GUI 实际效果独立验收。

两份大脑分册已定稿，协议目录、UI 交互说明、结构入口与领域词汇已同步。文档链接、表格、票据依赖和差异格式已检查；尚无模型实验、运行故障测试或性能结果。

后续责任保留在已有票据：模拟执行验证动作与补偿能力；授权明确目标/预算修改权限及凭据落实；扩展明确版本兼容和激活；观测评测明确用量、版本及效果证据；里程碑明确各验证环境和量化门槛。本轮未出现需另建票的独立设计问题，也未重新选择已确认的端云或隐私策略。
