## Question

任务上下文、运行状态、长期记忆、证据与产物如何关联，如何落实来源、适用范围、纠正、删除和跨端同步的独立权限？

## Scope

定义对象生命周期、存储职责、检索与上下文组织、同步与用户控制；候选存储事实不足时增加独立研究票。

## Expected evidence

给出数据模型、读写与同步流程及用户控制的可验证语义，不把摘要作为唯一事实记录。

## Output

已确认方案：[上下文、记忆与同步](../../../docs/architecture/05-memory-and-context.md)、[记忆数据契约与生命周期](../../../docs/architecture/05-memory-data-and-lifecycle.md)、[端云记忆驻留与联合检索](../../../docs/architecture/05-edge-cloud-memory.md)。

## Comments

已由 codex 领取；本票只解决技术决策或事实调查，不交付业务实现。

协议决策已提供 Query/Get/Put/Correct/Delete 操作、动态 Schema 与版本冲突表达。本票细化记录模型、来源与用途、同步和删除传播，避免把读取资源自动视为长期保存授权。详见 [原生接口与消息目录](../../../docs/architecture/03-contract-message-catalog.md)。

端云恢复已确认。记忆或独立 UI 存储与运行存储分离时，按同一 operation_id 幂等转交且能查询受理结果；不能依赖隐式跨库事务。需协调删除/纠正与仍需保留的最小恢复记录，区分接纳窗口、离线授权和记忆用途期限。详见 [恢复状态与故障检查表](../../../docs/architecture/04-recovery-state-and-failure-matrix.md)。

### 第一轮：数据表达、上下文组织与同步权威

已核对目标 C2/C7、领域词汇、MemoryService 契约和端云恢复约束。本轮不重新询问既有权限边界，不选择第三方存储产品。

1. **记忆记录如何统一而不丢失语义？** 建议使用带类型、来源、置信度、适用范围和修订版本的统一记忆记录；事实、偏好、推断与经验区分表达。上下文、运行状态、证据和产物维持各自生命周期并通过引用关联。代价是维护版本和派生依赖；避免无结构文本把治理责任推给每个调用方，也避免每类记忆独立建一套系统。
2. **首版检索与上下文组织保证到哪一层？** 建议受控检索与有预算的上下文组装分别提供可替换 Interface；参考实现以元数据和文本检索完整运行，语义检索、重排和压缩可增强。保留来源与裁剪信息，缺少必要约束时显式失败。代价是基础语义召回可能较弱，须以实际个性化效果评价，不能把关键词命中等同能力完成。
3. **多个端如何提交同一份共享记忆？** 建议每个记忆集合有一个可位于端或云的逻辑修改权威，其他端按授权同步副本；非权威端离线修改作为待提交意图，重连做版本冲突检查，不按设备时间静默覆盖。独立本地集合仍可离线正式写入。代价是非权威副本断连时无法完成共享正式写入；多主写入另行扩展和验收。

用户回复：“接受建议”。上述三个方向已确认，已同步主分册及领域词汇。本票保持 claimed，继续细化依赖它们的生命周期与恢复语义；不提前追加 Answer 或写入地图已决事项。

### 第二轮：生命周期与恢复

关联草案：[记忆数据契约与生命周期](../../../docs/architecture/05-memory-data-and-lifecycle.md)。记录与 Interface 为已确认方向的展开；以下三项行为取舍已获用户确认。

1. **删除保证到什么范围和完成度？** 建议删除覆盖受控内容副本、索引、缓存与派生摘要，分别报告权威提交、本地停止使用、副本传播和归档清理；离线副本显示待处理，严格用途要求在线校验。保留不含正文的必要防重放元数据，旧副本及备份必须核验后重建，不能恢复已删除内容。外部来源、已导出副本和已发生动作明确界定控制范围。代价是需要持续跟踪传播及清理，不能承诺断连节点即时完成。
2. **固定上下文与最新纠正如何兼容？** 建议每次决策固定来源修订，但在发送模型前、模型返回后及答案发布/新动作准入时检查适用性；已知依赖失效则重新组装和决策，必要输入缺失则等待。运行中的动作按既定停止与效果核对处理，历史事实不改写；离线使用遵守有限授权与新鲜度要求。代价是多一次或多次核验，信息频繁变化可能导致重算或等待，不承诺跨节点全局原子撤销。
3. **离线冲突和同步缺口是否自动消解？** 建议修改按预期修订提交，冲突显式交由用户或获准业务策略决定；操作受理不明先查询，未受理且窗口过期不自动换身份。同步采用一致快照边界加增量游标，副本事务性应用，游标/权限视图失效时重建并清理旧数据；待提交修改隔离保存。代价是冲突可能需要介入，重建需要传输成本；避免静默覆盖或把过期动作当新动作。

用户回复：“接受建议；记忆要考虑端云结合，部分重要隐私数据无法全部上云，但需要被检索到；端侧数据也会别挖掘，存储策略哪些数据在端还是在云需要明确；”。前半句确认第二轮三项建议；补充要求扩大本票内的数据驻留、联合检索和端侧挖掘设计深度，不能当作对尚未提出的默认策略的确认。保持 claimed，继续本票。

### 第三轮：端云驻留、联合检索和端侧挖掘

关联方案：[端云记忆驻留与联合检索](../../../docs/architecture/05-edge-cloud-memory.md)。用户补充要求已写入目标 C2、设计硬约束和领域词汇；以下默认策略已获第三轮答复确认。

1. **哪些数据默认在端、哪些可在云？** 建议采用“严格留端、原文留端但允许有限结果、明确授权共享、获准云端资料”四种参考配置；未分类个人数据不自动上云。原文、目录/元数据、索引/向量、派生内容和备份分别限制保存与计算位置。集合默认策略由记录及来源限制收缩；持有完整受限内容的修改权威必须处在获准处理位置。代价是更多策略元数据及端侧资源消耗。
2. **原文不离端时如何被检索到？** 建议将查询路由到获准节点，在数据所在处检索，仅返回允许的字段、引用或计算结果；严格留端内容可由端侧合并、推理和直接呈现，云端不默认获知具体命中。目录不保存全量私有语义索引。端离线时只使用许可且满足新鲜度的已有投影，否则部分应答或等待；不具端侧计算能力时明确不足。代价是全局召回和时延受端侧可用性影响，云侧可能无法独立完成答案合成。
3. **挖掘内容是否自动共享？** 建议端侧在已有读取、提取、保存授权内运行挖掘并自动积累记忆；推断、摘要与向量继承来源限制，转换和结果披露必须有对应授权。持续授权可自动生效，不要求每条都确认；模型不能自行判断脱敏成功后放宽限制。来源纠正删除传播到派生内容。代价是依赖跟踪与输出检查，不把“短摘要”当作天然可上云数据。

第三轮用户回复：“接受建议”。端云存储矩阵、查询到数据所在处执行和端侧挖掘继承来源限制三项均已确认。补充方案给出策略矩阵、联合检索 Interface、端侧提取流程及多模拟节点的验证设计，没有运行测试结果。

## Answer

通过三轮用户答复完成本票，所有建议均获确认；第二轮答复另增加端侧隐私数据可检索、端侧挖掘及明确存储位置的要求，并在第三轮确定实现策略。

1. **统一模型与明确生命周期**：长期记忆采用带类型、来源、置信判断、适用范围和版本的记录；上下文、内核事实、证据及产物分别管理，以类型化引用关联。摘要及索引可重建，不作为唯一事实记录。
2. **可替换的检索和上下文组织**：基础文本/元数据检索可单机运行；语义检索、摘要及组装策略可替换。上下文固定来源修订并有界组织，在模型输入、返回及新行动/答案发布前检查依赖失效，缺少必要信息则重建或等待。
3. **单一修改权威与恢复**：每集合一个逻辑修改权威，非权威离线修改作为待提交意图；预期修订冲突显式返回。独立 MemoryStore 原子更新记录、操作回执及同步变更，复用 operation_id 核对未知结果；同步快照与增量有明确边界，副本应用与游标原子更新，失效视图重建。
4. **纠正删除**：分维度报告权威提交、本地使用、副本传播及归档清理；派生内容随源失效，离线副本不伪造完成。内容清理与最小防重放记录分离，旧副本和备份先核验再恢复，外部已发生效果不改写。
5. **端云驻留与联合检索**：分别约束保存、处理、可发现、结果披露与留存，采用严格留端、原文留端但允许有限结果、授权共享和获准云端资料四类配置。查询在获准的数据位置运行；私有信息可端侧合并和呈现，无本地能力时明确不足，离线来源不被当成零命中。
6. **端侧挖掘**：在持续授权内读取、提取并保存记忆；派生事实、偏好、摘要、向量与推断继承来源限制，结果外发需相应授权。用户无需逐条确认已授权行为，模型不能自行放宽驻留或披露限制。

方案已写入上述三个分册，MemoryService 结果查询与 MemorySyncService 已同步到 [原生接口与消息目录](../../../docs/architecture/03-contract-message-catalog.md)。领域词汇、目标 C2、设计约束及后续票据已同步。协议 Schema、代码、运行实验和性能数据属于后续实施，不在本票伪造完成。

后续票据承接的事项：大脑落实端侧受限推理与上下文检查；授权落实受信位置、策略凭证及有效时间；扩展落实声明和隔离；观测/自进化落实派生内容治理；里程碑落实能力与故障测试。默认基线不包含集合权威自动接管、多主自动合并或特殊隐私计算 Adapter；这些扩展必须独立声明并验证，不阻塞当前参考实现。
