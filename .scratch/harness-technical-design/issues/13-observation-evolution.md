### 第二轮建议：接口、基准与发布条件

详细方案：[评测接口、参考基准与发布判定](../../../docs/architecture/10-evaluation-contracts-and-release-gates.md)。以下均为待确认的工程配置及政策，没有把研究结论当作已实测门槛。

1. Observation、Evaluation、Evaluator、Evolution 分别负责诊断、评测运行、评分和候选发布；管理接口归入任务协作领域，局部 Store 与持久交接恢复，评测结束、通过、证据完整性分别记录。
2. K 至少 1001；单步每 API 20 例、10 个来源族，首次宏平均至少 90%、任务成功宏平均至少 95%；多步至少 max(2000,K) 例、每 API 出现于至少 4 个任务，任务成功至少 95%。正确不执行至少 1000 例单列，拟议通过率 95%，禁止动作硬失败。
3. 每任务最多 2 轮纠错；单步/多步分别最多 4/12 次模型请求、65536/262144 token、3/12 个新执行类操作、32/128 次辅助查询、120/600 秒，每操作最多 2 次传输补发；参考并发和 Wasm 资源额度在详细分册列明，不声称这些数值保证精度或性能。
4. 固定基准按点估计达标；区间报告明确假设，参考按 API 分层、族整体配对 bootstrap，95% 区间，10000 次重采样，方法实施验证前不得用于正式推断。自动质量优化的主指标固定为首次正确率，改善差值下界大于 0，其他任务成功点分不低于基线，代价不高于基线 110%，全部绝对和强制门槛保持。
5. 开发/验证每轮最多筛选 5 个候选，只冻结 1 个送独立保留确认；采用 5%/25%/100% 阶段，新任务保持版本，前两阶段分别至少 200/1000 个可核对任务及 24 小时，最长 7 天，证据不足不晋级，违规立即停止并按现有契约处置。
6. 默认诊断元数据 30 天、获准正文最多 7 天、评测/发布最小报告元数据 90 天，遵守来源更短期限；私有评测正文不默认复制。专项能力仍需单列真实模型与证据判定，具体专项规模随能力里程碑落实。

## Answer

已完成观测评测与自进化技术决策，规范见 [运行观测、能力评测与受控自进化](../../../docs/architecture/10-observation-evaluation-and-evolution.md) 和 [评测接口、参考基准与发布判定](../../../docs/architecture/10-evaluation-contracts-and-release-gates.md)。

- 业务模块持久维护权威事实，Observation 组织诊断、覆盖和受控投影；诊断可以采样，正式判分证据不能靠采样成功片段代替。接口、评测与发布管理沿已有任务协作领域，不新增通用协议身份或存储直写入口。
- Evaluation 管理不可变计划和隔离运行，Evaluator 依预定真值评分，Evolution 维护候选及阶段；各自局部原子提交与稳定操作交接，取消和重启核对原任务，运行结束、通过与证据完整性分别表达。
- K 至少 1001，单步每 API 20 例，首次宏平均至少 90%、有界成功宏平均至少 95%；多步至少 max(2000,K) 例且每 API 至少参与 4 个任务，完整成功至少 95%；正确不执行至少 1000 例单列。覆盖、模板族及错误事实不能通过合并分数或重复计样本隐藏。
- 每任务最多 2 轮纠错；单步/多步模型请求上限 4/12、token 65536/262144、新执行操作 3/12、辅助查询 32/128、时间 120/600 秒；每操作补发最多 2 次，参考并发与 Wasm 配额按详细分册锁定。预算内未完成算未成功；设施重测保留原尝试，不挑最好一次。
- 固定基准按点估计验收，统计区间仅在假设与方法已验证时解释。参考固定目录下分层、族整体配对 bootstrap；自动质量优化要求主首次正确率的改善区间下界大于 0、任务成功点分不降及代价在容忍范围内。无法推断不自动发布；研究常数或参考配置不保证统计精度或模型达标。
- 候选筛选与保留确认隔离，参考每轮筛选最多 5 个、冻结 1 个独立确认。实际启用按 5%/25%/100%，前两阶段至少 200/1000 个可核对任务及 24 小时、最长 7 天，违规立即处置，证据不足不晋级；代码发布仍需维护者确认。
- 诊断元数据 30 天、获准正文最多 7 天、评测/发布最小元数据 90 天，遵守更短来源约束。删除或用途变化可使证据失效并阻止新晋级，不能借恢复或评测保存已禁止内容；已发生事实不被回滚改写。
