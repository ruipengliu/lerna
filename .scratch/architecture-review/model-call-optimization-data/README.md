# 模型调用优化：限定前提下的合成投影

本目录回答“已有语义理解结果之后，哪些决策可以在固定前提下用规则重新生成”。它保留原基线数据，新增四个**调用层派生投影**；不是完整可重演的协议包，也不是已实现的 Harness。所有产品、设备、来源、授权、模型返回及检查时间沿用或派生自合成 fixture。

## 投影与真实持久化的边界

每个零模型条目保存新的 `DecisionRequest`、固定输入摘要、完整处理来源、符合现行 schema 的 `DecisionRecord` 与重新构造的 `Proposal`。零模型 `DecisionRecord` **省略** `model_call` 字段；外层 `model_calls=[]`、模型费用为零，任务总费用未知。规则输出并不免除 Decision 的接纳、恢复 job、固定终态、Orchestrator 的当前准入与单独消费。费用为零只指这轮未发物理模型生成，内容处理或执行成本仍需另外核算。

这些 JSON 是磁盘上实际保存的**合成期望记录**。DecisionStore 事务、原命令回执、当前 Grant/use、与新 Decision 绑定的费用预留、新 Content owner 发布及来源策略继承均未执行。新身份由独立 fixture 命名空间确定性分配；新正文引用的 SHA-256 与字节数覆盖实际文件，但不是 Content owner 已提交的证明。`completed` 只表达依赖成功后的预期终态。拿到真实运行环境后，缺少任一依赖必须继续等待或拒绝，不能把本目录当作完成凭据。

保留的模型轮只引用原基线记录与物理调用身份，未声称在新候选路径上重新运行过它们。各条目的 `source_baseline` / `source` 给出相对文件、JSON Pointer 和选定值的摘要。对照基线快照的数字修订并不意味着已经创建了一条新的完整 Task 时间线。

## 规则命中条件与回退

共同前提是 D1 条件补全已被消费，目标进入 g2；D1 同提案中其余动作或计划全部丢弃，并留下新决策责任。规则读取之后的固定快照，不复用失效 Proposal。当前目标、控制、设备和能力绑定、处理资格、预算及期限必须仍有效；不存在未核清效果和必要上下文缺口。此处的当前门禁值是明确列出的合成假设，实际实现必须向相应 owner 取证。零模型路径仍经过现有 ProposalValidator 和 Orchestrator 准入。

表格描述候选需要满足的条件；本目录构造器的测试范围更窄：完整目标正文（含原 `user_text`）、D1 已接受的完整 Requirement（含准确 `rule_ref`、`source_ref`）与完整能力声明/绑定必须精确匹配冻结 fixture。同义改写也会退出这个测试分支。这只是限制样例范围，不代表已实现自然语言语义路由；任意目标和额外约束的覆盖率尚未验证。构造器还核对输入正文与 ContentRef 的摘要、字节长度及清单关系，并按实际 `DecisionRequest.limits.max_actions` 限制直接行动数。

| 规则 | 额外限定条件 | 不命中后的责任 |
| --- | --- | --- |
| 蓝牙 D2 | 一个已固定的 effect 条件；设备身份与 desired=true 完整；观察能力和准确绑定唯一 | 缺参数补上下文；绑定/目标变化重新固定快照；其他目标交普通决策 |
| 蓝牙 D3 | 新快照中唯一、同设备、版本明确且未过期的关闭观察；当前无计划；新计划身份已分配 | 观察过期或设备不符重新观察；效果未知核对原操作；已有计划先核对，不覆盖 |
| 报告 D2 | 两个产品的名称、版本、官方域名及保存位置完整；维度严格为部署方式、功能限制、维护成本，固定查询模板适用 | 缺字段补齐；额外维度、歧义产品或需要搜索策略推理时交普通模型决策 |
| 报告 D3 | 两份与产品/版本对应的结构化搜索结果，每份 1–2 条、总计不超过 4 条唯一 HTTPS 同域同版本命中；全部抓取，无语义筛选 | 缺材料或越界命中补资料；过期重新搜索；需语义筛选或超出有限上界时交普通模型决策 |

30 秒事实新鲜度和查询模板是本候选的**新增合成策略前提**，不是现行通用契约或已发布产品配置。搜索命中同域只是抓取范围过滤，不证明内容真实、引用支撑成立或报告质量达标。D4 综合与 O7 独立评估保留；事实不足时继续补资料，不能借三次目标强行提交。

没有匹配规则与规则自身出错是两种情况。前者在上下文与全部门禁允许时可进入普通模型决策；缺字段、未知效果、授权或预算缺口分别保留相应补齐/核对/等待责任。规则冲突或规则产物违反契约时，本轮应以 `failed`、`invalid_output`、`retry=after_change` 结束且不携带 `model_call`；Orchestrator 等待准确策略版本修复后固定新快照、新 Decision，不能自动发模型来掩盖规则错误。本投影未实现完整策略注册与修复调度。

蓝牙 D3 从当前观察、已接受条件和准确能力重新构造计划，生成独立 `plan_id`、分配句柄、新上下文及新计划正文。计划安装与直接行动仍互斥；设置原效果核清后才物化观察步骤，最终完成依赖当前有效观察及固定条件核验。计划包含新输入的完整来源清单，没有把 D1 旧计划改绑到 g2。

## 可复核产物与检查

- [derive.py](derive.py) 只从基线输入重建限定候选，不读旧 Proposal 来构造动作；保留模型轮只做引用投影。
- [baseline-digests.json](baseline-digests.json) 锁定原数据目录中的 JSON、正文和组件。脚本及渲染文档不属于该锁范围，允许授权的措辞修正。
- [validate.py](validate.py) 检查来源指针/摘要、正文准确字节、schema、g2 输入、新决策/计划身份、动作参数、调用唯一性、原数据不变以及异常分支。
- [validation-results.json](validation-results.json) 分别记录静态检查和未执行的运行验证。反例覆盖缺字段、旧目标/绑定、同类条件换规则、额外自然语言约束、能力声明变化、输入字节篡改、行动上限、非法 URL、过期观察、效果未知、报告参数与材料缺失，以及综合和语义评估不能被规则省略。

在仓库根目录运行 `python3 .scratch/architecture-review/model-call-optimization-data/derive.py` 后运行同目录 `validate.py` 可重建并复核。脚本运行时间仅是本地合成生成/校验时间，不计为模型性能。下一步应在相同真实任务集上测量规则覆盖率、误命中率、回退次数、最终成功率和逐调用用量/延迟，才能决定是否落地。
