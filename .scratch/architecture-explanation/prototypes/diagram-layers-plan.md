# 架构图示分层原型计划

状态：2026-10-03 用户已确认采用当前修订版。正式决定见[职责数据与部署分别用什么图说明](../issues/03-diagram-layers.md#answer)；本文保留素材处理和原型取舍，不替代正式决定或架构规范。

直接打开[架构图示分层原型](diagram-layers.html)，按“职责 → 报告主线 → 回执丢失 → 事实归属 → 部署”阅读。HTML 自包含，双击即可查看；文档依据链接依赖当前仓库的相对目录。

用户反馈首版粒度过粗：只展示业务流程，没有解释关键数据、进程与边界。首版“四张图和一张表”方案未被采用。当前修订采用概览配机制详图，关键场景必须同时交代进程、持久记录、事务、外部效果及恢复入口；不能以分层为由把这些联系省掉。

修订版保留职责、正常主线与部署概览，将回执丢失扩展成“提交与丢失位置”和“接替 worker 恢复”两张连续详图。用户进一步要求补充分布式故障转移和服务节点滚动升级，因此新增数据库接管、worker 升级、应用与网关切换、Executor 宿主升级四张时序。当前共九张图，并用表格解释记录、提交条件、失败处理和版本兼容；数量不作为定案约束。

## 共用的阅读约定

- 职责图的框表示逻辑负责方，连线表示业务交接或依赖，不指定 RPC，也不指定事务。
- 时序图从上到下表示先后。实线为请求，虚线为返回；图例必须就近解释。无须展开的阶段用文字说明，不能虚构一个合并所有工作的公共接口。
- 部署图的框表示运行角色或存储，区域只表示实际的云端与设备边界。网络连线注明协议；库内读写明确标注为存储访问。
- 同一名称在各图保持含义一致。worker 更换不改变 Task 或 Operation 的身份；Orchestrator 不代表一台永久存活的主进程。
- 图旁说明省略项和假设。任何跨库、网络、模型或文件操作都不能仅因画在相邻位置而被解释为同一数据库事务。

## 数据归属表的讨论样例

| 关键事实 | 谁负责裁决与维护 | 其他参与方能做什么 |
| --- | --- | --- |
| 用户原输入及其投递 | 应用 Interaction | Orchestrator 接收原输入引用，组织关联任务；界面关闭不取消任务。 |
| 目标、条件、控制与完成结果 | 原 Orchestrator | Brain 提建议，应用展示结果，Executor 接收准入后的行动。 |
| 一次决策提案及模型用量 | Brain | Orchestrator 固定输入并决定是否采纳，不能把模型输出当作行动授权。 |
| 行动意图、接纳、尝试与效果 | Orchestrator 保存原意图；Executor 保存执行事实 | 双方各写自己的事实，通过原操作关联；不是共同原子提交一条记录。 |
| 正文与准确内容版本 | Content 所属负责方 | 有权的模块按准确版本读取；进入上下文不自动获得长期保存许可。 |
| 长期记忆 | Memory 所属负责方 | 在独立保存与使用许可内跨任务复用；不把它等同于任务进展记录。 |
| 授权许可与本人确认 | Grant 所属负责方管理许可；实际业务负责方保存并消费确认 | Brain、应用展示和插件声明均不能替代受信决定。 |
| 费用与持久工作 | 各原费用及业务负责方 | 任务完成后仍可能核对费用和效果；工作者只领取已有责任。 |

表中的负责方是逻辑职责，不推导物理表或进程数量。此表只辅助解释，准确写入与生命周期规则以原数据设计为准。

## 提议的呈现方式

草图放在一个可直接打开的 HTML 中，每图附简短结论、图例、来源与省略项。概览采用 960 × 600；机制与部署续接详图宽 1280，高度按内容安排，窄屏在图内横向滚动。新增的“故障接管”“滚动升级”可从页首直接跳转，升级组内可跳到各类节点及版本回退。用户已选择沿用现有文档风格：浅色底、青绿色节点、中文字体。字体栈优先 Noto Sans CJK SC，缺失时使用 PingFang SC 等系统字体，不加载外部字体；中文标签沿用文档可读字号，不套用插件默认的小字号。

已在浏览器检查提交详图、接替恢复图及新增故障接管和三类升级图；图内滚动容器可聚焦，页面本身没有因画布产生横向溢出。单文件、SVG 无障碍结构与本地链接检查通过。修订吸收了用户对首版理解缺口及部署续接覆盖不足的反馈，并已获得用户接受；未进行逐项复述验证，也没有做真实运行、恢复、滚动升级或容量验证。

## 后续读者验证

正式说明仍需验证开发者能否直接指出：原意图与执行事实分别在哪个库、哪些记录共同提交、哪里发生不可由数据库回滚的外部效果、具体丢失哪种答复、接替进程从哪份记录继续，以及故障接管和升级分别需要什么条件。当前方案已获用户接受；图示只能说明设计，不能证明实现、恢复或生产容量已验证。
