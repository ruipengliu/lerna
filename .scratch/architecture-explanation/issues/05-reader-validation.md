## Question

如何验证拟定的文档能帮助开发成员理解架构，而不只检查措辞、字数或链接？新主文档的名称、保存位置及入口调整怎样支持首次阅读和后续查阅？

基于已选结构、短章和图示，讨论读者需要完成的复述或判断任务，例如沿报告流程指出负责方、解释未知写入为何不能盲目重试、定位负责模块的准确接口合同。确认试读安排、反馈如何触发修订，以及无法取得真实读者反馈时要明确保留什么未验证项。用户参与讨论不自动等于开发成员试读通过。

入口调整须决定新增文件的位置、架构 README 中的引导方式、到现有规范的直接链接，以及日后规范变化时需要同步核对的解释内容。不得通过复制合同减少导航跳转。

## Answer

### 正式文档与阅读入口

规划阶段曾确定：正式主文档采用标题“Harness 架构讲解”，保存为 `docs/architecture/guide.html`。配套图示放在已有 `docs/architecture/assets/`，从正文相应机制段落直接引用。该决定形成时尚未创建正式稿或修改阅读入口；当前单页落位与交付状态见本节末尾。

只调整以下三处入口：

1. [架构 README](../../../docs/architecture/README.md)将新讲解列为首次阅读入口，保留按模块、字段、接口和存储查阅的现有路径。
2. [工程说明](../../../docs/architecture/engineering/README.md)开头增加简短回链，方便尚不熟悉架构的开发者先理解分工与恢复机制。
3. [开发准备度](../../../docs/architecture/engineering/implementation-readiness.md)开头增加简短回链，仍以实现范围和实施前检查为正文职责。

新讲解末章反向链接工程步骤与验收要求。正文就近链接准确合同章节，不复制整套规范，也不把读者引向研究材料寻找必需业务规则。根目录不另建 README，领域术语继续由现有 CONTEXT.md 维护。

### 开发者理解验证

正式稿完成后，请至少一位未参与写作的目标开发者独立试读，另由熟悉合同的维护者复核技术准确性。试读允许查文档，先记录独立判断与定位过程，再讨论；作者不得在记录独立结果之前提示答案。具体人选在执行试读时安排，本次没有联系或邀请任何读者。

| 阅读任务 | 必须观察的判断与定位 | 需要修订的关键误读 |
| --- | --- | --- |
| 用户中途修改报告要求 | 指出谁接纳变更、旧提案如何处理、已发生效果怎样继续核对，并找到目标与控制合同 | Brain 直接改权威目标；条件改变后照用同轮旧行动；认为目标变化撤销历史效果 |
| 比较两类答复丢失 | 分别解释 Executor 已保存 applied 但查询 Reply 丢失，以及目标可能写入而效果尚未知的恢复入口 | 两者都直接重写；超时被当作未执行；混淆 ReplyAck、历史效果、独立读回与 Task 完成 |
| 更换 worker、扩容或设备断网 | 指出 Task、Operation、Job 的原身份、临时领取和权威存储哪些改变、哪些不变 | 换 worker 新建写入；已有 Task 改投新 owner；端侧缓存裁决云端 Task 完成 |
| 判断故障接管与滚动升级 | 区分数据库提升、worker 排空和执行宿主升级；判断旧写者隔离、未结责任与格式兼容是否允许继续 | 租约到期被当作旧外部入口已停；新版本任意解释旧操作；软件回退被当作业务历史回滚；保持 socket 被当作业务无中断 |
| 找到准确实现合同 | 从答复丢失场景定位查询方法、ReplyAck、Job 领取、文件读回和完成规则，说明讲解未覆盖的细则 | 只找到目录或研究报告；把图示当完整接口合同；找不到相应字段、状态或失败条件 |

试读记录至少包含文档版本、读者相关背景、题目、独立回答、实际查阅位置、所需提示、误读以及对应修订。时间可作为观察记录，不设未经依据的时长或通过率门槛。评价以能否正确解释关系、判断继续或等待并定位合同为准，不要求背诵字段或固定术语措辞。

出现关键责任、权限、事务或恢复保证误读时，修订对应段落、图示或导航，再用同类变体场景复查。需要作者提示后才能完成的结果必须保留提示记录，不能写成独立理解通过。技术复核、链接检查与代理评审分别记录，均不替代真实读者试读。

如果暂时没有试读者，可以完成正式稿交付，但必须标明“开发者理解未验证”，保留上述任务供后续试读。不把本次对写作方案的确认写成试读通过，也不因此声称读者已经能够实现系统。

### 维护与后续反馈

修改现行合同的同一变更必须检查受影响的讲解段、图示、示例、导航和阅读验证任务。解释页发生冲突时，先按原合同纠正；若发现合同自身存在行为、权限或恢复保证的歧义，另提明确设计问题，不靠改写讲解覆盖决策。

现有样稿与机制图已暴露的粒度问题均已处理并取得用户确认。当前没有已知的其他待决写作问题。未来真实试读暴露的问题属于正式编写和验证中的修订输入：次序或表达问题直接修订；超出既定写作方案的设计问题另建具体议题，不能预先声称不存在任何误读。
