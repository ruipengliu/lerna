# 04: 持久无进展判断与有界续行

**What to build:** 设计长任务在重启、重复反馈或依赖失联后继续有限推进的规则，使用户能看见实际进展、停止原因和恢复条件。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

**Progress:** completed

- [x] 定义可观察进展、已计数反馈、推进次数、无进展原因及下一次可检查条件的持久归属。
- [x] 新目标事实、新结果、有效人工输入与重复通知分别处理；原反馈不重复计数，重启不重置预算或无进展历史。
- [x] 区分正常效果核对与无进展循环，不把重复读回一律判为空转，也不反复调用模型探测依赖。
- [x] 达到策略上限后保存等待或失败原因，未知效果与结算继续由原责任承接；无进展上限不构成成功依据。
- [x] 覆盖重启、重复领取、目标修订、模型拒绝、失联子任务和预算耗尽的时序与验收断言。
