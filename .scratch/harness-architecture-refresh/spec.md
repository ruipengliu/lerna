## 本轮设计约束

1. 保留九模块及原事实归属；Task 固定归属逻辑 Orchestrator，工作进程和会话不能成为新的任务权威。
2. Brain 每个 Decision 至多发起一次物理模型请求，透明重试关闭；新的模型尝试由 Orchestrator 另行准入，辅助处理也须独立记录费用与责任。
3. Operation 与 Effect 沿原身份恢复；取消、超时、合成工具响应或摘要均不能消除未知效果及费用责任。
4. 当前 Grant、准确 Content、来源闭包、独立任务核验，以及事实与 jobs 共事务继续成立。
5. 优化集中在既有 interface 的内部实现与可验证合同。需要改变公开字段或方法时，同步处理 Schema、登记、示例及校验；内部诊断不自动成为公共协议。
6. 经验精炼、程序化执行、渐进式发现是候选设计。保留冻结对照、完整成本、独立证据和发布批准的启用条件。
7. 修改所属模块的规则正文；综合入口负责导航和采用范围，避免另建一份重复规范。保留现有目录，协调主入口、Orchestrator 说明与详细设计。
8. 研究报告及其基线快照是历史取证材料。后续架构改动的检查结果独立记录，不改写历史研究快照以制造“一致”。

## 已确认的任务范围

以下保留已确认的范围与验收条件；执行与验收状态以 [独立票据](README.md) 为准。

### 01：重启后先恢复原责任，再开放新执行

**What to build:** 设计宿主从不可执行到可恢复、再到可接纳新工作的完整路径。使用者能查询原决定和未决责任，并明确知道新任务为何尚不能启动。

**Blocked by:** None (can start immediately).

- [ ] 明确数据库写资格、旧写者隔离、原关闭记录与未决工作、当前安装及批准、控制恢复、新执行开放的顺序与成功点。
- [ ] 区分内存准备、存储接纳、耐久提交、提交未知和实际出站，只有适用的耐久资格成立才能启动效果或费用。
- [ ] 恢复完成表示必要状态和处理能力已恢复；原效果仍未知时保留责任，不要求等待所有历史责任结清才能提供获准查询。
- [ ] 覆盖提交前失败、提交回执丢失、提交后崩溃、旧写者未隔离、存储不可写和唤醒丢失，逐项说明出站次数及用户可见状态。
- [ ] 沿原 Command、JobStore 和业务成功点设计恢复，不引入第二套业务状态机。

### 02：长任务上下文与最终模型请求的来源核验

**What to build:** 设计长任务经过多次压缩和目标修订后，仍能使用准确事实与获准材料形成一次可追溯的模型请求，并解释缺口、费用与结果来源。

**Blocked by:** None (can start immediately).

- [ ] 分清机械重建的硬约束、获准正文、近期事实、候选摘要和最终供应商编码；摘要不能修改目标或效果事实。
- [ ] 将最终请求的全部实际字段纳入来源、接收方、用途和尺寸核验，覆盖附加日志、元数据及插件字段，明确禁止保存材料的最小记录边界。
- [ ] 记录准确输入版本、策略与编码配置、保留和排除依据，投影落后、来源关闭和必要材料超窗均有明确分支。
- [ ] 覆盖三次压缩、目标修订、冲突、原操作无结果、local_only 资料及附加日志外发；合法本地处理和获准披露均有正例。
- [ ] 新摘要处理另行准入并计入完整成本；保持单 Decision 至多一次物理模型请求。

### 03：最终工具参数准入与完整效果交付

**What to build:** 设计一个候选行动从参数变换、准确绑定、授权准入到结果交付的完整路径，使调用者能够分辨正确执行、部分覆盖和未知效果。

**Blocked by:** None (can start immediately).

- [ ] hook、模板和包装器变换先完成，再作严格校验、资源规范化及准确目录与安装绑定；后续变化不得静默改变原 Operation 的输入。
- [ ] 实际入口重新核验当前控制、Grant、预算、目标及资源，hook 的 allow 不能产生权限。
- [ ] 区分逻辑调用源序和完成顺序，保留准确原结果、必要的大字节引用、分页、截断、筛选、观察时间与部分覆盖。
- [ ] 明确实时流、最终结果、适配器占位和费用结算的不同含义，流中断或合成响应不消除未知效果。
- [ ] 覆盖最后参数改写、同名工具、旧目录、撤权、路径变化、乱序、漏页、合法空集及媒体超限；每种拒绝有相应合法正例。

### 04：持久无进展判断与有界续行

**What to build:** 设计长任务在重启、重复反馈或依赖失联后继续有限推进的规则，使用户能看见实际进展、停止原因和恢复条件。

**Blocked by:** None (can start immediately).

- [ ] 定义可观察进展、已计数反馈、推进次数、无进展原因及下一次可检查条件的持久归属。
- [ ] 新目标事实、新结果、有效人工输入与重复通知分别处理；原反馈不重复计数，重启不重置预算或无进展历史。
- [ ] 区分正常效果核对与无进展循环，不把重复读回一律判为空转，也不反复调用模型探测依赖。
- [ ] 达到策略上限后保存等待或失败原因，未知效果与结算继续由原责任承接；无进展上限不构成成功依据。
- [ ] 覆盖重启、重复领取、目标修订、模型拒绝、失联子任务和预算耗尽的时序与验收断言。

### 05：多端输入一次消费与界面恢复

**What to build:** 设计用户在两个设备提交、确认、取消或断线重连时的准确行为，确保界面能恢复原输入和任务事实。

**Blocked by:** None (can start immediately).

- [ ] 输入接纳、转交、业务消费及可信确认分别定义持久成功点，准确绑定原请求、版本及必要正文预览。
- [ ] 明确 accepted 尚未领取时的取消、新输入与旧控制的关系，以及旧运行退出不得误伤新运行的条件。
- [ ] 两设备竞争只允许业务事务中的胜方生效，败方不写自动许可；超时或断线不能推断已消费。
- [ ] 界面先取得可读的持久快照，再依赖可丢提示加速；只对呈现增量做合并，旧世代数据不能覆盖新 Surface。
- [ ] 覆盖重复 deny/confirm、旧预览、撤权、终结提示丢失、队列切换及客户端存储失败，并给出 SDK 查询原决定的路径。

### 06：子 Agent 异步等待、冷恢复与结算

**What to build:** 设计父任务接纳一个子目标后，经过有界等待和重启仍能查询同一子任务，取得范围明确的结果并保留未决效果与费用。

**Blocked by:** 01：重启后先恢复原责任，再开放新执行。

- [ ] SDK admission handle、读取、有界等待和批量读取复用原 Delegation 与唯一子 Task；接纳句柄不代表完成。
- [ ] 冷恢复固定原父子映射及准确安装组合；能力不足时拒绝新启动，同时保留获准的原责任查询。
- [ ] 父任务消费结果、重复报告、父取消、子效果和费用晚到均沿原身份归并，父成功仍独立核验条件和必要效果。
- [ ] 区分子目标行动结束、效果核清、报告交付与费用封账；不得凭 complete 文本归还未结预算。
- [ ] 覆盖子效果发生后父崩溃、组合漂移和字段不支持；协作比较计入等待、汇总、失败及清理成本。

### 07：扩展暂存装配、配置竞争与实例就绪

**What to build:** 设计扩展从准确制品进入暂存装配、通过检查并发布实例就绪的完整路径，配置变化或初始化失败时仍能解释当前可用能力。

**Blocked by:** 01：重启后先恢复原责任，再开放新执行。

- [ ] 按 InstallLock 固定实际字节、依赖、配置及平台条件，暂存实例与注册项在全部检查通过前不供新调用使用。
- [ ] 就绪检查关联当前批准、实例健康与配置世代；初始化期间配置再次变化时，旧结果不能提交为当前 ready。
- [ ] 失败时释放暂存 handler，并保留已产生的原效果、费用和清理责任；卸载或进程退出不证明外部效果已消失。
- [ ] 覆盖半包、字节替换、依赖漂移、初始化异常、批准撤回及重启，沿原激活记录解释结果。
- [ ] 回退核验旧版独立批准和格式兼容性；维持内置静态组合、第三方受控进程或服务的选择。

### 08：经验候选形成与受控评测发布

**What to build:** 设计任务经验如何形成可审查的准确候选，处理基线变更后进入独立评测，再获准用于后续任务。

**Blocked by:** 02：长任务上下文与最终模型请求的来源核验；07：扩展暂存装配、配置竞争与实例就绪。

- [ ] 候选固定类型、范围、版本、来源、before/after 及回退关联；当前条目改变时拒绝误覆盖，部分应用明确报告。
- [ ] 任务局部材料取得独立保存许可后才能成为跨任务 Memory，纠正、源关闭与 local_only 限制贯穿候选及派生材料。
- [ ] 候选选择、冻结、未暴露正式样本、独立判断、受信批准和目标就绪按既有流程衔接。
- [ ] expected_outcome、回归通过或模型自评仅作候选理由，不能成为能力改善结论；额外处理和失败全部计入成本。
- [ ] 读时整理与自动精炼的实验因素分别冻结，保留原实验统计含义及不确定结果的基线选择。

### 09：受限程序化工具的执行与恢复合同

**What to build:** 设计一段获准程序如何在受限执行宿主内完成有限工作，逐次经过真实出口的准入，并在取消或恢复后解释每项效果与费用。

**Blocked by:** 03：最终工具参数准入与完整效果交付；07：扩展暂存装配、配置竞争与实例就绪。

- [ ] 程序化能力归 Executor driver，固定代码、运行配置和输出版本；每次外部效果、模型请求及子委派分别准入和关联。
- [ ] 明确文件、网络、凭证、子进程、时间与输出限制；平台能力不足时关闭相应能力，不以 VM 名称代替隔离证据。
- [ ] abort 回执与 cell 或子进程实际停止分别记录；恢复不得依赖不可信对象反序列化或重放未知效果。
- [ ] 若编译为原有限计划则沿既有计划实验；交互式 cell 使用独立冻结对照，不能复用不同因素的统计分母。
- [ ] 给出越界访问、DNS/重定向、符号链接、取消、恢复及合法程序正例的验收设计，费用覆盖全部尝试和维护成本。

### 10：渐进式能力发现与 Skill 加载对照

**What to build:** 设计 Agent 在同一准确目录和安装组合上采用不同发现与加载策略时，如何选择、加载并使用能力，以及如何独立判断实际收益。

**Blocked by:** 03：最终工具参数准入与完整效果交付；07：扩展暂存装配、配置竞争与实例就绪。

- [ ] 明确直接目录、受控检索及延迟加载的候选路径，发现结果仅提供候选，使用仍经过准确绑定与当前资格检查。
- [ ] 记录召回、选择、正文实际加载、触发时机和最终任务结果；缓存当前性与配置变化可解释。
- [ ] 覆盖应触发与不应触发、同名能力、旧 Schema、缺依赖、断连、加载过晚及加载无益。
- [ ] 将收益、退化、搜索和加载成本纳入固定对照，不只比较目录 token 数量；未达门槛时保留原策略。
- [ ] 沿已有选择实验声明适用因素，额外改变模型或运行模式时独立冻结，不扩大既有结论。

### 11：贯穿场景验收与架构入口一致性

**What to build:** 将更新后的方案组织成可连续阅读、可逐项追踪和验证的设计交付。读者可以从研究并保存报告的主线定位各模块职责、异常继续方式与证据缺口。

**Blocked by:** 01～10 全部任务。

- [ ] 十二项调研建议逐项映射到采用或实验范围、所属模块、工程阶段及验收证据，避免遗留只在研究报告中的规则。
- [ ] 共享故障语料覆盖新合同的组合竞争；机制验收、真实数据库与平台故障、质量实验的证据分别登记。
- [ ] 主入口、Orchestrator 说明、详细设计、贯穿场景和工程阶段一致，维护本次涉及的本地链接与稳定锚点。
- [ ] 如公开契约变化，同步完整机器资产并运行相关校验；未改公开契约时也检查正文没有暗中声明额外协议保证。
- [ ] 运行适用的现有静态检查，记录实际命令、结果与未运行范围；不把静态通过写成真实故障恢复或性能结论。
- [ ] 检查全部新决策与现有 ADR 和领域词汇一致，发现矛盾时明确提出，不静默修改已确认决定。
