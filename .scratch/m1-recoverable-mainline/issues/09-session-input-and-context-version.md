# 09: 会话输入与上下文版本

**What to build:** 用户在任务运行中修改目标或回答问题，修改被接纳后，基于旧上下文的提议无法准入；一个会话可以先后关联多个任务，任务关闭不关闭会话；分支和历史编辑明确返回"不支持"。

**Blocked by:** 05（准入：脚本化提议到动作意图交接）

**Status:** resolved

- [x] 会话输入类型：新目标、修改、回答、确认、任务控制，带准确的目标和请求引用
- [x] 会话事务序、稳定身份、依赖和版本检查；模拟并发下不误投、不丢输入
- [x] 修改或回答被接纳后，旧快照上的提议被准入门禁拒绝
- [x] 条件集接纳只支持任务模板和显式条件列表；模板外的目标请求用户澄清
- [x] 分支与历史编辑返回"不支持"，不原地覆盖


## Answer

- 实现独立空会话、同会话多目标，以及 `GOAL / MODIFY / ANSWER / RECORD / CONTROL` 的显式投递。消息序由裁决事务分配；依赖按完整命令身份核验，未满足时保存为 `WAITING_DEPENDENCY`，`RouteInput` 重启后仍只投递原输入和原目标。分支与历史编辑返回 `UNSUPPORTED_FEATURE`，不覆盖历史。
- 问题由受信宿主发布，回答核验完整请求引用、期限、任务/会话及当时版本；两个独立 SQLite 连接竞争时只有一个回答生效。任务修改和改变依据的回答递增输入版本及控制代次，绑定版本等待可信处理；不改变依据的回答保持控制代次，并按连续已处理输入推进绑定。仅记录消息不修改任务版本。暂停、恢复、取消有控制代次检查，重放旧恢复不会解除后续暂停。
- `ProcessInput` 按输入版本逐条处理，支持受信模板、保存的显式用户条件及澄清等待。`AcceptRequirements` 也不得跳过未处理输入。模板外目标可通过后续回答的精确 `source_input_ref` 取得显式条件，再按顺序处理原目标与回答；跨任务、错误版本或被改写的条件列表均被拒绝。处理输入只清除本模块负责的等待原因，保留取消收尾等已有责任。
- 新上下文快照保存按任务输入序排列的 `input_refs` 和内容引用；条件重绑定生成新引用，历史条件、提议和快照可继续查询。原 `SubmitGoal` 路径也保存可回查的输入来源，查询结果不回显认证或诊断字段。
- CLI 增加空会话、输入、问题、待投递输入恢复、输入历史查询及可信处理命令；复杂条件和来源引用使用公共契约 JSON。确认的专用受信入口和原子消费归工单 08；本工单提供 `SessionInput.confirmation_ref`，普通输入不得冒充确认。
- 为工单 07 保留唯一的 `tasks.supersedeVerification` 原事务入口：建立实际核验对象后，必须在同一事务写入 `SUPERSEDED`，不得只清冻结后异步补记。当前保存被替代代次，并完整保留准入动作清单和已开始未收尾的阻断记录。
