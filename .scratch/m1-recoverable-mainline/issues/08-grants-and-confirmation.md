# 08: 授权与确认

**What to build:** 用户可以对具体动作给出单次授权或有明确范围和期限的持续授权，在命令行确认核心生成的动作描述；确认只消费一次，参数改变后旧确认失效；撤销授权后依赖它的新准入立即被拒绝，并能查询撤销进度。

**Blocked by:** 05（准入：脚本化提议到动作意图交接）

**Status:** resolved

- [x] 单次授权与动作在准入事务中原子绑定；持续授权有主体、资源、动作、范围、期限、用户和语义版本
- [x] 确认绑定核心生成的描述和事项类型；回执丢失后重试只消费一次（交互适配器 M1 演示 2）
- [x] 参数改变后旧确认失效
- [x] 出口凭据为不透明引用，绑定准入、主体、出口、请求摘要和期限；出口处再次核验当前有效性
- [x] 撤销被接纳后新准入和新凭据被拒绝；同进程内撤销与出口的竞争按权威检查处排序；进度可查询
- [x] 操作权利与处理目的两字段保留，未知值拒绝；委派、组合多个来源返回"不支持"；不得实现成"读取自动包含保存、同步和行动"


## 实现与验证

- 单次／持续授权、作用域与用量池、可信签发和动作确认已接入公开装配及 CLI。确认消费与授权使用、预算预留和准入决定共事务；参数变化、撤回、错误事项类型、未知权利／目的和委派均有拒绝测试。
- 不透明出口凭据保留不可变签发历史，实际 P4 使用单独保存；撤销立即禁止新使用，并通过原始封闭命令、目的端回执和源端确认推进。启动与 `recover` 继续未完成交接；实际发送前后、跨 Harness 等待、重启和回执丢失覆盖真实出口。
- 确认展示和出口发送共用 `command.ContentBytes`；UTF-8／Base64 与媒体类型无损展示实际参数。真实 HTTP 响应内容经过两次确认后再次发送，验证二进制、空内容及含 NUL 的 UTF-8 字节一致。
