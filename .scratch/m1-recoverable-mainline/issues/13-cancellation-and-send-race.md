# 13: 取消与发送竞争

**What to build:** 用户取消任务后，新准入立即停止，已准入但未发出的动作被封闭；与发送竞争的动作按实际窗口如实呈现；取消后迟到的效果和费用仍被接纳和展示。

**Blocked by:** 07（完成门禁与 Result：主线打通）、12（安全重发与保持未知）

**Status:** resolved

- [x] 取消被持久保存后，新的准入被拒绝
- [x] 取消分别落在 P4 之前、P4 与 P5 之间、P5 之后三个窗口，各有故障测试；结果与出口闸门和执行管理的竞争规则一致
- [x] P4 与 P5 之间的封闭需执行端点确认才能出具内部封闭证明
- [x] 命令行显示已保存的控制、核对中的动作和未知效果（交互适配器 M1 演示 3）
- [x] 取消后迟到的效果归原动作，费用仍可查（交互适配器 M1 演示 5，标注 G10、G11）

## Answer

取消在原用户控制事务中保存独立 `Cancellation`、完整原准入清单、逐项封闭意图与持久交接待办；范围包含原模型准入。控制回执只证明控制与责任已保存。恢复先查询原命令，再补交同一命令；只有原端点持久确认后才完成原待办。取消不伪造完成提议或核验。端点封闭与 P4、P5 和真实 I/O 共用跨进程临界区，暂停的旧 worker、过期领取和通用待办控制都不能越过原责任。

P4 前取消阻止新开始；P4 后、P5 前由原端点不可变证明封闭从未进入 P5 的准确发送；P5 后保留未知效果、迟到可能性及原费用。完整发送历史逐项处理，封闭最新登记发送不会清除旧发送的未知效果或费用。尚未到达原 P2 的准入也保存永久封闭标记，迟到交接只能产生原身份的禁止执行记录，实际目标发送为零。正在执行的真实 HTTP 请求结束后才能取得端点封闭确认，迟到的原效果和账单继续接纳。取消后的独立核对按当前控制重新准入，并保留原动作与查询各自的事实及费用来源。

CLI 分别展示已保存控制、未取得端点回执的封闭责任、核对责任与未知效果。合法的先封闭、后原交接历史展示原意图、回执、`NoSendProven` 封闭证明及等待原动作记录的准确准入引用，不虚构动作记录、版本或未知效果；迟到原交接产生记录后展示原动作。真正的读取失败与没有动作记录明确区分。任务仍保持 `CANCELLING`，最终非成功 Result 的固定由后续独立关闭协议负责。

取消、原意图、端点证明和源域 ACK 的追踪源事件与各自原负责方事实同事务保存；源事件失败使原事实一并回滚。公开源查询、独立运行记录接纳、源 ACK 与索引恢复保持原取消／意图／准入／动作／尝试／发送身份，不复制正文、目标文本、端点地址或本机路径。正式集成的 FILE、历史只读核对、模型快照与同任务 CLOSURE 归属规则保持完整。

2026-10-06 验证通过：公开取消与 CLI race 回归 14.503 秒、模型范围与供应商零调用回归 2.603 秒；取消全部 27 个三窗口故障组合及正式 FILE 四项历史／弱证据／已知结果／跨适配器回归 43.103 秒；格式、正常与 fault 静态检查、规则和协议生成检查通过。同一冻结树 `eb74031ef734c7494408171a0c75f4b0bec0f902` 的原样完整 `GOFLAGS=-v make check` 实际退出 0，启动时刻 03:11:09 UTC，观察退出时刻 04:28:00 UTC；完整 fault 包 4372.348 秒，普通 admission race 包 229.665 秒。

本轮实际矩阵：SQLite 439 个 I/O 事件、2105 个恢复图像；首次启动 1421 个 I/O 事件、7110 个恢复图像；P4 51 个持久 I/O 事件、260 个图像及真实子日志 I/O；原生文件 14 个实际事件、225 个图像和四个省略屏障负对照；文件与数据库共同时间线 980 个 SQLite 事件与 14 个原生事件、995 个切点、全部 4975 个联合图像。完整检查保留所有前缀的五种恢复策略及同步失败负对照，没有筛减矩阵。随后仅补充本票据与 ADR 0009 的验收记录，运行代码与测试未变更。原始日志永久保存在工作区旁的 `lerna-m1-context/ticket13-full-make-check.log`；公开 RED/GREEN 与集成窄回归日志一并保留。
