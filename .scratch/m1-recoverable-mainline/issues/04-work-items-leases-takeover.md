# 04: 待办工作、租约与接替

**What to build:** 持久工作的待办工作能被工作者原子领取、续租，租约到期后由另一工作者接替；被接替的旧工作者不能再覆盖当前推进。用户感受到的是：进程中途卡住或重启后，任务继续推进且不出现两个执行者。

**Blocked by:** 02（提交目标与创建任务）

**Status:** resolved

- [x] 原子领取、有界租约、续租、领取代次、工作修订号、受阻和封闭
- [x] 旧领取者在接替后提交的写入被拒绝（fencing），用故障测试证明（标注 G11）
- [x] 接替不改变动作的执行端点
- [x] 持久工作语义测试按"同一事务后端接口"组织，以便将来 PostgreSQL 后端复用同一套用例

## Answer

实现 `JobCommand` 的 CLAIM / RENEW / PROGRESS / CONTROL / ENQUEUE 与查询；原决定含空领取、固定续租截止时间及永久拒绝，使用完整命令身份去重。SQLite 在 BEGIN IMMEDIATE 取得写锁之后取得权威时间，领取、核验、状态变化与回执同事务提交。领取最多 100 项，租约范围 1–60000 ms，默认目标工作租约 30000 ms；续租不改变领取代次或工作修订号。

目标工作通过领取与 `Sessions.ProcessClaim` 恢复，处理事务先核验状态、实例、代次、修订号和截止时间，再原子写入原目标决定与任务/会话事实。工作规格或控制变化使旧修订失效；受阻可以显式恢复，完成和封闭不可重开。固定交接工作保存端点与执行管理域，接替不改变这些字段；实际跨域投递仍由后续执行管理工单接入。

`conformance/durable` 的同一后端工厂覆盖领取、重复续租、空清单重放、有界租约、并发领取、等待、修订、受阻、封闭和固定端点接替。独立连接持锁测试验证等待数据库锁期间过期的续租被拒绝。`conformance/fault` 验证旧工作者暂停后恢复不能写入业务事实、领取回执丢失后查询原决定，以及 durable.jobs 提交前后真正退出子进程再恢复。

装配启动使用最多 65 秒的目标工作恢复期限，等待现有租约自然过期后接替，避免 CLI 退出导致后台恢复尚未运行；不会提前抢占有效领取。期限耗尽返回错误，保留持久责任。故障子进程使用公开领取命令的 100 ms 租约缩短测试，不改变生产时钟。

验证：`make check`（格式、双构建 lint、协议、race、故障子进程、规则标注与生成一致性）。本工单证明进程重启恢复，不声称通过掉电准入；后者归 21。
