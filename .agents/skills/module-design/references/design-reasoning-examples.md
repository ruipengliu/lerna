# 论证与表达对照

按遇到的问题选读：推荐理由不足看案例一，身份或字段难以理解看案例二，代价无法判断看案例三。以下为 2026-09-25 会话材料的压缩与改写，用于校准分析方法，不是当前模块的权威契约，也不要求每篇方案采用相同结构。

## 一、理由只证明共同前提

来源：[大脑总览：单轮决策](../../../../docs/architecture/brain-system/README.md#decisions)。

问题写法：

> 工具可能已经执行但答复丢失，因此大脑必须每轮只提交一个有界行动批次。

这里省略了中间判断。答复丢失说明需要保存原操作并统一处理后续行动，但保留大脑循环、每次行动仍由核心准入，也可能满足这一要求。

更充分的分析：

> 统一准入确定了行动资格和恢复责任的归属。单轮提案与逐次准入的大脑循环仍需比较：各自保留哪些恢复状态，如何处理控制变化，正常任务要承担多少交接。已有理由支持统一准入，尚不足以单独确定循环边界。

这个案例需要补设计依据，不能仅靠润色得到完整的推荐理由。评审应能指出哪项决定尚未被支持；待验证的假设保留为假设，不补写成已证实的优势。若现有约束已明确排除其他方案，直接说明该约束即可。

## 二、先给身份，后给动机

来源：[调用交接](../../../../docs/architecture/brain-system/contracts-and-runtime.md#call-handoff)。

问题写法：

> 核心按 work／attempt 管理调用；适配器持久分配授权使用 ID，保存两者映射。同一调用不能重新分配身份。

信息本身有用，但读者还不知道为什么需要两套身份，也不清楚重新分配会改变什么。

改写示范：

> 适配器重启后，应核对原调用的授权消费，而不是把恢复当作一次新的授权使用。核心按 work／attempt 归集决策与账务，授权服务则按使用操作 ID 记录许可消费，因此适配器需要持久保存两者的对应关系。恢复时沿原映射核对，再按原调用回送事实。

先解释这段关系，再给唯一键、不可变绑定和冲突行为。改写保留两个身份各自的职责；省略的查阅细则仍由原契约完整定义。单纯列出字段供熟悉机制的读者查询时，可直接使用表格。

## 三、代价只有抽象名称

来源：[大脑总览：取舍与接入](../../../../docs/architecture/brain-system/README.md#decisions)。

问题写法：

> 单轮设计增加串行步骤经过核心的次数，新能力可能需要补充任务策略和验证规则。

孤立这句话不足以判断谁会受到影响。评审须连同相邻段落判断：原文的验收责任与实际接入验证说明，可能已经提供足够依据，此时无需为满足格式再补一段成本分析。

改写示范：

> 连续 GUI 操作每次取得新观察后，都要进入下一轮决策，用户等待时间因此包含逐轮交接。交接是否成为瓶颈，应分开测量组装、准入和生成等环节。接入新能力时，若已有任务策略和验证器不能覆盖其目标与效果，接入者还需补充这些规则；可通过一次实际接入记录新增规则和需要修改的模块。

这段说明成本出现在哪里、由谁承担，以及如何取得判断依据，没有虚构延迟数值或开发工时。代价不必全部量化；约束已经确定、只需定性说明的取舍，可以保持简短。

## 校准流程修改

修改论证或审查流程后，先回放这三个问题，检查能否发现论证跳步、解释顺序和成本承担者方面的缺口。对照后的修订须保留原职责与保证；承认证据不足也是有效结果。

再选一篇未用于上述案例的文档，给独立审查者提供原始需求和正文，不附作者解释、预期结论或案例评语。保留简短的输入范围、发现与正文依据、修订结果及未解决项。若文档已有充分解释，应允许无问题结论；没有竞争方案时不要求虚构替代。

一次试用只能说明本次发现了什么。稳定减少推理缺口、合同遗漏和用户纠正，仍需在后续真实文档中观察；字数、标题齐全或自报通过不能单独证明改进。
