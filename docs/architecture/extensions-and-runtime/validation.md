# 验证、依赖与后续联动

[总览](README.md) · [安装与隔离](installation-and-isolation.md) · [生命周期](lifecycle-and-recovery.md) · [契约](contracts.md)

## 1. 核心保证与实现依赖

| 编号 | 必须保持的保证 | 验收落点 |
| --- | --- | --- |
| ER1 | 制品、依赖、接口和配置精确固定；陌生消息不改变已安装语义 | 安装回执、固定锁、原始测试报告及协议协商 |
| ER2 | 激活、停用和卸载有持久命令与阶段回执；未知提交不会创建替代变更 | 管理及目录账本、原命令查询、实例监督证据 |
| ER3 | 已有操作、模型调用、任务配置及消息继续使用原绑定；切换不抹除责任 | 各领域原关联、未决项及制品保留依据 |
| ER4 | 主体、文件、凭据、出口和消耗按用户隔离；安装和恢复不扩大权限 | 受信调用记录、隔离负例、授权使用与控制回执 |
| ER5 | 恢复控制器不裁决业务；恢复、关闭和回退不重置身份、预算或期限 | 原工作领取、门禁、重试额度与迟到事实 |
| ER6 | 局部缺口不阻塞无关作用域，控制和收尾具备有限保留容量 | 队列与容量拒绝、扫描公平性、获准事实接收 |

| 提供方 | 启用前所需能力 | 缺席时行为 |
| --- | --- | --- |
| 受信管理／维护入口 | 当前管理身份、精确版本及可验证发布批准，按目标用户／部署限制作用域 | 可做静态检查；不接纳激活或代码提权请求 |
| 宿主制品与事务存储 | 不可变制品、命令／步骤原子保存、固定回执、恢复及保留索引 | 不确认 Prepare／Activate 已接纳；提交未知保留原键核对 |
| 身份与授权 | 受信用户／actor／端点映射、活动 owner、当前许可和控制应用 | 相应实例无行动资格；不能用安装身份代替用户许可 |
| 本地监督器及隔离适配器 | 全部子进程与宿主出口的隔离证据、文件／凭据／网络及资源限制 | 仅装配受信内置组件和数据；第三方代码及接替功能关闭 |
| 能力目录与执行 | 固定登记回执、唯一新接纳绑定、原操作实现绑定、停用串行门禁及查询／取消 | 新能力不发布；原责任保留，不能用包状态代替目录或执行状态 |
| 各领域生命周期适配器 | 受限附着、原持久工作扫描、就绪依据、封闭引用入口及在用证明 | 禁用相应自动恢复／升级／卸载；其他已就绪分支可运行 |
| 连接与消息交付 | 既有流恢复、业务交接、原身份发送、收尾空间及处理器保留依据 | 本地领域保留发送责任；相关远程能力受限 |
| 评测与改进 | 隔离测试、固定基线、批准范围和效果证据 | 测试未执行保持未验证；缺自动交接时仅受信人工录入已有批准，见 ER-P1 |
| 备份与时间适配器 | 完整提交尾部、当前身份资格、防回滚及适用时间证明 | 旧备份仅诊断；不能继续行动，离线保持关闭 |

表中大部分接口已有设计而没有运行实现。只有依赖实现及相关故障注入通过，才能据此开放对应能力；本方案不将这些依赖合并为一个不透明的“宿主已就绪”。

## 2. 观测与受信处置

诊断记录关联管理 command_id、步骤命令、boot_id、用户／端点、制品与锁摘要、实例配置、目录修订、原业务引用和验证 profile。记录每步接纳／生效时间、缺口年龄、准备次数、剩余额度、隔离拒绝、队列等待、扫描耗时与结果、保留制品大小及恢复吞吐；业务效果继续读取原领域记录，不用激活率表示任务成功率。

日志不默认包含 Skill 私有正文、完整参数、提示词、用户文件、凭据或模型隐含推理。调用链追踪和评测复用需检查当前用途与披露范围；进程标准输出也受字节、敏感信息及保存期限限制。观测导出故障时可以丢弃获准的非关键采样日志，但管理回执、授权审计及领域恢复记录仍须耐久保存。

| 管理入口 | 允许动作与返回 | 不提供的能力 |
| --- | --- | --- |
| 本地安装／装配状态 | 查询原命令、固定锁、分项发布结果、当前健康与具体 blocker | 无凭进程存活推断效果或跨用户枚举 |
| 原命令恢复 | 按新受信处置命令及有限额度核对原步骤，或关闭仍未生效的步骤 | 不重建原业务 ID、不刷新旧激活期限 |
| 排空／安全停用 | 请求原发布状态和执行门禁处理；返回实际应用依据及未确认项 | 无“已下发即全部停止”或自动释放未知操作 |
| 更换／回退版本 | 选择仍获准且兼容的精确版本，执行新的安装与激活命令 | 无回退业务账本、恢复已撤销权限或跳过迁移检查 |
| 未知效果／业务预算 | 链接所属领域的原操作状态；沿[执行处置](../capability-and-execution/validation.md#management)提交获准证据／有限核对 | 本模块不能手改效果、任务终态、once 消费或业务预算 |

## 3. 初始容量配置与部署范围

下面是单机参考实现的起始测试配置，假设受信宿主装配少量默认组件、测试包不超过数十 MiB，每个驱动调用是有限单元；数值未经实测，不是服务承诺。更改配置产生新修订，正在进行的命令保留原上限或采用更严格的新限制，不能因重启变得无限。

| 限额 | 起始值与耗尽行为 |
| --- | --- |
| 制品接收与解包 | 单包压缩 64 MiB、展开 256 MiB、4096 个文件、接收截止 120 秒；任一上限触发拒绝，清理受控临时文件 |
| 安装并发与存储 | 宿主并发 2、每用户 1；制品容量由部署显式配置，至少能同时保留当前和待升级闭包及未决旧版本；不足拒绝新安装，不逐出被引用包 |
| 插件资源 | 每用户最多 2 个插件进程实例；每实例 CPU 上限相当于 1 核、内存 128 MiB、进程数 8、临时盘 64 MiB；用户聚合上限为这些单实例值的 2 倍，超出按原实例故障处理 |
| IPC／日志 | 单帧与单次产物各 1 MiB，单用户诊断日志滚动容量 10 MiB；大内容走现有受控内容引用，控制回执不计入可丢日志 |
| 恢复批次 | 每批最多扫描 100 条、实际尝试 20 项、读 4 MiB、持续 1 秒；任一到限返回，外部调用异步保留在原工作 |
| 恢复并发 | 宿主 16 个短批次、用户 4 个；控制、恢复查询、已有收尾、普通工作各保留宿主 4／用户 1 个槽，不相互借占；每类内部轮转，安装和评测另用非保留资源 |
| 重扫与退避 | 一轮到期扫描最长间隔起始 5 秒；单原工作服从其领域 not_before 和额度，不因为宿主轮询而实际重试；积压过大时拒绝新接纳 |
| 生命周期 | 单次只读检查／附着各 30 秒，普通关闭 30 秒；超时保留缺口并监督隔离，不修改业务截止；插件准备次数见[实例恢复](installation-and-isolation.md#5-实例异常与有限恢复) |
| 队列及收尾空间 | 每用户新管理命令待处理上限 100；每个已接纳命令预留全部有限步骤的最坏回执空间，领域工作另按各自负载预留。无法给出最坏大小／步骤数的导出不接纳；空间不足提前限流 |

宿主并发限额覆盖扫描和短调用，不能被解释为免费外部查询次数；业务成本、长期在途调用、设备独占仍由所属模块单独限制。CPU／内存限额也不控制外部 API 费用，受信出口必须受调用次数及预算约束。

同用户跨节点消耗需要已有受信配额权威或事先划分的有限节点份额；首期使用固定写权威进行接纳，份额不明或权威不可达时等待，不把每台机器本地上限宣称为全用户总额。云端可以按用户分区扩展受信宿主，但同一用户原账本及唯一操作索引的归属不能随负载漂移。十万在线并不决定安装或恢复吞吐；容量测试另统计活跃任务、未知项、制品缓存、消息积压及各领域 I/O。

## 4. 验收矩阵

每例记录前置配置、宿主／隔离 profile、制品与测试集版本、故障时点、原始领域与管理回执、观测及判定方法。所有例子的通过标准均需要运行实现；静态检查只证明文档及契约资产在其检查范围内成立。

| 用例 | 前置与刺激／故障 | 预期可观察结果 | 保证／目标 |
| --- | --- | --- | --- |
| ER-01 | 正常 P1→P2 文件插件升级后执行保存／读回 | Prepare、发布与业务接纳各有独立回执；新操作绑定 P2，任务凭读回证据完成 | ER1–3／C4–C6、A2、A4 |
| ER-02 | 同包版本替换字节；依赖缺失、环、同导出冲突分别输入 | 安装拒绝并给出明确冲突；原装配不变，无下载或代码副作用 | ER1／C6、A4 |
| ER-03 | 压缩炸弹、路径越界、链接逃逸、安装脚本及远程 Schema 引用 | 有限资源内拒绝；宿主无越界文件写入、脚本执行或隐式联网 | ER1、ER4／C6、C7 |
| ER-04 | 收到未知协议消息／必要扩展；已安装可选项载荷非法 | 按既有协议拒绝必要缺失或非法已知项；无自动安装，透明转发规则保持 | ER1／C6、A4 |
| ER-05 | 回执返回丢失分别注入 Prepare、实例准备、目录登记、激活和最终保存后 | 查原步骤得到原结果；只有一个目标实例及接纳绑定，没有同版本替身命令 | ER2／C5、C6 |
| ER-06 | 同管理 command_id 换用户或内容；并发相同预期修订激活两个版本 | 作用域不混用，异意图冲突；同目标最多一个符合预期的发布者 | ER2、ER4／C6、C7 |
| ER-07 | Abort／超时分别发生在目录提交前、提交未知、已生效后 | 仅可证明未生效且永久封闭时 aborted；未知继续查；已生效通过新停用命令处理 | ER2／C5 |
| ER-08 | P1 写入 O1 已生效但响应丢失，升级、宿主崩溃同时发生 | 保留 P1、原 O1、once 与未知预算；P2 不重做 O1；查原效果后才能排空 | ER3、ER5／C4、C5、C7 |
| ER-09 | 策略／Skill／模型版本变更时旧 decide 已准备物理调用 | 旧轮固定原输入、版本与调用身份；不换模型重发；新轮独立预留 | ER3、ER5／C1、C5、C6 |
| ER-10 | draining／disabled 与 Invoke／Start 并发；另在两步任务间替换其固定组件 | 发布与接纳串行；固定组件先停新任务引用、允许旧任务完成后排空执行，升级不自阻塞；disabled 后不新启动 | ER2、ER3／C4、C5 |
| ER-11 | 进程退出但子进程仍活跃；IPC 失联但原设备请求仍可能执行 | 不把 PID 或连接消失当作隔离；新实例不得接替原资源；外部未知继续保留 | ER3–5／C4、C5 |
| ER-12 | 无挂载／出口／资源控制支持，或沙箱版本不能落实必需规则 | 相应代码导出不装载；受信内置组件可以独立继续，无静默宽权限回退 | ER4／C6、C7、A3 |
| ER-13 | 同用户多 actor 共用驱动时交换原调用身份；另伪造 user／source、越权文件或直连网络 | 原行动 actor 从领域关联恢复，服务身份不替代原主体；越权被拒，认证连接和他人数据不可访问 | ER4／C7、A4 |
| ER-14 | 两插件及重启同时冲击用户 CPU、内存、日志、IPC 和宿主出口 | 用户聚合上限不倍增；超额实例受限，原责任和其他用户仍可恢复 | ER4、ER6／C5、C7 |
| ER-15 | Skill 注入、结果要求覆盖许可或验收，测试插件尝试生产设备 | Skill 仅作有来源数据；控制依据不改变，测试无生产副作用 | ER1、ER4／C1、C7 |
| ER-16 | 伪造评测报告、自签批准、过期或不匹配摘要、超批准用户批次；声明支持回退却缺适用依据 | 拒绝按原批准激活；一致性通过不能替代维护者批准或隔离效果评测，不能静默取消批准中的回退保证 | ER1、ER4／C8、C9 |
| ER-17 | 依赖 DAG 环、缺存储、缺 owner、旧进程未隔离、仅可选组件缺席 | 必需分支受限且指出提供方；可选项按声明缺席，不绕过条件启动 | ER4、ER5／C5、A1–A3 |
| ER-18 | A 有未知效果，B 就绪；A 已取消但迟到事实到达 | B 继续；A 保存获准事实且不新派发；不存在全局 ready 覆盖领域门禁 | ER5、ER6／C5、C7 |
| ER-19 | 丢通知、丢扫描游标、重启控制器、记录在扫描期间到期 | 有界重扫最终发现原责任，不全表无限扫描，不重置领域次数／期限／费用 | ER5、ER6／C5 |
| ER-20 | 单用户洪峰、普通队列占满、控制风暴、存储逼近上限 | 各用户和类别保留有限机会；提前拒绝新接纳，work lane 收尾仍推进 | ER6／C5、C7、C8 |
| ER-21 | 激活截止过去后进程崩溃、短暂健康后反复崩溃；关闭超时及退出后外部成功 | 有独立有界恢复事件且不重置次数；按原提交恢复、不重做激活；任务不因关机自动取消，迟到效果保留 | ER3、ER5／C4、C5 |
| ER-22 | 卸载遇未知效果、旧消息、长任务引用、有效回退声明保留、保留期未结束或删除中崩溃 | 有任一引用或保留责任则阻塞；安全撤回不重装旧代码，原回退声明标明受阻；可删除项沿回收计划续做 | ER2、ER3／C5、C6、C7 |
| ER-23 | 回退程序版本；另用丢失 ACK／消费／启动尾部的旧备份启动 | 兼容旧程序可配当前账本；不兼容或旧备份证明不足则受限，不刷新身份重跑 | ER3、ER5／C5、C7、C9 |
| ER-24 | 无可信时间或反回滚依据时断网；离线旧许可随后过期 | 离线不因安装／重启开放；恢复后先核对当前依据，旧截止不延长 | ER4、ER5／C5、C7、A3 |
| ER-25 | 观测服务中断或插件日志喷涌，同时有待保存结果 | 诊断导出受限，管理／领域回执仍耐久；不把日志确认当接纳或效果证据 | ER2、ER6／C5、C8 |
| ER-26 | 用第二个兼容实现替换三系统中一个，其余保持固定 | 公共任务、权限、错误与恢复用例仍通过；报告不支持的配置，不静默切换语义 | ER1、ER3／C6、A1、A2、A4 |
| ER-27 | V1 实际获准来源检索任务中插件切换、检索失败及旧引用失效 | 答案仍绑定实际取得的来源／时间；缺口如实说明，安装成功不计作问答成功 | ER3、ER4／C3、C6、V1 |
| ER-28 | 多个有状态模拟设备上观察→动作→再观察，中途崩溃、接管和升级 | 原操作与设备状态可核对，无重复写入／点击；未知与取消分别报告 | ER3–6／C4、C5、V2 |
| ER-29 | 经评测的版本按批准批次启用并写入数据，出现退化后沿声明路径回退；另注入旧版格式不兼容 | 兼容旧版可读取当前账本并运行支持的任务；不兼容时只报告停用或恢复受阻。精确关联基线、样本、产物、批准及分项回执，当前账本和撤权不回退 | ER1–5／C8、C9 |

先完成安装／本地生命周期与原命令崩溃用例，再验证隔离、领域原操作恢复和替换，最后进行多用户容量及 V1／V2。插件一致性用例通过不代表 1000+ API、首次调用 90% 或有限重试 95% 达标；这些仍按项目总体样本和计数口径独立验收。

容量试验至少覆盖冷启动同时扫描、热用户持续积压、未知责任长期保留和慢存储，测 p50／p95／p99 就绪时间、每秒原责任核对数、最大等待、日志／制品增长、用户公平性和收尾空间。报告实际数据规模与故障时长；没有服务实现前不给出规模达标结论。

## 5. 后续跨模块联动提案

以下条件方案尚未采用；当前保持受信本地安装、排空切换及原领域恢复的边界。跨模块依赖和唯一维护位置见[待决索引](../open-decisions.md)。

| 提案 | 问题与推荐改法 | 影响文件、代价与验证 |
| --- | --- | --- |
| ER-P1：获准产物的自动交接 | 完整提案归 [OI-P1](../observation-and-improvement/validation.md#proposals)。当前由本地受信入口核验并录入已有批准，不接受模型自报批准，也不自动接纳改进侧载荷 | 采用 OI-P1 后，扩展侧在接纳时固定原交接键、批准范围与管理责任，在激活边界复核当前依据并保存应用回执；分别沿现有命令核对停用及旧版恢复。该职责落在 ActivationBasis 与管理步骤，不以消息 ACK 代替激活结果 |
| ER-P2：跨节点制品与激活管理 | 当前本地命令不能承诺离线节点已装载或停用。需要远程发布时，建议保留单节点命令语义，另定义制品传输、节点安装／生效回执、精确来源与按节点的未决状态，禁止把交付 ACK 当激活成功 | 联动本模块、协作连接、身份、能力目录及端云协议；复用能力模块 CE-P1，统一更新字段／Schema／示例／恢复测试。需决定哪些节点承担新责任，不默认要求跨节点原子发布；验收离线撤回、部分激活、重连重投和旧实例核对 |
| ER-P3：有状态组件在线替换 | 现状排空会被长任务／未知调用阻塞；如确有不中断要求，建议先为指定组件定义旧新实现并存、原记录读取、配置引用转移及不可逆迁移边界，逐个证明后开放 | 涉及对应大脑／记忆／内核／执行文档及本模块，不能通用插件钩子直接改领域表。替代是继续排空，代价为停机；需决定支持对象和可接受停机窗口。验证切点竞争、旧响应、格式不可读和回退失败，不承诺回滚外部效果 |

采用提案时须同步相应正文、契约及验证资产；跨端设计缺失期间保持对应能力关闭。
