# 执行接口、资源控制与故障验证

状态：已确认；目标与验收原则见 [工具执行与多模拟设备](07-tools-and-simulated-devices.md)。本文件没有对应运行或评测结果。

决策依据：[确定多模拟设备与工具执行的验证方案](../../.scratch/harness-technical-design/issues/10-execution-devices.md)。只细化能力调用领域，不新增顶层协议领域，也不改变 Go 进程内、gRPC 进程间、WebSocket 端云绑定。

## 目录检索与按需加载

保留既有能力 `List / Describe`，增加 `Search`。服务绑定归属 `CapabilityService`，内部由消费方依赖的 `CapabilityCatalog` Interface 承担；目录存储、搜索索引和可选排序器是实现依赖，不进入调用参数。

| 方法 | 输入 | 输出与失败语义 |
| --- | --- | --- |
| List | 获准范围、过滤条件、页大小与游标。 | 分页能力摘要与版本；游标绑定授权视图和目录修订，失效后重新枚举。 |
| Search | 目标描述、资源类型、必需能力、用途、允许位置、候选及时间预算。 | 候选摘要、可见覆盖状态、目录修订及可解释的匹配依据；区分无匹配、部分节点不可达、索引滞后和预算耗尽。 |
| Describe | 能力引用与准确版本。 | 完整 Schema、适用条件和执行保证；版本不可用则显式失败，不静默替换为最新版本。 |

参考实现采用本地持久目录及嵌入式文本检索，支持关键词、业务分类和别名。语义检索与重排序按 Interface 扩展，可在允许位置运行；是否采用由相同千级评测结果决定，不能仅凭文本检索已实现便宣称达到 90% / 95%。目录使用 SQLite，索引可重建；索引损坏、滞后或重建期间允许有界的权威目录扫描，仍须报告覆盖和预算限制。

目录条目包含能力引用、版本和内容校验值、实现引用、输入输出 Schema、资源与用途、处理位置、前置条件、效果与幂等保障，以及支持的取消和核对方式。能力语义版本与驱动实现版本分别保留；同一能力可能存在多个实现，检索和执行不能将它们混成新的 API 数量。依赖的声明及 Schema 修订在一次已准入调用中固定。

查询内容和能力描述本身也受数据策略约束。只本地可见的能力不要求上传云端目录；联合发现只向获准节点发送可披露查询，返回授权范围内的候选或覆盖信息。缓存按授权视图和修订隔离，权限变化后重新过滤；检索分数不是执行许可，也不能跨实现直接当作可比置信度。

大脑需要补充候选时，由内核协调的上下文准备步骤进行有界检索与 Schema 加载，再交给大脑决策。检索使用模型时同样计入模型预算和处理位置检查；不能借检索建立不受管理的模型调用循环。发现不到足够信息时明确扩大检索、等待或澄清，不猜测能力或参数。

## 持久执行协调与 Driver 分工

共同执行模块承接 `Invoke / GetInvocation / Reconcile / RequestCancel` 等入口，持有操作接纳、准入、调度、去重与报告的恢复责任。Driver 只负责与具体目标交互并提供其声明支持的事实。接口是 Go 的领域类型，不暴露数据库事务、HTTP 响应或供应商 SDK 对象。

| 内部 Interface | 方法 | 调用者需要知道的契约 |
| --- | --- | --- |
| ExecutionDriver | Start / Inspect / Cancel | Start 接收稳定操作引用、固定能力及实现版本、受控参数和执行资格；返回已知未开始、执行中或已完成等事实。Inspect 接收原操作及已持久化的外部关联信息，查询或核对；不能暗中重做动作。Cancel 请求停止，不能把请求返回当作已停止。可选行为按声明返回不支持。 |
| ExecutionStore | Load / Commit / LookupCommit / ListRecoverable | 持久化操作事实、外部关联引用、待处理工作及报告 Outbox；提交核对预期记录版本和 Worker 资格，未知提交先查询。事务实现细节保留在模块内部。 |

ExecutionStore 管理执行事实，与管理任务状态的 RunStore 分属逻辑存储职责；可以共享 SQLite 文件，但不承诺跨任务与外部动作的原子事务。其提交核对键为存储内部元数据，不扩展公共操作身份；同一内部提交重试与原业务操作重试分别处理。操作接纳、可执行工作与去重记录原子保存；报告保存与 Outbox 原子推进，接收方按原操作及报告修订消费。

执行记录至少保存原操作类型及语义指纹、目标、固定能力/实现版本、输入或受控引用、接纳窗口、执行与效果维度、外部关联、控制请求、证据引用及待处理工作。沿用协议的 `NOT_STARTED / IN_PROGRESS / FINISHED / UNKNOWN`、结果及效果确认维度，不复制任务主状态机。Load 按类型化操作或资源引用读取；Commit 显式给出预期记录版本、资格和受约束的变更，不能成为远程任意写库入口。ListRecoverable 分页返回候选，处理前重新领取并校验资格。

读、接纳、重放和报告均先校验授权。已知相同操作返回原回执，新操作才应用当前接纳与版本检查；相同身份配不同语义拒绝。操作明细清理遵守接纳窗口和恢复保留规则；删除敏感载荷后无法可靠比对时拒绝重提交，不能为去重继续保留已禁止保存的正文。

开始动作前，执行端检查当前权限、数据位置、任务/Worker 资格、资源控制及预算，再持久化“准备调用且可能已发送”的恢复状态。外部调用在事务外发生。若此后崩溃，即使没有保存发送完成也不能推断未发送；恢复必须 Inspect 或利用目标支持的、仍有效的幂等保证，无法核对则保留未知效果。

外部接口返回异步作业引用后先持久保存，再安排有界轮询。推送结果需验证来源，按版本或已知事实单调合并；迟到“处理中”不能覆盖已确认完成。若外部引用随回包丢失，须按原幂等键或可证明的业务关联查询；仅支持随机作业引用的目标可能无法自动恢复，必须在能力声明和报告中保留限制。

相互矛盾的终局证据保留来源并进入核对，不凭最后到达覆盖。轮询、Driver 返回载荷与事件队列均有大小、频率和时间限制；临时进度可合并，可靠报告不得静默丢弃。等待超时不表示外部停止，未知状态的后续核对使用已确认的有限处置预算。

本地重复接纳只能保证不重复调度同一逻辑操作，不自动提供外部动作恰好一次。执行 Adapter 的幂等声明包含适用操作、作用域、有效期及恢复依据。查询不到记录只有在目标保证覆盖范围充分、旧请求已不可能稍后执行时，才可作为未生效证据；否则仍为未知。

Driver 不隐式开启 SDK 的副作用重试。确定未发送的重试、目标有效幂等保障下的重复提交及结果核对由执行协调模块按预算安排。参数或目标改变时建立新操作；原操作的未知结果必须先处置，不能靠新 ID 绕过核对。

取消、完成、接管可能并发。收到控制请求后先阻止适用的新动作，对在途动作请求停止或核对，最后依据证据报告实际状态。不可取消的动作继续跟踪，不能清空记录或提前释放其仍占用的资源资格。查询、核对及报告均受授权和数据保留策略约束。

## 共享资源控制及 GUI 观察

GUI 自动化默认以设备为串行控制范围，API 按业务资源及版本前提控制并发；不同资源可以并行。默认参考实现将同一受控资源的所有 Harness 变更路径交给一个可验证的执行协调方，不建立任意节点都能独立授予的共享锁。控制方不可达时新竞争动作等待，不以心跳超时重新授予控制。

运行节点、任务拥有者和资源控制责任分别表达。跨节点调用仍走能力协议；若未来支持离线资源控制授权，必须证明期限与旧执行者隔离，才能声明其独占保证。当前离线任务只能使用已有有效且覆盖该资源的执行资格，不因一般任务离线授权就取得共享资源的新控制权。

能力调用领域提供以下资源控制入口，已同步 [原生消息目录](03-contract-message-catalog.md)：

| 方法 | 契约 |
| --- | --- |
| GetResourceControl | 输入已有资源的类型化引用，返回授权可见的控制意图、进展及局部版本。 |
| RequestResourceControl | 输入稳定操作身份、资源范围、TAKEOVER 或 RESUME 意图、预期控制版本及授权引用。持久接纳控制更新；受理与落实分别报告。 |

既有针对单次调用的 `RequestTakeover` 可解析为相应资源接管，转交时保留同一逻辑操作身份；不能只取消当前调用而让其他任务立即继续点击。控制引用使用命名空间及已有资源定位，版本是局部元数据，不增加通用接管任务或新的全局会话身份。

资源控制记录由相应执行协调方通过 ExecutionStore 保存，包含规范化资源范围、当前意图、局部版本、在途操作集合及落实进展。接管接纳与新动作的启动登记在该控制范围内串行化并原子校验版本；先登记的动作计入在途处置，接管先接纳则后续启动被拒绝。该本地提交不包括外部动作，旧 Worker 可能产生的迟到效果仍要核对。

驱动声明资源冲突范围，并将会相互影响的 API/GUI 操作映射到同一控制范围；未知对应关系保守扩大到相关应用。范围扩大必须符合授权，不能由大脑自由指定更大的控制范围。涉及多个独立范围的复合任务分别安排工作，不承诺跨范围原子加锁或业务回滚；外部能力确有更强保证时单独声明并验证。

接管受理后拒绝该范围内的新自动化变更，等待在途动作停止或效果得到处置，才报告已落实。API 与 GUI 修改同一业务资源时均检查相应控制；映射不明确则保守暂停相关应用的受控变更。Harness 不掌握的第三方写入不能被锁住，需通过观察和版本冲突反映。

恢复需单独的获准 RESUME 操作。恢复后重新观察、核对旧动作，并由任务拥有者判断是否继续；恢复控制不撤销任务原有暂停或取消意图。迟到控制请求以操作去重和预期版本拒绝旧意图覆盖新控制；重启保持已经接纳的接管状态。

控制操作经授权后先核对已知身份：原请求重试返回原接纳回执，新请求才按预期控制版本比较并更新。控制意图与待送达、已受理、已落实的进展分别保存；只有相关在途动作已停止或已完成处置时才报告接管落实。RESUME 不能绕过仍未解决的冲突动作。执行端无法保证某条路径停止时须报告限制，不能显示已完成独占接管。

GUI 观察返回设备/应用定位、采样时间、设备生命周期版本、视图版本、图像或结构树引用、坐标系和支持的定位方式。控件定位仅在其观察范围内有效；图像坐标明确尺寸和方向。敏感观察可以仅保留在端侧，通过受控引用供端侧模型使用。

GUI 动作包括点击、滑动、输入和返回，携带目标、固定参数与必要观察前提。输入模式明确为替换或追加，不能将重复追加误当作幂等。前提失效明确拒绝并重新观察；新观察改变动作语义时创建新操作，不重写旧动作载荷。

模拟设备能够原子核对观察前提并更新状态；真实驱动如无法做到，应声明检测窗口与竞态限制。动作后的界面相同、出现成功提示或驱动返回成功都不必然证明具体业务变更恰好发生一次。核对须附观察时间、范围、来源及能支持的结论；无法建立动作与效果的关联时保持未确认。

## 最小参考实现与故障矩阵

API 验证提供两种外部接口形态不同的有状态模拟后端，两个独立 Adapter 将其映射为相同的代表性能力契约，复用验收套件。千级目录另按不同业务语义提供调用和效果判定，不能用两个后端复制 API 数量。第二种 Adapter 不要求完整重复千级目录，只为接口替换提供明确覆盖证据。

设备验证至少提供结构树驱动与图像/坐标驱动两种实现及多个独立设备状态，按各自声明复用共同动作契约并运行专属观察测试。测试判定器直接核对模拟业务状态，大脑不能取得测试专用答案。结构树缺失时不向图像驱动暗中提供控件答案；有状态模拟不要求 Android/iOS 操作系统。

API/GUI 共用状态的组合对象验证路径切换、防重复及共享控制；不同 Renderer 的模拟 UI 端另按 UI 契约运行，覆盖聊天、表单、通知、自定义组件和快照恢复。全部可在单机运行，协议故障需使用实际多进程 gRPC 和 WebSocket，节点分别持久化受控状态。

| 故障或验收项 | 预期证据 |
| --- | --- |
| 千级候选遗漏、近义混淆、资源或参数错误 | 完整目录下记录首次错误；有限纠错另计最终结果，满足已确认 90% / 95% 目标。 |
| 目录修订、权限变化、远端目录离线 | 固定版本校验、撤销后拒绝、部分覆盖明确；不得猜测不存在的能力。 |
| 接纳提交前后崩溃、重复传输 | 一个逻辑操作关联原接纳结果和恢复工作，身份冲突拒绝。 |
| 外部生效后回包丢失、异步引用丢失 | 核对原操作；无足够证据时保留未知，API 与 GUI 均不重做。 |
| 作业完成与取消竞态、过期幂等键 | 保留实际事实，不把取消受理或查不到记录当作未执行。 |
| 同资源 API/GUI 竞争、用户接管 | Harness 范围内阻止新冲突动作；在途处置后再报告接管落实。 |
| 接管后崩溃、旧 Worker 或迟到恢复请求 | 保留控制状态，旧资格和旧版本拒绝；迟到效果仍用于核对。 |
| 界面变更、追加输入、弹窗与手动操作 | 旧前提拒绝或明确驱动限制；重新观察；不重复追加。 |
| 私有截图、查询或能力描述仅限端侧 | 模型、索引、日志及 Outbox 出口均检查；能力不足不转云。 |
| 两种 API Adapter、两种设备驱动替换 | 共同契约与差异能力分别记录，不靠换配置或空成功桩证明替换。 |
| 自然语言任务、图像观察及联网问答 | 真实模型效果另验；脚本或模拟来源不能代替模型质量或真实联网证据。 |

[评测基准与发布判定](10-evaluation-contracts-and-release-gates.md) 已确定每 API 20 例单步、独立多步组、指标聚合、统计适用性及具体重试和时间上限；已有 90% / 95% 门槛保持。资源控制与凭证机制已由授权分册确定；声明导入、版本兼容及升级恢复已由扩展分册确定。本册的执行接口、未知效果与资源控制语义均已确认；后续分工不能降低这些契约。

执行准入与凭证使用已由 [授权生命周期](08-authorization-lifecycle-and-interfaces.md) 确定：纯权限判定与单次许可消费分别管理，消费同原操作启动在执行存储中原子登记，配额交付不明不能重复分配；CredentialBroker 仅为受信执行路径提供绑定目标的凭证使用。授权签名不替代资源控制与 Worker 资格。
