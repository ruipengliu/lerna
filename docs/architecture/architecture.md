# 架构分层与模块职责

Lerna 按业务责任组织模块，按依赖接口组织代码，按伸缩与隔离需要组织进程。三种划分分别成立。开发者首先需要知道谁能裁决一项事实，然后才能选择它的数据库和部署位置。

本章定义职责与依赖；[数据与存储](data-model.md)给出记录，[接口与协议](contracts.md)给出调用合同，[部署与运行](deployment.md)给出进程装配。

## 四层分别隐藏什么复杂性

| 层 | 对调用方提供的能力 | 内部承担的复杂性 | 不得越过的职责 |
| --- | --- | --- | --- |
| 应用 | 提交目标、补充输入、任务视图、受信交互 | 输入持久投递、断线恢复、进展与正式结果呈现 | 不自行改 Task 终态，不把窗口状态当业务控制 |
| Agent 领域 | 目标推进、能力执行与有依据的判断 | 目标修订、准入、效果、证据、授权和预算规则 | 不把基础设施错误直接改写为业务事实 |
| 可靠运行 | 接纳命令、提交后续工作、领取与恢复 | 去重、并发接替、提交未知、有界调度 | 不判断任务成功，不自动重发外部动作 |
| 平台适配 | 实现存储、传输与外部能力接口 | SQL、网络、供应商协议、设备驱动和平台差异 | 不绕过领域准入，不自行扩权或换操作身份 |

层次的价值在于把复杂性集中在少量稳定接口后面。例如，应用提交目标后只需保留回执和观察任务，不需要了解任务将被哪个 worker 领取；Executor 的调用方不需要知道具体供应商怎样查询原请求，但必须能观察效果是否确定。

## 领域模块与事实归属

负责方（owner）是保存一类事实、裁决其变更的逻辑服务；工作者（worker）是暂时处理工作的进程。owner 可以由多个进程提供服务，一个进程也可以在开发装配中承载多个 owner。

决策引擎（Decision Engine）依据当前目标、上下文和反馈生成下一步提案；Orchestrator 负责提案采纳、行动准入和任务完成裁决。代码目录和接口命名空间统一使用 `decision_engine`。`Decision` 表示单次决策记录，不是模块名称。

| 模块 | 拥有的事实和裁决 | 主要输入 | 主要输出 |
| --- | --- | --- | --- |
| Interaction | Session、原始输入、投递记录、Surface 界面快照 | 用户输入和业务状态 | 原目标命令、控制命令、受信呈现 |
| Orchestrator | Task、目标修订、Requirement、行动意图、Task Result | 原始要求、提案、效果和条件判断 | 决策请求、获准行动、控制、最终结果 |
| ContextCompiler | 无独立目标权威；由 Orchestrator 管理快照形成 | 当前目标、进展、来源与访问许可 | 不可变 Snapshot 与材料缺口 |
| 决策引擎 | Decision、模型请求记录、提案和模型用量 | Snapshot、策略和限额 | 结构化 Proposal 或明确失败 |
| Executor | Operation 接纳、Attempt、Effect、资源占用 | 已准入意图和有界执行许可 | 实际效果、证据、费用与关闭情况 |
| Memory | 跨任务记忆、提取候选、检索投影和更正 | 获准来源、写入或查询请求 | 带来源、时间和适用范围的记忆 |
| Content | 准确版本字节、来源、持有副本和清理责任 | 有权保存的材料 | 可核验 ContentRef 与受控读取 |
| Evaluator | 按规则形成的条件判断 | 准确条件、成果、证据与规则版本 | pass、fail 或 unknown，及适用限制 |
| 授权与预算模块 | Grant、使用额度、预留、用量结算 | 受信主体决定与实际使用记录 | 准入依据、有限使用窗口、剩余额度 |
| 扩展与评测模块 | 制品、安装、批准、就绪、实验和发布记录 | 候选实现、测试计划、维护者决定 | 当前 Binding、评测证据和可回退版本 |

授权与预算不是必须独立部署的中心服务。默认与 Task 共同裁决的记录放入 Orchestrator 所属数据库；远端资源的授权负责方可以独立存在，此时必须先交付有界许可，再进行本地准入。不能把跨库调用包装成一个不存在的原子事务。

## 哪些接口公开

| 接口面 | 使用者 | 稳定承诺 | 不公开的实现细节 |
| --- | --- | --- | --- |
| 应用接口 | Web、CLI、产品服务 | 输入投递、Task 控制和观察、交互请求、成果读取 | Job、数据库锁和每一步内部状态迁移 |
| 能力接口 | 决策引擎、Memory、Executor、Evaluator、外部 Agent 开发者 | 版本化输入输出、身份、恢复、权限、费用与关闭语义 | 默认组件内部算法、表布局、工作队列 |
| 平台接口 | 宿主和适配器开发者 | 事务、存储、时钟、密钥、传输、隔离生命周期 | 特定数据库驱动或公司平台 SDK |
| 内部接口 | 同版本框架维护者 | 同仓测试保证，允许协同修改 | 不承诺作为第三方扩展 API 长期稳定 |

公开接口按调用者任务设计。不得为了“所有模块可插拔”而暴露数据库对象和每个内部函数。扩展接口是否足够完整，应由第二种实现检验；不能只用默认实现调用自己证明可替换。

## 代码依赖与运行调用

领域包声明所需的小接口，平台适配器实现接口，宿主负责注入。Orchestrator 只依赖决策引擎等能力合同，不导入默认决策引擎的实现包。决策引擎不回调 Orchestrator 的内部存储；需要行动时返回提案，经公开准入流程处理。

```text
contract/                 公开语义类型与版本化方法合同
domain/task/              目标、条件、准入、控制与完成
domain/authorization/     授权裁决与有限使用
domain/accounting/        预留、用量与结算
components/decision_engine/  默认决策与模型适配接口
components/memory/        默认记忆、检索与投影
components/execution/     默认执行宿主与效果核对
components/evaluation/    默认条件核验
runtime/                  命令接纳、Tx、JobStore、Claim、Clock
adapters/                 PG、SQLite、对象存储、WSS、gRPC、外部协议
host/                     装配、发现、健康、排空、组件生命周期
sdk/                      应用 SDK 与扩展开发工具
apps/                     示例应用与受信交互呈现器
conformance/              同版接口、互操作和故障验收
```

以上是建议代码组织，不表示已有代码。初期同仓、一个 Go module；公开协议与 Go、TypeScript SDK 同版验证。独立进程不要求独立仓库或独立发布。

## 分布式为什么不另设业务层

远程调用改变延迟和失败方式，不改变目标或效果的含义。框架在公开命令入口统一处理身份、去重、超时、查询和恢复；同进程调用也遵守这些语义，只省略网络编码。

Task 固定归属一个 Orchestrator。负载均衡只能为这个 owner 选择健康进程，不能在原请求结果未知时改投另一个任务数据库。决策引擎、Memory、Executor 可以分别远程部署；它们各自接纳与提交，交接双方分别保留责任。

外部协议由适配器转译。MCP 的远端任务、A2A 的 Task 和 Lerna 的 Task 不直接共用状态机；远端 `completed` 只是新的输入事实，本地还需核验业务结果与未结效果。

## 插件化允许改变什么

| 可替换点 | 默认路径 | 替换后仍必须成立的规则 |
| --- | --- | --- |
| 决策引擎 | 有界 ReAct，规则决策作为确定性基线 | 只能提出提案；固定输入与版本；用量可归责 |
| 上下文策略 | 当前事实优先，按需检索和回读正文 | 不漏掉目标、控制与未决效果；材料当前获准 |
| Memory 检索 | 词法与元数据检索，保留简单对照 | 来源、时间、权限、纠正和删除语义一致 |
| Executor 驱动 | API 优先，受管文件与设备操作 | 真实入口检查、效果核对、取消与费用可追踪 |
| Evaluator | 效果谓词与规则检查；开放质量单独判断 | 声明适用范围，返回证据，不能裁决 Task |
| 协作策略 | 单任务控制者，必要时有界委派 | 子目标、授权和预算受限，父任务独立验收 |

Skill 是操作知识，Plugin 是携带代码或适配器的安装包，Agent 是持有目标、上下文和决策循环的工作主体。三者分别管理，不用同一个“插件对象”隐藏它们的生命周期差异。

## 设计的收缩条件

公共运行模板只承接反复出现的并发与恢复规则。如果模块必须大量绕开模板才能正确处理效果，应收缩模板接口，保留领域责任。若某一扩展只有一种实现且没有真实替换需求，建议先保留为内部接口。

新模块必须回答三件事：它独占哪类事实，调用方因此少承担哪些复杂性，如何通过公开接口验证。只转发参数、另造第二套任务状态或重复已有权威的模块，不建议独立建立。
