# 授权预算与插件生命周期

Lerna 的控制约束必须在模型之外执行。模型可以建议行动，插件可以声明能力，Skill 可以说明步骤；只有受信主体和业务规则能授权资源使用。升级与自动改进也不能扩大已有权限。

本章定义授权、费用、来源和版本管理。它们属于共同领域规则，不要求建设一个拥有所有数据的中央治理服务。字段见[数据与存储](data-model.md)，管理入口见[接口与协议](contracts.md)。

## 信任来源与执行入口

| 来源 | 可以提供 | 不能提供 |
| --- | --- | --- |
| 受信用户与管理主体 | 目标、明确控制、权限决定和发布批准 | 不能让系统把未知效果改成未发生 |
| 任务内核 | 按规则准入、预算预留、目标与完成裁决 | 不能证明外部系统已经执行 |
| 模型、Skill、网页、工具正文、长期记忆 | 建议、知识、观察材料或证据候选 | 不能自行扩大授权、变更目标或发布代码 |
| 已认证执行负责方 | 实际尝试、目标观察、费用与关闭依据 | 不能代替用户决定新的目标 |
| 第三方协议服务 | 声明能力、结果与远端状态 | 声明本身不能证明隔离、幂等或取消保证 |

外部文本中的指令始终作为来源内容处理。提示注入防护同时依靠来源标记、结构化行动、受限能力范围、真实入口授权和隔离环境；不能只依靠系统提示让模型拒绝恶意文字。

插件进程默认不持有广泛宿主凭据。密钥由受信出口在核准用途内使用；网络、文件和设备访问按插件信任级别隔离。受信静态组件仍必须遵守相同业务权限。

## 授权的两个检查点

**准入时**，Orchestrator 检查当前目标、准确行动参数、主体、资源、用途、范围、期限和额度，并固定 GrantUse 与 OperationIntent。授权和准入位于同库时共同提交。

**实际启动时**，Executor 检查当前资源门禁、准确行动摘要、TaskGate、GrantUse、组件就绪和资源占用。检查通过并保存 Attempt 后才允许发送。任何改变收件人、路径、金额或正文的准备逻辑必须在这一身份固定前完成。

远端 Grant 不参与本地原子事务。授权 owner 先签发绑定准确行动、有截止时间和额度的有限使用凭据，并从可用范围扣除；Orchestrator 保存该凭据后才准入。若后续准入失败，释放按原使用身份处理，不能让同一额度同时出现在两端。

一次性许可被消费后，即使调用失败、任务取消或预留释放，也不得重新变为未消费。确需再次授权时，由受信主体形成新的明确许可。

## 撤销传播与离线执行

撤销首先在原授权 owner 封闭新使用，并保存向已登记使用者传播的责任。已经签发且尚未过期的离线窗口可能继续有效；系统必须公开最大撤销生效延迟。若业务要求每次启动都取得当前许可，该能力必须在线核验，离线时等待。

| 场景 | 允许行为 |
| --- | --- |
| 云端 Task 与设备失联 | 默认停止需要新授权窗口的启动；已有发送继续本地核对与补传 |
| 已签有界离线行动 | 仅在固定动作、额度、截止和本地资源门禁内执行，不扩展为新的自主目标 |
| 设备独立 Task | 独立 Orchestrator 管理自己的目标、许可和账本，与云端 Task 不竞争权威 |
| 时钟或撤销依据无法核验 | 封闭依赖它的新行动，保留已知事实与等待原因 |

重连后先同步当前控制、许可和用量，再开放新行动。重启不能延长凭据有效期，也不能继承未经重新证明的实例就绪。

## 用户确认与界面责任

Confirmation 必须绑定原命令、准确参数摘要、请求版本、本人身份和有效期。确认后的实际业务事务再次检查条件，并与业务变更共同一次消费；普通自然语言回复不能自动替代这种受信绑定。

受信 Renderer 取得完整准确正文并成功呈现后，才启用依赖该正文的确认按钮。摘要、加载失败或过期版本不能替代正文。服务端核验原请求、当前权限和准确版本，但预览引用不证明用户实际阅读或理解。

确认等待释放工作者。用户返回时目标、价格、收件人或组件版本已改变，则原确认不再适用，返回明确原因；不得自动扩大原批准的含义。

用户可以查看、纠正、限制用途、删除信息并接管设备。取消任务与删除数据是不同命令；删除界面历史也不能抹去仍需恢复的最小执行记录。

## 预算预留与结算

预算同时包含费用、调用次数、期限和并发限额。决策引擎接收剩余预算帮助决策，框架负责硬性执行。模型声称“成本很低”不作为准入依据。

1. 准入前按供应商或能力的可证明上界预留各单位额度，包含模型输出、工具费用和必要核验。
2. 不能给出可执行上界的能力，不开放硬预算下的自动计费路径。可以采用供应商硬限额，或执行端能够强制限制且有合同依据的保守上界；用户批准一个估算数字不能阻止实际超支，不能替代该前提。
3. 执行后按实际计费来源的累计用量及修订结算差额。重复回执不重复扣费，迟到更正继续入账。
4. 只有证明不再新增消费且最终用量可确认，才释放多余预留。未知费用不能按零处理。

子任务分配从根预算扣除：根侧可用额度减少，子侧取得固定分配；子侧未封闭消费前根侧不能回收重用。根预算、子分配、已消费和未结预留必须可以核对，禁止通过多层委派突破总量。

探索、核验和收尾分别配置有限额度。达到目标行动预算上限时停止新增行动；原效果和费用继续在收尾额度内处理。额度不足则报告仍未知的部分，不以无穷核对掩盖系统无法结束。

预算闭合与 Task 终态分别保存。账单更正可以晚于封账；系统保存更正依据，不倒改用户曾经看到的原结果，也不复活一次性授权。

## 内容来源与数据生命周期

读取、处理、长期保存、同步和向外披露分别授权。派生结果受全部实际处理来源约束，不能只保留最终答案列出的公开引用。模型输出、摘要、向量、截图、缓存和运行轨迹都必须登记适用来源和持有责任。

跨来源派生的用途范围采用各来源允许范围的交集，保留期限不得超过可适用的最严限制；无法形成合法交集时拒绝派生或请求新的授权。限制是否允许转换后解除必须由明确的受信政策裁决，不能由模型自称“已匿名”决定。

撤权先封闭新使用，再传播停止与清理工作。副本状态区分使用已停止和字节已擦除。离线设备失联时保留残留与期限，不能报告已经全局清除。

遥测默认记录标识、阶段、延迟、错误类别和用量；正文、提示、截图和密钥不默认进入日志。允许记录内容时必须有用途、访问、保留和脱敏策略。调试方便不能成为跨用户读取的例外。

## 插件从安装到可服务

Plugin 包含代码或适配器；InstallLock 固定制品、依赖、配置、契约 profile、数据格式、平台和隔离要求。Capability 声明操作含义，Binding 将能力连接到准确实现和资源。安装、批准和实例就绪是三种不同事实。

```mermaid
flowchart LR
    P[固定制品与依赖] --> V[兼容与隔离验证]
    V --> A[取得有限范围发布批准]
    A --> I[启动准确实例并自检]
    I --> C[比较目标版本，提交 Binding 与就绪]
    C --> U[实际调用再次核验]
    U --> D[停用封新调用，保留原责任恢复]
```

默认 Go 内核和受信组件静态构建；第三方可替换代码运行于受控进程、沙箱或远程服务。不采用 Go 热卸载作为可靠性基础。插件构造和自检不得隐式发起模型或目标业务调用。

可查看[插件启用流程图](assets/plugin-lifecycle.svg)。图中批准和实例就绪是两个检查点，准备完成不能直接对外提供能力。

同一部署目标只有一个 BindingHead，它决定新任务默认选择哪个版本；不同准确 Activation 可以在保留期限内并存，为已经固定版本的任务服务。激活、停用和重启必须在该稳定目标上比较 revision 与 generation；两个候选不能各锁自己的安装记录后同时成为默认版本。旧初始化回调只能更新自己的实例，旧清理不得删除新实例。

重启需要新的随机 instance_id 和就绪记录；同一安装版本不代表旧实例的资格可以继承。签名和来源检查只证明制品身份，不能替代隔离、合同与故障测试。

## 在途版本升级与回退

新任务固定准确组件与策略清单，已准入 Decision 和 Operation 固定准确 Binding。普通升级只改变新任务的默认选择，不自动停用旧 Activation。已固定旧版本的 Task 可以在旧批准、实例就绪和 holder 均有效时继续产生新的 Decision 或 Operation；这些调用仍逐次经过普通准入。新任务不得在无显式配置时继续选择已被替换的默认版本。

显式 deactivate 或安全停用封闭该 Activation 的所有新调用，包括旧 Task 的下一轮调用；旧任务必须等待或走已批准的迁移路径。已经启动的原操作仍可核对。确需迁移时，必须有兼容声明、原责任 checkpoint、迁移记录和失败恢复路径。

安全停用先封闭新使用。原效果查询与结算继续由可信旧实现或经过合同验证的接管器承担；无合格接管器时保留账本与限制，不继续运行已知不可信代码。

自动回退是一次新的激活，需要旧版本独立且当前有效的批准、兼容数据格式和目标版本比较。新版批准被撤销不自动取消旧批准，也不使旧版永久可用。已经有第三版启用时，迟到回退返回冲突，不能刷新版本后强行覆盖。

数据库升级采用扩展字段、分批迁移、切换、观察和收缩。旧格式删除必须等待旧实例退出、在途工作可恢复及回退保留期结束。回退不能倒退已发生的业务事实、撤权记录或费用。

卸载先封新引用，再检查全部任务、操作、环境和评测 holder。分页只是一种展示方式，不能只检查第一页就判断零引用。清理仍有残留时返回残留清单和负责方，不报告 disposed。

## 自动改进的控制

经验候选、策略候选和代码候选使用不同发布规则。实验计划在运行前冻结数据、模型、版本、预算、指标和停止条件；调参与最终验收材料隔离。普通兼容安装与声称效果改善的发布分别说明证据，不能换标签规避评测。

发布分批进行，观察错误动作、错误完成、延迟、成本和未知效果比例。扩大范围必须满足原批准的条件；修改门槛或扩大总范围需要新的批准。可观察到的质量下降触发封新使用或有资格的回退。

评测通过不授予发布权，发布批准不证明实例已经就绪，实例就绪不证明某次任务可以越过权限。三者在查询视图中必须分别呈现。
