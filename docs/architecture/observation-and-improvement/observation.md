# 观测与数据使用

## 1. 记录分层与诊断路径

运行观测消费获准的提交后记录，继承[任务内核约束](../task-kernel/decision-and-work.md)和[身份审计约束](../identity-and-authorization/mechanisms.md)。诊断的起点可以是任务、操作或用户报告的问题，先找到所属权威及修订，再关联授权、决策、工作、模型调用、执行、消息和结果；缺失片段明确显示未采集、过期、无权读取或来源不可达。

| 记录类别 | 保存要求与使用边界 |
| --- | --- |
| 领域正确性记录 | 任务／操作、授权消费、管理回执等由原领域耐久保存，按其恢复接口查询；不能放入可丢的遥测队列后就删除原责任 |
| 诊断记录 | 有限队列、可采样、可丢弃，记录丢弃量和覆盖范围。接纳表示进入观测缓冲，不承诺持久或完整；不能作为已接纳任务、实际效果或完整评测分母的依据 |
| 评测证据 | 在独立评测账本固定来源和字节绑定；该次评分需要的证据不得采样。缺失时保存缺口，不能借用相似任务的日志补成通过 |

下图表达记录进入评测的顺序；线索获准可见，不代表允许复制为样本。

```mermaid
flowchart LR
    Fact[领域已提交事实] --> Filter[处理端过滤与用途检查]
    Filter --> Buffer[有限观测缓冲]
    Buffer --> Diagnose[关联诊断与缺口]
    Diagnose --> Reuse[评测再用途检查]
    Reuse --> Manifest[固定来源与样本清单]
    Manifest --> Evidence[隔离执行后的独立证据]
```

诊断按“任务准入 → 授权使用 → 操作接纳 → 动作／观察 → 效果核验 → 成果发布”展示事实阶段，分开显示消息送达、业务接纳和效果。查询日志失败不触发领域操作重试；需要核对时由拥有原操作的处理端按其预算和权限继续。

## 2. 关联与时序

首期推荐使用 OpenTelemetry 的 span、event 和 link 表达诊断过程；本地字段先按[ObservationRecord](contracts.md#observation)适配，不绑定特定可视化后端。短调用用父子 span，跨重启或异步工作在新片段中保留原业务标识，有已验证上下文时加 link；OpenTelemetry 的 link 可连接不同 trace 的 SpanContext。[OpenTelemetry Tracing API](https://opentelemetry.io/docs/specs/otel/trace/api/#link)

任务、操作、消息等业务标识始终保留各自含义。`trace_id` 只作诊断关联，不用于授权、幂等、账单或因果裁决；即使 trace 丢失仍能凭原 operation_id 定位。当前 [WSS 信封](../endpoint-cloud-protocol/wire-format.md)没有标准 trace 字段，首期用已有消息／操作标识在受信域内关联各端记录，不向 payload 或顶层添加字段。标准跨端传播需单独扩展 profile；缺失它不影响本地业务关联。

数据出口只允许配置中的字段和接收方，不转发任意 baggage 或上下文。追踪上下文本身也可能形成关联泄露，不编码用户、资源路径、凭据或内容；W3C 对 traceparent／tracestate 同样规定不得承载个人及敏感信息。[W3C Trace Context 隐私约束](https://www.w3.org/TR/trace-context/#privacy-considerations)

单进程时长用单调时钟差值，跨端保存各自时间、时钟来源及不确定范围。因果顺序由原请求／响应、领域修订和提交关联判断，不能按跨端墙钟排序推断先后；无法证明时钟可比时不报告精确单向网络延迟。重投与原操作恢复分别记录，计数按领域身份去重，不能把多个 span 当作多个成功动作。

## 3. 采样、指标与告警

诊断采样按用户限额和固定策略进行，记录策略版本；即使错误记录也只作有界优先保留，不承诺高峰下全量留存。业务线程只做有界投递，队列满立即返回 dropped，不等待后端恢复。丢失数在本地独立计数并按有限周期导出；若进程连该计数也丢失，覆盖标为 unknown，不据“零错误日志”推出零错误。

查询和实际导出前再次检查当前来源关闭状态、用途、接收方及 retain_until；入队时的使用依据不能授权稍后的出口。到期或撤回记录从缓冲剔除并计获准的最小缺口，权限权威不可用时停止导出，达到缓冲上限按丢弃规则处理。已经交付给获准接收方的字节不能靠清空本地队列追回。

| 观测问题 | 指标与解释限制 |
| --- | --- |
| 时间花在哪里 | 接纳等待、上下文、模型、执行、取证、收尾及报告生成的分布；任务端到端时长由统一起止定义计算，不能简单相加并行 span |
| 是否正在失去可见性 | 采样率、dropped、缓冲年龄、字段拒绝、导出失败、来源缺失与无权读取数；缺失率必须与质量图一起显示 |
| 为何不能继续 | 未知效果、未知用量、报告不可用、隔离失败、撤权、原命令待核对及其年龄；领域账本决定是否仍需恢复 |
| 是否挤占用户资源 | 每用户排队、评测 CPU／模型／存储额度及拒绝；用户配额保留独立受控记录，不把 user_id 作为公共指标标签 |
| 改进是否退化 | 绑定批次与实际版本的任务样本、契约违例及效果分布；仅采样错误或样本量不足时，只报风险线索，不给无偏成功率 |

聚合指标标签仅包含有限的组件、能力类别、结果类别、版本组和部署 profile；完整 task_id、operation_id、URL、错误原文和用户标识留在受限检索记录中。版本明细可按受限报告查询，不让任意候选 ID 形成无限指标序列。每条告警有原证据、作用域、首次／最近出现时间和处置状态；重复以同一问题键合并。告警不自动产生生产行动，改进侧处理见[监测与停推](improvement.md#monitoring)。

## 4. 再用途、撤回与删除

观测、构建测试集、模型判分、生成候选、保存报告和披露结果分别建立 UseIntent，复用[身份接口](../identity-and-authorization/contracts.md#interfaces)。受信宿主绑定真实处理主体、用户、位置、接收方及完整来源集合；先保存原使用身份，再按具体动作调用 BeginUse。预检 allow 或历史 ReadUse 回执不替代当前使用资格。动态多样本处理要求适用的持续许可；单次许可只能覆盖固定的一次使用，不能逐样本换 ID 扩大次数。

默认只记录获准元数据，不保存完整提示词、输入、截图、记忆正文、凭据或模型隐含推理。需要正文的测试集必须声明处理、保留与派生范围；打码和摘要也是处理，只有受信处理策略证明满足约束后才能扩大用途。模型生成报告及统计值继承完整来源约束，不能因不含原文就默认公开。

冻结样本只固定版本，权限持续变化。采样、模型输入、取证、评分、报告导出和发布审查前均复核；权威不可达或无法证明来源当前可用时暂停该使用，到有限截止形成不可用报告。关闭一个来源会沿本模块反向引用索引阻止样本、证据、评分、报告及候选继续使用；禁止以移除引用或只保留派生评分绕过。

来源关闭与派生提交在本模块事务域内串行：Score、Report 和 Candidate 提交时核对全部本地来源／数据代次仍开放，并同事务登记完整依赖。关闭先提交时，迟到结果不得写成可用正文，只保存获准的最小控制／用量事实及清理责任；派生先提交时，关闭工作必能发现其依赖。来源权威在模块外的，仍依当前许可及已落实的关闭传播能力判断，不以本地事务承诺远端即时撤回。

本模块只为受控载体承诺清理。首期可接纳合成／公开许可测试数据，或在同一受信宿主管理、具有可执行期限和关闭依据的数据；来自其他模块且要求持续撤回的数据，在 [OI-P2](validation.md#proposals) 的登记交接具备前不导入为持久评测集。临时获准查询仍须逐次复核，查询不能暗中扩大为长期复制。

| 载体 | 关闭与清理结果 |
| --- | --- |
| 样本、证据、报告、候选和索引 | 先原子标记不可使用并登记逐载体清理工作；再删除获准范围内字节及索引，保存回执。来源删除后不重生成同一派生产物 |
| 判分进程、临时盘和缓存 | 关闭新读入口并通知进程停止；已交付字节无法追溯撤回，结束／隔离进程后清理受管副本，未确认项单列 |
| 本模块备份 | 记录备份副本与到期，恢复时先应用独立保存的当前关闭依据；无法证明关闭依据完整则不开读取及评测入口 |
| 其他模块、外部模型或用户已导出副本 | 标为外部持有／已披露，不用本地清理回执宣称全链擦除；要求可撤回而提供方无保证时拒绝披露 |

删除正文不删除防重放事实后再接纳旧请求。最小命令墓碑与关闭依据保留至原截止、重投窗口及未决责任均结束；若政策不允许保留，先在受信权威封闭原数据集／命令代次，缺少不可回滚关闭能力时不接纳该可恢复模式。报告的内容不可变与当前可使用性分别保存：撤回可使旧报告不可读取、不可发布，但不把历史决定伪装成从未发生。

## 5. 部署边界

运行观测适配器可与领域同宿主；评测和改进控制记录复用宿主的事务存储与受控内容存储，按用户／维护作用域隔离，具体原子边界见[存储规则](contracts.md#storage)。无需首期新增通用事件总线或数据湖。观测出口可替换，必须保留过滤、有限缓冲与缺口语义。

端侧私有数据可以只在端侧评测；导出分数也须获准。跨用户基线默认使用另行许可的公开或合成数据，不读取各用户私人评测结果拼接。云端扩容按用户分区、独立评测 worker 和有限任务批额实现；十万在线不是十万评测并发，容量估算及拒绝行为见[容量验证](validation.md#capacity)。
