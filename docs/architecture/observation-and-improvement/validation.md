## 1. 实施依赖与缺席行为

下表区分现行契约与本模块仍需实现的适配器。文档中的本地闭环是设计，不表示这些运行依赖已经可用。

| 提供方 | 所需能力与现行依据 | 缺席时行为 |
| --- | --- | --- |
| 身份与授权 | 受信 RequestContext、用途／来源检查、BeginUse、撤回与原键查询，见[接口](../identity-and-authorization/contracts.md#interfaces) | 禁止导入、处理或披露对应数据；无当前依据不借用历史许可 |
| 任务内核 | [Submit／ReadTask／ReadResult／ReadOperation／ApplyInput／Cancel](../task-kernel/storage-and-interfaces.md)及固定任务策略 | 不接纳端到端评测；有组件测试环境时可明确降为组件测试 |
| 执行／大脑／记忆 | 准确能力、原操作核对、独立用量和来源记录；各模块的现行验证矩阵 | 只启用可提供完整判据的测试项，计划声明的必需项缺失则拒绝；不据日志猜费用和效果 |
| 本模块环境及采集适配器 | 隔离创建、原实例查询、只读真值、输入脚本、受信轨迹、封闭与清理 | 未实现，不接纳相应计划；核心摘要接口不能替代完整取证 |
| 扩展与运行保障 | [Prepare／Activate／QueryCommand](../extensions-and-runtime/contracts.md#commands)、隔离、排空、当前格式下回退 | 只能产生审查候选，不能声称已启用或 C9 发布闭环完成 |
| 本地受信维护入口 | 批准主体／范围核验、原管理命令关联、分批选择和停推处置 | 不批准或推进批次；普通 task.input／模型文本不能代替维护批准 |
| 内容与本模块数据持有者 | 按[共同交接](../content-and-provenance.md)取得字节、来源及有限保留依据；本模块另保存派生依赖和受管清理回执 | 不接纳需要该保证的持久样本；缺正文保留时报告不可复核，不能发布；外部全链清理仍待决 |
| 生产测量提供方 | 实际版本绑定、完整样本框架和分母、适用来源权限 | 只出诊断线索；不能从错误采样率或存活任务估算总体改善 |
| 跨端领域 profile | 身份 P1、执行 CE-P1／P2、记忆 MS-P1 等适用契约 | 首期本地调用／明确获准导入；不新增未定义 WSS 字段，离线无法核对的工作等待 |

<a id="capacity"></a>
## 2. 装配、容量与可观察性

默认在受信宿主内装配观测适配器、评测控制器、判定器和改进管理器；被测实现运行于隔离宿主／进程。控制与评测证据使用事务记录和受控内容存储，诊断导出使用独立有限缓冲。后端可替换，须通过相同的提交未知、重复、来源关闭和隔离用例。

以下数值是首轮本地参考实现的保守测试配置，估算前提为一台开发宿主、两个模拟设备、单用户评测；不构成生产吞吐或延迟承诺。真实模型费用及资源量须在启动前填写有限值，无配置则拒绝 run。

| 限额 | 首轮配置及超限行为 |
| --- | --- |
| 诊断缓冲 | 每宿主 16 MiB、每条至多 8 KiB；字段校验超限拒绝整条，队列满丢诊断并计缺口，不反压业务事务 |
| 评测并发 | 每用户 1 个活跃 run；每宿主最多 2 个在跑样本变体，按用户轮转；剩余排队，排队 deadline 到期出具未运行报告 |
| 计划大小 | 每 run 至多 10,000 个样本位置，含变体／重复；接纳前检查全部键、预留空间与预算，超限拆为预先固定的分片计划，不能运行后选片汇总 |
| 样本时间与恢复 | 每例目标测量上限 10 分钟；原任务／成本查询至多 6 次且不超过另行配置的收尾截止，退避 1、2、4、8、16、30 秒。额度用尽停止主动查询，保留 quarantine 和待处置责任 |
| 判分与费用 | 每评分项至多 1 次初判和 1 次计划允许的复判；每 run 明确生成／执行／判分／收尾的调用与费用总额，未知费用保留预留，不计零 |
| 数据与清理 | 每用户分别配置样本、证据、报告、命令与备份字节及期限；接纳前预留收尾／墓碑空间，接近上限先拒绝新 run／候选，保留关闭和核对入口 |

诊断与评测不占用生产控制／恢复的保留槽。云端按用户分区配置独立评测额度；即使同用户开多个端点也共享限额。实现须先验证两环境配对、满队列时取消／清理仍可用，再逐步增加活跃 run、每例操作量、模型并发及证据字节。十万同时在线、百万日活和千万注册用户分别转换为连接、活跃任务、数据与后台工作负载，不能按在线人数直接承诺本模块 QPS。

本模块观测自己的接纳等待、证据缺口、判分失败、报告不可用、各类成本、清理残留、停推到受信确认／实际停用的时间；不得循环把自身诊断再次当作改进任务。用于恢复的命令、报告和通知责任仍在事务账本，观测后端失效不丢责任。

## 3. 验收矩阵

所有用例固定计划、测试集、版本／配置、身份与许可、环境初始状态、故障时点和独立观察通道。故障覆盖提交前、提交后返回前、效果发生后响应前及关闭与旧请求竞争。以下是待实现的运行验收设计，文档静态通过不代表这些用例已执行。

| 用例 | 前置及刺激／故障 | 必须观察到的结果 | 保证／目标 |
| --- | --- | --- | --- |
| OI-01 | 普通保存任务执行中停止观测后端，并塞满缓冲 | 原任务与操作仍有持久责任并可恢复；诊断标缺失，不凭零错误判成功 | O1／C5、C8 |
| OI-02 | 重复、乱序消息及伪造 trace／用户关联 | 业务按原操作去重，诊断标来源冲突；跨用户不可查，不从 trace 推断身份或效果 | O1、O4／C7、C8、A4 |
| OI-03 | 两端时钟偏移，恢复后产生新 trace | 按业务关联定位原任务，单向延迟不可比时不报精确数值 | O1／C5、C8、A3 |
| OI-04 | 冻结后替换样本、阈值、候选字节或判定器 | 拒绝覆盖，要求新计划／候选；原报告仍固定原版本 | O2／C8、C9 |
| OI-05 | API 别名、重复包装、版本复制及仅有效调用通过 | 覆盖去重；缺负例／故障保证的操作不计完整支持，目录数独立报告 | O2／C4、C8 |
| OI-06 | 样本混入失败、unknown、截止与预算耗尽 | 全部留冻结分母，unknown 对成功计0并单列；不因普通unknown就删除样本或自动重做 | O2、O3／C4、C8 |
| OI-07 | 同目标超过重试数；正常多步骤；模型修复／传输重投 | 各类次数分别计，正常步骤不误算重试；任务全局上限仍成立，无隐藏业务重做 | O2、O6／C4、C5 |
| OI-08 | 双方预检失败与候选启跑后依赖失败对照；反复挑候选 | 前者无有效比较且保留失败，后者不删分母；保留集暴露后新候选不能沿原集宣称独立提升 | O2／C8、C9 |
| OI-09 | 候选尝试读取答案、改评分或访问生产凭据 | 隔离拒绝并记录契约失败；效果高分不能覆盖越权 | O3、O4／C6、C7、A2 |
| OI-10 | V2 保存已发生但响应丢失，重启评测宿主 | 查原任务／操作，真值独立记录；不重做保存，不复用未封闭设备，未知责任保留 | O1、O3／C4、C5、V2 |
| OI-11 | 模型判分超时、无效格式、重复不同结果 | 原调用未知先查；新复判有独立预算／身份，冲突不覆盖原分数，不隐含重复费用 | O3、O6／C8 |
| OI-12 | 有效输入请求、过期请求及无脚本请求；GUI 接管 | 只消费匹配受信脚本，原键恢复；无脚本等待到截止；接管后无新自动动作，原效果仍核对 | O3／C1、C7、V2 |
| OI-13 | 仅许上下文使用的日志被请求作为测试集或发给模型 | 再用途拒绝，无持久正文／未获准披露；元数据与评分也受来源约束 | O4／C2、C7、C8 |
| OI-14 | 评分算完尚未提交时关闭来源；另保留已生成报告、待批准候选及待导出缓冲 | 本地关闭与派生提交串行，迟到正文不复活；缓冲出口复核并丢弃，受管清理可查，历史评分不能继续作为发布依据 | O4、O5／C7、C9 |
| OI-15 | 清理回执丢失、恢复旧备份、删除全部正文后重投 | 原清理键核对，当前关闭依据先应用，旧请求不重建内容；外部残留不报已擦除 | O4／C5、C7 |
| OI-16 | 两用户相同内容、同命令 ID，并尝试跨用户配额／缓存复用 | 私有数据、查询、去重和消耗按受信 scope 隔离，不泄露另一用户存在性 | O4、O6／C7、A3 |
| OI-17 | 伪造批准、摘要不符、过期、超范围或模型自批 | 拒绝交接；报告pass、安装许可和发布批准各自独立核验 | O5／C7、C9 |
| OI-18 | 激活生效后响应丢失；部分目标失联 | 原 command_id 核对，分项保留实际／未知，批次paused且无下一批，不重发新激活身份 | O5／C5、C9 |
| OI-19 | 撤回批准与派发资格提交竞争，崩溃于实际调用前后；线上退化或遥测缺失 | 关闭新批次并保存通知，已取得资格的命令均按可能提交核对；分别显示停推、待处置、实际停用，不能凭本地撤回声称全停 | O5／C7、C9 |
| OI-20 | 发布声明支持回退；分别缺少适用依据，以及先由新版写入再用指定旧版恢复 | 缺依据不按原批准交接；恢复用例检查旧版读取当前数据并运行支持的任务，保留账本、授权及预算事实。只核对版本指针不算恢复通过 | O5／C5、C9、A2 |
| OI-20a | 回退遇当前格式不兼容、旧未知操作或目标失联，同时停用已生效；另以明确不保证旧版恢复的批准发布 | 停用回执与恢复受阻／待核对分别保存；只有选定处置完成才进入 stopped，改为仅停用须另存受信决定。只停用不计 C9 旧版恢复通过，不保证恢复的批准也不能代替恢复证据；不恢复旧库或补造无效果 | O5／C5、C9、A2 |
| OI-21 | 迟到证据／费用导致新报告修订，旧批准已使用 | 旧报告及历史决定不覆盖，新修订重新审查，报告失效关闭后续批次；已发生效果单列 | O2、O5／C8、C9 |
| OI-22 | run接纳／证据保存／报告提交后立即崩溃 | 原命令回执与工作可恢复，唯一评分不双计；reported与settlement_pending独立 | O6／C5、C8 |
| OI-23 | 大用户排满评测且达到存储配额，再取消并清理 | 新run拒绝／有界等待，既有取消、核对和清理有预留资源，小用户不被无限阻塞 | O6／C5、C7 |
| OI-24 | 成本返回丢失、收尾查询额度用尽、无可用处置权限 | 未知预留不归零，释放主动槽而保留责任／隔离；可查处置缺口，不无限重试 | O6／C5、C8 |

此外按[专项矩阵](evaluation.md)分别执行 V1 的回放／实时获取与引用核验、个性化有无对照、V2 多设备实际状态变化，以及各领域替换／互操作用例。报告逐项列 C1–C9、A1–A4、V1–V2 的目标等级、证据类型、实际等级和已知边界；没有运行证据时标“未验证”，不能由文档推演填写 L2／L3／L4。

## 4. 贯穿场景的计分示例

以下是解释分母的虚构数字，不是实测：固定 100 个“保存笔记并核对”任务，S1 成功 88，S2 成功 94；四格为双成功86、仅S2成功8、仅S1成功2、双未成功4，净改善6个百分点。S2 其余6例中4例有反证、2例保存响应丢失且必要证据不足，后两例仍在100的分母内并单列unknown；若还有未结成本，保留未知预留。

这一组可报告样本内改善，但未达到有限重试95%的目标；首次调用90%须在其独立调用集计算，不能从94个成功任务推出。若该计划将95%列为发布硬门槛，即使改善量足够也不通过。若100例中有1例的来源许可已撤回导致评分覆盖无法合法复核，报告转为受限／不可用于发布，不能改用99作新分母。任何新试验先固定新计划并保留原报告。

## 5. 跨模块待决提案

| 提案 | 问题、推荐及维持现状的影响 | 涉及文件、取舍与验证 |
| --- | --- | --- |
| OI-P1：自动批准与撤回交接，合并 ER-P1 | 已有本地批准记录，但自动交接载荷和激活前撤回复核缺失。建议改进侧提供可验证的精确产物／报告／批准范围／期限／撤回修订，并携带批准所绑定的回退声明；扩展侧持久保存原交接键，在接纳时固定批准范围、在激活边界复核当前依据。新增查询与撤回应用回执，逐目标区分已接纳、已生效、已停止及旧版恢复结果。先同宿主，再考虑远程；维持现状则继续受信人工核验与逐目标处置，无自动及时停用保证 | 本行是完整提案权威。联动本模块 contracts／improvement、extensions-and-runtime/contracts／installation-and-isolation／validation、identity-and-authorization 的维护批准信任依据；若跨端另改协议 Schema／示例／校验。既有全景图获准版本边无需变职责。代价为撤回传播、原命令和离线未确认管理；需决定自动化对象、批准权威及停用时限。以 OI-17～20a 及乱序撤回验证 |
| OI-P2：评测数据的外部清理边界 | 持有者登记、关闭传播和外部清理的完整提案归 [MS-P2](../memory-system/validation.md#proposals)。本模块当前只接纳可落实关闭与保留的数据；要求持续撤回的外部数据，在适用交接具备前不导入为持久评测集 | 本模块补充[再用途与报告适用性限制](observation.md#data)：样本、评分、报告及候选不能因派生而摆脱来源约束。采用 MS-P2 后以 OI-13～16 验证持有者失联、关闭传播及旧备份下的评测限制 |
| OI-P3：自动触发与候选入口的关联 | 终态触发、幂等和独立用途／预算交接的完整提案归 [MS-P3](../memory-system/validation.md#proposals)。本模块当前采用显式 Propose 和有限的普通生成任务，不由日志消费者启动生成循环 | 采用 MS-P3 后，生成任务仍经[候选入口](contracts.md#interfaces)提交固定产物、来源和生成任务关联；自动触发不赋予批准或启用资格。评测与改进侧验证重复提交不重复接纳候选，生成失败不改变原任务结果 |

标准 trace 传播、跨节点评测调度与生产随机对照不属于首期闭环；有明确需求再提出领域扩展，不因引入 OpenTelemetry 自动改 WSS 信封。
