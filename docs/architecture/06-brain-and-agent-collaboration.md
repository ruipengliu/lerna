# 大脑循环与多 Agent 协作

状态：已确认。覆盖有限决策步、Brain 与 Model 独立替换、任务委派协作，以及提案准入、持续交互、子任务收尾和预算恢复。

决策依据：[确定大脑循环与多 Agent 协作方式](../../.scratch/harness-technical-design/issues/09-brain-agents.md)。共同约束见 [内核运行](02-runtime-and-state.md)、[端云恢复](04-edge-cloud-and-recovery.md) 与 [端云记忆](05-edge-cloud-memory.md)。

## 已确认的起点

- 大脑理解、规划和提出请求；内核推进任务权威状态，执行系统报告动作与效果事实。
- 每个任务只有一个逻辑 Task Owner。自主委派形成独立子任务；普通远程能力调用不强制生成子任务。
- 内部 Agent 的生命周期由 Harness 管理，外部 Agent 拥有独立运行时。连接位置、模型供应商与任务所有权分别表达。
- 上下文带来源修订；交付模型前、模型返回后及答案或行动准入时复核失效。不能把部分检索覆盖解释成零命中。
- 处理位置、结果披露和保存权限分别受控。需要端侧私有内容的推理在允许的位置完成；没有所需能力时不得自动发送给云端模型。
- 模型或连接恢复不能清除取消和暂停意图；效果不明的动作先核对，不因重新规划生成新身份重复执行。

## 已确认方向：以有限决策步组织大脑循环

内核以当前任务快照调用 `Brain.Decide`。每次返回一个完整的结构化决策提案，表达下一段有限工作；内核校验并持久化后再安排后续工作。参考大脑采用“观察当前事实—提出计划与下一步—消费反馈—调整计划”的循环。

计划表达预期步骤、依赖和验收要求；计划中的文字不是待执行指令队列。只有本次明确请求并经准入的行动或委派才成为持久化工作。简单问答可以直接形成回答提案，不必先生成一份完整计划。

| 决策输出 | 语义 | 内核责任 |
| --- | --- | --- |
| 请求行动 | 给出有限的一组能力请求、目标、参数与明确依赖；读取信息也通过受控能力接入。 | 校验能力、权限、数据位置和运行控制，记录稳定操作身份后调度。 |
| 请求委派 | 给出有限子目标、输入范围、结果要求及约束。 | 建立持久委派关系，经任务契约提交，保存与子任务的关联。 |
| 请求等待 | 指出缺失输入、依赖或授权等具体原因及恢复条件。 | 建立等待项或依赖记录；仍有可运行分支时不将整个任务判成等待。 |
| 提交结果 | 给出回答或产物、支持依据、完成判断与尚未解决的问题。 | 检查完成条件和未决效果，决定结果是否可发布、任务是否可进入终态。 |

提案可以携带计划修订和简短决策依据，但不要求保存模型内部思维链。提案关联任务状态版本、上下文来源修订及大脑实现版本；不为计划节点、模型尝试和每个文本片段新增全局业务 ID。

设计 Interface 保持小表面：输入包含目标、约束、受控上下文、可见能力、剩余预算及既有工作摘要；输出包含完整提案或明确的能力不足、格式无效、输入失效等失败原因。供应商对象、数据库连接和设备连接不进入该 Interface。

并发结果使提案依据过期时，参考实现严格拒绝旧状态版本提案并重新决策，不能让旧提案覆盖新状态。大脑在一次决策内部可以有界地调用模型、修复输出格式，但不能通过私有工具循环自行执行设备动作、写记忆或创建子任务。

**取舍：** 每一步都有持久化与校验成本，但运行恢复不依赖模型的会话记忆，也能替换大脑策略。参考实现不强制全量静态工作流图；复杂规划可在同一提案契约后扩展。

## 已确认方向：大脑策略与模型生成分别替换

提供两个独立的 Seam：`Brain.Decide` 隐藏决策策略，`Model.Generate` 隐藏模型接入。模型输出进入大脑的解析与校验过程，不直接成为已获准执行的调用。

| 模型契约内容 | 要求 |
| --- | --- |
| 输入 | 受控内容块、所需输入模态、输出 Schema、允许处理位置、生成限制及取消上下文。 |
| 能力声明 | 支持的输入输出模态、结构化输出方式、流式能力、上下文限制和实际处理位置；不根据供应商品牌猜测能力。 |
| 输出 | 完整生成结果、结束原因、可获得的用量和供应商请求引用；引用只作诊断，不能充当业务去重身份。 |
| 流式输出 | 区分临时增量与完整结果；不完整工具参数不能执行，临时文本不能作为任务完成依据。 |
| 失败 | 区分不支持、暂时不可用、输出截断、格式不合约、输入失效和生成取消；未知用量不能当成零成本。 |

处理位置和所需能力先作为硬性筛选条件，再按配置选择模型与可接受的回退目标。回退不得默默改变披露范围或舍弃必需模态；没有合适实现时明确报告不足。

模型请求超时可能已经消耗资源。重新生成不保证相同文本，也不保证供应商只计费一次；可以重试的生成工作与不可盲重做的设备动作分别处理。已准入的行动由内核记录恢复，不能重新询问模型来推断动作是否发生。

开发期用脚本化大脑和可控模型替身运行恢复、拒绝和异常契约测试，再用模型驱动大脑验证真实规划与答案质量。模型可以按部署条件接入本地或远程实现；替身通过测试不代表模型效果已达标，也不强制单机参考环境具有特定规模的本地模型。

**取舍：** 模型归一化需要 Adapter 工作，但核心不绑定供应商工具调用格式；能力声明保留差异，避免将所有模型宣称为完全等价。

## 已确认方向：以受委派任务组合 Agent

参考协作采用父任务协调、子任务自主运行的结构，支持串行委派、并行分工与结果汇总。Agent 的角色和策略可替换；不把“规划者、研究者、执行者”等角色写死为内核进程。

1. 父任务大脑提出子目标及可披露输入。内核收缩授权和资源范围，记录提交意图与稳定操作身份。
2. 受委派方按任务契约接纳，具有自己的 Task Owner、状态与恢复责任。父任务提交不明时查询原操作，不能再次创建同一逻辑子任务。
3. 子任务在许可范围内独立决策；输出结构化结果、证据引用、覆盖范围、未解决事项和可见效果状态。
4. 父任务按自身验收要求消费结果、处理冲突或追加验证；子 Agent 的“完成”报告不是父任务目标已满足的充分证据。
5. 取消与失联依既有端云规则处理；取消请求受理不等于子任务已停止。

委派关系表达运行责任，协作消息表达信息交流。允许通过受控路由向关联任务传递补充事实和协作请求，但接收方内核决定是否接纳为输入；其他 Agent 不能直接修改接收方任务状态或扩大其目标、权限。消息式协作不依赖共用可写聊天记录。

外部 Agent 通过既定任务协议 Adapter 接入，显式声明查询、取消、进度与证据能力。无法核对的外部工作应保留不确定性，不由本地包装成已确认效果。具体外部协议映射沿用已确认的协议分册，本轮不追加未经核验的 SDK 支持承诺。

端云协作中，云侧可委派端侧处理私有目标，端侧只返回获准披露的结果，也可直接向获准端侧 UI 呈现私有回答。云侧只能据可见的控制事实管理关联工作，不能声称已阅读端侧私有论据。仅需端侧检索时继续用能力调用，无须建立自主子任务。

**取舍：** 这种参考协作易于归属预算、错误和恢复责任；复杂网络式协作可组合任务与受控消息，但本轮不默认提供任意 Agent 共享写入任务状态的机制。

## 已确认方向：明确完成证据与有限自主运行

在任务接纳时保存目标的验收要求和运行预算；大脑可以建议细化，不能自行放宽用户条件。预算覆盖决策次数、模型用量、执行次数、并发、委派深度及期限，按配置限定，不在设计阶段编造性能或成本数值。

参考大脑依据可见事实判断目标满足程度，并将完成依据交给内核。可机械检查的条件由规则或验证能力核验；开放式答案使用来源支撑、冲突与缺口表达，质量仍需单独评测。不能承诺用一个通用判定器证明任意目标完成。

- 输出格式修复、重复无进展和失败重试必须有限；达到界限时报告原因及已完成部分。
- 预算或必要能力不足时停止增加相关工作，进入可解释的等待或失败路径；具体状态映射见关联运行分册。
- 必须完成的分支失败或效果不明时，不能宣告完整成功。可以交付已验证的部分结果，同时保留未决工作与控制状态。
- 暂停、取消和新的授权限制由内核落实，不依赖模型主动遵守；预算耗尽不应阻止必要的取消、结果核对和恢复处理。
- 内部测试对任务事实、恢复和准入断言，不以逐字复现模型输出为契约要求。

**取舍：** 有限预算与完成检查增加运行元数据，但避免无界循环以及将“模型说完成”当成系统完成。它们不改变用户已经授权的自主执行范围，不新增每次行动都要确认的流程。

## 已确认的运行细节

以下细节已确认，完整契约见 [决策准入、交互与协作恢复](06-decision-admission-and-collaboration.md)：

- 决策提案字段、有限批次的准入原子边界、状态变化后如何拒绝旧提案，以及大脑版本替换时的检查点兼容。
- 流式答案的预览与正式发布、用户新输入到达时的重规划、已有 UI 等待项失效与恢复。
- 子任务结果归并、并行失败策略、取消传播、补充协作消息的接纳与重复处理。
- 预算在父子任务之间的分配与回收、未知模型用量、无进展检测和停止原因的状态映射。
- 共同 Interface 的替换测试、端侧受限推理及多 Agent 故障矩阵。

授权材料及预算调整已由 [授权分册](08-authorization-lifecycle-and-interfaces.md) 确定；插件安装与版本激活见 [扩展分册](09-extension-ecosystem.md)，评测配置与候选发布判定见 [评测分册](10-evaluation-contracts-and-release-gates.md)；本分册只向它们提供大脑和协作的约束，不重新选择已确认的权限和端云协议路线。

## 已确认补充：千级 API 选择

用户要求超过 1000 个 API、首次调用正确率至少 90%、有限重试后的任务成功率至少 95%。已确认通过权限过滤、候选检索与按需加载 Schema 准备可见能力，再由大脑生成调用提案；目录查询和检索中的模型使用由内核协调并计入预算。具体契约见 [执行接口](07-execution-contracts-and-validation.md)。候选遗漏及内部纠错均计入适用效果指标，不改变本文已确认的有限决策提案、模型替换与内核准入职责。
