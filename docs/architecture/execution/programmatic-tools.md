# 受限程序化工具候选

[执行设计](README.md) · [最终参数与出口](implementation.md#dispatch-encoding) · [平台隔离](../security/README.md#boundary-validation) · [实验登记](../validation/optimization-evidence.md#experiments)

报告材料已由工具取得时，一段程序可以按固定规则筛选字段、合并结果，再返回带来源的材料。这条路径先固定代码、输入和运行配置，在受限环境中执行，最后交回准确输出、调用清单及缺口；需要继续读取、调用模型或委派时，每项新增工作仍经过原 Task 的准入。

本候选借鉴 Pi Codemode、DeepSeek VM／Python 和 Prime RLM 的程序组合方式，归 Executor driver。程序处理、过滤和组合已经获准的数据；Task 的目标、预算、控制及完成仍由 Orchestrator 决定。当前是候选设计，不表示已提供相应公共工具、host-call 协议或隔离实现。

## 1. 两种接入路径

| 路径 | 身份与执行 | 启用条件 |
| --- | --- | --- |
| 编译为有限计划 | 编译产物固定输入、准确能力、有限步骤、退出条件；每步沿原 Task 实例化原 Operation | 沿原有限计划及 X-06；编译器不得插入隐藏模型调用，动态内容或未知效果使相关步骤停止 |
| 交互式 cell | 父 Operation 固定代码 Content、运行配置、运行时版本与输出 Schema；每个有界 host call 有稳定位置及原子接纳映射 | 另按 X-08 冻结实验；内部 host-call 接纳、挂起和继续契约先完成实现及验证，不能假定现有公开协议已提供该能力 |

交互式 cell 的受信宿主把“父操作＋固定调用位置＋输入摘要”映射到原 Task 的一次接纳，持久保存映射后才派发。工具效果建立原 Operation，模型调用建立独立 Decision／ModelCall，子 Agent 建立原 Delegation。继续时按原标识查询，重投相同位置不产生新责任；不同输入冲突。程序不能自己调用供应方 SDK、消费未登记预算或启动第二个自主循环。没有这条受控接纳路径的宿主只开放纯计算。

父程序的 CPU、内存、运行时和存储开销单列；被调工具、模型及子任务的费用引用其原账。同一物理消费不得在父子两边重复相加。代码、输入、输出及压缩结果继承实际来源，程序名称和代码审查不能解除 local_only 或保存限制。

## 2. 真正的执行边界

| 资源 | 必须实施与记录的限制 |
| --- | --- |
| 文件 | 固定根与访问模式、链接解析及最终目标检查；禁止通过符号链接或路径替换越界，明确临时空间额度 |
| 网络 | 默认关闭；开放时由受信代理检查当前目标、DNS 解析、重定向与实际连接，禁止绕过代理的原始套接字 |
| 凭证 | 运行时没有宿主秘密；按准确能力在真正出口使用凭证，不把环境或全量凭据注入程序 |
| 子进程与本地接口 | 默认关闭；需要时声明可执行程序、进程树及退出能力，不隐式继承宿主文件描述符与设备权限 |
| 资源与输出 | 固定 CPU／墙钟期限、内存、并发、host-call 次数、输出字节及日志上限；达到限额保存明确的截断／中断事实 |

仅叫 VM、sandbox 或使用某语言运行时不能证明隔离。只在通过 SEC-02 与 EXE-03 适用平台探针的配置上开放；缺少网络、进程或最终路径边界时关闭相应能力。合法纯计算、有许可的精确文件读取及有限组合也必须通过正例，不能以全部拒绝代替隔离实现。

## 3. 取消、恢复与结果

abort 接纳、停止信号送达、cell／子进程实际退出分别可观察。未证实退出时保留物理并发名额和原子调用责任；Task 取消封闭新 host call，已发生的效果、未知项及晚到账单继续核对。父 Operation 退出不证明子操作无效果。

恢复只加载固定 Schema、版本和额度内的被动数据检查点；禁止把不可信 pickle、dill 或任意对象图恢复成可执行状态。先查原 host-call 映射与子结果，再决定能否继续纯计算；未知外部效果不重放。不能安全恢复 cell 时结束该尝试并暴露缺口，不能以清空映射或换一个父操作假装首次执行。

结果沿[原结果与派生呈现](implementation.md#result-provenance)保存：原输出、截断范围、实际调用清单、未决子责任和准确派生引用分别可查，最终文本不替代原效果。

<a id="reusable-environment"></a>
### 3.1 可复用环境与 Operation 分开

只有需要跨调用保留计算状态时，Executor 才管理可复用 kernel、后台进程或工作区环境。环境保存稳定资源身份、负责 Executor、实例与控制代次、准确配置、租户／使用主体、占用、活动调用及停止核对责任；不能仅用进程号或 Session 标识判断是同一环境。它可服务多个 Operation，每个 Operation 仍固定自己的代码、输入、使用许可、目标关联和费用。

| 生命周期边界 | 最小合同 |
| --- | --- |
| 创建与绑定 | 创建本身使用准确能力与原 Operation；答复未知先核对原环境创建，不通过另建环境释放旧占用。绑定保存实际运行配置与隔离证据，未就绪不可接纳计算 |
| 读取与复用 | 查看元数据、取得保留变量、运行新 cell、停止与销毁分别核对用途及管理权限。新的 Operation 重新检查 Task 控制、当前许可、来源、环境配置和剩余额度；变量留在内存不延长其使用许可 |
| 并发与占用 | 默认同一有状态环境串行处理 cell；并行仅在声明并验证独立状态／资源域后开放。宿主按实际活动及未知退出保留物理容量，不能因客户端停止等待或 Operation.closed 提前复用忙环境 |
| 取消与退出 | 取消指定 Operation、停止环境、销毁持久材料分别报告。宿主保存停止请求及实际进程树退出证据；旧回调绑定原实例／代次和 Operation，不能更新后来重建的环境 |
| 失联与冷恢复 | 首先核对原实例、控制、活动调用和当前来源；无法证明旧执行已退出则保留隔离与缺口，不凭租约过期将其当空闲。确需重建时使用新实例身份，旧环境的效果和账务继续可查 |
| 检查点与清理 | 检查点固定来源环境、计算位置、配置和有界 Schema，并列出不包含的资源。它可恢复获准计算数据，不恢复 socket、进程、设备占用或外部效果；清理正文和变量不删除未决调用及最小停止／去重依据 |

检查点加载沿前述被动数据限制，不能从 pickle／dill 恢复任意代码或把未知 host call 重演为首次执行。使用资源隔离与停止证据的具体平台驱动、环境查看／销毁及 cell 控制协议均待独立交付；现有 `resource.*` 与普通 Invoke 不能直接宣称具备完整 kernel 互操作。未启用环境复用时沿单次有界工具路径，不为普通 Operation 建立常驻环境。

## 4. 验收与采用

覆盖文件链接／路径替换、DNS 重绑定／重定向、凭证与子进程越界、资源耗尽、取消与实际退出间隙、映射提交后崩溃、效果发生后失答复、恢复数据注入，以及合法组合正例。共同向量登记为 [HAR-09](../validation/harness-scenarios.md#har-09)。记录全部尝试、物理请求、维护成本及独立任务结果。

环境复用另外观察：cell 已回复 aborted 但进程仍忙时不能接纳冲突调用；后续 Operation 不继承旧一次性授权；原来源关闭后保留变量不可再次读取或外发；新实例不消费旧回调；恢复检查点不重放已经可能发出的工具写入。运行与平台证据缺失时保留未验证，不以文档中的环境记录推定能力已实现。

有限计划与交互 cell 的因素、分母和恢复能力不同，分别取得 X-06／X-08 证据。未证明相对原单工具路径的净收益，保留原路径；不为支持候选提前引入常驻 kernel 服务。
