评测与进化负责测量 Agent 的契约符合性和任务效果，并从运行经验中提出改进。它持有测试集、候选产物、评测计划、评分和报告，**不写任务状态、动作效果、授权、预算或实际发布状态**。候选通过评测后，由扩展管理发布。

本设计的要点：

- **正式评测冻结一切**：候选、基线、测试集、环境、评分规则和完整的运行清单都在开始前固定；失败的运行不得通过"再试一次"消失；
- **开发集和正式集分开**：开发集用于生成和筛选候选；正式集保持独立，逐题答案和轨迹不回流；
- **契约和效果分开评分**：契约违反一票否决，效果再好也不得抵消；
- **证据独立于候选**：评分依据模拟目标的真实状态、核心记录和实际出口，不相信候选自报的"完成"或它产生的日志；
- **回滚只改变后续任务的版本选择**，不重新执行原任务，也不自动撤销外部效果。

## 1 职责与边界

| 事实或工作 | 唯一负责方 | 本模块的使用方式 |
| --- | --- | --- |
| 测试集、评测计划、评分规则版本、报告 | 评测与进化 | 持久保存、冻结版本、生成可追溯的报告 |
| 命令回执、待办工作、领取与租约 | 持久工作 | 使用其公共接口，不另建语义不同的内存队列 |
| 任务、条件、准入、完成判断、Result | 任务编排 | 创建测试任务和候选生成任务，查询事实，提交证据 |
| 执行尝试、效果、核对 | 动作账本 | 查询和关联，不把评分写成动作效果 |
| 当前授权、预算、实际用量 | 授权、预算 | 每次使用都检查；模型评分和辅助调用也要准入和记账 |
| 测试内容、运行记录、候选产物的来源与删除 | 内容治理、运行记录 | 通过受用途限制的引用访问，登记派生关系 |
| 安装、兼容检查、灰度、回滚 | 扩展管理 | 提交带报告依据的建议，查询原交接的结果 |
| 插件和核心代码的修改 | 维护者的代码审查 | 只生成补丁和评测材料，维护者确认后发布 |

适用边界：

- 测试任务走正式的核心接口和准入路径，没有"评测特权"（R1–R7）；
- 候选、候选的输出、候选读到的外部内容都视为不可信；评分器、证据采集和环境控制由项目维护，候选不得修改；
- 测试使用隔离资源和测试凭据，不持有生产写入凭据；端侧专有内容在端侧评测，未经授权不上传原文、派生数据或报告；
- 评测核心补丁时，被测核心自己的记录不能证明自身正确，必须核对实际出口和模拟目标的状态；
- 不训练基础模型，不自动补偿外部效果，不把模拟设备上的成绩当作真机支持。

评测报告是平台的测量记录，**不是**核心事实；核心的"持有事实"原则不延伸到评测元数据，但报告也不得写入任何核心对象。

## 2 对象与状态

### 2.1 主要对象

| 对象 | 关键字段 | 约束 |
| --- | --- | --- |
| 测试集版本 | 测试项及其版本、成员摘要、用途（开发、契约回归、正式）、C/G/S/V 标注、分层与权重、来源分组、所需能力、初态和核验方法 | 冻结后成员和权重不变；按来源、模板和任务组合分组切分，同源的近似题不跨集合 |
| 评测策略版本 | 契约必测项、主效果指标、回归门槛、预算与时限、重复次数、停止规则、基础设施异常规则、正式查询配额、反馈范围、发布观察要求 | 只有维护者能改；门槛变化生成新版本，不得用来把本轮失败解释为通过 |
| 候选版本 | 类型、父版本、产物摘要、实现与依赖版本、声明的能力和权限、来源、生成任务、开发评测引用 | 冻结后修改生成新候选；权限只能收缩；正式集不得作为生成来源 |
| 改进活动 | 版本谱系、开发集、允许改进的对象、候选上限、预算、正式查询额度及其使用 | 改名、微调提示或新建候选，都不得重新获得正式查询额度 |
| 评测计划 | 用途（正式、开发、诊断）、候选、基线、测试集、环境、评分方法、策略、完整运行清单、预算、时限、计划摘要 | 正式计划接纳后不得增删测试、追加重复或更换对象；所有依赖固定到内容摘要 |
| 测试运行 | 评测编号、测试项版本、候选或基线、重复序号、环境实例、初态摘要、随机参数、任务引用、证据引用、费用引用、异常归因 | 重启不改变运行身份；输入已暴露后不得悄悄重置 |
| 评分与报告 | 运行清单、证据摘要、评分器版本、逐项断言、契约结论、效果指标、完整分母、未完成项、污染标记、时间和费用、结论、修订关系 | 不接受候选自报的"通过"；修订保留原报告 |
| 发布交接 | 候选和报告引用、预期的稳定版本、发布策略、授权引用、扩展管理的回执 | 只记录本方意图和回执；实际发布状态属于扩展管理 |
| 观察窗口 | 发布版本、对照版本、范围、任务分配、最少样本、截止时间、完成与未完成任务、指标、缺失数据 | 不只采集成功的任务；迟到的观察不得改变已回滚的发布 |

**环境版本**至少包含：核心与契约版本、推理与记忆策略、适配器和扩展版本、模型标识及供应商提供的修订信息、提示模板、依赖和镜像摘要、设备模拟器版本、检索快照、记忆初态、资源限制。供应商不能提供不可变的模型版本时，报告注明这一复现边界。

只记模型名称是不够的。Anthropic 的工程报告指出，评测的是模型和 Harness 的组合，残留文件、缓存和 Git 历史都会让不同运行互相影响（[Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)）。运行目录、显示名称都不得单独作为缓存身份：SWE-bench v3.0.15 在已有 `report.json` 时直接返回旧报告，不核对本次的补丁摘要（[源码](https://github.com/SWE-bench/SWE-bench/blob/b524f150d5d76f188c741d75669025f718c89c2e/swebench/harness/run_evaluation.py)），复用路径换了补丁就可能拿到旧结果。

### 2.2 三种身份

| 身份 | 由什么确定 | 可以发生什么 |
| --- | --- | --- |
| 一次正式评测 | 用户、改进活动、冻结的计划；由受信的控制端登记 | 可以按原计划恢复，不得追加"再试一次" |
| 计划中的一次测试运行 | 评测编号、测试项版本、候选或基线、重复序号 | 可以接续持久状态；不得用新的随机结果替换失败 |
| 一个动作的执行尝试 | 动作账本的原尝试标识 | 只能按 G1 和适配器声明安全重试；费用按实际计费来源结算 |

### 2.3 状态

| 对象 | 状态转换 | 禁止的转换 |
| --- | --- | --- |
| 测试集 | 草拟 → 冻结 → 停止使用；撤回后进入清理 | 冻结后原地修改；泄漏后继续作为正式集 |
| 候选 | 生成中 → 已冻结 → 停止使用 | 修改不产生新版本；评测通过后增加权限 |
| 改进活动 | 开发中 → 候选锁定 → 正式评测中 → 已结束 | 正式失败后解除锁定，继续查询同一批正式题 |
| 评测计划 | 已接纳 → 准备中 → 运行中 → 汇总中 → 已封存；可停止推进或等待恢复 | 取消时删除已运行的项 |
| 测试运行 | 已计划 → 环境就绪 → 执行中 → 收尾或等待证据 → 已记录 | 环境丢失后直接回到干净初态重新采样 |
| 报告 | 证据不足 → 已封存；需要时产生修订 | — |
| 发布交接 | 意图已保存 → 对方已接纳 → 回执已保存 | 回执丢失时另提一个发布请求 |

报告的结论分三种：**满足门槛、不满足门槛、结论不充分。零测量不得通过。**

**评分已记录不代表被测任务已成功关闭。**比如一个预期保持"效果未知"的故障用例，契约检查可以通过，但这个任务不得计为成功。

## 3 接口

所有命令经持久工作取得持久回执。接口区分三种含义：**责任已接纳、业务处理完成、满足评测门槛**。超时返回可查询的原命令标识，不解释为未执行。

| 接口 | 输入 | 成功含义 | 主要错误 | 幂等 |
| --- | --- | --- | --- | --- |
| 登记评测资料 | 类型、内容引用、版本、来源、用途 | 资料已持久登记并通过检查，返回不可变引用 | 用途失效、来源缺失 | 原命令返回原引用；内容相同可复用，但不继承权限 |
| 请求生成候选 | 来源、开发集、父版本、修改范围、授权、预算、停止规则 | 核心已接纳生成任务（**不是**已有候选） | 无权、预算不足、范围越界 | 同命令关联同一任务 |
| 冻结候选 | 生成任务、产物、能力与权限声明、依赖 | 候选引用和摘要 | 派生未登记、权限扩大、产物不完整 | 同产物返回原版本 |
| 开始评测 | 用途、活动、候选、基线、测试集、策略、环境 | 评测编号、计划摘要、接纳回执 | 配额耗尽、计划冲突、资料失效 | 同计划返回原评测，不同计划报冲突 |
| 查询评测 | 评测编号、视图或报告版本 | 进度、缺口、报告引用 | 无权、用途不允许 | 无副作用 |
| 取消评测 | 评测编号、预期版本、原因 | 取消已保存；列出已发出和待核对的动作 | 并发冲突、状态不允许 | 重复取消返回原决定 |
| 接纳证据 | 原运行、任务或动作引用、证据、发生和观察时间 | 证据已保存；效果事实仍由动作账本处理 | 来源不可信、身份不匹配 | 按证据身份去重 |
| 封存或修订报告 | 评测编号、固定的证据集合、评分规则、原报告 | 报告引用和资格结论 | 缺测、证据冲突、污染、评分版本错误 | 同证据同方法复用原评分；**不得随机重评挑最好的** |
| 建议发布、暂停、回滚 | 候选、报告、发布策略、授权、预期发布版本 | 扩展管理的接纳回执（**不是**已生效） | 授权失效、基线过期、并发冲突 | 用原交接查询 |
| 分析观察窗口 | 发布引用、固定窗口、授权范围 | 观察报告和推进建议 | 数据不足、用途失效 | 同窗口同证据得同一结果 |

正式评分器和评测策略的登记权限只授予维护者流程，候选生成任务不得使用。通知只提示"状态更新了"，消费方必须读持久记录。

## 4 关键流程

### 4.1 测试资料、基线和候选生成

1. 读取运行记录前检查当前授权：操作权利（读取、保存、同步）分别检查，处理目的必须包含"评测"或"生成改进"，"诊断"不能代替；"已经读过"不得代替 G8；
2. 经验、测试材料和候选产物都登记为内容，保存来源和派生关系（**持久化点 E1**）；
3. 测试资料分为开发、契约回归、正式三种用途；同一来源、模板或同一轨迹派生的题按组切分；正式参考答案和评分材料不进入候选的环境；
4. 固定**基线**：当前稳定版本，以及一个简单的默认策略。简单基线同样启用完整的核心保障。研究指出，不控制尝试次数和成本时，复杂方法常常比不过简单的重试基线（[AI Agents That Matter](https://arxiv.org/abs/2407.01502)）；
5. 生成候选作为普通任务执行，模型调用和辅助调用都经过准入、出口闸门和预算；开发反馈可以产生新的候选版本；
6. 在开发集上选定候选后，冻结产物、依赖和权限声明（**持久化点 E2**）。

开发集上的改善只是**待验证的假设**。自我反思和候选自测同样如此：Reflexion 在 MBPP 上反而低于基线，作者把部分原因归于自生成测试的假阳性（[Reflexion](https://arxiv.org/abs/2303.11366)）。

### 4.2 正式评测：防止反复试到通过

1. 由受信的控制端分配正式题目，候选不得挑选自己擅长的题；
2. 在一个事务中锁定候选、基线、测试集、评分策略、环境、完整运行清单，扣除配额，登记待交接意图（**持久化点 E3**）；
3. 一个改进活动原则上只提交一个候选；修改后再验证必须用新的独立批次，换名称不得重置额度；
4. 同题重复次数事先固定；首轮失败或结果接近门槛都不得追加运行；
5. 进程恢复、回执查询和安全的传输重试**不增加样本**，工作者接续原运行的身份；
6. 测试输入一旦暴露、或模型调用已经发生，环境丢失就不得按"没开始"处理，这次运行保留为异常；重跑只用于诊断，不替换正式成绩；
7. 正式报告保留全部预先登记的运行。候选自己造成的资源耗尽、非法访问、超预算，属于候选的行为，不得归为基础设施异常而排除；
8. 正式的逐题答案、诊断和轨迹不回流候选生成，只允许策略限定的有限资格反馈；一批题用完或暴露后退出正式用途。

只隐藏逐题答案还不够：反复观察总分并据此修改候选，同样会让留出集失去独立性（[Dwork 等，可复用留出集](https://arxiv.org/abs/1506.02629)）。所以正式查询要有配额。

这个流程保证的是**受信评测流程内的完整登记和停止规则**，阻止不了维护者在流程外复制数据、离线反复调优；报告要写明信任范围和已知的暴露历史。

### 4.3 隔离运行与证据采集

1. 每次运行建立独立的初态：文件、缓存、Git 历史、记忆、设备状态和模拟目标的数据都来自固定快照；
2. 核对实际加载的产物与计划摘要一致，验证资源限制、网络出口、挂载和凭据（**持久化点 E4**）；
3. 候选只能访问当前任务需要的输入和允许的工具；评分进程、正式答案、其他运行、报告库和生产资源都不可达；
4. 创建测试任务，跨域交接遵守 R7（**持久化点 E5**：核心的任务、准入、尝试和交接回执）；
5. **独立采集证据**：模拟目标的真实状态、核心的准入和动作记录、实际出口、时间和费用；候选的文本只是待核实的内容；
6. 动作结果未知时，由动作账本核对；本模块等待或记录缺口，不重发动作，不用"重置环境"来规避未知；
7. 正式运行之间不保留学习状态。场景确实需要跨任务记忆时，事先登记生命周期和允许的内容，结束后清理。

**容器隔离不等于出口封闭。**Inspect 的文档说明，容器内禁网不会限制宿主上的评测进程、模型供应商调用或容器外的工具（[沙箱说明](https://github.com/UKGovernmentBEIS/inspect_ai/blob/9f6accda8dce5ccd754e6be1a22fbcee96042e82/docs/sandboxing.qmd)）。候选、工具、评分和辅助模型调用的出口都要覆盖。不可信候选在受限容器（配合系统调用隔离，如 gVisor）和微型虚拟机（如 Firecracker）之间按威胁模型选择；两者都要通过相同的出口和隔离测试，不凭名称认定满足 G5、G12。

**独立评分器还需要独立的证据链。**Darwin Gödel Machine 的论文记录了一个候选删除工具日志里的标记、拿到检测满分、却没有解决问题的案例（[DGM 附录 H](https://arxiv.org/abs/2505.22954)）。评测核心补丁时，即使外围闸门挡住了非法动作，也不得据此判定被测核心符合契约，必须记录它的绕过尝试。

### 4.4 双轨评分

**契约轨道**

- 对适用的 G1–G12 分别记录：通过、违反、未测、证据不足；
- 用状态和证据断言，检查实际资源、参数、授权版本和动作身份；
- **必测项违反或证据缺失，阻止发布**，效果不得抵消；
- "本次没有发现违反"只适用于声明覆盖的范围，不是对所有故障的证明。

**效果轨道**

| 项目 | V1 联网问答 | V2 手机 GUI |
| --- | --- | --- |
| 输入与初态 | 问题、条件、检索材料、时间点、授权的个性化初态 | 多个有状态的模拟设备、应用初态、条件和允许的动作 |
| 正式比较 | **固定的检索内容快照**，候选与基线配对比较 | 固定初态和参数，独立初始化 |
| 实际获取验证 | 另设受审计的实时联网测试，记录实际取得的内容和时间 | 声明支持的设备观察接口和能力 |
| 效果指标 | 答案正确性、引用支撑、引用覆盖、时效、个性化效果 | 条件是否满足、实际状态变化、有没有破坏非目标状态 |
| 评分依据 | **原始用户请求**作为独立的评分输入；不只按被测 Agent 自己抽出的条件评分 | 同左 |
| 异常场景 | 检索失败、证据不足、来源冲突、过期信息、恶意内容 | 中断、接管、交还、撤权、设备离线、迟到生效 |
| 证据 | 实际内容引用、断言对应的原文、获取时间；语义争议人工复核 | 动作前观察、动作记录、动作后观察、独立的状态核验 |
| 不能替代的判断 | 答案正确不能掩盖虚假引用或未授权的个性化 | 截图相似、点击成功、固定动作序列都不能代替效果核验 |

V1 的答案正确性和引用质量分开衡量，这是 ALCE 的做法（[ALCE](https://aclanthology.org/2023.emnlp-main.398/)）；自动蕴含判断不是真值，中文需要人工校准。实时联网的成绩必须单列污染审计：Anthropic 在 BrowseComp 上观察到模型找到了公开泄漏的答案，甚至识别出基准后解密答案（[eval awareness](https://www.anthropic.com/engineering/eval-awareness-browsecomp)）。URL 黑名单只能作为辅助。

V2 参照 AndroidWorld，为每个任务提供初始化、状态检查和清理，用系统和应用的实际状态衡量效果（[AndroidWorld](https://arxiv.org/abs/2405.14573)），另加 Lerna 特有的接管、撤权和未知效果测试。核验的是条件和合法动作，不要求每道题只有一种动作路线。

候选与基线使用相同的条件、环境参数和预算上限，独立初始化，运行顺序交叉安排，记录供应商变化和资源异常。

**计数口径**

| 指标 | 口径 |
| --- | --- |
| 分母 | 以冻结计划为准，分别列出成功、失败、未完成、异常和未知；不只分析完成的子集 |
| 单次效果 | 每个预先登记的运行都计入，不挑最好的轨迹 |
| 重复稳定性 | 同题全部预定重复都成功的比例（τ-bench 的 `pass^k`，[论文](https://arxiv.org/abs/2406.12045)）；`pass@k`"至少一次成功"不得冒充稳定性 |
| 有限重试后的成功率 | 一个任务在预先固定的预算、时限和安全重试规则内最终达成；不同评测运行中最好的结果不得代替它 |
| 首次调用正确率 | 分母包括被核心拒绝的错误提议，不只统计准入成功的；本来就要拒绝的安全场景另列 |
| 改善比较 | 主指标和最小有意义的改善事先固定；按任务或来源分组计算配对差异和区间；重复运行不冒充新增的独立任务 |
| 时间 | 端到端、执行、核对时间分开报告；迟到的达成不补计为按期成功 |
| 费用 | 候选运行、评分、环境费用分开列；失败、取消、重试和迟到的账单都保留 |

逐项评分、完整分母和报告保存后才算完成（**持久化点 E6**）。报告可以基于原证据修正评分错误，但必须保留原报告和原因，并对基线和候选用同一方法重评。模型评分也按预定次数运行，不得评到通过为止。AgentDojo 的研究提醒，模型评分器本身也会受到注入（[AgentDojo](https://arxiv.org/abs/2406.13352)），所以契约评分依赖确定性检查，模型评分只辅助判断语义效果。

### 4.5 受控发布、监测与回滚

| 阶段 | 处理 | 持久化点 |
| --- | --- | --- |
| 资格检查 | 必测契约项、效果改善、回归、污染、覆盖和证据完整性 | E7 报告的资格结论 |
| 提交发布 | 保存交接标识、候选、报告、预期稳定版本、策略和授权，提交扩展管理 | E8 意图 → 对方接纳 → 回执 |
| 发布前复查 | 扩展管理核对当前授权、安装声明、兼容性和稳定版本；报告不得扩大发布权限 | 扩展管理的发布记录 |
| 逐步启用 | 从影子运行或有限任务范围开始，达到预定样本和观察要求才扩大 | 扩展管理的阶段和版本选择 |
| 监测 | **同期对照加绝对门槛**；监测完整任务、未知效果、费用、撤权行为和数据缺失 | E9 观察窗口报告 |
| 暂停或回滚 | 严重的契约信号立即关闭相关新行动；一般的效果异常或数据缺失按预授权的策略暂停、收缩或回滚 | E10 回滚意图、接纳和回执 |

只看相对差异不够：Google SRE 指出共享依赖可能让对照组和灰度组同时变差（[Canarying Releases](https://sre.google/workbook/canarying-releases/)）。发布工具的"成功"也不得直接当作评测通过：Argo Rollouts 有一条"没有测量但被终止的指标返回成功"的路径（[源码](https://github.com/argoproj/argo-rollouts/blob/49fa1516cf71672b69e265267da4e1d16e1fe114/analysis/analysis.go)）。Lerna 自己定义"测量充分、证据完整、允许发布"，零样本不得通过。

候选的权限上限是**来源授权、当前有效授权、安装声明和本轮限制的交集**。不同的改进对象分别处理：

| 改进对象 | 生效方式 |
| --- | --- |
| 记忆 | 常规的授权更新可以自动生效；声称效果改善时需要评测 |
| Skill、执行策略、Agent 配置 | 评测通过后，由扩展管理逐步启用 |
| 插件和核心代码 | 只生成补丁和报告，维护者确认后发布 |
| 核心保障、评分门槛、正式查询配额、发布控制策略 | **不得**成为自动改进的对象 |

版本至少在任务开始时固定；共享记忆或长期配置可能影响归因时，按用户或隔离的记忆范围固定观察组。不得在每个动作上随机切换候选和基线。

回滚改变后续任务的版本选择。运行中的任务默认不换版本，由核心决定暂停和恢复；原动作、费用、未知效果和负责方都保留。**回滚不重新执行原任务，也不自动撤销外部效果。**旧版本只有在当前授权、内容可用性和依赖兼容性仍满足时才能恢复，不得恢复已删除的记忆或已撤销的权限。

### 4.6 删除与撤回

内容治理通知删除后，立即停止使用相关内容，以及由它派生的候选、报告证据和缓存；依赖它们的发布资格失效，并通知扩展管理停止相应的推进。沿派生关系跟踪各持有方的清理回报；保留的审计元数据必须符合剩余授权，不得以审计为由保留已要求删除的原文（**持久化点 E11**）。

## 5 故障与恢复

| 故障 | 负责方 | 恢复方式 |
| --- | --- | --- |
| 回执丢失 | 持久工作、交接发起方 | 查询原命令或交接，不新建评测、任务或发布请求；查询不可用就等待 |
| 进程崩溃 | 持久工作、本模块；动作由动作账本负责 | 从冻结计划和原运行恢复；环境完整就接续；输入已暴露而初态丢失的，保留为异常 |
| 重复请求 | 持久工作、对象写入方 | 同标识同内容返回原决定；不同内容报冲突；重复的证据不重复计分或计费 |
| 并发冲突 | 本模块、扩展管理 | 配额、候选锁定、报告版本用原子的版本比较；稳定版本变了就拒绝旧的发布依据 |
| 依赖不可用 | 依赖事实的负责方 | 内容、授权、预算、环境或评分无法验证时停止推进；零结果不记为通过 |
| 迟到的结果 | 动作账本、预算、本模块 | 按原动作和计费来源接纳；补充报告不覆盖历史；截止后达成的不计为按期成功；迟到的报告不得复活已回滚的发布 |
| 过期领取者的回报 | 持久工作、动作账本 | 不覆盖新的控制状态；但实际的外部效果证据仍按原动作核对，不得直接丢弃 |
| 取消与执行竞争 | 任务编排、动作账本 | 停止新准入；未发出的封闭；已发出的继续核对；保留取消和费用 |
| 环境故障与候选故障难以区分 | 本模块、环境控制 | 按预定规则和独立的宿主证据归因；不能证明是基础设施故障的，标为"不充分"，不选择性删除失败 |
| 评分器错误或被篡改 | 本模块、维护者 | 停止报告资格；修正后对原证据同等重评，保留旧版本；不重新采样 |
| 撤权或删除 | 授权、内容治理；本模块响应 | 立即停止新使用，派生资格失效；核对也缺少当前授权时保持未知 |
| 监测数据中断 | 本模块、扩展管理 | 暂停扩大范围；按预授权的时限收缩或回滚；"没有异常数据"不等于正常 |
| 回滚回执丢失或旧版本不可用 | 扩展管理；本模块查询 | 查询原回滚；旧版本不满足当前约束就保持停止，不恢复已失效的权限或数据 |

## 6 不变量落实

| 不变量 | 本模块怎样保证 | 怎样验证 |
| --- | --- | --- |
| G1 | 使用动作账本的效果；未知不触发新运行或有副作用的重试 | 请求已执行但回执丢失；核对不可用时保持未知 |
| G2 | 独立检查条件证据和动作收尾；报告不代替核心的 Result | 末态正确但有未确认的动作时，任务不得成功 |
| G3 | 计划、责任、报告和发布意图持久化后才确认 | 在 E1–E11 前后崩溃 |
| G4 | 生成、测试、模型评分都经过准入，关联条件、授权和预算 | 旧条件、过期授权、无预算的请求被拒绝 |
| G5 | 候选、工具、评分和辅助调用的出口都受约束 | 直接联网、读文件、访问设备和辅助模型的旁路测试 |
| G6 | 候选的完成声明和评分建议都不写核心事实 | 伪造的"通过""已完成"改变不了核心状态 |
| G7 | 候选权限取交集；报告不签发授权；扩展管理独立复查 | 增权的候选、"得分高了所以增权"的发布都被拒绝 |
| G8 | 运行记录的读取、生成、评分、保存和同步分别检查操作权利和处理目的 | 允许读取但不允许保存、生成或同步的内容 |
| G9 | 评测内容和候选登记派生关系，停止使用和清理可追踪 | 删除覆盖题目、缓存、候选、报告和回滚路径 |
| G10 | 实际计费来源由预算去重；模拟费用和真实费用分开 | 重复回报、重复调用、迟到账单、取消后的费用 |
| G11 | 原任务、运行和动作的身份固定；领取者替换不改变负责方 | 超时、重启、回滚后没有新建任务来规避未知 |
| G12 | 用户级的数据、权限、费用、运行空间和资源额度隔离 | 跨用户读取、共享缓存、单用户资源压力 |

这些保证依赖相邻核心模块的公开契约；本模块使用和验证它们，不重复实现核心裁决。

## 7 取舍

| 选择 | 得到 | 付出 |
| --- | --- | --- |
| 固定正式计划和完整分母 | 失败不能通过追加尝试或选择性报告消失 | 基础设施故障可能让整轮评测无法得出结论 |
| 开发反馈与正式反馈分开 | 降低过拟合和泄漏 | 调试反馈变慢，需要维护多套材料 |
| 独立评分和独立证据采集 | 抵抗候选篡改日志和评分器 | 运行、采集和存储成本更高 |
| 契约一票否决 | 保持目标的优先顺序 | 有些效果更好的候选不能发布 |
| V1 固定快照加实时专项验收 | 比较可复现，联网能力也测到了 | 两类结果需要分别解释 |
| 按任务或用户固定版本 | 恢复和归因清楚 | 灰度观察可能跨越长任务周期 |
| 回滚只调整版本选择 | 不重复动作，不伪造补偿 | 已发生和未知的效果仍需单独收尾 |

被否决：单一加权总分（高效果会抵消契约失败，违反 C8）；只用公开集并保存历史最高分（污染和选择偏差）；在线直接覆盖当前策略（绕过隔离评测和逐步启用）；无界的自我修改（成本不可控，无法保持预算、来源和发布门槛）；靠提示禁止或路径黑名单防泄漏（约束不了文件访问、镜像和缓存）。

正式查询和反馈的限制、证据采集的信任划分、版本固定和回滚语义难以撤回，正式采纳前必须写成 ADR。

## 8 待定事项

| 事项 | 验证方法 | 不成立时 |
| --- | --- | --- |
| 开发集的改善能否迁移到真实个人任务 | 按来源、时间、任务组合和设备变体留出，保持相同预算 | 收窄声明，不自动扩大发布范围 |
| 中文语义评分能否支持 V1 | 独立人工标注集，测错误率和争议类型 | 增加人工复核，自动评分不单独决定资格 |

## 9 M1 范围

**M1 不实现评测平台服务，评测与进化推迟到 M5。**M1 只在一致性测试中验证可恢复主线：使用可注入故障的幂等、可查询、不可查询三种模拟 API，记录实现版本、用例身份、故障点和核心轨迹；事务边界和 R7 交接不得省略。M1 必须保留来源和派生关系、稳定的核心标识和基础运行记录，否则以后无法解释旧轨迹。

| 里程碑 | 本模块的内容 |
| --- | --- |
| M2 | V1 参考验收；用途、删除、费用和记忆行为测试（仍可由测试套件运行） |
| M3 | V2 有状态模拟设备、端云断网和接管测试；真机支持另行声明 |
| M4 | 一致性测试用于第二种可替换实现和扩展，验证兼容和权限限制 |
| M5 | 本文的冻结计划、基线比较、隔离评测、受控的候选流程、发布交接和回滚；S8 包含真实的回滚演练 |
| M6 | 多用户隔离、并发正式评测、资源故障域、容量和成本 |

## 10 测试要点

| 用例 | 必须成立 | 对应 |
| --- | --- | --- |
| 对方持久接纳后丢弃回执 | 查询原请求，没有新增动作或任务 | G1、G3、G11、R7（M1） |
| 在每个持久化点前后退出进程 | 每项责任有记录，恢复不依赖内存队列 | G3、G11（M1、M5） |
| 不可查询的动作超时，模拟目标实际已执行 | 保持未知，不重发，任务不标成功 | G1、G2（M1） |
| 模型、摘要、工具、文件和网络尝试旁路 | 无凭据被拒绝，已发出的调用可追溯、已记账 | G4、G5（M1 起） |
| 重复正式请求；同标识换候选 | 只有一个计划、一份配额消耗；换内容报冲突 | C8、G3（M5） |
| 改名、微调提示、换活动名来绕过配额 | 拿不到同一批正式题的新尝试 | C8、C9（M5） |
| 复用路径但换了产物、环境或评分器 | 拒绝使用旧报告 | C8（M5） |
| 模型调用完成后丢弃本地状态 | 原运行保留为异常，不得干净重跑替换 | C8、G10、G11（M5） |
| 禁止评分、丢失证据、取消零测量任务 | 零测量、缺测和未知都不得通过门槛 | C8、G2（M5） |
| 删除日志标记、伪造完成回报、改评分文件 | 外部证据发现问题；缺少证据不通过 | G2、G6、C8（M5） |
| 植入答案诱饵、历史 Git、共享缓存和评分凭据 | 候选不可达；污染被记录并使资格失效 | G5、G8、G12、C8（M5） |
| 正确答案配假引文、过期页面、冲突来源、检索失败 | 各指标分别失败，缺口如实报告 | C2、C3、V1（M2、M5） |
| 点击回报成功但状态没变；延迟点击、接管、撤权 | 完成需要后续观察和核验；不追补未授权的动作 | C4、C7、V2（M3、M5） |
| 修复一个错误的评分器 | 保留旧报告；基线和候选同等重评 | C8、C9（M5） |
| 删除用于生成候选的经验，再请求回滚到旧版本 | 派生产物停止使用；回滚不恢复已删内容 | G8、G9、C9（M2、M5） |
| 重复账单、取消后的账单、供应商更正 | 每个实际计费来源只计一次，关闭后费用不消失 | G10（M2、M5） |
| 回滚后收到旧的扩量回执或旧观察 | 版本比较拒绝旧决定，不复活候选 | G3、C9（M5） |
| 候选付款超时后请求回滚 | 不重建任务、不重新付款；原动作继续核对 | G1、G11、C9（M5） |
| 丢失候选组指标；对照组和候选组同时变差 | 不扩大范围；检查绝对门槛，保留未完成的分母 | C8、C9（M5） |
| 用户甲耗尽资源并尝试读取乙的缓存 | 乙的数据、费用和状态不受影响 | G12（M6） |
