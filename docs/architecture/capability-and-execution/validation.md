## 1. 提供方与缺席行为

| 提供方 | 必须提供的交接 | 缺失或失效时的行为 |
| --- | --- | --- |
| 内核／受信应用宿主 | 固定操作、完整来源、任务控制关联、已准入的有限预算与查询／收尾用途；无任务操作由宿主承担同等限制 | 接纳前拒绝依据不全；接纳后阻止新启动并留工作。执行端不自行分配新的目标操作或扩大预算 |
| 授权服务 | Evaluate／BeginUse／ReadUse、当前披露判断、资源规范化器共同版本、控制连续应用及可信时间 | 无当前 allow 不启动；未知消费按原键核对；无离线许可及可信时间不离线执行 |
| 启动组装器／端点宿主 | 配置锁定、持续账本、唯一活动所有者、资源入口与旧实例隔离 | 禁止无证据接替，旧在途保留；默认启动屏障关闭直到核对完成 |
| 扩展管理器／运行器 | 包校验、受信激活命令、驱动依赖及隔离配置、排空与停用交接 | 声明留 staged 或拒绝登记；无受限执行环境不开放相应权限要求的驱动 |
| 消息交付／恢复适配器 | 两处持久交接、原消息去重、按作用域和行为恢复、授权及任务控制切点／连续接续、work lane 收尾容量 | 本地闭环可先实现；跨端缺少必要依据时禁新行动，获准查询与事实可独立处理 |
| 内容服务／来源适配器 | 按[共同交接](../content-and-provenance.md#publication)完成证据字节耐久保存、原操作／来源绑定、引用保留确认及当前读取／披露；按[关闭合同](../content-and-provenance.md#closure)查询本提供端清理进度 | 内容缺失不声称证据充分；不能履行必需证据保留时拒绝该可靠执行模式；本提供端回执不证明外部副本已清理 |
| 工具／设备驱动（本模块） | 声明准确性、资源规范化、受控启动、原调用映射、查询和取消的真实保证 | 不支持项明确声明；未知后无核对能力转待处理，不自动重做 |
| 任务验收策略／评测 | 固定目标条件、可信证据格式与允许生产者、调用与任务效果计分 | 本模块只输出执行事实，不自判整体完成或声明 90%／95% 已达标 |

上表中目录、协调器、执行存储及默认驱动由本方案定义实现要求；其他提供方维持现有职责。设计契约明确不等于提供方已经实现。邻接方案中的“待实现”仍然成立。

## 2. 未知效果的受信处置入口

处置入口由本端受信管理宿主调用执行模块，复用[身份管理入口](../identity-and-authorization/contracts.md#interfaces)的本人认证规则，Agent 和普通 task.input 不能冒充用户批准。以下执行侧逻辑方法只处理原操作核对和设备控制，任务核心没有据此人工完成、追加预算或恢复任务的消息。

所有变更携带固定 command_id、原操作或资源、预期内部修订、明确参数和期限；按用户隔离并持久保存决定、后续责任与回执。同命令重投返回原结果，异内容冲突，提交未知查原回执。管理命令本身不证明外部效果。

操作的 reconciliation_enabled 和处置修订持久保存。StopReconciliation 原子关闭此门禁并撤销尚未开始的核对资格；已发出的核对可按权限接收结果，不能据此再排下一次。工作者及 Execution.Query 唤醒路径都检查门禁，只有新的 RequestReconcile 命令在预期修订下能重新开放。该门禁不阻止被动接收获准迟到事实。

| 方法与允许动作 | 条件与结果 | 不能发生的行为 |
| --- | --- | --- |
| `InspectPending`：分页查看最小状态、原关联、缺口及所需材料 | 本人或明确委派的状态查询权；敏感参数与证据另查披露权 | 不因拥有 ID 展示其他用户对象 |
| `RequestReconcile`：重开原操作一次有界核对 | 新命令绑定核对范围、已有有效核对许可、可用的原收尾额度及预期修订；原子保存工作和回执，无额度则拒绝 | 不扩大任务预算，不使用原写入许可自动读取目标，不新建目标行动 |
| `SubmitEvidence`：提交原操作关联的外部回执／证据内容引用 | 当前保存与读取权成立；只接受声明列明的证据格式、生产者和可验证关联，保存候选证据及验证工作；验证通过才更新效果事实 | 用户文字“已成功”或手填状态不能直接把 effect 改成 confirmed；无验证器保留缺口 |
| `StopReconciliation`：停止自动查询及提醒 | 保存用户决定和残留责任，继续接收获准迟到事实 | 不标记未执行，不释放未知费用或仍可能被占用的设备，不删除幂等依据 |
| `ReopenAutomation`：重新开放指定设备的未来自动操作 | 新的明确用户意图、当前管理／行动及观察读取权限、预期接管修订、旧在途已结束或隔离、重新观察；原子更新屏障及回执 | 不恢复已取消／终结／过期的操作，不清除尚未解决的外部效果 |

补证无法验证时，入口返回具体缺少的生产者、原调用关联或权限；额度耗尽时用户可停止核对。追加额度需另行定义预算接口，当前不能据此继续消耗。跨端处置 UI 的协议映射尚未定义，本端管理入口可以实现上述行为。

### 覆盖与效果的计分口径

千项 API 以固定版本测试清单中不同的业务 API 操作为单位，记录提供者、方法／动作、参数模式、授权范围、驱动和环境。相同 API 的别名、重复包装、版本复制不重复计数。每项至少有有效调用、坏参数、权限不足三类用例；其声明的查询、幂等及取消保证须有适用故障用例。目录录入数量与通过调用验收数量分别报告。

首次调用正确率以冻结的、属于已声明支持范围且前置资源可用的调用样本为分母，首个业务尝试的能力选择、参数、对象、权限和实际结果均满足判据才计正确；不以 Schema 校验通过计成功。有限重试任务成功率使用冻结任务集及固定验收条件，所有必需条件满足才计成功。样本及排除规则在运行前固定，失败、未知、超时和耗尽预算不能事后移出分母；专门的越权／坏参数集另报正确拒绝率。

参考效果 profile 推荐首次尝试加至多两次新的业务尝试，并配置全任务时间／费用上限；只有正常恢复规则允许才可再次尝试，未知副作用不能为了达到 95% 而重做。消息重投、原调用查询和安全原键恢复分别计数，不伪装成新的业务尝试。该次数是待验证的测试选择，不是已发布系统默认值。报告样本量、任务类别、成功比例、置信区间、延迟与成本分布；90%／95% 是目标，当前无实测结果。

V1 还需整体评测答案正确性、引用支撑、时效性及冲突处理；本模块的实际内容获取只提供证据基础。V2 以模拟设备真实状态变化和前后观察判断，覆盖所有规定动作及中断／接管；不能只读执行状态枚举。

## 4. 跨模块待决项

本地目录、执行门禁及效果核对沿当前内部合同实现；以下跨端增强尚未采用，现行线协议的缺口与保守恢复边界继续有效。跨模块依赖和统一状态见[待决索引](../open-decisions.md)。

| 提案 | 问题与推荐的具体改法 | 涉及范围、代价与验证 |
| --- | --- | --- |
| CE-P1：跨端准确目录与执行依据 profile | v1 能调用能力但未定义准确声明分发和完整来源／控制解析。建议先定义目录精确查询／声明内容校验及受信操作关联的领域适配 profile；授权部分合并身份模块[待决 P1](../identity-and-authorization/validation.md#proposals)，复用其连续切点，不给 invoke 临时塞字段 | 决策后同步 endpoint-cloud-protocol 的 extensions、recovery-and-control、相关 Schema／manifest／示例，task-kernel 的能力与来源依赖、身份接口映射及本模块。比较专属 HTTPS 与领域消息并固定默认路径；替代方案是先保持本地接口，代价为跨实现互操作受限。验证丢页、旧声明、失联、恢复竞争及来源缺项 |
| CE-P2：跨端执行事实修订、用量与取消答复恢复 | 现有三维事实无法靠到达顺序化解全部冲突，且没有用量或取消完整答复查询。建议另开明确版本的执行事实／用量和取消结果查询契约，定义生产者修订范围、事实查询切点、用量去重及取消固定结果保留；不复用 stream seq | 决策后同步 execution Schema、注册表、恢复与字段文档、内核事实合并／预算、示例和校验。新版本增加实施与协商成本；当前可沿保守合并、可信账单适配及超窗缺口运行。验证乱序、重复累计、修订丢失、撤权和结果清理 |

推荐先落地本地参考闭环，在独立端点互操作前确定并完成 CE-P1；需要跨端硬预算或更强事实恢复时确定并完成 CE-P2。两项增强的部署范围、默认传输及版本合同仍待决定，不阻止现有本地能力实现。
