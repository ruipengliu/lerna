# 身份、授权与用户控制

状态：已确认。覆盖本地身份管理、统一授权判定、执行位置、凭证使用与扩展信任范围；具体生命周期与机制见关联分册，尚未进行实现或安全验证。

决策过程见 [确定身份、授权与凭证的执行位置](../../.scratch/harness-technical-design/issues/11-authorization.md)。目标约束见 [C7 与默认发布权限](../harness-project-goals.md)，领域用语沿用 [领域词汇](../../CONTEXT.md)。本册落实统一授权，不重开既有自主执行范围。

## 已确认的前提

- 授权表达主体、资源、动作、范围与有效期，支持单次和持续授权；委派只能收缩，不能增加权限。
- 内核管理授权检查，实际数据及动作处理端落实准入。大脑、Skill、插件、内部和外部 Agent 均遵守共同约束。
- 读取、提取、保存、同步、使用和披露分别受控，记忆、目录、模型输入、截图、UI、日志与产物遵守相应数据策略。
- API 为主要执行路径，GUI 为适用兜底；没有 API 权限不能通过 GUI 绕过。资源接管同时约束共享资源的 Harness 执行路径。
- 任务、操作、等待项、资源控制及授权意图分别管理；消息持久化、UI 呈现回报、任务拥有者身份本身不构成执行授权。
- 离线只在可本地核验且仍有效的范围内运行。要求即时核验撤销的动作依赖在线控制；断连时尚未送达的撤销不能被宣称已在远端生效。
- 常规记忆更新可在授权范围内自动生效；Skill、执行策略及 Agent 配置经评测逐步启用；插件与内核代码由维护者确认发布。自进化不能提升权限或降低门槛。
- Go 与单机完整运行是参考条件，不强制依赖独立身份平台、策略集群或云端密钥服务。

## 已确认方向：身份建立与授权责任

将用户或服务主体、实际运行的 Agent/扩展、承载运行的节点分别识别。请求保留受信的原始发起主体、当前代理执行者、节点与委派关系；对端消息中的自报名称不能建立这些身份。转发或委派不能把原请求改写成拥有更大权限的节点自身请求。

参考部署提供本地身份登记与受控节点加入流程，由安装时建立的管理身份登记受信主体、节点及允许代理关系。单机可以完整初始化，多端使用同一身份与协议抽象；接入外部身份平台作为可替换 Adapter，不要求用户依赖某家云账号。

身份可信仅说明对端是谁。能否读取某条记忆、调用某个 API 或签发委派授权，仍由相应资源的授权策略确定。签发权必须明确限定资源范围及允许的委派深度，加入节点不自动获得用户全部权限。

策略修改和授权签发的责任可位于端侧或云侧，按资源范围明确配置；端侧私有资源可由端侧管理，云侧身份管理不天然拥有读取原文或替端侧放宽策略的权力。参考单机先由本地授权模块承担这些职责，不把逻辑责任拆成必需进程。

连接身份认证、授权材料签发及撤销传播是不同职责。正式 gRPC 与 WebSocket 使用受保护的已认证连接；具体认证绑定、材料格式、密钥生命周期与可信时间见生命周期分册，不采用自定义密码算法。

## 已确认方向：统一决策模型与委派收缩

提供可替换的授权判定 Interface，输入主体及委派来源、资源和动作、用途、处理/接收位置、范围、时间与相关策略版本。输出允许、拒绝或需要用户输入，并携带必须执行的限制及可安全展示的依据。无法理解必要限制的处理端不得将其忽略后执行。

参考实现使用 Go 内嵌策略判定及 SQLite 持久化策略与授权记录。角色可以表达管理权限，但实际执行仍按资源、动作、用途、位置和期限约束，不能只凭“用户”或“Agent”角色放行全部操作。后续策略引擎可替换，须维持同一决策与失效契约。

没有适用授权时不允许新动作；用户已有单次或持续授权可直接使用，不为每次 API 调用、记忆更新或模型请求重新弹窗。请求只有在明确允许由用户补充、且存在有权回应主体时进入授权等待；硬性限制返回拒绝，不能通过反复询问绕过。

有效范围由已有授权、委派限制、资源策略及当前已知撤销共同约束。父任务授予子任务的资源、动作、用途、位置、期限和额度只能保持或收缩；接收方不能因为调用了自己的工具就换用更宽的用户权限。能力描述、网页内容、模型输出与 Skill 文本都不是策略修改来源。

策略收紧后阻止相应新工作，并按各模块既定生命周期处置在途动作、上下文及副本。历史已发生事实继续保留适用最小记录，策略变更不回滚外部效果。授权过期或判定暂不可用时不得新起受限动作，但已有有效离线授权及必要受控收尾沿既定规则处理。

## 已确认方向：检查位置与外部凭证

内核在任务接纳、委派、决策准入及调度时检查适用权限；实际处理模块在读取、写入、发送或启动外部动作前再检查。允许结果不是永久通行证，恢复、重连、目录变化和授权更新后仍重新核验。

| 处理位置 | 执行责任 |
| --- | --- |
| 连接入口 | 建立可信对端身份、绑定会话及原始发起关系，拒绝伪造主体；不替代业务准入。 |
| 任务与协作 | 区分追加事实、修改目标、委派、取消及预算/期限调整权限；记录控制操作并维持恢复约束。 |
| 能力目录与执行 | 目录只返回获准可见内容；执行端检查目标资源、参数作用域、当前资格及资源控制，API/GUI 同样适用。 |
| 记忆与内容存储 | 分别检查读取、提取、保存、同步、解引用与删除；按数据生命周期落实投影、失效和清理。 |
| 模型调用及结果出口 | 发给模型前核对实际处理位置与允许披露内容；向 UI、其他节点或外部工具发布时再次按用途和接收方检查。 |
| UI 与控制入口 | 确认回应者身份、等待项、请求范围及版本；呈现成功不能当作同意，普通聊天不能自行授予更大权限。 |
| 观测与自进化 | 记录决策依据和最小必要事实；数据采集、评测使用及发布均沿用授权，不记录密钥或借诊断上传受限内容。 |

第三方 API 凭证与 Harness 内部授权分别管理。大脑、任务上下文、Skill 及通用消息只传受控凭证引用；真正调用外部 API 的受信执行模块在获准时取得必要凭证，绑定目标服务、账号和允许用途。拥有某项凭证不自动拥有使用它进行任意操作的许可。

凭证保留在允许的端侧或云侧位置，按调用需要使用；端侧账号的长期密钥不因任务委派自动交给云侧或外部 Agent。不能在满足限制的情况下完成调用时报告不支持或授权不足，不静默扩大第三方权限。凭证保存、解锁、轮换与失效由可替换凭证管理接口承担，参考存储与启动方式见生命周期分册。

## 已确认方向：扩展的信任范围与用户控制

进程内 Go 扩展只适用于明确受信的代码。统一接口和权限判定约束正常调用路径，不把它们当作可阻止同进程任意代码读取内存或绕过接口的隔离机制。需处理不同信任级别的扩展时使用独立执行环境及受控入口，后续扩展分册声明实际隔离能力。

外部 Agent 及不受信扩展只取得受限任务输入和能力入口，不能直接读取宿主数据库或通用凭证库。仅换成独立进程而仍共享全部系统权限，不计作已提供强隔离；是否提供文件、网络及进程级隔离应按实现声明和独立验证，不影响单机受信参考部署完整运行。

授权授予/撤销、预算及期限调整、资源接管/恢复分别作为显式管理意图，经稳定操作身份、适用版本及有权主体校验后持久化。自然语言可生成待确认的具体请求；已有授权允许的自动调整可按其规则直接执行，不能把任意模型生成文本当作授权。

用户确认绑定明确的主体、资源、动作、范围、期限及对应等待项或控制请求。请求改变后旧确认不能移用于扩大后的范围；跨端重复提交返回原接纳结果。控制已受理、已送达及已落实分别表达，保留既有任务取消、未知效果核对和资源接管的规则。

## 生命周期与验证分工

[授权生命周期、凭证与控制接口](08-authorization-lifecycle-and-interfaces.md) 已确认节点与浏览器认证、ES256 签名授权、委派/撤销、离线时间边界、本地 AES-GCM 凭证存储及管理操作。

机制依据见 [认证、签名与时间研究](../research/harness-identity-credentials-and-offline-time.md)。实现阶段锁定具体依赖版本并执行互操作及故障测试；研究和方案定稿不表示这些测试已通过。扩展分册落实实际隔离方式，评测分册固定测试配置与指标，部署配置提供有限期限和密钥来源。

验证至少覆盖伪造主体、越权转发与委派、范围收缩、失联撤销、过期和时钟异常、凭证误用、上下文及结果出口、重复确认与版本冲突、重启恢复，以及模型/扩展不能通过改变文本获得更大权限。验证实际阻止行为与保留状态，不以单纯记录审计日志证明授权已落实。
