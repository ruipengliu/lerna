- 状态：草稿
- 负责满足：C2；记忆侧落实 G3、G5、G7–G9、G12；A2、A3
- 协同：C3、C7–C9；G1、G2、G4、G10、G11
- 涉及场景：S1、S4、S6、S8；为 S2、S5、S7 提供获准的事实和经验
- 上游：[项目目标](../../project-goals.md)、[分层与模块](../../layers.md)、[核心契约](../../core/contracts/README.md)、[内容治理](../../core/content/README.md)、[授权](../../core/grants/README.md)
- 默认实现：[default.md](default.md)

记忆策略负责从内容中**提炼**可以跨任务使用的信息，并在需要时把它们**找出来**。它可以替换：提取方法、合并规则、索引结构、检索和个性化算法，都可以随研究进步而更换。

但它**不是**另一套授权、内容治理或任务事实系统。来源、用途、驻留位置、能否发布、删除是否完成，始终由核心裁决：记忆条目本身是内容治理登记的**派生内容**，其来源和治理状态只能由内容治理写入。

本接口的核心约定：

- 记忆以**结构化条目 + 证据引用**表达，区分事实、偏好、推断和任务经验，并带**双时态**（现实中何时适用、系统何时记录）；
- 检索**之前**先由核心限定获准的内容集合，交付和使用时再复核；
- 记忆的任何持久产物（条目、摘要、嵌入、索引、图、缓存）都必须**先登记、后写入**；
- 删除时先禁止使用，再按登记的清单清理、验证、回报；共享的摘要整体失效，从剩余的获准来源重建。

## 1 职责与边界

| 模块 | 持有或产生什么 | 分工 |
| --- | --- | --- |
| 记忆策略 | 类型判断、提取候选、等价和冲突建议、索引组织、排序和个性化建议 | 可以替换；不裁决授权、删除完成、任务效果或预算 |
| 内容治理 | 来源、版本、用途限制、保留期限、派生关系、持有方、清理进度 | 记忆的正文和版本作为派生内容登记；治理状态只有这里能写 |
| 授权 | 保存、读取、处理、同步和行动的许可；当前撤销状态 | 策略不能根据"曾经读过""曾经保存过"推定许可 |
| 持久工作 | 命令回执、待办工作、领取与接替 | 策略宿主使用核心的持久工作，不用内存队列接下责任 |
| 任务编排、动作账本、预算、出口闸门 | 准入、实际调用、效果、用量和出口检查 | 提取模型、嵌入、远端索引、重排调用都受它们控制 |
| 推理 | 根据获准的记忆产生提议 | 通过 R4 只读查询；记忆写入、条件变更和行动仍经过核心 |
| 评测与进化 | 基线比较、隔离评测、发布依据 | 常规记忆更新可以按 C9 自动生效；声称效果改善必须有评测证据 |

依赖规则的含义：策略只使用核心契约，不调用核心内部实现，也不直接调用其他可替换部分；R4 允许的直接查询只能读取获准材料，**不隐含保存、续期、同步或新的供应商调用**；派生存储只能使用已登记的存储位置和受限的能力，扩展不能私建未登记的副本；工作接替只换工作者，不换逻辑负责方。

**语义来源和治理来源分开记录。**策略可以指出哪些材料"支持"某条记忆；核心还要保守地登记生成该产物时**实际处理过的全部输入**，包括用来比较、合并和重排的材料。策略不能通过少报引用来缩小治理关系。

## 2 对象与状态

### 2.1 四类记忆

| 类型 | 需要保留的依据 | 使用规则 |
| --- | --- | --- |
| 事实 | 用户陈述或获准的来源内容、版本、证据片段和时间 | 作为有来源的事实表达；用户自述不自动等于独立核实 |
| 偏好 | 明示还是推断、适用条件、强弱、有效范围 | 默认影响排序或表达；**不能自动成为必要条件或授权** |
| 推断 | 输入依据、推断方法、版本、不确定性 | 明示为推断；不会因为被反复召回就升级为事实 |
| 任务经验 | 条件版本、环境和能力版本、动作和结果的引用、适用前提 | 已生效、未生效、未知以动作账本为准；不能把模型的"成功"声明当证据 |

同一用户的"出差偏好直飞"和"度假愿意转机"可以同时成立。事实中的否定、单位、条件和归因必须保留。

经验只是带来源的材料，不能获得指令或授权的地位。MemoryGraft 研究过伪装成"成功经验"的污染记录在特定 Agent 中的召回情况（[论文](https://arxiv.org/html/2512.16962v1)）；这个实验不能直接推算 Lerna 的攻击成功率，但说明了为什么经验不能升级为指令。

### 2.2 记忆条目

| 字段 | 含义与约束 | 写入职责 |
| --- | --- | --- |
| `memory_id`、`content_ref` | 稳定的记忆标识；正文对应精确的内容版本 | 核心登记 |
| `kind` | 事实、偏好、推断、任务经验之一 | 策略提出 |
| `subject`、`attribute`、`value`、`qualifiers` | 主体、属性、值，以及单位、否定和条件 | 策略提出，保留证据 |
| `source_refs`、`evidence_spans` | 支持该条目的来源版本和片段定位 | 策略提出；核心验证引用资格 |
| `valid_from`、`valid_to` | 信息在现实中适用的半开区间 | 策略依据证据提出 |
| `time_precision`、`time_status` | 时区、精度；明确、推断还是未知 | **不能用提取时间去填补未知** |
| `recorded_at`、`record_revision` | 系统接纳该版本的时间和顺序 | 内容治理赋值 |
| `scope` | 所属用户、领域、情境和适用条件 | 用户归属由核心固定；情境由策略提出 |
| `confidence` | 依据、等级、可选的校准分数和校准版本 | 没有校准时不声称是概率 |
| `support_refs`、`conflict_refs`、`supersedes_refs` | 支持、冲突、替代关系 | 策略提出，按预期版本发布 |
| `experience_refs` | 条件、动作、效果和 Result 的引用 | 只能引用相应的核心事实 |
| `producer_version` | 策略、模型、提示模板和提取配置的版本 | 宿主绑定并登记 |

**适用范围只回答"什么时候适合参考"，不能代替授权范围。**置信度和检索分数是两回事；未经校准的模型分数不能称为"真实概率"。

### 2.3 派生登记

每个持久的派生物，以及可能被跨调用复用的临时产物，都要登记。字段包括：派生物标识和精确版本；类型（条目、证据摘录、摘要、嵌入、索引条目、图边、分类摘要、上下文快照、检索缓存等）；全部治理输入（合并和重排的输入也算父项）；持有方、端点和可清理的位置；与来源删除状态关联的治理代次；索引版本及已覆盖的来源修订位置；状态（登记待写入、可用、禁止使用、清理中、已清理）；保留、驻留、处理和同步限制。

派生物的限制不能比任何一个父项更宽。多个来源的限制不兼容时，不合并；改用分区的条目，或者拒绝这种派生方式。嵌入也不是匿名数据：已有研究在特定条件下从嵌入中恢复出了大量原文，包括临床文本中的个人信息（[EMNLP 2023](https://arxiv.org/html/2310.06816v1)）。

### 2.4 状态

| 对象 | 状态转换 | 谁决定 |
| --- | --- | --- |
| 语义判断 | 候选 → 适用 / 冲突；适用 → 被新版本替代 | 策略提出判断，受控发布 |
| 派生内容 | 登记待写入 → 可用 → 禁止使用 → 清理中 → 已清理 | 内容治理 |
| 索引投影 | 构建中 → 就绪；任何未清理状态 → 禁止使用 / 清理中 | 核心维护发布资格，策略报告构建进度 |
| 持久工作 | 已接纳 → 执行中 → 完成；或等待依赖、停止推进 | 持久工作与负责方 |
| 清理工作 | 已接纳 → 分项清理 → 验证 → 完成；失败时保留待办 | 内容治理汇总，各持有方回报 |

**"被替代"不等于"被删除"**：获准的历史查询可能读到旧版本；而删除会禁止所有时间视图再次使用该内容。

## 3 接口

记忆策略对外只有三个处理接口和一个检查接口。命令的接纳和回执由受控宿主通过核心的持久工作实现，第三方策略不能自行声明"持久责任已成立"。接口的机器定义属于核心契约。

| 接口 | 输入 | 成功含义 | 主要错误 |
| --- | --- | --- | --- |
| 接纳派生工作 | 命令标识；类别（提取、投影或重建）；精确的来源引用；保存和处理凭据；预期修订；已准入的调用引用 | 持久接纳回执；之后返回候选、产物清单和进度。**接纳不代表发布，完成不代表所有检索能力就绪** | 无保存许可、来源不可用、版本冲突、能力不足 |
| 只读检索 | 查询内容引用；当前的检索凭据；任务和条件版本；用途；时间视图；结果数量上限；已准备的向量或调用引用 | 命中项及来源；适用或冲突的说明；完整、部分或不可用的状态 | 凭据无效、范围不符、**需要准备工作**、索引落后 |
| 接纳清理通知 | 通知标识；删除代次；目标内容和派生物；持有方；仅限于清理的能力凭据 | 持久接纳回执；分项的进度和清理证据；只有清理和验证都结束才回报完成 | 代次过旧、范围不符、仍有待核对的项目 |
| 检查工作或产物 | 原命令或通知标识、产物引用 | 原回执、状态、能力版本、索引覆盖位置、待清理的项目 | 不可见、标识未知；**只读，不重建，不重新调用模型** |

共同约定：

1. **检索凭据**绑定用户、任务、用途、范围、有效期和当前授权版本；客户端的参数只能进一步缩小范围；
2. **只读检索不隐含外部调用许可。**如果需要计算查询嵌入、付费重排或远端索引调用，而又没有对应的准入记录，就返回"需要准备工作"，由核心推进；也可以按请求允许的方式降级为关键词检索；
3. 检索不能延长保留期限、更新画像、写持久缓存或自动同步；
4. "没有命中""只有部分检索能力可用""授权检查不可用"要分别表达，**不能都返回一个空列表**；
5. 对不可见的资源，错误语义不泄露它是否存在；
6. 用户纠正、删除和改变用途都通过核心的入口；记忆策略没有直接修改授权或治理状态的接口。

## 4 关键流程

### 4.1 提取与发布

| 步骤 | 处理 | 持久化点 |
| --- | --- | --- |
| 1 | 核心确定来源版本，分别检查读取、处理和保存的许可 | **P1**：工作意图、来源引用、授权和准入依据 |
| 2 | 记忆策略宿主接纳工作 | **P2**：接纳回执和待办；发送方记录原回执（R7） |
| 3 | 通过核心接口读取获准的来源；模型等调用经过出口闸门 | **P3**：调用尝试、用量来源、实际输入引用登记到相应核心记录 |
| 4 | 产生四类候选；先找同主体、同属性、同范围的旧条目，再用语义检索补充候选 | 需要保存的候选先登记为受限的派生内容 |
| 5 | 提出等价、冲突、有效区间或替代关系；**不直接删除旧条目** | **P4**：候选和拟议的变更清单 |
| 6 | 核心先分配并登记受控的存储位置，再写正文、嵌入和索引 | **P5**：产物登记先于持久写入；未完成的产物不可检索 |
| 7 | 发布前复核保存许可、父项版本、删除代次、预期修订和领取代次 | **P6**：条件发布新的内容版本和可用投影 |
| 8 | 索引就绪后推进覆盖位置，回报工作结果 | **P7**：最终回报；未完成的投影仍由原工作负责 |

并发发布使用预期修订检查：两个工作基于同一个旧版本时，一个成功，另一个重新读取、重新合并，不能静默覆盖。模型输出可能不确定：保存首次被接纳的输出，重放时复用它；确需重新生成时创建新的生成尝试，由核心记录实际用量。

### 4.2 双时态查询

检索提供两个独立的参数：

- **有效时间**：询问信息在什么时候适用；
- **记录视图**：询问系统截至哪个已持久的修订知道什么。

例如，10 月收到一条材料"我从 8 月开始改为偏好高铁"：有效时间从 8 月开始，记录时间是 10 月。它不能被理解成"10 月才改变偏好"。记录视图使用核心的修订顺序，不依赖端点时钟。未知的有效时间保持未知；相对日期的解析要保留依据、时区和精度。历史查询仍然检查**当前的**授权和删除状态。

Graphiti 的事实边区分 `valid_at/invalid_at` 和 `created_at/expired_at`（[edges.py](https://github.com/getzep/graphiti/blob/76053036e3db086f57444a29c53d427b0d635a80/graphiti_core/edges.py#L263)），本设计借鉴了这种双时态区分。

### 4.3 检索与交付

| 步骤 | 处理与检查 |
| --- | --- |
| 1 | 在任何嵌入计算、候选查询或图遍历**之前**检查当前凭据，确定用户、用途、驻留和处理范围 |
| 2 | 内容治理构造"获准且未被禁止使用"的内容集合，再应用有效时间和情境范围 |
| 3 | 在这个集合**内部**执行关键词和语义召回；图模式中的节点、边、路径和摘要也限于该集合 |
| 4 | 融合、去重，限制重复的来源；冲突的事实保留下来，不通过排名消除 |
| 5 | 按相关性、范围匹配、证据质量和类型排序；近期程度不能推翻有效时间，检索分数不能充当置信度 |
| 6 | 交付之前复核授权、内容版本和删除代次；登记实际影响结果的输入引用 |
| 7 | 推理使用结果、构造上下文和模型出口时，再经过使用检查；过时的结果被阻断 |
| 8 | 需要缓存或保存上下文时，另外检查保存许可并登记派生关系；缓存命中不复用旧的授权决定 |

**为什么必须在检索之前限定范围。**检索之后再过滤，未授权的材料可能已经参与了候选生成、重排或图遍历。Elasticsearch 明确区分近邻检索的前过滤和后过滤，后过滤还可能让结果少于目标数量（[kNN query](https://www.elastic.co/docs/reference/query-languages/query-dsl/query-dsl-knn-query)）；PostgreSQL 的行级安全对表的所有者和特权角色存在绕过条件（[行级安全](https://www.postgresql.org/docs/17/ddl-rowsecurity.html)），不能仅凭"开启了过滤"就认定隔离成立。还要注意库对空范围的解释：Graphiti 的检索路径会把空的分区列表转成"不限分区"（[search.py](https://github.com/getzep/graphiti/blob/76053036e3db086f57444a29c53d427b0d635a80/graphiti_core/search/search.py#L68)）。所以空的授权集合必须被拒绝，或返回获准的空结果，不能交给底层库解释为"全部"。后端如果不能在获准集合内完成候选生成和重排，就使用隔离的索引，或在获准子集上做精确检索。

**撤销、删除与交付的先后顺序。**由核心的公开接口在最终交付阶段持有一个短暂的读取屏障（授权和内容版本），校验后完成交付；撤销和删除在屏障之外提交。这正是[内容治理](../../core/content/README.md#3-接口)中的"联合使用检查"。屏障只覆盖短暂的交付，不覆盖整个模型生成过程。已经送入模型的材料无法撤回：核心停止后续使用，阻止它的迟到输出进入新的回答或行动，并继续跟踪相关的派生物。

### 4.4 删除、撤回与清理回报

| 步骤 | 处理 | 持久化点 |
| --- | --- | --- |
| 1 | 内容治理接收删除或撤回命令，提升相关的治理代次 | **D1**：命令、禁止使用状态、清理意图 |
| 2 | 根据派生关系和持有方清单展开目标，包括待写入的位置、旧版本和临时副本 | **D2**：清理范围和每个持有方的待办 |
| 3 | 持有方接纳通知；新的读、写、发布和同步被阻断 | **D3**：原通知的接纳回执 |
| 4 | 清理条目、证据副本、摘要、向量、图、缓存、上下文和含正文的日志 | **D4**：逐项的清理进度和外部请求状态 |
| 5 | 混合了多个来源的摘要**整体失效**；需要时从剩余来源重建新版本 | 新版本重新走登记和发布流程 |
| 6 | 验证对象、索引和缓存不可用，确认旧代次不能再发布或恢复 | **D5**：验证证据和分项回报 |
| 7 | 内容治理汇总所有持有方；离线或无法验证的项目保持待清理 | **D6**：所有目标完成后才保存"清理完成" |

清理凭据只允许清除指定的产物、取得必要的验证信息，不依赖已被撤销的普通保存许可。备份和快照在恢复时不能复活已删除的内容。审计只保留必要的、不含正文的元数据；内容哈希、旧值和提示副本都不能成为隐含的保留出口。

为什么"共享摘要整体失效、从剩余来源重建"，而不是让模型从摘要里删掉那句话：模型删句子无法证明清理完整。memU 1.5.1 在删除条目后让模型修补分类摘要，模型响应解析失败时就跳过更新，存在"条目已删、旧摘要仍在"的路径（[crud.py](https://github.com/NevaMind-AI/memU/blob/357aefc8012705bfde723f141d52f675fe712bed/src/memu/app/crud.py#L651)）；Graphiti 0.28.1 的 `remove_episode` 不会重算幸存实体的摘要，也不会从幸存的边中移除旧来源（[graphiti.py](https://github.com/getzep/graphiti/blob/76053036e3db086f57444a29c53d427b0d635a80/graphiti_core/graphiti.py#L1570)）。

### 4.5 端云分布与替换

| 数据类别 | 默认处理 |
| --- | --- |
| 端侧专有的原始内容和记忆 | 原文、摘要、向量、图和个性化计算都留在获准的端点 |
| 获准同步的记忆 | 按精确版本同步；来源、用途和删除代次一并传递 |
| 个性化排序、命中结果和最终回答 | 都是派生内容；不能因为"没有原文"就默认允许上云 |
| 云端运行记录和评测材料 | 不接收端侧专有正文及其敏感派生物 |

可以让云端检索获准的公开候选，再由端侧用私有偏好排序并生成最终回答。所需的端侧能力不可用时，等待或明确说明缺口，不能自动扩大同步权限。每份记忆数据的归属按数据策略固定；不采用"各端多写、自动合并"，因为它难以处理删除、授权变化和 A1 的唯一写入方。

替换策略时，核心的清单、内容归属和删除代次保持连续：新实现声明它的类型、检索、时态、驻留和清理能力；基于仍然获准的来源构建新的投影并登记全部产物；通过兼容性和一致性检查后切换；旧实现的产物仍保留清理责任，旧工作者不能凭过期的领取写回；回滚时也重新检查当前治理状态，不能恢复已删除的旧投影。

## 5 故障与恢复

| 故障 | 负责方 | 恢复方式和禁止事项 |
| --- | --- | --- |
| 回执丢失 | 发送方、持久工作；清理由内容治理协调 | 用原命令或通知标识查询接纳和发布状态；不新建工作绕过原责任 |
| 进程崩溃 | 策略宿主、持久工作；外部调用归动作账本 | 新工作者读取阶段和清单；未发布的产物不可检索；已登记的待写位置可以清理；有过外部调用时先核对 |
| 重复请求 | 持久工作、内容治理 | 重复接纳返回原回执；产物按稳定标识条件写入；不重复增加支持或置信度 |
| 并发冲突 | 内容治理检查版本，策略重新计算 | 预期修订不符就拒绝发布，重新读取当前内容；删除和明确的纠正不能被旧结果覆盖 |
| 依赖不可用 | 对应工作的负责方 | 保存等待状态和缺口；授权无法核实时不使用；检索能力降级要明确说明；清理失败不能回报完成 |
| 迟到的结果 | 核心发布方、内容治理、预算 | 校验领取、来源、条件和删除代次；拒绝过时的发布，清理迟到的产物；实际费用照常结算 |
| 索引写入成功但发布失败 | 原投影工作的负责方 | 查询原产物和发布回执，安全继续或清理；不可见的索引不当作成功结果 |
| 数据库删除成功、外部索引删除失败 | 内容治理、索引持有方 | 保持禁止使用，保存待清理项，核对后重试原删除工作 |
| 删除后重建摘要失败 | 重建工作的负责方 | 旧摘要保持不可用；不会因为模型失败而恢复旧摘要 |
| 端点离线 | 端侧持有方、内容治理 | 云端不宣称该副本已清理；重连后先核对当前授权、代次和工作，再继续 |
| 旧备份恢复或旧缓存命中 | 恢复宿主、内容治理 | 先应用当前的删除记录和授权状态，才允许读取 |

## 6 不变量落实

| 不变量 | 本接口怎样保证 | 怎样验证 |
| --- | --- | --- |
| G1 | 索引、模型或清理超时不被解释为"未发生"；交给动作账本按目标的能力核对 | 注入"发出后断线"，验证原尝试、未知状态和核对记录 |
| G2 | 记忆和经验不裁决任务完成；清理完成需要分项证据 | 伪造成功经验、清理布尔值，核心仍拒绝没有证据的完成 |
| G3 | 工作接纳、产物登记、发布和清理回报都先持久化 | 在各持久化点之后丢回执或崩溃，恢复后责任仍在 |
| G4、G5 | 新增的外部调用绑定当前条件、授权和预算依据；提取、嵌入、重排、远端索引、同步和清理都没有直连供应商的旁路 | 截获全部网络、模型和文件出口，核对准入和用量 |
| G6 | 记忆只提供材料和判断；必要条件、行动和完成都回到核心 | 恶意的记忆要求行动时，无法直接执行 |
| G7 | 派生物的用途和扩展的能力不超过父项和安装声明 | 合并不同范围的内容、扩展申请更宽的能力时被拒绝 |
| G8 | 读取、保存、处理、同步分别检查；每次使用复核当前状态 | 在候选、重排、交付和模型出口各阶段分别撤销 |
| G9 | 完整登记派生物和持有方；先禁止使用，再清理验证；旧代次不能发布 | 删除旧版本、共享摘要、缓存和离线副本；注入迟到的写回 |
| G10 | 不维护第二套费用事实；每个实际计费来源交给预算去重 | 重复用量回报、调用取消、迟到账单都不漏计、不重计 |
| G11 | 原工作、动作和持有方的标识持续存在；接替不改逻辑归属 | 超时、重启和断网后，仍查询原交接 |
| G12 | 用户归属由核心固定；索引、缓存、队列和存储能力都带用户限制 | 篡改用户、空范围、跨用户缓存、单用户过载 |

## 7 取舍

| 问题 | 选择 | 被否决的方案及理由 |
| --- | --- | --- |
| 记忆怎样表示 | 结构化条目 + 证据引用；文本画像和图都作为登记过的派生内容 | 自由文本的用户画像：难以逐条落实 G8、G9，事实、推断和偏好容易混在一起；以图为主要表示：共享节点、摘要和路径大大扩大清理范围 |
| 何时提取和保存 | 获准的来源触发持久工作，产生候选后受控发布 | 每轮交互自动提取并立即写入：容易把读取许可扩大成保存许可；用户逐条确认：不是 C9 常规更新的必要前提，交互负担大 |
| 合并与冲突 | 版本化条目 + 有效区间 + 显式冲突关系 | 最新写入覆盖：隐藏来源冲突，迟到的结果会覆盖纠正；由模型直接合并和删除旧条目：把判断变成了治理裁决 |
| 授权与缓存 | 检索前限定获准集合，交付和使用时复核 | 用户分区加静态凭据：无法证明当前用途许可；检索后过滤：未授权材料已参与候选和重排 |
| 删除 | 先阻断使用，再按清单清理、验证、回报 | 交给记忆库自行删除：没有统一清单和回执；只做逻辑失效、靠 TTL 清扫：无法证明全链清理 |

为什么不直接把某个记忆库的 CRUD 返回值当作 Lerna 的保证：

| 实现 | 删除的实际行为 |
| --- | --- |
| Mem0 1.0.0 | 单条删除先删向量，再把含旧正文的删除记录追加到历史表，历史查询仍会返回；这条路径不调用图删除（[main.py](https://github.com/mem0ai/mem0/blob/394203d1b5f56385d28690ea27c0d746007ff940/mem0/memory/main.py#L1188)） |
| Letta 0.16.4 | 档案删除默认非严格模式：SQL 删除之后，外部向量索引删除的异常可以只记日志，函数仍返回成功（[passage_manager.py](https://github.com/letta-ai/letta/blob/65dbd7fd89b965c0fd52295dc1dd9bdd01a93fa9/letta/services/passage_manager.py#L767)） |
| LangGraph Store（Postgres 3.1.2） | `refresh_on_read`（读时续期）和 `omit_expired`（过滤已到期未清扫的条目）彼此独立，基础默认分别为真和假：关闭续期不等于到期不可读（[TTL 定义](https://github.com/langchain-ai/langgraph/blob/fde3068970679184b68d3d068a92c83c966a4888/libs/checkpoint/langgraph/store/base/__init__.py#L545)） |

此外有几种常见误用需要避免：用向量相似度判定两条记忆等价（否定、范围和时间差异会被合并）；用重复次数提高置信度（重放、转载和同源摘要会被误当成独立佐证）；用数据库更新时间判断"当前事实"（迟到的历史材料会覆盖当前偏好）；把共享的记忆块直接当作用户规则（推断或外部文本会变成长期指令，绕过 C7、G6–G8）。

记忆作为派生内容的归属、双时态语义、删除完成的口径、跨域使用的顺序，正式采纳时应写成 ADR。

## 8 待定事项

| 事项 | 默认做法或假设 | 验证方式 |
| --- | --- | --- |
| 置信度的标尺 | 默认用等级和依据；没有校准数据时不提供概率 | 用标注集校准，按类型分析错误 |
| 派生的粒度 | 默认条目级，小范围摘要 | 测量删除高扇出来源时的暂停时间和重建成本 |
| 物理存储 | 不选定产品；先验证"内容治理事务存储 + 可重建的检索投影" | 容量、过滤、条件写入和删除测试 |
| 端侧模型能力 | 假设本地提取和嵌入能满足最低的个性化需求 | 测量设备资源、质量和耗时 |
| 第三方持有方的证据 | 默认逐项回报，独立核查可观察的项目 | 明确不可验证的项目和完成口径 |

## 9 M1 范围

**M1 不实现记忆策略。**

| 阶段 | 实现到什么程度 |
| --- | --- |
| M1 | 内容治理记录来源、版本和派生关系；模型输出等实际产生的内容可以追溯。接口能明确返回"不支持记忆能力"，不做一个返回假空结果的实现 |
| M2 | 默认记忆策略：四类信息、来源、时间、范围；最低的个性化用例；用途检查、纠正、删除传播、清理验证 |
| M3 | 端侧专有记忆、受控同步、离线等待和重连清理；验证隐私派生物不上云 |
| M4 | 第二种策略实现、扩展能力限制、沙箱和替换一致性验证 |
| M5 | 完整的个性化和经验改进评测、发布与回滚 |
| M6 | 多用户隔离、容量、删除扇出和故障域验证 |

## 10 测试要点

所有实现使用同一套用例。

| 用例 | 注入或输入 | 必须观察到 | 对应 |
| --- | --- | --- | --- |
| 类型与归因 | 用户自述、外部事实、模型推断、效果未知的经验 | 类型和来源明确；推断不升级，未知不写成成功 | C2、G1、G2 |
| 重复提取 | 同一命令重复、同一来源重放、同源转载 | 没有重复的责任、支持或费用；置信度不因重放增加 | G3、G10 |
| 并发纠正 | 两个工作基于同一个旧版本发布 | 版本冲突可见；旧结果不能覆盖纠正 | C7、R3 |
| 迟到的历史 | 新偏好先入库，旧的有效时间材料后到 | 当前视图正确；历史视图区分有效时间和记录时间 | C2 |
| 未解决的冲突 | 同范围、同时间的互斥信息 | 保留冲突和来源，不通过排名默默消除 | C2、C3 |
| 检索前授权 | 空范围、错误用户、已撤销的凭据、扩大命名空间 | 候选、嵌入和图查询都没有越权读取 | G7、G8、G12 |
| R4 限制 | 只读请求缺少新增模型调用的准入 | 返回"需要准备工作"或声明降级；没有直连供应商的旁路 | G4、G5、R4 |
| 撤销竞争 | 在召回、重排、交付和模型出口分别撤销 | 后续使用被阻断；迟到的结果不进入新回答 | G8 |
| 图路径隔离 | 路径中的某个节点或边未获准 | 无法通过中间信息推出受限的关系 | G8、G12 |
| 多来源删除 | 一条记忆由来源 A、B 支持；分别删除其中一个 | 旧的合并版本不可用；只根据剩余来源重建 | G9 |
| 共享派生删除 | 分类摘要、画像块、图摘要混合了多个来源 | 所有受影响的旧版本停止使用，不能只擦引用 | G9 |
| 分阶段崩溃 | 在 P1–P7、D1–D6 之后逐点崩溃 | 已接下的责任不丢；未发布的产物不可用；恢复时查询原记录 | G3、G11、R7 |
| 部分删除 | 主条目已删，外部索引删除失败 | 状态仍为待清理，不回报完成 | G1、G9 |
| 迟到复活 | 删除完成后，旧的嵌入、摘要或同步结果才返回 | 旧代次的发布被拒绝；新出现的残留进入清理清单 | G9、G11 |
| 索引替换 | 停止索引、字段减少、模型切换 | 旧向量不参与当前召回；覆盖状态准确 | C2、G9 |
| TTL 与缓存 | 停止清扫、读时续期、命中旧权限的缓存 | 到期和撤回规则仍生效；读取不延长最长保留 | G8、G9 |
| 恶意策略 | 漏报来源、伪造引用、跨用户写入、私建副本 | 核心的登记和存储能力拒绝；不仅信任策略的回报 | A2、G5、G7、G12 |
| 端侧隐私 | 检查网络、云端日志、提示、索引和评测材料 | 原文以及受限的摘要、向量、排序结果都没有越界 | C2、A3、G8 |

个性化另设成对的用例：无偏好与有适用偏好（排序或建议按预期改变，事实和引用仍正确）；相反的偏好（应受影响的结果变化，并能解释依据）；当前任务的要求覆盖旧偏好；无关、过时、错误的推断不产生不当的个性化；纠正、撤回或删除后重跑，旧信息不再影响检索、上下文和结果。
