| 日期 | 修订说明 |

- 状态：草稿
- 实现的接口：[记忆策略接口约定](README.md)
- 负责满足：C2；在 M2 首次实现

默认记忆策略是记忆接口的参考实现，M2 首次交付。它采用业界已验证的做法：提取和更新分开、带证据的结构化条目、关键词加语义的混合检索；图检索只有在评测证明收益之后才启用。

## 1 提取与合并

提取分两步：先由模型从获准的来源中提取四类候选，再检索同主体、同属性、同范围的旧条目作为比较对象，由模型提出等价、冲突、有效区间或替代的建议。Mem0 也是把提取和更新分开处理的：模型先提取事实，再检索同范围的旧记忆，由模型选择新增、更新、删除或不操作（[Mem0 1.0.0](https://github.com/mem0ai/mem0/blob/394203d1b5f56385d28690ea27c0d746007ff940/mem0/memory/main.py#L386)）。差别在于：**默认实现的模型只能提出建议，不能直接删除旧条目**；版本条件、来源资格和发布由核心决定。

合并和冲突的规则：

| 情况 | 处理 |
| --- | --- |
| 同一来源、同一版本、同一提取结果的重放 | 不新增支持，不提高置信度 |
| 独立来源表达同一事实 | 保留各自的支持关系；只有范围、时间和治理规则都兼容时才合并 |
| 文本相似，但否定、单位或条件不同 | 不自动合并 |
| 有效区间不相交的不同值 | 作为历史共存 |
| 同范围、有效区间相交的不同值 | 显式标为冲突；检索时返回冲突说明 |
| 用户明确纠正自己的偏好 | 新版本可以替代旧偏好；保留纠正的来源和生效时间 |
| 用户陈述与外部事实冲突 | 保留归因；不因"用户优先"改写外部世界的事实 |
| 模型推断与明确的证据冲突 | 推断降级或停止适用；不删除证据 |
| 合并了两个来源的产物，其中一个被删除 | 旧的合并产物禁止使用；从剩余来源重新生成，重新计算置信度 |

**语义相似度只负责找候选，不负责证明等价或判断真假。**

保存的时机：用户明确要求记住的信息可以走短路径；常规提取遵守持续保存的授权；没有保存授权时，不建立长期记忆或持久缓存。

## 2 检索

| 候选 | 特点 | 结论 |
| --- | --- | --- |
| 关键词检索 | 授权过滤和精确的来源匹配容易实现；同义表达的召回有限 | 作为可声明的降级路径 |
| 语义检索 | 同义召回好；精确值、否定和时态仍需结构字段 | 与关键词合用 |
| **关键词 + 语义混合检索** | 两路使用同一个获准集合；需要融合和去重 | 默认采用 |
| 图 + 混合检索 | 多跳能力有潜力；建设、更新和清理最复杂 | 评测证明增益足以抵消成本后再启用 |

精确的标识、日期、状态和数量优先利用结构字段。融合默认使用排序融合，权重不预先确定，由分层评测决定。

图并不必然改善多跳检索。Mem0 论文在其设置下，多跳问题的模型裁判分数为：基础版 51.15，图版 47.19（[Mem0 论文 表 1](https://arxiv.org/html/2504.19413v1)）。Zep 论文在 LongMemEval 的部分配置中改善了总体结果和延迟，但也有类别出现退步（[Zep 论文](https://arxiv.org/html/2501.13956v1#S4)）。所以评测必须按类别报告，并计入提取、更新和清理的全生命周期成本。LongMemEval 还发现，把记忆进一步压缩成孤立的事实会损害总体表现（[LongMemEval §5.2](https://arxiv.org/html/2410.10813v2)），这支持保留可以回查的证据引用、而不是只存摘要。

## 3 个性化怎样产生效果

偏好默认影响**排序、表达或建议**；它要成为必要条件，必须走条件变更流程，不能由记忆策略自行升级。以 S1 为例，假设两班航班都满足当前的必要条件：

| 输入 | 行为 |
| --- | --- |
| 没有可用的偏好 | 按明确的普通方式排序 |
| 获准的偏好"出差尽量直飞" | 直飞候选获得排序优势，并说明依据 |
| 用户本次明确要求"价格最低，可以转机" | 当前条件覆盖长期的软偏好 |
| 只有推断出的直飞偏好 | 保持较弱的影响，必要时询问；不排除所有转机候选 |
| 偏好已删除或撤回 | 排序和上下文都不再受旧偏好影响 |

这些变化不授权订票，也不改变预算。

**"答案变了"不等于"个性化有收益"。**LaMP 定义了七项个性化任务，不同的检索方式没有通用的赢家，部分零样本的推文改写结果甚至因个性化而下降（[LaMP 表 4](https://aclanthology.org/2024.acl-long.399.pdf)）。最低的评测设计：

| 维度 | 对照与指标 |
| --- | --- |
| 实际效果 | 相同的任务、推理版本、预算和候选信息下，对比无记忆、正确记忆、获准完整证据（上界）；测量任务质量和偏好满足度 |
| 因果影响 | 修改一个适用的偏好，观察应受影响的排序、选项或表达；其他事实保持正确 |
| 当前条件优先 | 当前要求与旧偏好相反时，测量旧偏好的误用率 |
| 适用性 | 加入无关、过时和错误的推断，测量过度个性化和不当排除 |
| 纠正与删除 | 重跑原任务，验证旧版本不再参与检索、上下文和结果 |
| 检索质量 | 类型、来源、时间的标注质量；证据召回率、排序质量、冲突遗漏 |
| 成本 | 提取、检索、更新、重建和清理的全生命周期耗时和费用 |

契约违规单独记录，不能被平均质量的增益抵消。评测数据按用户和时间划分，隔离测试材料，记录环境、实现版本、样本和评分方法（C8）。PersonaMem 用演变的合成人设和带有过时偏好干扰项的选择题来测试（[PersonaMem](https://arxiv.org/html/2504.14225v2)），可以补充过时偏好和情境适配的测试，但不能代替真实的开放任务。

## 4 存储

| 候选 | 前提 | 结论 |
| --- | --- | --- |
| **内容治理的事务存储 + 可重建的检索投影** | 条目、版本、来源和发布记录由核心原子维护；投影不是事实来源 | 默认实现先用这一种 |
| 独立的向量存储 + 核心登记 | 需要稳定的条目标识、条件写入、可查询的删除和持有方清单 | 达到容量或检索能力瓶颈后再考虑 |
| 独立的图存储 + 核心登记 | 关系任务收益明确，边和摘要支持细粒度的来源管理 | 图检索被证明有收益之后 |

端侧可以选嵌入式事务存储，云端可以选关系型事务存储，产品不在本设计中固定。

## 5 待验证假设

| 假设 | 验证方式 |
| --- | --- |
| 图检索在关系和时间任务上有净收益 | 与混合的条目检索比较全生命周期成本 |
| 自动提取的阈值：明示偏好优先，推断保持可见的不确定性 | 比较精度、遗漏、污染和费用 |
| 本地的提取和嵌入能满足端侧最低的个性化需求 | 测量设备资源、质量和耗时 |
