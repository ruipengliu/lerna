默认推理是推理接口的一个参考实现。它的目标不是追求最高的任务质量，而是**在可靠性约束下提供一个足够好、行为可预测、容易验证的基线**；更强的策略可以作为替换实现，通过同一套一致性测试接入。

## 1 求解策略

默认实现采用**短的观察驱动策略，附带有限计划**：

- 每次提议请求至多发出一次直接的模型请求；
- 本地做确定性的解析和校验；
- **不内置**模型驱动的自动修复、评审、降级或工具执行循环；
- 需要观察结果才能决定下一步时，返回一个单步行动，等任务编排带着新的进展再来请求。

| 候选策略 | 特点 | 结论 |
| --- | --- | --- |
| **短观察驱动，附有限计划** | 核心每轮提供真实进展，错误的影响范围小 | 默认采用；往返较多 |
| 先生成完整计划，再按计划执行 | 稳定任务可以省调用；环境变化时需要失效和重新规划 | 作为后续可选策略 |
| 多样本、评审或多模型求解 | 部分任务质量可能更高；每次调用都要准入，恢复和预算更复杂 | 必须实测成本收益后再引入 |

ReAct 交替进行推理、行动和观察，但它并不普遍优于纯推理：在 HotpotQA 上 ReAct 的 EM 为 27.4，CoT 为 29.4；作者记录的失败包括重复同样的思考或行动、无信息的搜索导致难以恢复（[ReAct §3.3](https://arxiv.org/html/2210.03629v3)）。所以循环由核心限制和记录，"继续思考"不算进展。

## 2 模型视图的组装

模型视图按以下层次组织，从上到下优先级降低：

| 层次 | 内容 | 裁剪规则 |
| --- | --- | --- |
| 必须保留 | 当前目标、必要条件及其版本、控制状态、**未知的效果**、未决的确认、当前的缺口 | 超过输入限制就返回错误，**不得通过摘要删掉** |
| 当前依据 | 最近的相关观察、证据引用、动作回报 | 保留来源、时间和效果类别；大段正文可以换成允许补读的引用 |
| 最近交互 | 最近完整的用户输入和工具交互 | 不留下无法解释的半对"调用—回报" |
| 历史视图 | 有来源的摘要、已裁决提议的概览、明确的省略区间 | 可以替换或重建；不得覆盖核心事实 |

长上下文和摘要都不得代替完整的条件、效果和证据记录。Lost in the Middle 的研究在其评测的模型和任务中发现，相关信息位于长上下文中间时表现下降（[论文](https://arxiv.org/abs/2307.03172v3)）；Anthropic 也指出过于激进的压缩可能丢掉后来才变得重要的细节（[上下文工程实践](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)）。这就是"必须保留"一层存在的原因。

M1 只使用**确定性的选择和裁剪**，不做模型摘要。M2 引入模型摘要时，摘要由核心作为独立的辅助工作调度：单独准入，登记全部父内容和用量。推理不得把摘要调用藏在一次提议请求里，也不得直接要求记忆策略写入摘要。完整历史的保留受保存授权和期限限制，不得以"恢复需要"为由无限保存。

供应商提供的会话状态和压缩结果（例如 OpenAI 的压缩输出包含不透明的加密条目，见[压缩文档](https://developers.openai.com/api/docs/guides/compaction)）只能作为**可以丢弃的性能优化**。因为无法逐条检查其中的内容，它依赖的任何内容一旦被删除或撤回，整份状态必须失效。

### 2.1 M1 确定性视图策略

`m1-default-v1` 把固定事实、完整必要正文和结构化输出要求放在必保留层。受信宿主通过内容派生接口取得正文后，按引用的稳定顺序排列补充材料；超过限制时从补充材料的末尾移除整项，记录省略引用。不得截断必要正文、未知效果、未决交接、条件或能力版本。必要层本身超限时，返回 `CONTEXT_TOO_LARGE`，不准入模型动作。

参考编码器同时限制编码后的 UTF-8 字节数与保守 token 预算：每个字节计一个预算单位。这是明确的输入上界，不冒充供应商的实际 token 用量。实际计费仍使用可信出口回报。默认上限为 262144 字节、65536 个预算单位，宿主可以指定更小上限。排序、裁剪和提示版本进入封存描述；实际读取后被省略的材料仍保留派生关系。

模型只返回提议载荷。宿主绑定任务、快照和全部版本；模型输出不得指定这些权威字段。行动可以给出具体 JSON 参数，宿主从真实模型输出派生不可变参数内容，再按能力的固定 Schema 核验。引用前序输出的占位符不属于具体参数。输出未知、非法或不完整后，恢复继续查询原请求；不得自动用相同输入建立新请求来重采样。

提议的结构记录保存任务、快照、版本、能力、条件和证据引用；生成的问题、选项、缺口、条件变更理由、预期证据及结果草稿必须放入由真实输入派生的内容。`BodyContentRef` 绑定完整提议载荷，普通查询只返回结构记录。读取正文必须再次检查内容可用性，并核对正文投影与结构记录一致。内容不可用时不得从提议回报、计划状态或恢复结果中旁路返回正文。

`RunReasoner` 是受信宿主入口。默认推理与脚本化推理都经此入口校验、治理正文和保存回报。存储回执丢失或提交状态不确定时保留原请求和命令身份；这类暂时故障不得固化为模型解析失败。恢复重读原调用结果，完成未完成的派生与回报，不再调用供应商。

生产装配提供 `RunDefaultReasoner`，只构造默认实现并转发既有 `RunModelCallCommand`；模型设置来自该命令，仍由任务编排核验。CLI 的 `run-reasoner --json FILE` 必须原样保留已配置的调用方、命令身份、请求、领取、能力和授权引用，不得把普通用户身份改写为 `host`。它不自动创建请求、领取工作、配置权限或循环调用。运行结果只展示结构回报；`read-proposal --json REF_FILE` 通过内容治理读取完整提议，正文不可读时明确失败。

运行记录的来源必须与原负责方事实在同一事务保存：任务编排记录提议和回报的原请求、快照、规范正文、参数及证据引用；内容治理记录规范正文和问题正文的实际派生来源；会话记录问题发布、回答以及确认的各个版本。主观确认关联原条件版本、描述和证据，消费关联原核验轮次。普通、模型、收尾和授权签发确认共用这个结构来源路径。采集、源回执确认和索引各自独立；正文不可读不影响结构来源交接。不得把提示、参数、问题文字或历史 `Description` 副本写入来源，也不得通过当前状态或临时渲染重造过去的事件。运行记录只说明这些原始引用之间的关系，不授予正文读取权或推导业务终态。

### 2.2 生产有限推进

受信宿主可通过任务编排配置持久 `ReasonerDriver`，再调用 `AdvanceReasonerTask`。默认装配启动仅恢复这些已经显式承接的责任。任务编排真实领取原 PROPOSE、运行默认单步推理、按固定授权映射准入并执行 ACTION，再根据原动作已落定的真实效果建立下一唯一请求。等待和恢复规则见 [ADR 0012](../../../adr/0012-bounded-reasoner-driver.md)。模型设置与能力、grant 和确认都来自宿主配置，推理不得提供或替换这些权威信息。

无配置、缺授权、确认或预算不足时必须明确等待；修复预算或权限后，宿主以新的配置命令显式恢复。新的准入裁决身份绑定这次配置，但原模型位置、封存输入和已存在的准入必须复用。未修复配置的自动恢复重放原拒绝，不偷偷重采样；同请求位置的 UNKNOWN 不产生新采样。每次调用有有限阶段上限，未完成责任下次由同入口恢复。`run-reasoner` 继续支持原单次命令重放。

真实 CANCEL 接纳后，显式推进与启动恢复都按当前取消控制等待，不调用模型、不发出目标请求，也不建立下一请求或替代准入。原模型输入和回报、原动作准入及其封闭责任继续可查。模型已调用的费用与尚未发送目标的未使用预算分别沿原事实处理，不能把取消 ACK 当成原模型未调用或最终任务 Result。

完成提议引用原否定证据时，默认推理如实保存 UNSATISFIED 和缺口，宿主把对应原动作作为候选交给完成门禁独立核验。被拒绝轮次的继续请求只使用原 Verification.ContinuationRequestRef 及其准确 Snapshot；原核验自身的控制代次变化不触发新的替代请求。原负责方读取失败时等待，恢复后继续同一关联请求。可信取消关闭产生固定 Result 后，有限推进结束，保留原模型与动作事实及费用，不重新采样或发送。

下一快照保留所有原模型动作的结构引用、状态、原参数引用和效果证据，原模型输入可按原调用独立读取。已有模型提示正文不再次成为下一模型的必保留输入，避免逐轮递归嵌入旧上下文；目标动作参数、必要条件和真实效果证据仍按原引用读取。此选择不产生摘要调用，不删除历史材料，也不把未读取的旧正文登记为本次实际读取来源。

实际文件动作复用受管理文件适配器及宿主固定根配置。`TARGET_RECORD` 验收必须绑定原能力与原参数内容引用；模型生成的新参数即使正文相同，也不得冒充预先接纳的参数引用。联合验收通过生产 `configure-reasoner`、`advance-task` 和启动恢复驱动，按实际快照中的文件效果与证据选择 COMPLETE，并独立检查文件指针、对象正文及重启后的稳定性。模型的两笔费用与文件的非计费来源分别核验。受管理根在获准的 P5 使用边界核验；P5 已保存后发现根映射缺失的发送仍保持未知。补上宿主映射不提供原发送未发生的证据，推进责任不得因此重新发送或重采样。

## 3 能力的渐进暴露

千级规模的 API 不建议一次全量放进上下文。Anthropic 的工程报告指出，全量加载工具定义会增加上下文消耗，并导致选错工具和参数错误，名称相近的工具尤其明显（[Advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)）；其中的评测数字是厂商自己的，不得直接作为 Lerna 的预期指标。

默认实现的做法：

1. 核心先按用户隔离、环境可用性、版本和可发现范围，固定能力目录；
2. 模型最初得到**目录概览**和少量候选能力的完整参数约定；
3. 需要更多详情时，推理返回"上下文不足"和候选引用，由核心在**同一目录版本**中补充材料，然后发起新的请求；**不在内部偷偷续跑模型循环**；
4. 目录版本变化后，旧的候选必须重新验证；
5. 模型只能提议已经拿到参数约定的能力；未知的标识和过期的 Schema 被拒绝。

目录概览必须保留发现遗漏能力的途径，不得把候选集合当成全部可用的能力。发现能力不等于获得行动授权；工具对自己的描述（例如"只读""幂等"）也不得自动获得核心的信任（[MCP 工具规范](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)）。

## 4 状态

默认实现可以保留进程内的缓存（例如已构造的模型视图、候选能力详情），但它们全部可以丢弃：缓存命中时仍检查当前授权和内容的有效性；进程重启后从核心记录重建。不要求重建后的输出和原来相同，只要求权威事实和行为约束相同。

## 5 待验证假设

| 假设 | 验证方法 |
| --- | --- |
| H1：单次调用的默认策略足以支撑 M1 | 与允许有限次额外求解的策略比较任务成功率、首次提议正确率、调用次数和费用 |
| H2：有限计划能减少往返，且不增加失效的行动 | 分别在稳定和动态环境中测试，记录重新规划、未执行的步骤和错误准入 |
| H3：渐进暴露适合千级 API | 用名称相近、跨类别的能力和被漏选的候选，测量发现的召回率和最终的参数正确率 |
| H4：分层的历史视图优于固定的消息窗口 | 在长任务中注入旧条件、未知效果和迟到的证据，比较遗漏、重复行动和完成误判 |
| H5：新的推理实例能从核心快照恢复质量；重新运行时能按相同调用位置和描述拿回已有的模型结果 | 让原会话和全新实例分别接续同一核心状态，比较行为的正确性，不要求措辞相同 |

所有实验按 C8 固定测试集、实现版本、模型标识、提示版本和测量方法；契约符合性和任务质量分别计分。
