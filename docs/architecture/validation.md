# 实施顺序与验收设计

首先实现可接入、可中断、可恢复的研究报告任务，再以第二种组件和真实端云部署验证扩展能力。质量、契约符合性、故障恢复和生产容量分别取证，不能用文档检查或单个场景通过替代其他结论。

本章给出工程切片、反例和开放门槛。研究提出的实验方向见[能力研究](research-learning.md)与[运行研究](research-runtime.md)；本章把它们转为本项目的待执行计划。

## 首条完整场景

用户给出研究问题、比较范围、来源要求、指定保存位置、预算和期限。应用允许用户查看进展、补充要求、暂停、恢复、取消和回答澄清。系统取得实际来源，形成报告，保存并读回核验，最后返回正式结果及仍存在的限制。

场景必须同时覆盖正常路径与至少三种中断：模型结果返回前退出、写入发生后丢回执、用户改变目标时旧提案返回。缺少来源、读回不符或效果仍未知时不得成功。模拟目标用于故障实验，真实应用接入用于验证使用成本，两者分开记录。

## 工程切片与退出条件

| 切片 | 可交付内容 | 进入下一阶段的证据 |
| --- | --- | --- |
| A 共同身份与持久工作 | Command、Tx、JobStore、PG 与 SQLite 适配、规则决策引擎、可查询模拟目标 | 去重、提交未知、旧 worker 和新增工作竞争测试通过；不接真实副作用 |
| B 单目标完整路径 | Task、原文与条件、Snapshot、Operation、Grant、预算、确定性核验、Result | 在实际数据库上完成写入与读回；中断恢复不重复效果；错误条件不能完成 |
| C 应用与真实能力 | 应用 SDK、受信输入、模型与搜索适配、报告默认组件、示例 Web 或 CLI | 至少一个内部应用完成接入；真实来源和目标写入得到核验；成本与等待有界 |
| D 分布式与替换 | 独立网关、应用、工作池、执行宿主，异构语言组件，三系统第二实现 | WSS/gRPC 断连与乱序、远程替换、用户隔离通过同一合同套件 |
| E 记忆与委派 | 获准提取、更正、检索、内部与外部委派、有限端侧自主任务 | 当前权限、来源更正、子额度、取消传播和远端未知均可恢复 |
| F 受控改进与生产规模 | 冻结评测、分批发布、回退、跨区演练、容量和专项验收 | 在实际开放范围内取得质量、恢复、成本与负载证据 |

切片表示实现依赖，不表示必须等到 E 才能首次交付。首阶段以 A 至 D 中研究报告所需范围构成最小完整产品。首次生产仍必须满足独立进程、耐久与故障隔离门槛；本机验证不替代生产演练。

## 目标到证据的映射

| 目标 | 核心验证 | 需要的证据 |
| --- | --- | --- |
| G1 持续目标 | 多轮推进、目标修订、等待、当前必要条件完成 | 原输入到 Result 的完整关联；旧提案不能作用新目标 |
| G2 故障恢复 | 重复、乱序、丢回执、进程接替、未知效果 | 实际数据库与目标状态断言；原身份和未结责任不丢失 |
| G3 能力替换 | 三系统第二实现和至少一个异构语言远程实现 | 同一正反例套件通过；无默认实现内部依赖 |
| G4 端云协作 | 失联、重连、委派、设备接管和独立 owner | 控制、额度、效果与源目录可核对；无双重 Task 权威 |
| G5 受控且可核验 | 越权、预算耗尽、恶意材料、错误完成 | 未授权实际效果为零的受测证据；失败与 unknown 全部计入 |
| G6 接入与改进 | 内部应用真实接入、策略配对实验、回退 | 接入过程记录、维护成本、固定条件下的结果与费用比较 |

“受测的未授权效果为零”仅描述指定环境和攻击集，不能宣称系统不存在漏洞。质量改善必须标明适用任务、版本和资源范围。

## 故障与并发反例

| 场景 | 注入方式 | 必须观察到的结果 |
| --- | --- | --- |
| 提交成功但回执丢失 | Command 提交后断连 | 查询原命令返回原决定，只有一个 Task 或 Operation |
| 原键被用于不同输入 | 改参数后重传相同 command_id | 固定冲突，第二份内容不执行 |
| 新工作遇到旧完成 | worker 处理时增加 work_revision | 新责任仍可领取，旧完成不能覆盖 |
| 旧 worker 迟到 | 租约到期接替后让旧进程提交 | 数据库拒绝旧 epoch；外部未知由效果核对处理 |
| 写入已发生但结果未落库 | 目标提交后杀 Executor | 不盲目重复写；沿原身份核对或保持 unknown |
| 取消先于 invoke | 乱序投递两个原命令 | Executor 保留关闭身份，迟到启动被拒绝 |
| 取消后仍有迟到效果 | 发送后暂停网络，再取消 | Task 显示取消与未结效果，迟到事实仍归并 |
| 目标修订与旧 Proposal 竞争 | 同时提交 steer 和旧提案 | 只按锁定目标版本准入，不采纳过期提案 |
| 父目标变化时子任务继续 | 子任务失联时修改父目标 | 旧委派封新资格并持久传播，有限旧窗口可观察，旧结果重新核验 |
| 控制消息乱序 | 先投递高版本暂停，再投递低版本允许 | 低版本拒绝；恢复不复活已关闭 Operation |
| 接纳后执行失败 | invoke 已返回 accepted 后目标报错 | 原接纳回执不变，业务失败单独查询，不误建同义操作 |
| 强制上下文超过模型上限 | 放入超长目标或大量必要条件 | 返回 context_overflow，不静默裁掉约束或发送超限请求 |
| 候选完成时还有在途创建 | 延迟对 Executor 的接纳回执 | 已登记责任阻止成功，不因远端列表为空漏项 |
| 批量行动部分执行失败 | 四项获准行动中拒绝一项外部效果 | 本地准入事实不变，各效果分别记录，重新规划 |
| 旧授权窗口被重复使用 | 重启、回退并重放一次性许可 | 消费身份不复活，当前权限仍核验 |
| 费用晚到或更正 | 先终态后返回更高累计用量 | 只结算增量，未知预留不提前释放 |
| 插件激活竞争 | A、B 同时自检，A 迟到 | 只有匹配目标头的一方就绪，旧回调不覆盖新实例 |
| 普通升级与旧任务下一轮 | 默认版本切换后继续原 Task | 保留的旧 Activation 在有效批准下可服务原 holder；显式停用后等待或迁移 |
| 旧版本回退资格失效 | 撤回旧批准或破坏格式兼容 | 停用并报告缺口，不无条件自动回退 |
| 远端任务 completed 但业务失败 | 返回错误或缺失产物 | 本地条件不通过；远端状态不能完成本地 Task |
| 记忆撤权与分页竞争 | 第一页之后撤回来源 | 后续页拒绝旧视图，不泄露受限结果 |
| 内容发布中断 | 对象字节写入后、元数据发布前退出 | 恢复原发布或清理孤儿，不产生缺失字节的成功引用 |
| 环境 cell 崩溃 | hostcall 已成功，变量提交前杀沙箱 | 不回滚外部效果，不透明重放 cell |

每个反例都需要正向对照：允许的动作仍能完成。不能通过拒绝全部动作获得表面的故障或安全通过。

## 组件合同与互操作

同版合同测试至少覆盖 Schema、状态前提、身份去重、方法成功点、权限范围、取消、查询恢复、用量与内容引用。测试通过组件公开接口运行，避免依赖默认实现的私有表或函数。

决策引擎、Memory、Executor 各提供第二种独立实现；至少一个组件用不同语言通过真实 WSS 或 gRPC 运行。只替换模型名称、包名或同进程函数不算跨实现互操作。

MCP 与 A2A 按所声明版本连接真实协议服务，测试能力不足、取消不终止、句柄过期、业务错误和断连。未支持的保证必须限制能力，而不是适配器伪造成功。

## 能力质量与优化实验

| 候选能力 | 对照组 | 主要指标与停止条件 |
| --- | --- | --- |
| 上下文与长材料 | 全文、词法检索、混合检索、程序化读取 | 来源覆盖、事实错误、累计费用、延迟、材料越权；无净收益不默认开启 |
| 跨任务记忆 | 无记忆、直接提取、带来源和验证的经验 | 过期信息误用、更正生效、实际任务改善、写入与维护成本 |
| 规划与预算 | 固定策略、预算感知、显式预留核验成本 | 有效成果、无效循环、超限、核验完成率 |
| 多 Agent | 单 Agent、并行独立研究加集中核验 | 任务成功、总费用、协调等待、共享资源冲突与错误传播 |
| 开放质量判断 | 模型自评、规则、规则加独立评估 | 错误完成率、错误拒绝率、unknown、不同任务范围的校准 |
| 经验自改进 | 不更新、自动反思、候选验证后发布 | 新旧任务效果、错误经验传播、环境变化与回退 |

所有组使用相同根预算、数据快照和工具条件。多 Agent 的费用包含全部分支与汇总，检索的费用包含索引构建、提取和维护。不能只报告成功样本或最好一次运行。

正式评测固定模型标识、可取得的供应商版本、提示与策略、插件、环境、样本清单、重试上限、期限和费用。供应商不能固定内部模型时明确可重复性限制。调参集与最终验收集分离，结果使用配对样本、重复运行及适当不确定性区间解释。

首轮小样本用于发现流程问题与估算方差，不用于宣称达到最终成功率。正式样本量根据业务容错率和预期区间精度确定，在观察最终结果前冻结。

## 质量目标与人工参与

最终 API 覆盖数量与效果分别验收。首次调用正确率至少 90%，有限重试后的任务成功率至少 95%；必须预先定义什么是一次调用、什么是正确、允许几次尝试及对应任务范围。未知结果留在分母，不得删除未完成样本。

正常澄清与授权可以纳入预设交互；人工提供正确答案、纠错或代做必要步骤的样本单独报告，不计为自主成功，对应样本仍保留在总分母。运行时用户接受成果不能替代必要外部效果核验。

联网问答单独测答案正确性、引用支撑、时效、证据冲突及获取失败。手机 GUI 单独测观察、输入、再观察、效果判断、中断与用户接管，使用多个有状态模拟设备；模拟通过不代表真实手机平台已经支持。

## 性能和生产验收

先测直接回答、读取后回答、冷恢复、保存并读回四类请求，再扩展到长期记忆、并行委派和大量设备连接。逐级增加负载并记录失效点，控制流与普通工作分别观察尾延迟。

生产首次开放必须取得单区故障下已确认账本 RPO=0、控制和查询恢复不超过 60 秒的演练证据。最终千万注册、百万日活、十万在线需要单独容量报告，包括模型吞吐、活跃任务、数据库压力和故障后备用容量。

耗时、费用和重试限额优先采用接入应用的硬要求；暂无要求时，先用有上限试运行测基线，再冻结正式验收门槛。无法确定的价格、时钟、隔离或供应商查询前提列为开放阻塞项，不用文档中的示例代替探针。

## 文档与真实读者验收

文档检查包括本目录链接与锚点、字段和状态名称、接口成功点、图文关系、JSON 示例和 Mermaid 渲染。检查只证明文档资产可使用，不证明业务实现正确。

至少邀请一名应用接入者和一名组件开发者执行读者试验：前者仅凭应用接口接入报告场景，后者仅凭能力合同替换一个组件。记录他们必须追问的规则、首次得到有效结果的步骤、接入代码量与错误恢复困难。评审者据此修改文档和接口，不用任意字数或合规百分比评价清晰度。
