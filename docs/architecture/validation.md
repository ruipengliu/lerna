# 系统验证设计

[整体设计](README.md) · [贯穿实例](design-walkthrough.md) · [待决索引](open-decisions.md)

本页将项目目标映射到跨模块场景、判据与证据；各模块验证页继续定义具体故障用例，评测模块继续定义计划、计分和报告。本页不声明用例已经执行，也不要求在设计阶段完成数据集建设、平台证明或容量实测。

## 1. 验证范围先固定

每份验证计划选择明确的部署与能力范围。跨端合同已经采用，验收必须同时覆盖其正常与异常链；缺少实现或平台证明时只验证入口正确受限，不把拒绝路径通过当作完整能力通过。后置的迁移、直连和在线格式替换不纳入当前通过声明。

| 范围 | 前提与要验证的交接 | 不包含的结论 |
| --- | --- | --- |
| 本地参考闭环 | 同宿主固定权威；核心、策略、执行、授权、内容、UI 与持久交付齐备；按贯穿实例验证 | 不证明独立端点、离线或自动迁移可用 |
| 云任务权威＋端侧领域 | 端侧独立大脑、记忆与执行；WSS 身份引导、准确目录、来源和原调用恢复；私密内容按驻留策略处理 | 端侧断网不成为第二个任务权威；云模型调用不能替代远程 Brain 验证 |
| 端侧任务权威＋云侧领域 | 相同领域合同反向部署；本地新任务与依赖云端的受阻步骤分别检查 | 本地任务权威可达不证明授权、来源或发布权威全部可达 |
| V1 联网问答 | 实际来源获取、答案及引用规则、获取时间；固定内容回放与真实联网分别组织 | 回放通过不证明时效，格式通过不证明答案正确 |
| V2 模拟手机 | 多个独立有状态设备、任务侧观察、判定侧只读真值及本地接管；需要用户看材料的场景验证固定预览及输入绑定 | 不证明真实手机平台支持；渲染成功不证明用户已理解或行动效果成立 |
| 替换与互操作 | 固定被替换模块、接口版本、部署和相应领域合同；相同输入及故障刺激 | 同一实现两进程通信不等于异构实现互操作 |
| 治理与规模 | 按需选择数据清理、受信发布／旧版恢复、容量或备份恢复，明确保证与故障范围 | 停用不等于旧版恢复，空连接数不等于任务处理能力 |

计划字段复用 [EvaluationPlan](observation-and-improvement/contracts.md#plan)：固定实现与配置版本、部署和用户／端点、能力声明、授权与来源条件、初始数据、样本选择规则、判定器、全任务期限、重试与费用上限、故障位置及测量截止。样本与参考答案由执行验证时的受信数据集提供；文档审查检查其选择与冻结规则是否明确。

两种跨端配置分别叠加远程内部 Agent 和外部独立运行时。内部子接纳仍回到原用户核心；外部普通输入分别取本方接纳与外部应用的回执。三系统至少各选择两种独立实现验证适用合同，不要求穷举所有位置排列。每份报告固定离线上限、来源新鲜度、活动批准有效窗口、清理和备份期限；配置缺省不得解释为无限有效。

## 2. 目标、判据与权威用例

表中列出的模块共同提供证据。C1–C9、A1–A4、V1／V2 各自形成结论，组合场景不能替代单项目标验收。能力成熟度仍依[项目目标](../harness-project-goals.md)逐项记录，L2–L4 只能由相应运行证据支持。

| 目标 | 跨模块判据 | 主要用例与规则 |
| --- | --- | --- |
| C1 决策 | 提案引用获准事实；过期提案不派发；未知证据不能完成；固定条件覆盖用户约束 | [核心](task-kernel/recovery-and-validation.md#validation)、[大脑](brain-system/validation.md#tests) |
| C2 记忆 | 获准偏好实际改变适用行为；纠正／禁用后不继续采用旧依据；清理结论限于受管范围 | [记忆](memory-system/validation.md)、[个性化专项](observation-and-improvement/evaluation.md) |
| C3／V1 取证与问答 | 引用对应实际取得内容；正确性、支撑、时效、失败与冲突分别判定，呈现不丢来源 | [V1 计分与专项](observation-and-improvement/evaluation.md#metrics)、[UI-22](application-and-interaction/validation.md) |
| C4／V2 工具与 GUI | 原操作的实际效果可核对；观察→单动作→再观察；接管优先；设备身份不混淆 | [执行](capability-and-execution/validation.md)、[UI-14](application-and-interaction/validation.md)、[独立取证](observation-and-improvement/evaluation.md) |
| C5 运行与协作 | 接纳后责任不丢、未知不重做；暂停、恢复、取消、迟到事实和用量分别恢复；父子预算不重复占用 | [核心](task-kernel/recovery-and-validation.md#validation)、[委派矩阵](agent-coordination/validation.md#tests)、[通信矩阵](endpoint-communication/validation.md#tests) |
| C6 扩展与接口 | 更换实现后同样的输入／错误／权限语义成立；缺必要能力明确拒绝，旧操作不换解释版本 | [协议](endpoint-communication/validation/README.md)、[扩展](extensions-and-runtime/validation.md)、[UI-21](application-and-interaction/validation.md) |
| C7 用户控制 | 主体和实际资源匹配；once 不多次消费；撤权、暂停、取消、接管各按自己的成功边界生效；补证不绕过验证，离线及物理清理残留如实呈现 | [身份矩阵](identity-and-authorization/validation.md)、[交互管理](application-and-interaction/interaction-and-recovery.md#management) |
| C8 观测与评测 | 能从关联标识定位原事实；固定分母、成本及环境可追溯；日志不替代权威效果 | [观测](observation-and-improvement/observation.md)、[评测验证](observation-and-improvement/validation.md) |
| C9 改进 | 隔离比较、受信批准、分批生效与监测分别有依据；停用与恢复旧版本分别判定 | [改进与回退](observation-and-improvement/improvement.md#monitoring)、[扩展验证](extensions-and-runtime/validation.md) |
| A1 职责分工 | 模型不裁决许可／终态，交付不裁决效果，UI 不裁决业务消费 | [贯穿实例](design-walkthrough.md)、各模块事实归属表 |
| A2 独立替换 | 分别替换大脑、记忆或执行，通过同一适用场景；其他模块不修改共同规则 | [模块接口](README.md#3-模块与权威文档)、上述 C1／C2／C4 用例 |
| A3 端云部署 | 本地与两个方向的跨端配置核对固定权威、身份引导、路由、来源及恢复；使用相同领域语义 | [委派部署边界](agent-coordination/delegation.md#placement)、[通信验收](endpoint-communication/validation.md)、[领域合同](endpoint-communication/domain-profiles.md) |
| A4 共同契约 | 静态结构、运行语义和不同实现互操作分别验证；不从一个层次推出另一个层次 | [协议验收分层](endpoint-communication/validation/README.md)、[通信互操作](endpoint-communication/validation.md)、[CO-23](agent-coordination/validation.md#tests) |

## 3. 跨模块故障场景

先审查[贯穿链](design-walkthrough.md)，再在同一原任务上注入下列故障。测试控制器固定输入和故障位置，原领域继续裁决业务；判定器从领域记录和独立环境取得证据，不通过手改业务表制造成功。

| 场景 | 观察的事实与判定依据 | 复用用例 |
| --- | --- | --- |
| 接纳后丢确认，进程重启 | 应用保留原提交；核心原任务、首次工作与回执共同存在；不创建第二个任务 | TK-01／02、UI-02、[EC-13](endpoint-communication/validation.md#tests) |
| 输入已消费，UI 答复丢失并关闭 | UI 固定父子操作可核对；核心消费一次；关闭意图持续生效 | UI-03～06、TK-03 |
| 写入已发生，结果丢失，随后撤权／取消 | 原操作保持未知直到证据核清；新写入关闭；迟到事实不重开取消任务；费用不归零 | 核心恢复场景、执行恢复矩阵、IA-11／12、CO-10 |
| 来源在评估或结果披露前关闭 | 每次使用按当前依据拒绝；结果状态、内容可用与清理回执分别展示 | IA-18、记忆失效用例、OI-13～15、UI-17 |
| 内容发布与清理竞争 | 已接受的有限保留责任可查；不先返回可用引用再遗失唯一字节；强制禁用留下受限事实和缺口 | [内容专题](content-and-provenance.md)、协议内容用例、UI-12 |
| 升级后退化，回退目标格式不兼容 | 新批次停止；已停用与旧版恢复分开；当前许可、原操作和未知责任不回退 | OI-18～20、OI-20a、扩展切换与回退用例 |
| 单用户洪峰及大量历史恢复 | 新接纳有界，控制／收尾获保留容量，其他用户继续推进，旧责任不为腾空间被清除 | 各模块容量用例、IA-19、UI-19、[EC-19](endpoint-communication/validation.md#tests)、OI-23 |
| 首次恢复及恢复中撤权 | 无业务同步状态时仍能用受限资格核对；该资格不能调用工具或批准用户意图。丢页、旧 owner 和过期证明均不能开启行动 | 身份 P1、协议领域用例 |
| 暂停与准备派发／正常完成竞争 | 先提交的决定可解释；已开始单次动作如实结束，后继受阻；暂停先提交则正常完成等待恢复，取消及原期限照常生效 | 内核控制、执行、协作暂停用例 |
| 父恢复但子自行暂停／撤权 | 只解除该祖先暂停原因，不清除子自身屏障；失联外部项仍显示未确认 | 内核控制及协作恢复 |
| 预算变更与迟到账单竞争 | 同一调额不重复增加；不能降低到已承担消费以下；内部份额不双计，终态只增加原收尾额度 | 内核预算、CE-P2、协作用量 |
| 预览后重启、材料删除或请求替换 | 恢复原版本及输入绑定；必需内容不可取则拒绝旧提交；补证接纳不直接改写执行效果 | UI-P2、任务补证、内容治理 |
| 远程内部子接纳／外部输入丢答复 | 内部仅创建一个子任务及一份受限预算；外部沿原请求查询应用，不把本方接纳当外部已消费 | CO-P1、外部输入用例 |
| 成功终态后崩溃并重复触发 | 已启用类别只创建一次独立提取任务；失败／取消终态不自动提取，来源失效时不发送材料 | MS-P3、内核持久交接 |
| 关闭受管来源后设备离线、旧备份恢复 | 关闭传播及最晚合法使用边界可查；失联或备份残留不能报告已物理清除；恢复先补当前关闭事实 | MS-P2／OI-P2、共同来源 |
| 大脑反复要求补上下文，目录出现空页或输入已过期 | 需求绑定原轮、按规范化内容去重并累计限额；可信游标前进可继续有限组装，只有新增可用材料才重新决策；旧结果只收事实 | TK-26／27、BS-33～35 |
| 策略在任务中途升级，外部证据获取失败 | 原任务固定策略及验证器版本；本地扩展不能发副作用，外部核验走可恢复 Operation；缺证不能通过完成裁决 | TK-28、ER-09 |
| 内部子已完成，远程 Peer 随后离线 | 核心直接观察已绑定子任务的权威事实，迟到 Peer 回报按同一来源去重；配置接纳与外部独立运行时边界不变 | TK-29、CO-28～30 |
| 正文已撤权，用户管理删除；翻页期间无关写入 | 最小管理元数据独立授权，按当前修订条件删除；固定有限集合继续扫描，失效条目形成累计缺口，不因无关写入重开查询 | MS-27、MS-34／35 |
| 收尾消息位于正文缺口之后 | 原流不越过 seq；已知关联立即唤醒原领域查询，查询不改旧 ACK、消息或原操作身份 | EC-20／21 |
| 一组来源中部分许可失效，提交后回执丢失 | 同一权威全部检查后原子消费；拒绝不新增消费，成功保持原回执且发送前再核对；未知只查原集合，跨权威不声称原子 | IA-27～29 |
| 一个模型提供方长期不报告物理终结 | 原未知占位保留；固定容量域及用户保留量限制影响范围；不同域有独立资源时才可继续，不以超时或换 profile 释放占位 | BS-36 |
| 批准撤回与远端激活交错 | 逐节点查询原命令及当前批准；已知撤回或依据过期关闭新使用，实际停用与回退独立确认，旧批次不自动扩展 | OI-P1／ER-P1／ER-P2 |

涉及提交的每条链至少分别放置三个故障点：提交前、提交后答复前、跨模块确认后本端记账前。前者不能宣称接纳，后两者必须能沿原身份继续。执行效果由独立观察或原提供方证明，不能仅以请求日志或数据库终态断言外部效果。

## 4. 计分、容量与证据

API 去重数量、首次调用正确率、有限重试成功率、unknown 的分母处理及比较方法，以[评测指标](observation-and-improvement/evaluation.md#metrics)为唯一规则来源。每份计划预先固定样本分类、纳入／排除规则、重试组、全任务预算、主要指标及专项门槛；不能运行后改分母或阈值。1000 API、90%／95% 和服务规模仍是项目目标，无须在文档阶段虚构清单或达标数据。

容量设计先声明假设：任务到达率、每任务调用与消息数、平均及尾部处理时长、内容字节、保留时间、故障积压和用户热度分布。模型调用、事务写入、内容通道、恢复扫描分别测量；在线连接数不能替代这些负载。记录正常、过载、断线集中重连与存储近满下的接纳、控制、恢复延迟和公平性，具体阈值随被验收部署在测试前固定。模块限额和底层选型继续归所属文档。

一次结果至少关联计划／用例版本、实现／配置、部署、输入和原任务／操作／消息、故障切点、前后权威记录、独立效果证据、测量截止、成本及未决责任。敏感正文仍受用途和保留限制。证据索引只关联原记录，不再维护一套可覆盖业务事实的状态机。

文档语义、链接与图示、Schema 静态校验、运行故障验证、替换互操作和容量测试分别报告。文档通过表示前提与判据完整一致；运行未执行如实标记未验证，不将其计为文档质量失败。
