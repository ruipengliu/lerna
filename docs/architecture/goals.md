# 建设目标、功能与范围

[总览](README.md) · [验收设计](validation/README.md)

本项目建设面向个人智能应用的开源 Harness 框架及可运行实现。使用者可以提交自然语言目标，接入自己的数据、工具和设备，让 Agent 在明确授权下持续工作；开发者可以独立替换大脑、记忆、执行系统，并使用共同接口接入插件、Skill 和其他 Agent。

需求编号用于追踪能力，不能代替运行证据。本方案完整保留下列建设目标，默认实现从独立接入、业务入口与工作池的生产分布式装配验收，开发单体复用相同契约以便调试。V1、V2 是两个专项验收的编号，与建设阶段没有对应关系。

## 1. 用户目标与必须交付的功能

| 编号 | 用户需要 | 必须提供的功能与可观察结果 | 主要设计 |
| --- | --- | --- | --- |
| C1 | 把目标推进成结果 | 理解目标及约束，制定和更新计划，选择工具或 Agent，拆分委派，根据反馈重规划；信息不足先补充或澄清，结果不明如实表达 | [大脑](brain/README.md)、[运行时](task-runtime/README.md) |
| C2 | 跨任务复用信息且保有控制权 | 当前任务上下文；事实、偏好、推断、经验的长期记忆；来源、时间、置信度和范围；端侧挖掘、提取、受控跨端访问；个性化实际影响结果；纠正、限制和删除 | [记忆](memory/README.md)、[授权](security/README.md) |
| C3 | 取得可核查的信息 | 可替换搜索及内容获取；取得实际内容并标明来源和获取时间；发现证据不足、冲突和获取失败，不用搜索摘要冒充未读正文 | [执行](execution/README.md)、[大脑](brain/README.md) |
| C4 | 操作工具、设备和外部系统 | API 优先、适用时使用 GUI；声明能力与条件；观察、动作、反馈、后验核对；分别报告是否执行及效果是否确认 | [执行](execution/README.md) |
| C5 | 长时间和跨端任务可靠推进 | 持久任务、调度、超时、有限重试、暂停、取消和恢复；按能力与用户策略路由；Agent 委派、进展、控制和结果；离线继续本地任务，重连核对原操作 | [运行时](task-runtime/README.md)、[协作](collaboration/README.md) |
| C6 | 接入和替换扩展 | 插件安装与兼容性检查；用户 Skill；受管内部 Agent 与独立外部 Agent；共同任务、能力、记忆、端点和 UI 接口；框架无关且可以脱离任务存在的 UI | [扩展](extensions/README.md)、[契约](contracts/README.md)、[交互](interaction/README.md) |
| C7 | 控制权限、数据用途与行动 | 主体、资源、动作、用途、范围、期限；单次与持续授权；委派只收缩；独立约束读取、处理、提取、保存、同步和披露；预授权内自动执行；撤权、取消和设备接管 | [授权](security/README.md) |
| C8 | 解释运行、比较效果与成本 | 跨端关联诊断，版本及测试集固定，质量、耗时和费用计量；契约符合与实际任务成功分别报告 | [评测](evaluation/README.md) |
| C9 | 有证据地改善能力并可撤回 | 从获准经验产生候选；隔离基线比较；发布授权、分批启用、效果监测和回滚；保留候选来源、版本、评测依据 | [改进](evaluation/README.md)、[激活](extensions/README.md) |

插件提供组件或适配器；Skill 提供操作知识与流程，本身不获得执行权限；Agent 持有目标、上下文和决策循环。内外部 Agent 的区别在于谁管理其生命周期，不以是否调用云模型区分。

每个用户可以拥有多个端点、任务和 Agent。不同用户的数据访问、任务推进、额度和并发互相隔离；任何用户的洪峰或未知调用不能无界占用其他用户的资源。

## 2. 必须保持的系统边界

| 编号 | 要求 | 可判断的设计约束 |
| --- | --- | --- |
| A1 | 职责分开 | 记忆管理信息，大脑提出规划与判断，执行提供行动事实；运行时提供生命周期、调度、准入和运行记录。提案、网络确认不裁决外部效果 |
| A2 | 三系统独立替换 | 各有可用默认实现及版本化接口；更换任一系统不改任务、权限和成功语义；不能只替换模型供应商就宣称替换大脑 |
| A3 | 端云位置可变 | 三系统可分别在本机、云或不同端点部署；任务 Home 固定，领域位置不固定；离线仅继续条件齐备的工作 |
| A4 | 共同契约 | 接口明确输入、输出、错误、权限、版本和恢复；一致性测试与异构实现互操作提供证据 |

用户预授权覆盖工具、资源、用途、有效期和额度。范围内自动执行，超范围重新请求；高影响操作按已安装策略要求确认。模型、插件、Skill、Agent 和改进产物不能自行降低这些限制。

“读取到任务上下文”与“保存为长期记忆”是两种用途。重要隐私资料可留在本机；原文、索引、派生记忆和返回结果分别决定存储、处理和同步范围。把资料改写为摘要不自动解除限制。

## 3. 默认产品行为与取舍

| 场景 | 默认承诺 | 用户承担的边界 |
| --- | --- | --- |
| 本地任务、公网中断 | 全部依赖和授权均在本地时，继续决策与行动，也可接纳新本地任务 | 依赖搜索或云模型的步骤等待；不能把缓存当新取得的证据 |
| 云任务失联、用户打开另一端 | 可以查看已同步且仍获准的状态；原 Home 恢复后核对 | 不自动接管同一个任务；可以明确创建另一个目标不同的新任务 |
| 多端都离线 | 各自执行自己的任务，使用本地权限及预分配额度 | 不并发裁决同一个单次许可、共享余额或设备占用；远端撤权存在有效期内的传播延迟 |
| 工具已行动但答复丢失 | 保留原操作，按提供方能力查询或核对 | 无法核对的副作用进入待处理状态；不以重新执行消除不确定性 |
| 开放式研究或写作 | 可以接纳，保留质量评估或用户验收依据 | 评估不是客观真值，也不能证明另一项外部操作成功 |
| 插件接入 | 内置和经维护者审核的代码先形成可运行闭环 | 审核属于信任决定，不等于已验证隔离；任意不可信代码须按平台验收后开放 |

原任务的失败、取消和质量不足可解释、可查询。任务已结束不代表未知外部效果或未结费用已消失，必要收尾仍由原负责方处理。

## 4. 专项与量化目标

| 目标 | 验收范围 | 不能替代的证据 |
| --- | --- | --- |
| 1000 个以上 API | 语义不同的 API 操作、准确声明、输入输出与受控调用；版本别名、不同账号和重复包装不重复计数 | 接口数不证明调用正确 |
| 首次调用正确率 ≥90% | 在冻结任务集上同时判断能力选择、参数、资源、权限和目标适配 | JSON 合法不等于第一次调用正确 |
| 有限重试后任务成功率 ≥95% | 预先限定重试、期限与费用，计入失败、超时和未知效果 | 不能排除难例或无限重试后再计分 |
| 最终服务规模 | 千万注册、百万日活、十万同时在线；另测任务到达率、活跃任务、模型调用、写入和内容负载 | 空闲连接数不证明任务处理规模 |
| V1 联网问答 | 正确性、引用支撑、时效性，检索失败、证据不足和来源冲突；来源必须实际获取，个性化遵守用途规则 | 固定内容回放不证明当前时效 |
| V2 手机 GUI | 多个有状态模拟设备；观察→动作→再观察→验证；点击、滑动、输入、返回、中断与用户接管，覆盖权限及未知效果 | 模拟器通过不证明真实手机平台已受支持 |

质量指标的样本、分母、重试预算和报告口径在[验收设计](validation/README.md#metrics)固定。容量模型及初始假设见[部署](deployment.md#capacity)。这些数值均是建设目标，没有实测达标含义。

## 5. 交付物与证据等级

项目最终交付：架构规范、共同接口协议、可运行内核、大脑／记忆／执行默认实现、扩展 SDK，以及一致性和效果测试。参考 CLI、Web 及模拟设备为验证这些交付物的可运行入口。

| 等级 | 所需证据 |
| --- | --- |
| L1 契约定义 | 职责、输入输出、状态、错误、权限、恢复和能力声明可实现、可审查 |
| L2 参考实现 | 对应实现可运行，用例可重复，报告环境与已知限制 |
| L3 替换与互操作 | 不同实现通过同一契约，并完成适用跨组件、跨节点或 Agent 场景 |
| L4 恢复与治理 | 故障注入、权限变化、用户控制、升级与恢复通过；C9 另需改善证据和旧版恢复 |

每项能力分别报告目标等级、实际证据和缺口。当前方案以完整 L1 设计为交付范围；静态示例校验和图示渲染不使任何模块自动达到 L2。建设顺序是实施计划，不是减少本轮方案覆盖范围。
