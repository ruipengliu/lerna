## 1 职责与边界

`infra/hosting` 协调既有负责方推进原责任。宿主只注入窄命令接口，阶段清单固定在实现内；不接收任意处理函数，不拥有任务、回执、效果或费用事实。各核心模块继续按原身份、权威依据和事务写入自己的事实。

交互适配器只解析 `recover` 并委托 `ManualProgress`。生产装配把同一用户的现有负责方接入该入口。实际出口、源意图／接收方决定／源回执及兼容性资格仍由原模块处理。

## 2 对象与状态

宿主只保存进展接口，不新增持久对象、恢复位置或工作状态。`ManualDependencies` 明确列出必需的会话进展和各可选阶段。会话进展缺失或 typed nil 是配置错误；可选阶段未提供表示该宿主没有此能力，提供 typed nil 则是配置错误。构造检查在运行之前完成。

报告与解释共用一个可选端口；核对与随后动作进展共用另一个可选端口，保留原能力成组出现的范围。完成、取消、非成功关闭及执行／结算后续责任分别注入，不能因为某一能力缺席而猜测其他能力。

## 3 接口

`NewManual(ManualDependencies)` 返回完成配置校验的宿主；`ValidateDependencies()` 供生产装配汇总校验。`ManualProgress(context.Context, Caller)` 返回原负责方的首个错误或全部支持阶段的返回结果，不包装错误、不改变回执。

入口原样传递调用方和 context；不添加启动的 65 秒期限，不把普通调用方替换成 `host-recovery` 或 `host`。没有输入输出协议或权限扩展。

## 4 关键流程

每次手动请求执行以下固定阶段一次；各负责方内部的已有领取、等待和处理行为不变：

1. 会话 `ProcessPending`。
2. 可选内容 `ProcessObservations`。
3. 可选执行管理 `ProcessReports`、`ProcessInterpretations`。
4. 可选授权 `ProcessRevocations`。
5. 可选任务 `ProcessCompletions`、`ProcessCancellations`，分别按其能力是否提供执行。
6. 可选执行管理 `RecoverReconciliations`、`ProcessOperationProgress`。
7. 可选任务 `ProcessTaskClosings`。
8. 可选预算 `ProcessClosures`。
9. 可选执行管理 `ProcessExecutionFollowups`。
10. 可选预算 `ProcessSettlementFollowups`。
11. 可选运行记录 `Recover`。

任一步错误立即返回，后续阶段不执行。每一步的持久化点、固定生产者和业务命令身份由原负责方定义；协调器不合并事务。

打开生产 CLI 的数据库会先执行现有启动恢复，然后才进入手动进展。两种阶段的责任、身份和调用增量必须分别记录。启动仍留在原装配流程：资格检查先于业务恢复，启动期限、自然租约到期等待和独立启用 driver 的 `host` 身份不属于手动入口。手动入口不增加内容登记、原交接扫描、启用 driver 或第二遍动作进展。

## 5 故障与恢复

负责方暂时失败时，入口原样返回错误，原工作保留；再次请求继续使用原意图和决定，不创建替代身份。当前租约、未来 due time 和领取代次由原工作接口判断，手动请求不提前接管。取消沿 caller context 传到原负责方。

崩溃、丢回执、重复交付和迟到事实按负责方既有查询与重放协议恢复。入口不能把 UNKNOWN 改成未发送，不能从封闭推导费用已结清，不能改写固定 Result。其有限阶段清单不新增后台循环或持有等待事务锁。

## 6 不变量落实

| 不变量 | 落实方式 | 验证 |
| --- | --- | --- |
| G3、G11 | 原工作和原回执由负责方继续处理 | 公共回执、Job、动作与后续责任查询 |
| G4 | 原样传递 caller，不增加 host 权限或实际发送入口 | 普通 CLI 身份及独立目标次数 |
| R6、R7 | 窄接口协调，事务和交接继续归原负责方 | 依赖检查和生产 CLI 故障恢复 |

## 7 取舍

固定协调顺序使 CLI 不必了解核心恢复协议；显式可选端口保留能力缺席。通用注册表会引入额外执行权限和顺序配置，因此不提供。启动和手动阶段有既有差异，不能以一个阶段列表或一个受信身份代替。

## 8 待定事项

启动恢复迁入同一宿主模块另行实施，迁移时保留已有资格、顺序、期限和身份。本次不改变启动协议。

## 9 M1 范围

本次提供本地 CLI 固定手动进展和生产装配；不新增远程恢复、持续自动循环、处理注册或存储格式。

## 10 测试要点

通过生产 CLI 与各负责方公共查询验收原回执、观察、报告、解释、撤销、完成、取消、核对与后续责任。分别记录 Open 和 ManualProgress 的结果、身份及独立目标增量。保留未来 due time、当前租约、暂时错误后的原责任和重放；必要配置检查只验证缺失及 typed nil，不复制核心一致性套件。
