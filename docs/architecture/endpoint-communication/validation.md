# 端点通信验证与启用依赖

[模块总览](README.md) · [交付实现](delivery-and-recovery.md) · [协议结构与互操作](validation/README.md)

本页验证端点通信的持久交接、按行为恢复、运行隔离和有界容量。协议结构与独立实现互操作由[协议验收](validation/README.md)组织；任务、委派、UI 及其他领域继续验证自己的业务决定。本页是运行要求，当前没有通信参考实现或故障注入结果。

<a id="dependencies"></a>
## 1. 启用依赖与取证范围

| 提供方 | 必须具备的依据 | 缺席行为 |
| --- | --- | --- |
| 受信宿主、身份与存储 | 用户／端点／owner 绑定、持续账本、原提交核对、旧写入及执行入口隔离 | 不接管无法耐久保存的新责任；不凭换连接或租约超时激活接替 |
| 领域处理与恢复适配器 | 可恢复处理决定、作用域解析、当前轮次的权威切点及连续变化、按行为结论 | 可在获准容量内保管消息，但不伪造业务接纳或开放缺证据的行动 |
| 协议与网络实现 | 固定规范版本、已安装类型及 Schema、可信网关路径、接收限制与来源核验 | 必要语义不兼容或无获准路径时拒绝新发送，不降级可靠等级 |
| 授权、内容与来源 | 接收／保存／传送／披露依据、内容当前状态与完整性 | 正文受限时保留获准最小缺口；消息回执不证明内容完整交付 |
| 有限运行配置 | 每用户／端点／目标总额、活跃流、字节、工作领取及核对预算、收尾保留份额 | 必需限额未配置不开新接纳；不得轮转淘汰已接纳责任 |

每项运行测试固定实现、[整套规范版本](protocol.md#versions)、端点与用户、领域适配器、存储耐久配置、owner、时间依据、消息窗口和配额。保留原消息／操作、提交键、故障位置、重启后的记录及实际动作。模拟领域通过只证明该交付测试，不代替真实领域的授权、效果或隔离证据。

## 2. 持久交接与恢复矩阵

先验证正常本地及双端交接，再分别注入提交前、提交后答复前、跨模块确认后本端记账前三类故障。验收同时观察消息账本、领域回执和真实动作；目标 ACK、业务 accepted 和最终结果单独记录。

| 编号 | 前置条件与刺激／故障 | 必须观察到的结果 | 依据／目标 |
| --- | --- | --- | --- |
| EC-01 | 票据重复消费、伪造 source、跨用户目标、welcome 丢失重连 | 来源与用户隔离成立；重连重新认证，保留原消息与流；票据不落业务队列或日志 | [接入](transport.md#session)／C7、A4 |
| EC-02 | 网关支持而目标不支持类型、必要扩展缺席、作用域伪报或同流改绑、路由切换 | 按最终目标及路径能力判断；非法绑定拒绝；获准切换保留原 source／target／流／操作和用途约束 | [流注册](transport.md#stream-registration)／C6、C7 |
| EC-03 | 出入站或放行事务提交未知、只读副本未见、旧领取持有者迟到 | 沿原提交键查询写权威；未知不换键／换操作；只有旧提交已结束或隔离才认定未应用，旧持有者不能提交新进度 | [提交边界](delivery-and-recovery.md#ledger)／C5、A4 |
| EC-04 | 首连 streams 为空但领域依据缺失；离线许可到期或可信时间失效 | 连接不开放新行动；获准恢复查询仍可推进；离线条件不足停止新使用，原效果继续核对 | [恢复规范](recovery-and-control.md#resume)／C5、C7 |
| EC-05 | 结果只携带引用，内容失效、撤权、摘要不符或提供端失联；大内容传输同时取消 | 记录消息、领域结果与内容取得的不同状态；不报告完整交付，不重做任务取内容；取消仍有保留容量 | [内容交付](message-contract.md#delivery)／C4、C7 |
| EC-06 | 主动查询预算用尽、进程重启、旧事实随后到达 | 次数／期限不重置；留下可查询缺口及获准通知，停止主动消耗，合法迟到事实仍可接收 | [有界工作](delivery-and-recovery.md#scheduling)／C5、C8 |
| EC-13 | Delivery 接管后答复丢失；目标 ACK 前／后崩溃；业务提交后确认丢失 | 原 message_id／seq 稳定，待处理和发送责任存在；领域返回原决定，不重复应用原业务操作 | [两处交接](message-contract.md#handoff)／C5、A4 |
| EC-14 | 同流缺 seq、乱序暂存、伪造 ACK、中继 relay_stored | 不越过连续前缀交接或确认；只有目标证明允许源端提前清理 | [ACK](transport.md#ack)／C5 |
| EC-15 | 超窗、源正文撤权、未处理入站清理、旧备份缺失已 ACK 记录 | 缺口及后续责任先提交；不换流重编号／改文重投；记录丢失不回退游标续跑 | [清理](delivery-and-recovery.md#streams)／C5、C7 |
| EC-16 | 单 scope 缺证据而其他 scope 就绪；快照切点并发取消／撤权，旧轮或旧 owner 答复迟到 | 缺口不堵无关工作；先关闭依赖失效证据的行为；旧答复不放行；任务取消约束传播到关联操作 | [恢复轮次](delivery-and-recovery.md#recovery)／C5、C7 |
| EC-17 | 多连接共用端点、接替时旧实例仍离线行动、丢失账本新安装 | 序号／配额共享；不能凭断线接替；新端点不自动重做旧操作 | [活动所有者](transport.md#endpoint-owner)／C5、A3 |
| EC-19 | 普通 work 满额、大量历史恢复，同时产生取消结果／执行事实；超过 256 条流 | 既有 work lane 内收尾取得保留容量及调度；恢复分批，未列出的流不算就绪；用户总额有限，其他用户可推进 | [调度](delivery-and-recovery.md#scheduling)／C5、C8 |

EC-13～17、EC-19 承接原协作矩阵中的同号通用交付用例，保留编号便于核对既有验证引用。委派接纳／控制及 UI 输入消费的业务结果由各领域矩阵判断；通信只证明原消息和后续交接责任持续存在。一次业务成功不能弥补目标 ACK 或流证据缺失。

涉及有限离线、跨端领域和中继保管的用例，只在其具体提供方、权限及配置具备后执行；缺席时先验入口保持受限。直连、跨主机接替与任务权威迁移仍按[当前范围](README.md#scope)关闭，不用模拟成功扩大实际支持范围。

<a id="capacity"></a>
## 3. 容量与故障下的公平性

测量每用户及端点的活跃流、待确认消息数量／字节、未处理责任、恢复缺口、重连频率和积压年龄。持久空间至少覆盖“到达率 × 保留时间 × 平均记录大小”、未决责任、去重／游标及备份；声明大内容是否另计。这是容量估算方法，不是吞吐证明。

| 负载或资源条件 | 必须观察的指标与行为 |
| --- | --- |
| 新接纳高峰、单用户洪峰、多连接和多流 | 汇总数量／字节限额、接纳拒绝时点、用户调度份额；连接与流增加不能放大用户额度 |
| 目标失联、慢领域处理、磁盘接近满额 | 最老消息／未交接年龄、账本占用、背压与拒绝；已承担责任不能为新工作被淘汰 |
| 批量重连及大量历史流 | 每轮批量与恢复时延、普通工作及其他用户等待；超过批次上限的流继续有界推进 |
| 取消、查询及必要事实收尾积压 | 各 lane 与 work 收尾的队列、工作者和存储份额；普通 work 不挤占保留量，控制恢复也不能无限饿死普通工作 |
| 内容传输与消息并发 | WSS 写缓冲、取消排队、消息与内容吞吐分别测量；TCP 已排队字节不可抢占，不承诺取消零延迟 |
| 清理、备份恢复与预算耗尽 | 先保存缺口再删除载荷、未知提交原键可查、限额不因重启刷新；来源撤权后的正文不再发送 |

报告固定硬件、存储同步方式、网络、用户分布、消息大小、领域处理耗时和故障条件；分别给接管、目标 ACK、业务交接和恢复的延迟及尾部积压。十万同时在线与系统任务吞吐另按[系统验证](../validation.md)取证，空连接数和 Schema 通过均不足以证明。

## 4. 交付检查的证据边界

语义审查、链接／锚点、图示渲染和机器资产校验分别记录；运行验收还须提供上述故障及记录。单一实现测试不能代替[独立实现互操作](validation/README.md#interop)，互操作通过也不能代替容量或物理存储耐久证据。当前重划仅调整职责与文档权威，没有新增线字段或改变已确认业务保证。
