# 协议资产校验与互操作验收

[协议规范](../protocol.md) · [通信运行验收](../validation.md) · [标准注册表](../schemas/standard-registry.json) · [任务／UI 示例](../examples/task-ui-flow.json)

本页组织协议结构、跨领域可观察语义和独立实现互操作的验收。消息账本的事务、隔离、故障恢复和容量由[通信运行验收](../validation.md)定义；领域的业务裁决沿所属矩阵验证。当前交付为设计与校验资产，没有协议运行实现；运行及互操作用例均待实施。

| 证据 | 能回答的问题 | 判定边界 |
| --- | --- | --- |
| 静态契约校验 | Schema、注册声明、固定消息串及非法用例是否满足结构和指定关联？ | 不证明持久事务、授权裁决、并发处理或外部效果 |
| 单实现运行验收 | 在故障、重启和竞争下，记录、后续责任及实际行为是否符合契约？ | 需观察存储与执行，不能只比较网络返回值 |
| 独立实现互操作 | 不同实现能否在正常、重复、恢复及拒绝路径上兑现同一规范语义？ | 单实现通过或 Schema 相同不能代替互操作 |
| 容量与隔离验证 | 在规定负载及故障下，配额、公平性与恢复机会是否成立？ | 功能通过不能代替压测，空连接数不能代替业务吞吐 |

文档链接、图示渲染和语义审查单独记录；它们用于检查方案本身，不计作协议运行通过。设计范围与缺失依赖时的行为见[总览](../README.md#scope)。

## 1. 运行静态校验

在已安装 Python 3.12+、支持 venv 的环境中，从仓库根目录运行：

```bash
python3 -m venv /tmp/harness-protocol-validation
/tmp/harness-protocol-validation/bin/pip install -r docs/architecture/endpoint-communication/validation/requirements.txt
/tmp/harness-protocol-validation/bin/python docs/architecture/endpoint-communication/validation/validate.py
```

[validate.py](validate.py) 只解析本地 Schema，不下载 `$id` 指向的资源。它是协议资产检查器，不提供客户端 SDK 或可靠传输实现。

| 检查对象 | 当前覆盖 | 边界 |
| --- | --- | --- |
| Schema 与引用 | Draft 2020-12 合法性、本地引用可解析 | 不加载远程声明或处理器 |
| 标准注册表与扩展声明 | 类型／版本身份、请求响应配对、交付约束、scope_binding 与声明结构 | 权限名称的结构合法不代表运行时已授权；能力安装与路径协商仍需运行验证 |
| 信封、载荷、附加项与视图 | 对应 Schema、类型规则、必要附加项及降级约束 | 不证明处理器落实授权、隐私或执行语义 |
| [任务／UI 消息串](../examples/task-ui-flow.json) | 响应引用、操作标识、流序号、作用域／lane 绑定、目标回执、UI 修订及输入消费关系 | 关联检查限于固定消息串；其中截图预览包含原投影／输入／内容摘要和受信宿主取得凭据的关联，不证明默认装配可用，也不模拟崩溃或并发 |
| [成果与呈现恢复](../examples/result-and-presentation.json) | 完整输入描述、两端呈现隔离、条件更新答复、旧操作决定复用、正式结果与当前状态分离 | 校验示例中的状态关联；不提供 UI 管理器实现，不证明持久化、并发裁决或实际窗口到期 |
| [任务／大脑／执行跨端链](../examples/core-domain-flow.json) | 准确声明、原生成调用、控制／预算、补证、事实与用量、原取消及设备管理；操作与生产者关联 | 固定证明值只作结构绑定，不代表已签名或当前获准；竞争与停止仍需运行取证 |
| [身份授权跨端链](../examples/identity-domain-flow.json) | 主体许可、收缩委派、消费／撤销状态、恢复快照与应用、有限离线证明 | 固定签名样本和载荷结构不证明真实身份提供方、时间锚或离线防回滚 |
| [记忆／治理跨端链](../examples/memory-governance-domain-flow.json) | 记忆原命令、固定视图、来源／内容及逐持有者清理回执 | 分项回执的静态结构不证明载体已清理，物理清理仍由持有者运行取证 |
| [交互目录跨端链](../examples/interaction-domain-flow.json) | 获准目录、订阅及恢复投影 | 订阅投递、实际字节获取和多设备竞争需运行验证 |
| [委派与发布跨端链](../examples/runtime-domain-flow.json) | 固定权威子接纳与查询、外部输入／授权恢复、批准／逐节点发布及停用回退 | 不证明真实 Agent 或制品适配器能力、隔离与物理停止 |
| [恢复与取消示例](../examples/recovery-and-cancel.json) | 逐条消息的结构与类型约束 | 假定已有持久记录，不验证恢复时序与实际效果 |
| [HTTPS 示例](../examples/http-exchanges.json) | 请求及响应 JSON body 结构 | 不验证 HTTP 方法、状态、头、票据消费或内容字节 |
| 严格原语与[非法用例](invalid-cases.json) | 日历时间、uint64 上限、重复键、非 JSON 数值，以及预期拒绝的结构与语义组合 | 固定时间是测试数据，不按运行当天判定业务有效期 |

样例使用固定虚构 UUID、摘要、证明引用和时间；它们不是可用于真实服务的凭据。金额为最小单位整数，task-control 的分配与 target／cleanup 账本包装复用共享用量，不把父聚合与子明细重复计费。

回归检查允许 `completed + effects_pending=true`：线字段不能判断剩余效果是否影响成果，任务核心仍须取得“不影响目标”的证据。检查还覆盖可靠消息必填 scope、同流混作用域拒绝、自定义视图的完整输入元数据及已拒绝呈现操作不得在重投后改为成功。消息自报的状态、来源和权限仍须由运行实现核实。

## 2. 公共行为与领域交接验收

运行前固定[整套规范及领域引用版本](../protocol.md#versions)、实现、端点与用户、能力及许可、时间依据、窗口和配额。先沿[整体设计推演](../../design-walkthrough.md)验证正常本地交接，再验证跨端行为；示例消息只提供刺激与关联，不能把其虚构证明、摘要或时间当作真实运行依据。

公共交付的故障步骤与存储观察集中在[通信矩阵](../validation.md#runtime)，本页从协议对等方可观察的行为选择验收入口。第三方可使用不同存储和调度器，确认时点与失败后的责任必须等价。

| 规范场景 | 对等方须得到的行为 | 运行取证入口 |
| --- | --- | --- |
| 接收 ACK、接管答复或业务确认丢失 | 原 message_id／流位置不变；返回原交付及业务决定，消息接收不冒充业务接纳 | EC-13、EC-03 |
| 缺 seq、乱序、中继保管或伪造目标 ACK | 不跨过连续前缀交接／确认；只有目标证明允许源端提前清理 | EC-14 |
| 超窗、正文撤权或目标曾确认记录丢失 | 留下可查询缺口；不改正文冒用旧 ID、不重编号续传、不把未知当未执行 | EC-15 |
| 首连无流、旧轮恢复答复、取消或撤权变化有缺口 | 按当前轮次、owner 与领域依据逐行为放行；获准查询和事实收尾继续 | EC-04、EC-16 |
| 双实例、多连接及账本丢失 | 同一有效所有者共享序号和配额；断线不授予接替，新身份不重做旧操作 | EC-17 |
| work 拥塞、超过 256 条流或大内容传输 | 分批恢复且保留查询、取消及既有 work 收尾机会；不承诺远程取消零延迟 | EC-19、EC-05 |

领域验收须同时核对相关业务事实，不能仅观察网络上“成功”字样。规范性行为与实现记录分开：第三方须满足下表语义，未必采用本项目的表或工作者。

| 领域场景 | 必须保持的可观察语义 | 规范与领域验证 |
| --- | --- | --- |
| 执行结果丢失、取消与完成并发、任务已取消后结果迟到 | 核对原操作，不重复动作；保留真实效果与未知项，迟到事实不重开任务；原取消固定答复独立查询 | [恢复与控制](../recovery-and-control.md)、[执行验收](../../capability-and-execution/validation.md)、[内核验收](../../task-kernel/recovery-and-validation.md#validation) |
| UI 已接纳、转交或消费答复丢失，多端回应同一请求 | 原父子关联可恢复；消费由业务权威裁决；同操作返回原决定，不同操作至多一项消费 | [输入规范](../../application-and-interaction/interaction-contract.md#input)、[UI 验收](../../application-and-interaction/validation.md) |
| 只取得 ui.get、文字进度更新或旧快照到达 | 完整输入与视图一次恢复；内容不回退，进度变化不使原有效请求失效 | [快照规范](../../application-and-interaction/interaction-contract.md#view)及 UI 验收 |
| 关闭后后台快照到达、开闭答复迟到、关闭意图已保存后重启 | 本端最新显式选择继续生效；关闭不撤回已接纳输入，一端关闭不关闭另一端 | [呈现规范](../../application-and-interaction/interaction-contract.md#presentation)及 UI 验收 |
| 正式结果消息超窗、原结果已清理或必需内容不可取 | 查询固定原结果；当前状态、取消答复和内容可用分别判断；缺失不以摘要冒充完整结果 | [结果查询](../../task-kernel/storage-and-interfaces.md#result-recovery)、[内容交付](../message-contract.md#delivery) |
| 查看中间产物后回应，期间来源失效、预览被清理或请求被替换 | 依赖原精确预览与受信取得依据；缺必要材料不允许提交，旧输入不重新绑定 | [预览规范](../../application-and-interaction/interaction-contract.md#preview)及 UI 验收 |
| 委派已接管／子任务已接纳但答复丢失、父取消后结果与用量迟到 | 固定原委派及子提交，不产生第二任务；父完成独立裁决，未知预算不因超时释放 | [协作规范](../../agent-coordination/peer-contracts.md#normative)、[协作矩阵](../../agent-coordination/validation.md#tests) |
| 授权恢复、记忆删除、来源关闭或版本撤回与业务并发 | 各领域独立应用修订和控制依据；恢复不绕过披露、来源或版本限制 | [领域规范索引](../protocol.md#domains)及各领域矩阵 |

## 3. 独立实现互操作

至少使用独立实现的发送方与接收方，并在适用场景加入网关。固定双方声明、规范清单和所需领域版本；同一实现启动两个进程只证明该实现的通信，不构成独立实现证据。对每个声明支持的领域执行正常交接、重复请求、恢复及关键拒绝分支。

| 互操作项目 | 检查内容 |
| --- | --- |
| 接入与来源 | HTTP／WSS 方法、头、子协议、票据单次消费和受限恢复资格；网关保留来源、拒绝伪造及跨用户路由 |
| 严格编码与关联 | 时间与 uint64、重复 JSON 键、未知字段、同 ID 异内容、请求响应／事件配对；运行解析与本地 Schema 校验一致 |
| 类型及路径协商 | 最终目标而非只看网关能力；缺 request／response、必要附加项或视图时拒绝，可选能力独立关闭 |
| 相同成功与错误含义 | ACK、accepted、completed、recorded、applied 按所属类型解释；retry 不触发无条件重做，Unknown 不被改写成拒绝 |
| 流与恢复 | 交换 ACK／resume，注入缺序、超窗、旧轮答复和权限变化；公共行为符合上一节，恢复证据实际来自领域权威 |
| 视图与扩展 | 自定义类型的作用域及恢复规则有效；已知可选项数据非法仍拒绝，fallback 不丢失必需输入或授权含义 |
| 外部协议适配 | 映射前后的身份、许可、原操作、执行事实、结果与恢复语义一致；对方没有查询或取消能力时如实拒绝或限制 |

标准类型的不同版本互通须等相应版本实际定义后验收；不得混用不同 v1 草案冒充兼容。发布后的规范引用与机器资产一并冻结，互操作报告标明测试到的类型集合和路径，不能将一个领域通过推广成全部领域通过。

## 4. 条件能力与规模证据

领域合同已定义不代表提供方已经可用。跨端执行、委派、交互、授权恢复和记忆同步在真实实现、平台及恢复依据齐备后验收；缺席时先验证对应入口受限。截图消息串的完整运行还须落实原预览读取、来源、受信取得凭据及临时内容清理，不以静态载荷替代这些证据。

有限离线按有效许可、可信时间、防回滚、当前 owner、本地依赖和领域资格共同验证；端端直连、跨主机接替与运行中权威迁移仍按[后置范围](../README.md#scope)关闭。以后采用相应契约时，再补正常及故障互操作用例，不根据当前例子推断已经支持。

吞吐、尾延迟、用户隔离、总配额与恢复公平性沿[通信容量矩阵](../validation.md#capacity)取证，三种部署及项目目标沿[系统验证](../../validation.md)取证。结构、单实现运行、独立互操作和规模四类结果分别报告。
