# 契约校验与运行验收

[总览](../README.md) · [标准注册表](../schemas/standard-registry.json) · [任务／UI 示例](../examples/task-ui-flow.json)

本页规定协议资产如何静态校验，以及实现后用什么证据验收可靠交接、业务恢复和互操作。当前交付为设计与校验资产，没有协议运行实现；下文的故障场景均为待实施要求。

| 证据 | 能回答的问题 | 判定边界 |
| --- | --- | --- |
| 静态契约校验 | Schema、注册声明、固定消息串及非法用例是否满足结构和指定关联？ | 不证明持久事务、授权裁决、并发处理或外部效果 |
| 单实现运行验收 | 在故障、重启和竞争下，记录、后续责任及实际行为是否符合契约？ | 需观察存储与执行，不能只比较网络返回值 |
| 互操作与规模验证 | 独立实现能否交换相同语义，部署能否满足目标负载与隔离？ | 单实现通过或 Schema 相同不能代替互操作，功能通过不能代替压测 |

文档链接、图示渲染和语义审查单独记录；它们用于检查方案本身，不计作协议运行通过。设计范围与缺失依赖时的行为见[总览](../README.md#scope)。

## 1. 运行静态校验

在已安装 Python 3.12+、支持 venv 的环境中，从仓库根目录运行：

```bash
python3 -m venv /tmp/harness-protocol-validation
/tmp/harness-protocol-validation/bin/pip install -r docs/architecture/endpoint-communication/validation/requirements.txt
/tmp/harness-protocol-validation/bin/python docs/architecture/endpoint-communication/validation/validate.py
```

[validate.py](validate.py) 只解析本地 Schema，不下载 `$id` 指向的资源。它是协议资产检查器，不提供客户端 SDK 或可靠传输实现。

| 检查对象 | 当前覆盖 | 边界 |
| --- | --- | --- |
| Schema 与引用 | Draft 2020-12 合法性、本地引用可解析 | 不加载远程声明或处理器 |
| 标准注册表与扩展声明 | 类型／版本身份、请求响应配对、交付约束、scope_binding 与声明结构 | 权限名称的结构合法不代表运行时已授权；能力安装与路径协商仍需运行验证 |
| 信封、载荷、附加项与视图 | 对应 Schema、类型规则、必要附加项及降级约束 | 不证明处理器落实授权、隐私或执行语义 |
| [任务／UI 消息串](../examples/task-ui-flow.json) | 响应引用、操作标识、流序号、作用域／lane 绑定、目标回执、UI 修订及输入消费关系 | 关联检查限于固定消息串；其中截图预览包含原投影／输入／内容摘要和受信宿主取得凭据的关联，不证明默认装配可用，也不模拟崩溃或并发 |
| [成果与呈现恢复](../examples/result-and-presentation.json) | 完整输入描述、两端呈现隔离、条件更新答复、旧操作决定复用、正式结果与当前状态分离 | 校验示例中的状态关联；不提供 UI 管理器实现，不证明持久化、并发裁决或实际窗口到期 |
| [任务／大脑／执行跨端链](../examples/core-domain-flow.json) | 准确声明、原生成调用、控制／预算、补证、事实与用量、原取消及设备管理；操作与生产者关联 | 固定证明值只作结构绑定，不代表已签名或当前获准；竞争与停止仍需运行取证 |
| [身份授权跨端链](../examples/identity-domain-flow.json) | 主体许可、收缩委派、消费／撤销状态、恢复快照与应用、有限离线证明 | 固定签名样本和载荷结构不证明真实身份提供方、时间锚或离线防回滚 |
| [记忆／治理跨端链](../examples/memory-governance-domain-flow.json) | 记忆原命令、固定视图、来源／内容及逐持有者清理回执 | 分项回执的静态结构不证明载体已清理，物理清理仍由持有者运行取证 |
| [交互目录跨端链](../examples/interaction-domain-flow.json) | 获准目录、订阅及恢复投影 | 订阅投递、实际字节获取和多设备竞争需运行验证 |
| [委派与发布跨端链](../examples/runtime-domain-flow.json) | 固定权威子接纳与查询、外部输入／授权恢复、批准／逐节点发布及停用回退 | 不证明真实 Agent 或制品适配器能力、隔离与物理停止 |
| [恢复与取消示例](../examples/recovery-and-cancel.json) | 逐条消息的结构与类型约束 | 假定已有持久记录，不验证恢复时序与实际效果 |
| [HTTPS 示例](../examples/http-exchanges.json) | 请求及响应 JSON body 结构 | 不验证 HTTP 方法、状态、头、票据消费或内容字节 |
| 严格原语与[非法用例](invalid-cases.json) | 日历时间、uint64 上限、重复键、非 JSON 数值，以及预期拒绝的结构与语义组合 | 固定时间是测试数据，不按运行当天判定业务有效期 |

样例使用固定虚构 UUID、摘要、证明引用和时间；它们不是可用于真实服务的凭据。金额为最小单位整数，task-control 的分配与 target／cleanup 账本包装复用共享用量，不把父聚合与子明细重复计费。

回归检查允许 `completed + effects_pending=true`：线字段不能判断剩余效果是否影响成果，任务核心仍须取得“不影响目标”的证据。检查还覆盖可靠消息必填 scope、同流混作用域拒绝、自定义视图的完整输入元数据及已拒绝呈现操作不得在重投后改为成功。消息自报的状态、来源和权限仍须由运行实现核实。

## 2. 先验证完整交接，再注入故障

运行前固定实现版本、协议草案及 Schema 摘要、持久存储配置、端点与用户、能力和许可、时间依据、窗口与配额。每个用例保留故障位置、原消息／操作标识、关键提交前后的记录及实际执行次数，分别判断交付、业务处理和效果。

首个集成运行基线采用[整体设计推演](../../design-walkthrough.md)的同宿主链路：用户先澄清保存目标，系统生成有来源答案、保存固定成果、独立读回，核心核验后固定正式结果。澄清请求须可凭完整文本与字段作答，不依赖中间截图或工具产物预览。运行前落实该链的任务策略、验证器、准确能力声明、许可及内容提供方；当前设计推演没有对应的新 JSON 消息串，也不表示参考实现已存在。

先观察本地交接的接纳责任、执行事实、UI 输入消费、正式结果和内容可用性的独立依据，再注入下表适用故障。本地消息交接遵守同样的持久边界；跨端流、网关、断连和网络容量行为在所需领域实现与配置齐备后单独验收。[截图消息串](../examples/task-ui-flow.json)继续用于静态校验，其完整运行链列于第 5 节条件能力。

| 前置条件与故障 | 必须观察到的记录与行为 | 目标关联 |
| --- | --- | --- |
| 接收记录已提交，丢弃回执后重连 | 重投原消息返回既有交付状态；去重及待处理责任恢复，不创建第二个业务操作 | C4、C5 |
| 分别在接收确认后、业务接纳后崩溃 | 前者恢复消息与待交接责任，后者恢复处理决定、操作关联及后续工作；提交和确认之间无丢失责任的空档 | C5 |
| 外部动作已发生，丢弃执行结果 | 先查询原操作并读取执行记录；无法确认时保持效果未知，不用新操作重复动作 | C4、C5 |
| 最终结果引用的内容失效、撤权或完整性校验失败 | 消息接收、结果可查与内容可用分别记录；不报告完整交付，由业务决定后续处置 | C4、C7 |
| 积压超限，或已接纳消息耗尽可靠窗口 | 接纳前拒绝或降速；已接纳责任不静默丢失，超窗留下可查询的缺口与后续动作 | C5、C8 |
| 传输大文件时发出取消 | 内容传输不得占用控制／恢复保留容量，取消仍按当前事实裁决；保留容量不承诺拥塞下零延迟 | C5、C7 |

成功条件与持久边界以[可靠交接](../message-contract.md#handoff)为准，内容交付见[内容通道](../transport.md#content)。回执丢失、业务未接纳和效果未知应得到不同结论，不能统一实现为重新执行。

## 3. 验证恢复期间的竞争与隔离

恢复用例要同时观察流位置、领域已应用位置、允许行为和实际行动。流 ready 只证明可续传；门禁按依赖证据的行为关闭，获准的查询、控制同步和结果上报仍须能够推进，完整判定见[恢复与控制](../recovery-and-control.md#resume)。

| 前置条件与刺激 | 必须观察到的记录与行为 | 目标关联 |
| --- | --- | --- |
| 首次连接无历史流，初始业务依据缺失 | 空 streams 和连接成功均不开放依赖该依据的行动；记录缺口，领域取得依据后再放行 | C5、C7 |
| 离线期间云端撤权 | 仅在有效离线许可内行动；到期停止新行动，重连先核对授权 | C5、C7 |
| 用户本地接管，或取消与完成并发 | 阻止新自动动作，保留真实完成或未知效果，不伪造回滚 | C4、C7、V2 |
| 任务已取消，迟到执行事实或结果到达 | 禁止新目标行动，在当前权限内接收原事实；任务终态与未明效果分别保存，不重开任务 | C4、C5、C7 |
| 跨用户引用、队列或恢复游标复用 | 拒绝访问，不泄露其他用户的数据和操作状态 | C7 |
| 工作流先 ready，取消或撤权同步尚未完成 | 依赖缺失证据的行为保持受限；核对本轮及活动所有者绑定、持久应用位置后才放行，获准的事实收尾仍可继续 | C5、C7 |
| 取得快照后发生新撤权，或后续更新有缺口 | 更新连续衔接，缺口关闭相应门禁；行动前复核适用证明，不宣称瞬时全局撤权 | C5、C7 |
| 旧轮恢复答复在新轮开始或所有者更换后迟到 | 旧轮次／旧所有者的证据不能解除当前限制；保留当前恢复记录与缺口 | C5、C7 |
| 同端点双实例、旧离线实例尚可执行、账本丢失 | 新实例无持续账本及旧所有者隔离证据不得激活；新身份不重做未知旧操作 | C4、C5 |
| 任务 A 的流有缺口而任务 B 已就绪 | B 可继续；伪造作用域或中途改绑流被拒绝；作用域隔离不绕过业务依赖 | C5、C8 |
| 超过 256 条流、多个连接共同消耗容量 | 分批恢复，不遗漏未核对流；用户／目标／会话总配额不因多流多连接扩大 | C5、C8 |

## 4. 验证输入、呈现与正式结果独立恢复

以下用例同时检查业务权威、UI 管理器和渲染端的记录。输入请求、共享内容和每端呈现状态分别判断；客户端显示“成功”不能代替业务消费或任务完成，完整规则见[任务与 UI](../task-and-ui.md)。

| 前置条件与刺激 | 必须观察到的记录与行为 |
| --- | --- |
| task.submit 重投 | 沿用原任务与提交操作，不创建第二个任务 |
| execution.result 丢失 | execution.query 核对原操作，不重复文件写入等目标动作 |
| UI 已接纳输入，分别在保存子操作关联前后崩溃 | 恢复输入与转交责任，先持久确定或复用关联再继续；多次转交只消费一次原输入 |
| 两台设备回应同一表单 | 不同操作只有一项生效，另一项冲突；同一操作重投返回原结果 |
| 仅进度文字刷新 | 不误判仍有效的表单过期 |
| 任务已取消，旧表单迟到 | 拒绝应用，保留已发生效果及取消记录 |
| 取消结果丢失 | 窗口内恢复原结果，超窗查询领域原固定答复；原记录已清理、未固定与无权读取分别返回，不用当前状态重建 |
| 关闭界面或任务结束 | 分别维护界面与任务生命周期，不隐式互相取消或销毁 |
| 正式结果消息超窗，但成果仍获准保存 | 凭 task_id 查询完整原结果及成果引用；最新状态单独查询，不能通过重新执行恢复成果 |
| 正式结果已清理、撤权或内容提供端失联 | 按授权返回不可恢复、拒绝或内容缺口，不把摘要／引用返回当成完整内容已交付 |
| 新端点只取得 ui.get，无历史 input_requested | 恢复输入用途、期限及字段约束；已消费或失效请求不可复活，业务消费仍权威裁决 |
| 一端关闭后输入、结果、快照或重连到达 | 本端保持关闭，另一端保持自身状态；已接纳输入继续转交，获准通知不隐含打开 |
| 关闭与重开竞争，旧成功／拒绝答复迟到 | 原操作决定不变；旧答复不能覆盖最新本端意图，呈现更新仍核对预期修订 |
| 关闭意图保存后崩溃或离线超过请求期限 | 重启先恢复本端关闭与待同步责任；旧请求沿原身份核对，必要新请求只落实最新显式意图 |

## 5. 条件能力、互操作与规模验收

依赖尚未落实的能力先验证入口保持受限，满足启用条件后再执行完整链路。不能用模拟提供方通过，替代真实身份、领域同步或隔离适配器已经具备的证据。

| 能力 | 当前限制与启用后的验证 |
| --- | --- |
| 截图预览与输入 | 默认关闭依赖中间预览的输入。按已采用 [UI-P3](../../application-and-interaction/validation.md#proposals) 的实现契约落实预览提供方及所需跨端领域依据，再运行[截图任务](../examples/task-ui-flow.json)：经网关提交、获准截图、查看后回应、固定结果；分别在截图已生成但输入未消费时重启 UI、撤销来源、清理内容或替换请求，恢复正确预览或明确禁止回应。任务完成仍须保留临时截图的获准清理责任 |
| 跨端能力调用 | [授权 P1](../../identity-and-authorization/validation.md#proposals)及[执行 CE-P1／P2](../../capability-and-execution/validation.md#proposals)已有设计按本组合落实提供方与验证后，验证手机经云端向电脑派发工作；原调用身份与关联保留，转发及路由切换不改变控制权，交付、效果和内容分别确认 |
| 身份、授权与离线 | 验证真实票据单次消费、来源绑定、权限与过期时间；缺少账本、可信时间或隔离依据时不得开放相应离线或接替能力。身份载荷及受限恢复资格见[身份合同](../../identity-and-authorization/contracts.md) |
| 记忆跨端恢复 | 已有[领域视图与恢复设计](../../memory-system/synchronization.md)，[跨端合同](../domain-profiles.md)已定义；启用后注入记忆删除、UI 旧输入及任务状态并发恢复，观察各领域分别应用，不以统一最后写入覆盖 |
| 端端直连 | 当前不启用；缺少接入、对端身份或来源绑定依据时入口关闭。契约与实现齐备后，验证身份、用户、来源及路由绑定，切换路径保留原消息与操作，并遵守同一授权、配额及恢复约束 |
| 任务控制权交接 | 首期关闭，须先补齐交接载荷、权威记录及操作索引迁移；启用后在各阶段断线，验证原方冻结或新方尚未激活，恢复后至多一方推进 |

互操作至少覆盖独立实现的发送端与接收端。固定双方的已安装类型、版本、附加项和视图能力，交换合法消息、必要能力缺失和不兼容版本；可选能力可以关闭，必要语义不满足必须拒绝。标准类型的不同版本互通用例须待对应版本实际定义后执行，不能混用不同 v1 草案冒充兼容。外部协议适配还要比较映射前后的身份、权限、操作关联、执行事实和恢复语义。

吞吐、延迟、队列配额、资源隔离及十万同时在线等[项目目标](../../../harness-project-goals.md)另行压测。报告须固定部署资源、用户与活跃流分布、消息大小、内容流量及故障条件，同时记录总配额、控制与恢复容量是否仍有效；不能仅凭在线连接数推断任务吞吐或恢复能力达标。
