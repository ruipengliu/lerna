# 决策准入、交互与协作恢复

状态：已确认。方向依据见 [大脑循环与多 Agent 协作](06-brain-and-agent-collaboration.md)；本文件定义运行契约，不表示已有实现或测试结果。

决策记录：[确定大脑循环与多 Agent 协作方式](../../.scratch/harness-technical-design/issues/09-brain-agents.md)。

## 有限提案整体准入，外部工作分别确认

### 输入、输出与身份

`Brain.Decide` 接收任务引用与状态版本、目标及约束、ContextAssembler 的受控快照、可用能力及版本、已准入工作的摘要和剩余预算。返回一个有限提案，明确本次请求的行动或委派、等待原因或结果判断，可附计划修订及简短依据。

提案中仅使用任务内局部键表达本批次依赖；持久化准入时由内核分配或绑定既有稳定 operation_id，建立局部键到操作的映射。模型供应商的工具调用 ID 只在 Adapter 内关联响应，不成为 Harness 操作身份。重新生成不能覆盖已准入操作的类型、目标或参数。

输出 Schema 区分互斥的主要决策类型，参考实现不在一个提案中同时请求新动作和完整成功；结果可以包含部分产物而不请求任务终态。未知必需类型、越界参数、循环依赖、超大批次和超预算一律显式拒绝。

### Interface 对照

下表中的名字用于表达待实现的 Go 契约，不代表已经发布 SDK；接口不要求新增独立进程。

| Interface | 输入与输出责任 | 必须保持的行为 |
| --- | --- | --- |
| Brain.Decide | 输入版本化任务快照、受控上下文、能力及预算；输出完整 Decision Proposal 或领域失败。 | 提案只描述工作；不能直接推进任务、执行设备动作或写入长期记忆。 |
| Model.Generate | 输入受控内容、模态、Schema 和生成限制；输出临时增量、完整结果及可获得的用量。 | 完整结果与增量分开，取消和中断显式结束；不自动执行供应商返回的工具调用。 |
| ContextAssembler.Assemble / Validate | 组织允许位置的上下文，并复核来源修订与用途。 | 沿用记忆分册，不在 Brain 中复制另一套无约束记忆访问。 |
| TaskService.Submit / SubmitUpdate / ProvideInput | 接纳任务、正式更新或具体等待项的回答。 | 沿用操作去重、权限及状态版本规则；协作消息不直接修改接收方权威状态。 |
| RunStore.Commit / LookupCommit | 提交准入工作、预算和待发内容，核对不明提交。 | 任务内原子性，不冒充跨任务或外部动作事务。 |

模型能力声明随已选择的 Adapter 配置提供，并接受兼容检查；供应商私有类型不泄露到 Brain 的公共输入输出。生成事件流须有有界缓冲和背压，消费者中止后不得在后台无限生成；中止后未知用量仍按预算规则记录。

格式无效、能力不足、输入失效、预算不足和暂时不可用是可辨认的领域结果；传输断开不能伪装为其中某一种确定业务结果。失败结果携带允许披露的原因与既有引用，是否重试由内核结合事实、控制意图和预算判断。

### 准入与恢复顺序

1. 内核读取当前事实与控制意图，恢复未完成的既有工作，领取本轮决策工作并持久化生成预算预留；模型调用不在数据库事务内。
2. 以领取与生成预算预留提交后的任务版本为输入基线，ContextAssembler 交付在所选处理位置可使用的上下文，大脑生成完整提案。模型或工具来源的内容不能自行授予权限。
3. 返回后验证 Schema、所引用的能力及输入、来源失效和预算。参考实现严格要求提案的任务状态版本仍然匹配；有变化就重新组装、重新决策，不实现自动合并过期提案。
4. 在该任务的一次 RunStore.Commit 中原子校验 owner/epoch、Worker 领取代次、状态版本及控制意图，保存准入提案摘要、操作映射、待处理工作、预算预留和必要 Outbox。
5. 提交成功后调度。执行端、子任务端和 UI 发布端按当前权限及位置要求再次准入。跨模块的来源有效性检查遵循既有有限新鲜度保证，不能声称与远端删除形成全球原子事务。
6. 提交结果不明时先 LookupCommit；仅在确认提交结果后发送或重新决策。远端提交不明则 LookupOperation，沿用原操作，不能因重启重建同一业务动作。

这里的“整体”只表示有限批次的运行记录整体准入，不保证批次中的外部效果一起成功或一起撤销。批次后续某动作权限失效或失败，仍须保存已发生效果并按依赖关系处理其他工作。

不能对每次 UI 呈现回报都递增任务决策版本；无关显示状态由 UI 模块管理。真正的任务输入、运行事实和控制变更改变任务版本，避免为了减少重规划而隐藏相关变化。持续高频变化时合并尚未消费的事实，并受决策预算约束。

合并指一次处理多条已持久化事实并触发一次决策，不允许丢弃可靠业务结果。当前生成的用量结算可随准入或拒绝记录一起提交；若另有任务提交已推进版本，仍按冲突规则处理，不为模型结果绕过版本检查。

| 故障窗口 | 行为 |
| --- | --- |
| 模型返回前崩溃 | 原生成预算保留待结算；若生成结果不能恢复，可在剩余额度内重新生成，不推断已产生设备效果。 |
| 提案生成后、准入前崩溃 | 无外部业务工作被准入；恢复可重新生成，原输出不构成执行凭据。 |
| RunStore 提交成功但回执丢失 | 先查询原 change_id，恢复原操作映射和工作，不重新创造动作。 |
| 子任务提交已受理但关联回执丢失 | 查询原提交操作并补齐关联，不创建第二个子任务。 |
| 并行结果或用户输入先更新任务版本 | 拒绝旧提案；已持久化事实保留，使用新上下文重新决策。 |
| 大脑升级后重启 | 继续核对和处理已准入工作；下一次决策才选新实现，不把旧计划文字重新执行一遍。 |

### 大脑替换与模型状态

参考大脑将可恢复工作信息保存为版本化结构，并以任务事实和已准入工作作为恢复依据。供应商会话 ID、隐藏上下文和模型内部状态不是唯一恢复来源；无法恢复时重新组装获准信息。

每次决策固定大脑版本、模型配置、适用 Skill 版本及上下文组装版本，受控记录用于解释结果。替换时新实现需声明可读取的工作信息版本；遇到不兼容，先迁移或等待明确处置，不能静默丢弃关键约束。版本激活与回滚权限由扩展及自进化分册细化。

## 正式输入可改变后续决策，呈现与执行分别控制

### 运行中输入

任务协作领域提供 `TaskService.SubmitUpdate`，表达正式追加信息或修改目标；它使用已有 operation_id、目标 task_ref、明确意图、预期任务版本及受控内容。该方法已纳入 [原生接口与消息目录](03-contract-message-catalog.md)，使用既定 gRPC 与 WebSocket 绑定。

| 输入意图 | 处理 |
| --- | --- |
| 回复一个现有问题 | 沿用 ProvideInput 与 interaction_id，验证该等待项；不通过新方法绕过等待项竞争规则。 |
| 追加相关事实或用户补充 | SubmitUpdate 的追加意图，保存来源和提交主体；允许的协作 Agent 也可提交事实，但其文字不自动成为用户指令。 |
| 修改任务目标或约束 | SubmitUpdate 的修改意图，显式预期版本并要求对应权限；目标变更不自动增权、增加预算或改变数据策略。 |
| 暂停、取消、恢复或授权决定 | 走各自受控操作；不靠模型从一段普通文本中直接改变控制状态或授予权限。 |
| 编辑尚未正式提交的 UI 草稿 | 由 UI 管理，不推进任务状态。 |

参考更新使用严格版本检查；新操作冲突时返回当前可见版本，调用方根据新状态决定是否提交新的更新。原操作重试先返回原受理结果，不因版本已经推进而误报失败。任务已经终结时返回已终结，不能用更新重开任务。

任务接纳更新后，旧决策结果因状态版本不匹配而失效；尽力取消在途生成以节约资源，取消生成本身不等于供应商未产生用量。根据目标是否变化处理已准入工作：尚未发出的不再适用工作停止调度；已发出工作请求取消并核对效果。需要用新参数行动时创建新操作，不能篡改旧操作。

只撤销被新输入改变语义的等待项，新问题分配新 interaction_id；无关且仍有效的等待项可保留。源端与 UI 的撤销通知经 Outbox 可靠传播；UI 尚未更新时的旧输入仍由任务端拒绝。

### 流式答案与 UI

参考默认及时展示受控进度，答案经完整输出校验、来源复核和发布准入后发布。进度只表达已发生的阶段和事实，不能把模型猜测写成动作成功，也不暴露内部思维链。

协议保留可选的答案预览：仅在允许增量披露、Renderer 能表达草稿及失效状态时启用；每个发送块在披露前检查用途、接收位置和允许字段。依赖全篇校验才能判断可披露的答案必须缓冲，不能先发送再指望撤回。

预览失效时停止后续发送并更新 UI 状态，但已经显示或被复制的内容不能保证撤回。正式答案与草稿使用明确的呈现状态和版本；最终可靠结果通过快照恢复，不从可能缺失的 token 增量猜出最终正文。

内核保存结果引用及待发布工作，UI 模块按既有幂等转交规则处理；UI 发布、任务完成和用户实际看到不是同一原子事件。若目标明确要求交付，须将相应交付条件纳入验收；Renderer 回报不能证明用户已理解或同意。

上述路径同样支持端侧私有回答：正文只在获准位置生成和呈现，云侧仅保留获准控制状态。上下文或答案因驻留策略无法在云端校验时，由有权处理的端侧模块承担对应检查，并明确云侧能确认的范围。

## 按依赖处理子任务失败，收尾前处置所辖工作

### 委派与结果

在委派时固定子目标、授权范围、允许输入与结果位置、预算上限、期限、结果 Schema、验收条件、必需性和依赖关系。父任务可记录多个并行子任务；无需暴露供应商内部 Agent 会话作为运行权威。

子结果包含可见的产物或受控引用、证据及其来源、覆盖范围、未解决事项和效果状态。父任务验证结构和来源，按本身的目标评价；不把子任务的完成标签、置信分数或投票多数替代效果证据。

受控协作消息沿用 SubmitUpdate 的追加事实语义；接收方接纳后推进自身状态并决定如何使用。必须拒绝形成不可满足的等待依赖，例如父任务等子任务完成、子任务又把父任务完成作为必要条件。跨运行时不能完整探测的依赖仍受期限和无进展检查约束。

### 失败、取消与完成

| 情形 | 默认规则 |
| --- | --- |
| 必需子任务明确失败 | 停止依赖其成功的后续工作；独立分支可在剩余预算内继续，保留有用部分结果。 |
| 可选子任务失败 | 记录缺口，依据原验收要求判断是否可完成；不能为了成功临时把必需项改成可选。 |
| 子任务结果冲突 | 保留不同来源，进行获准的验证或请求澄清；不默认按多数或最近返回者覆盖。 |
| 子任务失联或效果未知 | 记录依赖/核对等待，不因超时将其当作已停止；能够确认的部分结果仍可交付。 |
| 父任务取消或不再需要某分支 | 向相关子任务传播取消，记录实际停止或未能阻止的效果；离线时保持待送达或待核对。 |
| 父任务准备进入终态 | 所辖子任务及外部操作必须完成、明确未启动或已停止并处置；关键效果无待核对事项。 |

参考默认不允许子任务悄悄脱离父任务继续后台工作。需要独立长期工作时，应在既有授权范围内明确创建独立任务，具有单独目标、预算和责任；不能用“脱离”规避父任务的取消或重复启动未知工作。

失败恢复不默认回滚已完成动作。补偿是新的业务操作，需要声明支持、当前授权、独立身份及效果验证；无法补偿时报告实际影响，不能声称任务失败意味着外部状态未变。

## 预算先预留再使用，未知消耗不自动归零

### 持久化预算与委派

预算以任务状态中的结构保存，不新建必需的预算服务或全局 ID。每次生成、行动、委派准入时预留相应额度，完成或核对后结算；预留与待处理工作在同一任务提交。供应商多次请求分别计入用量，即使最终只采用一次生成结果。

一次 Decide 内的格式修复和模型回退只能消耗已经预留的有限生成额度；耗尽后返回明确结果。模型 Adapter 不得开启未计入该额度的隐藏重试。进程崩溃导致实际消耗不明时，未核清的预留保持占用，不能重启即重置。

父任务先从可用额度中预留委派份额，再发送与原委派操作和子任务绑定的有限额度。子任务在自己的权威存储内原子扣减，向后代分配的总额不能超过自身可分配额度；重复接纳同一委派不能获得第二份额度。

这不是父子任务间的分布式事务。父提交已确认、子接纳不明时保留父预留并查询原操作；不能同时留给子任务使用又恢复到父任务余额。子任务离线时只使用已分配且仍有效的额度，不从云端共享一个可被重复扣减的浮动余额。

额度回收需确认接收方不再能继续使用原分配，并核对已发生消耗；失联、父端等待超时或取消请求已发出都不满足回收条件。即使执行资格已可靠失效，历史用量未知也应保留保守占用或显式记为未结算，不能虚构余额。并发槽位同样不能在旧工作仍可能运行时重新分配。

### 硬限制与估算

决策次数、准入次数及本地已知配额可以在内核强制限制；外部模型的金额上限受供应商计量与请求限制能力约束。仅有价格估算或请求超时，不能宣称能够保证精确账单上限。

对外承诺硬上限时，Adapter 必须能在发起前给出可执行的保守上界或提供可验证的配额机制；不具备时明确不支持该保证。未知消耗保留待结算，重试仍需剩余额度。评测的 token 与期限阈值见 [参考基准](10-evaluation-contracts-and-release-gates.md) 和 [专项 profile](11-specialized-validation-and-handoff.md)；业务部署额度与有依据的金额预算由相应获准配置确定。

### 预算不足与无进展

| 情形 | 状态与恢复条件 |
| --- | --- |
| 可补充预算但尚未获得 | 停止新的目标工作；通过明确输入等待预算调整，授权不足则另记授权等待。 |
| 预算不能增加或业务期限已过 | 进入失败处置；已知所有关键效果且所辖工作处置完成后才 FAILED。 |
| 模型或必要能力暂不可用 | 有限重试后等待依赖，并记录期限；未满足前不能无界空转。 |
| 重复建议同一已处理动作、反复无新事实或无目标进展 | 达到配置阈值后停止该循环，报告依据；可澄清则等待输入，否则按失败处置。 |
| 已耗尽目标工作额度但需取消、核对或恢复 | 使用另设的有界处置额度，不能用于扩展原目标或任意继续规划。 |
| 处置额度也不足且效果未知 | 保持明确的待核对状态，等待获准资源或外部证据；不能仅为收尾伪造 FAILED/CANCELLED。 |

控制消息的接纳不因目标预算耗尽而被禁止；实际核对可能需要外部资源，应明确其可用限制。预算和期限的修改必须由有权主体明确提交并持久化，不能靠模型修改自己的输入文本生效。具体授权操作由授权分册承接。

无进展判断依据规范化请求、已记录工作、观察变化和验收条件进展；不以文本相似度单独证明整个任务没有进展。规则只是可解释的停止触发器，不能保证识别所有循环。

## 验证计划

以下是必须覆盖的共同 Interface 验证矩阵，全部尚未执行。可用脚本化大脑、模型替身、多个模拟端与模拟云构造故障；真实模型质量另行评测。

| 能力或故障 | 必须观察到的结果 |
| --- | --- |
| 单步与批次提案 | 非法批次整体不准入；合法批次产生稳定操作映射，外部部分失败仍保留事实。 |
| 准入崩溃与重复提交 | SQLite 重启后恢复原工作，提交未知不生成重复设备动作或子任务。 |
| 状态竞争与记忆失效 | 旧提案不能覆盖新输入/取消；失效源不能继续驱动新行动或答案。 |
| 模型与大脑替换 | 同一契约套件在两种大脑策略运行，模型 Adapter 差异被明确表达；不要求逐字相同输出。 |
| 流式中断 | 半截参数零执行；过期草稿不被标成正式答案，末次增量丢失可由快照恢复。 |
| 用户中途输入 | 新目标影响后续决策，旧动作实际效果仍可核对；旧等待项输入不绑定新问题。 |
| 串行、并行和冲突结果 | 依赖顺序、失败影响范围和证据缺口可观察，子报告不直接决定父终态。 |
| 子任务取消和失联 | 不将消息送达当作停止；父任务保持处置状态，部分结果与完整成功区分。 |
| 端侧受限推理 | 私有原文不进入云模型、消息或日志；云侧仅使用允许结果，本地能力不足不自动外发。 |
| 离线预算与恢复 | 重复委派不双倍授额，父子并行与重启不增加总额度，未知用量不归零。 |
| 停止与恢复 | 预算、期限和无进展触发有限行为；必要核对未完成时不制造终态。 |

方案同时覆盖 C1、C5 的决策与协作、C2 的上下文控制和 C7 的准入边界；联网问答及 GUI 的真实效果仍需各自专项验收，不能用脚本化大脑契约测试代替。

预算与期限调整已定义为 TaskService.AdjustLimits，按有权主体、稳定操作和任务版本提交；不得抹去已用/未结算额度或清除暂停/取消。授权判定及委派签发见 [授权生命周期](08-authorization-lifecycle-and-interfaces.md)，不改变本册先预留、核对后回收及有限收尾预算规则。
