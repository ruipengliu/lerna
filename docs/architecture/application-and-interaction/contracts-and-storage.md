<a id="interfaces"></a>
## 1. 复用的线契约与本次内部接口

所有内部入口接收宿主构造的 RequestContext，绑定用户、端点、行动主体、来源及当前许可。下表是默认宿主的类型化逻辑接口；对外行为以[UI 交互规范](interaction-contract.md)为准，跨端编码沿[通信映射](../endpoint-communication/task-and-ui.md)，view 不能指定任意方法名。线字段与错误以[协议 Schema](../endpoint-communication/schemas/ui.schema.json)及[公共信封](../endpoint-communication/wire-format.md#envelope)为唯一权威，不复制一套同名 Schema。

| 逻辑接口 | 最小输入 → 输出 | 归属、映射与前提 |
| --- | --- | --- |
| `Application.SubmitTask` | 冻结目标／附件、任务 ID、提交操作、期限 → 本端记录及核心处理结果 | 本次宿主接口，调用既有 Submit／task.submit；本端 saved 与核心 accepted 分开 |
| `Surface.Bind` | 受信提供方、来源对象、视图用途、固定绑定键 → surface_id | 本次内部接口；唯一映射、初始呈现关闭、首次刷新责任同事务，普通客户端不能绑定任意任务 |
| `Surface.Refresh` | 已绑定 surface、触发原因 → 新快照或未变／缺口 | 本次内部接口；适配器读取来源后条件提交，同版本异内容拒绝 |
| `UI.Get` | surface_id → 完整 view、inputs、内容修订及源端点 presentation | `ui.get@1`；只读，不打开或隐含订阅 |
| `UI.ApplyInput` | surface、seen_revision、输入请求、值及父操作 → accepted／拒绝；随后最终结果 | `ui.input`／`ui.input_result`；固定子操作，仅权威消费后 applied |
| `UI.ApplyAction` | surface、seen_revision、action_id 及父操作 → accepted／拒绝；随后最终结果 | `ui.action`／`ui.action_result`；当前只转交已保存的 cancel_task；submit_input 控件走 ApplyInput |
| `UI.SetPresentation` | surface、期望呈现修订、明确 open／closed 及操作 → 原同步答复 | `ui.set_presentation@1`；以源端点隔离，事务与去重按既有协议 |
| `UI.ReadOperation` | 原操作 ID → recorded／applied／rejected／conflict 或安全拒绝 | `ui.query_operation`；不返回完整原开闭答复、取消答复或输入正文 |
| `Renderer.Apply` | 已校验的快照／追加、类型能力、本端当前意图 → 缓存更新与本地渲染结果 | 本次渲染器接缝；渲染失败不是业务拒绝，缓存可从快照重建 |
| `UI.CheckRecovery` | 当前恢复轮次、surface／原操作、身份与领域依据 → 可查询／可转交／可呈现及缺口 | 本次本地恢复适配器，落实协议已有 UI 恢复责任；不产生线 ready 或替代交付模块最终放行 |

宿主维护显式绑定的渲染端集合；向某端推送前复核其身份、协商能力与当前披露许可。绑定由受信启动配置／本地打开流程建立，并有有限有效期及配额。`ui.get` 本身不注册持久订阅；目录发现与显式订阅沿[独立接口](#directory)，没有绑定时使用 ui.get 拉取。

内部来源适配器锁定版本并声明：来源权威、读取方式、输入消费／查询方式、完整性判断、来源及披露约束、支持视图。任务适配器调用[核心接口](../task-kernel/storage-and-interfaces.md)及固定中间投影，验证已安装策略与 required_preview_ids；必需预览缺失时只开放相应只读展示。独立 UI 的提供方由宿主安装，不能由 Agent 提交任意回调；缺少耐久消费及恢复能力则只开放展示。

只读接口超时可以在原查询预算内重查；副作用入口超时保留原命令并核对，不自动取消。停止等待或离开页面不撤销已保存责任。接口／适配器升级须锁定旧未决操作的解释版本；无法解释旧记录时禁止迁移后重派发，保留恢复缺口。

<a id="records"></a>
## 2. 记录与唯一性

以下是默认实现的内部记录，相关领域消息只承载完成交接所需字段。所有键含受信 user_id，涉及端点的键另含 endpoint_id；同一用户的 UI operation_id 在该固定 UI 权威内跨 surface／种类唯一，转交到核心的子 ID 还遵守核心全用户唯一约束。

| 记录 | 必须保存的字段组 | 唯一性与用途 |
| --- | --- | --- |
| Surface | ID、提供方及版本、来源绑定、用途／来源约束、来源版本、内容 revision、完整 view／input_requests、final、刷新状态 | 固定绑定键唯一；内容修订从 1 起，不回退、不复用；清理后原 ID 不创建另一界面 |
| ActionBinding／InputProjection | surface、动作 ID 与含义、精确目标、有效版本；请求 ID、权威、用途／字段／期限、已知消费／失效依据 | 以来源权威请求为准；保留足以判断旧 seen_revision 的最小关联，不需保存全部历史内容 |
| Presentation | surface、源端点、已确认 state／revision | `(user, endpoint, surface)` 唯一；初始 closed／0，内容更新不写此记录 |
| UIOperation | 原 operation_id、类型／版本、源端点、surface、规范意图、接纳／拒绝决定、当前处理状态、原回执、固定最终事件 | 同键异意图拒绝；先查原决定再判断新的版本前提。开闭的完整原答复单独保存 |
| Forwarding | 父 ID、子 ID、精确权威／目标、冻结请求、原期限、可能已转交标记、子处理依据 | 一父一固定子映射，随接纳共同保存；记录不会因租约或重启换 ID |
| UIWork | 工作 ID、kind、关联对象、pending／leased／done／closed、领取代次／期限、预算、下一时间、尝试与缺口、固定发送消息／接管凭据 | 转交、刷新、发送、清理等有界工作；同一责任唯一，派发前核对领取和当前门禁 |
| LocalIntent | 本端意图序号、surface、最新明确选择、已发送原操作及请求、已确认呈现修订、待协调标记 | 多窗口共享宿主串行入口；未决操作与最新选择分别保存 |
| LocalCommand／TaskBinding | 提交或管理命令的固定身份／意图／截止、目标权威、已知结果、task 与 surface 关联 | 本端保存和远端接纳分开；本端索引与获准全局目录的固定切点分别记录 |
| RendererCache／Draft | 用户／端点／surface、内容修订、校验结果、来源／用途／到期、草稿对应 input_request_id | 缓存可丢弃重建；草稿不是业务输入。失效、退出和清理规则单独落实 |

规范意图包含种类、版本、用户及源端点绑定、目标、语义载荷、原期限与许可关联；不只比较哈希。规范化器版本固定，JSON 成员次序可忽略，数值、数组、空值及字段缺省按同版 Schema 处理。查询重投即使返回原历史成功，也先核对当前披露权。

内容 revision、presentation.revision、来源版本、本端意图序号及消息流 delivery.seq 各有用途，互不替代。线 uint64 保持十进制字符串；内部版本也禁止环绕，耗尽时拒绝新增变更并留下可查询故障。

<a id="transactions"></a>
## 3. 本地事务与责任交接

默认界面账本使用条件更新、唯一约束和本地事务；本端日志、UI 权威、运行存储及消息交付分别提交，即使同库产品部署也不依赖跨模块全局事务。任何网络、模型、内容读取和领域调用都在事务外执行。输入规范允许接纳后、首次转交前固定父子映射；下表选择与接纳同时提交，不将这一更强实现约束施加给其他协议实现。

| 事务 | 共同提交的内容 | 提交后才能进行的行为 |
| --- | --- | --- |
| 本端提交准备 | 原任务／UI／管理命令、冻结意图及待发送责任 | 向业务权威发送；本端保存回执只表示 queued locally |
| 本端开闭选择 | 最新选择与序号、未决请求关联、同步责任 | 发送开闭请求；关闭在存储失败时也隐藏，但不声称已耐久 |
| Surface 绑定／刷新 | 唯一来源绑定、来源版本、完整快照、动作／输入投影、刷新工作进度、可靠发布责任 | 推送快照；旧提供方响应不能覆盖新绑定 |
| UI 输入／动作接纳 | 原决定、规范意图、父子操作映射、转交工作及 accepted 答复责任 | 交接答复或转交子操作，两者的到达次序不作为业务因果依据 |
| 开闭条件更新 | 操作决定、Presentation 新修订及原同步答复责任 | 返回 completed；期望不符的拒绝同样保存，重投不重新裁决 |
| 子操作结果应用 | 子处理依据、父状态／最终事件、失效输入投影或刷新责任、发送工作 | 发布 input_result／action_result；不得先标 done 再补责任 |
| 消息发送接管 | 原发送工作、Delivery.Accept 凭据及 done | 由消息模块继续目标交付；未取得持久接管凭据时继续原工作 |
| 清理 | 内容禁用／清理状态、残留及下一责任、获准最小墓碑 | 删除可回收字节，未交接操作不因清理消失 |

发送工作在调用 Delivery.Accept 前固定 message_id、目标、类型／版本、载荷、scope 和原窗口；确认未知沿原消息查询／重交。入站消息交付先保存消息及待业务处理责任，UI 事务提交后才确认业务处理；确认丢失由 UIOperation 原决定消重。接收回执、UI accepted、业务 applied 与用户实际看见分别记录，不提供未经定义的“用户已读”协议保证。

事务步骤复用固定提交键：业务请求用原 operation_id 及种类，可靠事实用来源端点／message_id，工作用 work_id／领取代次／步骤名。存储返回 Committed、确定未应用的 Rejected、Unknown；Unknown 先查原回执或重试原提交，不能换工作代次或键绕过。旧事务尚未结束、只读副本未见或备份缺记录均不能证明未应用。

转交工作到期领取，租约过期先核对原步骤，固定子操作使旧持有者迟到发送仍可去重；旧持有者不得提交新的工作进度。唯一写权威及端点活动所有者保证由宿主提供，数据库锁不能证明另一个进程已停止对外发送。所有权不明时限制新发送，原查询在获准范围内继续。

<a id="errors"></a>
## 4. 错误和用户可执行的下一步

错误结构与 retry 完全沿[公共错误表](../endpoint-communication/wire-format.md#errors)。下表只说明应用映射，不定义新 wire code。

| 情况 | 既有返回／本地观察 | 展示与继续者 |
| --- | --- | --- |
| 身份或披露不成立 | core.unauthenticated／forbidden | 退出相关展示，重新认证或由用户管理授权；不泄露对象存在性 |
| 类型／版本缺失 | core.unsupported_type／unsupported_extension | 停用该交互，提供方仅可使用显式合法 fallback |
| 输入过期／冲突／格式错 | ui.input_expired／input_conflict／input_invalid | 刷新权威请求；保留必要草稿供用户重填，不自动回应另一个请求 |
| 呈现条件冲突 | core.precondition_failed | 本端读取当前修订，按最新显式选择有限协调 |
| 标识冲突 | core.identity_conflict | 停止该操作，保留诊断关联；不得改写原身份载荷 |
| 容量不足且确定未接纳 | core.overloaded | 按返回退避及原期限重投；控制、核对与收尾继续获得保留份额 |
| 调用超时／事务未知 | 本地结果不明；线响应不虚构新状态 | 原键查询，维持核对提示；未定前不宣称 rejected 或 applied |
| 交付缺口／保留窗口耗尽 | core.recovery_gap／delivery_expired | 查询原业务操作；不能给旧消息换序号、换流或延长窗口 |
| 正式结果不可用 | task.result_unavailable | 标明完整原成果不可恢复，当前状态可另查，不重跑任务恢复内容 |

<a id="deployment"></a>
## 5. 默认组装、存储与替换

首个参考部署在同一受信宿主内装配 document 渲染器、单个状态管理器、任务／管理适配器及 SQLite 界面账本；渲染器可在独立进程，须经宿主受控桥调用。选择理由是本模块的关键约束集中在少量关联记录的原子提交，独立 UI 服务和消息中间件没有首期必要性。纯浏览器部署须另提供经验证的耐久本端存储适配器，未具备时不宣称跨重启意图保证。

SQLite 使用短写事务及唯一约束，`BEGIN IMMEDIATE` 提前取得写资格；忙冲突有界重试，网络调用不能持有写事务。SQLite 同库只有一个并发写事务，因此该选择面向端侧和单机参考部署，不以十万在线目标直接证明容量可行。[SQLite 事务说明](https://www.sqlite.org/lang_transaction.html)

每用户独立数据库或等价受控命名空间，启用 WAL 与 `synchronous=FULL`；锁定含官方 WAL-reset 修复的受维护版本，部署时核验实际版本与配置。WAL 数据库只在同主机使用，不放到跨主机共享文件系统；本端日志与服务端账本按各自位置部署。耐久性仍依赖底层正确兑现同步，需断电／崩溃测试。[SQLite WAL](https://www.sqlite.org/wal.html)、[同步配置](https://www.sqlite.org/pragma.html#pragma_synchronous)

写排队持续超过交互预算、需要多主机接管或集中云端托管时，再替换服务端事务存储；仍按用户固定权威、保持 UI 操作唯一性和完整事务。Renderer、Store、Delivery、来源适配器各可独立替换，替换后重跑同一验收矩阵。首期不新增第二套云存储实现或自动主从切换方案。

清理分别配置快照缓存、草稿、命令／去重、未决工作、内容及审计的生命周期。未决责任、未核清本端关闭及原父子映射不能因普通缓存淘汰而丢失；最小墓碑阻止旧 ID 重新创建操作。若数据策略要求删除尚有恢复依赖的正文，先禁止使用并登记缺口，只保留获准控制依据；连最小可靠性记录都不允许保存时，接纳前拒绝该模式。

备份记录用户、账本代次与工作水位，恢复前封闭旧写者并核对去重／未决责任；旧备份可能遗漏一次已消费输入，不能按“查不到”重发新操作。无法证明连续性时保持受限。缓存清理不改变正式任务成果的独立保留策略，也不承诺文件系统、备份或外部导出的即时擦除。

<a id="limits"></a>
## 6. 容量与观测

启动配置须给出下列有限上限，缺少必需项拒绝启用可写交互；数值由参考实现测定，不在无证据时给出吞吐承诺。协议现有上限直接遵守：每快照 64 个输入请求、每表单 64 个字段、每 document 256 个块、每 actions 块 32 个动作；消息完整 UTF-8 大小还须满足整条路径的协商限制。

| 限额 | 过载行为与必须保留的责任 |
| --- | --- |
| 每用户 surface、活跃端点、绑定、未决命令／输入数及字节 | 新建／接纳前拒绝，不能截断已发布输入集或丢弃已接纳回应 |
| 快照总字节、内容并发／单项字节、缓存与草稿空间 | 过大展示内容使用获准 content 引用；必要输入仍完整，无法容纳时不发布交互 |
| 刷新间隔、合并等待、每轮批量、每用户并发 | 合并重复刷新，终态且无未决责任才停止常规轮询；有未决项保留有限查询工作，用户间公平轮转 |
| 重试次数／总时长、工作租约、延后上限 | 到限留下缺口及一次通知，不延长原请求／输入期限 |
| 可靠消息积压与存储保留 | 接纳前预留答复、转交和收尾容量；压力大时先丢临时增量，不能替可靠消息伪造成功 |
| 控制／恢复份额 | task.cancel／pause／resume、原操作查询、当前开闭及本地接管保留处理容量；网络拥塞仍不承诺远程取消零延迟 |

观测关联 user 的受控标识、endpoint、task、surface、内容／呈现修订、父子 operation、work 与 message；记录排队、核心接纳、输入消费、快照就绪、内容验证、实际本端展示等时点及缺口原因。实际展示测量是本端遥测，未定义跨端已读回执。日志不默认包含表单值、截图、授权票据或完整任务正文。

容量验证分别报告任务创建率、同时待输入量、每任务刷新次数、快照平均／峰值字节、慢端积压、SQLite 写等待、内容吞吐、控制延迟和每用户占用。测量配置、用户分布及注入故障一起保存；系统规模目标与当前单机参考能力分别报告。

<a id="directory"></a>
## 7. 目录与订阅的本地投影

对外合同集中在[目录与显式订阅](interaction-contract.md#directory)。默认实现以 DirectorySnapshot 保存用户、权威、collection、固定切点、游标、已读取页、观察时点及缺口；与本端尚未交接的 LocalCommand 分开记录。通知只合并刷新工作，定期有界刷新补漏；订阅原命令及查询关联复用 LocalCommand，不因页面重建续租。

<a id="preview"></a>
## 8. 预览获取记录

完整交接和证明要求见[预览规范](interaction-contract.md#preview)。默认 PreviewAcquisition 以用户、端点、surface、输入、projection_revision 和 preview_id 为键，保存内容摘要、实际取得／校验依据、来源、用途、期限和证明关联。签发入口只接受受控桥冻结的原 UI 操作，渲染器不能直接写入该记录。UI 接纳事务保存原凭据及校验事实，和父子映射共同提交；恢复继续使用原记录，不更新旧证明期限。

## 9. 管理适配器装配

管理入口及领域消息的规范引用见[受信管理合同](interaction-contract.md#management)，默认本地控件见[管理实现](interaction-and-recovery.md#management)。每个适配器固定目标权威、命令类型、规范化版本和原命令查询入口；本端日志保存用户意图与调用关联，不承担许可签发、证据核验或设备效果裁决。相应提供方缺席时不安装可调用入口。
