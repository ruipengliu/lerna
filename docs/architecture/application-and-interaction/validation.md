## 1. 运行验收设计

测试宿主需要可控制时钟与故障点的事务存储、两个独立渲染端、同端点多窗口、任务／身份／内容与执行模拟器。每项同时读取本端日志、UI 账本、领域账本及可见状态；验证引用外部效果的用例还读取模拟设备真实状态，不能只断言 UI 文案。以下均为待实施运行用例。

| 编号 | 前置条件及刺激／故障 | 必须可观察的结果 | 保证／目标 |
| --- | --- | --- | --- |
| UI-01 | 已获准检索及呈现，按总览提交比较任务、回答成本优先 | 任务 accepted、UI accepted、权威 consumed、父 applied 与正式结果各有依据；没有新增许可或长期记忆写入 | U1–U3／C3、C5–C7、V1 |
| UI-02 | Submit 已提交但回应丢失；用户重复点击并重启 | 保留原任务和提交操作，核心只创建一个任务；本端先核对才显示接纳 | U1、U2／C5 |
| UI-03 | UI 接纳事务提交前、提交后及转交标记后分别崩溃 | 未提交不报告 accepted；已提交恢复同一父子映射与工作，没有已确认却无责任的空档 | U2／C5 |
| UI-04 | 核心消费 Q 后丢 O2 答复，随后关闭、过期并重连；accepted 晚于最终事件 | 父仍沿 O2 查询并最终 applied；过期或迟到 accepted 不回退消费事实，关闭持续隐藏 | U2、U4／C5、C7 |
| UI-05 | 两端以不同操作回答 Q，同时重投其中一项 | 一项消费，另一项冲突；原操作重复不创建第二个子操作或再次消费 | U2／C5、C6 |
| UI-06 | 仅进度刷新；另组改变字段含义并替换请求 | 前组旧 seen_revision 的有效回应可消费；后组旧请求不绑定到新请求 | U3／C6 |
| UI-07 | action_id 替换目标、提交任意方法／值、submit_input 双发 | 旧动作拒绝，不能路由任意接口；表单只产生一个 ui.input，无第二条输入路径 | U2、U5／C6、C7 |
| UI-08 | 先 delta 后快照、缺基准、重复／逆序、同修订异内容 | 旧内容不回退，缺基准有限 get，异内容停止套用；新端仅完整快照即可恢复输入 | U3／C5、C6 |
| UI-09 | 一端离线关闭后崩溃，另一端仍打开；结果和快照持续到达 | 恢复本端关闭，其他端不变；已接纳输入和任务继续，通知不能自动打开 | U4／C5、C7 |
| UI-10 | 同端点两个窗口快速关闭／重开，旧答复迟到，条件冲突 | 一个宿主意图队列，旧回执不覆盖新选择；有限协调，无未确认内容闪现 | U4／C7 |
| UI-11 | 关闭日志写入失败、开闭回执超窗、读取到旧 presentation | 先隐藏；明确耐久缺口；query_operation 不伪装完整答复，未核清旧请求前不开启 | U4、U6／C5、C7 |
| UI-12 | 完成结果超交付窗口，任务当前修订高于原结果；内容端失联 | ReadResult 返回原固定结果，ReadTask 单独展示；字节缺口不报告完整交付，不重跑任务 | U1／C3、C5、V1 |
| UI-13 | 取消与完成并发；取消已处理但效果未知，丢失完整取消答复 | action applied 只表示控制处理；当前事实和原答复缺口分别显示，不宣称远端停止 | U1、U6／C4、C7 |
| UI-14 | 多个有状态模拟设备执行点击／滑动／输入／返回；云断线时本地接管 | 立即封闭新自动动作；存储失败不报告耐久成功，重连／普通表单不解除屏障；重新开放依既有入口 | U5、U6／C4、C7、V2 |
| UI-15 | 伪造授权批准、模型生成同样按钮、确认范围被扩大、响应丢失 | 只有受信宿主真实用户依据可签发；变范围新建确认，原命令核对不重复签发 | U5／C7 |
| UI-16 | 记忆纠正冲突、delete 已提交丢回应、离线副本仍保留 | 原命令核对；不自动覆盖新修订，逻辑禁用与清理进度分别展示，不宣称全链删除 | U1、U5／C2、C7 |
| UI-17 | 快照／缓存撤权、退出后切换用户、旧响应迟到、猜测其他用户 ID | 停止相关显示和新发送，旧响应不进入新用户缓存；拒绝不泄露对象存在性 | U5／C7 |
| UI-18 | Markdown 脚本、原始 HTML、自动远程图片、恶意内容类型或错误摘要 | 无脚本／任意网络加载，内容验证失败可见，无管理调用；既有输入责任不因渲染失败丢失 | U5／C6、C7 |
| UI-19 | 一个用户大量 surface／输入／大文件、存储近满且控制到达 | 接纳前限流，其他用户有进展，原输入不丢，取消／核对／本地接管获得预留处理容量 | U6／C5、C8 |
| UI-20 | 双实例、旧备份缺去重、旧工作者迟到、账本不可写 | 无权威依据不启用新发送；未知旧操作不换 ID，关闭仍隐藏，未决责任可查 | U2、U6／C5、A3 |
| UI-21 | 替换渲染器／Store／本地业务适配器，缺少必要消息或消费核对能力 | 支持者通过同一矩阵；缺能力关闭相应交互，不把安全降级解释为完整可用 | U1–U6／C6、A2、A4 |
| UI-22 | V1 答案含实际来源、获取时间、冲突及失败；分别丢快照／引用内容 | 这些信息在最终展示和恢复后仍可见，缺内容明确；答案正确与引用支撑由整体 V1 评测另判 | U1、U3／C1、C3、V1 |
| UI-23 | 任务终态但 effects_pending=true，收敛通知丢失；耗尽刷新预算 | 未决查询工作仍可获知新事实；预算耗尽留下缺口，显式核对可恢复有限查询，不重新执行任务 | U1、U6／C5、C8 |
| UI-24 | 必需预览声明、输入或固定投影不完整，或策略版本变更未重新验证 | 不发布可提交控件，不以 purpose 文案猜测依赖；取得当前完整预览依据后才开放 | U1、U5／C4、C6、V2 |

V2 先使用多个有状态模拟设备；模拟通过不代表真机支持。V1 的答案正确性、C4 的 API 覆盖和任务成功率由对应整体评测负责，UI 通过只证明呈现与控制链未破坏这些依据。C8 单独记录时延、存储与流量，不以静态示例或一次手工点击宣称规模达标。

## 3. 已采用的目录、预览与管理合同

UI-P1／P2／P3 已采用。任务／surface 目录与显式订阅、固定中间预览及其输入依赖、身份确认和领域管理分别定义于[接口与存储](contracts-and-storage.md#directory)。普通 UI 输入不代替受信批准或任务管理命令；完整取消答复也须按原任务／执行取消查询取得，不能从当前状态重建。

| 追加验收 | 刺激与预期 |
| --- | --- |
| UI-25 新设备目录 | 丢本端索引后获准分页恢复；查询变化、删项、跨用户和游标超期，不越权枚举、不混合切点；目录缺席明确不完整 |
| UI-26 订阅 | 接纳响应丢失、通知丢失、重连及到期；按原订阅 ID 查询，通知仅触发读取，旧通知不直接创建可显示内容 |
| UI-27 预览绑定 | 截图生成后重启、输入／投影替换、来源撤销、内容到期；任一必需预览无当前获取依据则不转交输入，不把客户端自报已看作为证明 |
| UI-28 受信管理 | 伪造本人批准／补证、管理答复丢失；原领域命令可查；许可、补证接纳、证据核验与任务完成分别呈现 |
| UI-29 暂停与预算 | 动作边界暂停、在途工作未结束、父子暂停来源、恢复响应丢失、未知用量；UI不将暂停等同物理停止，期限继续流逝 |
| UI-30 数据关闭 | UI登记后来源关闭、离线设备未回执、备份残留；立即遮蔽已知失效内容，物理清理保持未完成直到对应依据齐备 |

任务暂停／恢复、预算调整与受信补证已有所属领域合同；整体目标改变新建任务。自动记忆提取只处理 opt-in 成功任务并消费独立用户额度。任意聊天历史同步、多写者界面及跨端已读仍不在当前设计范围。
