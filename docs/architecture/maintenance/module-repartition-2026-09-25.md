## 1. 职责与文档归属

原协作分组同时承载任务委派和各领域共用的消息交付，协议专题又重复展开 UI 行为。本次按事实归属重划三个模块，保留既有接口、消息与业务保证；模块分组不限定进程、部署位置或数据库。

| 内容 | 调整后的权威位置 |
| --- | --- |
| 通用交付、连接路由、流与恢复轮次 | `endpoint-communication/`；连接适配器从全景图 `coordination` 移至 `communication`，其中包含 Delivery 与 Transport |
| Agent 声明、委派合同、子提交及外部任务映射、控制与结果／用量转交 | `agent-coordination/`；`coordination` 保留协作任务端点 |
| 输入转交、完整快照、每端呈现、目录、预览与管理入口 | [UI 交互规范](../application-and-interaction/interaction-contract.md)；本端日志、事务、队列与扫描保留在默认实现篇 |
| 正式任务结果查询 | [任务核心结果契约](../task-kernel/storage-and-interfaces.md#result-recovery)；协议只定义消息映射，UI 按领域事实呈现 |
| 第三方互操作规范 | [独立协议入口](../endpoint-communication/protocol.md)；公共规则、领域规范及机器资产共同构成契约，发布时冻结完整规范引用 |
| 验收责任 | 通用 CO-13～17、CO-19 迁为通信 EC-13～17、EC-19；委派和 UI 矩阵分别保存领域判据，系统矩阵引用各自权威用例 |

架构总览、全景图源文件与导出图、系统验证、提供方依赖及相邻文档链接同步更新。Schema、注册表、消息示例和校验器仍集中在通信目录，领域模块不复制机器资产。

## 2. 语义与异常审查

正常交接分别核对领域保存发送工作、通信接管、目标持久接收、领域提交决定及可靠答复。消息 ACK、业务接纳、效果确认与完整内容交付仍是独立结论。

| 异常场景 | 核对后的责任与结果 |
| --- | --- |
| Delivery 接管或目标接收后丢回执 | 沿原消息、流与位置恢复；领域记录不能被消息去重代替 |
| 子任务已接纳、答复丢失，父随后取消 | 沿原委派及子提交查询，取消责任继续；不创建第二子任务，不释放未知用量，迟到结果不重开父任务 |
| 输入已消费、UI 回执丢失，另一端回应 | UI 沿固定父子操作取得原消费事实；业务权威裁决竞争，普通拒绝与消费冲突分别映射 |
| 用户关窗、重启后收到结果 | 本端意图和每端呈现独立恢复；内容到达不能替代显式打开与展示条件 |
| 流已就绪、授权或控制依据不足 | 领域裁决允许行为，通信组织本轮证据并落实门禁；宿主扫描不建立覆盖它们的全局 ready |

规范与默认实现分别审查：UI 首次转交前必须持久确定唯一父子关联，默认宿主在接纳事务中一起固定；本端串行开闭队列及具体事务组织属于默认实现。协议继续允许能够兑现相同可观察保证的其他实现。
