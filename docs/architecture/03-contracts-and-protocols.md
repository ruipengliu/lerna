# 内部契约与外部协议映射

状态：协议路线、编码分工、全双工消息交付及兼容策略已由用户确认。接口与消息目录见配套分册；尚无协议实现或互操作测试结果。

对应决策：[定义内部契约与外部协议映射](../../.scratch/harness-technical-design/issues/06-protocol-contracts.md)。前置设计：[Go 内核与本地持久化](02-runtime-and-state.md)。外部机制依据：[协议适配边界研究](../research/harness-protocol-contracts.md)；官方来源另见 [协议来源复核](../research/harness-protocol-source-check.md)。规范目标版本在本文锁定；SDK 与 Skill 格式基线已由 [扩展分册](09-extension-contracts-and-activation.md) 固定，生成工具及实际依赖校验值在实现阶段锁定；这些不构成已验证的互操作支持。

## 已确定的职责划分

| 接口领域 | 负责表达什么 | 不承担什么 |
| --- | --- | --- |
| 任务协作 | 提交与委派、状态查询、结果、取消请求及恢复所需关联。 | 不把某次工具返回或网络送达直接认定为整个任务完成。 |
| 能力调用 | 能力声明、输入输出、执行事实、效果核对及能力适用条件。 | 不自行决定用户任务的生命周期或扩大授权。 |
| 记忆访问 | 按范围读取、保存、纠正、删除信息及其来源和用途约束。 | 不将可读取资源自动视为可保存或可同步的长期记忆。 |
| 端云连接 | 节点发现、身份关联、连接状态、消息交付和连接恢复。 | 不因重连或心跳成功便认定任务恢复、执行成功或授权继续有效。 |

四个领域是基础逻辑契约边界，不要求四套独立传输协议。在此之上增加 [用户交互与呈现契约组](03-ui-interaction-contracts.md)，支持端侧多种 UI 形态，并以具名类型、版本、Schema 和能力协商支持后续扩展。它复用基础契约的授权、交付及任务关联，不将所有 UI 交互伪装成执行数据。运行存储接口留在其消费模块内部；不会因为底层 SQLite 可经远程访问，就将数据库操作自动公开为端云协议。

## 已确认的路线

| 设计方面 | 用户决定 | 设计影响 |
| --- | --- | --- |
| 独立契约 | 接受独立于 Go 实现维护 Schema、方法清单、行为说明与一致性测试。 | 公开协议不从内部 Go 类型隐式推导；生成与运行行为分别验证。固定结构以 `.proto` 为准，动态能力参数采用 JSON Schema。 |
| 进程间通信 | 使用 gRPC，兼容后续双工通信需求。 | 进程内继续直接调用 Go Interface；跨进程绑定需支持普通 RPC 和适用的双向流。 |
| 端云通信 | 使用 WebSocket 全双工通道，推送数据和交互事件。 | 端云连接绑定需要明确消息关联、流量管理、断连恢复和请求双方的权限。 |
| 外部生态 | 接受 MCP 工具/资源双向适配、A2A 任务委派与受理、Agent Skills 内容兼容，均按需启用。 | 分方向验证互操作；网络端口和能力暴露必须由配置与授权决定。 |

进程间与端云的范围在此区分为：一个部署侧内部跨进程调用使用 gRPC，端侧与云侧之间的连接使用 WebSocket。端云链路即使两端运行在同一开发机器，也用 WebSocket 完成协议验证；不能因为都在同机就省略端云绑定。未来拓扑可以扩展，此规则不固定记忆、大脑或执行所在位置。

原生 HTTP JSON 加 SSE 的推荐已由用户指定的通信方案替换。外部 MCP、A2A Adapter 仍须遵循各自版本的标准传输绑定，不能将本项目的 gRPC 或 WebSocket 消息直接称为标准 MCP/A2A。

## 契约资产组织

协议资产独立于核心实现，遵守下文编码分工。目录名属于规划，不代表已创建协议代码。

| 规划资产 | 用途 |
| --- | --- |
| `contracts/common/` | 标识、关联、错误、结果确定性及版本声明等共用数据结构。 |
| `contracts/tasks/` | 任务协作的数据结构、操作清单和行为约束。 |
| `contracts/capabilities/` | 能力调用、观察与效果确认的共用契约。 |
| `contracts/memory/` | 记忆访问契约；业务数据模型由记忆分册细化。 |
| `contracts/connections/` | 节点能力、连接及交付契约。 |
| `contracts/interactions/` | 端侧 UI 呈现、用户动作、等待输入、状态恢复和扩展类型契约。 |
| `contracts/bindings/` | gRPC 与 WebSocket 的方法、错误、事件、流及传输映射规则。 |
| `conformance/` | 复用的输入、预期行为、异常场景及各版本和能力组合的测试清单。 |

结构约束和行为约束分别表达：Schema 可检查字段是否合法，一致性用例检查消息顺序、错误、重复处理、授权和取消等可观察行为。生成出来的 Go 类型不能单独证明行为兼容。

JSON 载荷的大整数、二进制产物、时间、可空字段及未知枚举等规则见 [接口与消息目录](03-contract-message-catalog.md)。业务内部类型可以更丰富，但必须通过显式映射进入公开契约，不能泄露数据库对象或框架对象。

## 内部原生契约与外部 Adapter 的关系

双向适配方向及规范目标版本已确认；参考传输与支持范围见配套接口目录，实现须独立验证。

| 入口或出口 | 适配职责 | 必须保留的项目语义 |
| --- | --- | --- |
| MCP 客户端 | 将外部工具和资源转换为可声明、可调用的能力。 | 工具响应、动作是否发生、效果是否确认分别记录；资源读取不自动保存为长期记忆。 |
| MCP 服务端 | 将显式选择的 Harness 能力或资源映射给外部调用者。 | 按调用者授权控制暴露范围；内核存储与任意终态写入不对外开放。 |
| A2A 客户端 | 向外部 Agent 委派任务，将远端更新转换为本地任务事实。 | 内部任务标识与远端句柄分别保存；外部状态由内核校验后使用。 |
| A2A 服务端 | 受理外部 Agent 请求，经 Harness 入口建立和管理任务。 | 身份、权限、取消、期限和最终结果仍受内核规则约束。 |
| Agent Skills 内容加载 | 读取开放内容格式并转换为宿主可使用的知识与流程。 | Skill 内容不自行授予工具权限；安装、隔离、依赖和发布由扩展生命周期设计处理。 |

双向 Adapter 指提供入站服务和出站调用两种角色，不等于同一外部协议连接支持任意双向 RPC；原生 gRPC/WebSocket 的全双工能力不改变外部标准规则。原生端云连接不自动使用 MCP 或 A2A 承担全部节点控制。外部标准可以复用，但只有存在明确的字段和行为映射时才能宣称兼容；缺失的授权或结果核对语义必须声明，不能默认为已经满足。

## 用故障检查适配是否完整

用“远端已执行动作，响应丢失，随后事件流断开”检查协议：

1. 本地任务、执行类操作、应用消息和远端句柄分别关联；调用以 operation_id 标识，请求以 message_id 关联，不再单独引出 invocation_id 和 request_id。重发请求不必然代表新的逻辑动作。
2. 断流只证明连接中断，不能证明动作没发生、任务已停止或当前授权已撤销。
3. 重连后依据查询或核对接口取得状态；无查询能力、句柄已过期或效果无法确认时保留不确定结果。
4. 是否允许再次执行由内核根据能力和授权决定，不能让传输 Adapter 盲目重试有副作用的调用。
5. Harness 原生 WebSocket 和 gRPC 流须定义各自的恢复规则，但不能把这些规则套用到外部 MCP 或 A2A 的标准接口。

这些约束沿用已确认的运行和执行目标。重连、重复消息及所有权的完整算法由端云恢复分册细化。

## 编码、通道与兼容策略

用户已接受固定结构与动态参数分工、消息分级交付和按版本及能力组合管理兼容性。

### 固定协议结构与动态能力参数分别定义

`.proto` 作为固定消息、公共错误、服务方法及流消息的唯一结构定义来源，生成 Go 及其他语言的传输类型。gRPC 使用相应服务，WebSocket 使用同一批消息类型的 Protobuf 二进制编码，并增加明确的消息种类与关联信封。信封结构也在 `.proto` 定义。

JSON Schema 用于插件、工具、Skill 和 UI 扩展的动态输入输出。能力声明以 Schema 标识、版本和内容摘要绑定其动态载荷，调用时按声明校验。固定协议字段不另外手写一份等价 JSON Schema，避免字段编号、缺省值或类型发生漂移。

动态 JSON 载荷以受 Schema 约束的 UTF-8 字节装入消息，大小受协商上限约束，不能把任意 JSON 无检查地透传。调试 JSON 仅作视图，不作为第二套线协议；大整数和字段缺省按所选映射规则处理。

固定 Protobuf 消息提供统一扩展载荷容器，以具名类型、版本、Schema 引用及受校验数据承载自定义 UI 或其他应用消息。新组件及事件通过注册实现和声明能力接入，不要求不断扩充 Envelope 顶层 oneof；未知必需类型明确拒绝。

这项分工由独立协议资产驱动，行为说明与一致性测试约束两种传输。固定结构不维护 JSON Schema 到 Protobuf 的双向同步生成器。

### 全双工通道按可靠性需要分类

同一连接内定义逻辑流和关联消息，允许双方发起已授权的请求、发送响应与推送事件。不同消息采用明确的交付约束：

| 消息类别 | 交付与恢复规则 |
| --- | --- |
| 任务指令、取消或接管请求、最终结果、必要的交互输入 | 发送前持久化，接收后以持久化回执确认，允许带相同业务标识重复交付；应用层去重，断连后核对并补发。 |
| 可替换的进度、临时预览、设备实时状态 | 能力契约显式标注为临时更新后允许合并或丢弃；重连取得新快照。若用于结果判断或审计，应先升级为需保存的证据。 |
| 大产物与连续数据 | 使用受限分块或可授权读取的产物引用，限制大小、并发和队列；必要控制消息保留发送预算。 |

收到消息、接收方已持久化、动作已执行和效果已确认是不同事实。可靠消息交付可重复，不等于外部动作恰好执行一次；去重、查询和未知结果处理仍执行内核既定契约。

每个逻辑流使用关联标识和序号，描述本流的顺序与缺口；不承诺跨流全局顺序。gRPC 的一次双向流与 WebSocket 连接都不能替代持久化收发记录。关闭连接或流不自动取消业务任务，取消和用户接管有独立请求及结果表达。

流量管理包括有界待发送队列、每流额度和公平调度；队列已满应表达背压，不能无限积压。可靠控制消息不能按临时进度的规则被丢弃。单连接中已经排队的传输字节仍可能造成阻塞，逻辑优先级不构成零延迟保证；大数据应限制分块尺寸，并允许后续按契约使用独立数据连接或产物引用。

在本票中确定这些可观察语义；重连游标、回执保留、节点所有权及旧连接失效的具体算法由端云恢复分册设计。

### 按版本与能力组合声明兼容性

内部契约使用主版本加明确能力集。破坏兼容性的消息或行为变更升级主版本；新增可选行为通过能力协商启用，缺少必需能力时显式拒绝，不能静默降级授权、持久化或结果核对要求。编码能解析不代表行为兼容。

连接级发现与协商用于建立可用配置；每次操作仍关联具体能力版本和有效授权。协议版本、能力版本及授权是不同维度，协商成功不代表对所有操作有权限。

外部参考目标固定到已核验的 MCP `2026-07-28`、A2A 协议 `1.0`；Agent Skills 使用可追溯的格式快照。具体 SDK 基线已单独锁定，严格版本选择、取消及媒体类型等适配仍须实现并测试，不因规范已发布便宣称 SDK 已覆盖。旧协议版本通过独立 Adapter 和测试矩阵增加，不自动兼容全部历史版本。

MCP Tasks 参考首期不启用；此类可选扩展后续单独声明和验收，未支持时按实际能力表达；不能把异步能力缺失隐藏为长期占用一个同步请求。A2A 的幂等、流式更新和推送也按对端声明与测试结果启用。该策略不要求第一版启用所有可选扩展。

## 外部证据与验证边界

[协议来源复核](../research/harness-protocol-source-check.md) 保存已核验的版本与规范依据。此前的 HTTP/SSE 研究保留作历史候选和外部适配参考，不构成内部默认绑定。复核已补充 gRPC 双向流、Protobuf 表达及兼容性、WebSocket 双向发送与异常重连的官方依据；协议内建的流式能力不能代替 Harness 的恢复和授权契约。尚未验证具体 SDK 或消息实现。

## 接口与一致性要求

[接口与消息目录](03-contract-message-catalog.md) 定义原生服务、公共标识、WebSocket 信封、错误与结果、协商及消息示例，供 `.proto` 和 SDK 实现使用。[标识模型简化评估](03-identifier-model.md) 将执行类调用并入 Operation 身份、请求关联并入 Message 身份；内部 `ChangeID` 继续独立，对外协议不暴露任意存储写入入口。

UI 扩展必须验证不同模拟端的组件能力、多窗口路由、无任务交互、快照与增量恢复、重复提交及未知类型处理，详见 [UI 交互分册](03-ui-interaction-contracts.md)。UI 呈现回报不代表用户确认或业务执行完成。

一致性验收至少包括：结构验证、版本与能力协商、操作权限、消息关联、重复提交、持久化确认、结果未知、取消竞态、流控、游标过期及外部状态映射。进程内、gRPC 与 WebSocket 使用共同业务用例，再分别验证传输特有的失败路径。配套目录列出详细矩阵；所有运行验证当前均为未执行。
