# 设计选择与适用条件

本章解释本方案为什么采用这些模块和机制，以及什么证据会促使重新选择。以下条目是本次架构设计的决定，不代表已经实现或通过性能验证。外部研究只提供候选机制和失败边界；工程证据仍由 Lerna 自己取得。

## 任务语义内核与可替换策略分开

**选择。** Task、授权、预算、效果和完成依据由稳定领域合同约束；决策引擎、上下文、记忆检索、计划和协作策略允许替换。默认单任务控制者组织有界决策循环。

**理由。** 更换推理算法不应改变“取消是否已接纳”或“写入是否发生”的含义。应用接入者需要稳定控制接口，研究者需要独立改变策略的空间。多 Agent 研究显示协作收益随任务结构变化，因此本方案将协作作为策略选择。[一手研究](https://arxiv.org/abs/2512.08296v3)

**代价与重选条件。** 内核必须维护目标版本、准入和完成门禁，接口约束比普通工具循环多。如果简单应用必须理解大量内部状态才能完成接入，应压缩应用接口；不能为减少接口而取消真实责任记录。

## 共用持久工作机制并保留领域阶段

**选择。** 默认以 PostgreSQL 的短事务和 JobStore 共提交事实与工作责任，设备使用 SQLite 适配。公共模板统一接纳、领取与条件提交，领域模块维护发送、核对和完成阶段。

**理由。** Task、权限和预算的关键裁决可以在一个明确数据库范围内完成，同时减少首版所需运维系统。持久引擎可以复用已记录的步骤，但外部效果仍需幂等或核对；因此效果模型不能交给通用任务重试机制推导。[Temporal Activity 官方说明](https://docs.temporal.io/activity-definition)

**备选。** Temporal、LangGraph 或其他持久引擎可用于组件内部，也可在独立评估后实现适用宿主接口。将其作为全局必需引擎会引入额外部署、事务交接与端侧适配成本；仅共享少量原语则会让各模块重复实现并发故障分支。

**重选条件。** 实测队列维护、定时器规模、历史恢复或运维成本超过当前方案可接受范围，且替代引擎能保持原身份、事务和效果合同。多数模块绕过工作模板时，应先收缩模板。

## 明确记录未知效果

**选择。** Effect 与 may_apply_later 分开；超时后沿原 Operation 查询，未知状态阻止同义盲目重做。取消和补偿也是有业务含义的行动。

**理由。** 外部动作与本地结果入库之间存在崩溃窗口。检查点或任务重放不能消除这个窗口。LangGraph 官方文档同样要求为可能重复的副作用采用幂等或核对。[官方说明](https://docs.langchain.com/oss/python/langgraph/functional-api)

**代价与重选条件。** 无查询或幂等能力的工具会留下需要人工处理的未知状态。可以优先选择保证更强的目标 API；不能用自动重试掩盖目标不提供的保证。只有目标系统明确参与同一原子协议时，才考虑收紧相应能力的保证。

## 目标与对话分离

**选择。** Session 管理输入和呈现，Task 管理目标与执行责任。一段对话可包含多个目标，任务可以跨越多轮交互与客户端连接。

**理由。** 用户离开界面后任务仍可能执行，用户返回时也可能修订目标。分离后，应用不需要维持一条永不结束的聊天请求来托管长任务。

**代价。** 应用必须区分输入已保存、业务已接纳和目标已完成。SDK 负责恢复投递与映射，UI 负责解释不同状态。若产品只有一次性无副作用问答，可通过更窄的应用封装使用同一内核，不必暴露完整会话能力。

## 固定逻辑负责方并独立伸缩工作者

**选择。** Task 固定 Orchestrator owner，服务进程与 worker 可以更换；默认云端保存 Task 权威，设备保存本机执行。新任务可以选择新 owner，原命令不得在未知时改投。

**理由。** 去重、控制与完成需要可定位的权威。将任务身份绑定某台进程会妨碍恢复；无约束地迁移权威又会扩大并发裁决范围。

**代价与重选条件。** 需要受信发现、来源目录和分片容量管理。确有热点迁移需求时设计独立迁移协议，证明旧写端已隔离并保留原身份；不能以重新创建 Task 代替迁移。

## 使用准确内容引用与可重建检索

**选择。** Content 保存准确版本字节，Memory 保存可复用语义与来源，Snapshot 固定每次决策实际使用的材料。检索投影可以替换或重建，长期保存许可独立裁决。

**理由。** 同一段历史可能有原始观察、摘要和后续更正，不宜混成一个可任意改写的提示字符串。近期记忆研究考察环境变化与经验适用性，支持把来源和时间放入接口，但并未证明某种索引普遍最好。[LongMemEval-V2](https://arxiv.org/abs/2605.12493v1)

**代价与重选条件。** 来源与 holder 记录增加写入和清理成本。可以按实际保留政策减少副本或正文，但不能保留“证据可核验”的声明同时清除其唯一依据。是否默认向量检索由固定任务集的累计成本和质量决定。

## 决策预算可感知且由内核强制执行

**选择。** Snapshot 含剩余预算与期限；模型、工具和委派在启动前预留，按实际累计用量结算。核验与必要收尾保留有限额度。

**理由。** 模型需要知道何时停止探索和保留验证成本，但提示词不能执行硬限额。预算感知研究提供了可评测的策略方向，本设计另用领域账本约束实际消费。[预算感知工具使用研究](https://arxiv.org/abs/2511.17006v2)

**代价。** 无可信收费上界或原用量查询的供应商限制自动运行范围。该限制不能通过把费用估算成零解除；可以接入供应商硬限额或选择保证更明确的服务。

## 公共协议与外部生态协议分离

**选择。** Lerna 的 Application、Component 合同维护任务与效果语义，MCP 和 A2A 通过适配器连接。端云使用 WSS，内部使用 gRPC，字节内容使用 HTTPS。

**理由。** 外部协议负责互通，其 Task、取消和完成含义与本地目标不必相同。版本升级也可能改变协议会话与交互方式。Lerna 应适配这些变化，不能把它们直接写成内部权威状态。

**代价与重选条件。** 维护转译与兼容测试，承担 WSS 流控及重连成本。只有公开协议能完整表达并验证本项目所需语义时，才考虑减少包装；不能仅凭名称相似合并状态。

## 版本发布不改变在途工作的含义

**选择。** InstallLock、发布批准和实例就绪分别保存；新工作使用新绑定，旧工作保持准确版本或经过显式迁移。回退需要旧版独立有效批准，不倒退业务数据。

**理由。** 插件升级可能改变参数、效果和数据格式，而运行中的任务仍需核对原动作。将“最新同名组件”用于旧记录会使恢复失去确定含义。

**代价。** 必须保留旧查询能力、holder 和兼容接管路径。供应商模型无法固定真实内部版本时记录可取得的版本与限制，不能声称完全可重现。

## 用业务效果和故障证据评价先进性

**选择。** 所有优化都在固定任务、模型、工具、数据与预算下比较；同时检查正确性、成本、耗时、错误外部效果和恢复。自进化产物经过用途授权、验证与受控发布。

**理由。** 更多 Agent、更大上下文或更多工具调用会改变成本与失败机会。先进性需要表现为指定范围内更可靠或更有效的任务结果，不能由机制数量或论文名目代替。

**代价与重选条件。** 需要独立验收集、真实目标状态和重复实验。某策略没有净收益时保持可选或停用；不能为维护既有投入临时放宽评测门槛。

## 当前不扩大建设范围的事项

第一版不建设通用 DAG 平台、全局事件总线、自动跨分片任务迁移、任意程序栈恢复、无限自治循环或自动发布内核代码。有限计划、周期触发、向量检索、递归推理和复杂协作按实际场景逐项开放。

这些范围限制不免除首版分布式恢复、授权、预算和效果核验。新增能力必须有独立使用者、清晰负责方及可验证的收益，避免把一次说明或实验扩展成必须运维的新系统。
