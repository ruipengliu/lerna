# 上下文、记忆与同步

状态：已确认。覆盖记忆模型、上下文组织、集合修改权威、纠正删除、同步恢复，以及端云数据驻留、联合检索和端侧挖掘。

决策依据：[确定上下文、记忆与同步的数据模型](../../.scratch/harness-technical-design/issues/08-memory-context.md)。

## 已确认约束

- 任务上下文服务当前任务；长期记忆在授权范围内跨任务复用。读取、提取、保存和同步分别检查权限。
- 运行状态和执行记录由内核管理，摘要不能替代动作事实或恢复依据。
- 事实、偏好、推断和经验必须能区分，保留来源、适用范围，并支持用户纠正、删除和用途限制。
- 开发期以 Go 和 SQLite 等无独立外部服务依赖的组件完整运行，按 Interface 依赖并可替换 Implementation。
- 沿用 MemoryService 的 Query/Get/Put/Correct/Delete 语义；独立记忆存储按同一 operation_id 幂等受理并支持结果查询，不能假设与 RunStore 有跨库事务。
- 同步经过既定 gRPC/WebSocket 绑定；连接恢复不等于数据已同步，可靠传输不决定记忆冲突如何裁决。

## 已确认：数据责任与记录表达

以下是逻辑责任划分，不要求分库或分进程，也不为每一类关系新建全局身份。

| 对象 | 表达 | 不承担的责任 |
| --- | --- | --- |
| 运行状态与执行记录 | 引用内核的 task_ref、operation_id 及相应版本/结果。 | 不以记忆条目覆盖任务权威或动作事实。 |
| 任务上下文 | 当前任务选择的内容、带版本的来源引用、预算与组织结果；必要工作信息按任务恢复需要保存。 | 不因持久化恢复需要就取得跨任务复用权限。 |
| 长期记忆 | 一种带类型和版本的记录模型，区分事实、偏好、推断、经验；动态内容使用已登记 Schema。 | 不为每种记忆固定一套服务、表或进程；不把模型推断自动当成事实。 |
| 证据与产物 | 原始材料及生成内容的受控引用，携带来源位置、获取/生成时间、媒体类型与可用状态；大内容按需另存。 | 不因被引用而自动转成长期记忆；产物本身不必然是事实证据。 |
| 检索索引与摘要 | 从获准使用的记录派生，保留输入引用和生成版本，可失效、重建。 | 不成为唯一事实记录，不获得超过来源的可见范围或用途。 |

长期记忆的固定元数据至少表达以下语义。字段与存储细化见下文关联分册。

- **身份及版本**：作用域内稳定记录引用与修订版本；不同修订沿用记录身份，操作引用说明由哪次变更产生。
- **语义**：信息类型、内容 Schema 及版本、描述对象和适用条件。用户明确表达与模型推断使用不同来源属性。
- **来源**：来源引用、来源修订、提取或生成方式、记录时间；适用时另记事实发生时间和有效区间，不能混用时间含义。
- **置信度**：保留置信判断及其依据、评估方式和适用范围；未知时显式标注，不把不同模型或来源的分数直接当作同一尺度。
- **控制**：可使用主体/用途、保留期限及同步范围的策略引用；策略引用不是授权凭证。
- **生命周期**：可用、已被纠正或已删除等可观察状态，修订关系与必要的来源依赖。旧内容保留受策略限制，不承诺永久版本历史。

同一对象存在多条相互矛盾的观察时保留来源差异；相同实体或相似文本不自动表示同一条记录。纠正具体记录和裁决不同来源的主张是不同动作。类型表达信息性质，不能仅用一个置信分数替代证据。

此方案的代价是必须维护版本、来源和派生依赖；收益是各类记忆共用访问与治理契约，仍可扩展领域内容。若采用无结构文本库，这些责任会散落到大脑和调用方；若每类记忆分别建系统，则扩展与迁移负担更大。

## 已确认：检索与上下文组织

记忆检索与上下文组装分开：记忆系统返回受控候选及来源，大脑使用组装结果决策，组装策略可替换。它们可以运行在同一进程中。

1. 输入明确任务目标、用途、允许范围及内容预算，按当前授权限制候选范围。
2. 参考实现支持元数据过滤与文本检索；排序使用可解释的适用性、来源及时间信息，语义检索和重排可由 Adapter 增强。
3. 组装时保留目标、约束、关键运行事实以及完成判断所需的证据；为相关记忆与长内容分配有界预算。
4. 摘要或压缩结果携带来源修订，事实与推断保持区别。内容不足、被裁剪、来源失效和矛盾信息必须可观察。
5. 交付大脑前复核来源可用性及用途；保留选入、排除和裁剪原因的最小记录。源内容不获准保留时，不能以诊断或重放为由偷偷保存副本。

参考检索与组装不强制依赖 Embedding 服务或向量数据库；这不意味着只验收关键词命中。必须验证适用的个性化信息实际影响应答或执行，并覆盖冲突、删除、用途限制及无相关信息的情况。不同检索实现的效果可比较，正确性和授权契约共用。

可复查的上下文组装不承诺模型输出完全可复现。若必要约束无法装入预算，应报告不足或请求缩小输入，不能静默丢弃约束后继续执行。预算、摘要失效与 Interface 的细化见 [数据契约与生命周期](05-memory-data-and-lifecycle.md)，其中生命周期与恢复策略已确认。

此方案优先满足单机运行、可替换和可验证性；初始语义召回效果可能弱于专用检索实现，需要用能力评测识别差距。

## 已确认：同步与修改权威

按记忆集合划分修改权威，每个集合有一个负责提交正式修订的逻辑权威；其位置可在端侧或云侧，不等同于任务拥有者。同一部署可有多个集合分别由不同节点负责。

- 本地集合可在本地授权范围内独立读写；共享集合向其权威提交修改。
- 同步选择获得授权的集合/记录及字段范围，不默认复制所有上下文、原始材料或 UI 草稿。接收方仍需检查用途和访问权限。
- 非权威副本离线时可读取仍获准且新鲜度满足用途的缓存；修改作为有稳定操作身份和基础版本的待提交意图保存，不能显示为共享记录已经正式更新。
- 重连时先核对权限、操作受理结果和记录版本，再提交或返回冲突。两个节点基于同一旧版本修改同一记录时，默认不按设备时间静默覆盖，也不自动让模型合并。
- 离线草稿可以呈现给用户；若任务要使用尚未提交的内容，应以明确的临时输入和来源处理，不冒充已经收敛的共享记忆。
- 需要同步协议表达修订、游标、快照以及删除传播。引用被同步不表示其指向的原始内容也获准同步；接收方须能表达来源不可访问。

该方案牺牲非权威副本断连时的正式写入可用性，换取清楚的冲突和纠正删除语义。集合权威默认不可自动抢占；后续若需要迁移，必须另行定义封存和激活过程，不能直接照搬任务字段。多主写入可以作为未来扩展，但需独立声明合并、因果与删除规则并验证，不能宣称当前基线已经支持。

## 端云数据驻留、联合检索与端侧挖掘

用户已明确：部分重要隐私数据不能全部上云，但仍需可检索；端侧数据也需被挖掘，必须明确哪些数据保留在端、哪些可以存入云。

因此需分别表达数据存放位置、允许计算位置、可被远端发现的范围以及允许返回的结果。记忆修改权威只决定正式修订由谁提交，不能替代这些约束。端侧数据可由端侧完成检索与提取，不以复制到云端为前提。

[端云记忆驻留与联合检索](05-edge-cloud-memory.md) 给出已确认的数据分类矩阵、跨端查询流程、端侧挖掘及存储策略。原文、元数据、索引、派生内容及备份分别约束，查询或挖掘不隐式扩大外发范围。

授权材料和可信时间由授权分册负责；大脑循环和改进发布遵循数据允许的计算和结果披露范围，由对应后续分册细化。
