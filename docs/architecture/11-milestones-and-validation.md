# 能力里程碑与实施依赖

状态：四阶段、成熟度目标、独立替换、专项数值、第二持久化参考实现、迁移及实施交接均已确认；没有代码、运行结果或已达成的里程碑。

目标：[项目目标基线](../harness-project-goals.md)。设计入口：[架构总览](README.md)。决策过程：[确定能力里程碑与实施依赖](../../.scratch/harness-technical-design/issues/14-implementation-milestones.md)。本文沿用 L1–L4 的既定定义，不以项目阶段代替每项能力的实际成熟度。

## 已确认的前提

- 面向通用开源 Harness，C1–C9 各有独立契约与证据；A1–A4 和 V1–V2 另外验收。手机与电脑协作仅可作为组合示例。
- Go、SQLite 单机完整运行，模块依接口替换；多模拟设备及实际 gRPC/WebSocket 链路验证跨端，无真机要求。外部模型和联网是能力需要的外部调用，不是必需部署的数据库或工作流集群。
- API 为主要执行路径，GUI 为适用兜底。超过 1000 个独立 API 与 90% / 95% 质量目标，样本、预算、统计与发布规则已由 [评测分册](10-evaluation-contracts-and-release-gates.md) 固定。
- 关键授权、隐私、稳定操作及未知效果处理从对应执行入口的首个实现开始生效；不能因为完整 L4 验证安排在后期，就先允许无授权写入或自动重复未知动作。
- 代码生成、契约测试通过、真实模型质量、实际联网、模拟设备和不同后端耐久性分别留证，不用一种证据替代另一种。

## 四个按能力验收的阶段

| 阶段 | 本阶段结果 | 完成条件与发布含义 |
| --- | --- | --- |
| M1 契约与验证基础 | 可版本化的领域接口、协议/Schema、夹具与实施骨架；三系统和内核职责可对应到模块。 | C1–C9 的 L1 证据齐备；夹具定义正常、错误、权限和恢复断言，记录后续运行命令及支持范围。可公开设计和开发资料，不声明已能完整执行任务。 |
| M2 单机参考能力 | 三系统默认实现、SQLite 持久化、有限任务循环、工具/模拟设备、基本扩展接入、用户控制和评测报告能运行。 | C1–C8 达 L2，C9 保持 L1 并准备候选/发布接口。覆盖问答、API、GUI、个性化、内部/外部 Agent 及端云基础协作；为开发预览，完整质量与自进化尚未验收。 |
| M3 独立替换与互操作 | 三系统及关键 Adapter 以独立实现替换，真实协议边界、多节点部署和第二持久化后端完成验证；自进化流程可运行。 | C1–C8 达 L3，C9 达 L2。不能把两种配置、内存替身或同一个实现套两层包装计成独立替换。发布可扩展预览及 SDK/一致性套件。 |
| M4 完整质量、恢复与治理 | 全量质量基准、专项能力、故障/隐私/控制矩阵、自进化实际改善与发布回滚证据齐备。 | C1–C9 在声明范围内达 L4，A1–A4 和 V1–V2 均通过。具备首个完整参考发布资格；不暗示全部设备平台、所有外部供应商或真实生产容量均获支持。 |

上述是依赖与验收阶段，不预填无人员/运行依据的日期。阶段可以提前开发后续工作，但必须先满足依赖和验证条件，不能按代码量或日历自动晋级。完整参考系统在单机上可运行，M3 的跨端模拟进程可以同机部署。

| 通用能力 | M1 | M2 | M3 | M4 |
| --- | --- | --- | --- | --- |
| C1 任务理解、规划与决策 | L1 | L2 | L3 | L4 |
| C2 上下文、记忆与个性化 | L1 | L2 | L3 | L4 |
| C3 信息获取与证据处理 | L1 | L2 | L3 | L4 |
| C4 工具调用与设备操作 | L1 | L2 | L3 | L4 |
| C5 任务运行与端云协同 | L1 | L2 | L3 | L4 |
| C6 扩展接入与协议互操作 | L1 | L2 | L3 | L4 |
| C7 授权与用户控制 | L1 | L2 | L3 | L4 |
| C8 运行观测与能力评测 | L1 | L2 | L3 | L4 |
| C9 受控自进化 | L1 | L1 | L2 | L4，包含 L3 的改进产物互操作证据 |

表中全部是目标等级，实际等级必须由逐项报告填入。L4 保留之前等级的要求，不能只跑故障测试跳过参考实现与替换验证。C9 的流程演示可用受控候选验证机制；M4 则必须有同条件基线、有效评分和实际改善，不能把流程可执行当作效果证据。

## 替换验证进入发布依赖

每个声明已通过替换验收的 Interface 应有共同测试入口，至少一个与参考实现独立构建的适用替代实现；本阶段必需范围为三系统及下表中的关键 Adapter。分别记录被替换对象、共同契约、差异能力和验证位置；不将更换模型供应商直接算作更换 Brain，不将换数据库直接算作全部 Memory 策略替换。

| 替换或互操作方面 | 必需证据 |
| --- | --- |
| Brain 与 Model | 两种实际决策策略分别经 Brain 契约，模型 Adapter 的能力/结构化输出/位置差异单列；同一任务内核与授权仍有效。 |
| Memory 与持久化 | 记忆访问/组织实现经共同契约；SQLite 与第二持久后端独立承担适用 Store 的原子、快照、重启及迁移验证，内存实现仅用于基础测试。 |
| Execution 与设备 | 两种独立 API Adapter、结构树与图像观察驱动，共同验证动作、结果及差异；模拟设备保持独立有状态对象。 |
| 信息获取 | 搜索与内容获取 Adapter 分别有可替换实现，实际取得来源、时间、失败及证据缺口可核对；固定资料重放与真实联网分开。 |
| 原生协议与 UI | 进程内、gRPC 和 WebSocket 经共同业务用例及各自故障路径；多模拟端、多个 UI surface、自定义类型/事件、无任务交互、快照恢复与重复输入。 |
| 外部生态 | MCP stdio/Streamable HTTP、A2A HTTP+JSON 的入站与出站分别验证；独立对端或一致性夹具不能仅与同一 Adapter 自连。Skill 内容与脚本执行、Wasm 限制、Renderer 兼容分别报告。 |
| 治理与评测 | 不同组件接入统一观测/评测，评分器替换可比较范围明确；改进产物在兼容组件中使用，授权和发布边界不变。 |

第二持久化后端必须进入 M3 的实际验证路径，不能留作无期限的“未来可替换”。默认开发与完整运行继续 SQLite；额外后端用于证明独立实现、耐久性和数据交接，已确认采用 bbolt v1.5.0 验证独立持久化，官方依据见 [第二持久后端研究](../research/harness-second-persistent-backend.md)，同机停写双向迁移与故障验证见 [专项与实施分册](11-specialized-validation-and-handoff.md)。

迁移验证至少覆盖停止准入、在途处置、稳定快照/变更交接、引用与版本校验、切换及失败恢复；迁移不消除原操作、授权消费或删除水位。备份回滚和身份克隆按既有隔离规则处理，不能借“新后端”重新执行旧写操作。实际支持的迁移方向与可逆条件须列明。

## 完整质量与专项结果分别放行

千级 API 完整基准从 M2 就可以增量试跑，M4 才能依据已确认完整计划声明达标。开发快速回归可用小集合，但报告清楚标注覆盖不足；不能以子集达到 90% / 95% 冒充完整目录验收。

联网问答、GUI 与个性化从 M2 提供运行证据、M3 验证相关实现替换、M4 完成独立质量及控制验收。三项分别固定数据集、结果真值、预算和门槛，不能靠同一手机/电脑场景演示互相代替。专项样本、预算和门槛已保存在 [专项验收分册](11-specialized-validation-and-handoff.md)，各组分别判定，不以 API 分数替代。

| 维度 | 必须独立体现的结果 |
| --- | --- |
| V1 联网问答 | 固定资料集与实际联网两组；可回答、证据不足、冲突与获取失败分别计分。核验关键事实、引用支持、获取时间和失败表达，真实联网不能以录制响应替代。 |
| V2 手机 GUI | 全部必需动作和观察/接管断言；真实模型在模拟 UI 的结构树/图像输入上选择动作并验证业务效果。错误副作用、陈旧观察及不合法 API 兜底不能被最终成功覆盖。 |
| C2 个性化 | 适用信息实际改变回答或行动；不适用、过期、冲突、删除和禁止披露条件正确处置。成对对照分别使用允许的上下文，缺少权限不能凭测试便利上传端侧内容。 |
| C9 自进化 | 完整候选/验证/保留确认/激活/监测/回滚流程，以及实际改善证据。只有失败候选或不足以比较的结果时保留未通过，不能为了完成里程碑降低门槛。 |

## 实施按依赖展开，证据贯穿各阶段

| 工作组 | 可开始的条件 | 交付和后续依赖 |
| --- | --- | --- |
| 契约、构建与测试骨架 | 已确认架构 | Go 包与 Proto/Schema、规范测试清单、可调用夹具、版本锁定与单机启动约定；为后续实现提供固定接口。 |
| 持久运行与授权底座 | 固定状态/操作/授权契约 | RunStore/ExecutionStore 等原子提交、任务准入、操作核对、身份、授权、凭证和恢复；动作执行须先依赖这组约束。 |
| 三系统与基础交互 | 相应底座和夹具可用 | Brain/Model、Memory/Context、API/GUI 驱动、信息获取和 UI；可按接口分工并行，但协作准入使用同一内核。 |
| 跨节点与扩展生态 | 本地契约路径可运行 | 真实传输绑定、端云恢复、联邦记忆、外部 Agent/工具、扩展激活、独立后端和替换验证。 |
| 观测、评测与数据 | 记录/评分接口确定即可建设，完整运行依赖相应能力 | 从前期构建判定器和数据生成/核验工具；后续接真实模型、完整目录、专项和统计验证。不能到最后才编写判分规则。 |
| 受控改进与发布 | 评测证据可追溯、权限和扩展激活可用 | 候选隔离、保留确认、阶段控制、监测与回滚；最终实际改善依赖完整可比较基线。 |
| 完整验收与开源维护交接 | 各组适用证据齐备 | 能力矩阵、参考部署、SDK 示例、支持范围、升级/迁移说明、贡献及兼容性检查入口。 |

对开发人员可并行的工作组是实现依赖安排，不等同当前会话启动多个实现任务。当前授权只编写方案和决策文档，不生成业务代码或安排部署。

## 统一验收报告和支持范围

每项能力报告至少包括目标/实际成熟度、实现及依赖版本、操作系统/架构、部署拓扑、测试计划/数据集、模型配置、预算、结果/原始证据引用与已知限制。状态区分未实现、未运行、通过、失败、不适用/不支持、证据不完整；缺失不能默认为通过。

| 架构约束 | 跨阶段的证据要求 |
| --- | --- |
| A1 逻辑职责 | 依赖检查与运行事实证明 Brain 提案、Execution 报告、Memory 访问及 Core 状态推进分工成立；扩展不能取得任意终态写入权。 |
| A2 默认与替换 | 单机默认实现可运行，M3 有不同实现共同契约和持久化证据，M4 更换后仍保持运行与质量边界。 |
| A3 端云位置 | 模拟不同节点部署与交换三系统位置，跨节点检索/推理/执行、离线与协作移交实际运行；不强制真实设备。 |
| A4 契约与授权 | 四领域、UI 扩展及管理操作沿共同准入；委派、撤销、隐私出口和版本错误在各实现及传输中实际拒绝。 |

最终参考发布同时满足 C1–C9、A1–A4、V1–V2，而非先宣称通用完成、再把关键缺口留给示例开发者。更强隔离后端、额外设备平台、自动接管、外部密钥设施及可选外部协议扩展按独立支持范围记录，不因默认实现通过就自动获得支持标记。

M1 起即可公开文档、规范和开发资料；M4 是“完整参考能力通过”的技术门槛，不表示此前禁止开源，也不代替维护者执行发布操作。实际日历、人员和模型调用费用在实施排期时根据试跑测量安排；现阶段不凭空承诺工期或成本。

## 设计完成与实施验证边界

[专项验收、持久化替换与实施交接](11-specialized-validation-and-handoff.md) 已明确专项数值、第二持久后端、停写双向迁移与后续工作包。当前技术方案具备拆分实施任务所需的职责、接口、依赖、失败语义和验收条件；设计定稿不等于 M1–M4 已完成。

| 实施时仍需取得的证据 | 既定验证入口 | 不满足时的处理 |
| --- | --- | --- |
| 库配置、协议适配、生成工具与实际平台兼容 | 锁定构建环境和依赖；按原生/外部方向与特性执行共同矩阵。 | 不标记相应支持；保持协议目标和权限边界，针对可复现缺口修复或新建设计问题。 |
| 数据库、文件系统及备份/迁移的耐久性 | SQLite/bbolt 共同故障套件，含同步错误、结果不明、切换和旧备份隔离。 | 停止不可靠的新变更，保留回执与恢复水位；不得以缓存可读宣称耐久成功。 |
| 模型质量、实际联网、GUI 和个性化 | 完整 API 与各专项 profile、真实模型、独立真值和有状态环境。 | 按原计划报告失败/不完整，不删样本、放宽预算或代换场景来完成阶段。 |
| 统计适用性与自进化收益 | 相关结构、边界得分与配对方法验证；候选保留确认与发布监测。 | 无有效推断不自动声称改善或晋级；生成候选和完成流程不等于改善成立。 |
| 性能、容量、成本与工期 | 在固定配置中试跑并记录用量/排队/延迟和资源峰值，再安排实施资源。 | 明确实测范围，不从目录数量推导吞吐量，不把工程预算说成容量保证。 |

以上属于按既定方法取得实现证据的工作，不是尚未回答的架构选择。若实际验证暴露无法在既定契约内解决的问题，再记录可复现输入、失败证据和受影响目标，开启对应后续决策；不能反向将未验证能力标为已通过。
