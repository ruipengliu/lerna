## 记录、版本和关联

数据位置和允许传输的投影由驻留策略约束；下表是完整逻辑记录模型，不要求把所有字段发给云端。固定元数据通过 Protobuf 表达，内容采用已登记的动态 Schema；沿用[协议编码规则](03-contracts-and-protocols.md)。以下是语义字段组，不是最终 `.proto` 字段编号或额外线协议。

| 字段组 | 表达 | 不变量 |
| --- | --- | --- |
| 记录引用 | namespace、collection_key、record_key | 键在所属作用域内定位；不为每个类型增加全局实体身份，已删除的记录身份不重新用于另一条记忆。 |
| 修订 | revision、适用的前一修订、产生修订的 operation_id | 同一记录修订有序；与任务版本、传输 seq、同步游标各有独立含义。 |
| 内容 | kind、schema_ref、受控 JSON 内容或内容引用 | 类型区分事实、偏好、推断和经验；缺少必需 Schema 支持时拒绝，不能将未知类型当作可信文本执行。 |
| 来源 | 类型化来源引用、来源修订、可选片段定位、提取/生成方式 | 引用可指向用户输入、证据、操作结果或其他记忆；来源不可访问时显式表达，引用不授予读取权限。 |
| 适用性 | 描述对象、适用条件、发生/记录/有效时间、置信判断及依据 | 缺失与不适用分别表达；不按设备时钟决定写入优先级。 |
| 控制 | 策略引用、用途及同步约束、保留规则 | 策略引用由受信策略判定；客户端不能通过修改这些字段扩大权限。 |
| 生命周期 | 当前状态、纠正关系、必要删除元数据 | 当前检索默认排除旧修订及已删除内容；历史读取须另行校验权限和保留政策。 |

记录修订、集合变更位置以及来源修订是定位元数据，不新增独立的 Operation。模型推断修订需要写入授权，不能仅因检索评分变化改写事实。用户明确输入、观察与推断的冲突由大脑结合来源处理，存储层不替模型裁决事实真伪。

## Module 与 Interface

调用方依赖语义 Interface。认证、授权及协议校验完成后才进入相应用例；对存储 Adapter 的直接访问不是外部插件绕过治理的入口。

| Module / Interface | 操作 | 调用方必须知道的行为 |
| --- | --- | --- |
| Memory | Query、Get、Put、Correct、Delete、LookupOperation | 有界查询返回来源、修订和可见性；变更保持 operation_id。结果未知时查询原操作，不能换身份重做。LookupOperation 只查询记忆操作。 |
| ContextAssembler | Assemble、Validate | 输入任务事实版本、用途、候选来源和预算；输出上下文及来源清单、截断/冲突/缺失信息。不得推进任务状态或隐式写长期记忆。 |
| MemoryStore | Read、Scan、Commit、LookupOperation、ReadChanges、ReadSnapshot | Commit 在同一本地原子边界校验版本并更新记录、操作回执和同步变更；其余操作支持有界查询和恢复。具体签名应保持这些语义。 |
| MemorySync | OpenView、ReadSnapshot、ReadChanges、GetStatus | 管理获准同步的视图、快照和变更位置；修改复用 Memory 的变更操作，不另造一套绕过权限的复制写入接口。 |

存储 Interface 属于 Memory 内部的替换位置；排序与摘要等策略不必变成公共远程服务。参考 MemoryStore 使用 SQLite；内存 Adapter 用于共同语义检查，不能据其测试宣称实现耐久性。

Query 同时受访问范围、用途、数量、大小及新鲜度要求限制；不能只在排序返回后删掉无权记录而泄露计数、片段或排序解释。Get 指定修订时必须精确返回该修订或明确不可用，不能用最新内容冒充旧修订。查询和回执重放都重新校验当前权限；被删除内容不得从旧操作回包再次返回。

Query 以“本次获准查询范围”为覆盖基准，分别返回是否完成、是否存在可见的不可用来源及结果新鲜度；完整范围内零命中与部分范围尚未查询不能合并。预算不足、必需处理能力缺失、来源不可用和源修订失效使用明确领域结果，调用方分别缩小范围、等待或重新组装。对无权主体的响应不暴露记录究竟存在、被删除还是不可见。

### 已确认：写入与冲突

Put 默认创建新记录；Correct 必须携带目标记录和预期修订，成功生成新修订。Delete 的记录级请求同样校验预期修订，避免删除用户尚未见到的新内容；批量删除如需支持，应明确集合范围、截止版本及单独授权，不能让记录级请求暗含无限范围。

版本检查失败返回 VERSION_CONFLICT。用户或获准的业务策略读取可见的新版本后，才可形成新的修改意图；默认不自动覆盖或让模型合并。原操作语义保持不变，修改目标版本或内容需要新的 operation_id。

未知提交先 LookupOperation。已提交时返回相同结果引用；明确未受理且接纳窗口仍有效时可补交原操作；窗口已过且未受理时报告未提交/已过期，传输层不自动申请新身份。离线草稿保留期限和用途仍需满足策略。

操作去重检查相同身份的语义一致性，同时受删除策略约束。保留比较依据时不得借此保留被删正文；若清理后已无法可靠比较补交载荷，则拒绝该次补交并指向原操作状态查询，不重新受理，也不仅凭 ID 相同宣称两份内容一致。历史受理状态和当前内容可用性分别返回。

## 已确认：纠正、删除与传播完成度

纠正生成新修订并使依赖旧修订的当前索引、摘要和上下文失效。旧修订只有在用途和保留期限允许时才能作为历史读取；普通检索与下一次上下文组装使用可用修订。

删除应覆盖被指定记录的受控内容副本，以及依赖它的缓存、索引和摘要；不能仅从当前列表隐藏。原始外部网站、独立来源和用户已导出的副本不因删除一条记忆自动被删除，完成报告明确控制范围。清理备份遵守部署声明的生命周期，不承诺立即物理擦除存储介质。

删除过程分维度报告，避免单个“成功”同时指代不同阶段：

| 维度 | 可观察结果 | 含义 |
| --- | --- | --- |
| 权威提交 | 未提交、已提交或结果未知 | 是否已持久化删除决定及相应修订。 |
| 本地使用 | 已阻止新使用、内容清理中、已清理 | 删除提交后立即从权威端普通访问中排除；物理清理可以异步，但不得仍从索引或回执读出内容。 |
| 副本传播 | 已应用节点、待应用节点、不可联系/已移出管理的节点 | 不将离线节点计为完成；移出管理不伪造其已清理。 |
| 派生及归档 | 失效、清理中、完成或超出当前控制范围 | 包括摘要、上下文缓存和受控备份的处理，分别报告范围。 |

离线副本只能在既定的有限授权及新鲜度窗口内使用缓存；严格要求最新纠正或撤销的用途必须在线核验。权威不可达时，本机收到用户删除请求可以先抑制本地使用，正式删除仍显示待提交；不得冒充已传播。

### 防止被删除内容重新出现

- 删除决定与可补读的变更记录在同一存储事务中产生。普通内容清理后保留必要的记录引用、删除修订及同步拒绝旧数据所需水位，不保留被删正文；元数据本身仍受访问与保留约束。
- 墓碑清理须满足受控副本已应用，或旧副本的同步世代已被持久化关闭且重返时必须重建。不能仅按时间删墓碑，然后允许旧副本直接上传原记录。
- 游标过期后，用当前权威快照替换相应同步视图，清除视图内本地残留；尚未提交的本地意图隔离保存，不能混进权威快照。
- 依赖某来源的混合摘要先整体失效，再从仍获准的来源重建。显式复制到其他受控对象的内容也须登记来源依赖；没有依赖记录不能宣称完成了全面清理。
- 运行记录保留动作是否发生及最小核对身份，但分离并清理受影响的敏感载荷。原操作回执仅返回状态或经当前权限校验的引用；内容已删除不等于动作从未发生。
- 删除传播完成必须覆盖声明范围内的受控副本、派生内容和备份生命周期。无法联系的副本持续标明不确定；有限离线授权不能被描述为即时远程擦除。
- 旧备份恢复先隔离，核验最新删除水位、同步资格和权威状态，再开放数据使用；无法获得可信的新状态就保持隔离，不能凭旧数据库独立证明自己是最新状态。

已经发给外部模型或已经产生的外部效果无法通过本地删除撤回。受控输出和改进产物的来源关联要向观测/自进化 Module 提供失效通知；其下架或重建由相应生命周期执行，不能只删除 Memory 表就报告全系统完成。

## 已确认：上下文快照与失效检查

一次决策使用一份固定的上下文组装结果，记录 task_ref、任务事实版本、使用目的、组装策略版本和来源修订。其身份可由任务内局部版本定位，无须新增全局请求 ID。允许留存的正文才进入持久化快照；否则保留受控引用，恢复时重新获取或明确报告缺失。

预算至少包含输入大小上限及模型 Adapter 声明的上下文容量；为输出和协议包装预留空间。无法精确计数时使用声明的保守估算，并由实际模型 Adapter 在发送前验证容量。目标、用户约束、行动结果确定性和必要授权条件必须保留，不足时返回预算错误。

| 检查点 | 行为 |
| --- | --- |
| 组装和发送模型前 | Validate 检查来源修订、删除/失效、用途与新鲜度；出现不满足要求的来源则重新组装或报告缺失。 |
| 模型返回后 | 再校验本次输入的依赖版本；已知被纠正、删除或权限失效时，不直接发布答案或采纳原行动提案。 |
| 发布答案或启动新行动前 | 内核检查任务控制与上下文适用性，执行端仍做动作准入。失效的提案重新决策，不能因持有旧快照绕过当前限制。 |
| 正在执行的动作 | 按任务控制和能力取消/核对契约处理；记录已发生效果，不以新记忆版本推翻历史动作事实。 |
| 重启与长期等待后 | 从当前有效来源和内核事实恢复；缺少必要输入则进入对应等待，不能仅凭旧摘要继续。 |

Validate 的成功表示检查时及所声明新鲜度范围内可用，不承诺跨库、跨节点到外部动作的全局原子撤销。严格用途要求在线核验；离线场景暴露最后核验位置与有效窗口。具体凭证和可信时间由授权分册定义。

默认只让依赖受影响记录的上下文失效；不因另一条无关偏好变化重启所有任务。持续纠正导致无法稳定组装时，有界重试后等待，避免无限推理循环。

## 已确认：同步视图与快照恢复

同步仅用于允许复制的数据；禁止上云的数据经端侧查询使用，不为查询建立云端数据副本。同步视图绑定集合、获准记录/字段范围、用途和策略版本。内容投影携带原记录修订，但部分字段副本不能作为全量记录覆盖提交；Correct 需要精确字段意图及权限，否则要求重新读取后修改。

1. 建立获准视图及世代；来源正文、来源定位信息和派生内容分别校验是否允许同步。
2. 读取具有一致快照边界的分页快照，取得对应变更游标。后续增量从该边界开始，不允许分页快照混合不同时间状态导致漏删或漏改。
3. 副本在本地事务内同时应用变更和推进游标；崩溃重放不能重复应用。授权过滤形成的游标必须由服务端解释，不按业务记录编号的缺口猜测漏消息。
4. 持久化应用位置后报告同步状态。WebSocket 消息持久化回执只说明消息已收，不代替副本已应用修订。
5. 游标或视图世代失效时明确要求重建，丢弃旧视图的残留，隔离本地待提交修改。快照容量与保留时间有界，超限时背压或重新建立快照，不承诺无限历史。
6. 权限或投影范围变化使旧视图失效；接收端收到后清理不再可见的字段/记录。未送达的离线副本仍按有限授权处理，不能依赖普通“新修改事件”发现权限收缩。

原操作是否受理通过 LookupOperation 核对，不由“当前快照没有这条记录”推断。已受理操作可能后来被纠正或删除；查询应同时区分历史提交状态和当前记录可用状态。

## 单机参考存储展开

参考 SQLite 保存集合元数据、当前记录及允许保留的修订、来源依赖、操作回执、集合变更、删除与同步水位；表名不是外部契约。一个本地记忆提交原子更新记录、操作结果和待同步变更。RunStore 与其通过既定幂等转交协作。

首版小内容可直接放入 SQLite，减少跨文件提交窗口。大产物可使用本地受控内容存储：先暂存并确认可读，再发布引用；未引用的暂存内容按策略清理，悬空引用显式报缺失。内容存储可替换，但不因此假定其与 SQLite 有原子事务。

文本与元数据检索完整可用；派生索引持有输入修订，查询命中后由 Memory 校验当前记录可见性，确保异步删索引期间不泄露内容。质量、资源上限和耐久性分别验收，不强制引入向量库或独立工作流服务。

## 待实现的一致性与故障验收

| 验收点 | 必须观察的结果 |
| --- | --- |
| 两节点竞争同一修订 | 最多一次提交成功，另一方明确冲突；不因时钟偏差覆盖。 |
| 提交成功但回执丢失 | 同一操作查询到原结果，不生成重复记忆；已删除正文不从回执复现。 |
| 同步应用中崩溃 | 游标与本地应用一致，重放无重复效果；消息回执不掩盖未应用。 |
| 离线纠正/删除与重连 | 展示待提交和传播状态，旧副本不复活删除记录；窗口过期不自动续身份。 |
| 同步游标及权限视图失效 | 当前快照重建并清理旧范围，隔离待提交意图，拒绝过期世代。 |
| 检索、摘要及模型调用途中删除 | 已知失效后不发布旧提案，缓存与派生内容不可继续被正常访问。 |
| 上下文预算不足或来源缺失 | 明确不足/等待，不丢掉必要约束后继续行动。 |
| 后端替换 | 相同语义夹具验证访问、版本、幂等和同步；耐久性对持久 Adapter 单独验证。 |

以上均为验收设计，尚未执行运行测试。多模拟节点即可验证；不同模型/检索策略的个性化效果另用可比较能力基线衡量。
