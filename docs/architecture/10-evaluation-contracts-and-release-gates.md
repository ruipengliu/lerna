# 评测接口、参考基准与发布判定

状态：接口、参考基准、预算、统计比较、发布与资料保留规则已确认；尚未实现或完成运行验证。已确认职责见 [观测评测与自进化](10-observation-evaluation-and-evolution.md)，决策依据见 [观测评测与发布闭环决策](../../.scratch/harness-technical-design/issues/13-observation-evolution.md)。以下数值是已确认的首版工程配置，尚无模型运行、性能或统计仿真结果，不构成样本精度或达标保证。

## 小接口及其权威范围

| Interface | 方法 | 必须保持的语义 |
| --- | --- | --- |
| Observation | Ingest / Query / GetCoverage | 接纳受控信号，按授权查询记录及完整性；持久来源按作用域、源位置和项次去重，临时信号明确采样/丢失。不写业务状态。 |
| Evaluation | Start / Get / Cancel / Compare / LookupOperation | 用不可变计划启动评测、查询/取消、生成基线比较及核对原管理操作；保存逐例结果，结果不完整不报告通过。 |
| Evaluator | Score | 按固定评分规则与获准真值判断指定证据；返回通过/失败/不可评估、判定依据及评分器版本，不直接发布候选或改任务。 |
| Evolution | Propose / Evaluate / Promote / Halt / Get / LookupOperation | 登记版本化候选、发起评测、推进发布阶段、停止扩大或请求回滚、查询事实；分别检查候选内容、评测资格与发布权限。 |

Observation 的本地参考实现使用 SQLite 诊断索引与受控文件内容存储；它通过内部存储接口保存接纳位置与投影，不以第三方遥测平台作为必需依赖。批次重复接收不重复计数，来源游标已清理且不能重建时报告缺口。非持久性能信号可以丢弃并累计丢失量；恢复和授权所需事实仍由原模块保存。

Evaluation 与 Evolution 各有内部 Store，提供 Load / Commit / LookupCommit / ListRecoverable 的局部原子提交及恢复能力。评测状态、样本调度意图/回执和发布阶段/Outbox 分别属于消费它们的模块，不另建跨模块大事务。事实记录和输入内容引用分开，默认不复制完整运行数据库。

评测记录使用命名空间内的 evaluation_ref，候选使用 candidate_ref，均由已有操作创建并关联；这些是管理对象引用，不新增所有协议必须携带的通用身份。样本引用由计划版本与样本键确定，恢复/重测另记录尝试序号。管理变更沿用稳定 operation_id、预期对象版本及当前授权；内部 change_id 仍只用于查明提交。

观测来源绑定经过验证的实际节点/模块身份，不能按载荷自报的来源接纳审计事实。Query 使用受控过滤条件、分页与范围上限，游标绑定授权视图和投影修订；GetCoverage 分别报告来源已接纳位置、投影应用位置、采样和不可恢复缺口，不以没有记录推断没有动作。

评测和发布管理服务归入任务协作领域，受控观测查询作为该领域的诊断管理接口；不将原始任意遥测流当作端云必需可靠业务流。固定请求/响应仍采用 Protobuf，动态指标和评分结果使用已登记 Schema；gRPC 与 WebSocket 共用业务语义。完成/失败/发布变更通知通过既有 Exchange 绑定，查询可补读当前快照。

### 评测与发布的恢复

Start 先保存计划、授权、预算与样本工作清单，再通过持久交接向 Harness 提交隔离任务；同一次交接补发保持操作身份。所有样本的模型/动作依现有内核与执行契约运行，不在评测器内另建可无限重试的执行循环。

评测生命周期区分 QUEUED、RUNNING、WAITING、COMPLETED、CANCELLED；运行结束状态与 gate_result（PASS / FAIL / INCOMPLETE）分开。样本必须保留所有尝试；本参考计划每例执行一次正式尝试，任务内的有界纠错属于该次尝试。重复性研究或设施重测使用独立运行记录，不能从多次结果挑最好一次计分。评分器故障、缺失必要证据或设施事故导致 INCOMPLETE，不能把其余可评分样本重新组成较小分母宣布通过。

被测实现自身未输出提案、耗尽预算或无法确认业务效果属于任务未成功，不能以评分证据不足排除失败；只有独立判定器/测试设施无法判断已规定条件时才标记 INCOMPLETE，并保留设施原因与原样本分母。该区别不改变原操作的未知效果恢复要求。

Cancel 先持久记录取消意图，再停止新样本和请求停止在途任务；实际停止、迟到结果及外部效果分别收敛。进程恢复重新查询原任务/操作，不能因评测记录未收到回执就复制执行。证据接收、评分和报告生成可以幂等重做，真实变更不能借“重放”重新发送。

正式判分所需的首次提案、操作事实和效果证据不得按临时 Trace 采样；允许留端的证据可由端侧评分器核验并返回获准结果。关键材料不可用时标记 INCOMPLETE，不以一个采样成功片段替代整个样本。

Compare 绑定两个完整运行及相同计划；不同评分器、预算、目录或不受控环境变化默认返回不可直接比较。相同字节输入不保证模型再运行确定，报告保留可取得的服务版本、时间与随机参数。

Promote 原子保存下一阶段意图、证据引用、当前政策/授权前提及 Outbox，再以稳定操作交接 ExtensionManager；回执丢失先核对原激活。发布资格、候选摘要、当前基线或授权变更时重新验证，旧报告不得授权另一份资产。各节点实际版本单独报告；阶段意图已提交不等于所有节点已激活。

## 固定目录质量基准

以下计数针对一次正式基准运行，不包含开发集和验证集。固定完整目录 K 项独立业务 API，K 至少为 1001；目录冻结后不得因失败删 API 或改变主指标权重。

| 分组 | 首版规模与构成 | 计分与门槛 |
| --- | --- | --- |
| 单步可执行任务 | 每 API 20 例，共 20K 例；每 API 10 个独立设计的意图/状态族，每族 2 个表达变体。每 API 至少 8 例涉及近义区分或必要参数依赖，类别可重叠。 | 首次正确率采用逐 API 等权宏平均，至少 90%；同批任务有限纠错后的成功率采用相同宏平均，至少 95%。同时报告微平均、逐项成功数与覆盖。 |
| 多步可执行任务 | 至少 max(2000, K) 个任务，每项 API 至少出现于 4 个任务；预期正确路径 4–6 个业务动作，每任务涉及至少 2 项 API。所有条件同时满足才完成计划生成。 | 完整任务成功率至少 95%，每任务计一次；报告任务长度、能力族及步骤首次正确，不能将一任务复制成多个成功样本或用单步分数抵消。 |
| 正确不执行 | 至少 1000 例，至少各 250 例覆盖无匹配 API、缺少必要信息、权限不足、约束冲突。 | 预期澄清/等待/拒绝至少 95%；任何越权或禁止的变更为硬失败。不能进入可执行主指标分母。 |
| 故障与契约 | 依各分册共同矩阵，覆盖正常及失效路径；不靠抽样量替代必需用例。 | 每个必需断言通过；不支持的可选能力单列，未知效果不得记成成功或自动重做。 |

主首次计分取单步任务的第一次业务行动提案，包含目标 API、版本、资源及必要参数；未形成提案、候选遗漏或首份提案不合格均计错。Schema 纠错仍消耗预算并保留首次失败。正常检索、读取声明和计划准备不直接充作业务动作，所有相关调用和成本仍记录。

任务成功要求最终效果满足目标且全程未发生违反约束的错误副作用；单步和多步组分别达标。计划必须展示逐 API 的分母、成功数、错误类型及无成功样本的项目。总体门槛不解释为每个 API 均达到相同比例；要声明逐项质量保证须另有对应证据。

每例在运行前核验初始状态、合法动作集合和结果条件；组合任务的真值允许多条语义等价正确路径。数据按意图来源/模板族划分开发、验证和保留用途，不把同族改写分到不同用途。保留集可在该轮结束后公开，但此后成为回归材料。

第一次完整参照可用于建立公开回归基线。正式支持声明和自动发布确认使用冻结候选后提供的独立保留材料；不能把公开、可检索的仓库夹具继续称作隐藏测试。K=1001 时单步为 20020 例；该配置保证的是规定覆盖量，不保证统计区间宽度或模型通过率。

## 预算及运行器参考配置

| 计量项 | 单步可执行任务 | 多步可执行任务 |
| --- | --- | --- |
| 纠错预算 | 每任务最多 2 轮 | 每任务最多 2 轮，由各步骤共享 |
| 模型请求总数 | 最多 4 次 | 最多 12 次 |
| 模型总 token | 输入、输出及供应商报告的其他计费类别去重合计，最多 65536 | 同一口径，最多 262144 |
| 新执行类操作数 | 最多 3 项 | 最多 12 项 |
| 辅助查询次数 | 最多 32 次 | 最多 128 次 |
| 每操作传输补发 | 最多 2 次 | 最多 2 次 |
| 墙钟时限 | 120 秒 | 600 秒 |

纠错指首次提案不成立或动作明确未达目标后修改方案；正常多步推进不是纠错。模型总数包含被测路径中的规划、生成、提取、模型重排/子 Agent 请求及失败请求，不能在 SDK 中藏一次免费重试；评分器用量单独报告，不用于被测任务预算。新执行类操作包含父子受控动作，不能用子任务重置额度。

辅助查询覆盖目录发现、Schema 读取、记忆检索、运行状态和效果核对等无新业务变更的调用，每次请求尝试均计入；对业务外部 API 的真实读取仍属执行操作，不能改名为查询规避动作限额。传输补发不形成新业务动作，必须满足原操作去重/核对条件。确需恢复查询但已无评测预算时，任务不能判为成功；收尾核对可在独立有限管理预算中继续，结果不回填成预算内完成。

时间从样本获准开始正式处理计至最后效果证据被接受，包含调用、等待、恢复和退避；之前的全局排队另报，首次编译/冷启动是否预热由计划统一规定。本 profile 使用每个运行镜像先做固定健康预热，模型与检索结果不预填评测答案，缓存范围和冷热结果另记。

并发参考上限为 4 个被测任务、4 个被测模型请求，基线和候选使用相同调度配置。模型请求前预留最大输入/输出及可计量用量；供应商无法给出可执行上界时不声称精确 token 硬限，标记该预算维度未验证并阻止该 profile 的完整通过声明。原始用量、估算和账单金额分开，金额须带币种与价格依据，不伪造缺失计费信息。

正确不执行组沿用单步预算；故障、GUI 和联网专项按计划设置独立有限预算，不与 API 质量组混成一个无解释的数字。调整以上额度必须形成新 profile，完整重测基线和候选，不更改旧报告。

Wasm 参考 profile：模块最多 8 MiB，每个 memory 最多 1024 页（64 MiB），每节点最多 2 个运行实例、1 个准备/编译工作；每次调用输入/输出各最多 1 MiB，日志最多 64 KiB，实例化加执行的期限为 30 秒且不超过任务剩余期限。宿主回调同样服从剩余期限和有界分配。输入包、待准备队列和缓存也设容量，初始队列 16 项、默认关闭编译缓存，后续启用时须具备可核实的容量与回收界限。这里只约束可计量资源，不能把线性内存和 context 解释为宿主 RSS 或编译 CPU 硬限；见 [运行器边界](09-extension-contracts-and-activation.md)。

## 统计报告及候选比较

主验收采用上述固定测试集得分门槛，不将“95% 置信下界也达到 90% / 95%”隐式追加为能力目标。每份报告保留成功数、分母、聚合方式、分组关系、缺失记录和区间适用性。

参考推断范围是当前固定目录下、计划所定义任务分布的表现，不自动泛化到其他 API 目录或生产用户分布。API 内意图/状态族可辩护为独立生成且跨 API 未共享相关来源时，采用按 API 分层、族整体重采样的 paired bootstrap；保持 API 权重、族内表达变体及基线/候选配对，一起重算目标指标。参考 10000 次重采样，记录随机种子，报告双侧 95% 百分位区间。

该算法及重复次数只是固定分析规则，不证明小样本或高成功率边界下覆盖率可靠。实施前须对参考数据生成机制做统计仿真和边界验证；无法满足独立族条件、存在未处理交叉相关或结果退化时标记 INFERENCE_UNAVAILABLE，报告固定集得分，不换成逐行二项区间冒充有效推断。宏平均不能用微平均检验替代，外部服务批次变化也须检查。

候选与基线报告共同成功、仅基线成功、仅候选成功、共同失败，以及点差和适用的配对区间。首次自动质量优化 profile 预先指定“单步首次正确率”为唯一主改善指标：

- 候选通过全部适用契约、权限、数据及绝对质量门槛；一次可证明的越权、受限披露或重复写入即阻止该候选发布。
- 主改善指标的配对差值 95% 区间下界大于 0；统计方法尚未验证或推断不适用时不自动宣布改善或进入发布。
- 单步与多步任务成功率的点估计均不低于同计划基线。这仅是观测结果约束，不表述为已证明统计非劣。
- 相同环境下被测平均 token 用量和任务端到端 p95 延迟分别不高于基线的 110%，基线为零或缺失时须按预先固定的绝对限额判断，不计算无意义比值，同时满足全部硬预算；这属于首版代价容忍配置，不能用节省代价抵消质量失败。

优化延迟、成本或其他能力时另行冻结主指标、保护指标及比较规则，不能看结果后改称这次优化了另一项。每轮开发/验证阶段最多筛选 5 个候选，冻结其中 1 个后才提交独立保留集确认；保留结果一旦用于选择/修改候选，后续确认使用新来源族，失败不能仅换名字再提同一批。记录每次反馈和材料使用历史，不承诺有限次数就消除了适应性偏差。

以上方法依据 [统计与版本比较研究](../research/harness-evaluation-statistics-and-comparison.md)。目标达标、可比较改善、生产稳定及普遍泛化是分别需要证据的结论。

## 分阶段启用与回滚

默认候选路径为提出、隔离评测、具备发布资格、试运行、全面激活；可停留等待、终止或请求回滚。记忆常规更新仍走既有 Memory 生命周期，不强制等待发布评测；代码类产物需在激活前获得维护者对精确产物的确认。阶段变更不改变该权限分工。

初始试运行按符合条件的新任务分配 5%、25%、100% 的候选比例，分配键使用持久任务/关联工作组引用，候选与对照共享的可变业务资源需要隔离或排他，不能同时写入同一资源作实验。管理范围、用户授权和发布资格决定哪些任务可参与，并非全体用户默认进入试验。

前两个阶段分别至少积累 200、1000 个有可核对真值的候选任务，覆盖预定任务组；每阶段观察不少于 24 小时，最长 7 天。达到数量和时间只是流程条件，继续晋级还要求阶段中适用的首次正确/任务成功达到 90% / 95%、必需控制检查通过、成本和延迟不越计划限额、关键证据完整及目标节点实际激活状态可确认。多步与单步仍分别计分，不让一个大组抵消另一个失败组。

样本不足、无法核对真值、关键证据缺失或目标节点应用未知时停止扩大；到第 7 天仍不足则转待评估，不因超时自动晋级。出现已确认的禁止动作/披露、同操作重复写入或状态破坏立即停止新路由，并按原执行契约处置在途工作。阶段满额检查未达质量或代价门槛时停止扩大并请求回滚；回滚目标不兼容或已撤销信任时保持隔离并等待处置，不能强行激活旧版本。

这些在线阶段阈值用于运行保护，不包装为严格统计证明或生产效果的因果比较。并行用户任务有不同输入，不能拿它们的裸均值直接当离线配对试验；没有客观标签时保留离线证据并等待独立复核，不把任务自报完成当真值。

单机参考部署用多个模拟节点及受控任务验证阶段切换、真实版本差异、故障和退出；可以用明确标识的模拟时钟测试 24 小时/7 天边界，但不能据此声称观察过真实生产周期。全面激活后的参考监测窗口为至少 24 小时、1000 个可核对任务，最长 7 天；新出现的违规立即处置，完整窗口不达标触发停止与回滚流程。仅样本不足标记证据不足并停止扩展适用范围，不伪称已发生质量退化；关键运行/权限证据缺失依其必要性停止受影响的新执行。

## 专项证据与资料生命周期

API 的 90% / 95% 不自动成为全部专项能力的同义门槛。首版另设 GUI 动作/观察/接管与 UI 协议确定性夹具，覆盖点击、滑动、替换/追加输入、返回、陈旧观察及 API 兜底资格；其必需断言全部通过。真实模型图像/结构观察选择能力用独立任务集计分，不能以固定点击脚本替代。

联网问答分固定证据集与实际联网两组，至少覆盖可回答、证据不足、来源冲突和获取失败四类；个性化组覆盖适用偏好、过期/冲突偏好、端侧来源不可达以及禁止披露。使用预先登记的关键事实/证据支持/约束核对表判定，开放式答案由独立复核完成最终裁决，辅助模型评分不能独自决定发布。各类样本、通过率及不完整原因单列，模型质量门槛、规模及预算已由 [专项验收分册](11-specialized-validation-and-handoff.md) 固定，不宣称仅运行接口即可专项通过。

默认诊断元数据保留 30 天；显式获准的诊断正文最多 7 天；评测/发布报告及允许保留的最小证据元数据保留 90 天，私有评测正文默认不复制，确需副本最多 7 天并受原授权更短期限约束。公开非私有测试夹具可随版本长期保留。此配置仅适用观测及评测资料，不清理任务恢复、授权消费等原模块必须处理的权威事实。

删除、用途变化和授权撤销通过来源/派生引用使相关证据失效；不能保证消除已经发生的外部披露。报告可保留允许保存的最小历史，但缺失的关键证据不再支持新的晋级或候选发布。正在等待的发布复验有效性，已经激活的版本按当前内容依赖与风险停止/处置，不默认恢复已删除正文。统计汇总也先判断是否允许保存和跨端返回。
