# 渐进式能力发现与 Skill 加载

[材料契约](README.md#skill-materials) · [执行目录](../execution/implementation.md#catalog-conformance) · [选择对照](../brain/decision-paths.md#6-验证启用与后续范围)

报告任务需要选出合适的读取和保存能力，也可能需要一份说明操作步骤的 Skill。小目录可以一次提供准确声明；目录增大后，可以先检索候选，再读取能力描述或需要的 Skill 正文。两条路径最后都要固定实际选中的版本、参数与当前使用资格，搜索命中本身不构成执行依据。

本页定义这些候选策略的比较方式。默认小目录直接装配，检索与延迟加载按证据启用；不新增目录服务或 SkillRouter。减少提示长度只是过程指标，采用依据仍是任务质量、退化与完整成本。

## 1. 在同一准确候选集合上比较

| 路径 | 可见材料 | 必须保留的诊断 |
| --- | --- | --- |
| 直接目录 | 有界集合的完整能力声明与固定 Skill 材料 | 实际可见项、被裁剪项及上下文成本 |
| 检索后描述 | 有界 search 候选，再取得准确 Capability／Binding 描述 | 查询、候选排序、未召回、同名歧义、describe 缺口和最终选择 |
| 元数据后正文 | 先读名称、用途、适用／不适用条件及依赖，需要时加载 Skill 正文 | 被选、实际加载、加载时机、实际采用及未使用原因 |

实验清单冻结候选集合的准确引用、InstallLock、查询范围、来源和权限条件；不虚构现有协议没有的全局 catalog_version 字段。固定实验集合不冻结运行资格：实际使用仍核验准确 Schema、Binding、当前实例 ready、批准与数据用途。搜索结果与已加载正文均不能替代最终准入。

缓存键包含准确版本和查询范围，按当前来源／权限检查投影；同名不共享键。配置变化、依赖缺失、撤权和来源关闭后，不再以旧缓存允许新使用。允许继续的原工作保持其固定绑定，不把新版搜索结果混入旧 Operation；目录不可达时，只有原准确绑定及当前资格可核验的操作可继续。

## 2. 独立计算发现与使用的收益

诊断作为原 Decision／上下文的内部清单，记录召回、选择、正文加载、触发位置和采用结果；正文只存准确 Content 引用，避免另建一份日志副本。至少覆盖应触发、不应触发、同名能力、旧 Schema、缺依赖、断连、加载过晚和加载无益，配套合法正例。任务失败不能只归因为“检索不准”。

固定模型、提示预算、可用能力和环境，比较独立任务结果、所有搜索／describe／加载次数、读取字节、token、时延、失败和维护成本。任务若为了加载材料新增模型回合，费用与时延必须计入。用同一批任务测得的目录 token 降幅不能直接宣称成功成本下降。

只改变 Skill 选择／加载策略的比较沿 X-03；改变全目录发现机制按独立 X-09 冻结。若同时更换模型、程序模式或目录内容，再拆出独立因素，不扩大原 X-03 的结论。候选未达门槛或结果不确定时保留原策略；撤回与回退沿 Extensions 的当前批准和实际就绪检查。组合故障见 [HAR-10](../validation/harness-scenarios.md#har-10)。
