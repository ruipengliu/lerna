本方案交付设计和本地实现契约；下面场景是参考实现及互操作验收要求，尚未运行。CO1–CO7 对应[模块保证](README.md#guarantees)，C／A／V 编号对应[项目目标](../../harness-project-goals.md)。

<a id="dependencies"></a>
## 1. 启用依赖与缺席行为

| 提供方 | 需要交付的依据 | 缺席时的行为 |
| --- | --- | --- |
| 任务内核及运行存储 | 父准入／预算预留、固定操作和子关联；受信子配置进入 Submit 事务；Observe、ReadTask／ReadResult、用量账本投影与取消 | 不提供内部 Agent 可派发候选；不能降级创建不受限普通任务 |
| 身份与授权 | actor／endpoint／owner 绑定、Delegate、使用判定、来源及用途复核、撤销与连续恢复依据 | 身份不成立拒绝；当前判断不明等待；跨端缺授权 P1 的实现和映射时相关行为不开门 |
| 已安装 Agent／扩展 | 固定目标／结果合同、配置版本、查询／取消／用量保证及受控出口 | 不自动信任自报能力；缺必要保证则禁用该配置 |
| 执行与内容 | 原操作事实、可核验效果、完整成果及来源、获准读取和保留 | 结果不完整或效果不明时不能完成依赖它的父目标 |
| 领域恢复适配器 | 本轮权威快照、切点、连续变化和持久应用依据，按行为裁决 | 流可恢复仍限制业务；只查询、控制或接收适用获准事实 |
| 受信宿主与存储 | 有限配置、持久账本、原提交核对、旧实例隔离、本地管理入口 | 不接纳新责任；浏览器内存或仅关连接不能满足恢复承诺 |

连接适配器的内部收发记录已在本方案展开，仍不表示其代码实现存在。记忆、UI、授权、执行及大脑的跨端条件分别按所属方案启用，不用一个“协作已支持”开关同时打开。

## 2. 核心验收矩阵

每项运行测试固定实现／配置／Schema 版本、用户和端点、权限、预算、内容及故障点，并观察持久记录、网络消息和实际效果。事务故障至少覆盖提交前、提交后答复前、跨模块确认后记账前三个位置。模拟提供方通过只证明该测试合同，不能替代真实提供方的隔离或耐久保证。

| 编号 | 前置条件与刺激／故障 | 必须观察到的结果 | 保证／目标 |
| --- | --- | --- | --- |
| CO-01 | 同用户内部 D 正常委派、同 D 重投、同 D 换目标 | 一份合同、C/S 及子任务；异意图拒绝；recorded、accepted 和父完成分别可查 | CO1、CO2／C5、A1 |
| CO-02 | D 接管或 C 创建后崩溃；接纳答复丢失 | 原 S 可查；无第二子任务；扫描继续；未知期间父预算不释放 | CO1–CO3／C5 |
| CO-03 | 子提交误用 D；另一个任务复用 S；父请求错投其他权威 | 用户级索引冲突或路由拒绝；无新任务、预算或控制权 | CO1、CO6／C5、A4 |
| CO-04 | 适配器未安装、声明过期、子配置无法约束核心 | 不生成可派发候选或明确拒绝；不能回落普通 Submit／工具 | CO2、CO3／C6、A2 |
| CO-05 | 子完成，父尚缺方案乙来源或效果观察 | 父不完成；子事实保留来源及保证边界，补证或明确失败 | CO2、CO3／C1、C3、V1 |
| CO-06 | 账单重复、跳修订、乱序、同修订不同内容、子终态但 final=false | 累计差额只记一次；乱序不回退；冲突不放款；未知余额保留 | CO3／C5、C8 |
| CO-07 | 两个子任务并行及子再委派，份额接近总额；提供方仅有估算上限 | 不超卖、不双计后代；hard 要求拒绝 estimated，收尾不能挪为目标费用 | CO3、CO7／C5、C7 |
| CO-08 | 取消先于本地接纳准备；准备先于取消；D 尚未到达 | 前者封闭且无子创建；后两者沿原接纳核对，不将未找到当永久屏障 | CO4／C5、C7 |
| CO-09 | 子取消被拒后 C 才创建；原取消答复超窗 | 按新事实创建有界新子取消尝试；原答复不改写；超窗缺口不伪造 | CO1、CO4／C5 |
| CO-10 | 子成功结果及账单迟到，父已 cancelled | 保存真实效果／费用，父终态不重开；仅全部开放项核清才清除 effects_pending | CO3、CO4／C7、V2 |
| CO-11 | 外部服务接纳，返回 ID 前断线；原任务已有副作用 | 以固定外部提交键恢复原任务；不重建；无原键核对能力的目标禁用 | CO1、CO4／C4、C6 |
| CO-12 | 外部报告 success 但无来源；自行扩大权限、再委派或超额 | 父验收不通过；违规配置隔离并留证；不把硬上限违例隐去 | CO3、CO7／C6、C7 |
| CO-13 | Delivery 接管后答复丢失；目标 ACK 前／后崩溃；业务提交后确认丢失 | 原 message_id／seq 稳定，待处理和发送责任存在；业务只应用一次原操作 | CO5／C5、A4 |
| CO-14 | 同流缺 seq、乱序暂存、伪造 ACK、中继 relay_stored | 不越过连续前缀交接或确认；只有目标证明允许源清理 | CO5／C5 |
| CO-15 | 超窗、源正文撤权、未处理入站清理、旧备份缺失已 ACK 记录 | 缺口及后续责任先提交；不换流重编号／改文重投；记录丢失不回退游标续跑 | CO5、CO6／C5、C7 |
| CO-16 | 单 scope 缺证据，其他 scope 就绪；快照切点并发取消／撤权，旧轮或旧 owner 答复迟到 | 缺口不堵无关工作；本行为先关门；旧答复不放行；取消约束传播到关联操作 | CO5、CO6／C5、C7 |
| CO-17 | 多连接共用端点、接替时旧实例仍离线行动、丢失账本新安装 | 序号／配额共享；不能凭断线接替；新端点不自动重做旧操作 | CO5、CO6／C5、A3 |
| CO-18 | 离线许可到期、时钟不可验证、剩余预算不足或本地权威缺席 | 停止依赖条件的新行动；已发生事实保留；不能取得父控制权或新签许可 | CO3、CO6／C5、C7 |
| CO-19 | 普通 work 满额，大量历史恢复，同时产生取消结果／执行事实 | 既有 work lane 内收尾获得预留容量及调度；用户总额仍有限，其他用户可推进 | CO5、CO7／C5、C8 |
| CO-20 | 只收到结果引用，内容失效或当前无权；另用户猜中 D／内容／恢复 ID | 不报告完整交付、不泄露对象；查询和结果也受当前披露约束 | CO2、CO7／C2、C7 |
| CO-21 | 主动核对用尽、Peer.Recheck 重复、被动结果随后到达 | 通知去重、无无限轮询或扩额；管理只查原对象，迟到合法事实仍可消费 | CO4、CO7／C5、C8 |
| CO-22 | 跨端合同／授权 profile、直连或迁移证明缺失 | 对应能力入口关闭，不能用普通 task.submit 或 core.resumed 携带未定义字段 | CO3、CO6／C6、A4 |
| CO-23 | 两个独立交付实现交换消息，再替换 Agent／存储适配器 | 合同、错误、去重、恢复和权限一致；实现版本固定，未知版本明确拒绝 | CO1–CO7／A2、A4 |
| CO-24 | 正常联网比较及有状态模拟手机子工作，分别注入断线／取消 | V1 引用来自实际资料且支撑父结论；V2 动作后观察证明效果，未知如实显示 | CO2–CO4／V1、V2 |

首批验证 CO-01～10、13～17、19～21 的本地闭环与交付存储；外部 Agent、离线和跨端分别在依赖齐备后验收。用两个进程交换样例不能证明异构互操作，静态 Schema 通过不能证明磁盘耐久、撤权时序或真实设备支持。

<a id="capacity"></a>
## 3. 容量验证

先测每用户活跃委派、平均后代数量、每委派事实量／字节、子运行时长、累计用量滞后、每端活跃流、未确认消息及恢复积压。持久空间估算至少覆盖“到达率 × 保留时间 × 平均记录大小”、开放责任和备份，并声明故障保留及大内容是否计入；该公式只用于容量假设，不能证明吞吐。

压测分开覆盖新工作高峰、单用户洪峰、目标失联、存储接近满、批量重连与有意构造的取消／收尾积压。记录硬拒绝是否发生在接纳前，已接纳责任是否存续，取消／恢复及其他用户的延迟，原操作是否重复，未知预算是否准确。十万同时在线与千万注册等目标另按实际部署验证，不能用空连接数代替任务和恢复能力。

<a id="proposals"></a>
## 4. 跨模块提案与采用条件

以下提案尚未采用，依赖排序及共同联动见[跨模块待决索引](../open-decisions.md)。当前采用同一固定写权威内的委派与本地适配合同；跨端委派和写权威迁移须分别落实 CO-P1／P2 后启用。提案采用时统一更新涉及的正文、Schema、示例与验证；这些草案没有已发布兼容约束，不保留无共存要求的旧分支。

| 提案 | 问题、依据与推荐改法 | 影响文件及验证／取舍 |
| --- | --- | --- |
| CO-P1：跨端委派领域合同 | task.submit@1 缺父子、收缩许可、预算及结果／用量合同。推荐新增独立委派消息族，覆盖 Delegate、ReadDelegation、ReadResult、Cancel／ReadCancel、可靠事实及累计用量，并定义可信声明获取；可靠 scope 按原 D 的 operation 解析，控制、查询、结果按安装注册划分 lane，不以可选 metadata 隐藏关键语义 | 联动 `endpoint-cloud-protocol/{extensions,task-and-ui,recovery-and-control,wire-format}.md`、schemas、标准注册表、示例与校验，及内核／大脑／身份相关契约。内部跨端仍回到同一固定 Harness 任务权威，外部只引用 foreign_task_ref；需与[授权 P1](../identity-and-authorization/validation.md#proposals)协调主体、来源及恢复证明，按需满足[执行 CE-P1／P2](../capability-and-execution/validation.md#proposals)。替代是本地适配器，不提供通用跨端互操作；采用后执行 CO-01～23 适用用例 |
| CO-P2：任务写权威迁移 | 固定同用户 Operation 唯一索引使单任务拷贝不足以迁移，且原 source 发送责任不能由新端改名恢复。推荐首个迁移范围为整用户内核写权威，保留单一用户操作索引：原方冻结全部任务及未知提交，封存一致切点，目标 importing；受信单一裁决记录固定唯一目标／新代次与切点，旧入口持久隔离后新方才 active；原端消息身份继续可靠转交 | 涉及 `task-kernel/{lifecycle,storage-and-interfaces,recovery-and-validation}.md`、身份 owner／隔离契约、协议交接载荷及协调恢复。必须明确权威路由记录与唯一生效记录同一裁决、全用户操作索引迁移、原端持续消息代理／身份保留、跨主机隔离证明，再确定线字段。代价是迁移期间全用户任务暂停、原权威不可达时不能自动推进；竞争方案为全局操作目录支持单任务分片，增加跨存储裁决，待有明确分片需求再选。逐阶段崩溃／旧入口迟到／源身份丢失均须证明至多一个写权威 |

CO-P2 的推荐是后续设计方向，当前没有唯一生效服务或迁移管理入口，不能据此开启强制接管。保持现状可以完成同一权威内的委派及分布式执行，代价是该权威不可达时依赖它的新决定等待；任务交接不是本模块设计闭环的隐含前提。

记忆同步、远程大脑、UI 中间成果／全量目录及设备接管的新线载荷继续按各模块已有提案处理，详细合同与启用条件由所属模块维护。只有需要相应能力时才纳入部署启用检查。
