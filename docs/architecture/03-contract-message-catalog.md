# 原生接口与消息目录

状态：根据[已确认协议方案](03-contracts-and-protocols.md)整理的设计规范，供后续 Schema 和 SDK 实现使用。表中名称是计划的接口标识，不代表已有代码。数据模型及恢复算法由对应后续分册细化。

## 统一操作目录

gRPC 使用具名服务与方法；WebSocket 的请求体使用同一操作对应的 Protobuf 消息。进程内调用通过领域 Interface 接入同一用例。四个领域可以共用通道，不能跨过调用准入直接调用存储 Adapter。

| gRPC 服务 | 方法 | 请求要点 | 结果及关键约束 |
| --- | --- | --- | --- |
| TaskService | Submit | 稳定操作标识、目标、输入引用、约束；委派时增加父任务和授权引用。 | 返回任务引用和持久化受理结果；重复提交关联既有任务，不重复创建。 |
| TaskService | Get | 任务引用。 | 返回已授权可见的任务快照、状态版本及结果引用；状态属于当前任务权威。 |
| TaskService | ProvideInput | 任务引用、等待输入的交互标识、输入、稳定操作标识。 | 核对当前等待项；迟到或重复输入不能错误地推进另一个等待项。 |
| TaskService | SubmitUpdate | 稳定操作标识、任务引用、追加信息或修改目标的明确意图、预期任务版本、受控内容及来源。 | 正式接纳后推进任务版本；重复操作返回原结果，新操作版本冲突显式拒绝；不增权、不隐式加预算、不重开终态。 |
| TaskService | AdjustLimits | 稳定操作标识、任务引用、预期任务版本及明确预算/期限变更。 | 校验调整权限并原子提交；不扩大授权、不清除已用与未结算额度，不重开终态或清除暂停/取消。 |
| TaskService | RequestCancel | 任务引用、稳定操作标识、原因。 | 返回取消请求受理情况，最终停止或已完成仍由后续状态报告。 |
| TaskService | LookupOperation | 操作标识及其作用域。 | 查询提交是否受理、关联任务/调用和结果确定性；不是 RunStore 的通用远程查询。 |
| AuthorizationService | IssueGrant / DeriveGrant | 稳定操作标识、授权范围、预期策略修订；派生附父授权及修订，交互批准关联有效等待项。 | 签发权限与范围收缩均须验证；返回授权引用和可披露材料，签名不等于已经消费或已执行。 |
| AuthorizationService | RevokeGrant / GetGrant | 撤销携带操作标识、目标授权及预期修订；查询携带获准授权引用。 | 返回原管理回执或授权当前状态，分别报告权威撤销、接收方应用及待送达。 |
| AuthorizationService | UpdatePolicy / GetPolicy | 更新携带操作标识、策略范围、预期修订与变更；查询提供策略引用。 | 验证策略管理权限，子范围不得放宽强制限制；查询不泄露隐藏资源。 |
| AuthorizationService | LookupOperation | 管理操作引用。 | 在当前授权范围内查询原接纳/提交结果，不据操作 ID 公开签名材料。 |
| AuthorizationService | ReadSnapshot / ReadChanges | 获准策略/授权视图，分页或连续变更游标。 | 返回一致快照边界及策略、授权、撤销变更；游标过期重新取快照，不允许任意远程读库。 |
| ExtensionService | Prepare / Validate | 稳定操作标识、管理范围与预期版本，来源/资产或精确锁定引用；验证附运行配置与测试集引用。 | 返回准备或验证回执及状态；资产导入不执行安装钩子，验证代码仅在获准环境执行，验证通过不等于已激活。 |
| ExtensionService | Activate | 稳定操作标识、精确锁定结果、目标节点管理范围及预期版本。 | 原子提交本地激活修订与绑定；分别报告节点应用，提交结果不明先查原操作，已固定工作保留原版本。 |
| ExtensionService | Disable / Remove | 稳定操作标识、版本/锁定引用、管理范围与预期版本；停用区分排空与风险隔离。 | 停止新路由或请求停止，真实停止另报；删除须处置持久引用，不清除业务事实或重复未知效果。 |
| ExtensionService | Get / LookupOperation | 扩展与节点范围，或原管理操作引用。 | 按授权返回管理版本、验证/激活进展或原回执；管理端请求受理不等于远端已切换。 |
| ObservationService | Ingest / Query / GetCoverage | 获准来源与信号批次，或受控查询条件、分页、来源范围。 | 绑定实际认证来源并去重；分别返回投影与来源进展、采样/缺失范围；不公开任意读库或业务事实改写入口。 |
| EvaluationService | Start / Cancel | 稳定操作标识、不可变评测计划或目标评测引用、预期版本与适用预算/授权。 | 持久交接隔离样本任务；取消意图与实际收尾分开，重启核对原任务，不复制真实执行。 |
| EvaluationService | Get / Compare / LookupOperation | 评测或原操作引用；比较附两个运行与相同计划，生成持久比较记录时携带操作身份及版本前提。 | 返回报告、配对比较及证据完整性；结束不等于通过，不同预算/评分器不直接比较，不挑选成功尝试缩小分母。 |
| EvolutionService | Propose / Evaluate / Promote / Halt | 稳定操作标识、候选/计划/阶段或停止意图、预期版本、证据及当前授权前提。 | 分别登记候选、触发评测、推进阶段或停止扩大/请求回滚；代码发布另验维护者对精确产物的确认。 |
| EvolutionService | Get / LookupOperation | 候选、发布范围或原管理操作引用。 | 返回获准的资格、阶段意图及各节点实际应用，提交阶段不等于节点激活或效果改善。 |
| CapabilityService | List / Describe | 获准范围及分页参数，或能力引用与准确版本。 | 返回能力摘要或完整声明；游标绑定授权视图和目录修订，版本不可用不静默替换。 |
| CapabilityService | Search | 目标描述、资源类型、必要能力、用途、允许位置及候选/时间预算。 | 返回授权候选、目录修订及覆盖情况；无匹配、部分不可达、索引滞后及预算耗尽分别表达。 |
| CapabilityService | Invoke | 执行类操作标识、能力版本、参数、授权引用及可选任务引用。 | 返回受理句柄或执行报告；不得用工具返回替代整个任务终态。 |
| CapabilityService | GetInvocation / Reconcile | 执行类操作引用；核对时附可用证据引用。 | 返回执行事实与效果确认；不具核对能力则显式说明，不能自动重做动作。 |
| CapabilityService | RequestCancel / RequestTakeover | 目标执行类操作引用、原因及本次取消/接管的操作标识；接管携带预期资源控制版本。 | 取消受理与已停止分别报告；接管解析为明确资源范围并核验权限，同一逻辑操作转交保持身份，受理不等于已落实。 |
| CapabilityService | GetResourceControl | 资源的类型化引用。 | 返回授权可见的控制意图、落实进展和局部版本；查询不授予控制。 |
| CapabilityService | RequestResourceControl | 稳定操作标识、资源范围、TAKEOVER 或 RESUME 意图、预期控制版本及授权引用。 | 去重并按版本接纳；接管约束范围内 API 与 GUI 路径，在途动作处置后才报告落实；恢复不清除任务暂停或取消。 |
| MemoryService | Query / Get | 访问范围、用途、查询或记录引用/修订、接收位置、允许结果形式、新鲜度及分页限制。 | 返回获准内容投影、受控引用及可见覆盖状态；离线或未授权不能当作零命中，检索不授予保存/同步权限。 |
| MemoryService | Put / Correct / Delete | 稳定操作标识、集合及记录引用、内容或精确字段意图、适用的预期修订。 | 创建或按版本更新；返回提交结果，删除另报告本地使用、副本传播与归档清理维度。 |
| MemoryService | LookupOperation | 操作标识及其作用域。 | 查询原记忆操作的受理/提交及当前可见结果；重放仍校验权限，不返回已删除正文。 |
| MemorySyncService | OpenView / ReadSnapshot / ReadChanges / GetStatus | 获准同步范围、用途及位置；后续携带绑定范围和世代的视图引用、分页位置或游标。 | 返回一致快照边界、增量及同步状态；过期视图重建，内容仅在获准复制时传输。更新仍走 MemoryService。 |
| UserInteractionService | GetSurface / GetActionResult | 界面引用或已提交的操作引用。 | 返回授权范围内的快照、有效等待项或操作结果；不要求存在 task_ref。 |
| UserInteractionService | SubmitAction / EmitUIEvent | 界面目标、事件类型、Schema 数据；变更时附 operation_id，等待输入时附 interaction_id。 | 分派到登记处理模块；正式提交可靠去重，临时事件按声明处理。 |
| ConnectionService | Negotiate | 受信身份绑定、协议版本、必需与可选能力、消息和队列限制。 | 建立连接配置，或显式拒绝不兼容要求。 |
| ConnectionService | Exchange | 双向流：订阅、通知、应用回执、流量额度和适用的交互消息。 | 两方向独立处理；发送返回不代表业务持久化；流断开不自动取消任务。 |

gRPC 的具名 RPC 承载请求响应，`Exchange` 承载双向交互和推送；不要求把全部 unary RPC 再封进流中。WebSocket 双方通过统一信封发起同样的操作。可推送事件包括任务更新、输入请求、调用报告、进度、能力变化，以及 UI 快照/增量、呈现请求、通知和交互状态；先订阅或明确委派关系，再按权限推送，不能将“可全双工发送”等同“所有事件都可广播”。

端侧 UI 的完整消息形态、生命周期和扩展规则见 [UI 交互契约](03-ui-interaction-contracts.md)。固定请求/响应/事件内部提供具名扩展载荷，按类型版本与 Schema 注册；不会为每个新控件添加新的顶层消息种类。

AuthorizationService 是任务协作领域内的授权管理入口，不增加第五类协议领域；其授权判定被所有领域复用。认证绑定、ES256 签名授权、离线期限、凭证保存与管理恢复见 [授权生命周期](08-authorization-lifecycle-and-interfaces.md)。原生节点使用 mTLS，浏览器 UI 使用独立的同源会话配置；任何领域都不能仅凭已建立连接绕过业务授权。

Exchange 可可靠推送授权/策略失效和应用进展。快照、通知和材料本身仍受接收方与披露范围限制，推送成功不代表远端已应用。签名授权只放入具名授权载荷或受保护的逐调用上下文，原始第三方凭证不进入通用任务、UI 或追踪载荷。

目录检索、执行 Driver 和资源控制见 [执行接口与故障验证](07-execution-contracts-and-validation.md)。Search、GetResourceControl 和 RequestResourceControl 仍属于能力调用领域，固定消息经 gRPC 和 WebSocket 采用相同语义；不要求为目录或资源控制部署额外进程。控制进展可通过 Exchange 可靠推送，失联后查询当前版本恢复；发起调用的接纳及效果报告继续使用原操作身份。

任务更新与 Agent 协作细节见 [决策准入、交互与协作恢复](06-decision-admission-and-collaboration.md)。SubmitUpdate 属于任务协作领域：追加事实保留来源及主体，修改目标另验对应权限；回复具体等待项继续使用 ProvideInput。经 UI SubmitAction 转交时保留同一 operation_id，任务接纳回执不等于旧动作已取消。更新后拒绝旧版本决策提案，但已发生的动作事实仍须保留并核对。

观测、评测与候选发布管理归入任务协作领域，具体契约见 [评测接口与发布判定](10-evaluation-contracts-and-release-gates.md)。Evaluator.Score 是评测模块使用的受控评分接口，不向被测 Agent 开放真值或任意改分入口。evaluation_ref 和 candidate_ref 是作用域内对象引用，不新增所有消息必携带身份；诊断采样不能删除正式判分所需的证据。

扩展管理细节见 [扩展清单、运行器与激活恢复](09-extension-contracts-and-activation.md)。ExtensionService 属于任务协作领域，管理操作沿用稳定 operation_id、当前授权和版本前提；不向普通扩展公开 ExtensionStore。激活修订是节点管理范围内的版本，不增加通用身份或跨节点全局顺序。UI 管理动作转交同一操作时保留身份，目录及 UI 类型投影未应用对应修订前不得暴露新绑定。

记忆方法细节见 [数据契约与生命周期](05-memory-data-and-lifecycle.md)，查询位置和返回范围见 [端云记忆驻留与联合检索](05-edge-cloud-memory.md)。MemorySyncService 属于记忆访问领域，不引入新的协议或必需进程。固定请求/响应及事件仍由 Protobuf 定义，通过 gRPC 与 WebSocket 采用同一语义。

`Exchange` 可承载受控的记忆视图变更/失效通知、删除传播进展及副本应用位置报告；可靠生命周期通知按已有持久化与补读契约处理，业务访问仍检查当前权限和版本。视图引用是作用域内的有期限读取上下文，不是新的持久业务操作身份。副本应用位置单调推进且可重复报告，不能把消息持久化回执当成业务应用完成。通知、游标和覆盖信息也遵守数据可发现范围，不能向云端泄露仅允许端侧知道的命中。

## 标识、作用域与关联

ID 不等同于独立数据实体或数据库表。按用户已确认的 [标识模型简化评估](03-identifier-model.md)，原 `invocation_id` 并入执行类 `operation_id`，原 `request_id` 的消息关联职责由 `message_id` 承担；生命周期不同的身份继续保留。

| 标识或引用 | 所属层与作用 | 重试与恢复约束 |
| --- | --- | --- |
| task_ref | 业务：任务引用，作用域由 namespace 明确。 | 一个任务关联多个操作；跨连接保持，权威迁移遵守端云恢复分册。 |
| operation_id | 业务：一次逻辑变更意图；能力调用属于执行类操作。 | 命名空间内唯一，类型、目标、业务期限及语义载荷固定；传输重试、执行核对和恢复保持身份。 |
| message_id / reply_to | 消息：一条应用消息及其回复所指向的消息。 | 原消息补发保留 ID；新请求消息用新 ID，同一业务操作仍引用原 operation_id。reply_to 不分配新身份。 |
| interaction_id | 业务附属状态：具体等待项，仅相关载荷携带。 | 同一任务不同等待点各有身份；输入提交操作引用等待项；独立 UI 等待项也须绑定受控处理模块。 |
| change_id | 内核存储：一次原子提交，原生对外协议不携带。 | 一次操作可产生多次提交；提交核对与业务去重分别管理。 |
| stream_id / seq | 通信：逻辑流与单向序号，用于顺序、补读和额度。 | 每方向分别计数；不替代消息或操作身份。 |
| connection_id | 通信：连接/协商上下文中的身份。 | 重连换新 ID，旧连接单独校验；无须每条信封重复携带。 |
| trace_id / causation_ref | 可选诊断上下文；因果引用指向既有操作或消息。 | 不参与授权或业务去重；不新建独立“因果对象”。 |

标识值不依赖单机内存地址；跨命名空间引用使用明确的类型化 Ref。`target_operation_ref`、`reply_to` 和 `causation_ref` 只是已有身份的引用，不引出新的实体。能力调用仍有独立的执行状态和核对能力，但不再额外分配第二个调用 ID。

operation_id 的内部表示绑定接纳窗口世代，仍作为一个不透明业务身份；过期窗口不能因重连或去重记录清理重新接纳旧操作，规则见 [恢复检查表](04-recovery-state-and-failure-matrix.md)。

操作类型与发起主体不用于让同一个 namespace 内的 operation_id 指向不同对象；相同 ID 配不同类型或载荷返回身份冲突。认证和权限检查先于读取或重放既有操作结果，不能靠自报身份或猜中 ID 取得权限。转发保留操作身份及受信发起关联，真正的新子动作才创建新操作。

UI 路由采用作用域内的 surface_ref 与 component_key，界面版本使用 revision；它们属于载荷内的定位与状态元数据，不新增全局 UI 任务/请求/事件身份。交互等待项可绑定独立应用的受控作用域，不强制关联 task_ref。

消息去重、操作核对、交互等待和内部提交回执分别保留记录。执行类操作记录不能随短期受理回执一起过期；记录不足时显式报告恢复边界，不能把原操作当成新动作。

## 编码与消息信封

固定消息使用 Protobuf；需要区别缺省与零值的字段显式声明 presence，互斥载荷用 `oneof`。删除字段保留编号，不能复用旧编号；未知值在结构层可读并不代表调用层可执行，未知操作或必需能力必须拒绝。

动态载荷采用 UTF-8 JSON 字节，并附 `schema_id`、`schema_version`、内容摘要。参考方言为已核验的 JSON Schema 2020-12；允许使用的关键字和格式验证规则必须由测试夹具固定。远程 `$ref` 不在调用时任意联网解析，应使用已登记的固定 Schema 资源集。

动态 JSON 的跨语言约定：精度敏感整数以 Schema 明确约束的十进制字符串表示；小整数限制到双方精确表达的范围；缺失与 `null` 分别校验。二进制大产物使用引用或分块，不混入任意文本字段。JSON 对象拒绝重复键。固定消息时间使用 Protobuf 时间类型；JSON 时间使用带时区的明确格式并启用验证，不能只依靠 `format` 注解。调试视图遵循 ProtoJSON，不作为额外生产传输绑定。

每条 WebSocket 二进制消息承载一个 Envelope，WebSocket 帧分片由传输库重组。接收方对重组长度和载荷大小设置限制，不能等到无限缓冲完毕才校验。信封字段如下：

| 字段组 | 内容 | 适用规则 |
| --- | --- | --- |
| 协议 | protocol_major | 与已协商配置相符；连接身份由绑定上下文提供，协商/恢复时才显式交换必要连接引用。 |
| 消息关联 | message_id、reply_to | reply_to 指向原请求消息；不同回复和事件各有自己的 message_id。 |
| 业务关联 | namespace、operation_id、可选 task_ref | operation_id 用于变更操作；查询的目标操作及 interaction_id 按方法放入载荷，查询本身不伪造变更身份。 |
| 流控制 | stream_id、seq、delivery_class | 可靠与临时消息使用不同逻辑流，避免临时丢弃破坏可靠消息补读。 |
| 调用上下文 | deadline、authorization_ref、可选 trace_id / causation_ref | deadline 表示应用操作期限，RPC 等待期限另行处理；不得携带可被日志随意记录的明文凭据。 |
| 主体载荷 | oneof：request、response、event、receipt、flow_control、hello、welcome、resume | 每条消息只出现一种载荷；各载荷使用固定 Protobuf 类型，request/response/event 内可含已登记的具名扩展载荷。 |

操作名称在方法清单中唯一映射到请求和响应类型。SDK 对非法字段组合做结构校验，接收端再次校验行为、作用域及权限。信封只是绑定层结构，不强迫进程内领域 Interface 接收全部字段。

## 协商与启动顺序

1. 建立可识别对端的连接。正式端云通信使用受保护通道；身份与凭证机制由授权分册确定，不能靠自报节点名完成认证。
2. 使用单独固定的 bootstrap 消息定义交换 `Hello` / `Welcome`，其格式不随业务主版本变化；不兼容 bootstrap 时拒绝连接。这样无需先理解待选择的业务编码版本就能完成协商。
3. 协商共同主版本、允许的能力及版本、必需能力、最大消息/分块尺寸、待确认窗口、心跳及记录保留范围。限制不允许无限制值；未就必需限制达成一致则拒绝。
4. 验证该主体可使用的操作范围，再开放业务流；恢复请求携带原逻辑流和已确认位置，由服务端核对保留记录及当前授权。
5. gRPC 的 `Negotiate` 与绑定的连接配置提供等效语义，后续 unary/stream 调用由绑定上下文关联该配置（必要时通过 metadata 携带配置引用），业务消息体不必重复连接 ID。配置过期或对端重启失效时重新协商；它不是新的任务所有者。

能力声明分别表达“实现支持什么”与“本次允许用什么”。具体授权更新、重连凭据、过期窗口和并发连接裁决在端云与授权分册落地。断连本身不解释为撤销授权，也不能保证连接期间授权一直有效。

## 回执、结果与错误

可靠消息接收端先持久化必要的接收与去重记录，再返回 `PERSISTED` 回执。这只表示消息已被安全接收，业务可能仍未获准执行。变更受理成功另返回 `ACCEPTED` 及任务/调用引用；完成状态和效果确认再分别报告。回执本身不要求无限递归确认，丢失时通过原消息补发或状态查询重新取得。

调用报告至少区分：执行阶段 `NOT_STARTED / IN_PROGRESS / FINISHED / UNKNOWN`，结果 `SUCCESS / FAILURE / UNKNOWN`，效果核对 `NOT_APPLICABLE / UNVERIFIED / CONFIRMED / CONTRADICTED`。这些是可观察维度，不能直接拼接成内核任务状态机；任务状态转换见 [恢复状态表](04-recovery-state-and-failure-matrix.md)。

取消及接管使用独立操作和交互状态。受理请求不承诺动作已停止；完成与取消竞态时保留实际动作和结果证据。外部未知结果不能因连接关闭自动改成失败或成功。

错误记录包含稳定 `code`、可安全展示的说明、结果确定性、关联标识及建议恢复动作。建议恢复动作供内核判定，不是 Adapter 自行重试的许可。

| 错误类别 | 应表达的事实 | 调用方行为 |
| --- | --- | --- |
| INVALID_ARGUMENT / UNSUPPORTED_VERSION / MISSING_CAPABILITY | 请求无效或协商要求不满足。 | 修正请求或选择已支持配置；不静默降级必需语义。 |
| UNAUTHENTICATED / PERMISSION_DENIED | 身份未建立或当前操作不获授权。 | 拒绝新动作，依授权流程补充身份或权限。 |
| VERSION_CONFLICT / IDENTITY_CONFLICT | 预期状态版本过期，或同一操作身份对应不同载荷。 | 读取当前状态重新决策，或修正标识使用。 |
| RESOURCE_EXHAUSTED | 有界队列或额度不足。 | 背压并依据期限退避，不能把可靠消息改为可丢弃。 |
| OUTCOME_UNKNOWN | 已发出或已提交操作的结果无法确认。 | 按原逻辑操作标识查询或核对，不能自动再次执行。 |
| CURSOR_EXPIRED / RECEIPT_EXPIRED | 所需恢复或去重记录已经不在保留范围。 | 重新取得快照并核对；不可将旧动作当成全新提交。 |
| UNAVAILABLE / DEADLINE_EXCEEDED | 服务或当前等待失败；仍须表达结果是否确定。 | 区分未受理与结果未知，采用对应恢复路径。 |

gRPC status 用于表达 RPC 层结果，领域错误在类型化响应或约定的错误详情中携带；WebSocket 使用同样领域错误。若传输错误使领域回包丢失，调用方必须按结果未知处理可能已生效的请求，而不是只看状态码重试。

## 示例：远端调用已发生但回包丢失

以下为 Protobuf 消息的人工可读视图，用于解释语义，**不是额外 JSON 线协议**。真实字段编号由 `.proto` 固定；连接和认证信息由绑定上下文提供，省略可选诊断字段。

```json
{
  "protocolMajor": 1,
  "messageId": "msg-101",
  "operationId": "op-9",
  "namespace": "user-a",
  "taskRef": "task-7",
  "streamId": "control-a",
  "seq": "41",
  "deliveryClass": "RELIABLE",
  "request": {
    "capabilityInvoke": {
      "capabilityId": "simulator.tap",
      "capabilityVersion": "1",
      "arguments": {
        "schemaId": "simulator.tap.input",
        "schemaVersion": "1",
        "schemaDigest": "<已登记的内容摘要>",
        "jsonUtf8": "eyJ4IjoxMCwieSI6MjB9"
      }
    }
  }
}
```

`jsonUtf8` 是 bytes 字段在调试视图中的 Base64，内容为 `{"x":10,"y":20}`。接收方可以先报告持久化回执，再进行业务准入和执行：

```json
{
  "protocolMajor": 1,
  "messageId": "receipt-101",
  "replyTo": "msg-101",
  "receipt": {"level": "PERSISTED", "acceptedMessageId": "msg-101"}
}
```

假设动作已经发生，业务回包却丢失。新连接使用新的绑定上下文，原执行类操作仍为 `op-9`。查询创建新消息并在载荷中引用该操作；原消息补发则保留 `msg-101`。若重新构造同一业务变更请求，使用新消息 ID 但保持 `op-9`，按操作记录去重；新的取消请求必须使用另一操作 ID，并明确目标为 `op-9`。连接与诊断信息可以更新，原操作的语义载荷不能改变。去重比较依据定义的语义载荷而非原始 Protobuf 字节序列，不能依赖序列化字节天然规范化。

查询获得 `FINISHED / SUCCESS / CONFIRMED` 后内核才依据任务目标推进；若只知道远端接收，或去重回执已过期，就继续核对或保留未知状态。不能将外部执行稳定关联到本地操作或不能提供效果证据的 Adapter 必须声明该限制。

以下为参考实现的设计目标，不是已实测清单。官方证据见[来源复核](../research/harness-protocol-source-check.md)。

| 对象 | 规范与参考绑定 | 最小行为及可选项 |

| A2A | 目标协议 `1.0`，参考 HTTP+JSON 绑定。 | 双向发送/受理、Message 或 Task 响应、查询与取消结果映射。流式和推送分别声明，不默认依赖 webhook；外部 Agent 可能不能成功取消或提供幂等。 |

## 一致性矩阵

| 验证层 | 必须覆盖 | 证据要求 |
| --- | --- | --- |
| 结构 | Protobuf 字段演进、动态 Schema、缺省/null、整数精度、未知操作、非法载荷及消息大小。 | 共享正反例，各 SDK 给出相同接受/拒绝结果。 |
| 绑定等价 | 相同操作分别通过进程内、gRPC unary/双向流、WebSocket 执行。 | 业务事实与错误一致；传输特有错误单独标注。 |
| 协商 | 无共同版本、缺必需能力、可选能力关闭、配置过期。 | 显式拒绝或按已协商组合运行，不放宽权限或可靠性。 |
| 交付 | 原消息重复、新消息引用同一操作、回执丢失、收发端重启、流序号缺口、游标及回执过期。 | 不重复创建业务操作；已发生但未知的效果可被核对或保留。 |
| 取消/接管 | 接收后未执行、正在执行、已完成同时取消；取消操作与目标操作身份分离。 | 保留受理和实际停止/接管的差别，结果证据不被覆盖。 |
| UI 交互 | 自定义组件、能力差异、多窗口路由、无任务交互、补丁失配、重复提交、过期等待项及多端竞答。 | 核心消息结构可复用；不支持时显式表达；界面呈现、用户提交与业务完成可区分。 |
| 负载 | 大分块、慢消费者、双向同时写、队列满、控制与数据竞争。 | 内存和队列有界，无协议死锁；可靠消息不静默丢弃。 |
| 授权 | 自报身份、越权方法、重复请求时授权已变化、订阅信息泄露。 | 接收/执行/推送分别落实适用校验，拒绝信息有明确归属。 |
| 外部互操作 | MCP 工具失败包装为完成、A2A 无幂等、句柄过期、取消失败、可选扩展缺失。 | 按版本、绑定、方向和能力组合记录；未测试不宣称支持。 |

生成器、编译器、Schema 验证器和协议 SDK 均需固定版本。发布兼容声明前执行此矩阵，不能只引用规范页面、成功编译或模拟桩返回作为互操作证据。
