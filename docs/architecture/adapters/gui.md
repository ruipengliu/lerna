- 状态：草稿
- 负责满足：C4、C5、C7、C8 中的 GUI 部分（GUI 不是关键能力，没有专项验收）
- 涉及场景：S3、S4、S6
- 上游：[项目目标](../project-goals.md)、[执行适配器接口](../ports/executor/README.md)、[交互适配器接口](../ports/interaction/README.md)、[执行管理](../core/ledger/README.md)
- 首次实现：M4，可选交付

GUI 适配器用于没有合适 API 的应用，以及作为兜底的执行路径。它执行"**观察 → 一次已准入的动作 → 再观察**"，回报平台的反馈和可见的证据。动作的效果由执行管理核验，任务的条件由任务编排核验；"核验"不是适配器的职责。

本设计的要点：

- **每个动作对应一次明确的节点动作或一个有限的手势。**"滚动直到找到""允许弹窗""失败后换个坐标再点"都包含新的行动，必须分别准入；
- **节点优先，截图按需。**不预设截图一定能提高成功率；
- **平台反馈、可见状态、业务证据三者分开**；手势完成和界面稳定都不是业务完成的证明；
- **设备控制有代次。**用户接管时，旧代次在本机出口处被封闭，有端侧回报才算接管落实。

## 1 职责与边界

| 事实 | 负责方 |
| --- | --- |
| 接管和交还的控制意图 | 任务编排 |
| 设备控制权代次 | 授权 |
| 端侧的落实回报（旧代次已在出口封闭） | 端侧执行管理 |
| 观察、单次动作、平台反馈 | GUI 适配器 |
| 动作效果的裁决 | 执行管理 |
| 任务条件的核验 | 任务编排 |

需要用 API 或文件来核对效果时，由核心安排对应的动作，GUI 适配器不直接调用其他适配器（R4）。观察本身也经过出口闸门：**观察不得静默改变设备**，例如打开网络、启动应用、允许权限或执行导航。AndroidWorld 的 `get_a11y_tree()` 就会尝试关闭飞行模式相关的限制、启用网络（[android_world_controller.py](https://github.com/google-research/android_world/blob/2655e27cd090f97fbf2ccaecf759057bec0a8460/android_world/env/android_world_controller.py)），说明一个叫"观察"的函数也可能夹带对设备的修改。

## 2 对象与状态

| 对象 | 关键字段 | 用途 |
| --- | --- | --- |
| 能力描述 | 后端及版本、操作系统和应用范围、窗口读取、节点动作、手势、截图限制、查询能力 | 明确适用的环境 |
| 设备身份 | 端点、设备启动代次、显示屏、系统和应用版本 | 设备重启或从快照恢复后，旧凭据失效 |
| 观察 | 观察标识、开始和结束时间、窗口和应用、方向和尺寸、节点树和截图引用、完整性和脱敏标记 | 不把异步的采集伪装成原子快照 |
| 定位输入 | 观察引用、唯一的选择器或坐标、窗口前置条件、最长有效时间 | 防止旧节点和有歧义的目标 |
| 动作输入 | 原动作和尝试、设备控制代次、输入参数、出口凭据 | 绑定执行资格 |
| 执行回报 | 未派发 / 已派发 / 不明、平台回执、回调、后观察、业务标识 | 平台反馈与实际效果分开 |

| 维度 | 状态转换 |
| --- | --- |
| 执行 | 待派发 → 可能已派发 → 平台反馈已取得 / 缺失 |
| 设备控制 | 系统持有 → 接管已保存、出口封闭中 → 用户持有 → 交还后重新观察 |
| 效果 | 未知 → 经执行管理核验的已生效 / 未生效；手势完成不直接改变效果 |

观察过期、目标不唯一、窗口改变、用户干预或控制代次不匹配时，停止派发，取得新的观察。

## 3 接口

| 接口 | 输入 → 输出 | 成功含义 | 错误 |
| --- | --- | --- | --- |
| 观察 | 设备、窗口范围、读取用途和凭据 → 节点树和按需的截图 | 拿到声明范围内的内容；每次都是一个新时刻 | 安全窗口、采集不完整、设备不可用、权限失效 |
| 执行 | 原尝试、观察、控制代次、定位和输入 → 平台回报和后观察 | 拿到派发反馈和证据 | 观察已过期、目标有歧义、设备忙、权限失效、派发结果不明 |
| 查询 | 原尝试、业务标识、读取凭据 → 原回报和当前证据 | 补充核对材料；**不重复点击**，需要导航时必须另行准入 | 没有查询能力、证据不足、需要导航 |
| 接管和交还事件 | 用户事件、设备、命令标识 → 核心控制回执 | 核心已保存，并落实本机的控制边界 | 控制冲突、保存失败、端点未确认 |

Android 并不认识 Lerna 的尝试标识，所以对 GUI 动作来说，平台层面没有幂等可言：去重完全依赖核心，未知的点击不得重放。

## 4 关键流程

### 4.1 单个动作

1. 核心安排一次受控的观察；内容治理保存允许保存的来源和观察版本；
2. 推理基于观察提议**一个**动作；任务编排准入条件、授权、预算和动作意图；
3. 按 R7 交给端侧的执行管理，保存尝试和待派发工作；
4. 本机的串行出口请求开始门禁（P4，默认部署中在云端裁决域；断网时不派发，见[执行管理 4.5](../core/ledger/README.md#45-端侧补传与云端对账)），在本机核验窗口、目标和前置条件，写下"可能已发出"后派发**一次**输入；
5. 收集平台反馈，等待声明的观察条件，取得后观察；
6. 执行管理接纳回报，内容治理接纳证据，预算接纳用量；
7. 执行管理核验效果，任务编排核验当前条件。

平台层面的几个"完成"都不是业务完成：Android 无障碍节点可能是虚拟节点，节点 `refresh()` 失败表示原节点已经离开了视图树，手势的派发和完成回调是分开发生的（[AccessibilityNodeInfo](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-15.0.0_r1/core/java/android/view/accessibility/AccessibilityNodeInfo.java)、[AccessibilityService](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-15.0.0_r1/core/java/android/accessibilityservice/AccessibilityService.java)）；UI Automator 的 `waitForStable()` 只表示界面树暂时没变化，不保证后台任务已空闲（[UI Automator 指南](https://developer.android.com/training/testing/other-components/ui-automator)），界面稳定之后网络提交可能仍在进行。所以"界面稳定"只能作为观察条件。

**不得有隐藏的动作。**UI Automator 的固定版本中，`setText` 在平台动作失败后可能只写一条警告；节点刷新可能运行 watcher；部分滚动方法包含重复动作（[UiObject2.java](https://android.googlesource.com/platform/frameworks/support/+/ec9022d156846f24e22bec3e475d4206d6f321ea/test/uiautomator/uiautomator/src/main/java/androidx/test/uiautomator/UiObject2.java)）。GUI 适配器只使用可以审计的单动作路径，不得使用可写的 watcher 和隐式的动作重试。

### 4.2 接管与交还

1. 任务编排保存接管意图；授权关闭相关设备资源的新自动操作权限，推进控制代次；
2. 端侧执行管理落实停止要求：本机出口拒绝旧代次，并持久回报封闭情况；
3. 只有在端点能证明旧的自动操作不会再进入设备出口时，才呈现"接管已落实"；已经进入 Android、应用或远端服务的行为仍需核对；
4. 用户交还后，保存交还意图；
5. 适配器取得**新的观察**；推理基于新观察给出**新的提议**；不自动恢复旧计划。

触摸检测只能作为额外的暂停信号，覆盖不了排队中的动作和所有形式的干预。本机串行出口负责给"接管"和"实际派发"排出先后。

### 4.3 观察的表示

节点树结构清晰但覆盖有限（自绘界面拿不到）；截图成本高、容易误读，还会扩大隐私暴露。默认**节点优先、按需截图**，并记录采集的非原子性和隐私限制。节点树和截图在采集期间可能不一致：标记为不完整，重新观察，不拼成一个虚构的快照。坐标动作只能作为明确的提议，不作为默认路径。

## 5 故障与恢复

| 故障 | 负责方 | 恢复方式 |
| --- | --- | --- |
| 回执丢失 | 端侧执行管理 | 查询原尝试和观察证据；没有回报不能证明未派发 |
| 进程崩溃 | 原端点的执行管理、持久工作 | 派发窗口保持未知；恢复观察和核对，**不重放点击** |
| 重复请求 | 持久工作、出口闸门 | 同身份去重；不得使用可写 watcher 和自动的动作重试 |
| 并发冲突 | 核心的设备控制、出口闸门 | 串行的控制代次；检测到窗口变化或用户干预时暂停；不保证任意应用都没有竞态 |
| 依赖不可用 | 端侧执行管理 | 服务关闭、设备离线、截图不可用时等待；不静默修改设备设置 |
| 迟到的结果 | 执行管理、预算 | 绑定原尝试和设备启动代次，追加证据；不得让已取消的任务恢复推进 |
| 用户接管 | 会话、任务编排、端侧核心 | 持久的控制事件，封闭旧资格；已派发的行为继续核对 |
| 模拟设备从快照恢复 | 端侧核心、评测环境 | 更新设备启动代次，旧凭据失效；原执行管理负责方的未知责任保留 |

## 6 不变量落实

| 不变量 | 怎样保证 | 怎样验证 |
| --- | --- | --- |
| G1 | 派发窗口是未知的；不重放没有幂等能力的点击 | 点击已入队、回报之前杀进程 |
| G2 | 平台反馈、可见状态、业务证据分别核验 | 手势完成但保存并未提交 |
| G3 | 尝试和接管控制先持久 | 接管回执和观察回报丢失 |
| G4 | 每次输入都绑定条件、授权、预算和控制代次 | 在派发边界插入接管或撤销 |
| G5 | 观察和设备操作全部经过出口；关闭隐藏的动作 | 观察打开网络、watcher 允许权限，都被拒绝 |
| G6 | 动作的选择和核验都回到核心 | GUI 上显示"已完成"不得裁决任务 |
| G7 | 限定应用、窗口、输入类别和资源 | 提议进入范围外的应用或权限设置 |
| G8 | 节点树、截图、OCR 的保存和同步分别授权 | 端侧专有的观察不上传 |
| G9 | 截图、节点树、OCR、摘要和缓存登记派生关系 | 删除后不得复用旧的定位材料 |
| G11 | 原设备负责；失联时不换设备重做 | 设备离线后任务等待 |
| G12 | 用户、设备绑定、控制和观察隔离 | 两个用户竞争同一设备，只有合法的持有方能派发 |

## 7 取舍

| 选择 | 得到 | 付出 |
| --- | --- | --- |
| 单动作粒度 | 故障边界清楚 | 往返多；一致性通过后可以引入有限的条件计划优化 |
| 节点优先、按需截图 | 减少内容暴露和观察成本 | 覆盖不了全部自绘界面 |
| 本机持久的接管 | 支持 S3 和 C7 | 增加核心的协调成本 |
| 模拟设备验收 | 可以复现 | 真机的支持范围必须另行验证 |

Android 后端的候选：AccessibilityService 便于在端侧运行，但受能力和分发前提约束；UI Automator 适合测试或受控设备，依赖控制通道；截图加坐标输入能覆盖自绘界面，但定位和遮挡风险高。交付时（M4，可选）默认先在受控的模拟设备上用 UI Automator，端侧的 AccessibilityService 另行验证适用范围。

**分发环境约束**：当前 Google Play 的政策限制通过 Accessibility API 自主发起、规划和执行动作；确定性的人为脚本和经过验证的残障辅助工具有不同的适用条件（[Google Play 无障碍政策](https://support.google.com/googleplay/android-developer/answer/10964491?hl=en)）。所以不得默认把通用的自主 GUI 产品放进这个分发渠道；支持范围必须分别声明为模拟设备、受控设备和真实的个人设备。

设备控制事实的归属，正式采纳前必须写成 ADR。

## 8 待定事项

- 首批后端、真实设备和分发环境；
- 选择器和局部前置条件能否把误操作降到可接受的程度；观察和派发之间的应用竞态仍然存在；
- 按需截图是否改善特定应用的定位和诊断。AndroidWorld 有 116 个任务、20 个应用，按实际设备状态评分，主要使用不需登录、可以离线的应用，其错误分析表明多模态输入并非普遍优于文本（[AndroidWorld](https://arxiv.org/html/2405.14573v2)）；这个基准的成绩不能外推到真实账户、支付或任意手机；
- 目标动作是否有足够的业务查询或停止证据；没有时明确保持未知。

## 9 M1 范围

M1 不运行 GUI 后端；共同的执行接口要能表达观察证据、不幂等和查询不足。GUI 适配器是 M4 的可选交付：交付时实现闭环、模拟设备和接管，真机的支持范围另行验证。参考评测使用多个有状态的模拟设备，它们要提供界面观察和由动作引起的可核对的变化。模拟设备上通过，不等于真实手机平台已受支持。

## 10 测试要点

**效果评测方法。**参照 AndroidWorld，为每个任务提供初始化、状态检查和清理，用系统和应用的实际状态衡量效果（[AndroidWorld](https://arxiv.org/abs/2405.14573)），另加 Lerna 特有的接管、撤权和未知效果测试。核验的是条件和合法动作，不要求每道题只有一种动作路线。

| 用例 | 核心断言 |
| --- | --- |
| 输入入队后杀进程 | 保持未知，不重复点击 |
| 接管插在出口检查之前、之后、Android 入队之后 | 接管之后旧资格无法派发；在途的行为继续核对 |
| 旧节点、同文本的多个按钮、屏幕旋转、遮挡、弹窗 | 有歧义就不猜，重新观察 |
| 平台正常返回但文本没变；UI 稳定但后台尚未提交 | 完成门禁不通过 |
| 观察打开网络、watcher 允许权限、自动滚动 | 未准入的行为被拒绝 |
| 用户做了相似的操作后交还 | 没有证据时不归因给旧尝试；重新提议 |
| 节点树和截图采集期间变化；模拟设备从快照恢复 | 不虚构快照；旧的启动代次失效 |
| 界面或节点元数据中注入指令 | 内容不得改变授权、条件或执行范围 |

效果失败至少区分感知、推理、应用知识、定位和环境问题；另外统计重复输入、假完成、接管竞态和证据泄露等契约失败。
