- 上游：[项目目标](../project-goals.md)、[执行适配器接口](../ports/executor/README.md)、[任务编排](../core/tasks/README.md)、[授权](../core/grants/README.md)

外部 Agent 是另一个独立运行的智能体。Lerna 把**一次外部委派表达为一个长时间运行的动作**，由原来的动作账本负责：远端的进展和产物是回报和证据，远端的"完成"不得直接映射为 Lerna 的成功。如果委派承载的是一个子目标，Lerna 的子任务由任务编排创建并保持唯一的负责方；远端协议里的任务标识只是一个外部绑定，不得代替 Lerna 的任务。

本设计的要点：

- **两档接入**：只交付内容的委派门槛较低；**要让远端自主执行外部行动，远端必须能落实收缩后的权限、预算上限、行动范围、恢复和停止核对**，并通过一致性认证；
- **首次交接必须可恢复**：首次接单的回执丢失时，要能按客户端的交接标识查到远端任务；做不到的目标，回执丢失后保持未知，**不重新委派**；
- **快照是恢复的底线**：流式更新和推送只是提示；有可靠的事件标识时才按增量应用；
- **取消只是请求**：发出取消后继续核对原委派，不创建新的委派来回避未知。

## 1 职责与边界

适配器负责：发现目标、提交一次委派、查询、接收进展和产物、发送取消或补充输入、回报证据。动作账本持有效果和收尾责任；任务编排持有子任务、取消和 Result。

| 档位 | 前提 |
| --- | --- |
| 内容产出 | 只交付获准的内容；约定用途、保留、成本和可以验证的产物 |
| 自主外部行动 | 远端能落实收缩后的权限、预算上限、行动范围、恢复和停止核对；通过对应的一致性认证 |

只有 Agent Card 或文字承诺的目标，得不到自主写入的委派。外部 Agent 请求新的工具、数据或授权时，回到核心处理，不直接连接本地的适配器。

## 2 对象与状态

| 对象 | 关键字段 | 用途 |
| --- | --- | --- |
| 目标描述 | 服务身份、Agent Card 摘要、Agent 版本、协议和绑定、能力、必需的扩展 | 固定互操作的范围 |
| 委派输入 | 原动作和尝试、交接标识、条件版本、子目标、输出条件、内容引用 | 固定这次的责任 |
| 权限限制 | 来源授权、收缩后的范围、资源、期限、凭据引用、再委派规则 | 约束远端的行为 |
| 成本约束 | 报价或费用上界、预算引用、收费来源、用量查询 | 不得只约束本地的费用 |
| 接纳绑定 | 客户端交接标识、远端任务标识、接单证据、去重和查询的期限 | 恢复首次回执的窗口 |
| 进展证据 | 原远端绑定、事件身份或游标、时间、状态、部分效果 | 进展不等于完成 |
| 产物 | 产物身份、版本、完整性、摘要、来源和派生关系 | 核验输出与条件 |
| 收尾证据 | 远端终态、是否仍在执行、外部效果、最终费用或待核对的费用 | 核验取消或完成的后果 |

| 维度 | 状态转换 |
| --- | --- |
| 本地执行阶段 | 待提交 → 接单结果未知 → 已绑定远端任务 → 运行中 / 等待输入 → 已取得远端终态 |
| 取消处理 | 未请求 → 取消已保存 → 请求已发出 / 结果不明 → 已证实停止 / 仍需核对 |
| 效果与收尾 | 全程由动作账本独立维护；远端终态不直接写成本地成功 |

A2A 的 `INPUT_REQUIRED`、`AUTH_REQUIRED` 是进展证据；补充输入或凭据属于新的受控推进，不由适配器自行满足。

## 3 接口

| 接口 | 输入 → 输出 | 成功含义 | 错误 |
| --- | --- | --- | --- |
| 描述目标 | 固定的 Card 引用、访问凭据 → 目标能力快照 | 拿到经过身份校验的材料 | 身份、版本或必需扩展不支持 |
| 委派 | 原尝试、交接标识、条件、限制和内容 → 接纳或执行回报 | 拿到接单证据；它是否持久取决于目标的约定 | 接单不明、权限不足、预算无法约束、协议错误 |
| 查询 | 原尝试、交接标识或远端任务标识 → 快照和证据 | 查到原委派；**不重新委派** | 首次标识丢失且无法查询、任务已过期、不可访问 |
| 接收进展 | 已认证的事件和原绑定 → 核心接纳回执 | 核心已保存事件和内容 | 任务不符、用户不符、重复、缺块、保存失败 |
| 取消或补充输入 | 核心的控制命令、原远端绑定、新凭据 → 控制回报 | 拿到请求的处理信息 | 不可取消、已终态、请求不明、授权不足 |

只有经过认证的目标去重约定，才能支持重发委派。A2A 原生的查询依赖远端任务标识；按客户端的交接标识找回首次接单，必须另外约定扩展或目标公开的接口，不得假定 `GetTask` 已经提供了这个能力。

## 4 关键流程

1. 核心安排目标的发现和认证，保存目标版本、内容用途和可靠性能力的证据；
2. 推理提议子目标和目标 Agent；任务编排持久保存子任务、收缩后的授权、预算和委派的动作意图；
3. 按 R7 交给动作账本，固定客户端交接标识、参数指纹、目标和协议版本；
4. 出口检查当前授权、预算、内容同步范围和远端限制，**只提交一次**；
5. 目标按已认证的约定持久接纳并返回原任务的绑定，本方持久保存回执。普通的 A2A 响应没有这种保证时，只按取得的证据记录；
6. 进展和产物经过身份、范围和版本检查，由内容治理和动作账本持久接纳之后，再确认推送已收到；断线恢复时先查快照；
7. 远端完成后，核验产物、目标条件、部分外部效果和迟到的边界；任务编排执行 G2；
8. 取消时，任务编排先保存"停止推进"，动作账本保存取消的控制工作；发送取消请求并持续核对原委派。

没有事件身份或偏移量的追加块，重连后不得直接重复拼接：取得完整的产物快照，或者把产物标记为不完整。

A2A v1.0.0 的几个特性决定了这些规则：新任务的标识由服务端生成，首次接单回执丢失时客户端可能不知道远端任务标识；发送消息的幂等是 MAY，取消只是"尝试"，可能遇到不可取消的任务（[A2A v1.0.0 规范](https://github.com/a2aproject/A2A/blob/v1.0.0/docs/specification.md)）；产物更新有追加和"最后一块"等字段，但不要求每个业务更新都带全局的去重序号，推送可能重复，发送方也可能停止重试（[a2a.proto](https://github.com/a2aproject/A2A/blob/v1.0.0/specification/a2a.proto)）。协议兼容和服务持久是两回事：a2a-python v0.3.0 的 `InMemoryTaskStore` 明确会在进程停止后丢失任务（[inmemory_task_store.py](https://github.com/a2aproject/a2a-python/blob/v0.3.0/src/a2a/server/tasks/inmemory_task_store.py)），所以生产接入认证必须测试对方的恢复行为，不得凭 SDK 的名字推定。

## 5 故障与恢复

| 故障 | 负责方 | 恢复方式 |
| --- | --- | --- |
| 接单回执丢失 | 动作账本 | 按客户端交接标识查询；不支持就保持未知，**不再次委派** |
| 本地进程崩溃 | 原端点的动作账本、持久工作 | 恢复绑定、查询和控制工作，不重新创建远端任务 |
| 重复请求 | 本地持久工作、目标系统 | 本地去重；只按经过验证的远端约定重发；同身份不同参数拒绝 |
| 输入与取消并发 | 任务编排、动作账本、目标系统 | 本地持久排序；取远端的当前状态；已终态的不再追加推进 |
| 迟到的完成或费用 | 动作账本、预算、内容治理 | 接纳原委派的证据；不撤销用户的取消，也不抹掉费用 |
| 远端数据丢失或返回 404 | 动作账本 | 不推断为未执行；检查过期、访问范围和目标的恢复能力 |
| 流断线、重复或缺块 | 动作账本、内容治理 | 有游标就按约定恢复；否则读取完整快照 |
| 取消回报丢失 | 动作账本 | 查询原任务；可以按协议重试**取消**，但不重试**委派** |
| 远端违反权限或效果约定 | 授权、动作账本、任务编排 | 阻止新的委派和新的凭据；记录冲突，核对实际后果，保留原责任 |

## 6 不变量落实

| 不变量 | 怎样保证 | 怎样验证 |
| --- | --- | --- |
| G1 | 接单不明时不重新委派；终态与效果分开 | 远端接单后丢失首次回执 |
| G2 | 产物、条件、外部效果和收尾分别核验 | 远端 completed 但缺产物，或仍有在途的写入 |
| G3 | 本方意图、目标接纳、本方回执按 R7 | 双方在各持久化点前后崩溃 |
| G4 | 委派、补充输入和凭据都经过核心 | 远端请求额外操作，不会自动执行 |
| G5 | 本方的协议和下载出口全覆盖；自主行动要求远端落实约定 | 回调旁路、未申报的远端工具行为 |
| G6 | 远端的判断作为证据，核心裁决 | "任务完成"文本不得关闭本地任务 |
| G7 | 收缩后的凭据、范围和再委派资格 | 远端试图访问父任务的其他资源 |
| G8 | 交付的内容、用途和后续使用分别授权 | 端侧专有内容的发送被拒绝 |
| G9 | 产物和缓存登记派生关系；远端的保留和删除保证纳入认证；严格删除的内容不发给无法验证删除的远端 | 撤回之后，迟到的产物不会重新启用来源 |
| G10 | 每项真实的计费来源去重；取消之后仍然登记 | 重复账单、追加费用、账单更正 |
| G11 | 本地任务与原委派的绑定保持不变 | 超时后不换一个 Agent 创建同目标的新任务 |
| G12 | 远端账户、任务、回调和内容隔离 | 相同的远端标识、账户错误的推送，跨用户测试 |

令牌交换也不能保证后续权限只收缩：RFC 8693 支持令牌交换，但输入令牌被撤销后，撤销并不会自动传播到换出来的令牌（[RFC 8693 §2.1](https://www.rfc-editor.org/rfc/rfc8693.html#section-2.1)）。所以必须校验实际签发的范围，并明确撤销的传播方式和远端出口的落实方式。

## 7 取舍

| 选择 | 得到 | 付出 |
| --- | --- | --- |
| 采用 A2A 互操作，补充首次交接恢复、权限和收尾的前提 | 复用生态 | 接入门槛提高 |
| 完整快照作为恢复底线 | 恢复简单可靠 | 轮询和传输成本较高 |
| 无法约束的外部 Agent 不开放自主写入委派 | 守住 G7 | 部分外部能力无法使用 |
| 取消后继续核对 | 不假装停止 | 取消后可能长期保持未知 |

被否决：失联后发起新的委派（违反 G1、G11）；把父任务的凭据传给远端（扩大权限）；只用文字约束远端（运行时约束不了）；取消回执一到就关闭（可能是"假停止"）；自动补偿（超出项目边界，而且会产生新的效果，补偿必须作为新提议重新准入）。

接入认证的标准、首次交接标识的规则，正式采纳前必须写成 ADR。

## 8 待定事项

- A2A 的绑定方式、兼容版本、首次交接的查询扩展和首批目标；
- 目标的持久接纳和去重保留期能否覆盖最长的恢复时间；
- 远端能否真正落实权限、费用上界、再委派限制和撤销传播；
- 目标的终态能否证明没有未披露的在途效果；不能时继续核对；
- 远端产物和内容清理的证据能否达到 C7、G9 要求的可验证程度。

## 9 M1 范围

M1 不实现外部 Agent 的运行时接入；共同的身份和回报格式不得依赖短连接。M4 实现委派、进展、取消和核对。

## 10 测试要点

| 用例 | 核心断言 |
| --- | --- |
| 接单后首次回执丢失，还没有远端标识 | 按交接标识恢复；不支持时保持未知 |
| 目标对重复的 `messageId` 不去重 | 不把协议原生字段当成幂等保证 |
| 流重复、缺块、乱序、没有事件身份 | 不重复拼接；恢复完整快照或标记为不完整 |
| 远端 completed，但产物不完整或仍有在途动作 | 本地不成功 |
| 取消后远端完成、返回 404、不可取消 | 查询原委派，不宣称已撤回效果 |
| 远端重启丢失任务 | 保留责任，不创建替代的委派 |
| 远端索取父凭据或请求再委派 | 权限不得扩大 |
| 账单重复、追加和更正 | 一项收费只计一次；多项真实收费全部保留 |
