# 验证、依赖与交付

[总览](README.md) · [处理机制](mechanisms.md) · [同步与恢复](synchronization.md) · [记录与接口](contracts.md)

本页区分设计约束与运行证据。当前只有详细设计与验收方案，未提供可运行记忆服务、驱动、同步或索引实现；不能据文档检查报告 L2–L4、V1／V2 或服务规模达标。

<a id="dependencies"></a>
## 1. 依赖与缺席行为

| 提供方 | 必须提供的保证 | 缺席行为与继续者 |
| --- | --- | --- |
| 身份与授权／受信入口 | 当前用户／actor／owner、Evaluate／BeginUse／ReadUse、管理意图、有限使用与出口约束 | 服务拒绝或报告依据缺口；使用未知查原键，用户经受信入口恢复权限 |
| 来源权威／资源适配器 | 按[共同来源合同](../content-and-provenance.md#bindings)提供精确资源、修订／摘要、当前证明、用途／驻留／保留约束及完整来源；具体外部适配器仍待交付 | 只开放能在记忆权威闭环的用户声明；接入内容或运行记录缺解析器时不提取／保存，不把来源不可达解释为可用 |
| 任务核心／组装器 | 固定任务用途与预算、来源继承、正常操作准入、三个使用阶段的当前复核 | 首期仍可用显式管理；无核心接入不宣称个性化或自动提取可用。可选记忆缺失继续任务，必要缺失保存 blocker |
| 大脑／能力与执行 | 受限提取生成、精确记忆能力声明、原操作／来源绑定、真实结果及取消核对 | 不发布提取／修改能力，只保留服务内部接口；不得用模型输出或任务终态替代保存回执 |
| 启动组装器／本地宿主 | 固定权威路由、独占账本、旧实例隔离、受控存储和网络、全局／用户配额配置 | 无唯一写资格不写；无出口隔离不开放禁止外发数据；无配额不接纳新内容 |
| 索引适配器 | 精确候选、profile／代次、水位、连续应用／重建及删除能力 | 有界权威扫描或 partial；权威仍可完成修改和删除，不等待索引来裁决 |
| 连接适配器／领域 profile | 两处可靠交接、本轮恢复绑定、完整来源、当前披露复核与应用回执 | 远程访问／同步关闭，本地闭环不受影响；实现与跨端契约须共同交付 |
| 备份／平台清理适配器 | 受控载体清单、保留边界、清理结果、防旧备份复活的恢复门禁 | 只确认逻辑禁用并显示物理清理缺口；不能满足强删除要求的数据在保存／复制前拒绝 |
| 时间／离线适配器 | 可信时间、防回滚、有效离线许可及来源新鲜度依据 | 离线关闭；连接恢复后重新核对，不因本地有缓存就继续 |

来源适配器沿[共同合同](../content-and-provenance.md#bindings)回答“这个精确版本现在是否允许用于该接收方”，不能只提供 URL 或内容哈希。静态公开内容的时效和重新取证按该合同处理；本提供端对象的关闭／清理与外部派生副本的清理边界见[到期与关闭](../content-and-provenance.md#closure)，不以内容上传成功代替记忆来源成立。

首期不保证仅凭旧 SQLite 备份恢复服务。备份适配器还须提供可证明完整的命令／删除尾部和当前账本资格；其保存位置必须独立于可能回滚的旧快照。此适配器尚未实现，缺失时只允许验证备份内容，不开放恢复后服务。

<a id="observability"></a>
## 2. 观测与处置入口

记录查询／命令／任务关联、权威和账本代次、当前修订、来源与策略版本、使用依据、候选及返回数、排除原因、partial 原因、索引水位、修改冲突、原命令核对、清理分项进度及用量。内容、完整查询文本、许可凭据和模型隐含推理默认不进入诊断日志；来源元数据的观测／评测复用也要获准。

耗时分别计入授权、检索、回源／来源核对、提交、索引追平、同步恢复和删除传播。按用户记录扫描字节、存储／索引／备份体积、待提交／blocked 工作年龄和配额拒绝；日志缺失不影响命令和清理责任。

用户在[管理入口](contracts.md#interfaces)可以查看来源、纠正、限制用途、删除并查询残留。受信运维入口仅提供重试原维护工作、停用／重建索引、关闭视图、隔离旧实例后恢复账本；每项有固定命令及当前管理权限。它不允许把未知写成成功、清空墓碑绕过去重、扩大许可或手工宣称备份已删除。依赖不可恢复时保留一次通知与缺口，停止无预算的轮询。

## 3. 运行验收矩阵

每例冻结服务／数据库／索引／提取 profile、用户及许可、来源样本、时间依据、故障位置和预算，观察实际返回字节、权威记录、使用回执、任务输出与载体清理结果。先用确定性来源和模型模拟器验证契约，再验证真实设备／模型；以下全部为待实施用例。

| 编号 | 前置条件与刺激／故障 | 预期可观察结果 | 保证／目标 |
| --- | --- | --- | --- |
| MS-01 | 显式保存总览偏好；新技术评审任务读取，非适用任务对照 | 保存回执可查，目标任务格式改变，其他任务不使用；记忆／任务成功分别证明 | M1、M7／C2、V1 |
| MS-02 | 事实、偏好、推断、效果未知经验混合，模型试图都标 fact | 类型和来源不丢失，未知经验不成成功行动依据；用户当前指令优先 | M1／C1、C2、V2 |
| MS-03 | 只获准读取／上下文；分别尝试提取、保存、嵌入外发、同步 | 未批准用途无实际写入或外发，拒绝有安全原因；没有隐含长期记忆 | M2、M6／C2、C7 |
| MS-04 | 生成输入含私密 M 和公开 P，候选只引用 P；来源闭包循环或超限 | 输出仍约束于 M；无法完整绑定则拒绝，不能截断后保存 | M1、M6／C2、C7 |

### 质量、效果与容量口径

检索评测固定获准且适用的人工标注集合，分别报告字面检索召回率、precision@k、冲突暴露、partial 比例及 p50／p95 延迟；不把未扫描区域排除出应召回分母。授权隔离与旧版本泄露单独作为必须零违例的契约门槛，不能混入相关性平均分掩盖。

个性化采用同一任务的“无记忆／有效记忆／已纠正／已删除”配对样本，观察实际答案或行动选择，记录输入差异、引用来源及任务验收结果。V1 同时检查当前取证与时效，不用历史答案替代联网依据；V2 用有状态模拟设备证明旧经验不会绕过当前观察、应用版本及用户接管条件。专项效果仍遵守[项目验收目标](../../harness-project-goals.md)，记忆存取成功率不能替代 90%／95% 的整体调用和任务指标。

经验更新可在原许可内自动生效；声称改善时须固定基线、样本、策略／模型／能力版本和预算，记录收益、退化及来源。回滚采用新的获准修订并重新核对来源，不能重新激活已删或撤权的旧内容。Skill／策略／代码发布仍归改进管理器，不因记忆评测通过而获得发布权限。

容量先测每用户一万条、不同正文／来源长度与查询分布，再测热用户和大量低活跃用户。报告每秒读取／修改、WAL 与索引增长、备份空间、恢复时间、清理尾延迟及公平性。扩展到多机存储前验证同用户原子边界和迁移去重，不依据“十万在线”直接填写检索 QPS。

## 4. 跨模块待决范围

以下提案均未采用，本地显式管理、来源复核和受控提取继续按现行合同实现；远程访问、外部副本全链清理及自动触发受所列条件限制。跨模块依赖和统一状态见[待决索引](../open-decisions.md)。MS-P2、MS-P3 分别维护与观测改进合并后的唯一详细提案。

| 提案 | 问题、推荐与具体联动范围 | 取舍、用户决定与验证 |
| --- | --- | --- |
| MS-P1：记忆跨端领域 profile | v1 无记忆请求／视图载荷，远端不能凭 grant_ref 取得完整来源和应用证据。推荐在本地验证后增加版本化记忆访问／修改核对／视图恢复 profile，复用可靠交接并与[身份 P1](../identity-and-authorization/validation.md#proposals)统一来源和主体绑定。涉及本模块、endpoint-cloud-protocol 的 extensions／recovery-and-control、对应 Schema／manifest／示例／校验；内核同步内部调用与远端适配说明 | 直接 RPC 工作少但缺少可靠恢复与当前用途保证，不采用。需确定远程部署范围及领域合同；采用后以 MS-08～11、16～19 验证两种独立实现，不能仅跑线格式检查 |
| MS-P2／OI-P2：外部派生副本的删除回执 | 当前使用前复核与[本提供端清理](../content-and-provenance.md#closure)已分别定义，但任务快照、模型、UI 和评测派生物之间没有全链清理交接。建议受管持有者登记精确来源修订、用途、受控副本及期限，来源关闭后分别返回停止使用、载体清理和不可撤回披露进度。涉及 task-kernel/storage-and-interfaces、brain-system/contracts-and-runtime、application-and-interaction、内容提供方、本模块及[观测评测的数据管理](../observation-and-improvement/observation.md#data)；改变关键交互时同步全景图源及导出 | 首期维持使用前复核和明确物理清理缺口；评测仍拒绝导入无法落实持续撤回要求的外部持久数据。更强删除增加持有者反向索引、传播及保留成本；需确定受管载体范围、离线关闭窗口与删除完成保证。用 MS-12～15、OI-13～16 加持有者失联、回执丢失和旧备份验证 |
| MS-P3／OI-P3：任务终态自动触发 | 当前使用[显式记忆提取任务](contracts.md#integration)、[Improvement.Propose](../observation-and-improvement/contracts.md#interfaces)及[普通候选生成任务](../observation-and-improvement/improvement.md)；核心没有终态后自动触发与预算交接。建议采用自动化时，由应用策略在原任务事实提交后持久登记独立提取／改进任务，以原终态修订和策略版本形成幂等触发键，固定来源、用途、授权、期限及独立预算，不阻塞原任务终态。涉及任务内核持久交接、应用策略、本模块及观测改进的候选入口 | 避免记忆服务或日志消费者内隐藏模型循环，代价是应用需维护触发去重、频率和预算。需确定触发任务类型、用途与费用归属；验证终态后崩溃、重复触发、撤权、预算耗尽及生成失败，均不得改写原任务结果或自动启用改进产物 |

上述增强不阻塞本地显式闭环。真实连接器、提取模型、全局配额和平台清理能力由参考实现按部署固定并通过上述用例验收；未提供对应实现前，入口按依赖表受限。
