# 记录与接口

[总览](README.md) · [处理机制](mechanisms.md) · [同步与恢复](synchronization.md) · [验证与待决](validation.md)

本页集中定义本模块的逻辑值与接口；同进程调用与[跨端 profile 1](synchronization.md#wire)共享行为，线结构见 [memory Schema](../endpoint-communication/schemas/memory.schema.json)。所有调用沿用[可信 RequestContext](../identity-and-authorization/contracts.md#identity)。用户、行动主体、处理服务和活动 owner 从可信入口建立，不能由业务参数覆盖。ID、时间及修订的外部编码沿[公共字段](../endpoint-communication/wire-format.md)，修订递增不环绕复用。

<a id="records"></a>
## 1. 记录、来源与策略

| 记录字段组 | 必需内容与约束 |
| --- | --- |
| 身份 | `user_id`、`authority_id`、`memory_id`；ID 创建后不变、不复用；单用户固定权威，错投不另建记录 |
| 内容版本 | `revision`、`kind`、获准正文、内容摘要、`schema_version`；正文按 UTF-8 有界文本或固定结构保存，修订不可改写；默认正文直接进入事务库 |
| 信息类型 | `fact`、`preference`、`inference`、`experience` 四类；fact 表示来源作出的事实陈述，不等于系统证明为真 |
| 类型补充 | fact 带陈述对象；preference 带偏好维度；inference 带推导方法／模型版本及不确定性说明；experience 带任务／操作事实、适用能力和环境版本、结果保证类别，未知效果必须保留未知 |
| 时间 | `observed_at` 为来源观察时点，`recorded_at` 为权威提交时点；`valid_from`、可选 `valid_until` 限定业务适用期；`review_after` 只触发复查提示，不延长有效期；策略另给数据保留截止，不能与业务有效期互相替代 |
| 可信度 | `confidence` 含数值或等级、给出方和依据／校准版本；未知明确写 unknown。用户声明的来源身份可信与其陈述真假分开，模型原始分数不当校准概率 |
| 适用范围 | 有限结构条件：任务类型、项目／容器、设备／应用／能力版本等；空集只在许可明确允许全用户范围时成立。未知条件按不匹配，不由模型猜测 |
| 匹配与冲突 | 规范标签；可选 `conflict_key` 及生成它的策略版本，表示已知同维度／同范围的竞争组。没有竞争键表示未识别，不表示无矛盾；键及标签不得扩大适用或授权范围 |
| 来源 | `source_bindings` 为受信服务验证的完整闭包；每项保存来源权威、资源 ID、精确修订／内容摘要、来源角色、获取时间、用途／接收方限制、权限及当前状态证明引用 |
| 生成依据 | 显式输入的受信原命令／用户确认引用，或提取任务／操作、固定输入闭包、提取规则／模型版本；提供者自报来源不算受信证明 |
| 策略 | `policy_ref` 及修订；原始数据、索引、派生记忆、返回结果四类产物分别列可存储／处理位置、允许用途／接收方、保留期限、同步字段和离线新鲜度；未声明的同步／外发禁止 |
| 生命周期 | 当前记录指针指向最新修订；删除后指向不可复活的墓碑。是否可用于一次请求由当前修订、有效期、来源与权限共同导出，不另存笼统的 active 布尔值 |

用户通过管理入口直接作出的陈述在本权威建立来源根，根内容、用户身份关联、保存依据与记忆修订共同提交。该根允许独立于临时聊天正文保留的前提是用户明确允许保存这项陈述及必要来源元数据；否则不能通过复制正文规避原来源的保留限制。接入文件、任务输出和模型提取产物始终保留其真实输入闭包。

引用另一条记忆时，闭包同时包含该记忆的精确修订和它的全部来源。候选来源由任务快照／受信适配器提供，记忆服务解析并展开；模型给出的引用只能补充说明，不能缩小集合。循环、引用目标记录任一旧修订、未知来源或闭包超限拒绝保存，不截断闭包。纠正后的新修订以新的用户声明或新取证作为依据；审计关联旧版本不等于语义上继续依赖已失效内容。模型已读目标旧版本时的替换限制见[提取规则](mechanisms.md#mutation)。

`policy_ref` 表达资源硬约束，不创建许可；实际有效范围为资源策略与本次全部许可的交集。改变硬约束是用户管理操作，Agent 不得放宽。收紧策略同样递增记录修订并触发失效；扩大未来用途须有对应新许可，不能仅改策略获得授权。

<a id="storage"></a>
## 2. 权威存储与原子关系

以下是逻辑记录，不要求逐行建表。全部键、索引、缓存、游标和内容摘要的查找均带受信用户作用域，禁止跨用户去重。

| 记录 | 键与主要内容 | 不可拆开的提交关系 |
| --- | --- | --- |
| 用户记忆控制 | 用户、固定权威及账本代次、单调 `change_seq`、配额与恢复门禁 | 当前写资格、容量预留、修订变更按同一提交顺序裁决 |
| 记忆当前值／修订 | 用户／memory_id／revision、上一版、上述内容及来源、当前指针／墓碑 | 修改时写新版本、切当前指针，并追加变化；旧版本不因历史可读而可用于新任务 |
| 来源关系 | 每一保存修订的完整闭包、反向依赖索引、来源根与已知失效 | 本地根失效和读取门禁同事务；反向索引用于找清理工作，读取仍逐来源验证 |
| 命令 | 用户／command_id、固定意图、预期修订、期限、授权使用关联、准备／最终回执 | `committed`／`rejected`／`closed_without_commit` 结论与其依据固定；提交内容与 committed 回执同事务 |
| 变化记录 | 用户／change_seq、记录 ID 与新修订、变更类别、最小获准数据 | 与记忆变更及维护责任同事务；同步和索引水位不能越过缺口 |
| 维护工作 | 唯一工作键、种类、目标修订／代次、状态、领取代次、重试／期限、缺口；保留到期清理含 not_before 和截止 | 创建责任与原变更同事务；完成及后续责任同事务。索引、清理、视图交接共用此表，不另建业务调度器 |
| 视图／副本 | 视图绑定、快照清单／固定切点、连续页与交接责任；副本的暂存区、当前代次、应用位置 | 接收方内容、移除项及应用游标同事务；完整快照就绪才替换可见代次 |
| 清理跟踪 | 原删除／失效命令、已封闭读取修订、各载体的清理位置／回执／缺口、备份边界 | 不随原响应或索引工作完成删除；外部未确认项保留 |

命令身份采用用户内唯一 `command_id`。经执行系统进入时直接绑定原 `operation_id`；用户入口为每次显式意图固定一个 UUID，不随重连重建。意图包括接口版本、行动主体、权威、动作、目标、期望修订、规范内容、来源、策略、用途、接收方和原期限。规范化规则随服务版本固定，处理期间保存规范值及摘要；同 ID 不同意图拒绝。正文必须清理时先终结或封闭 prepared 命令，再清理规范正文，仅保留获准的规范化版本、受保护摘要、原身份和最小结果；最终命令不能重新进入 prepared。无法继续证明同意图的旧键只允许返回历史缺口，不接受重新写入。

<a id="interfaces"></a>
## 3. 服务接口

全部接口带当前用途、实际接收方／位置、调用期限和有限资源上限。读取正文和披露内容均须 `BeginUse`；纯状态／用途预检采用 `Evaluate`，历史命令及清理核对按当前最小状态披露权处理，不能借此返回正文。有限内容批次具有稳定使用身份，Search 仅支持 continuous；once 只开放可以预先固定版本、投影和完整来源的 Read 或 Mutate，具体见[使用门禁](mechanisms.md#authorization)。

| 接口 | 输入 → 输出 | 业务含义与调用方下一步 |
| --- | --- | --- |
| `Search` | 有限查询文本／结构过滤、任务适用条件、top_k、扫描／返回字节限额、可选游标 → `ReadResult` | 返回获准当前记录；候选不足、扫描截断、索引落后或来源缺口分别报告，不将空页解释为用户没有记忆 |
| `Read` | 有界精确 memory_id 列表、可选期望修订 → `ReadResult` | 当前版本不匹配时报告 stale_reference；不默默换新版本继续旧意图。查看历史需管理用途和独立权限 |
| `Revalidate` | 固定记忆引用及完整绑定、即将进行的用途／接收方 → 当前适用证明或逐项缺口 | 只复核，返回证明不等于后续模块的启动许可；需要新内容时重新 Read／Build |
| `Mutate` | `create`／`replace`／`delete`／`restrict`，固定命令、目标、expected_revision、内容／来源或策略 → `MutationResult` | create 必须期望不存在（0）；其他动作要求当前精确修订。replace 提供完整新版本，delete 禁用并登记清理；不支持盲目 upsert |
| `ReadCommand` | 原 command_id、当前查询权限 → 原提交事实与可查缺口 | 用于响应丢失核对，历史 committed 不是当前内容／披露许可；未见记录不证明永不提交 |
| `CloseCommand` | 原完整命令身份及意图、当前控制权限 → 原最终结果或 closed_without_commit | 与原修改竞争同一命令键；关闭先提交则迟到原修改被拒，修改先提交则返回 committed。不能用关闭回滚已生效内容 |
| `ReadCleanup` | 原删除／失效命令 → 本地禁用、各载体清理进度、残留与缺口 | 用户可重试原清理或收紧访问；不能手填“全部已删”。清理重试由本模块按原责任执行 |

`ReadResult` 的权威字段组如下：

| 字段组 | 内容 |
| --- | --- |
| `items` | 获准投影、精确记忆引用、类型／时间／范围、完整绑定、当前适用证明；不向调用方返回仅索引命中的裸候选 |
| 读取依据 | 权威、读取时点、当前记录修订、检索 profile／索引代次及水位、策略／授权证明有效期；不是跨模块全局快照 |
| 完整性 | `coverage=complete/partial` 指在声明的过滤、匹配算法及数据切点上是否查完；`truncated`、可续游标、来源／索引／容量缺口。complete 不承诺语义上召回所有相关记忆 |
| 冲突 | `conflict_refs` 仅列有权披露的竞争记录，及检测范围；同义内容未识别不能宣称无语义冲突 |

`MutationResult` 分别表达 `committed`（固定结果修订及提交序号）、`rejected`（确定拒绝及原因）、`unknown`（需查原键）。`ReadCommand` 返回 `prepared`、`committed`、`rejected`、`closed_without_commit`、`not_observed` 或 `recovery_gap`；其中 prepared／not_observed／recovery_gap 均不能当未生效，unknown 是调用观察结果而非持久业务状态。delete 的 committed 只证明权威逻辑禁用及清理责任已保存。

管理入口提供分页查看、显示来源／类型／范围、纠正、限制用途、删除和查看清理状态，直接调用这些内部接口。它从真实用户会话建立管理权限，仍经已安装资源动作和授权链检查；Agent 无隐含本人管理资格。确认显示的对象、内容摘要与范围必须绑定原命令，普通任务输入已接纳不能代替许可签发。

<a id="integration"></a>
## 4. 任务提取与能力接入

记忆服务不主动调用模型。应用可显式提交，或按[用户 opt-in 策略](#automation)触发普通有限任务：“从这些已授权内容提取适用的偏好／经验并保存”。数据取得与模型处理沿任务、大脑和执行模块现有契约进行。大脑的 `act` 提案调用本模块提供的有限记忆驱动，核心正常准入，执行端固定原操作后调用 `Mutate`。不增加新的提案种类，也不让模型直写存储。

| 记忆驱动声明项 | 首期要求 |
| --- | --- |
| 有限操作 | 一次原操作对应一条 create／replace／delete／restrict；批量提取拆成有上限的多个正常操作，不提供任意后台循环 |
| 参数与来源 | 业务参数包含目标、期望修订、类型、正文及范围；来源和原意图从受信操作／快照关联取得，不能信任 arguments 中模型自报的闭包 |
| 授权使用 | 首期驱动与服务组合为执行端同一个已登记资源处理主体及 owner，共用完整 UseIntent、规范化器、原 operation_id、unit_no=1 和 source_role 映射；协调器取得与服务复核的是同一处理端同一使用。回执不可转交不同 processor；独立服务不能沿用此组合，须先定义经验证的适配 profile |
| 效果证据 | committed 回执证明记忆权威已应用，delete 仅证明已逻辑禁用；索引可见性、云端应用和物理清理分别报告；执行端按声明映射效果 |
| 查询与取消 | 查询沿 ReadCommand；取消未提交命令映射 CloseCommand；已经 committed 不撤回，撤销内容需新的获准修改。响应丢失不能再提取生成另一条替身 |
| 声明缺席 | 按[准确声明](../capability-and-execution/catalog-and-contracts.md#declaration)装配并验证参数／结果格式前不发布能力；本次未交付可安装驱动或 Schema 包 |

模型候选默认 `inference`；只有可核对原文的明确事实／偏好才能按对应类型保存，并标出它是引用／提取及验证方式。experience 必须关联正式操作事实，效果未知不能提取成成功操作知识。候选之间可以并存，不能凭较高分数覆盖用户已确认修订。自动常规写入要求持续保存许可、适用范围及来源齐备；缺长期保存权限时只能在原任务获准期限内使用。

<a id="errors"></a>
## 5. 错误、取消与版本

先核对身份和可访问性，再读原命令、比较意图、判定新操作前提。下列原因是内部枚举；跨端 profile 已固定为 `harness.memory.*@1`；适配器将内部原因映射到[既有公共错误](../identity-and-authorization/contracts.md#errors)或经批准的领域声明。

| 原因 | 当前调用方行为 |
| --- | --- |
| unauthenticated／forbidden | 停止，必要时走受信重新认证／授权；不能泄露其他用户对象是否存在 |
| identity_conflict | 原键意图不一致，拒绝并保留原记录；不能自动换键绕过 |
| revision_conflict／stale_reference | 读取当前版本，用户或新任务重新判断；同一命令保持原拒绝，改变意图须新命令 |
| source_gap／policy_unavailable | 该条不返回／不新保存；调用方等待提供方或移除可选记忆，不能使用缓存的旧 allow |
| unsupported／constraint_unenforceable | 关闭该模式，补齐实现／版本或调整获准范围后再调用；不降级丢失隐私条件 |
| overloaded／storage_full | 确定未接纳时按原期限退避；已有责任不删除，控制、核对和清理用预留容量 |
| cursor_expired／view_invalid | 重开查询／恢复；不跳过缺失页，也不沿用旧游标复活数据 |
| commit_unknown／recovery_gap | 查原命令；必要时 CloseCommand 封闭原入口，权威账本缺失则停止相关修改和视图使用 |

取消等待不取消事务；调用 deadline 只限制尚未开始的提交，已提交事实不会过期消失。prepared 命令恢复时重新验证当前权限及原期限；条件不足则固定拒绝，不能刷新期限。纯读取被取消后停止新增扫描与返回，已经披露的字节不保证撤回。

接口、记录、来源规范化器、提取策略与索引 profile 分别锁定版本。存储升级先关闭写入口、验证迁移与回执不丢失，再切换；索引升级按新代次重建。未知必需字段／约束拒绝，不以忽略字段提供伪兼容。

<a id="automation"></a>
## 5. 成功任务的 opt-in 自动提取

自动提取由应用策略发起，记忆服务继续只裁决确定的读取与修改。用户按任务类型明确 opt-in，固定策略版本、允许处理位置、读取／提取／长期保存范围、频率、期限与独立用户提取额度；`memory.set_extraction_policy` 由受信管理宿主转交应用策略权威保存配置和原命令回执。Agent 不能自行启用该策略。关闭策略阻止尚未接纳的新提取，已经接纳的任务按独立任务取消／授权规则处置。

核心只在原任务正式状态为 completed 且结果已提交后登记触发候选；失败、取消、过期及未核验成功的任务均不自动触发，可以由用户显式选择另建提取任务。登记触发与原终态后的通知责任耐久衔接；应用策略以 `(用户, 原 task_id, 原终态 revision, policy_id, policy_revision)` 去重，先固定新的提取任务 ID、提交操作与来源，再预留独立提取额度。它不消费原任务剩余额度，也不把提取失败改成原任务失败。

原任务有已披露的非关键未知效果时，只能提取已验证的适用事实；任何未知行动仍标未知，不能生成“成功经验”。来源采用原输入闭包及正式结果的精确版本，来源删除／撤权后重新判断能否读取和保存。模型读过的来源不得从新记忆中删去；自依赖替换仍按[修改机制](mechanisms.md#mutation)拒绝。

应用策略保存触发状态、原提取任务／提交 ID、预算预留、最后核对位置及有界重试责任。提交响应丢失查询原提交，不创建第二个提取任务。配额不足、许可到期、必要来源不可用时保留有限等待或固定拒绝；期限耗尽报告缺口，不能刷新原触发身份／策略或借用目标任务预算。旧策略触发不能在用户关闭后按新策略自动重建。结果回写沿普通执行准入、Mutate 原命令和清理登记；模型产出本身不是保存成功回执。
