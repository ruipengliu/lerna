# 验收设计与建设顺序

[总览](../README.md) · [目标](../goals.md) · [交付审查](../review.md)

验收分别回答：接口是否遵守契约、实际任务是否达到目标、故障之后是否仍守住权限和效果边界。本页给出可执行的实验设计；用例尚未在内核运行实现上执行。每次报告必须区分设计审查、静态资产、参考实现、替换互操作和容量结果。

本目录同时保存[文档检查](check_documents.py)、[完成判断校验](validate.py)和[协议序列校验](validate_protocol.py)。这些工具读取 [contracts](../contracts/README.md) 中的共享资产，执行命令及已取得的结果见[交付审查](../review.md)。后续跨模块验收在本目录细化，模块专属机制和用例在对应模块目录维护。

完整字段补齐后，领域序列覆盖全部登记方法；[传输与关闭记录校验](validate_transport.py)另检查基础入口及公开签名向量。[gRPC 绑定](../contracts/grpc.md)另提供 [.proto 描述符](../contracts/harness.proto)，编译与 JSON 封装映射检查不替代服务间认证或网络互操作。参考实现的接纳、未知写入、控制竞争、长期关闭、首装重启和内容交接实验已展开为[故障步骤与断言](fault-experiments.md)，须由实际服务取得运行证据。

分布式生产配置另按[生产部署验收](../deployment-production.md#6-发布观测与生产验收)执行 PROD-01～10，覆盖单区失效、旧工作者复活、热点租户、设备重连、内容故障、分区扩容、缺历史灾备、跨分区配额、慢端控制竞争及 gRPC 提交后断连。正常负载、单区失效和积压恢复分别报告性能，不能以静态协议通过替代生产可用性。

## 1. 测试装配与证据

最小测试宿主提供可暂停的时钟和工作者、事务故障点、受控网络代理、固定模型回放、真实模型适配器、模拟搜索源、文件版本驱动及多个有状态模拟手机。判定器可以读取独立真值，Agent 不能读取判定器的答案或手机内部状态来绕过观察。

正常链先在本机运行，再分别替换 Brain、Memory、Executor；跨端配置覆盖本地 Home＋云能力、云 Home＋端侧能力。至少各有两种实现通过同一接口用例，不能把同实现换端口称为独立替换。外部 Agent 另外验证其原生任务映射与控制边界。

每条写入链放置三个故障点：提交前、提交后答复前、对方确认后本方记账前。回放只证明固定输入上的机制，真实联网、真实模型质量和生产规模必须单独运行。模拟手机的交互与真值分通道，验收包括设备身份、界面版本和用户接管代次。

| 证据 | 必须固定的内容 |
| --- | --- |
| 执行环境 | OS、运行时、数据库、组件及配置摘要、依赖与提供方版本、数据驻留范围 |
| 计划 | 目标编号、数据用途分区、候选与保留占用、样本清单／抽样框架及相关组、初始状态、输入、授权、额度、期限、故障位置、判定及停止规则 |
| 运行记录 | tenant/task/command/operation/decision 关联、原回执、前后业务修订、独立效果证据、内容摘要、费用 |
| 结果 | 冻结分母、通过／失败／未知、质量与时延分布、配对差异及分类退化、比例目标／统计门禁／改善门禁、未决责任、限制及复现步骤 |

报告内容也遵守用途和保留权限。不能为了生成可复现报告，把禁止导出的原文、截图或模型输入复制到公共日志。

| SYS-14 GUI 接管；C4/C7/V2 | 操作准备后界面变化，用户接管，再投旧动作 | 旧观察或旧控制代次被拒；已发生效果如实报告 |
| SYS-15 外部 Agent；C5/C6 | 外部创建成功但答复丢失，父取消 | 查出同一远端任务，继续控制及结算；无查询能力不接有副作用委派 |
| SYS-16 升级与回退；C6/C9 | 排空有未知操作；新版退化、旧格式不兼容 | 前者阻止切换；后者可停用但不虚报旧版已恢复；账本不回滚 |
| SYS-17 过载隔离；C5/C7/C8 | 一租户洪峰、模型提供方大量超时、磁盘逼近保护水位 | 有界接纳与熔断，控制/收尾有保留容量，其他用户仍推进 |
| SYS-18 开放任务；C1/C6 | 新工具具备声明与效果合同，无专用任务流程 | 可在授权内规划、调用和评估；完成依据没有被抬高为确定性验证 |
| SYS-19 原协议恢复；A4 | WSS 通知乱序／游标过期、ReplyAck 丢失、gRPC 截止、同键不同输入 | 查询恢复当前事实，原命令去重，冲突不覆盖，网络通道不裁决效果 |
| SYS-20 改善证据；C9 | 多候选选择、保留反馈后修改、批准撤回、离线节点 | 全部尝试保留；每发布固定单候选，复用暴露集无正式资格；评测不签发权限，逐节点生效/停用可查 |
| SYS-21 祖先控制；C5/C7 | 子操作已远端接纳，父暂停，随后准备首次发送或安全重试 | Home 传播子任务的有效控制修订；确认后禁止两种启动；父恢复不解除子自身暂停 |
| SYS-22 API 去重；C4/C8 | 同一提供方同一业务操作有两个主版本、多个 SDK 包装与账号 | 覆盖操作数只增一项，版本和环境分别列通过及缺口；未通过适用用例不计达标操作 |
| SYS-23 指标分层；C8/C9 | 点估计达标但样本不足；另测固定穷举集、相关任务重复及关键类别退化 | 比例目标、统计门禁、改善门禁分别输出；无依据不作总体推断，重复不增独立 n，总体改善不覆盖分类失败 |

模块局部用例分别在[大脑](../brain/README.md)、[执行](../execution/README.md)、[记忆](../memory/README.md)、[授权](../security/README.md)、[协作](../collaboration/README.md)、[交互](../interaction/README.md)、[扩展](../extensions/README.md)、[评测](../evaluation/README.md)。跨模块测试必须从入口产生真实调用，不能手改最后一张业务表制造成功。

## 3. 冻结计数口径

指标按下面口径进入[EvaluationPlan](../evaluation/README.md)。首次调用正确率与重试后任务成功率各有分母，禁止相互替代；不能把静态 Schema 合法率当准确率。

| 指标 | 计数规则 |
| --- | --- |
| API 覆盖数 | 唯一键为提供方命名空间＋语义业务操作；主版本、驱动、实例、账号、SDK 包装与参数排列均不增数。分别报告已登记、部分通过和全部适用用例通过的操作数；只有最后一项用于判断至少 1000 项目标 |
| 首次调用正确率 | 分母为冻结任务集中应发起工具调用的所有样本；未发出、错误拒绝、选错工具／实例、参数错误或权限不符计失败。分子为第一次逻辑行动在正确目标上满足调用要求的样本；至少 90% |
| 有限重试后任务成功率 | 分母为冻结目标范围内所有正式任务样本；失败、超时、未知效果、耗尽预算均计未成功。每逻辑步骤最多 2 次额外安全尝试，整个任务另有固定轮数、期限与费用；至少 95% |
| 质量指标 | 按正确性、证据支撑、约束满足、时效性分别报告，不以一个加权总分掩盖关键失败 |
| 时延及成本 | 从原入口接纳到各成功边界分别计量 p50/p95/p99；统计所有物理模型请求、工具费用、核对和失败尝试 |

调用正确不仅包括请求结构，还包括选择和实际目标适配。首次结果丢失但独立证据证明该次调用正确，可算首次正确；没有证据仍算未知，不能用第二次成功补为第一次正确。准备材料期间的只读检索与最终被测目标调用必须在计划中明确划分，不得运行后挑选“第一次”。

API 清单登记 semantic_operation_id、提供方、业务输入／效果、别名及受支持版本矩阵。每项必须有准确声明、至少 10 个不同有效上下文，以及适用的参数、权限、幂等、查询、取消和故障反例。一个版本通过不能代替其他已声称支持的版本；只有支持范围内的全部适用用例通过且无必需 unknown，该语义操作才进入达标计数。业务语义确实不同才新建操作身份，并说明输入和效果差异；仅因主版本不兼容不能重复计数。

覆盖集按只读、幂等写、不可重复写、单步、多步和歧义分层，保证声明范围可查。每 API 的 10 个上下文用于覆盖，不能自动证明该 API 的成功率达到 90%，也不能把平均分配的覆盖集直接当作生产任务分布。质量统计另固定目标任务总体、时间窗、抽样方法和各类别占比，分别报告整体与类别结果。

### 比例目标与附加统计门禁

项目的比例目标仍是首次调用正确率至少 90%、有限重试后任务成功率至少 95%。本方案另外要求相应总体比例的双侧 Wilson 95% 区间下界达到各自目标，作为更严格的正式证据门禁。报告必须分别给出成功数、冻结分母、比例目标是否达到和统计门禁结论；不能把“点估计达到目标、区间下界不足”写成项目目标被改成了另一比例。该门禁的代价是接近阈值时需要预先设计更大的样本量；看完结果再不断补样直到通过不属于默认固定样本方案。

Wilson 计算使用 `z=1.9599639845` 的双侧区间；它不是单侧 95% 下界。采用方法及计算依据见 [NIST 比例区间](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。正式统计门禁必须同时满足下表条件，不能只把任何一组通过数代入公式。

| 实验范围 | 比例报告与统计边界 |
| --- | --- |
| 有明确抽样框架的独立二元任务样本 | 预先固定总体、抽样单位、样本量及停止规则；按该框架讨论总体比例，默认使用 Wilson 门禁 |
| 固定穷举集或人工挑选的覆盖集 | 比例只描述该集合；不把它包装成对任意任务的置信保证，统计门禁标 inconclusive，另采正式质量样本 |
| 同源改写、共享环境或其他相关任务 | 保存 source_group_id／cluster_map；不能假装独立后简单套 Wilson，也不能仅减少 n 而保留原成功数。改用独立抽样或预先审查的组级分析；缺少适用方法时门禁 inconclusive |
| 重复种子、物理重投、同一任务的有限重试 | 保留全部运行与费用，同一逻辑样本只占原位置；不增加独立 n，不从重复运行中择优计分 |
| 不等概率抽样或人为分层后加权 | 保存抽样权重及目标分布；不把加权通过率直接代入普通 Wilson。默认另取与目标框架一致的独立样本，其他方法须在运行前冻结并单列依据 |

统计门禁不能证明样本外的所有设备、版本或未来时间窗口。关键权限、隔离与重复副作用用例要求计划内零违反且无必需 unknown；这项契约门禁独立于比例和置信区间，有限测试也不等于生产永久无风险。

错误权限负例属于契约安全集，预期是拒绝；它们不混入“应调用”质量分母以提高正确率。人工主动取消等排除项只能在计划冻结时列明，并单独报告数量与原因。正式开始后的提供方故障进入失败，不以“基础设施问题”从报告消失；若整次实验判无效，保留原记录并整组重跑。

### 相对基线的改善门禁

改善评测在开发集和选择集完成选型后，按[保留评测规则](../evaluation/README.md)固定一个候选。基线与候选使用相同样本、初始状态、许可和预算，分别运行并由独立证据判定；效果 unknown 在已证明成功率中取 0，同时保留真实原因。下表四格覆盖同一组样本，缺失或未跑的位置仍不能被删除。

| 配对类别 | 记号 | 对净改善的贡献 |
| --- | --- | --- |
| 双方成功 | a | 0 |
| 仅候选成功 | b | +1 |
| 仅基线成功 | c | −1 |
| 双方未成功 | d | 0 |

样本数为 `n=a+b+c+d`，净改善为 `(b−c)/n`。正式改善要求主要指标达到预先固定且大于零的 minimum_practical_gain，同时满足每个关键任务类别、权限与恢复契约、费用和时延的界限。权重平均后的提升不能掩盖某类退化；没有有效最小改善量或守护指标时只做诊断，不能产生正式改善资格。

统计显著性可以作为预先固定的附加比较条件，但不能替代实用改善量、分类退化检查或修复反复挑选偏差。独立二元配对可使用精确 McNemar 方法；相关配对、连续质量评分、多指标或多候选选择必须另行说明适用方法与多重比较规则，不默认套用该检验。方法适用条件见 [NIST McNemar 方法](https://www.itl.nist.gov/div898/software/dataplot/refman1/auxillar/mcnemar.htm)。

正式统计结论还须覆盖整个改进过程：首次正式确认前冻结候选范围、尝试上限和停止规则；多次确认使用预先规定的整体推断方法。新申请、新候选或新保留分区都不清除之前的尝试，单次区间不能直接升级为跨多次选择后的保证。缺少该策略或方法时，单次比例照常报告，两项正式统计／改善门禁为 inconclusive。尝试占用和来源关联由[评测管理](../evaluation/README.md)保存。

三项门禁各自按“依据是否足够 → 对应阈值是否满足”输出 pass、fail 或 inconclusive，保留全部已知违规：target_attainment 判断正式比例目标，statistical_gate 判断抽样依据和附加统计规则，improvement_gate 判断配对实用改善及各项退化。整份报告还必须具备正式保留资格、完整必需覆盖及契约通过，才可用于改善批准。固定集比例达标、普通兼容性验证通过或一次统计显著差异，都不能独自替代这项发布条件。

### V1 联网问答

测试集至少覆盖可直接回答、需要多来源、来源冲突、无足够证据和高时效问题。答案断言逐项映射到实际取得内容；独立评审者按冻结规则判定正确性与引用支撑。高时效样本在测试窗口取证，并保留发布时间、获取时间及截止时点。

首个参考门槛设为总体正确性与引用支撑均 ≥90%、来源实际获取和获取时间记录完整率 100%、受限资料外发零违反；证据不足样本应明确缺口，不能为了答全编造。阈值是待实施验收规则，必须同时报告各类样本及争议裁决，不能声称对任意问题保证 90%。

### V2 模拟手机 GUI

至少使用三个各有独立状态和身份的模拟设备，每个支持列表、详情、表单、确认和返回；点击、滑动、输入、返回都改变可观察状态。正例以独立只读真值核验目标完成，负例覆盖界面过期、操作答复丢失、设备互换、权限变化、中断与接管。

首次动作正确率及有限重试后的任务成功率使用上述 90%／95% 口径，另要求旧观察和已失效控制代次不启动新动作。模拟器须隐藏内部状态和验收答案；真机接入后按各平台重新运行，不把模拟结果写成真实设备支持声明。

## 5. 建设顺序与退出条件

```mermaid
flowchart LR
    P1[阶段一<br/>本地完整任务闭环] --> P2[阶段二<br/>两项专项与用户控制]
    P2 --> P3[阶段三<br/>替换、端云与外部 Agent]
    P3 --> P4[阶段四<br/>受控改进与规模运营]
```

| 阶段 | 交付与退出条件 |
| --- | --- |
| 一 | 可运行 Home、默认三系统、授权与内容库、CLI／Web、文件和搜索适配器；接纳、费用、输入、未知效果、取消和重启闭环可重复；接口资产和 SDK 与代码一起发布 |
| 二 | 联网问答及多个有状态模拟手机完整专项，记忆提取和个性化，用户纠正/删除/接管；共同质量集和 1000 API 接入工作持续扩充，未达标如实记录 |
| 三 | 三系统异构替换、两向跨端配置、外部 Agent、离线租约与额度，受管副本关闭；所有相关故障矩阵通过，取得对应 L3/L4 |
| 四 | 隔离评测与改进发布/回退，目标 API 数量与质量达标，多租户服务和容量实验逐级达到最终规模；不可信插件与真实手机按平台单列验收 |

阶段一就必须有权限、未知效果和持久恢复；它们不能作为后期治理补丁。阶段四的规模运营不改变第一阶段保存原操作、成果版本和租户身份的规则。

本方案没有阻止技术文档落地的产品待决项。具体模型、搜索供应商、云对象存储实例、隔离平台实现及容量配置需要在实现装配时选定并通过本文实验；缺失能力的拒绝／等待行为已在入口和所属模块说明，不能默认视为已具备。
