# 验收设计与证据边界

验证必须能够发现设计承诺被违反。先检查身份、权限、事务和效果不变量，再测质量、时延与成本。构造JSON、画出成功流程或跑过一个小状态模型，都不能证明生产系统可靠。

本章给出可证伪的运行方案。当前仓库的文档、核心Schema和解释工具只能提供设计级证据；可运行内核、真实供应商、多进程及跨可用区结果必须另行建立。

## 1 四层证据

| 层次 | 建立什么 | 不建立什么 |
| --- | --- | --- |
| 文档与结构 | 引用、字段、样例、限定词与图文一致 | 真实身份、数据库原子性或目标效果 |
| 有界状态模型 | 声明的原子步骤下，竞争顺序与错误变体是否违反不变量 | 完整分布式实现、无限状态活性或网络/磁盘模型 |
| 实现合同与故障实验 | 实际SDK、数据库、驱动和owner交接遵守同一合同 | 超出已测故障域、负载和平台的保证 |
| 目标质量与生产 | 冻结任务集、真实故障域和容量下的效果、成本与恢复 | 所有任务域普遍成功或永不失败 |

每份结果绑定实现commit、profile/Schema摘要、配置、数据集、环境、随机种子、故障点、完整样本和测量方法。测试前提由夹具提供时必须写清，例如预置Grant不证明认证已实现。

## 2 关键故障矩阵

| 组 | 具体刺激 | 必须观察到的结果 |
| --- | --- | --- |
| F01 原命令 | 接纳前杀进程、提交后丢回执、换应用副本、清空通知 | 原键只建一Task，回执/Job共同存在，查询不改投新owner |
| F02 Job竞争 | worker暂停到租约过期；旧处理同时有新Raise；旧done/退避晚到 | 旧epoch不能提交，新work_revision不被覆盖，原到期不被推迟 |
| F03 发送未知 | send_started后发送前崩溃；发送后目标已写但回复丢失 | 不能从无回执推导未执行，按原调用核对，非幂等写不盲重发 |
| F04 控制竞争 | cancel先于invoke；pause→resume期间旧提案返回；成功与取消同时提交 | 墓碑阻迟到启动，旧control_revision不可采纳，只有一个固定终态 |
| F05 完成漏项 | 只登记部分目标；当前条件全pass但一已准入操作仍accepted | 漏项/未封发送均阻止成功，不能靠高分或空展示页通过 |
| F06 证据缺陷 | 缺陷登记与完成并发；覆盖评估或组合子检查命中缺陷 | Task 所属库的证据 gate 决定先后，活动重核；旧Result追加notice不重开 |
| F07 跨域资格 | 凭据过期、authority_epoch变化、缺陷游标缺口或本地时钟失信 | 不续长旧receipt，按策略窗口等待；窗口0不走伪原子远程检查 |
| F08 授权消费 | 多Grant部分消费后失败；once零账单；确认改正文/版本；重放本人决定 | 不行动、不返once；原业务准确一次消费；新参数须新确认 |
| F09 账务 | 重复/乱序累计账单、超预留、封账后更正、退款重交、父Task已终态 | 真实差额一次入账、未知预留不释放、退款不复活预算/once |
| F10 分配关闭 | 创建答复丢失；budget.close先到；receiver失联后尝试转移额度 | 至多一子Task，迟到创建不开消费，父方保持未知占用 |
| F11 内容治理 | 对象写完元数据未提交；跨库register_copy与close竞争；清理失败 | 无未登记发布或误删，当前使用受控，残留可查询并继续 |
| F12 检索水位 | 前序事务延迟/回滚，后序先准备；索引落后；权限扩张但无Memory change | 不越未提交切点，partial不伪装完整，visibility变化重建集合 |
| F13 私密派生 | 私密输入后来裁出提示或未被引用；正文TTL、来源关闭、旧摘要命中 | processed来源仍约束结果；读不延保留；关闭传播到派生/holder |
| F14 GUI/文件 | 旧观察点击、本人接管、symlink/硬链接别名、文件被旁路修改 | 不跨资源/epoch；未知在途不释放；效果与当前版本分开 |
| F15 程序环境 | hostcall提交后丢映射、同位置异参、aborted但进程仍忙、旧checkpoint恢复 | 沿原hostcall身份恢复，不重复发起子调用、实际退出前不复用，旧实例不能更新新generation |
| F16 输入与分支 | queued撤回/sending竞争；后续目标挡住前项回答；分支切换时旧输出 | 不虚报撤回，回答/steer仍可推进原Task，输出只归原分支 |
| F17 Schedule | 到期与编辑/停用竞争、DST重复/缺失、未知创建跨下一时刻、冷恢复 | 原occurrence唯一；未知占并发槽；不无限补发；规则停止不冒充Task取消 |
| F18 集合与订阅 | 未知ID在快照期间创建；跨页撤权/扩权；大扇出取消超过100项 | 不漏仍可见对象，不披露无权ID；内部全集门禁不依赖响应页 |
| F19 安装与回退 | 旧初始化晚到、新版撤回、旧批准失效、数据格式不兼容、恶意旧插件 | 不覆盖新实例，不用失效批准，不回滚业务史；不为收尾运行不可信代码 |
| F20 实验污染 | 反复换ID正式试验、早期曝光、封存后正常读反馈、取消千样本 | 不返正式次数；按曝光时点判资格；门禁先封，停止/残留分页核清 |
| F21 通道恢复 | 应用退出网关存活、旧binding帧晚到、ReplyAck丢失、慢端不读 | 外连接可保持，原业务恢复，旧输出隔离，内存有界且控制有份额 |
| F22 AZ与时间 | 同步确认后隔离主区、旧主仍活、UTC跳变/VM暂停/候选时差失证 | RPO/RTO按原记录实测；不双写、不复活boot、不偷偷降耐久 |
| F23 洪峰与容量 | 冷缓存重连、租户10倍流量、供应商限流、积压叠加单区损失 | 控制/收尾可运行，队列/连接/字节有界，μ≤λ明确不收敛 |
| F24 灾备与增长 | 旧备份缺最近撤权、墓碑长期增长、磁盘保护与对象缺失 | 只安全诊断，不复活旧动作；不删最后身份换空间，真实残留可见 |
| F25 数据血缘与条件 | 原文漏项、候选降级硬要求、重复采纳、改版澄清、空条件提交、跨租户来源、旧覆盖摘要 | 原始输入可追溯，候选不成授权，修订与行动分轮；未ready仅允许受信提炼/核验；当前准确覆盖才可推进 |

端云断网实验必须分别验证两种部署。默认云端 Task 断网时，给设备保留旧 Task/条件缓存并令其显示全部 pass。设备仍只能继续原准入与有限许可内的执行和收尾，不得据缓存改目标或提交 succeeded/Result；重连沿原命令和 Operation 补传，由原云端 PG 事务核验完成。可选端侧独立 Orchestrator 只推进原先归自己的 Task；缺少必需依赖时等待，不能接管云端 Task。

每个实验固定原输入和目标初态，观察原命令/双方账本/目标真值/真实出站/权限/费用/资源占用，不能只看UI。正例保证合法动作可完成，反例保证错误被正确拒绝；全拒绝不算正确实现。

## 3 目标覆盖与专项

- C1对应固定决策、计划、条件和有界续行；C2对应提取、纠正、时间、来源与个性化实际影响
- C3验证取得真实内容、引用支撑、时效和冲突；C4验证API/文件/GUI准确资源与效果
- C5验证持续责任、取消、离线/重连、端云和委派；C6验证三系统第二实现、异构SDK和扩展互操作
- C7验证最小权限、一次消费、用途分离和本人控制；C8验证完整观测与独立目标真值；C9验证冻结评测、有限发布和独立旧版回退
- A1职责、A2独立替换、A3端云可装配、A4共同契约分别取证，不能用同一个演示同时宣布全部成熟

联网问答V1以实际取回内容作为引用真值，包含无答案、来源冲突、过期和检索失败。手机GUI V2至少三台独立有状态模拟设备，完成观察→动作→观察→验证以及中断/本人接管；真实手机平台另行支持验收。

API覆盖按语义不同操作计数。首次调用正确率≥90%同时检查能力、参数、资源、权限和目标适配。有限重试成功率≥95%预先冻结总尝试、期限和预算，unknown/失败都进入分母。质量门槛和提供方计费模式不由重试器动态放宽。

## 4 性能实验

先固定直接回答、读后回答、冷恢复、保存并读回四种请求，分别测暖态/冷态/正常/故障。记录实际SQL、往返、扫描/锁行、事务、WAL、flush/sync、对象字节、模型请求/辅助调用和端到端费用，不能以逻辑对象数推导IO性能。

规模基线采用[生产假设](../production/README.md)：290新Task/秒、20万WSS、提供方/任务构成固定；另测500新Task/秒持续15分钟。稳态、峰值、损失一区和积压恢复各自报告。调用失败和迟到业务接纳分开计数，SLO不剔除系统过载。

扫描有LIMIT还须检查实际计划、索引、死元组、WAL及历史增长。批量不等于低成本；所有外部逐对象授权检查都计真实RPC。对公平性、最老责任年龄和恢复净余量设门槛，不能仅用平均CPU或平均延迟通过。

## 5 本系列附带的检查

在仓库根目录运行：

```sh
python docs/architecture/validation/check_architecture.py
python docs/architecture/validation/model_checks.py
python docs/architecture/validation/data_flow_checks.py
python docs/architecture/validation/implementation_contract_checks.py
python docs/architecture/validation/build_field_reference.py --check
node docs/architecture/validation/lab_checks.cjs
```

check_architecture.py 使用现有Python jsonschema包，检查正文独立性、相对链接/锚点、围栏、Schema与正反例以及关键跨记录关系。model_checks.py 仅用标准库，枚举小型原子步骤模型，检查旧Job结束、取消/成功竞争、账单累计与原操作未知，并证明故意移除门禁的错误变体会失败。

implementation_contract_checks.py检查本轮固定的批量准入、控制窗口、确认、结果发布、只读效果、cell提交、child切换、Schedule槽、部署CAS和资格登记的有限模型。它不执行真实服务或数据库。

data_flow_checks.py 验证输入、候选采纳、当前覆盖和控制竞争的有界模型，并保留错误门禁的反例；它不证明自然语言语义理解或实际数据库行为。build_field_reference.py --check 验证生成字段字典与同版 Schema 一致。

lab_checks.cjs 检查解释工具的状态函数、默认值和参数边界，不启动浏览器。正式视觉验收还应在真实浏览器检查逐步状态、键盘、窄屏和减少动画；本地HTML无需后端或网络。它解释因果和计算，不运行数据库或调用外部系统。

上述检查的运行结果随本次交付报告说明。它们不能替代F01–F25实现实验，也不能据此把RPO=0、RTO≤60秒或质量目标写成已达标。若形式化进一步展开，应绑定新模型/性质/公平性假设和哈希，并提供错误变体与可达见证；完整成功轨迹不是条件活性的证明。

本轮未执行HTML的浏览器点击验收，旧交付记录中的浏览器限制也未重新核验。已有解释工具仅重跑函数测试；新增数据SVG已渲染并目视检查。函数通过不表示布局、键盘或交互已验证。
