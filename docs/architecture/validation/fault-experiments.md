# 参考实现的故障实验

[验收总览](README.md) · [模块详设入口](../README.md) · [实际检查记录](../review.md)

本页定义参考实现需要提供的故障注入与断言，不是已执行的服务测试。现有 JSON 序列只能检查给定事实之间的关系；下面实验必须从真实命令入口触发事务和驱动，并独立读取双方持久记录与目标真值。

## 1. 固定装配与断点

每组实验使用独立临时数据库、内容目录、冻结时钟和一个有状态文件／手机模拟目标。参考内核使用 Go；同进程 Go 接口与跨进程 gRPC 两种装配分别测试，浏览器、CLI 和设备从 `/v1/connect` 的 WSS 入口触发。HTTPS 用于发现、认证和原始字节传输，上传／镜像管理走 WSS／gRPC。代理只控制网络传递；不能直接改业务表制造成功。测试控制器有独立只读真值通道，Agent和候选只能看到正常观察入口。

| 测试适配器 | 必须提供 | 隔离与限制 |
| --- | --- | --- |
| ProcessHarness | 启动、强制退出、以原数据重启、读取实际实例ID | 不删除原数据库；重启产生新实例资格 |
| StorageFaults | 指定事务提交前／提交后答复前暂停、写入失败、磁盘容量约束 | 故障位置以固定标签记录，不能更改提交结果 |
| NetworkProxy | WSS 握手、断连、应用帧延迟／重复与重连重放，gRPC 回复丢失和分区，HTTPS 字节中断 | 原字节、原身份、每次发送日志可核对；不把单一有序连接内不可能的网络乱序当作协议行为 |
| SimulatedTarget | 原操作日志、版本化文件、手机界面状态、接管代次 | 操作侧与真值侧权限分离，原操作日志不由模型填写 |
| ClockHarness | 单调时间和UTC推进、可信界限失效 | 不让重启重置租约或动作期限 |
| EvidenceReader | 按租户、原命令／业务身份读只读事实 | 对照摘要，原文遵守用途许可 |

三个固定断点是：`before_commit`（尚未提交）、`after_commit_before_reply`（决定已提交）、`after_peer_reply_before_record`（对方已答复、本方尚未记账）。同一场景至少各跑一次适用断点；没有达到预定断点的运行标无效，不能算通过。并发场景使用可控屏障决定竞态顺序，不以随机睡眠证明顺序覆盖。

## 2. 接纳已提交，答复丢失

对应 SYS-01。初始只有受信宿主、精确安装锁、有限许可与空任务库；固定一份 task.submit 及 command_id。

1. 在 Home 的 after_commit_before_reply 阻断回复，证据通道确认 Task、原 Receipt、预算和首 job 已在同次提交。
2. 强制退出 Home，以相同数据库重启；客户端保留原命令，先查原回执再重投同请求。
3. 同时由第二客户端重投同键同请求，随后另投同键不同目标。
4. 释放工作者，使用冻结模型和文件目标推进首轮。

断言：原命令只有一个 Task 映射；至少一个首 job 能继续但同一责任槽不重复存在；原回执不变；同键异意图返回冲突；目标动作按唯一 operation_id执行。随后在 before_commit 重跑，确认未提交记录不会被外部观察为accepted，原命令仍可在有效期内首次接纳。

禁止把“连接上只收到一次结果”或传输 ACK 当作去重成功。必须核对唯一键、任务数、job责任和目标真实动作数；gRPC deadline 或 WSS 断开都不能据此裁决原命令未提交。

## 3. 写入效果已发生，Executor崩溃

对应 SYS-02／03。冻结候选正文、目录与文件版本前提，Home已准入唯一 op_write。文件驱动必须声明目标幂等／原操作核对能力。

1. 让目标实际保存候选字节，记录目标版本；在Executor保存最终效果前强制退出，并丢弃网络回复。
2. Home收到超时，读取其预算预留及原poll责任，确认没有生成另一个写入意图。
3. 用户取消任务；暂停取消传播，使目标核对与Task取消存在交错。
4. 重启Executor，先恢复原操作及当前控制，按原目标凭据查询；恢复网络后让确认效果迟到。
5. 再次投递原dispatch和取消命令，推进所有有限收尾工作。

断言：Task始终cancelled，原Operation可以从unknown变为applied；文件只有预期版本变化；没有提醒等后续目标动作；费用只按原项调整一次。poll／settle责任只在目标效果及最终费用各自结清后结束，取消回执不能提前释放未知预留。

另测没有原操作查询能力的不可重复写驱动：必须保留effect_unknown及受信处置入口，不重复写入。这里的预期不是最终成功，而是保证未知被正确保留。

## 4. 旧工作者、取消与祖先控制

对应 SYS-05／14／21。父任务和内部子任务属于同一Home，子已有dispatch job；执行端和设备owner独立，当前有效控制为running。

| 顺序 | 刺激 | 必须观察到的结果 |
| --- | --- | --- |
| A | 工作者W1领取后阻塞；租约到期W2重领；父暂停提交；W1恢复并准备发送 | W1提交被旧lease_epoch拒绝；有效子控制已推进；已落实门禁的入口不发送 |
| B | 暂停已在Executor提交，但设备owner尚未确认 | Home显示逐入口待确认；execution.control最多accepted，不能报全端enforced |
| C | 设备先应用恢复9，再收到暂停8 | 保持9；控制乱序不使状态倒退 |
| D | 取消10后收到恢复11 | 原终态不重开；新任务必须新身份 |
| E | 子自身暂停，父暂停后恢复 | 子仍暂停；父恢复不覆盖子自身意图 |
| F | 手机观察后用户接管，再投旧动作 | 资源代次不匹配，动作拒绝；已发生效果仍可查询 |

对A分别安排原动作尚未发送和已交目标两条路径。前者可确认not_applied，后者只能停止后续发送并核对；不能用同一条“取消成功”断言覆盖。每条竞态读取Home、Executor和资源owner三方事实，控制job完成与目标已停止分开记录。

## 5. 取消先到与长期关闭索引

对应D-11及取消墓碑。创建一项活动任务，固定尚未投递的Invoke；先把原operation取消送达Executor。

1. 确认未知operation的取消墓碑已耐久保存，原Invoke仍在网络代理中。
2. 推进超过完整回执查询期，触发正文和完整回执清理；任务仍有效时不清除最后的取消依据。
3. 重启Executor，投递原Invoke，并另用新command_id携带同operation_id投递。
4. 将任务终结，在可证明任务永久关闭后合并局部索引，再重复迟到Invoke。
5. 查询已清理的原取消回执，并用不同参数重投原command_id。

断言：全部迟到启动均被阻止；原索引被合并时仍能定位永久关闭依据；完整回执返回gone，同键不同请求返回idempotency_conflict，不变成not_found或新业务rejected。正文和凭据已按策略清理，长期索引只含获准的最小字段。备份必须包含关闭依据；用缺少后续关闭记录的旧备份启动时，只读诊断而非重开动作。

## 6. 首装、实例重启与撤回

对应SYS-16／20。干净宿主只有受信最小管理入口和精确发行制品，提供随包契约报告及其受信来源。

1. 导入兼容性证据，保存本机批准和首份安装锁，以无旧锁、初始代际激活；合同报告来源保留原环境，不伪装成本机新评测。
2. 在活动指针提交后、实例对外开放前强制退出。重启装载同锁，保存新实例就绪及当前批准依据。
3. 确认原激活ID、原历史批准使用及格式迁移事实未被更新；当前实例可开放后才派发新工作。
4. 在另一条路径先撤回批准再重启；旧活动指针仍在，批准检查必须阻止新入口开放。
5. 远端模式丢失reopen回执，查询原use；不得用旧实例的激活回执或修改旧start_before恢复。

另测正式改善评测失败后自动改为兼容发布：原申请不能自行降级通过，需要新的明确发布用途和对应批准。只通过普通合同测试不产生改善资格。

## 7. 设备回复与内容清理竞争

对应SYS-10／11／19。设备主动建立 WSS 连接，服务沿连接发送 Delivery，其中承载 command、query 和 receipt_lookup 三类请求；大内容上传另以 MirrorTicket 主动下发。原 delivery、reply、ticket 和业务命令身份固定，精确帧遵循[公共传输契约](../contracts/transport.md)。

| 故障 | 必须观察到的结果 |
| --- | --- |
| 设备保存 Reply 后断线，接收方保存 Reply 后又丢 ReplyAck | 同 delivery／reply 的固定回复可重投；只有一次持久接收事实，Query 无伪造 command_id；ReplyAck 不代替业务回执 |
| 旧实例回复交给新实例连接 | 按原映射核对，不以新凭据认领旧工作；不明时保留恢复缺口 |
| 中转替换请求或目标设备 | 原签名／摘要／接收方绑定失败；不能凭来自网关放行 |
| MirrorTicket 发送后连接断开，重连重复发送同票据 | 使用原 ticket／upload_id 和原发送实例恢复；接收镜像只关联原 ContentRef／copy，不新建内容 owner |
| 上传字节已ready，content.put提交前孤儿清理并发 | 发布和清理锁同一元数据；只能发布完整不可变字节或明确失败 |
| content.get已返回定位，读取前来源关闭 | 下载重新核验并拒绝；旧定位不授予持久资格 |
| 下发部分字节时来源关闭 | 停止尚可阻止的发送，记录已登记持有者；不宣称召回已发字节 |

## 8. 网关断开与已提交命令

固定浏览器或 CLI 的原 input_id 和 command_id，交互服务与 Home 使用真实权威库。分别测试同进程提交与跨进程 gRPC 转交，不能为了测试协议而拆分共库原子事务。

1. 在原 owner 的 after_commit_before_reply 暂停，让证据通道确认业务记录、Receipt 和后续 job 已共同提交。
2. 退出 WSS 网关，保持 owner 运行；另一次运行保留网关并在 gRPC 已提交后制造 deadline。
3. 客户端显示离线或处理中，使用退避重连连接到另一网关，沿原身份查询回执及当前快照。
4. 对同键同意图恢复，再提交同键异意图；完成后使旧网关的迟到 Reply 到达。

断言：原提交只有一份业务事实和责任槽；新网关不重新分配业务身份，迟到 Reply 不覆盖更高业务修订；同键异意图冲突。客户端在取得业务回执前不能因为连接建立、传输确认、表单消失或 Change 到达显示已消费。gRPC deadline 和断连不取消已提交责任，业务取消必须另走原领域控制命令。

再在 before_commit 断开并恢复，确认没有被外部观察为已提交的半份事实；客户端仍按原命令和接纳期限恢复，不用新命令掩盖未知。

## 9. 重连风暴、慢客户端与控制流控

固定总用户数、每用户连接上限、发送队列的帧数／字节上限、在途请求上限和重连速率；参数为待测配置，不以空闲连接数充当任务容量。独立记录连接层、owner 和客户端的时间及队列水位。

| 注入 | 必须观察到的结果 |
| --- | --- |
| 同时关闭一组网关，让客户端集中重连 | 重连退避和入口限流生效，单用户多设备不放大份额；原 owner 的接纳与收尾继续推进，未接纳请求不显示已排队 |
| 一个客户端停止读取，同时持续产生快照变化 | 单连接及总发送内存有界，Change 可合并；无法保持覆盖时明确要求快照恢复或断开，持续慢端被断开；其他用户不被拖住 |
| 丢弃所有 Change，再恢复连接并读取快照 | 当前获准 Surface 与原业务回执恢复；无连续事件日志也能正确呈现，不假造消费或效果 |
| 普通输入、快照和内容流量满载时取消／撤权 | 控制及回执核对取得保留容量并优先调度；HTTPS 大文件不占用 WSS 的普通消息发送队列；逐业务入口是否落实由真实控制回执确认 |
| 取消已提交后，原客户端在 Reply 前停止读取 | 控制责任留在原 owner；连接关闭不丢取消，重连查询原命令取得决定，在途外部效果继续核对 |

若连接已无法传递任何消息，必须断开并恢复，不能声称控制优先级保证穿透网络分区。控制到达、业务入口封闭和在途效果核对分别计时；只有相关入口真实落实后才能报告相应范围已停止。

## 10. 长连接凭据失效与身份恢复

使用真实浏览器同源 Secure、HttpOnly 会话 Cookie 和 CLI／设备 bearer 两组入口。浏览器另从不受信 Origin 发起握手；身份变化由受信管理接口执行，不能直接改认证缓存制造通过。

| 顺序 | 刺激 | 必须观察到的结果 |
| --- | --- | --- |
| A | 连接建立后使会话过期，继续发 Command、Query 和原回执查询 | 每条消息按当前会话拒绝，旧连接关闭；已提交事实保留，但过期会话不获披露 |
| B | 设备已连接时提交 endpoint.revoke，继续发送 Reply 并接收排队 Delivery／MirrorTicket | 当前代次检查阻止旧凭据新收发；原未结工作保留，不能因旧连接已认证而放行 |
| C | 同一有效实例短暂断线后重连，随后另以新实例凭据连接 | 原实例沿原 delivery／reply 恢复；新实例必须遵守恢复映射，不能认领旧实例上传票据、余额或工作 |
| D | 内容预览后撤销披露权限，保持连接及 snapshot 修订不变 | 新读取或推送不披露旧正文，not_modified 不延长资格；依赖预览的输入仍由业务 owner 拒绝 |
| E | 不受信 Origin 携带已存在 Cookie 发起浏览器握手 | 入口拒绝；Cookie 存在、回环地址或已登录不能代替 Origin 校验 |

同时核对认证入口和最终 owner 的拒绝记录，避免只证明网关缓存更新。测试报告分别列出拒绝新消息、关闭旧连接和各授权传播窗口；立即关闭在线连接不等于所有离线租约即时失效。

## 11. 实验记录与判定

每次报告固定experiment_id、目标场景、版本锁、环境与配置摘要、初始数据、许可与预算、时钟、实际达到的断点、网络轨迹、原业务ID、最终两端记录摘要和目标真值。记录服务启动／停止时间，避免把一次测试残留误认成当前操作。

每项断言单独输出pass、fail或inconclusive及证据引用。安全与恢复不变量中出现已知违规即fail；缺少必须证据为inconclusive，不能以其他项通过抵消。所有未决效果、费用和清理作为独立残留列出，即使Task已终态。
