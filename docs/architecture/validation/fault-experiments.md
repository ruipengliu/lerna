# 参考实现的故障实验

[验收总览](README.md) · [模块详设入口](../README.md) · [实际检查记录](../review.md)

本页定义参考实现需要提供的故障注入与断言，不是已执行的服务测试。现有 JSON 序列只能检查给定事实之间的关系；下面实验必须从真实命令入口触发事务和驱动，并独立读取双方持久记录与目标真值。

## 1. 固定装配与断点

每组实验使用独立临时数据库、内容存储、冻结时钟和一个有状态文件／手机模拟目标。首轮恢复验收采用独立接入、应用及工作进程的生产装配；同进程调试装配作为附加对照。参考内核使用 Go；同进程 Go 接口与跨进程 gRPC 两种装配分别测试，浏览器、CLI 和设备从 `/v1/connect` 的 WSS 入口触发。HTTPS 用于发现、认证和原始字节传输，上传／镜像管理走 WSS／gRPC。代理只控制网络传递；不能直接改业务表制造成功。测试控制器有独立只读真值通道，Agent和候选只能看到正常观察入口。

| 测试适配器 | 必须提供 | 隔离与限制 |
| --- | --- | --- |
| ProcessHarness | 启动、强制退出、以原数据重启、读取实际实例ID | 不删除原数据库；重启产生新实例资格 |
| StorageFaults | 指定事务提交前／提交后答复前暂停、写入失败、磁盘容量约束 | 故障位置以固定标签记录，不能更改提交结果 |
| NetworkProxy | WSS 握手、断连、应用帧延迟／重复与重连重放，gRPC 回复丢失和分区，HTTPS 字节中断 | 原字节、原身份、每次发送日志可核对；不把单一有序连接内不可能的网络乱序当作协议行为 |
| SimulatedTarget | 原操作日志、版本化文件、手机界面状态、接管代次 | 操作侧与真值侧权限分离，原操作日志不由模型填写 |
| ClockHarness | 单调时间和 UTC 推进、可信界限失效；宿主／VM 暂停、UTC 跳变与数据库提升时差 | 进程暂停与宿主经过时间分别注入；不让重启重置租约或动作期限 |
| EvidenceReader | 按租户、原命令／业务身份读只读事实 | 对照摘要，原文遵守用途许可 |

三个固定断点是：`before_commit`（尚未提交）、`after_commit_before_reply`（决定已提交）、`after_peer_reply_before_record`（对方已答复、本方尚未记账）。同一场景至少各跑一次适用断点；没有达到预定断点的运行标无效，不能算通过。并发场景使用可控屏障决定竞态顺序，不以随机睡眠证明顺序覆盖。

## 2. 接纳已提交，答复丢失

对应 SYS-01。初始只有受信宿主、精确安装锁、有限许可与空任务库；固定一份 task.submit 及 command_id。

1. 在 Orchestrator 的 after_commit_before_reply 阻断回复，证据通道确认 Task、原 Receipt、预算和首 job 已在同次提交。
2. 强制退出 Orchestrator，以相同数据库重启；客户端保留原命令，先查原回执再重投同请求。
3. 同时由第二客户端重投同键同请求，随后另投同键不同目标。
4. 释放工作者，使用冻结模型和文件目标推进首轮。

断言：原命令只有一个 Task 映射；至少一个首 job 能继续但同一责任槽不重复存在；原回执不变；同键异意图返回冲突；目标动作按唯一 operation_id执行。随后在 before_commit 重跑，确认未提交记录不会被外部观察为accepted，原命令仍可在有效期内首次接纳。

禁止把“连接上只收到一次结果”或传输 ACK 当作去重成功。必须核对唯一键、任务数、job责任和目标真实动作数；gRPC deadline 或 WSS 断开都不能据此裁决原命令未提交。

## 3. 写入效果已发生，Executor崩溃

对应 SYS-02／03。冻结候选正文、目录与文件版本前提，Orchestrator 已准入唯一 op_write。文件驱动必须声明目标幂等／原操作核对能力。

1. 让目标实际保存候选字节，记录目标版本；在Executor保存最终效果前强制退出，并丢弃网络回复。
2. Orchestrator 收到超时，读取其预算预留及原poll责任，确认没有生成另一个写入意图。
3. 用户取消任务；暂停取消传播，使目标核对与Task取消存在交错。
4. 重启Executor，先恢复原操作及当前控制，按原目标凭据查询；恢复网络后让确认效果迟到。
5. 再次投递原dispatch和取消命令，推进所有有限收尾工作。

断言：Task始终cancelled，原Operation可以从unknown变为applied；文件只有预期版本变化；没有提醒等后续目标动作；费用只按原项调整一次。poll／settle责任只在目标效果及最终费用各自结清后结束，取消回执不能提前释放未知预留。

另测没有原操作查询能力的不可重复写驱动：必须保留effect_unknown及受信处置入口，不重复写入。这里的预期不是最终成功，而是保证未知被正确保留。

## 4. 旧工作者、取消与祖先控制

对应 SYS-05／14／21。父任务和内部子任务属于同一 Orchestrator，子已有dispatch job；执行端和设备owner独立，当前有效控制为running。

| 顺序 | 刺激 | 必须观察到的结果 |
| --- | --- | --- |
| A | 工作者W1领取后阻塞；租约到期W2重领；父暂停提交；W1恢复并准备发送 | W1提交被旧lease_epoch拒绝；有效子控制已推进；已落实门禁的入口不发送 |
| B | 暂停已在Executor提交，但设备owner尚未确认 | Orchestrator 显示逐入口待确认；execution.control最多accepted，不能报全端enforced |
| C | 设备先应用恢复9，再收到暂停8 | 保持9；控制乱序不使状态倒退 |
| D | 取消10后收到恢复11 | 原终态不重开；新任务必须新身份 |
| E | 子自身暂停，父暂停后恢复 | 子仍暂停；父恢复不覆盖子自身意图 |
| F | 手机观察后用户接管，再投旧动作 | 资源代次不匹配，动作拒绝；已发生效果仍可查询 |

对A分别安排原动作尚未发送和已交目标两条路径。前者可确认not_applied，后者只能停止后续发送并核对；不能用同一条“取消成功”断言覆盖。每条竞态读取 Orchestrator、Executor和资源owner三方事实，控制job完成与目标已停止分开记录。

## 5. 取消先到与长期关闭索引

对应D-11及取消墓碑。创建一项活动任务，固定尚未投递的Invoke；先把原operation取消送达Executor。

1. 确认未知operation的取消墓碑已耐久保存，原Invoke仍在网络代理中。
2. 推进超过完整回执查询期，触发正文和完整回执清理；任务仍有效时不清除最后的取消依据。
3. 重启Executor，投递原Invoke，并另用新command_id携带同operation_id投递。
4. 将任务终结，在可证明任务永久关闭后合并局部索引，再重复迟到Invoke。
5. 查询已清理的原取消回执，并用不同参数重投原command_id。

断言：全部迟到启动均被阻止；原索引被合并时仍能定位永久关闭依据；完整回执返回gone，同键不同请求返回idempotency_conflict，不变成not_found或新业务rejected。正文和凭据已按策略清理，长期索引只含获准的最小字段。备份必须包含关闭依据；用缺少后续关闭记录的旧备份启动时，只读诊断而非重开动作。

## 6. 首装、实例重启与撤回

对应SYS-16／20。干净宿主只有受信最小管理入口和精确发行制品，提供随包契约报告及其受信来源。

1. 导入兼容性证据，保存本机批准和首份安装锁，以无旧锁、初始代际激活；合同报告来源保留原环境，不伪装成本机新评测。
2. 在活动指针提交后、实例对外开放前强制退出。重启装载同锁，保存新实例就绪及当前批准依据。
3. 确认原激活ID、原历史批准使用及格式迁移事实未被更新；当前实例可开放后才派发新工作。
4. 在另一条路径先撤回批准再重启；旧活动指针仍在，批准检查必须阻止新入口开放。
5. 远端模式丢失reopen回执，查询原use；不得用旧实例的激活回执或修改旧start_before恢复。

另测正式改善评测失败后自动改为兼容发布：原申请不能自行降级通过，需要新的明确发布用途和对应批准。只通过普通合同测试不产生改善资格。

## 7. 设备回复与内容清理竞争

对应SYS-10／11／19。设备主动建立 WSS 连接，服务沿连接发送 Delivery，其中承载 command、query 和 receipt_lookup 三类请求；大内容上传另以 MirrorTicket 主动下发。原 delivery、reply、ticket 和业务命令身份固定，精确帧遵循[公共传输契约](../contracts/transport.md)。

| 故障 | 必须观察到的结果 |
| --- | --- |
| 设备保存 Reply 后断线，接收方保存 Reply 后又丢 ReplyAck | 同 delivery／reply 的固定回复可重投；只有一次持久接收事实，Query 无伪造 command_id；ReplyAck 不代替业务回执 |
| 旧实例回复交给新实例连接 | 按原映射核对，不以新凭据认领旧工作；不明时保留恢复缺口 |
| 中转替换请求或目标设备 | 原签名／摘要／接收方绑定失败；不能凭来自网关放行 |
| MirrorTicket 发送后连接断开，重连重复发送同票据 | 使用原 ticket／upload_id 和原发送实例恢复；接收镜像只关联原 ContentRef／copy，不新建内容 owner |
| 上传字节已ready，content.put提交前孤儿清理并发 | 发布和清理锁同一元数据；只能发布完整不可变字节或明确失败 |
| content.get已返回定位，读取前来源关闭 | 下载重新核验并拒绝；旧定位不授予持久资格 |
| 下发部分字节时来源关闭 | 停止尚可阻止的发送，记录已登记持有者；不宣称召回已发字节 |

## 8. 网关断开与已提交命令

固定浏览器或 CLI 的原 input_id 和 command_id，交互服务与 Orchestrator 使用真实权威库。分别测试同进程提交与跨进程 gRPC 转交，不能为了测试协议而拆分共库原子事务。

1. 在原 owner 的 after_commit_before_reply 暂停，让证据通道确认业务记录、Receipt 和后续 job 已共同提交。
2. 退出 WSS 网关，保持 owner 运行；另一次运行保留网关并在 gRPC 已提交后制造 deadline。
3. 网关退出时客户端退避重连另一网关；仅内部故障时按第 11 节先保持 WSS 并重绑。沿原身份查询回执及当前快照，不把两种故障强制归为同一次外重连。
4. 对同键同意图恢复，再提交同键异意图；完成后使旧网关的迟到 Reply 到达。

断言：原提交只有一份业务事实和责任槽；新网关不重新分配业务身份，迟到 Reply 不覆盖更高业务修订；同键异意图冲突。客户端在取得业务回执前不能因为连接建立、传输确认、表单消失或 Change 到达显示已消费。gRPC deadline 和断连不取消已提交责任，业务取消必须另走原领域控制命令。

再在 before_commit 断开并恢复，确认没有被外部观察为已提交的半份事实；客户端仍按原命令和接纳期限恢复，不用新命令掩盖未知。

## 9. 重连风暴、慢客户端与控制流控

固定总用户数、每用户连接上限、发送队列的帧数／字节上限、在途请求上限和重连速率；参数为待测配置，不以空闲连接数充当任务容量。独立记录连接层、owner 和客户端的时间及队列水位。

| 注入 | 必须观察到的结果 |
| --- | --- |
| 同时关闭一组网关，让客户端集中重连 | 重连退避和入口限流生效，单用户多设备不放大份额；原 owner 的接纳与收尾继续推进，未接纳请求不显示已排队 |
| 一个客户端停止读取，同时持续产生快照变化 | 单连接及总发送内存有界，Change 可合并；无法保持覆盖时明确要求快照恢复或断开，持续慢端被断开；其他用户不被拖住 |
| 丢弃所有 Change，再恢复连接并读取快照 | 当前获准 Surface 与原业务回执恢复；无连续事件日志也能正确呈现，不假造消费或效果 |
| 普通输入、快照和内容流量满载时取消／撤权 | 控制及回执核对取得保留容量并优先调度；HTTPS 大文件不占用 WSS 的普通消息发送队列；逐业务入口是否落实由真实控制回执确认 |
| 取消已提交后，原客户端在 Reply 前停止读取 | 控制责任留在原 owner；连接关闭不丢取消，重连查询原命令取得决定，在途外部效果继续核对 |

若连接已无法传递任何消息，必须断开并恢复，不能声称控制优先级保证穿透网络分区。控制到达、业务入口封闭和在途效果核对分别计时；只有相关入口真实落实后才能报告相应范围已停止。

## 10. 长连接凭据失效与身份恢复

使用真实浏览器同源 Secure、HttpOnly 会话 Cookie 和 CLI／设备 bearer 两组入口。浏览器另从不受信 Origin 发起握手；身份变化由受信管理接口执行，不能直接改认证缓存制造通过。

| 顺序 | 刺激 | 必须观察到的结果 |
| --- | --- | --- |
| A | 连接建立后使会话过期，继续发 Command、Query 和原回执查询 | 每条消息按当前会话拒绝，旧连接关闭；已提交事实保留，但过期会话不获披露 |
| B | 设备已连接时提交 endpoint.revoke，继续发送 Reply 并接收排队 Delivery／MirrorTicket | 当前代次检查阻止旧凭据新收发；原未结工作保留，不能因旧连接已认证而放行 |
| C | 同一有效实例短暂断线后重连，随后另以新实例凭据连接 | 原实例沿原 delivery／reply 恢复；新实例必须遵守恢复映射，不能认领旧实例上传票据、余额或工作 |
| D | 内容预览后撤销披露权限，保持连接及 snapshot 修订不变 | 新读取或推送不披露旧正文，not_modified 不延长资格；依赖预览的输入仍由业务 owner 拒绝 |
| E | 不受信 Origin 携带已存在 Cookie 发起浏览器握手 | 入口拒绝；Cookie 存在、回环地址或已登录不能代替 Origin 校验 |

同时核对认证入口和最终 owner 的拒绝记录，避免只证明网关缓存更新。测试报告分别列出拒绝新消息、关闭旧连接和各授权传播窗口；立即关闭在线连接不等于所有离线租约即时失效。

## 11. 内部重绑与跨实例推送

对应 PROD-11／12。至少部署两个独立网关、两个 Orchestrator 应用及另一个工作者进程，共用原分区数据库；建立有未决 Command、Reply 和订阅的 WSS，固定原 connection_id。

1. A 持有内部流，由 B 的领域事务产生面向该端的 Delivery；关闭全部通知监听，验证 A 通过有界索引补扫取得原记录。
2. 在 A 已提交原命令、返回前结束其内部流，保持网关和端侧 socket；网关以新 binding_id 绑定 B，查询原回执。分别让恢复落在请求期限内、超过请求期限但未超连接恢复上限两条路径。
3. 让旧 A 的响应、Change、ReplyAck、建流登记提交和条件清理迟到；先让更高 binding_revision 提交，再让较低代次到达，含应用路由过期但外连接仍存活的路径。新绑定同时交付原 Delivery。检查原 Reply 在未取得持久 ACK 时可重交。
4. 更新内部委托令牌，随后撤销原端点凭据，分别核对“内部轮换可继续”和“原身份失效必须停止”。
5. 对提示发布设置两事务乱序：较早分配的源记录晚提交；发布器恢复后两项都必须进入提示或明确缺口，不能凭最大序列号永久跳过一项。

断言：内部恢复保持外 connection_id、原 limits、外连接额度及请求序号高水位，不向客户端发送第二个 Ready；只有当前 binding 输出获准转发。每个外 request_seq 最多一个响应，期限后客户端另查原业务；服务端仅按原记录恢复，不盲重发写命令。原订阅收到 backend_rebind 缺口后才重建；网络暂不可达不假装无变化。进程数增加不能使数据库轮询器按连接数无限增加，记录无通知下的扫描延迟和 DB 成本。

## 12. 连接额度与暂停实例复活

对应 PROD-13。配置身份的服务内上限和总上限，连接多个 Orchestrator；身份权威分区与部分业务分区分开，使用实际连接记录和进程租约。

| 断点 | 必须观察到的结果 |
| --- | --- |
| 外额度已占、内部绑定提交前网关退出 | 未发外 Ready；原额度条件释放或到期回收，不出现永久泄漏或跨库伪原子成功 |
| 两个网关并发取得最后一个额度 | 身份行上的裁决只允许一个成功，各 Orchestrator 不能重复获得总额度 |
| 同 WSS 多次内部重绑 | 不增加外连接数，旧 binding 清理不删除当前绑定；同一原请求不重复计数 |
| 暂停网关超过进程租约期限，再恢复其发送循环 | 先检查本地截止并关闭，不续活旧租约；已发字节仍沿原业务身份核对 |
| 身份库暂不可达、业务库仍可用 | 新连接与无法核验资格的披露停止；不把缺失查询当新身份，不触发全部业务实例反复重启 |
| 达到单连接请求总数上限 | 普通请求提前停止，控制余量及原 Reply／ACK 有界完成，再轮换连接；请求关联内存不随连接寿命无限增长 |

报告分别计外连接配额回收、内部绑定恢复、认证拒绝和业务成功。构造租约记录只能作为静态反例；必须暂停实际进程并让其恢复，才验证旧发送路径是否关闭。

## 13. 内容依赖、耐久位置与滚动迁移

对应 PROD-14／15。同库 Memory／Content 元数据与跨 owner 两种装配分别测试。固定原 copy_id、Memory 创建命令和内容摘要，使用跨实例可读的内容存储。

1. 在来源持有者登记后关闭来源，再让接收端执行首次 control 查询；另在门禁建立后、Memory 提交前让本地核对工作提交 copy 关闭。两条路径均不得发布可使用的已关闭依赖。来源关闭与本地提交交错但尚未查得新修订时，另按下一项验证后续停用，不声称跨库原子关闭。
2. 反过来让 Memory 先提交，再由持久核对工作通过 content.get 的 control 分支读到关闭；已保存依赖必须进入停用／清理责任。另让旧查询答复迟到，核对较低修订不能重开本地门禁；查询不可达时阻止新的使用，不能推断来源已关闭。
3. 来源登记成功但答复丢失、Memory 提交后答复丢失各运行一次；查询并恢复同一 copy 和同一 Memory，清理没有被采用的登记。
4. 云端 Upload／Mirror 返回 ready 后删除上传进程本地临时目录并退出进程；其他健康副本仍能按准确版本和当前资格读取内容。
5. 生产负载中执行兼容格式扩展、小批回填及应用滚动；在检查点提交后退出迁移进程，恢复并回退到仍兼容当前格式的旧应用。随后尝试不兼容回退。

断言：没有源端未跟踪的依赖；发布和接收端关闭以共同门禁决定先后。对象可用性由实际耐久字节验证，数据库中的 ready 标志不能代替字节。回填按原检查点继续，旧应用不读取未支持格式，业务、关闭身份与效果历史不回滚；报告迁移期间的锁等待、WAL、业务延迟和失败率。

## 14. 带持续流量的故障恢复容量

对应 PROD-01／04／16。记录在线用户 U、活跃会话倍率 a、服务连接倍率 b，以 C=U×a×b 建立连接；同时发真实任务、内容和控制负载。至少覆盖稳态、峰值、单区失效和恢复积压四组，不把空闲连接测试作为完整生产验收。

| 实验 | 观测与断言 |
| --- | --- |
| 杀一个应用实例，再分批发布网关 | 应用故障尽量只造成内部重绑；网关发布的外断连批量、握手峰值、快照回查及请求错误在预算内 |
| 已确认提交后隔离主库所在区 | 旧主已隔离、提升记录完整且第二耐久副本就绪才恢复写；核对全部已确认业务，记录检测／提升／恢复／开放分段耗时 |
| 稳态 λ 下积压 B，再以实测 μ 恢复 | 当 μ>λ，实际排空时间与预算可比较；当 μ≤λ，明确报告不可收敛并限制新接纳，控制和核对仍有份额 |
| 通知停机同时恢复大量连接 | 补扫、身份核验和快照不能造成无界 DB 回源；退化下拒绝率仍计入 SLO |
| 加载多年关闭索引规模后重放旧命令 | 关闭查询仍准确，热 job 查询不扫描全历史；索引／vacuum／备份成本纳入实测 |

单区 RPO=0 只针对已确认账本，另核对内容与外部动作。故障注入中为了尽快恢复而降低同步提交、跳过旧主隔离或清除未知责任，均为失败，不能用更短 RTO 抵消。

## 15. 同一工作槽合并责任与旧处理完成

对应 PROD-20。使用真实任务事务与两个 worker，禁止直接改 jobs 制造唤醒。由原领域命令提交控制 r，让 W1 领取对应工作槽，在远端返回前暂停；再提交 r+1。固定原操作和控制命令的身份，记录工作槽的领取代次与责任版本。

| 屏障顺序 | 必须观察到的结果 |
| --- | --- |
| r+1 提交后，W1 的 r 处理成功 | W1 不得把 r+1 的责任标 done；最新责任仍有可领取槽 |
| r+1 提前 due_at 后，W1 返回可重试失败或超时 | 旧退避不得推迟新责任；失败尝试仍计入原有限预算 |
| W1 已完成槽，再提交 r+1 | 相同责任键产生唯一活动槽或重新激活原槽；不能因历史 done 忽略新责任 |
| W1 过期，W2 接管后，W1 返回 | 旧领取回写拒绝；实际远端事实仍可由独立归并事务收取 |
| 重复投递同一领域事实 | 不产生新责任版本、第二个活动槽或额外业务命令 |

随后完全关闭通知，只保留有界扫描。核对最新逐端控制最终可被领取，等待时间按控制类别报告；不能以最后扫描到了 done 槽掩盖此前超出传播预算的延迟。不同槽的原 dispatch 身份、已知效果和未决费用均保持，责任版本变化不能重置预算或重复启动动作。

<a id="memory-watermark"></a>
## 16. Memory 提交水位、回滚与视图切点

对应 PROD-21。配置同一 owner 的两条 Memory 变更及独立 owner 的对照写入，开启真实索引推进和 view.open／pull。由事务故障点暂停，不能用手写 change_sequence 模拟通过。

1. T1 取得 owner 的事务 head 后、提交前暂停；T2 尝试修改同一 owner 的另一对象。T2 必须等待相同 head，不能先发布一个越过 T1 的提交水位；另一 owner 应能独立推进。
2. 分别让 T1 提交、回滚及进程退出。T2 随后继续；提交顺序与 change_sequence 一致，回滚不留下必须永久等待的序号，业务修改、变化项和 head 不出现半份提交。
3. 让索引应用一批变化后、推进 checkpoint 前退出；恢复时重复应用不能重复产生候选或跳过变化。I 不得超过已完整覆盖的同 owner 序列。
4. 暂停 view.open 的一致快照事务，在其前后分别提交新增、修改和删除。初始固定集合与后续增量合起来无遗漏；初始集合的切点与 head 来自同一数据库快照，后续页面不维持跨请求数据库长事务。
5. 页间撤回读取资格、关闭来源或清理历史正文。固定集合不授予继续披露权；返回获准墓碑／缺口或要求重新快照，不能读取已失去资格的旧版本。

断言分别核对业务记录、事务 head、memory_changes、索引覆盖点与视图 ACK。WSS 提示头不是该领域序列的替代证据。记录 head 锁等待、事务持锁时间、索引滞后及有限补扫成本，不能用单 owner 吞吐推导所有 owner 必须全局串行。

## 17. 集合订阅的完整枚举与缺口恢复

对应 PROD-22。为六类订阅对象配置独立获准客户端 A／B；由 A 建立 operation、activation 和尚未使用的 Grant，B 不预存这些 ID。沿[类型与快照方法映射](../contracts/transport.md#6-变化订阅快照与错误)调用真实 Query，不从测试数据库给 B 注入 ID。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 首次订阅；对象创建早于返回的提示水位 | B 可经各领域列表枚举对象；不依赖对象以后再次变化 |
| 已订阅期间内部重绑、游标过期或缓冲溢出 | 显式缺口后重新枚举；旧订阅提示不被拼成连续历史 |
| 首页与后续页之间创建、修改或删除对象 | 固定成员集合和订阅之后的变化合并无遗漏；较旧页面不覆盖较新修订 |
| 页间权限缩减或扩大 | 逐页及发送前核验；旧集合失效并重取当前范围，新增可见对象不等其自身再修改才被发现 |
| 集合总上限、扫描预算或缓冲上限不足 | 保持明确不完整状态；有限退避后仍不能完整时保留缺口和受权查询，不能无限立即重取同一快照 |
| 游标跨主体、owner、query_id 或到期后复用 | 拒绝或返回明确过期；不续活旧查询身份、不暴露其他范围 |

当前可披露集合的真值通过独立观察入口核对，权限移除的对象标识不出现在给 B 的敏感缺口说明中。只有所有类型的分页结束且无未覆盖缺口，并处理已缓冲提示后，才可标记恢复完成。跨 owner 的结果分别标明来源，不输出不存在的全局原子快照时间。

<a id="lease-clock"></a>
## 18. 暂停、时钟跳变与租约回收

对应 PROD-17；PROD-13 的普通进程暂停仍单独执行。使用目标生产平台的 ClockAdapter，保存可信误差配置及平台提供的时间／暂停证据。模拟时钟通过只能作为预检，宿主和数据库切换条件须在实际平台重跑。

| 注入 | 必须观察到的结果 |
| --- | --- |
| 仅暂停进程线程，系统经过时间继续推进 | 恢复后的发送路径先发现原资格过期；迟到续约答复不能使旧 boot 复活 |
| 主机或 VM 暂停超过租约窗口 | 覆盖暂停的经过时间或恢复门禁阻止旧队列发送；不得只证明续约线程最终失败 |
| UTC 向前／向后跳，或经过时间可信界限失效 | 不能证明资格时先闭门；既有持久责任保留，不把动作解释为未发生 |
| 提升主库的 UTC 位于允许误差边界内外 | 界限内的本地截止仍保守；界限外停止依赖该租约的工作，按平台规则重新建立资格 |
| 续约请求较早发出、答复在本地截止后返回 | 本地原资格不延长，旧连接／流不能因答复成功继续使用 |

同时观察身份库额度回收、应用绑定与网关最后一条出站帧；任何期限内已发送但仍在网络中的数据另列，不把无法召回的字节描述为暂停后新发送。测量保守停止造成的拒绝／重连，并按接口 SLO 计入，不能为维持可用性数字放宽可信界限。

## 19. 保持原连接时的 gRPC 扩容与流满

对应 PROD-18。先仅部署应用 A，建立真实 WSS 与复用 HTTP/2 的 EndpointChannel；记录解析到的实际实例、连接数及每实例活动流。保持这些连接，不重启网关，再上线 B／C。

1. 观察发现更新、健康就绪及短 Call 分布；新请求在预算内进入新增实例，不能只显示地址列表已更新。
2. 持续建立新 WSS 与候选重绑流，直至 A 到达实例上限。后端最终接纳限额必须成立，多个网关的本地计数不能合起来突破服务端上限；新候选有界选择 B／C 或显式拒绝。
3. 将一个后端设为 draining，再使另一个后端不可达。已有流按有限排空／正常轮换迁移，新建流避开不可接纳实例；旧原命令仍按原身份查询，不借换目标重写。
4. 恢复后端并重复一次扩容，核对连接池没有按每条 WSS 或每次请求无限创建 ClientConn。另测发现暂时不可用，沿已规定的地址有效性和拒绝边界运行。

分别报告新流分布、每后端拒绝率、建立等待、连接数、候选重试次数、原 WSS 保持比例和重绑快照流量。round_robin 通过短 RPC 测试不能替代长流容量试验；发现记录中的“健康”也不能替代目标实际接纳。

<a id="availability-counting"></a>
## 20. 调用截止、查询重连与业务结果计量

对应 PROD-19。冻结客户端、网关和账本三个观察位置，使用同一组请求轨迹分别计算调用可用性、命令接纳与任务结果；观察口径归[生产 SLO](../deployment-production.md#42-可用性与时延验收口径)。

| 轨迹 | 应保留的计量事实 |
| --- | --- |
| 命令提交且在原 5 秒内取得确定结果 | 一次调用结果与一个原命令接纳，内部重绑不另增调用样本 |
| 命令已提交但初次调用超时，随后 receipt_lookup 成功 | 初次调用仍超时；查回执是另一次查询，业务接纳只按原 command_id 计一次 |
| 普通 Query 超时，WSS 重连后重读成功 | 两次可观察调用分别统计；第一次失败不被最终读取成功抹掉 |
| 多次读取同一 command_id 的回执 | 每次查询独立计量，不按被查命令合成一个可用性样本 |
| 系统过载、依赖不可达与预定权限拒绝 | 前两类进入系统不可用；权限拒绝按预先约定分类，不能在故障后重分类失败 |

对 5 秒截止边界、答复迟到和断连分别设置屏障，核对统计结果可重放且不会随稍后恢复改写。无响应调用不得从延迟报告中消失，成功延迟与超时／拒绝数量分别报告；请求指标与失败时段指标分别判定，不能用大量成功重试冲淡不可用窗口。

## 21. 重复定义与派生状态消融后的恢复验证

对应 D-19～22，在上述真实入口和故障宿主中逐项替换机制。静态序列只能核对已给出的关联事实，本节另验证实际发送、事务与恢复行为。

| 场景 | 刺激及故障位置 | 独立断言 |
| --- | --- | --- |
| 权威表单结构 | 发布只含 request_ref 的输入块；取得 Schema 后修订业务请求，再提交旧答案；另让请求 owner 失联 | 旧修订拒绝消费并提示刷新；失联输入不可用。恢复后按准确请求重新读取，Surface 不提供备用字段约束；并发回答仍至多一次业务消费 |
| 请求序号与控制排队 | 普通请求排队后插入控制请求，在真实写循环记录编号和发帧顺序；请求持续超过 10000 次 | 实际新 request_seq 严格递增；控制仍有在途／字节预留，连接不因历史请求数量轮换。网关只保存高水位及有界在途关联，内存不随已完成请求数增长 |
| 错误、重绑与序号耗尽 | 新号分别得到权限、过载、后端不可达错误，再尝试复用；处理未决请求时重绑内部流；另用新外连接及安全整数上界 | 错误也消费原号；重复或较低号不进入业务，按传输规则关闭有歧义的连接。内部恢复沿原号、不再次通过新请求准入；旧 binding 输出隔离；新 connection 允许自己的初始号；耗尽有界关闭，业务沿原 command 查询 |
| 委派摘要与关闭事实 | 外部创建成功但答复丢失；恢复唯一映射后父取消、子结果迟到且账单未最终；最后封账并清理可删详情 | 阶段按同一修订事实投影，创建未知和待收尾仍有原 jobs；父取消不被迟到成功重开。只有持久 Closure 才显示 closed；完整查询依据清理后返回 gone，最小关闭索引仍拒绝旧创建 |
| 租约首次使用与关闭竞争 | 分别令关闭先提交、首次使用先提交，并在使用提交后回执前崩溃；重连提交最终账单 | 关闭先提交拒绝新 use；使用先提交只扣一次并保留原使用。open 不代表零使用，closed 不退未知预留；重放不重复扣额，最终封账才 reconciled |

请求序号实验分别观察客户端实际发送顺序、网关高水位和在途映射、后端业务记录。委派与租约实验检查原创建、原 use、关闭和结算的权威记录，不能只断言界面阶段文字相同。

## 22. 实验记录与判定

每次报告固定experiment_id、目标场景、版本锁、环境与配置摘要、初始数据、许可与预算、时钟、实际达到的断点、网络轨迹、原业务ID、最终两端记录摘要和目标真值。记录服务启动／停止时间，避免把一次测试残留误认成当前操作。

每项断言单独输出pass、fail或inconclusive及证据引用。安全与恢复不变量中出现已知违规即fail；缺少必须证据为inconclusive，不能以其他项通过抵消。所有未决效果、费用和清理作为独立残留列出，即使Task已终态。
