# Harness 调研新增组合故障

[采用清单](optimization-evidence.md#harness-adoption) · [既有故障实验](fault-experiments.md) · [调研依据](../../research/agent-harness-comparison/architecture-optimization.md)

以下为 2026-10-01 补充的待运行向量，未替代既有 SYS、OPT、FW 或模块用例，也不是已经通过的测试结果。沿“取得准确资料—比较—保存—读回”的真实入口注入，每次保留原 command、Task、Decision／ModelCall、Operation／Attempt、Content 版本和相关使用身份；只记录本例实际存在的对象。独立断言读取领域原事实、目标状态、实际出站计数及费用，不从 UI 文本或模型自评推导成功。

每份运行记录固定实现与配置、数据库／平台、输入和来源、断点、时序、原对象引用、预期与实际断言、未知项及完整费用。机制构造测试、真实 PG／SQLite 与平台故障、模型质量实验分别登记；允许失败与未知，不能因一层通过就代填其他层。来源数据用途不覆盖测试复制时不得生成语料副本。

<a id="har-01"></a>
## HAR-01：上下文来源与最终数据出口

多轮压缩中穿插目标修订、冲突信息和未知写入；包装器在模型可读消息之外追加 metadata、附件或会话日志。核对原 Snapshot 与实际完整编码的来源闭包、接收方和字节数；未获准附加字段不得外发，硬约束／原未知操作保留。合法有界上下文应成功发送一次；禁止保存的编码只暂存，恢复失败不能伪造原资料。对应 BI-17～20、OPT-02／07。

<a id="har-02"></a>
## HAR-02：持久进展与重启

对原效果重复交回相同事实，并在无进展阈值之前重启；另交回新的有效证据。重复通知不重置计数，新证据按既定规则推进；达到有限阈值后保存具体等待或结束依据及原未知责任，重启不恢复无限循环。记录事实去重键、任务修订、计数前后值和真实模型次数。对应 RT-20～24。

<a id="har-03"></a>
## HAR-03：工具参数与结果完整性

hook 修改路径／目标，别名映射到同名能力，adapter 增添字段；返回时丢页、丢媒体或截断输出。核对最终参数准入记录、固定 Capability／Binding、真实请求及原结果／派生引用；变化后未重新准入不得发送，截断文本不消除已发生效果。包含合法规范化、真实空集和完整媒体结果正例。对应 EX-21～31、S-I27～31。

<a id="har-04"></a>
## HAR-04：耐久点与宿主恢复

分别在内存准备、存储接纳、提交答复未知和可能发送后终止宿主；同时制造旧实例未隔离、配置变化及存储不可写。诊断、原责任恢复和新动作接纳分别断言；无持久资格不新发送，unknown 按原身份核对。记录恢复可用与新接纳就绪的独立时间，不以启动探针代替原事实。合法重启可继续原未发送准备，不能一概永久停机。

<a id="har-05"></a>
## HAR-05：输入与界面竞争

接纳但尚未领取时取消；两设备同时确认／拒绝；预览后改版或撤权；T1 退出时 T2 已运行；丢终结提示及 SDK 本地事务失败。原输入一次消费，旧 Task 控制不作用于独立新 Task，旧呈现不能覆盖新快照。临时片段允许先显示、合并和丢弃；正式 Change 在相应事实可读后发送，断线按原对象恢复。对应 II-20～31，不要求逐 token 提交。

<a id="har-06"></a>
## HAR-06：子任务冷恢复与迟到费用

子任务已生效后父宿主退出，恢复时插件配置变化；重复报告、等待超时、父取消和晚到账单交错。原 Delegation 保持唯一子 Task 与原 InstallLock；等待超时不等于取消，子成功不掩盖未决效果或费用。当前批准缺失禁止新激活，但许可内的原结果查询可继续。合法冷恢复返回原子结果，费用按原来源修订只计一次。

<a id="har-07"></a>
## HAR-07：暂存装配与迟到初始化

配置 A 初始化中提交配置 B，再让 A 迟到返回；分别注入缺依赖、字节不符、自检失败和清理失败。只有当前配置与实例的核验结果可发布 ready，暂存项不进入新路由；失败不得调用裸实现。dispose 失败保留资源和外部残留。另验证准确配置、兼容批准及完整依赖的正常启动。

<a id="har-08"></a>
## HAR-08：经验候选与来源变化

形成 before／after 后纠正原记忆，再批量应用；其中一项 local_only、另一来源关闭，选择时暴露正式样本。检查 expected_revision 冲突、每项独立决定、来源限制和候选谱系；不能覆盖新修订、宣称整批原子或用暴露样本批准改善。正常用户偏好修订仍可直接按 Memory 授权保存，合格软件候选才走发布。

<a id="har-09"></a>
## HAR-09：程序调用与实际停止

依[程序化工具](../execution/programmatic-tools.md)注入路径／网络／凭证越界、资源上限、abort 后仍运行、host-call 映射提交后崩溃及不可信检查点。断言每次外部调用有原接纳映射，未知效果不重放；未实际退出不释放物理名额。合法有限组合和纯计算必须通过；X-06 与 X-08 的数据分别登记。

<a id="har-10"></a>
## HAR-10：能力发现与加载时机

固定同一准确候选集合，加入应触发／不应触发、同名、旧 Schema、缺依赖、断连、加载过晚及加载无益。记录召回、选择、实际加载和最后任务结果；配置与撤权影响缓存当前性，检索成功不证明可以执行。全部搜索／加载成本进入独立比较，X-03 与 X-09 的因素不混合。

<a id="har-11"></a>
## HAR-11：Session 与原任务交接

在 Task 已接纳但 Session 尚未保存关联时退出，归档 Session 后恢复；再在同一对话创建 T2 并迟到交回 T1 的取消。按原 command 查询补关联，仅有一个 T1；归档不取消任务，T1 旧控制不作用于 T2。只保存笔记时不得暗中调用模型；引用任务结果不复制第二份权威结果或预算。

## 证据与成本

每个向量同时保留合法正例、故障例和无法证明的缺口。真实出站探针需覆盖供应方附加日志、hook、重试与重定向，不能只比较模型消息数组。计量遵守[同场景读写口径](../../research/agent-harness-comparison/data-flow-io-comparison.md)：逻辑追加、写语句、提交与 sync 分列，记录恢复相对正常路径的增量。质量试验另按冻结计划、独立真值、全样本及完整成本判定；构造机制测试全过不证明质量或 IO 收益。
