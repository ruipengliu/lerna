本专题把各模块里的安全控制串成一个整体：攻击者能做什么、我们信任什么、在哪里拦截、拦不住时后果被限制在什么范围。它不新增一个"安全裁决模块"，各项事实仍由原负责模块持有。

基本思路：**允许推理和扩展提出提议，由核心控制它们实际能读取、发送和执行什么。**授权、出口闸门、内容治理和沙箱共同限制提示注入的后果；检测器、系统提示和扩展签名只提供辅助证据，不得代替这些控制。

对提示注入的承诺是：**即使推理完全服从攻击者，也不能取得未授权的资源、扩大权限或绕过出口。**授权范围内的错误判断、错误摘要和用户被钓鱼，仍要靠 C1、C3、C8 的质量和交互措施处理。

## 1 职责与边界

### 1.1 威胁模型

| 范围 | 假定 |
| --- | --- |
| 保护对象 | 用户内容及派生数据、凭据、授权、任务责任、动作效果、费用、发布权限、执行资源 |
| 攻击者能力 | 控制网页、邮件、文件、工具返回、扩展描述和代码；诱导推理；重放请求；让节点断线；作为另一个用户提交恶意负载 |
| 可信基础 | 核心代码和配置、可信的出口执行实现、身份验证和确认通道、所用的安全存储、经过验证的宿主隔离机制 |
| 不信任的对象 | 推理输出、扩展自报的权限、工具的自然语言描述、扩展自报的"删除完成"或"动作成功" |
| 外部系统 | 幂等、结果查询和证据格式只接受经过核查的具体能力；无法证明的效果保留未知 |
| 不承诺的范围 | 不抵御已被完全攻陷的宿主或核心；不阻止用户主动批准的恶意行为；不声称完整的信息流无泄露（次数、时序等侧信道） |

### 1.2 控制点与事实归属

| 威胁 | 主要控制点 | 事实负责方 |
| --- | --- | --- |
| 提示注入、伪造批准 | 结构化提议检查；可信的确认；来源与用途检查 | 任务编排、会话、授权、内容治理 |
| 恶意插件或 Skill | 安装权限上限；摘要绑定；隔离；不得直接访问资源 | 扩展管理持有安装事实，授权持有许可，出口闸门执行限制 |
| 数据外泄 | 数据来源与接收方绑定；模型、日志、渲染器和网络统一检查 | 内容治理、授权；出口闸门落实 |
| 凭据滥用 | 用引用代替密钥；目标绑定；最小范围；轮换与撤销 | 授权（凭据许可和状态）；安全存储保管秘密 |
| 跨用户越权 | 认证主体绑定；所有引用检查用户；存储、缓存、执行环境和配额隔离 | 各事实写入方；宿主的资源限制 |
| 供应链攻击 | 固定源码、依赖和描述；发布身份核验；隔离评测；版本撤销 | 扩展管理、评测与进化；核心发布仍经代码审查 |
| 伪造效果或删除回执 | 验证目标证据、回执主体和版本；证据不足就保持未知或"清理未完成" | 动作账本、内容治理 |

出口闸门不持有独立的授权、效果或费用事实（A1、R3）：使用记录写授权，尝试写动作账本，用量写预算，轨迹写运行记录。

### 1.3 来自真实事故的教训

| 案例 | 发生了什么 | 对 Lerna 的要求 |
| --- | --- | --- |
| 间接提示注入（研究） | 外部网页、文档里的内容可以改变 LLM 应用的行为；取得外部内容时发出的请求本身也能外泄数据（[Greshake 等](https://arxiv.org/abs/2302.12173)） | 网页、文件、邮件和工具结果都不得签发授权；**GET 请求也必须检查外发的数据** |
| EchoLeak（CVE-2025-32711，正式产品漏洞） | M365 Copilot 的攻击链组合了邮件注入、自动图片加载和代理出口（[CVE 记录](https://cveawg.mitre.org/api/cve/CVE-2025-32711)、[发现者分析](https://www.catonetworks.com/blog/breaking-down-echoleak/)） | **渲染器和自动资源加载也是出口**；只管工具调用会漏掉 G5；允许域名下的代理仍可能把数据交给其他接收方 |
| GitHub MCP（受控复现） | 公开 issue 里的注入让 Agent 读取私有仓库，再把内容放进公开 PR；作者归因于权限组合（[Invariant Labs](https://invariantlabs.ai/blog/mcp-github-vulnerability)） | 凭据能访问全部仓库，不等于当前任务获准访问全部仓库；读取私有资料与公开发布分别授权 |
| Claude Code 凭据目标漏洞（CVE-2026-21852） | 恶意项目配置可以在信任确认之前修改 API 目标，可能泄露密钥（[公告](https://github.com/anthropics/claude-code/security/advisories/GHSA-jh7p-qr78-84p7)） | 扩展或项目配置不得决定密钥的投递目标；初始化、配置加载和认证请求都必须纳入控制 |
| Claude Code 域名白名单（GHSA-fg94-h982-f3mm） | 预先批准一个裸域名，使攻击者控制的路径被自动放行，下载计数可以构成外泄通道（[公告](https://github.com/anthropics/claude-code/security/advisories/GHSA-fg94-h982-f3mm)） | 授权检查具体的资源、所有者、请求数据；"常见可信域名""只读请求"都不够 |
| Amazon Q 扩展（AWS-2025-015，实际供应链事件） | 范围过大的构建令牌被用来提交恶意代码，进入了正式发行的 1.84.0；恶意代码因语法错误没有成功执行（[AWS 公告](https://aws.amazon.com/security/security-bulletins/AWS-2025-015/)） | 运行权限和构建发布权限分别最小化；签名之外还要发布审查、凭据隔离和版本撤销 |
| 恶意 Skill（市场审计） | 对真实 Skill 市场的审计发现了恶意安装前置步骤、混淆外泄和关闭安全设置的载荷，确认的恶意载荷为 76 个（[Snyk](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/)） | Skill 声称的"必需初始化"不产生权限；文本、脚本、依赖和更新都要版本绑定、受控执行 |
| bubblewrap 权限提升（CVE-2026-41163） | setuid 模式下的权限提升，0.11.2 修复（[公告](https://github.com/containers/bubblewrap/security/advisories/GHSA-xq78-7hw4-5jvp)） | 沙箱本身也是供应链的一部分；支持范围包括运行时版本、配置和修复状态 |

## 2 对象与状态

本专题不新建与任务、授权、内容并列的对象，只说明安全相关的字段落在哪些已有记录上。

### 2.1 关键字段

| 所属记录 | 字段 | 含义与约束 |
| --- | --- | --- |
| 授权 | 主体、端点范围 | 谁可以用，在哪些端点用；扩展身份与用户身份分开 |
| 授权 | 资源范围、操作权利、处理目的 | 读取、保存、同步、行动分别表达；处理目的（诊断、评测等）是独立维度 |
| 授权 | 接收方范围、处理位置 | 允许的接收者和处理位置，**包括远程模型供应商** |
| 授权 | 委派来源、来源版本 | 每次使用核查整条有效的来源链 |
| 授权 | 扩展摘要、权限上限 | 绑定安装版本；更新不自动获得旧许可 |
| 授权 | 状态、撤销版本、绑定的动作 | 单次授权消费后绑定到既有动作 |
| 会话确认 | 确认标识、经认证的用户 | 真实用户确认的来源；**不接受内容里出现的"已批准"** |
| 会话确认 | 动作摘要、条件版本、展示摘要、消费方 | 绑定展示给用户的资源、接收者和内容；只能消费一次 |
| 准入记录 | 请求描述、载荷摘要、内容引用 | 固定目标和内容；适配器不得在核验后改写 |
| 出口凭据 | 签发方、受众、提交方绑定、密钥版本 | 绑定核验端和提交主体；**签名有效不代表当前授权有效** |
| 出口凭据 | 准入、动作、尝试、发送标识、工作者版本 | 防止重放、重复发送和陈旧的工作者使用 |
| 出口凭据 | 授权版本、内容版本、操作权利和处理目的、请求摘要、截止时间 | 只覆盖有限的出口 |
| 内容 | 来源、载荷摘要、父内容 | 摘要、嵌入和工具描述也登记 |
| 内容 | 操作权利和处理目的的上限、位置、接收方、截止时间 | 派生内容的限制不得扩大 |
| 凭据记录（授权内部） | 秘密引用、提供方、账户、范围、允许的目标 | 只保存引用和绑定；原始密钥不进入通用内容或轨迹 |
| 凭据记录（授权内部） | 秘密版本、租约、轮换命令、状态 | 轮换、过期、泄露封闭和提供方状态分别记录 |
| 扩展安装 | 产物、依赖、清单、发布者的摘要 | 覆盖代码、Skill 文本、工具描述和依赖 |

补充规则：

1. **派生来源取保守并集，允许的用途、位置和接收方取交集。**模型输出至少继承本次输入上下文的全部可能来源，包括影响动作选择的控制依赖。模型不得自行声明"输出没有用到某条敏感内容"来解除限制；
2. 没有保存授权时，不保存原始内容。承担动作责任确实需要持久保存某项资料的，必须说明所需的保存范围；得不到许可就拒绝该动作；
3. 日志里的路径、收件人、查询和摘要同样可能敏感。通用轨迹只保存必要的关联和原因码，详细内容受内容治理控制；
4. 期限只是必要条件；本机时钟不可信时，拒绝依赖期限的新使用。

### 2.2 安全相关的状态

完整的状态模型见[核心契约 2.5](../core/contracts/README.md#25-状态模型)。安全上需要强调的语义：

| 记录 | 关键语义 |
| --- | --- |
| 授权撤销 | 撤销意图持久化后立即拒绝新的准入和许可签发；"所有执行端点都已停止"是另一个阶段，必须单独确认 |
| 单次授权 | 消费后不得准入第二个动作；原动作的核对或安全重放仍检查当前许可 |
| 出口凭据 | "已使用"不证明请求已送达 |
| 内容 | 先停用，再清理；"清理完成"需要全部受控持有方的有效回执 |
| 凭据 | 怀疑泄露时立即封闭旧版本；新版本失败时**不回退到泄露的版本** |
| 扩展 | 内容或权限需求变化就重新核验；隔离不抹掉它已经产生的动作责任 |
| 动作 | 只有动作账本写效果；授权失效、进程死亡、任务取消都不得把"未知"改成"未生效" |

## 3 接口

本专题不新增可替换的安全接口，相关命令由各负责模块提供：

| 接口（负责方） | 成功含义 | 主要错误 | 幂等 |
| --- | --- | --- | --- |
| 创建、委派授权（授权） | 许可已持久记录 | 主体不符、来源失效、范围扩大、版本冲突 | 同命令同请求返回原决定 |
| 撤销授权（授权） | 撤销意图已保存；是否全部停止另行查询 | 无权、版本冲突 | 幂等；不会重新激活 |
| 保存确认（会话） | 持久的确认记录，可供一次准入消费 | 挑战过期、展示不匹配、主体不符 | 不重复消费 |
| 签发、消费出口凭据（授权） | 有限的出口许可和持久的使用回执；不代表外部效果 | 撤权、内容停用、目标不符、重放、工作者陈旧 | 同一发送标识返回原使用状态 |
| 执行出口（出口闸门） | 已拒绝、已尝试或发送不确定，并关联回报；效果由账本裁决 | 参数或目标不符、出口不支持、秘密不可用、状态无法证明 | 重复调用查询原尝试，**不自行重发** |
| 读取内容（内容治理） | 本次允许使用的内容或引用 | 已删除、已过期、用途不符、版本陈旧 | 查询可重复；旧的"允许"结果不得长期复用 |
| 注册、启用扩展（扩展管理） | 安装或启用记录；**不产生业务许可** | 摘要不符、版本已撤销、隔离不支持 | 按产物和命令去重 |

两条约束：

- **凭据使用接口不返回原始秘密。**可信出口按批准的认证方式注入或签名。它不得做成"替任意 URL 加上 Authorization"的通用代理，只支持经过审查的认证方式和目标映射；
- 出现未知错误、不确定请求是否已越过出口时，返回"发送不确定"，不得返回"未执行"。

缓存可以保存"拒绝"结果；复用"允许"结果必须有不会陈旧的权威机制，普通的过期缓存不能单独满足 G8。

## 4 关键流程

### 4.1 有效权限的计算

> 有效权限 = 用户明确授权 ∩ 当前任务范围 ∩ 委派来源的权限 ∩ 扩展安装的权限上限 ∩ 内容的操作权利与处理目的上限 ∩ 当前宿主的限制

显式禁止、字段缺失、版本未知或规则执行出错，一律拒绝。委派使用可判定的结构化范围，不要求系统证明任意两段策略代码之间的包含关系（详见[授权](../core/grants/README.md)）。第三方 OAuth 的 scope 只是上限：凭据能做的事，不等于当前任务获准做的事。

### 4.2 一次动作经过的安全检查

| 步骤 | 处理 | 持久化位置 |
| --- | --- | --- |
| 1 | 会话验证用户事件；外部内容里的指令保留为内容，**不会变成用户确认** | 会话域 |
| 2 | 内容治理固定上下文引用和来源，检查当前用途和位置 | 内容治理 |
| 3 | 任务编排请求推理；模型调用同样经过准入和出口闸门 | 裁决域、账本域 |
| 4 | 推理返回提议；核心核验资源、接收者和参数，需要时生成绑定具体动作的确认 | 会话域 |
| 5 | 裁决域原子检查条件、授权、预算和确认消费，写准入决定和派发意图 | 裁决域 |
| 6 | 动作账本按 R7 接纳 | 账本域 |
| 7 | 账本记录尝试；可信的执行实现固定请求内容和实际目标 | 账本域 |
| 8 | 实际出口重新检查条件、控制状态、授权、内容、预算和工作者版本，消费出口许可 | 授权域、账本域 |
| 9 | 可信出口取得凭据，发送固定的请求；适配器不得在检查后修改目标或载荷 | — |
| 10 | 保存回报和独立证据；费用按计费来源去重；未知则核对 | 账本域、预算 |
| 11 | 任务编排依据证据和全部动作的收尾状态裁决完成 | 裁决域 |

没有任务的会话可以存在，但需要对外行动时，必须先关联或创建一个有条件版本的任务。后台的辅助调用不得借"空任务、空授权"绕过 G4、G5。

**实际出口必须检查的内容：**

| 出口 | 必须检查 |
| --- | --- |
| HTTP、模型、搜索、嵌入 | 接收方、账户、资源、路径、方法、查询、载荷、模型处理位置；**不得只看域名** |
| DNS、重定向、代理 | 连接到核验过的地址；每次重定向检查新目标；凭据不得带到未批准的目标；默认拒绝内网和云元数据地址 |
| 文件 | 对受控目录和实际对象核验；避免"先检查路径、再沿可变的符号链接打开" |
| GUI、设备 | 应用、设备、动作范围和观察版本；用户接管后旧动作不得继续发出 |
| 输出呈现 | 自动加载的图片、预览、远程附件和遥测同样检查；模型输出不得触发未准入的后台请求 |
| 扩展生命周期 | 初始化、钩子、安装脚本、依赖下载和更新都不得走业务出口的旁路 |

核心自身的持久化、跨模块交接和端云控制流量属于**可信基础设施 I/O**，不经过出口闸门（见[分层与模块](../layers.md)）；但它们使用固定的身份、目标和配置，不得承载扩展的任意请求，也不存在宽泛的"内部流量豁免"。

### 4.3 撤权与发送竞争

1. 授权持久记录撤销意图和新版本，停止新的准入和出口许可签发；
2. 出口执行与撤销在权威检查处确定先后（[执行开始排序点](../core/egress/README.md#41-正常调用)）；已进入发送窗口的尝试留在原动作账本；
3. 向执行端点传播停止要求，封闭尚未发送的许可，执行端点回报停止状态；
4. 不能确认某个执行端点已停止时，显示"撤销已保存，执行端点停止尚未确认"；
5. 已发送或可能已发送的动作继续由原账本负责，撤权不改写它的效果。

**"消费了许可"不等于"已经发出"。**许可消费和实际发送之间仍有崩溃窗口，恢复时必须保留"发送不确定"。

权威状态不可达时，默认暂停依赖它的出口：长期离线凭据加"重连后再撤权"无法保证每次使用都检查当前授权；短期凭据加撤权通知只能缩短窗口，不能消除网络分区中的陈旧许可。签名有效、未过期的出口凭据**不能单独证明授权仍然有效**。只有相关事实确实由本地的权威核心持有时，任务才能离线运行；不得借断网转移任务或授权的负责方。

### 4.4 内容删除与运行中的上下文

| 阶段 | 处理 |
| --- | --- |
| 立即停用 | 内容治理写停用版本；新的读取、推理输入、检索、派生和出口使用全部拒绝 |
| 找出影响范围 | 沿派生关系确定原始内容、摘要、嵌入、索引、缓存、提议、在途上下文和已准备的载荷 |
| 封闭继续使用 | 废弃相关的未执行提议；终止或隔离受控的运行上下文；**丢弃相关的迟到模型结果** |
| 清理持有方 | 持久发送清理意图；持有方持久接纳，回报版本、对象范围和结果 |
| 防止恢复复活 | 恢复备份前先应用删除记录；旧索引和旧缓存不得重新投入使用 |
| 确认完成 | 全部受控持有方回执齐备，验证索引和缓存不再返回该内容，才记录清理完成 |

外部接收方（远程模型、外部 Agent、收件人）不得仅凭自然语言回复记为"已清理"；按 [G9](../project-goals.md#4-不变量)，对外部接收方如实报告其状态。要求可验证删除的内容，不得授予不具备删除能力的外部处理方。

### 4.5 凭据生命周期

| 阶段 | 处理 |
| --- | --- |
| 引入 | 用户通过可信的设置或授权流程提交；原始凭据不经过推理或普通扩展 |
| 保存 | 端侧用平台安全存储；需要保存密文时用经过审查的认证加密，绑定用户、提供方、引用和版本 |
| 使用 | 授权和内容策略检查通过后，可信出口取得最小凭据，注入到固定的目标 |
| 刷新、轮换 | 先持久记录意图；按提供方语义取得新版本，验证后切换；新旧状态都可查询 |
| 怀疑泄露 | 先封闭使用，再撤销或轮换；保留原动作和用量的责任 |
| 恢复 | 设备专有密钥无法恢复时要求重新认证；不自动复制到云端，也不降级为明文 |

身份密钥、出口凭据签名密钥、存储加密密钥和第三方业务凭据分开管理。扩展不得修改代理、信任根、凭据目标或凭据库位置。

接入第三方服务时：MCP 2025-06-18 要求接收方验证令牌的受众，禁止把收到的客户端令牌直接透传给上游（[授权规范](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/b86ba24b90d7651faabd597f5e2060f8cd7a4e9a/docs/specification/2025-06-18/basic/authorization.mdx)、[安全实践](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/b86ba24b90d7651faabd597f5e2060f8cd7a4e9a/docs/specification/2025-06-18/basic/security_best_practices.mdx)）；RFC 9700 要求公开客户端使用 PKCE，刷新令牌采用发送方约束或轮换（[RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html)）。用户登录凭据、出口凭据和第三方 API 凭据分开；连接成功、MCP 会话标识、工具声明都不是 Lerna 的授权。

各平台的安全存储有各自的限制，要按平台选择：

| 平台 | 注意事项 |
| --- | --- |
| Apple Keychain | `WhenPasscodeSetThisDeviceOnly` 不同步、不备份；端侧专有凭据禁用同步；后台任务需要更宽的可访问性时，必须明确展示这个取舍（[Keychain 数据保护](https://support.apple.com/guide/security/keychain-data-protection-secb0694df1a/web)） |
| Android Keystore | 密钥可以不可导出，但被攻陷的应用进程仍能**使用**密钥；是否由安全硬件承载需要检查（[Keystore](https://developer.android.com/privacy-and-security/keystore)） |
| Windows DPAPI | 默认绑定登录用户；`CRYPTPROTECT_LOCAL_MACHINE` 允许同机其他用户解密，不得用于个人凭据（[CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)） |
| Linux Secret Service | 规范草案不强制应用访问控制，查找属性可能未加密保存；只在查找属性里放不敏感的标识，沙箱不暴露整个会话总线（[访问控制](https://specifications.freedesktop.org/secret-service/0.2/ch10.html)） |
| 云端 | 优先使用短期、限定资源的动态凭据；凭据租约状态与 Lerna 授权状态分别检查，不得互相推断（[Vault 租约](https://developer.hashicorp.com/vault/docs/concepts/lease)） |

### 4.6 扩展隔离与发布

1. 扩展管理核验固定的产物、依赖、声明、发布身份和撤销状态，并持久保存结果；
2. 在没有真实业务秘密、没有生产写权限的隔离环境中运行一致性测试和攻击测试；
3. 用户批准安装的权限上限；具体任务的许可由授权另行签发；
4. 每次运行绑定产物摘要、用户和受控的执行环境；按用户限制 CPU、内存、进程、队列和输出量。不可信扩展的每个计算工作使用**新的隔离实例**，不复用接触过用户内容的可变内存、宿主缓存、临时文件、共享内存或继承句柄；按用户隔离不够，同一用户两个处理目的不同的调用也可能经实例内存串通。跨调用的状态只能交还核心登记来源后再读回（见[内容治理 4.2](../core/content/README.md#42-摘要索引嵌入记忆与模型输出)）；
5. 更新改变了任何受控产物就重新核验；需要更大权限就重新授权；
6. 隔离恶意版本后封闭新执行；它的历史未知动作仍由原账本负责，核对不得要求重新启用恶意代码。

**沙箱限制执行能力，出口闸门限制业务权限，两者不得互相替代。**bubblewrap 明确由调用者定义安全策略（[README](https://github.com/containers/bubblewrap/blob/719a4fd474d44b26906bcf2b1b0fb6eddd8d56d0/README.md)）；gVisor 隔离了工作负载的系统调用，但安全模型仍依赖宿主的资源限制、网络策略和硬件防护（[安全模型](https://gvisor.dev/docs/architecture_guide/security/)）。"启动了沙箱"不是验收结论，必须验证网络、文件、设备、IPC、继承的句柄和宿主配置都没有旁路。无论用哪种沙箱，都不给扩展真实的业务连接、核心存储句柄、凭据库访问或可修改的出口配置。不同用户的恶意代码不得共用可读写的执行环境。

S8 的评测通过只允许进入发布流程，不得扩大权限，也不得降低核心规则。

## 5 故障与恢复

| 故障 | 负责方 | 恢复方式与安全约束 |
| --- | --- | --- |
| 回执丢失 | 原命令接收方、持久工作 | 按原命令查询；准入、撤销、删除、凭据轮换、出口许可消费都**不用新标识猜测重做** |
| 进程崩溃 | 持久工作、原动作账本、执行宿主 | 新工作者接续原责任，旧领取失效；崩溃可能发生在发送前后时保持未知；可信出口不得同时向新旧工作者开放同一个发送责任 |
| 重复请求 | 各命令负责方 | 同标识同摘要返回原决定，不同摘要拒绝；重复的执行请求不得消费第二次许可 |
| 并发冲突 | 裁决域、内容治理、原账本 | 准入与取消、撤权按版本原子排序；删除与内容使用的竞争靠当前停用检查和持有方封闭处理；冲突后重新读取，不沿用旧的"允许" |
| 依赖不可用 | 发起模块 | 授权或内容状态无法证明时不发新出口；安全存储不可用时不降级取密钥；账本不可写就不执行 |
| 迟到结果 | 动作账本、预算、内容治理、任务编排 | 真实的效果证据和费用仍然接纳；涉及已撤回内容的模型输出不得重新进入上下文 |
| 网络分区 | 事实负责方、端侧账本 | 依赖远端当前事实的出口等待；重连先核对授权、内容、控制状态和原尝试 |
| 刷新已成功但新凭据的回执丢失 | 授权（凭据管理） | 按提供方能力查询；无法确认且刷新令牌已轮换时要求重新认证，不盲目重复旧令牌请求 |
| 扩展挂起或耗尽资源 | 执行宿主、持久工作 | 按用户配额终止或隔离；已进入外部系统的动作继续核对，**进程被杀不等于未生效** |
| 伪造的效果或删除回执 | 动作账本、内容治理 | 核验主体、关联标识、版本和证据；证据不足就保持未知或"清理未完成" |
| 恢复旧备份 | 各事实负责方 | 先处理撤销、删除和版本撤销记录；未达到所需版本前不提供"允许"判断或执行出口 |
| 安全密钥疑似泄露 | 授权、执行宿主、扩展管理 | 封闭受影响的密钥和许可，隔离来源，追查关联动作；补偿是新动作，重新准入 |

## 6 不变量落实

| 不变量 | 怎样保证 | 怎样验证 |
| --- | --- | --- |
| G1 | 出口失败区分"确定未发送"和"可能已发送"；重试由账本依据目标的幂等或核对证据决定 | 在许可消费、建立连接、发送和回报各阶段逐点崩溃 |
| G2 | 权限通过、HTTP 成功、扩展声明都不算完成 | 伪造成功、迟到生效、查询暂未完成时不得成功关闭 |
| G3 | 准入、确认消费、授权使用、撤销和清理责任都有持久记录；跨域按 R7 | 丢失通知和回执、提交前后重启 |
| G4 | 固定条件版本、授权、预算和具体请求；实际出口重新检查 | 修改条件、收件人、目标、载荷或权限后，原请求被拒绝 |
| G5 | 可信出口持有外部资源的权限；扩展没有直接访问能力；辅助调用同样受控 | 恶意扩展尝试直连、DNS、文件、IPC、自动资源加载、初始化旁路 |
| G6 | 推理只能提交提议，不得签发授权、消费确认、写效果或终态 | 恶意推理直接提交授权、执行和完成声明，全部无效 |
| G7 | 委派和安装范围取交集；绑定版本，检查来源链的当前状态 | 随机生成委派链，验证子权限不超过任一来源；升级不继承扩权 |
| G8 | 每次使用检查当前的读取、保存、同步、行动许可，以及位置和接收方 | 读取后保存、私有资料公开发布、端侧资料进云端，分别被拒绝 |
| G9 | 先停用，沿派生关系清理，废弃上下文和提议；恢复不复活 | 删除中崩溃、持有方失联、旧索引、迟到结果 |
| G10 | 发送标识关联提供方的实际计费标识；取消不删费用 | 重复、迟到、更正的用量；合法的多次收费不被错误合并 |
| G11 | 工作者可以接替，任务和动作的负责方不变 | 旧工作者恢复、断网重连、节点替换，都不新建责任来规避未知 |
| G12 | 认证、引用、存储、缓存、秘密、执行环境和预算都带用户隔离，资源按用户限制 | 跨用户引用、缓存污染、句柄继承、凭据使用、负载攻击 |

## 7 取舍

| 选择 | 得到 | 付出 |
| --- | --- | --- |
| 确定性的权限控制做最终裁决 | 不依赖模型抵抗注入，符合 G6 | 必须把资源和用途表达清楚；宽泛授权内的语义欺骗仍然存在 |
| 可信出口持有真实资源和凭据 | 同时控制旁路和凭据投递 | 出口支持的协议要逐个审查，不得提供任意认证代理 |
| 内容来源保守传播 | 删除和用途限制可追溯 | 误阻断增多；先缩小上下文，再优化粒度 |
| 当前状态无法证明时等待 | 保持 G4、G8 | 离线可用性降低，需要如实呈现中间状态 |
| 固定产物，升级时重新核验 | 防止描述变更、依赖替换和隐式扩权 | 扩展更新流程更长 |
| 最小运行记录 | 降低日志外泄和删除负担 | 诊断材料较少；详细采集需要额外的用途许可 |

比较过的方案：

| 问题 | 方案 | 结论 |
| --- | --- | --- |
| 提示注入防在哪里 | 系统提示、过滤器、第二个模型裁决 | 漏报会直接变成越权；**只作辅助检测** |
| | **核心检查结构化提议、数据来源和实际出口** | 采用：模型被完全操纵时仍能限制后果 |
| | 完整的控制流/数据流解释运行时（如 CaMeL） | M1 不采用；以后作为推理实现的候选，不得代替核心。CaMeL 在 AgentDojo 上的安全任务完成率为 77%，无防御系统为 84%，并明确列出了模型假设和侧信道边界（[CaMeL](https://arxiv.org/abs/2503.18813)） |
| 授权的表达 | 角色或工具名白名单 | 表达不了任务、资源、用途和委派收缩 |
| | **结构化授权 + 核心规则检查** | 采用 |
| | 通用策略引擎 | 可以作为授权的内部实现，不开放给扩展替换 |
| 阻止扩展绕过出口 | 同进程 SDK 包装 | 只适用于 M1 经过审查的默认实现 |
| | **隔离进程 + 资源限制 + 可信出口代理** | M4 基线 |
| | 用户态内核或微型虚拟机 + 同样的出口代理 | 云端运行高风险扩展时的候选 |
| 凭据交给谁 | 长期密钥放环境变量或扩展配置 | 容易进入子进程、日志和模型上下文；不采用 |
| | 给扩展短期限定凭据 | 只在隔离环境、明确接受暴露、没有更好路径时考虑 |
| | **凭据引用 + 可信出口注入或签名** | 采用 |
| 内容限制粒度 | 只靠敏感词和秘密扫描 | 跟踪不了改写、编码和摘要；作辅助 |
| | **内容级来源并集 + 限制交集** | 采用 |
| | 字段级来源与显式数据流 | 证明不会漏掉依赖后逐步采用 |
| 签名表示 | JSON + JCS 规范化（[RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html)）；确定性 CBOR（[RFC 8949](https://www.rfc-editor.org/rfc/rfc8949.html)） | 首批 SDK 能一致支持 JCS 就优先用 JSON；必须拒绝重复字段、统一数字和字符串语义；金额和标识不依赖浮点数 |

可信基础与隔离等级、撤销的生效语义、凭据投递方式、内容来源的传播规则，正式采纳前必须写成 ADR。

## 8 待定事项

| 编号 | 问题 | 所需证据 |
| --- | --- | --- |
| H1 | 内容级的保守来源传播是否造成不可接受的阻断 | 在 S1、S2 中比较正常任务完成率、确认次数和阻断原因 |
| H2 | 当前授权和内容检查的延迟能否接受 | 按用户负载、端云往返和长任务频率测量；不得用普通的"允许"缓存规避 |
| H3 | 各平台能否强制覆盖全部出口 | 每个平台做真实的旁路测试，明确不支持的能力 |
| H4 | 哪些 API 的幂等和查询承诺足够可靠 | 针对固定 API 版本核查并复现故障，不只信适配器声明 |
| H5 | 允许的出口中，次数、时序等侧信道怎样限制 | 数据流和隐式依赖测试；不声称信息流完全无泄露 |
| H6 | 第三方模型、外部 Agent 的保留和删除是否可以验证 | 合同、配置和技术回执；证据不足时，不授予要求可验证删除的内容用途 |
| H7 | 硬件安全存储与后台任务的冲突 | 真机测试锁屏、认证、重启、丢失和备份恢复 |
| H8 | 安全基准和误阻断的发布门槛 | 固定数据集、攻击预算、模型版本和人工复核方法，在 [C8 评测](../platform/eval/README.md)中定义 |
| H9 | 适配器回报的可信程度 | 一致性测试不能证明任意扩展如实报告效果、幂等或删除；必须在[核心契约](../core/contracts/README.md)中定义证据来源、验证者和适配器支持等级，未经验证的回报保留未知 |

## 9 M1 范围

M1 是单用户、默认实现可信的可恢复主线，**只用于受控测试**。它验证准入、出口和恢复的结构，不宣称已具备恶意插件隔离或多用户生产保障。

| 事项 | M1 实现 | 推迟 |
| --- | --- | --- |
| 会话 | 真实输入与确认关联；确认绑定具体动作，只消费一次 | 分支：M2 |
| 授权 | 单次和持续授权；准入检查、当前有效性检查、有限的出口凭据、防重放 | 完整委派、复杂用途配置：M2 |
| 预算 | 准入硬上限；按单次上界最小预留；未知费用不得当作零 | 多维预算、更正、退款：M2 |
| 内容治理 | 来源、不可变版本、派生关系；拒绝明显未授权的数据投递 | 完整用途治理、删除传播：M2 |
| 出口闸门 | 默认实现覆盖全部业务出口，包括模型、API、文件、辅助调用和认证请求 | 恶意插件沙箱：M4 |
| 凭据 | 平台安全存储、引用、目标绑定、日志遮蔽；不可用时拒绝 | 多提供方动态租约、跨端管理：M2/M3 |
| 运行记录 | 基础关联和最小的安全原因码；不记录原始密钥 | — |
| 平台服务 | 不引入扩展市场、任意 Skill 执行或远程插件 | 网关 M3、扩展管理 M4、评测 M5 |
| 用户隔离 | 所有记录和引用从第一天带 `user_id`，拒绝不匹配的主体 | 多用户运行和规模验收：M6 |

M1 不引入还无法治理的长期敏感内容和任意扩展。如果要把 M1 当作处理真实个人资料的产品发布，必须提前补足相关的 G8、G9 控制；不得用里程碑安排来解释违反不变量的行为。

## 10 测试要点

验收依据是核心记录、实际出口和目标状态；模型口头拒绝不算安全通过。

### 10.1 一致性与故障注入

| 阶段 | 用例 | 必须成立 | 对应 |
| --- | --- | --- | --- |
| M1 | 恶意推理直接提出越权请求、伪造批准、声明完成 | 没有有效准入就没有出口；提议不产生授权或终态 | G4–G6、C1、C7 |
| M1 | 合法工具 + 恶意参数（改收件人、仓库、账户、路径、金额、凭据目标） | 被拒绝 | G4、G7、G8 |
| M1 | 准入提交成功但回执丢失 | 查询原命令得到同一决定；不重复消费确认或预算 | G3、G4、R7 |
| M1 | 在许可消费、发送前、部分发送、响应后逐点崩溃 | 保持原标识；不确定时为未知；不擅自重发 | G1、G3、G11 |
| M1 | 两个工作者竞争；旧工作者暂停后恢复 | 旧领取不得发送或覆盖状态；真实的迟到证据仍能关联接纳 | G4、G11 |
| M1 | 准入、取消、撤权和发送并发 | 检查顺序可追溯；没有有效责任的新出口被阻止 | G3、G4、G8 |
| M1 | 授权、内容记录、安全存储或账本不可用 | 不发依赖这些前提的新出口；不降级到明文或旁路 | G3–G5、G8 |
| M1 | 枚举模型、标题生成、摘要、重定向、文件和认证出口 | 每个实际出口都有准入和关联记录；不存在空任务旁路 | G4、G5 |
| M2 | 允许读取但禁止保存、同步或行动 | 每种用途独立检查；摘要和嵌入不得"洗白"限制 | G8 |
| M2 | 删除中崩溃、重复清理、持有方失联、恢复旧备份 | 停止使用；清理缺口可查；旧数据不复活 | G3、G9、R7 |
| M2 | 删除后，旧上下文、提议和迟到的模型输出返回 | 不得再进入推理、检索或出口 | G8、G9 |
| M3 | 分区期间云端撤权、端侧持有旧凭据、然后重连 | 无法证明当前许可时等待；重连先核对再推进 | G4、G8、G11 |
| M3 | 设备接管、观察过期、锁屏、秘密不可访问 | 旧设备操作不继续；不绕过用户控制或存储策略 | C4、C7、S3 |
| M4 | 插件直接访问网络、DNS、IPC、文件、设备、继承的句柄 | 沙箱实际阻止旁路，拒绝事件可关联，核心不暴露秘密 | G5、G7 |
| M4 | 随机委派链、祖先撤销、扩展更新与权限变化 | 任一来源失效即拒绝；版本变化重新核验 | G7、R5 |
| M4/M5 | 恶意 Skill 的初始化、依赖下载、工具描述替换、回滚 | 没有隐式的安装权限；已撤销的版本不因回滚重新启用 | C6、C9、G7 |
| M6 | 用户 A 引用 B 的任务、内容、授权、预算、秘密、回执或缓存 | 拿不到 B 的数据或权限；错误响应不泄露对象信息 | G12 |
| M6 | 恶意用户耗尽 CPU、内存、队列、输出和模型并发 | 其他用户的记录、预算和恢复语义仍然正确 | G10、G12 |

### 10.2 攻击测试方法

| 方法 | 内容 |
| --- | --- |
| 确定性的恶意实现 | 推理始终提出攻击请求，扩展主动绕行，持有方伪造回执。用来证明控制有效，避免"模型碰巧没攻击"导致的假通过 |
| 状态空间与性质测试 | 组合准入、撤销、删除、发送、崩溃和恢复的顺序；验证权限单调收缩、决定唯一、责任不丢 |
| 解析与规范化模糊测试 | 重复字段、编码差异、异常数字、路径和 URL 的不同写法；确保签名、授权和实际请求的理解一致 |
| 检查对象与使用对象的竞争 | DNS 变化、重定向、符号链接、目录替换、载荷修改 |
| 真实模型攻击评测 | 以 AgentDojo（分别衡量正常效用、攻击下效用和攻击成功率，[论文](https://arxiv.org/abs/2406.13352)）和 InjecAgent（[论文](https://arxiv.org/abs/2403.02691)）为起点，补充混合正常材料、多语言、图片、摘要和记忆攻击，以及长期记忆、断网、撤权、恢复和并发场景；允许攻击者根据反馈多次调整 |
| 事故回归 | 把 EchoLeak 的自动资源加载、GitHub MCP 的"私有读取后公开发布"、凭据目标改写、可信域名下的攻击者资源作为固定的回归类别 |
| 隔离与供应链测试 | 针对实际发布的产物、依赖和运行时配置测试，不只测 SDK 的配合行为 |

每次评测至少记录：实现和产物摘要、宿主和隔离配置、模型版本、数据集版本、攻击预算、规则版本、正常任务完成率、攻击下完成率、实际越权次数、误阻断和人工复核结果。

**确定性的不变量用例必须零违规。**有限样本下攻击成功率为零，只说明这组测试没有发现违规，不能证明不存在攻击。
