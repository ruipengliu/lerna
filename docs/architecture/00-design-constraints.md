# 设计输入与硬约束

状态：目标、参考部署与核心语言已确认；内核、协议、端云、记忆、大脑、执行、授权、扩展、观测评测/发布及能力里程碑已分册明确，技术方案已定稿。

## 目的地

依据 [项目目标基线](../harness-project-goals.md) 制定通用开源 Harness 的技术实现方案，以多个 Markdown 文件保存在本目录。当前工作属于设计与技术决策，后续业务实现由能力里程碑和实施计划交接。

## 已确认的设计约束

| 设计方面 | 必须保持的语义 | 主要关联 |
| --- | --- | --- |
| 结构 | 记忆、大脑、执行为逻辑系统；内核提供公共运行保障；能力数量不决定部署单元数量。 | A1、C1–C9 |
| 替换 | 三系统有可用参考实现并可独立替换；运行保障在替换后继续成立。 | A2、C6 |
| 端云 | 位置不固定，节点声明能力；本地能力与有效授权足够时可继续，依赖失联节点的步骤等待。 | A3、C5 |
| 持久化 | 任务状态与执行记录均需持久化；重连核对状态、授权和实际结果。 | C5 |
| API 执行 | API 接口为主要执行路径，GUI 用于适用兜底；支持超过 1000 个 API，首次调用正确率至少 90%，有限重试后的任务成功率至少 95%。 | C1、C4、C6、C8 |
| 外部动作 | 结果不明时先核对，再决定是否重试；无法核对进入待处理状态。 | C4、C5 |
| 信息生命周期 | 任务上下文不自动变为长期记忆；读取、提取、保存、同步分别受控。 | C2、C7 |
| 记忆 | 区分事实、偏好、推断与经验，保留来源、时间、置信度和适用范围，并落实查看、纠正、删除及用途限制。 | C2 |
| 记忆端云结合 | 重要隐私数据可保留在端侧并按权限检索、使用；支持端侧挖掘，明确数据及派生内容的端云存储和处理策略。 | C2、C7 |
| 授权 | 主体、资源、动作、范围与有效期统一表达；委派只收缩权限；执行端落实动作准入。 | A4、C7 |
| Agent 协作 | 内部 Agent 受 Harness 生命周期管理；外部 Agent 保留独立运行时，通过共同任务契约协作。 | C1、C5、C6 |
| 联网问答 | 回答依据实际取得的来源，保留获取时间，表达冲突、证据不足和获取失败。 | C1–C4、V1 |
| 手机 GUI | 观察、动作、再次观察和结果验证形成完整闭环，覆盖点击、滑动、输入、返回、中断及接管。 | C4、V2 |
| 观测与评测 | 关联跨端任务、工具、授权和结果记录；契约检查与效果评测分别提供证据。 | C8 |
| 自进化 | 经验、提案、隔离评测、发布、监测、回滚完整闭环；配置经评测逐步启用，代码由维护者确认发布。 | C9 |
| 验收 | 按 L1–L4 记录能力成熟度，架构约束与专项能力另有完整证据；量化指标注明环境与方法。 | C1–C9、A1–A4、V1–V2 |

这些是选型约束，不代表已经通过实现验证。

## 已确认的参考实现条件

以下记录来自本轮技术方案讨论中用户对三个建图问题的直接答复，后续选型以此为约束，无需重新选择语言、最小部署形态或是否要求真机。

| 条件 | 用户确认 | 对方案的约束 |
| --- | --- | --- |
| 最小完整部署 | 单机完整运行，按需扩展端云。 | 参考系统无需集群即可完整运行；端云是可扩展部署能力，不能以单机限制模块部署位置。 |
| 开发期依赖 | 使用 SQLite 等无外部依赖组件。 | 采用 SQLite 作为开发期持久化参考实现；数据库、队列、工作流集群等独立基础设施服务不能成为开发基线的必需依赖。 |
| 核心语言 | Go。 | 核心模块与参考运行入口采用 Go；其他语言框架仅作机制参考或可选扩展，不重新作为核心语言候选。 |
| 模块替换 | 模块清晰，依赖接口而非实现，可由业务或后续生产环境替换实现。 | 存储、模型、工具、传输等实现细节留在 Adapter 内；核心调用者依赖行为契约，替换实现须通过共同测试。 |
| 设备验证 | 不需要验证真实设备，可构建多模拟设备；主要验证能力。 | 验收以多个模拟设备的可观察状态、动作效果、协作与故障处理为基础，不要求指定手机操作系统、真机、Root 或开发者模式。 |

参考依赖已确认最低 Go 1.25.0，实际构建锁定经验证的具体补丁版本；wazero、MCP/A2A SDK 及格式版本见 [扩展清单、运行器与激活恢复](09-extension-contracts-and-activation.md)。受限 Wasm 首个参考验证组合为 Linux amd64 与 Interpreter，其他平台/引擎分别取得证据；这不限制通用接口的跨端扩展范围。

“无外部依赖组件”按部署要求解释为无需独立基础设施服务，并不禁止第三方 Go 库。联网问答本身需要网络来源；真实模型、搜索服务等按能力配置接入，不据此要求常驻云基础设施。单机完整运行不等于所有模块必须处于同一进程。

模拟设备须产生可核对的实际状态变化，不能用固定成功回执代替执行。V2 的观察、点击、滑动、输入、返回、再次观察、结果验证、中断和接管仍需完整覆盖。模拟验证记录其环境与支持范围，不将其结果表述为真实 Android 或 iOS 设备的支持证据。

这些条件已确定方案范围。[Go 内核与本地持久化](02-runtime-and-state.md) 已进一步明确模块职责、任务级原子提交和替换验证；[协议方案](03-contracts-and-protocols.md) 已确定 gRPC、WebSocket 及消息契约；[端云恢复方案](04-edge-cloud-and-recovery.md) 已确定所有权、离线授权边界和恢复算法。[记忆方案](05-memory-and-context.md) 已确定数据模型、上下文生命周期和端云驻留/联合检索规则。

[大脑与多 Agent 方案](06-brain-and-agent-collaboration.md) 已确定有限决策循环、模型独立替换、持续交互、受控委派和预算恢复；模型效果与运行故障的验证证据仍需后续实现提供。

[执行方案](07-tools-and-simulated-devices.md) 已确定 API 优先、千级目录及准确调用目标，目录、Driver、资源控制和故障矩阵见 [执行接口分册](07-execution-contracts-and-validation.md)。

[授权方案](08-authorization-and-user-control.md) 已确定本地身份管理、统一判定及处理端检查，认证、签发/撤销、离线有效期与凭证保存见 [授权生命周期](08-authorization-lifecycle-and-interfaces.md)。参考方案可自托管，不新增必需云端身份或密钥服务。

## 外部事实依据

已有 [技术格局研究](../research/agent-harness-landscape-2026-09.md) 可用于定位候选，但它明确不等同于批准的方案。已完成以下机制研究：

- [核实现行协议与 Skill 规范的适配边界](../../.scratch/harness-technical-design/issues/02-protocol-evidence.md)：协议现行版本、扩展、授权与生命周期映射。
- [核对持久运行机制与存储的部署约束](../../.scratch/harness-technical-design/issues/03-runtime-evidence.md)：持久运行机制、依赖及失败语义。

[真实设备路径研究](../research/harness-device-execution-options.md) 已转为未来 Adapter 的背景材料；真实平台选择与实测不属于当前方案的必需前置步骤。多模拟设备的设计见 [确定多模拟设备与工具执行的验证方案](../../.scratch/harness-technical-design/issues/10-execution-devices.md)。

外部文档支持机制判断，实际效果与性能需要在选定参考环境中验证。方案中不把未经实测的路径记录为已支持。

## 交付约定

技术选型与 Interface 设计在已确认目标下推进。技术研究若暴露无法满足现有目标的限制，应记录到决策票据并提出明确取舍；不能通过删减验收项隐去限制。

评测参考配置已由 [评测基准与发布判定](10-evaluation-contracts-and-release-gates.md) 固定：千级 API 均衡单步与独立多步计分、有限预算、适用的统计比较及逐步启用门槛。数值是实现验收目标，不能作为已经实测达标的证据。
