# 授权生命周期、凭证与控制接口

状态：已确认；[身份、授权与用户控制](08-authorization-and-user-control.md) 中的架构基础已获接受。本文件不代表已完成实现或安全验证。

决策依据：[确定身份、授权与凭证的执行位置](../../.scratch/harness-technical-design/issues/11-authorization.md)。外部事实见 [认证与离线时间研究](../research/harness-identity-credentials-and-offline-time.md)，下列机制已由用户接受，属于 Harness 的参考设计，不将标准提供的局部机制等同整套授权保障。

## 授权数据与策略一致性

将策略、授权记录及签名材料分开：策略表达当前限制，授权记录表达谁在什么范围内授予了什么权利，签名材料用于另一处理端核验特定范围内的授权。持有合法签名不保证当前仍未撤销，不替代节点认证、任务拥有者资格或资源控制。

| 对象 | 必要内容及约束 |
| --- | --- |
| 主体与节点登记 | 受信身份、所属命名空间、可代理主体、认证材料版本及失效状态；显示名称不可充当可信绑定。 |
| 策略 | 资源范围、允许/禁止动作与用途、位置和数据限制、签发及管理权限、单次/持续和离线条件、修订。每个策略范围的修改权威明确，子范围不能放宽上级强制限制。 |
| 授权记录 | 签发方、被授权主体、代理执行者限制、目标资源及动作、用途、允许位置、接收方、期限、父授权引用、委派深度与额度条件、当前状态。授权续期或扩大范围须重新通过有权签发，不修改旧材料后继续重放。 |
| 验证材料 | 绑定对应授权、签发与验证上下文、接收方和代理身份、有效区间及所依赖的策略修订；采用下述受限签名格式及持有者校验。 |
| 用户确认 | 明确的请求内容、回应主体、等待项及有效版本；仅确认此请求，不作为任意其他任务的通行证。 |

策略引用使用命名空间内的键及修订；授权引用可关联产生它的签发操作，不增加与之独立、重复的全局授权请求身份。签名材料版本、密钥编号及撤销游标作为相应记录的元数据；不会进入每条业务消息成为额外通用 ID。

策略与授权更新通过各自权威的本地原子提交管理，连同回执及变更通知持久化。其他节点持有带修订的授权副本，不能离线修改同一权威记录再最后写入覆盖。端侧可对其独立管理的资源签发范围内授权，云侧不得凭管理身份放宽端侧私有资源策略。

判定按照可信身份、适用授权及委派链、资源策略和运行资格逐层校验。硬性禁止与未知必需条件不能被另一个允许条目覆盖；委派引用的所有祖先限制均有效。具体可比较的资源选择器、动作集合、用途、位置、期限和额度构成参考策略语言，不以任意自然语言策略宣称已经证明收缩。无法证明子范围包含于父范围时拒绝派生授权。

参考选择器限定为命名空间内的精确资源引用、枚举集合或已登记的资源树子范围；关系和标签来自受信登记，不采信请求自报的归属。动作、用途及位置用有限集合比较，期限用包含关系比较；未知谓词、无法界定的动态范围或超出预算的判定均不得生成允许结果。策略匹配数量、委派链深度及求值时间有上限，错误原因遵守资源可发现范围。

## 准入与授权消费

授权判定返回允许、拒绝或需要输入，以及限制、判定所依据的策略/撤销修订与适用有效区间。处理端无法落实某项必需限制时返回不支持或拒绝；不能只记录限制然后忽略。

单次授权绑定一项确定的逻辑操作及语义，传输重发和按原操作核对不重复消耗；变更目标、参数或改走不同语义的 GUI 动作需要重新判断是否有授权。持续授权可覆盖范围内多次操作，但仍受期限、额度及撤销控制，不因其名为“持续”而无限有效。

受限次数或额度须有可核验的预留及消费记录，不能将同一单次授权复制给多个节点并各自使用一次。参考方案将单次执行许可绑定一个执行接收方和原操作；跨端委派分配独立、不重叠的额度。未知消耗保持待核对，不能因接收方失联就把额度重新分配。

授权额度与任务运行预算分别约束，同一工作必须同时满足两者；给任务加预算不自动扩大授权，取得新授权也不自动增加任务预算。实际动作前复核当前可见策略及执行资格；跨节点没有全局原子撤销，已开始动作按原有取消和效果核对流程处置。

配额签发端先持久化预留及接收方绑定，再交付执行材料；执行端在其 ExecutionStore 中将单次许可消费与原操作启动登记原子提交。两端不是一个事务：材料交付未知时不重复分配，执行端重启按原操作恢复，只有证明旧端不能再使用且消耗已核对后才回收配额。授权模块的纯判定不承担隐式消费，任务预算仍由既有 RunStore 规则管理。

其他处理模块也须实现声明支持的单次消费：记忆变更可在其业务提交中绑定消费；单次读取在披露前持久化许可绑定的语义及读取修订/结果引用，重试只恢复原获准结果。无法恢复原结果时报告不可恢复，不凭原单次许可重新取得范围外或更新后的内容。不能原子整合消费的模块先通过本地受控消费记录预留，交接不明保留占用；不得仅调用无状态 Evaluate 就宣称已落实单次限制。

内核与 Worker 的状态推进资格仍由任务拥有者和执行协调方的受信规则确认，授权签名不使旧 Worker 重新有效。动作开始登记与资源控制按执行分册串行化；资格失效后的迟到效果作为事实保存，不能通过授权拒绝丢弃已经发生的结果。

## 签发、委派与撤销

IssueGrant 仅由有权签发者执行。DeriveGrant 根据原授权产生更窄范围，限定接收者、资源、动作、位置、用途、期限、委派深度和额度。签发权限不能从普通执行授权隐式推导。子任务拿到自身授权范围内的材料，不取得父主体的长期身份凭证。

RevokeGrant 原子记录撤销及待发送通知，重放同一撤销操作返回原回执。接收端收到撤销后原子推进本地已知撤销状态，先停止新受限工作，再处理在途操作、上下文失效和数据生命周期。撤销父授权同时约束其派生授权；在线验证不能仅检查最后一段。

撤销界面区分权威已记录、接收方已应用及仍待送达。签发方不可达时，资源处理方可先按其自身权限收紧本地准入，但不能伪造远端权威已撤销。恢复连接后先获取当前策略及撤销信息，再接纳依赖在线状态的新工作。

不提供“永远离线运行”与“远端撤销立即生效”的组合保证。允许离线的授权必须有有限期、接收方/操作或额度绑定以及可验证条件；需要在线核验的工作断连后等待。时钟回拨、重启和旧备份恢复的处理须纳入故障测试，不能只比较消息里的时间戳。

## Interface 与用户控制

| Interface | 计划方法 | 责任与失败语义 |
| --- | --- | --- |
| IdentityVerifier | Authenticate | 将可信连接或登录会话验证为受认证上下文；认证失败不得退回自报主体。 |
| Authorizer | Evaluate | 返回允许/拒绝/需输入及可执行限制；不直接写业务状态或执行副作用。 |
| GrantAuthority | Issue / Derive / Revoke / Get | 校验签发或派生权限，持久化授权及撤销；身份重放先核对原语义，修订冲突显式拒绝。 |
| AuthorizationStore | Load / Commit / LookupCommit / ReadSnapshot / ReadChanges | 策略、授权、撤销、管理操作回执及通知本地原子保存；提交未知先核对，游标失效重新获取获准快照。 |
| CredentialBroker | Use | 在获准的目标和用途下向受信执行路径提供受限凭证使用，不向大脑返回原始密钥；凭证不可用/过期/作用域不符分别报告。 |

这些是逻辑接口，不要求分别成为远程进程。管理协议置于现有任务协作领域的 AuthorizationService；连接身份建立仍属于端云连接领域，所有领域在各自处理点调用相同授权判定。固定字段及方法经现有 gRPC/WebSocket 绑定，不新增第五类协议。

| 管理方法 | 请求与结果 |
| --- | --- |
| IssueGrant / DeriveGrant | 稳定操作身份、明确授权内容及预期策略修订；派生附父授权与预期修订。交互批准附有效等待项关联；成功返回授权引用及可披露材料。 |
| RevokeGrant / GetGrant | 撤销携带自己的操作身份、目标授权及适用预期修订；查询按当前权限返回记录及撤销传播进展。 |
| UpdatePolicy / GetPolicy | 更新核对管理主体、资源范围及预期修订；未知或更宽范围不自动接受。查询按授权返回策略及版本，不泄露隐藏资源。 |
| LookupOperation | 按稳定管理操作引用查询受理与提交结果；授权检查先于回执读取，不能解引用出未获准签名材料。 |
| ReadSnapshot / ReadChanges | 输入获准策略/授权视图及分页或变更游标；返回一致快照边界、连续变更及删除/撤销状态，不是 AuthorizationStore 的任意远程读取。 |
| TaskService.AdjustLimits | 稳定操作身份、任务引用、预期任务版本和明确预算/期限变更；校验调整权限并持久化，重复请求返回原回执。 |

管理操作同样沿用“认证与授权检查→已知操作去重→新操作版本比较→原子提交”。签发及更新结果未知时核对原操作，不生成新的签发动作；不得仅凭猜中操作 ID 查询到授权材料。

AuthorizationStore.Commit 将策略/授权修订、管理回执、预留或撤销与通知 Outbox 在同一权威范围内提交；签发材料只在成功提交后交付，提交不明先 LookupCommit。签名材料基于固定的授权内容及预期策略生成，提交遇到修订冲突时不能继续交付旧材料。签发私钥不可用时报告暂不可用，不退回未签名许可。

ReadSnapshot 提供绑定获准视图、修订边界及分页位置的一致快照，完成后从该边界读取 ReadChanges。接收端将本地策略/撤销变更与已应用游标原子保存，消息持久化回执不能充当已应用回执。过期游标、视图或不可接续的缺口触发重新取快照，覆盖报告与通知也受披露策略限制。变更流中的验证密钥仅来自已经受信的签发者更新流程，不允许普通策略同步创建新信任根。


缺少可补充授权时，内核请求授权模块创建绑定具体范围的等待项。授权模块持有该等待项的批准与失效权威，任务只关联其当前状态。用户经 UI 的正式回应触发相应管理处理，签发仍由有权主体执行；拒绝回应关闭相应等待项而不产生授权。等待内容变化后旧回应失效，原回应重试仍关联原回执。拥有既有持续授权的工作不走新的确认流程。

授权等待项由授权模块在 AuthorizationStore 内按版本管理；批准时原子核对请求仍有效、记录回应操作并签发对应授权，其他回应只能取得原结果或失效拒绝。任务侧通过幂等结果交接接收授权引用，不声称任务状态、UI 状态和授权库一次提交。若任务取消与有效批准先后交错，已批准授权也不能启动被任务控制禁止的操作；不再需要的单次授权按其绑定和期限处置。

AdjustLimits 不能重新打开终态、撤销暂停或取消，也不直接修改其他节点已有离线预算。降低预算不得抹去已消费和未结算预留；需先处置相关工作，不能把账面减小当作远端额度已收回。缩短期限同样保留已开始工作的实际效果和收尾责任。

## 凭证位置与最小权限使用

CredentialBroker 按资源策略在实际执行位置解引用，绑定目标服务、账号、用途与驱动身份。只有受信 Driver 或受控出口可获得调用所需的短期使用能力；第三方 Agent 收到的是受限 Harness 能力入口，不是用户长期密钥。

原始凭证不得出现在模型上下文、任务普通载荷、搜索索引、日志或错误文本。引用本身也需授权，不能成为任意节点可下载密钥的地址。第三方认证材料与 Harness 授权不自动互通；外部账号权限过宽时仍由受信执行路径检查具体动作，不能将全部权限转交扩展。

参考实现采用下述本地加密存储与可替换主密钥来源。加密文件不等于能防御已控制宿主进程的攻击者，进程内受信扩展的信任假设沿已确认的架构基础。

## 节点、浏览器及首次信任建立

原生节点间 gRPC 和 WebSocket 使用双向 TLS。节点证书中的约定身份字段与受信登记记录精确匹配；验证证书链及目标身份后，按本地已知登记状态、密钥版本及撤销检查当前资格。长连接和恢复的 TLS 会话不能跳过应用层节点失效检查。默认节点直连，不直接信任终止 TLS 的中间代理声称的身份头。

首次安装从本地受信管理入口建立管理员与信任根。节点加入通过一次性、短期且绑定待加入节点公钥及目标命名空间的登记请求完成；管理员核对加入范围，接收节点验证预先获得的信任根。连接成功、自签证书或自报名不得自动登记为受信节点。

参考首次登记由本地受信管理入口核对公钥请求并交付签发证书，节点私钥留在所属节点，不要求未经认证的新节点先通过正常 mTLS 入口。首次信任根通过受信管理路径配置；自动发现只提供待核对线索。登记与节点禁用记录由受保护的身份管理处理器按版本持久化，日常业务消息不能自行修改登记。

浏览器 UI 使用同源 HTTPS 登录及服务端不透明会话，WebSocket 升级时同时验证会话和允许的 Origin。Cookie 设置 Secure、HttpOnly 和适用的 SameSite 策略，状态变更入口校验 CSRF 保护；会话到期、登出或用户禁用后不再接受新受限操作，已建立连接也须重新检查。原生节点端点和浏览器端点使用明确互斥的认证配置，不能在节点 mTLS 验证失败时退回较弱的浏览器身份。

本地参考管理登录可由受信 CLI 生成一次性短期登录码，经同源登录提交换取会话；不把登录码放入 URL，不将其当作长期 API 密钥。后续外部用户登录通过 IdentityVerifier Adapter 映射相同主体语义。注册、登录、换取会话及失效操作均受限速与重放检查，不引入常驻外部身份服务。

浏览器身份、节点身份与原始请求主体分别保留。节点代表用户操作时必须携带经过受信签发、接收方及代理身份校验的关系；原生调用不接受仅凭节点证书自报任意用户。进程内嵌入入口由受信宿主构造认证上下文，不允许普通工具参数覆盖它。

## 短期签名授权与转发

跨节点授权采用非对称签名的 JWS/JWT 受限格式，参考算法固定为 ES256，使用符合 JOSE 的实现处理签名编码与验证；Go 的 ASN.1 签名字节不能直接当作 JWS 签名。具体依赖版本在实现时锁定并通过互操作测试，算法替换需显式兼容配置，不能依据不可信请求任意切换。要求明确的类型、签发者、目标接收方、授权引用、主体及代理限制、签发/生效/到期时间、父授权和必要约束；固定允许算法和大小限制，拒绝无签名、算法混用或未知必需字段。密钥编号只查受信映射，材料中的任意远程地址不能引入新信任根。

签发私钥仅由获准签发方保管，验证方使用公钥。跨节点材料除 audience 外还绑定实际出示节点的证书摘要，验证时与当前 mTLS 对端比较；只验签而不比较持有者不算通过。该规则是 Harness 自身协议约束，参考现有证书绑定机制，不声称等同完整 OAuth 实现。

签名声明使用 `iss / sub / aud / iat / nbf / exp` 及明确的 Harness 类型/版本，`cnf.x5t#S256` 绑定已验证的实际出示证书；授权引用与约束使用具名应用字段。入口将已验证的出示关系绑定并保存到原操作，后续本地恢复使用该受信记录复核当前适用资格，不伪造一条仍存在的旧 TLS 连接。更新验证材料不修改原操作的业务语义或业务期限。

材料只保存必要且获准披露的范围与引用，避免放入端侧私有正文；签名格式不提供内容保密。单次消费仍依赖操作身份及接收方持久记录，不能把签名材料本身当作去重系统。

普通网络透传保持端到端认证及原操作。确需另一节点代理出示时，经有权签发方产生绑定新出示者及接收方的更窄材料，保留原发起关系及祖先限制；不能照搬绑定上一跳证书的材料。该授权材料变化不改变同一逻辑业务操作的身份。默认不支持未经声明和验证的任意代理链或 TLS 身份转换。

节点证书轮换需重新签发依赖其摘要的授权材料。有效旧节点可按既有权限申请受限轮换；密钥丢失或疑似泄露需受信管理入口重新登记及撤销旧资格。签发密钥轮换使用有界重叠验证期，旧材料仍受其原期限和撤销限制；信任根替换须通过原受信管理关系，不能由任意发现消息触发。

## 离线有效期与时间异常

参考信任假设包括节点操作系统和授权签发方的时钟来源受信；不承诺防御已控制宿主系统的时间篡改。接收方在线核验有限授权时建立时间锚点及本次进程内的最晚执行期限，期限不超过授权到期和策略允许的最大离线窗口，计入允许的时钟不确定性。

同一进程内结合时间锚点、单调经过时间和可检测的时钟/休眠异常检查期限。每次新动作、授权续期和控制资格变更均重新检查，不因长连接仍存在而延长。发现回拨、休眠导致时间不确定或过大偏差时，停止新受限工作并重新验证；已发出的动作继续按效果核对记录。

依赖远端有限授权的执行在离线重启后默认等待重新建立可信时间和授权状态；持久化剩余时长不作为仍有效证明。单机本地权威可以在受信本机环境中重新验证本地策略与时间、建立新的执行资格，不要求联系外部云服务。允许远端离线重启继续执行的替代实现必须另行提供可信时间与防回滚证据，不能由普通本地文件推导该保证。

撤销通知有界可靠补发，接收端持久化已应用修订/游标。游标过期时重新获取获准快照，不能把旧撤销列表清空后开始执行；旧备份恢复沿既有隔离和重新核验规则处理。新鲜度不足但有仍有效离线授权的工作只在原有限范围内运行，在线必需工作等待。

授权、节点证书和会话有效期、最大离线窗口、允许时钟偏差及轮换重叠期均由受权部署配置给定，必须有限且校验相互约束。未配置必要期限时拒绝启动相应功能，不使用隐式无限期默认值。

## 本地凭证保存与轮换

开发参考使用 SQLite 保存 AES-GCM 认证加密后的凭证，主密钥由独立受限文件注入；节点各自持有允许位置内的密钥与密文。主密钥不写入凭证数据库、任务配置或日志。提供主密钥供应 Interface，后续可以接入操作系统凭证设施或外部密钥管理，但不成为单机必需依赖。

加密使用成熟实现并遵守 nonce 唯一性及每密钥用量限制；附加认证数据绑定从可信上下文取得的凭证引用、主体、目标服务及格式版本。引用替换或跨账号搬移应校验失败；合法旧记录的整体回滚另受持久版本及恢复流程约束，加密不自动解决回滚。

开发默认受限文件支持无人值守启动，保护范围明确为文件访问控制与数据库单独泄漏；若主密钥与密文都被读取或宿主执行进程被控制，则不能保证保密。需要人工解锁或更强宿主隔离时由替代主密钥供应实现声明，不能将其假定为默认已支持。

密钥轮换保存记录的密钥版本，逐条重新加密并可断点恢复；新密钥生效前保留可读取旧数据的必要材料，完成迁移及允许的备份保留处置后再清理旧密钥。凭证轮换与第三方令牌续期按提供方契约执行，结果不明时先核对，不生成无限重试。

凭证缺失、过期或主密钥不可用时暂停依赖该凭证的新调用，其他独立工作可继续。解密后仅在受信执行路径必要的生命周期内使用，不承诺通用运行时中所有内存副本均可可靠擦除。诊断记录仅含受控引用和原因，不输出密钥内容。

## 验证与后续分工

接口、生命周期和参考认证/凭证机制已确认并同步协议目录及模块入口。验证包括伪造代理主体、跨接收方材料重放、父授权撤销、单次授权重复消费、游标/时钟异常、旧备份、迟到确认、额度调整、密钥轮换及秘密出口。所有检查必须验证实际拒绝与恢复事实，不能仅依赖审计文本。


## 故障与一致性验证矩阵

| 验证项 | 应核对的行为 |
| --- | --- |
| 节点身份错绑、证书失效及恢复 TLS 会话 | 原始主体和节点映射不可伪造，长连接仍检查当前登记状态；不能退回其他认证配置。 |
| 浏览器错误 Origin、会话过期和重复登录码 | 握手及状态变更入口拒绝，登录码只消费一次；已建立会话/连接不保留无限授权。 |
| 错误签发者、受众、算法、证书摘要或未知限制 | 实际准入失败；可信签名不能覆盖错误接收方或出示者。 |
| 委派扩大范围、超深链、父级撤销 | 签发及执行两端拒绝；已知祖先限制与撤销不能被子授权隐藏。 |
| 单次授权重复提交、双 Worker、配额交付不明 | 原操作只对应一份消费记录，未知占用不回收，不因新连接再次消费或扩额。 |
| 授权存储提交中断、签名完成后提交冲突 | 原提交可核对，未提交或失效材料不交付，不补发新的业务签发操作。 |
| 策略通知丢失、快照分页与游标过期 | 一致快照接连续变更，应用与游标原子推进；信息不足不错误放行在线必需动作。 |
| 离线撤销、重启、休眠或时间异常 | 有效离线范围与在线必需范围分别处理；时间不确定停止新受限工作，本地权威恢复不要求外部云服务。 |
| 用户重复/迟到确认、任务取消与批准竞态 | 确认绑定原等待项和范围；任务控制不被新授权清除。 |
| 降低预算、缩短期限和远端额度未结算 | 不清除实际消耗及预留，不提前收回仍可被远端使用的额度；收尾继续受控。 |
| 凭证目标错绑、密文替换、主密钥缺失及轮换中断 | 不向错误目标使用凭证，失败不泄露正文；轮换可恢复且不提前清理必需旧密钥。 |
| 私有记忆、能力目录、模型输入与结果出口 | 实际拒绝未获准读取/发送，受限凭证不进入普通消息、索引或日志。 |
| 进程内受信扩展与独立不受信扩展 | 分别记录信任假设和实际隔离证据，不把接口约束或独立进程等同强隔离。 |

本册规定需实现的行为及故障用例，尚未执行代码、浏览器兼容、密码互操作、离线时钟或安全实验。实际平台、期限配置、模型与扩展实现版本随测试报告记录。
