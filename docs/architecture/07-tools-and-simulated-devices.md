# 工具执行与多模拟设备

状态：已确认。覆盖 API 优先与 GUI 兜底、千级 API 发现与准确调用、执行协调、资源接管及模拟验证；尚无实现或实测结果。

目标约束见 [项目目标基线](../harness-project-goals.md)，决策过程见 [确定多模拟设备与工具执行的验证方案](../../.scratch/harness-technical-design/issues/10-execution-devices.md)。沿用 Go、单机完整运行、SQLite、按接口替换及无需真机验证的已确认条件。

## 已确认的前提

- 主要执行路径是 API 接口调用。GUI 用于第三方应用没有可接入的 API 能力或适用的兜底情况，仍保留 V2 的完整专项验收。
- 支持 1000 个以上 API；首次调用正确率至少 90%，有限重试后的任务成功率至少 95%。以上为用户指定的目标；独立业务操作计数、完整目录验收、首次与最终分别计分及预算预先固定的原则已获接受，预算具体额度与统计方法见已确认的 [评测基准](10-evaluation-contracts-and-release-gates.md)。
- 大脑提出行动，内核接纳并持久化工作，执行系统落实动作准入并报告事实。
- 沿用 [能力调用契约](03-contract-message-catalog.md) 的稳定操作身份、查询、效果核对、取消和接管语义，不为设备另建任务协议。
- 设备操作与 Harness 自身的 [UI 交互](03-ui-interaction-contracts.md) 是不同职责；两者均须验证。
- 未知效果先核对；取消受理不等于停止；既有实际效果不能因目标修改或重启被清除。
- 模拟设备有独立可观察状态，动作改变状态，且可注入故障。模拟设备与运行节点、进程不必一一对应。
- 输入、截图、界面文字、结果和日志沿用 [端云数据策略](05-edge-cloud-memory.md)。数据只能本地处理而本地能力不足时，不自动转交云端。

## 执行接口与能力差异

执行入口统一使用能力声明、调用、状态查询、核对与受控中断。工具与设备 Adapter 经这一共同契约接入；具体能力以版本化输入输出 Schema 表达，不强制所有工具实现点击、截图或接管。

能力表达要完成的行为；API 与 GUI 表达可能采用的执行路径。API 优先选择适用、可达且获准的 Adapter；这里的 API 包含本地和远程接口，不限定为云端 HTTP。Harness 模块间 gRPC、端云 WebSocket 的既定协议绑定保持适用，外部系统的具体协议由 Adapter 适配。

路径切换作为显式、可记录的决策：目标语义、结果条件、权限、数据处理位置和可核对性都满足时，才允许 GUI 兜底。API 无接口或明确不支持所需行为，与请求超时、限流、权限拒绝和未知效果分别处理。普通故障按能力契约有界重试或等待；权限拒绝不能靠 GUI 绕过。API 可能已经生效时先核对，无法确认则保留等待，不能再次通过 GUI 执行同一业务变更。

API 与 GUI 通常具有不同参数和能力目标，不强行共用相同操作身份；原 API 操作及核对事实保留，获准的新 GUI 动作使用新的操作身份并关联原工作。若 Adapter 内部提供真正统一的逻辑调用契约，其内部切换仍须保持该契约声明的去重与效果保证，不能隐藏未知结果。

设备观察、点击、滑动、输入与返回作为设备能力族。动作携带明确目标设备、输入及必要的观察前提；能力声明说明支持的观察形式、定位方法、核对、中断、离线及并发条件。执行端重新核对真实可用能力，不将发现时的声明当作永久有效承诺。

共享执行模块管理接收记录、去重、准入与报告；驱动处理目标交互及证据取得。驱动仍须声明自己能否持久核对、按操作身份去重或停止，公共模块不能凭本地日志补出外部系统没有的保证。具体 Go Interface 和持久化边界见 [执行接口](07-execution-contracts-and-validation.md)。

## 已确认方向：千级 API 的发现、选择与准确调用

按可独立调用且业务语义不同的 API 操作计数；同一操作的不同 URL、部署节点、别名或重复版本不重复充数。参考验收目录应超过 1000 项，并在同一运行配置中可被发现和选择，而非分批手工缩减为几个已知工具。该规模不等于要求 1000 个并发请求，也不等于接入 1000 家服务商。

采用已确认的分阶段选择：先按权限、用途、位置及必要能力过滤，再检索和排序候选能力摘要，按需加载候选的完整 Schema，最后由大脑生成有限调用提案。索引可重建，正式目录及具体版本的声明才是准入依据。候选不足时有界扩大检索或请求澄清，不能猜测不存在的接口；语义近似不代表可互换。无需把所有 API 的完整定义一次放进模型上下文。

API 描述至少解释用途及不适用情况、目标资源、输入输出、前置条件、副作用、幂等与核对语义，并提供适当示例。参数校验除 Schema 外还要核对资源身份、引用来源和业务前提；语法合法不能证明选中了正确用户、设备或对象。权限检查在候选发现和实际准入分别落实。目录更新、能力下线与权限变化后仍需重新校验，不能凭旧候选继续调用。

能力发现作为可替换职责接入现有能力调用领域；检索 Interface、索引与缓存策略见执行接口分册，能力声明质量和导入生命周期交由扩展分册确定。不预设必须引入外部向量数据库，不因能力检索让大脑获得私有执行通道，也不改变已有有限提案和持久化准入规则。

将“准确”拆开测量，结果都须在完整千级目录存在时获得：

| 指标 | 验证含义 | 防止误判 |
| --- | --- | --- |
| 候选覆盖 | 满足任务的有效 API 是否进入候选集；记录候选数量和检索预算。 | 模型无法从缺失的正确候选中选对；测试不能提前注入答案对应 API。 |
| 首次调用正确率 | 第一次提案是否选对能力及版本、目标资源和全部必要参数。 | Schema 通过率或 HTTP 成功率不能代替语义正确率。 |
| 有界任务成功率 | 在固定重试、决策和时间预算内，调用顺序及最终业务状态是否满足目标。 | 不以无限重试或忽略中间错误副作用换取成功。 |
| 正确不执行 | 无合适 API、信息不足或权限不允许时，是否按预期澄清、等待或拒绝。 | 正确拒绝单独计分，不用于抬高可执行任务的成功率。 |
| 副作用与约束 | 是否有错误目标写入、重复变更、越权或数据违规。 | 相关用例一旦出现违规即不通过，样本未出现不等于任意环境永不发生。 |
| 覆盖与成本 | 各 API 及能力族覆盖、长尾表现、延迟和模型用量。 | 同时报均值、分组与每项覆盖；不能只反复测少数容易接口。 |

测试集覆盖每项 API 的适用调用，并增加近义接口辨别、参数依赖、多步组合、缺失信息、权限变化及回执丢失等用例；评测任务与训练或示例数据分离，生成用例须独立核验预期结果。先以有状态模拟 API 验证规模和业务效果，再分别记录真实外部 Adapter 的验证范围。模拟目录通过不代表已有同数量真实第三方系统完成接入。

用户已确认首次调用正确率至少 90%、有限重试后的任务成功率至少 95%。两项分别达标，不用修复后的结果改写首次正确性。测试集版本、模型配置、预算、抽样量与统计不确定性需随评测报告记录。契约检查和模拟状态测试不替代真实模型选工具、填参数与规划的效果评测。

## 已确认方向：90% / 95% 的验收口径

在预先固定的可执行测试集上验收两项指标；任务目标、初始状态、可用能力及预期效果在运行前确定。需要澄清或应拒绝的任务独立计分，不混入可执行任务以提高成功率。接口能力不可达等故障按预先设计的故障测试另报，不能在运行后随意剔除失败样本。

首次调用正确性从完整能力目录的检索开始计算。候选检索遗漏、错误选型、错误目标或参数都纳入失败；因模型输出不合格而修复也应记录，不能先隐藏纠错再把最终产物计作首次正确。检索、加载 Schema 和正常的多步计划分别建模，不能把所有准备动作都算成一次业务调用。

有限重试后的任务成功必须满足最终目标，同时没有违反约束的错误副作用。只读错误可以在预算内纠正；写错对象后再写对对象不能据此记成成功。传输层原样重发、模型纠错、业务动作重试分别记录，效果未知时沿原操作核对；有重试额度也不能授权重复执行未知操作。

纠错轮数、模型调用量、执行操作数及墙钟时间上限应在验收前固定并在整个对比期间保持，耗尽计作未成功；具体上限已由 [评测分册](10-evaluation-contracts-and-release-gates.md) 固定，不能在看到结果后放宽。按单步及多步任务、能力族和每项 API 分别报告，统计方法与样本规模见已确认评测分册。

## API 与设备的模拟验证

以有状态的 API 模拟系统作为主要执行验证环境，覆盖查询、变更、异步完成、幂等、能力缺失和外部效果核对。提供可控的限流、拒绝、断连和执行后回执丢失，不能只返回预设成功结果。

另设 API 与 GUI 共用业务状态的模拟对象，验证 API 可用时优先使用 API、没有适用 API 时使用 GUI，以及 API 已生效但回执丢失时不会通过 GUI 重复变更。同一对象的两种入口用于验证路径协同，本身不等于两种独立驱动实现的替换证据。

参考设备采用可配置、有状态的 GUI 模拟环境。保存页面、控件、焦点、文本、滚动位置、导航关系和业务状态；点击、滑动、输入和返回确实改变相关状态。支持布局变化、弹窗、异步更新和用户插入操作，使固定步骤不足以保证成功。

至少覆盖两种观察配置：结构化界面观察，以及由同一界面状态生成的图像观察。驱动按声明提供控件定位或坐标定位；仅能取得图像时，必须通过声明支持的感知能力理解图像，不能读取测试专用的控件答案。

测试判定器可读取模拟环境的内部业务状态，核对最终效果及重复动作次数；大脑只能取得正式接口允许的观察。这一区分防止使用隐藏状态直接完成任务。脚本大脑可验证执行契约，模型对图像或任务的理解质量另行评测。

模拟环境只实现验证所需的界面与动作语义，不要求完整模拟 Android、iOS 或硬件。验收报告明确模拟精度及未覆盖的真实平台行为。

## 共享设备与用户接管

默认对同一设备的 GUI 变更串行执行，不同设备可并行。更细粒度的并行仅在驱动声明可独立控制的资源范围并通过验证后启用。只读观察能否并发及观察一致性由驱动声明。

API 并发按业务资源、版本前提和接口能力控制，不因运行在同一设备就全部串行。API 与 GUI 会修改同一资源时需核对冲突；用户接管所涉及的资源应阻止 Harness 经其他执行路径继续干扰。无法识别资源对应关系时，对相关应用采用保守暂停范围。对外部系统中不受 Harness 控制的变更只能观察和核对，不能承诺统一锁定。

用户接管作用于相应设备控制范围：执行端阻止该范围内所有自动化来源启动新动作，并处置已开始动作。仅取消某一次点击不足以保证用户随后操作时不被其他任务打断。设备控制与任务拥有者是不同责任，不因用户接管而转移任务状态推进权。

恢复自动化须有明确获准的恢复意图，并重新观察、核对旧操作及重新决策。用户改变后的页面不得沿用旧坐标直接续跑。动作前提已经失效时明确拒绝或要求重新观察；真实 Adapter 无法原子校验界面与点击时必须声明此限制，不能仅凭截图版本承诺消除竞态。

资源控制状态、在途动作停止条件和恢复入口见执行接口分册。沿用已有标识和局部版本，只有明确生命周期需要才增加新的身份。

## 按能力组织验证

| 验证层面 | 验证内容 | 证据边界 |
| --- | --- | --- |
| 执行契约 | 工具与设备 Adapter 共同验证准入、Schema、重复调用、错误、取消、核对与能力不支持。 | 不用相同模拟实现的两个实例宣称已验证驱动替换。 |
| API 主路径 | 查询、变更、异步结果、资源并发、幂等与未知效果；适用 API 优先。 | 执行状态与实际业务结果分别核对。 |
| 千级 API 准确调用 | 同时存在超过 1000 项 API 的目录；候选覆盖、首次正确、有界任务成功、正确不执行及每项覆盖。 | 注册数量、Schema 校验、模拟接口通过和真实模型效果分别报告。 |
| GUI 兜底 | 无可对接 API、API 明确能力不足、切换资格检查及共享业务状态。 | 不把权限拒绝或未知效果当作直接改走 GUI 的理由。 |
| 设备闭环 | 多设备独立状态；点击、滑动、输入、返回；结构化及图像观察配置；动作后效果核对。 | 使用可核对状态，固定成功回包不作为闭环证据。 |
| 共享控制 | 同设备任务竞争、用户接管、迟到动作、恢复前重新观察。 | 已发生的动作保留；停止能力按实际证据报告。 |
| 跨节点恢复 | 单机多进程运行真实 gRPC 和 WebSocket；断连、重复、回执丢失、重启、旧 Worker 及未知效果。 | 不用进程内假连接代替协议故障证据。 |
| UI 交互 | 多模拟 UI 端、不同 Renderer、聊天、表单、通知、自定义组件及快照恢复。 | 与手机 GUI 自动化分别记录。 |
| 联网问答 | 搜索和内容获取 Adapter 返回实际来源、获取时间与失败信息；可重复的本地来源用于契约验证，真实联网与答案质量另验。 | 本地来源通过不代表 V1 已通过；第三方搜索服务不是单机启动必需依赖。 |
| 替换能力 | API 工具及设备能力各选择代表性契约，由独立 Adapter 实现复用验证；最小实现组合见执行接口分册。 | 调用位置变化、能力配置变化、驱动替换分别记录，不能用 API 与 GUI 输入不同宣称同一契约替换。 |

手机与电脑协作保留为组合用例。里程碑仍按 C1–C9、A1–A4 与 V1–V2 记录，不绑定某个示范业务。
