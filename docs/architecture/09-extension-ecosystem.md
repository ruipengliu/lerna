# 插件、Skill 与 Agent 扩展生态

状态：扩展登记、Skill 加载、管理/运行接口、版本锁定、激活恢复及运行器/SDK 基线已确认；未实现扩展管理或完成运行验证。

目标约束见 [项目目标基线](../harness-project-goals.md)，决策过程见 [确定插件、Skill 与外部 Agent 的接入生命周期](../../.scratch/harness-technical-design/issues/12-extension-lifecycle.md)。领域用语沿用 [领域词汇](../../CONTEXT.md)，不将代码实现、操作知识与自主运行主体混为同一对象。

## 已确认的前提

- 插件提供实现，Skill 提供可复用知识与流程，Agent 拥有目标、上下文与决策循环。内部 Agent 生命周期由 Harness 管理，外部 Agent 保持其独立运行时。
- Brain、Model、Memory、Execution、身份授权和传输通过各自 Interface 替换，不为扩展绕开内核或创建新的业务协议领域。
- 进程内扩展仅用于受信代码。需要不同信任级别时须声明并验证实际隔离能力；独立进程本身不等于强隔离。
- 用户自定义 Skill、端侧 Renderer、UI 类型与事件、MCP/A2A Adapter 均属于接入范围。接收类型声明不自动触发安装或执行代码。
- 每次决策固定大脑、模型配置、Skill 与上下文组装版本；已准入操作固定能力与实现版本。升级不得抹去在途任务、旧操作、授权消费或未知效果。
- API 为主要执行路径，能力目录超过 1000 项时仍需准确选择；别名与重复版本不能充作不同 API。声明质量、兼容性和实际效果均须验证。
- 个性化及端侧数据约束跨扩展继续成立。凭证仅经受信执行路径使用，扩展声明或 Skill 文本不能扩大授权。
- 记忆更新、Skill/策略/Agent 配置及插件/内核代码沿既有默认生效规则；自进化不得自行增权或降低门槛。

## 统一登记信息，按对象提供不同入口

提供统一的扩展登记与版本管理，但保留三类不同接入入口：插件安装实现、Skill 导入内容包、外部 Agent 注册受信端点。外部 Agent 注册不意味着 Harness 安装或托管了它的运行时，Agent Card 中的技能描述不自动导入为本项目的 Skill。

本地目录和离线包作为参考导入来源，远程仓库或制品服务经可替换来源 Adapter 接入；开发期不要求在线市场、独立仓库服务或容器集群。导入时记录精确来源和内容摘要，不在任务执行途中重新下载可变的“最新版本”。

使用版本化 Harness 扩展清单，描述发布者及命名空间、扩展类型、版本和摘要、入口、依赖、提供/需要的接口与 Schema、处理位置、权限请求、运行条件和状态恢复兼容范围。清单是 Harness 自身的管理约定，不伪称 MCP、A2A 或 Agent Skills 已提供完整包管理协议。

同名不同来源或同版本不同内容显式冲突，不静默覆盖。版本号用于兼容选择，内容摘要用于固定实际资产；签名或来源可信度不替代权限授予与行为验证。可见能力及调用资格在激活后按权限发布，导入文件本身不让能力立即可调度。

## Skill 先发现，再按需加载

用户 Skill 保持开放内容包结构，Harness 的依赖、版本、作用域和运行策略作为伴随登记信息；普通内容包无需先改写成插件工程才能导入。格式基线已固定到 [SDK 与 Skill 快照研究](../research/harness-extension-sdk-and-skill-snapshots.md) 中的不可变源修订；每个内容包另锁完整文件摘要，实际兼容须经测试。

先加载名称、用途及适用条件，用于发现候选 Skill；任务选中后才在预算内读取正文和相关资料，固定此次使用的内容版本。目录摘要、Skill 正文及其附属内容均按获准位置和披露规则处理，不因用于检索而上传端侧私有知识。

Skill 中的工具建议只收缩可用能力，不能授予权限。脚本作为显式可执行资产登记，走受控执行入口和运行器，不因读取 SKILL.md 或参考资料就自动运行；脚本的网络、文件、进程与凭证使用遵守运行器声明及授权。

用户本地修改形成新的候选内容版本，先验证再激活；运行中的决策继续使用已固定版本。内容变化导致需要更多权限时不得自动继承较窄旧授权。自进化若生成或修改随包可执行代码，沿用适用的代码发布权限，不能通过将代码放进 Skill 包绕过该规则。

## 按实际能力选择运行方式

受信 Go 扩展默认采用编译组装方式集成，适用于内核内部及高频调用的替换接口。独立进程实现经既有 gRPC 契约接入；跨端实现通过 WebSocket 绑定参与，不要求扩展作者同时理解所有内部存储实现。

为需要受限执行的脚本或插件提供可替换运行器，声明语言、系统资源、文件/网络访问、取消、资源配额和恢复支持。参考采用 wazero 的受限 Wasm 范围，具体宿主访问及资源限制见 [运行器与激活恢复](09-extension-contracts-and-activation.md)；运行环境不能落实必需限制时拒绝加载，不能自动回退到宿主直接执行。

不同接口不强求采用同一种运行方式。外部 Agent 通过任务协作 Adapter 接入，MCP 工具通过能力 Adapter 接入；模型、存储或设备驱动依其接口提供实现。内核仍管理准入及 Harness 任务，外部结果只按声明能提供的查询、取消和核对能力解释。

默认不允许接入包任意运行安装钩子或自行下载并执行其他代码。安装依赖在受控准备阶段解析、固定并验证；包内脚本和运行入口与普通资料分开声明。实际安装/执行遵循已有权限，不能把“包已经被用户选中”解释成全部运行权限。

## 安装、激活与在途工作分开管理

生命周期至少区分导入、验证、激活、停止接纳新工作、停用及隔离。不同状态是管理记录，不额外生成业务任务身份；导入或验证成功不代表已经激活，激活请求受理不代表所有目标节点已经完成切换。

验证包括清单及资产完整性、版本/依赖与 Schema 兼容、必需运行能力和位置策略，以及适用的一致性测试。必需依赖缺失或存在无法解决的循环时不激活；可选能力缺失显式反映在能力目录和协商结果中。安装依赖不自动批准新的权限。

新版本通过验证并获准激活后只接纳新工作；已固定旧版本的在途任务继续使用可用旧实现。需要迁移持久状态或检查点时，必须有明确迁移规则和验证；不能只换入口就宣称无缝升级。旧实现无法安全继续时暂停相关工作并保留核对事实。

正常停用先停止新工作，等待在途调用和必要收尾完成；风险隔离可立即禁止新执行并请求停止，但仍保留原调用身份、实际效果及后续核对路径。无法停止的外部工作继续如实报告，不因插件已卸载而视为取消完成。

回滚改变后续选择的版本，不回滚业务事实、授权状态或外部系统。旧资产只在无运行、恢复和允许保留引用后清理；曾被撤销信任的版本不能仅因“回滚”而重新启用。端云分别记录实际激活版本，离线端不被假定已同步升级。

| 验证方面 | 需要证明的行为 |
| --- | --- |
| 接口替换 | 不同实现通过对应共同契约；Go 进程内、独立进程和外部协议的差异分别记录。 |
| 内容与脚本 | 导入普通 Skill 可发现和加载；读取不自动执行脚本，脚本不能越过权限或运行器限制。 |
| 千级 API 声明 | 不靠别名复制充数；用途、参数及结果语义足够用于选择，并纳入已确认 90% / 95% 效果评测。 |
| 依赖与版本 | 固定实际内容、拒绝冲突，必需能力或依赖缺失不静默降级。 |
| 激活与恢复 | 升级、停用、隔离、重启和回滚不丢失在途操作，也不重复未知效果。 |
| 端云与隐私 | 安装位置、运行位置和数据范围分别检查；远端未确认不能显示升级已落实。 |
| 外部生态 | MCP/A2A 与 Skill 内容兼容按固定规范及可选能力分别测试；不能将标准目标版本当作 SDK 已支持。 |
| UI 扩展 | Renderer、组件和事件经登记及兼容检查后使用，未知必需类型拒绝，不能按收到的类型动态执行未获准代码。 |
