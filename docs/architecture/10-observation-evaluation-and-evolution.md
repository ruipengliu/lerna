# 运行观测、能力评测与受控自进化

状态：观测/评测/发布职责、接口恢复、千级基准、预算、统计比较、分阶段启用及资料保留规则已确认。没有实现或评测结果。

目标依据：[项目目标基线](../harness-project-goals.md)。决策过程：[确定观测评测与自进化的发布闭环](../../.scratch/harness-technical-design/issues/13-observation-evolution.md)。沿用 [领域词汇](../../CONTEXT.md)，特别是运行观测、能力评测、自进化、操作和扩展激活的区别。

## 已确认的输入

- C8 提供运行诊断、质量/耗时/成本评测和可复用证据；C9 使用证据提出与发布改进，不取得任务状态或授权的任意修改权。
- 完整目录包含超过 1000 个独立业务 API。首次调用正确率至少 90%，有限重试任务成功率至少 95%；两项分别达标。检索遗漏及首次提案错误计错，写错后再写对不能抹去错误副作用；正确澄清、等待或拒绝单列。
- 契约验证、有状态模拟执行与真实模型效果分别记录。联网问答和手机 GUI 保留独立专项验收，模拟系统通过不等于真实设备或第三方系统接入通过。
- 记忆在授权范围内可自动更新；Skill、执行策略和 Agent 配置通过评测后逐步启用；插件/内核及随包可执行代码须经维护者确认发布。此处的执行策略不包括可由候选自行放宽的强制授权或评测规则。
- 端侧隐私的驻留、处理、发现、披露及删除要求适用于 Trace、评测样本和改进产物；不要求记录模型内部思维链。
- 扩展版本、Schema、配置和运行器固定；准备、验证、激活分离，端云逐节点报告应用，旧工作与未知副作用按原版本恢复。

## 业务事实持久化，诊断按需收集

各业务模块继续维护自己的权威事实，包括任务状态、动作接纳/效果、授权消费、记忆修订和扩展激活。必须用于恢复、去重或证明获准执行的记录随对应本地原子提交保存；观测模块不提供修改这些事实的替代入口。

诊断层从持久变更及受控运行信号组织查询视图、指标和 Trace。关键变更的导出通过原模块的持久工作/Outbox 恢复，重复交付不重复统计；临时跨度和性能细节可采样，并明确报告采样、丢失或保留范围。诊断导出故障不会把业务成功改为失败；权威持久化失败时则依原模块规则阻止无法安全记录的新变更。

统一关联已有 task_ref、operation_id、来源节点、主体作用域、版本和因果信息。单条事件的来源位置可用模块作用域内的变更位置及项次标识，不新增全系统通用业务 ID，不以墙钟时间或 Trace 顺序判断业务先后。跨端时间只用于诊断，实际推进仍依版本、所有权和操作记录。

开发期本地持久诊断视图、查询及报告即可完整使用，无须部署独立观测集群。对外遥测格式和存储后端通过 Adapter 替换；具体标准绑定在选用时核验，不由外部采样策略决定内部恢复所需的事实。

记录默认包含状态、错误类别、版本、耗时、用量、采样/缺失标记及必要引用；参数、正文、截图和模型输入输出为单独受控内容。不得把原始凭证、密钥或完整敏感授权材料写入日志，也不以“调试模式”绕过位置和保留限制。

## 共用评测机制，分别出具能力证据

评测运行绑定不可变计划：测试集、分类及预期结果、目录、模型/Brain/Skill、配置、运行器、环境初始状态、故障脚本、评分器、预算和基线版本。运行结果保存各样本实际输入引用、尝试过程、效果证据、用量及最终判定；后续更换评分器形成新判读版本，不能覆盖原始结果。

| 证据类型 | 回答的问题 | 判定依据 |
| --- | --- | --- |
| 接口与协议一致性 | 实现是否遵守共同契约？ | 共同测试夹具、状态和错误断言、独立实现及真实传输边界的行为。 |
| 执行与恢复 | 动作是否产生正确效果，故障后是否避免重复或丢失？ | 有状态模拟环境的独立业务状态、动作历史及故障注入结果。 |
| 模型任务效果 | 在完整可见目录和有限预算下能否正确选择、规划与完成？ | 真实模型通过正式接口运行，判定器依据预先核验的目标和效果；脚本大脑不得替代此项。 |
| 专项能力与代价 | 联网问答、GUI、个性化等整体验收，以及耗时和成本是否成立？ | 专项数据及效果判定，实际外网获取与固定资料重放分别报告，耗时/用量依明确测量条件记录。 |

评测复用生产任务、授权和执行契约，但运行在隔离的测试命名空间、模拟资源及明确获准的外部测试入口。判定器可读取测试真值；被测 Agent 只能通过其正式获准接口取得观察，不能读取评分答案、内部模拟状态或隐藏测试资料。

机器可判定的参数、资源、动作和状态条件由独立判定器检查。联网回答的证据支持、开放式效果等使用版本化评分标准和独立复核；模型评分可作辅助，不能让被测模型自行宣布成功。来源无法访问、证据不足或评测器故障须明确表达，不能改成通过。

模型调用和外部网络存在不能由输入快照消除的变化；保留服务、模型配置、运行时间及可取得的版本信息，区分固定资料重放、模拟重跑与真实外部再执行。历史记录重放默认只重算投影或评分，不重新发起真实变更。

## 以覆盖完整、预先固定的测试集验收千级 API

首期参考基准采用逐 API 均衡覆盖，另设近义能力辨别、参数依赖、多步任务及边界/故障组。每次被测检索面对完整目录，不按答案预筛目录。单步可执行样本评估首次正确和有限纠错后成功，多步样本另报告路径与完整任务成功，正确不执行和故障恢复分别出表。

90% / 95% 继续作为既定目标。详细计划必须明确主验收样本、聚合权重、逐 API/能力族分组，以及单步、多步各自适用的判定；不得只展示综合平均掩盖漏测能力或薄弱分组。统计区间不把同源改写、同一任务重跑或共享业务状态当作无关样本；固定基准按点估计验收，统计区间表达适用的不确定性；自动质量优化另需配对改善证据，具体规则见 [参考基准与发布判定](10-evaluation-contracts-and-release-gates.md)。

执行前固定模型调用/用量、纠错轮数、业务操作、传输重发、墙钟时间及运行器额度。预算用尽属于该计划下的未成功；传输恢复不能藏入模型纠错，模型纠错也不能删除首次错误。延长预算或改测试集只能产生新的计划与完整对照运行，不能用于修改原报告。

测试体系可以记录测试设施失效，但须保留原始尝试及失效依据；受影响计划应标为证据不完整，并按预先规定方式重跑。被测实现报错、超时或不兼容不能伪装成设施问题移出分母。质量、约束违规、耗时和用量分别统计，不能用速度或低成本抵消质量不达标。

首版配置已确定每 API 20 个单步样本，多步至少 max(2000, K) 例，单步/多步预算及正式尝试规则见 [详细基准](10-evaluation-contracts-and-release-gates.md)。统计依据见 [评测统计研究](../research/harness-evaluation-statistics-and-comparison.md)；这些工程配置不保证区间精度或模型达标。

## 候选生成与发布判定分开

改进候选记录目标问题、来源证据、产物类型与精确版本、预期改善、影响范围、所需权限及可用回滚版本。生成候选的 Agent 不控制评分器、发布门槛、保留测试答案或自己的授权；已有工具执行授权不自动包含修改这些管理对象的权限。

按开发集、验证集与发布用保留测试集区分用途。可用于生成或纠错的内容不能同时作为未见测试证据。保留集由评测侧管理，候选生成侧默认只收到获准的汇总结论；反复使用同一测试集及比较多个候选仍须记录，不能通过隐藏答案便声称完全免于污染。失去保留意义时按计划更新并重建可比较基线。

候选与现行基线使用相同计划、预算、目录和独立重置的初始状态比较；允许变化的对象明确列出。个性化上下文与外部数据版本能固定时固定，不能固定时标明比较局限。契约/授权/数据限制等必需检查未通过时不得以平均分改善抵消；整体达标也不能独自证明这次改动带来了改善。

离线通过后，在已获准的范围内逐步启用。影子评测仅生成提案或运行在隔离模拟环境，不对真实系统重复执行写操作。实际试运行按任务或明确的一组关联工作固定版本，避免同一任务在候选与基线之间跳转；试运行名额、观测窗口、退出规则预先固定。

发布控制复用 ExtensionManager 的验证/激活/停用能力以及对应业务模块入口，记录发布意图与各节点实际应用。发现违规或达到预设退化条件时停止扩大范围，并按当前信任、授权与兼容性停用或回滚。旧在途工作继续核对，不能用回滚代码或数据库抹去动作事实。

没有足够可比较样本、关键观测缺失或对照条件改变时，状态保持待评估或停止扩大，不自动视为稳定。初期没有真实生产流量，也须在多模拟节点中验证分阶段应用、故障退出及回滚机制，并明确缺少实际生产效果证据。

## 观测与学习继承端云隐私限制

运行内容、派生样本、特征、评分理由和候选产物分别保留来源与允许的驻留/处理/披露范围。受限端侧数据可在端侧评测，只返回明确允许的汇总或证据引用；数量、类别和命中状态也可能受限，不将统计值默认当作匿名信息。

来源纠正、删除或用途收紧时，关联评测样本与派生内容停止使用并按规则删除/失效；已获准保留的最小运行事实与敏感正文分开。报告应标记证据已删除或不可再复核，必要时撤销其用于新发布的资格。已经发生的动作或历史发布事实保持真实，不能因样本删除被改写。

候选产物是否需撤回依据内容依赖、当前授权及兼容性判断，不能把所有删除自动等同代码回滚，也不能用“模型已经总结”作为永久保留受限信息的理由。跨端汇总和数据导出仍经既有协议与授权接口，不引入默认云端集中收集。
