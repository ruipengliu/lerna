## 1. 首次成稿的设计基线与独立阅读

方案保留 C1–C9、A1–A4、联网问答 V1、模拟手机 V2，以及 API 数量、调用质量和最终服务规模目标。建设顺序从本地完整闭环开始，再取得替换、端云、改进与容量证据；分阶段交付不等于降低最终目标。

独立读者未取得设计讨论历史，仅依据本目录、目标要求和仓库文档规范复述主线并推演异常。复述得到的关键分工如下：

- Task Home 保存目标、控制、预算和完成决定；大脑提供绑定输入快照的提案，执行端保存实际启动与效果事实。
- 同宿主以短事务共同保存决定与后续工作；远端通过原命令回执、查询和持久交接恢复。网络响应、模型结论及界面提示均不能单独证明外部效果。
- 每任务固定 Home，共享资源由其 owner 裁决。失联时不自动接管同一任务；离线使用远端权限与额度必须预先划定窗口和范围。
- 开放任务可以采用质量评估或用户验收，但必要外部效果必须核清。取消终止新的目标工作，既有操作的效果与费用仍须收尾。

正常链路覆盖目标接纳、获准取证、报告生成、版本化保存、模拟手机操作及完成发布。异常链路重点推演写入答复丢失、取消后效果迟到、目标修订、用户验收竞争、远端控制乱序和批准撤回；逐项检查发起者、裁决者、持久事实、成功边界与恢复责任。

[生产部署专题](deployment-production.md)集中定义单地域三可用区拓扑、稳定 Home 路由、权威与派生数据放置、同步耐久提交、恢复顺序及配额归属。默认保留共同事务、按资源隔离工作池；增加 Home 只承接新任务。同库事务降低交接成本，单对象写入仍受热键限制；同步复制承担跨区延迟，条件不足时停止业务写入。跨分区配额先采用保守份额，承担额度闲置和人工调整成本；需要动态共享时再引入具备预留及结算协议的权威服务。

## 15. 生产分布式主线与中间件收敛

按已确认边界，将总览、目标、部署、模块实现和首阶段验收统一为生产分布式：单地域三个可用区，WSS 网关、Home 应用和工作池分别部署；开发单体复用相同契约。单区故障下已确认账本 RPO=0、控制／查询 RTO≤60 秒为待验收目标，整地域采用受限异地灾备。固定 Home、领域 owner 和原命令身份保持，进程拆分不要求分离原有提交域，物理分区搬迁也不改变任务负责端。

[生产部署](deployment-production.md)补齐连接配额与进程租约、内部绑定代次、跨实例 Delivery／Reply 交接、提示发布水位、实例重启、分角色滚动发布及格式迁移。[存储与中间件](storage-and-middleware.md)集中定义 PostgreSQL 与对象存储的数据放置、共享字节恢复、连接池、热表及关闭索引维护，并比较引入独立缓存、消息和检索设施的条件。可丢通知在业务提交后独立发送，原责任始终由有界索引扫描恢复。

语义复核沿提交后断线、旧实例迟到、通知完全丢失、内容关闭与发布竞争、设备宿主恢复、数据库提升和迁移失败推演。修正了三类实际缺口：旧内部建链可能晚于新绑定提交，因此增加单调绑定代次并保留最高代次；旧进程租约不能恢复为原实例，重启必须取得新身份；普通跨库内容持有者缺少可调用的控制状态合同，因此扩展现有 content.get 的 control 分支，复用原 Query／gRPC，方法总数保持 101。该查询只向当前已认证的原持有者返回有限控制元数据，不提供正文或保存许可；本地门禁分别按内容控制与 copy 修订单调合并，来源仍 active 的已停止副本也不能重开。查询不可达时阻止新使用，停止使用和物理清理分别回报。代理网关身份与原业务发送者分别核验，转交不覆盖实际 holder。

容量按十万在线用户展开为二十万 WSS 的初始假设，另测 1／2／4 倍连接倍率。预算分别包含请求 ID 驻留、内部委托轮换与订阅快照、实际任务驻留、全部数据库提交、跨库副本核验、永久关闭索引，以及持续到达下的积压排空。连接数、语言或中间件选型均不作为吞吐达标证据。相关运行场景扩充为 PROD-01～16，并与[故障步骤](validation/fault-experiments.md)互相查阅。
