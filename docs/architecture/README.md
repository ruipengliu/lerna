# Harness 整体设计与阅读入口

Harness 以任务核心保存的目标、操作和持久工作连接大脑、记忆与执行系统。大脑提出下一步，核心决定是否准入，执行端提供实际效果；授权、消息交付、交互与运行保障在各自交接位置落实共同约束。设计依据为[项目目标](../harness-project-goals.md)与[系统全景图](diagrams/system-panorama.drawio)（[导出图](diagrams/system-panorama.drawio.svg)）。图表示逻辑职责，不限定进程或端云位置。

## 1. 当前设计基线

设计覆盖固定本地、固定云端两种用户任务权威部署，以及三系统的独立跨端部署。受信宿主装配核心、单轮大脑、记忆、执行、授权、UI 及持久交付；内部 Agent 子任务共用唯一任务写权威。远程大脑承担原单轮调用，远程协作端点保存交接责任，不增加第二套任务裁决。调用云模型与独立远程 Brain 分别验证。

跨端领域合同统一采用网关 WSS，HTTPS 承担认证、连接票据、恢复资格引导及大内容。先通过受限资格恢复身份，再按领域证据开放行为，完整路径见[跨端领域合同](endpoint-cloud-protocol/domain-profiles.md)。本地参考闭环、云核心配端侧领域、端侧核心配云领域构成最小验证集合；运行中权威迁移仍后置。

| 关键选择 | 依据与主要代价 | 当前边界 |
| --- | --- | --- |
| 任务与内核操作由固定写权威裁决 | 在一个提交域内约束操作身份、预算和任务推进；权威不可达时相关新决定等待 | 不自动迁移、超时接管或建立第二写者 |
| 大脑单轮提案，核心准入，执行端核对效果 | 每次行动都可复核当前条件；多步骤任务需要多轮事实交接 | 模型输出、消息 ACK 和业务接纳均不代表任务完成 |
| 领域账本分别提交，交接保存后续责任 | 模块可独立替换，无须跨库全局事务；代价是原身份、回执和核对工作 | 未知提交查原记录，不能换操作重做未知效果 |
| 来源与用途逐次核对 | 上下文、保存、披露与长期记忆分别获准；需要保留完整来源关系 | 本模块逻辑禁用不等于外部副本全部擦除 |
| 条件能力按依赖分别开放 | 一个领域缺口不阻塞无关行为；需要逐行为表达就绪条件 | WSS 已连接、进程健康或接口已有设计都不能代替领域依据 |
| 动作边界暂停，显式恢复 | 保留在途效果、有效输入与核对责任；正常完成等待恢复，原期限继续计时 | 失联或不支持暂停的外部 Agent 单列未确认；加额不解除暂停 |
| 受管副本清理与批准后自动发布 | 来源关闭逐持有者确认，精确批准逐节点应用，原命令和残留可查询 | 物理清理、停止使用、停用与旧版恢复分别判断；扩批仍需批准 |

当前文档给出模块设计与验证方法，协议提供静态 Schema／示例。2026-09-24 已确认并联动采用所需跨端、控制、治理及自动化设计；尚无系统运行验收结果。[决策落实与剩余依赖](open-decisions.md)记录采用范围、后置增强和实现取证责任；启用前如何验证见[系统验证设计](validation.md)。

## 3. 模块与权威文档

所有模块的运行实现、替换与故障证据均待验。下表单独标明设计合同的范围，避免把“接口已有设计”和“能力已可用”混为一项状态。

| 方案 | 权威职责与主要内容 | 已有设计及条件边界 |
| --- | --- | --- |
| [任务内核](task-kernel/README.md) | 生命周期、上下文、提案准入、预算、持久工作与完成核验 | 暂停／恢复、预算调整、补证和原控制答复；目标编辑仍建新任务 |
| [大脑系统](brain-system/README.md) | 单轮策略、模型适配、证据综合与调用恢复 | 同进程及独立远程 Brain；原调用资格、结果和账务分别恢复 |
| [能力与执行](capability-and-execution/README.md) | 准确目录、执行事实、资源门禁、API／GUI 与未知效果 | 跨端准确声明、事实修订、可信累计用量和受信处置；未知不重做 |
| [身份与授权](identity-and-authorization/README.md) | 主体、端点、许可、单次消费、撤销与授权恢复 | 受限引导、跨端许可／来源依据及受信确认；离线仍须平台证明 |
| [记忆系统](memory-system/README.md) | 受控查询与修改、来源、索引、失效清理与获准视图 | 远程访问、受管副本治理和成功终态的 opt-in 提取；保持单一写权威 |
| [应用与交互](application-and-interaction/README.md) | 呈现快照、本端开闭、输入转交与受信管理 | 获准目录／订阅、中间预览和领域管理；输入不能绕过授权 |
| [端云协议框架](endpoint-cloud-protocol/README.md) | WSS／JSON、公共信封、领域消息与可靠交接 | 未发布 v1 的领域 Schema／示例；结构、运行和互操作分层验证 |
| [协作与端云](coordination-and-cloud/README.md) | 委派关联、消息账本、连接路由与领域恢复 | 单权威跨端内部委派、外部原生任务及普通输入交接；迁移后置 |
| [扩展与运行保障](extensions-and-runtime/README.md) | 启动、恢复协调、版本锁定、排空、隔离与受控回退 | 精确批准自动交接和逐节点管理；有状态在线迁移后置 |
| [观测、评测与改进](observation-and-improvement/README.md) | 诊断、隔离评测、独立判定、候选及分批启用 | 批准后自动执行、撤回及受管评测数据；候选生成保持显式 |

[内容与来源交接](content-and-provenance.md)集中解释已有内容提供方、来源权威及消费方之间的共同约束，不增加全景图模块。各模块仍保存并裁决自己的业务事实。

## 4. 文档状态与维护

根目录保留整体阅读入口、贯穿实例、跨模块规则、系统验证与决策／依赖索引；各模块子目录维护所属设计，`diagrams/` 保存图示，`maintenance/` 保存历史审查记录。协议的 Schema、示例与校验器集中在 `endpoint-cloud-protocol/`。
