# 专项验收、持久化替换与实施交接

状态：专项验收、bbolt 参考后端、停写双向迁移及实施交接已确认。阶段和发布边界见 [能力里程碑](11-milestones-and-validation.md)。本文的样本与预算为已确认的首版工程配置，没有运行、故障注入或效果达标证据。

## 三个独立专项 profile

全部使用真实被测模型、正式接口、预先核验的真值和固定预算；确定性驱动/协议夹具另报。每例一次正式尝试，错误副作用不能被后续正确结果抵消；缺失证据、设施事故、候选泄漏和保留集用途沿 [评测契约](10-evaluation-contracts-and-release-gates.md)。以下点分门槛分别适用，不能相互平均抵消。

| 专项 | 首版样本构成 | 通过条件 |
| --- | --- | --- |
| V1 联网问答 | 固定证据 400 例、实际联网 120 例；每组均等覆盖可回答、证据不足、来源冲突、获取失败四类。 | 两组及各类别的完整回答判定均至少 90%；需引用的关键事实，其引用支持与覆盖分别至少 95%。不得伪造已经取得的来源或绕过数据权限。 |
| V2 手机 GUI | 400 个任务，结构树观察与图像观察各 200；每种观察模式包含 150 个可执行任务及 50 个边界/中断任务。 | 两种模式的可执行任务成功率分别至少 95%；边界任务的正确拒绝/等待/接管分别至少 95%。所有必需协议/控制断言通过，禁止动作、错误副作用和重复写入阻止通过。 |
| C2 个性化 | 400 对任务；200 对适用个性化（回答/行动各 100），200 对不适用、过期/删除、冲突或禁止披露条件（各 50）。 | 适用组的回答和行动分别至少 95% 满足预定个性化效果；边界组各类正确处置至少 95%。隐私出口、删除与用途控制的必需断言全部通过。 |

这些数量保证的是规定覆盖，不保证统计区间宽度或对任意真实用户的泛化。专项报告保留逐类分母、来源族及相关结构；适用区间按预先确定的采样机制生成，无法合理推断时明确标记，不套用独立二项假设。发布候选涉及这些能力时，同时通过相应专项回归，不能仅满足 API 自动质量优化 profile。

### V1：回答、证据和实际联网

完整回答判定包括预定关键事实的正确性、必要范围和时间信息、对冲突/不足/失败的正确表达。关键事实集合由独立判定者依据题目及实际证据确定，不能只统计模型主动写出的少量容易陈述。

引用支持率以回答中需证据支撑的关键事实为分母，检查关联材料是否实际支持；引用覆盖率以预期答案中必须提供依据的关键事实为分母，检查回答是否给出可追溯支持。未提及必要事实不能用于提高覆盖率。无适用事实的样本标明不适用，不填成 100%；可回答类必须有足够适用样本满足计划。在固定组和实际联网组内，各类别对适用样本按例等权汇总，两项引用指标分别达到 95%；同时报告逐例分子分母，不把无适用样本的类别冒充已通过。不能只凭链接可打开判定支持。

固定组使用版本化证据快照验证可复核的问答行为；实际联网组必须通过真实网络取得材料、保留允许保存的响应证据和获取时间。获取失败可以对实际网络请求按计划注入拒绝/超时，必须在报告标明注入机制，不能用全量离线桩替代联网。外部来源变化时按采集时间判读，证据不能取得则依预定类别和设施规则计分，不事后改变题目类型。

开放式回答使用预先登记的事实/支持/限制核对表，独立复核者完成判定；争议样本记录分歧并裁决，未裁决不宣布完整通过。辅助评分模型不读取发布管理权限，被测 Agent 不访问答案或裁判内部状态。

### V2：真实模型、模拟设备与动作闭环

每种观察模式的 150 个可执行任务分别覆盖点击、滑动、输入、返回，每项动作至少出现于 30 个任务；输入包含追加与替换各至少 15 个任务。任务允许多种动作重叠，预期正确路径为 2–8 个动作，并包含业务效果核验。各模式至少 30 个任务具有明确的无 API 或 API 能力不足前提，验证 GUI 兜底资格。

每种模式的 50 个边界任务至少各 10 个覆盖陈旧观察、权限拒绝、API 未知效果、用户接管以及断连/重连。应等待或交还控制时即使未完成原业务目标也可在该边界组判为正确，但不能加入可执行任务成功率分母。

真值来自模拟设备独立业务状态、动作历史和控制状态，模型仅获得该观察模式允许的内容。图像模式不得向模型偷偷提供结构树、隐藏坐标答案或模拟后端状态；结构树与图像共用可比较业务任务族，统计时保留成组关系。多个模拟设备与多个 UI surface 分别验证，不要求真实手机。

### 个性化：成对验证影响与克制

一对任务包括相同目标/环境下的获准个性化上下文版本和预定对照版本。对照可以无该偏好、具有另一有效偏好或将其标为过期/删除；每一臂独立重置业务状态和可变记忆，分别判断其允许的正确结果。一对只计一个成对结果，不能把两臂当作两份无关样本。

适用组须同时证明实际输出/动作符合相应上下文，并且差异来自预定适用信息；任务应设计为个性化会改变可观察选择，不能只检查系统是否调用过 Memory。边界组检查保持默认行为、澄清冲突或拒绝披露，不能为了显示“有个性化”而强行使用信息。

每类至少一半任务使用端侧来源；至少 40 对验证严格留端信息被检索和用于端侧处理，至少 40 对验证仅获准派生结果回传，两者分别记录。检查云侧存储、模型请求、日志/评测出口和派生资产，不能仅验证原始数据库没有复制。场景无可用获准处理位置时应等待/拒绝，不能自行改用云模型。

## bbolt 作为第二持久化验证实现

采用 `go.etcd.io/bbolt v1.5.0`，固定上游提交 `e7a8b2dd498494a3766ba24dd94d3509e5588485`，最低 Go 1.25.0；模块建议工具链不是调用项目必须固定的补丁号。官方事实与限制见 [第二持久化后端研究](../research/harness-second-persistent-backend.md)。实际引入仍须锁定 go.mod/go.sum、构建工具链及平台测试记录。开发默认与完整参考部署仍使用 SQLite。

M3 用 bbolt 实现所选完整运行配置需要的持久 Store：运行/工作、执行及资源控制、记忆、授权、扩展和评测发布；观测索引可由事实重建。每个模块自己的原子提交单元放在同一文件事务内，不能将同一次 Commit 拆成跨文件写入。多个模块可共享文件但不得泄露底层 bucket 或扩大访问权限。

一个数据库文件由一个读写进程持有，其他进程通过已有受控 gRPC Adapter 访问；这属于可选验证部署，不把新数据库守护进程作为默认安装依赖。CAS、版本/资格校验、回执、墓碑、水位及 Outbox 均由 Store Adapter 实现，bbolt 事务不替代这些领域规则。

参考使用 Update，保留同步配置，事务闭包内不做外部调用。Adapter 在进入事务前有界排队，取消排队与开始提交分别处理；进入提交后不能用请求超时断言未提交。遇持久化 I/O 错误停止该单元新变更，经受控恢复核对耐久回执，不凭故障实例的缓存报告成功。

跨请求分页使用固定快照产物和对应变更边界；生成受控产物时有界占用读事务，产物过大或无法按预算完成时显式失败，不每页换新视图冒充一致快照。查询索引根据权威记录重建，记录覆盖/修订；未就绪拒绝或按声明有界扫描，不把无索引当作无数据。

首个验证组合限定 Linux amd64、本地文件系统。报告实际内核、文件系统/挂载、同步配置及上游已知问题核对结果；其他组合分别取证。长读、文件增长、数据库/快照/索引容量、队列和磁盘满均需有界配置及错误试验；MaxSize 不是宿主 RSS 上限，不承诺生产容量或任意硬盘损坏恢复。

## 同机停写迁移及恢复验证

首期证明同一受控节点的 SQLite → bbolt 与 bbolt → SQLite 逻辑迁移；不承诺在线双写、多主迁移或自动跨云接管。使用带格式版本、模块范围、内容摘要、恢复引用及水位的逻辑导出包，不能把原始数据库文件直接当作另一后端的格式。

1. 管理入口校验迁移权限并持久记录操作，停止相关新任务/动作准入和产生新写入的后台工作；排空或按契约停止在途 Worker。可能已有外部效果的操作保留原身份及查询信息，不以迁移完成代替效果核对。
2. 确认所有相关模块均到达持久切点，暂停写入和入口交接，记录已接纳未应用的消息/工作。停机期间对可恢复输入依协议拒绝或待补送；不承诺无法重放的第三方通知无损送达。仍无法排除旧写入时不导出/切换。
3. 导出状态、工作、原操作回执、版本/资格、资源屏障、授权消费/撤销、接纳窗口及删除水位，连同获准产物引用。凭证密文与密钥引用单独受控，主密钥不进入通用导出包；不能为迁移重新扩大数据驻留或保存权限。
4. 在未开放服务的目标库导入，重建索引、校验摘要和跨模块引用，并执行只读一致性/恢复计划检查。部分导入、压缩或复制的目标不得启用；备份/产物发布补齐文件同步及适用目录同步，不能把 CopyFile 返回当作耐久完成。
5. 在节点的共同维护屏障下持久更新唯一活动存储配置和启动代次，确认旧进程已停止且无法按旧配置接纳新写入，才启动目标。两个不同后端的文件锁本身不能防止双写；共同屏障和启动入口必须执行单一活动配置。
6. 新入口先核对原操作、未交接工作、权限/时间与外部未知效果，再恢复获准工作。失败若发生在切换前，可清理目标并恢复原库；切换提交不明先查迁移记录。目标已产生新写入后，回退须重新停写并反向迁移，不能直接启用陈旧源库。

迁移记录与切换配置自身也需要崩溃恢复证据。测试覆盖每一步中断、同步错误、引用缺失、仍在运行的旧 Worker、迟到回执与旧备份恢复。原有身份克隆/备份回滚隔离规则继续有效，迁移不能降低恢复水位或重放未知写操作。

## 发布证据与实施任务交接

M1 固定领域接口、Proto/JSON Schema、支持 profile、错误/权限及正常和故障夹具；按已确认概念建立可导入 Go SDK 与生成绑定。库的小版本、生成器具体发行及编译环境在各实现任务开始时锁定，不以尚未生成的源码冒充运行证据；这些常规依赖固定不得改变已确认接口与协议目标。

M2/M3 的开发检查按改动范围执行共同契约和小型真实模型回归，标明未覆盖完整质量基准。M4 放行必须有同一发布候选配置的完整 API 与专项报告、跨端和独立替换、故障/隐私/用户控制及自进化改善与回滚证据；涉及多个兼容组合时逐组合列明适用范围，不能把不同提交各自通过的片段拼成一个已通过版本。

| 交接工作包 | 首个可验证产物 | 必需依赖及最终证据 |
| --- | --- | --- |
| 契约/SDK/测试入口 | 公共领域接口、生成协议、Schema 注册与验证夹具 | 各分册定义和固定编码；进程内/gRPC/WebSocket 同语义，未知必需类型失败。 |
| 单机内核与身份 | 启动配置、SQLite、任务/操作与授权持久提交 | 身份/凭证与调用准入先于真实动作；重启与未知效果核对。 |
| 记忆/大脑/执行 | 各系统参考实现和独立测试数据 | 内核接口、位置/披露约束、真实模型与有状态环境。 |
| 协作/UI/扩展 | 多模拟节点、用户交互、MCP/A2A 和扩展激活 | 既有原生协议和具体外部适配差异；双角色、版本和迟到交互证据。 |
| 替换与迁移 | 独立实现共同套件，第二后端运行及双向迁移 | 稳定契约、维护屏障与逻辑导入导出；耐久性证据不能由内存替身代替。 |
| 评测与自进化 | 数据/判定器、完整基准、候选/保留确认/发布控制 | 版本化运行证据、独立真值和统计方法验证；实际改善及回滚。 |
| 完整开源参考交付 | 配置/SDK 示例、复现步骤、支持矩阵及升级说明 | C1–C9、A1–A4、V1–V2 独立证据，已知限制可见，维护者确认实际代码发布。 |

每份后续实现票以本工作包为入口，说明可观察结果、依赖接口、输入/输出、权限/隐私、失败/恢复、对应测试及产物；不要按内部文件数量拆成无法独立验证的任务。人员、日期和实际模型费用依据实现试跑排定；本方案不以未取得的性能数据承诺工期。

完整报告包含运行版本/模型/目录/数据和评分器、环境/拓扑、命令与配置、预算、成功/失败/不完整结果、证据位置及保留限制。网络/第三方凭证在公开文档中使用引用或占位，秘密不进入报告或版本库；公开敏感样本仍需相应披露权限。

本轮只完成技术方案，实施任务创建、业务代码、依赖安装及实际发布属于后续工作。已确认范围之外的平台、自动接管、更强沙箱及外部可选扩展保留独立验收入口，不作为默认完成的隐含声明。
