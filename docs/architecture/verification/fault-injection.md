本文只做一件事：给 M1 的每个持久化点一个**全局唯一的故障点名字**，写明可以在那里注入什么故障、注入后以什么为判据。各点的语义以链接的权威位置为准，本文不新增规则。测试代码用 `// 故障点：<名字> <时机>` 标注（见开发规范 5）。

## 1 判据的共同原则

- 判据是**持久记录**和**模拟目标实际收到的调用及产生的效果**，不是接口返回值、日志或界面文本；
- 每次注入都检查三件事：已确认的责任仍可查询；没有产生第二个决定、第二个动作或第二次非幂等效果；可能已发出的动作不被记为"未生效"；
- 每个故障点至少注入三种时机：**提交前**崩溃、**提交后、回执前**崩溃、**回执丢失**（调用方收不到回执，进程不崩）。持久档位的验证另加**掉电**（本地档，按[数据与存储 5.4](../topics/data-and-storage.md#54-持久档位)的存储故障模型）；
- 故障点名字写成"文档或流程名/编号"（[文档规范 5](../conventions.md#5-写作与链接规则)），不同文档的局部编号不会冲突。

### 2.2 跨域交接（R7）

权威位置：[持久工作 4.3](../core/durable/README.md#43-跨域交接r7)。每一次跨事务域的交接（裁决域 → 执行管理、执行管理 → 裁决域的回报、来源模块 → 运行记录、跨域的内容登记）都使用同一组故障点，测试时以交接种类区分。

| 故障点 | 额外注入 | 判据 | 规则 |
| --- | --- | --- | --- |
| 交接/源方记录 | 业务事务回滚 | 不存在已确认的责任 | R7、G3 |
| 交接/对方接纳 | 对方已接纳、响应丢失；重复投递 | 对方只有一份接纳；源方查询得到原回执 | R7、G3、G11 |
| 交接/源方收据 | 收据保存前崩溃 | 恢复后查询原交接并保存原回执，不新建交接 | R7 |

## 3 模拟目标

模拟 API 至少提供三类能力，每类都必须独立记录收到的请求和产生的效果：

| 类别 | 可注入的目标侧故障 |
| --- | --- |
| 幂等 | 已生效后丢回执；幂等键过期；同键不同参数 |
| 可查询、不幂等 | 已生效后丢回执；查询暂时返回"不存在"（最终一致）；原请求延迟后才生效 |
| 不可查询、不幂等 | 已生效后丢回执；超时；取消后仍生效 |

模拟模型供应商另需提供：已计费但响应丢失；流在中途断开；用量回报重复、乱序、迟到。

## 4 M1 覆盖要求

M1 退出时，第 2 节每个故障点的三种时机都有用例；掉电只在本地档声明的平台组合上做。用例按开发规范 5 的两层组织：故障矩阵属于契约场景层，只通过公共契约命令驱动。场景的格式和 M1 场景清单见[一致性测试](conformance.md)。
