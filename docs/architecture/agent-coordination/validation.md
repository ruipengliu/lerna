# Agent 协作验证、依赖与采用范围

[总览](README.md) · [协作契约](peer-contracts.md) · [委派机制](delegation.md) · [通信验收](../endpoint-communication/validation.md#runtime)

本方案交付设计、本地接口和跨端线契约；下面场景是参考实现及互操作验收要求，尚未运行。CO1–CO7 对应[模块保证](README.md#guarantees)，C／A／V 编号对应[项目目标](../../harness-project-goals.md)。

<a id="dependencies"></a>
## 1. 启用依赖与缺席行为

| 提供方 | 需要交付的依据 | 缺席时的行为 |
| --- | --- | --- |
| 任务内核及运行存储 | 父准入／预算预留、固定操作和子关联；受信子配置及父观察责任进入 Submit 事务；Observe、ReadTask／ReadResult、用量账本投影与取消 | 不提供内部 Agent 可派发候选；不能降级创建不受限普通任务；同权威观察不可用的替代实现须完整承担 Peer 转交责任 |
| 身份与授权 | actor／endpoint／owner 绑定、Delegate、使用判定、来源及用途复核、撤销与连续恢复依据 | 身份不成立拒绝；当前判断不明等待；跨端缺授权 P1 的实现和映射时相关行为不开门 |
| 已安装 Agent／扩展 | 固定目标／结果合同、配置版本、查询／取消／用量保证及受控出口 | 不自动信任自报能力；缺必要保证则禁用该配置 |
| 执行与内容 | 原操作事实、可核验效果、完整成果及来源、获准读取和保留 | 结果不完整或效果不明时不能完成依赖它的父目标 |
| 协作领域恢复及依赖提供方 | 原 D 的接纳、控制、结果和用量依据；授权及执行等依赖由原领域按本轮提供 | 流可恢复仍限制缺证据的委派行为；查询、控制和接收事实按各自权限继续 |
| 受信宿主与协作存储 | 有限委派配置、持久合同及 PeerWork、原提交核对、当前活动所有者依据、本地管理入口 | 不接纳新委派责任；协作决定不可耐久保存时，调用方继续承担原责任 |
| 端点通信 | 固定消息的持久接管、入站交接、本轮恢复结论与获准路径；通过[通信验收](../endpoint-communication/validation.md#runtime) | 接管未知保留协作发送工作；必要通信或恢复依据缺失时限制相应委派行为，不从连通性推断子接纳 |

通用收发账本、流恢复、活动所有者接替和传输容量由[端点通信设计](../endpoint-communication/delivery-and-recovery.md)及其验收负责。协作验收只验证调用这些能力时，原 D、合同及领域责任仍成立。记忆、UI、授权、执行及大脑的跨端条件分别按所属方案启用，不用一个“协作已支持”开关同时打开。

<a id="tests"></a>
## 2. 核心验收矩阵

每项运行测试固定实现／配置／Schema 版本、用户和端点、权限、预算、内容及故障点，并观察持久记录、网络消息和实际效果。事务故障至少覆盖提交前、提交后答复前、跨模块确认后记账前三个位置。模拟提供方通过只证明该测试合同，不能替代真实提供方的隔离或耐久保证。

| 编号 | 前置条件与刺激／故障 | 必须观察到的结果 | 保证／目标 |
| --- | --- | --- | --- |
| CO-01 | 同用户内部 D 正常委派、同 D 重投、同 D 换目标 | 一份合同、C/S 及子任务；异意图拒绝；recorded、accepted 和父完成分别可查 | CO1、CO2／C5、A1 |
| CO-02 | D 接管或 C 创建后崩溃；接纳答复丢失 | 原 S 可查；无第二子任务；扫描继续；未知期间父预算不释放 | CO1–CO3／C5 |
| CO-03 | 子提交误用 D；另一个任务复用 S；父请求错投其他权威 | 用户级索引冲突或路由拒绝；无新任务、预算或控制权 | CO1、CO6／C5、A4 |
| CO-04 | 适配器未安装、声明过期、子配置无法约束核心 | 不生成可派发候选或明确拒绝；不能回落普通 Submit／工具 | CO2、CO3／C6、A2 |
| CO-05 | 子完成，父尚缺方案乙来源或效果观察 | 父不完成；子事实保留来源及保证边界，补证或明确失败 | CO2、CO3／C1、C3、V1 |
| CO-06 | 账单重复、跳修订、乱序、同修订不同内容、子终态但 final=false | 累计差额只记一次；乱序不回退；冲突不放款；未知余额保留 | CO3／C5、C8 |
| CO-07 | 两个子任务并行及子再委派，份额接近总额；提供方仅有估算上限 | 不超卖、不双计后代；hard 要求拒绝 estimated，收尾不能挪为目标费用 | CO3、CO7／C5、C7 |
| CO-08 | 取消先于本地接纳准备；准备先于取消；D 尚未到达 | 前者封闭且无子创建；后两者沿原接纳核对，不将未找到当永久屏障 | CO4／C5、C7 |
| CO-09 | 子取消被拒后 C 才创建；原取消答复超窗 | 按新事实创建有界新子取消尝试；原答复不改写；超窗缺口不伪造 | CO1、CO4／C5 |
| CO-10 | 子成功结果及账单迟到，父已 cancelled | 保存真实效果／费用，父终态不重开；仅全部开放项核清才清除 effects_pending | CO3、CO4／C7、V2 |
| CO-11 | 外部服务接纳，返回 ID 前断线；原任务已有副作用 | 以固定外部提交键恢复原任务；不重建；无原键核对能力的目标禁用 | CO1、CO4／C4、C6 |
| CO-12 | 外部报告 success 但无来源；自行扩大权限、再委派或超额 | 父验收不通过；违规配置隔离并留证；不把硬上限违例隐去 | CO3、CO7／C6、C7 |
| CO-18 | 通信／身份报告离线资格失效，或子预算不足、固定任务权威不可达 | 停止依赖条件的新子工作；已发生事实保留；不能取得父控制权、新签许可或换端重做 | CO3、CO6／C5、C7 |
| CO-20 | 子成果只有引用，内容失效或当前无权；另用户猜中 D 或委派恢复关联 | 不把消息送达当成完整子成果，不泄露委派对象；结果引用、来源和查询继续受当前披露约束 | CO2、CO7／C2、C7 |
| CO-21 | 主动核对用尽、Peer.Recheck 重复、被动结果随后到达 | 通知去重、无无限轮询或扩额；管理只查原对象，迟到合法事实仍可消费 | CO4、CO7／C5、C8 |
| CO-22 | CO-P1 或授权处理器未安装／未协商，或协作请求指向非固定任务权威 | 对应委派入口关闭；不以普通 task.submit 绕过受信合同，不以流 ready 开放委派或转移任务权威 | CO3、CO5、CO6／C6、A4 |
| CO-23 | 使用通过通信验收的独立交付实现，替换 Agent／协作存储适配器后交换 CO-P1 消息 | 委派合同、错误、原操作去重、恢复、控制和预算一致；实现版本固定，未知版本明确拒绝 | CO1–CO7／A2、A4 |
| CO-24 | 正常联网比较及有状态模拟手机子工作，分别注入断线／取消 | V1 引用来自实际资料且支撑父结论；V2 动作后观察证明效果，未知如实显示 | CO2–CO4／V1、V2 |
| CO-25 | 唯一核心在云／端两种部署，远程 Peer 接管后向错误权威提交 C/S，或丢失正确 Submit 答复 | 错误路由拒绝；原权威查询同一 C/S；没有第二任务、额外用户额度或远端自主下一轮 | CO1、CO3、CO6／A3、A4 |
| CO-26 | 外部暂停、输入提交已应用但响应丢失、请求被替换、父取消后旧输入到达 | 本方接纳与外部应用独立回执，同键查询不重复输入；旧请求不能重新绑定；无暂停／查询能力不开放交互 | CO1、CO4、CO7／C7、A4 |
| CO-27 | 外部要求超原 D 权限／预算；内部父子预算管理修订并发普通 CO 重投 | 普通输入不签授权；外部新 D2 独立准入且旧责任不消失；内部只采用核心预算修订，CO 不改原合同 | CO3、CO4、CO7／C5、C7 |
| CO-28 | 远程内部 Peer 已接管配置并提交 C/S，随后失联；子在唯一核心完成并产生晚到用量 | C/S 创建时已有父观察责任；父直接取得原接纳、结果及累计用量，不等待 Peer 往返；来源与父验收仍有效，未封账余额保留，控制应用情况不冒充已知 | CO1–CO3、CO6／C5、A3 |
| CO-29 | 子创建提交后或父观察提交后崩溃、通知丢失；本地观察与迟到 coordination.fact 重复／冲突 | 沿原 D/C/S 及源修订恢复，父事实、唤醒和费用不重复；原生产者冲突可查询；Peer 消息身份不能制造第二份源事实 | CO1–CO3／C5、A4 |
| CO-30 | 配置只 Resolve 未接管、S／摘要不符、错投权威；同权威观察用于 external；替代 Peer 实现走原 CO-P1 转交 | 前述非法捷径全部拒绝，不能绕过配置接纳或创建外部代理子任务；合法替代实现的 recorded／accepted、查询、控制和事实成功含义不变 | CO1、CO2、CO6／A2、A4 |

原 CO-13～17、CO-19 的完整通用交付用例已归入[通信运行验收](../endpoint-communication/validation.md#runtime)的 EC-13～17、EC-19，不在本页重复维护。CO-18 的端点资格依赖 EC-17，CO-20／22／23 的交接及门禁依赖 EC-13～16；相关集成还须覆盖 EC-19 的收尾容量，协作侧仍分别观察原 D、父子控制、结果和预算。

首批验证 CO-01～10、CO-20～21、CO-28～30 的本地委派闭环、同权威观察与协作存储，并验证所需通信依赖；外部 Agent、离线和跨端分别在依赖齐备后验收。用两个进程交换样例不能证明异构互操作，静态 Schema 通过不能证明磁盘耐久、撤权时序或真实设备支持。

<a id="capacity"></a>
## 3. 容量验证

先测每用户活跃委派、平均后代数量、每委派事实量／字节、子运行时长、累计用量滞后、未转交协作事实及 PeerWork 积压。协作持久空间至少覆盖合同、固定映射、开放责任、未封账用量与备份，声明获准保留期及大内容是否计入。消息、流、连接和收发账本的空间与吞吐由[通信容量验证](../endpoint-communication/validation.md#capacity)单独测量，不能在两模块重复计为同一份配额。

压测覆盖新委派高峰、单用户洪峰、Agent 失联、协作存储接近满、通信恢复后集中到达的委派事实及取消／结算积压。观察拒绝是否发生在协作接管前，既有 D 是否继续可查询，父子取消／核对及其他用户是否获得有限工作机会，原子任务是否重复，未知预算是否保留。通信拥塞与收尾调度由 EC-19 验证，本模块再检查其交付结果能否正确转化为协作事实；系统规模目标按实际部署验证。

<a id="proposals"></a>
## 4. 采用状态与后置范围

CO-P1 已采用为设计，WSS 载荷、注册和示例见[线合同](peer-contracts.md#wire)；运行代码、真实 Agent 适配器和故障注入尚未交付。默认传输与身份／来源、执行及远程 Brain 的领域合同统一，不能仅凭 Schema 通过开放委派。

| 事项 | 已确认设计及启用验收 |
| --- | --- |
| CO-P1：跨端委派 | 独立消息族覆盖准确声明、Delegate、回唯一任务权威的 admit_child、查询、控制、普通外部输入及可靠事实；父子共用一份用户操作索引。按本页委派用例及所引用的 EC 用例验证原身份、取消及输入竞争、预算和两种固定权威部署 |
| 同权威内部观察 | 默认由核心持久观察原 C/S 的状态、固定成果与用量；配置接管、S 分配、CO-P1 查询及控制成功含义保持，直接观察与 Peer 事实按同一原权威身份去重；验收 CO-28～30 |
| 外部 Agent 交互 | 普通输入绑定原外部请求及核心输入；具备暂停和原键查询／应用回执的适配器才提供交互候选。新增权限经身份受信确认，不扩大原 D，超出合同须新委派 |
| CO-P2：任务写权威迁移 | 本轮后置；当前无迁移管理入口或唯一生效服务。若未来有运行中迁移需求，优先整用户权威迁移，仍须补全用户操作索引、唯一裁决、原消息身份保留及旧入口隔离。云／端分别部署不要求搬迁同一正在运行的权威 |
| 执行接替与直连 | 后置；失联不换端重做未知动作，连接沿已定义网关路径。CO-P1 不授予新 owner、设备控制权或其他领域写权威 |

## 5. 验证证据边界

本次同权威观察与收尾恢复调整保持 CO-P1 的消息、Schema、原操作关联及可观察成功含义；通用交付用例迁至通信验收，协作异常继续由本页覆盖。先前合并目录的静态和图示检查只对应当时资产，不作为当前目录的验证证据。当前导航见[整体设计](../README.md)，采用状态见本页及[共同索引](../open-decisions.md)。

| 类别 | 当前状态与证据边界 |
| --- | --- |
| 语义推演 | 已核对 D 接管及 C/S 接纳丢回执、接纳准备与父取消并发、结果／用量迟到：均沿原关联核对，未知接纳不释放预算，迟到事实不重开父任务，最终封账才释放已确认余量 |
| 静态与图示检查 | 本次改动须分别检查本目录链接、规范引用及图示；协议 Schema 和消息关联按[协议校验](../endpoint-communication/validation/README.md)验证，不能以旧目录的检查数量替代 |
| 运行验证 | 未执行；尚无本模块参考实现。委派、控制、输入、结算、适配器替换及容量用例均为待实施验收 |
| 联动范围 | CO-P1 已采用为设计并保持现有语义；CO-P2、执行端接替与直连仍后置，目录调整不扩大能力 |
