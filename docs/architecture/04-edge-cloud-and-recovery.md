# 端云任务所有权与恢复

状态：任务所有权、离线控制、协作移交、状态模型和局部恢复方案均已由用户确认。本文为设计规范，没有实现或故障实验结果。

对应决策：[确定端云任务所有权与恢复语义](../../.scratch/harness-technical-design/issues/07-edge-cloud-recovery.md)。前置输入：[内核与持久化](02-runtime-and-state.md)、[协议方案](03-contracts-and-protocols.md)、[标识模型](03-identifier-model.md)、[UI 交互契约](03-ui-interaction-contracts.md)。机制研究见[持久运行研究](../research/harness-durable-runtime-options.md)，运行保障沿用已确认的 Go 内核实现路线。

## 已确定的运行约束

- Go 内核推进 Harness 任务状态；大脑提出行动，执行系统报告事实。状态和执行记录必须持久化。
- 端侧与云侧是部署位置，不能固定为执行端与唯一大脑。默认单机可以构建多个运行节点和模拟 UI 端。
- 一个部署侧内部跨进程使用 gRPC，端云使用 WebSocket；本地进程内可直接调用 Interface。连接恢复不等于任务恢复。
- 本地能力齐备且有效授权足够的任务允许继续；依赖失联节点的步骤等待。未知动作结果先核对，不能因未收到回执就重做。
- task_ref、operation_id、message_id 分别表达任务、操作和消息；内部 change_id 管理一次原子提交。连接和流游标不替代业务身份。
- UI 呈现不是任务状态权威。任务可在 UI 关闭后继续；无任务交互也须有受控处理模块和明确等待项。

## 已确认的基础取舍

| 设计方面 | 已采纳方案 | 代价与其他路线 |
| --- | --- | --- |
| 权威分布 | 每个任务只有一个逻辑拥有者，可位于端侧或云侧；要交给另一节点自主运行的工作建立受委派子任务，由该节点拥有其状态，父任务只聚合结果。 | 增加父子任务与取消传播处理。另一条路线是让所有任务统一由中心节点拥有，端侧仅执行工作，但其离线自主范围会受中心可达性约束。 |
| 离线控制 | 按能力声明允许的离线动作，并使用有限期、可在本地校验的离线授权；要求即时撤销核验的动作等待在线验证。其他端的取消/撤销在断连期间显示待送达，不提前报告已停止。 | 离线自主意味着远端变化可能不能立即生效；需要严格即时控制的操作降低离线可用性。授权期限及各能力默认策略由授权分册细化。 |
| 保留窗口 | 消息补投按可配置窗口和容量限制；操作及提交核对记录至少覆盖其仍允许恢复/重试的生命周期。超出可恢复窗口时返回明确状态，以快照和效果核对恢复，不盲目补发过期动作。 | 超长离线无法承诺完整消息重放；无限保留则持续增加存储和升级成本。具体期限按能力和部署配置，不能随日志清理破坏有效操作的核对保障。 |

上述约束由本分册的移交、状态及恢复机制共同落实。

## 所有权与执行位置

“逻辑拥有者”指对一个任务有资格提交状态的内核责任单元，不等于某个 goroutine、一次进程启动或一条网络连接。节点重启可以恢复原责任，但需要防止旧 Worker 同时继续写入；具体约束见下文的拥有者世代和 Worker 领取代次。

拥有者可以通过远程能力接口调用另一个节点的工具，而不为每次 RPC 创建子任务。只有将一段工作的目标、决策循环或自主恢复责任委派出去，才建立子任务。由此区分：

| 行为 | 责任划分 |
| --- | --- |
| 远程调用一个已声明的能力 | 父任务拥有者推进任务，执行端维护被调用 Operation 的执行事实与去重记录。 |
| 委派一段可自主运行的工作 | 子任务有独立 task_ref 和拥有者；父任务保存委派关系并等待或聚合子任务结果。 |
| 查询任务进展 | 其他节点或 UI 读取权威快照或标注版本的副本，不获得状态推进权。 |
| 将同一任务迁至另一节点 | 属于显式所有权转移，不能仅更改连接路由。按下文流程封存旧拥有者并激活新拥有者。 |

“父子任务”不允许权限自动增加；父任务取消发起对子任务的取消请求，实际停止情况以子任务及执行端反馈为准。父任务不能代替失联子任务编造终态，子任务也不能直接覆盖父任务状态。

默认单机可用两个具有独立本地存储的逻辑节点验证委派与断连。多节点测试不能通过共享进程内对象绕过协议；每个声明的状态权威都必须可根据自身持久记录恢复。此处不要求部署数据库或共识集群。

## 离线控制的边界

离线授权不是“持有过授权就一直可以运行”。在本地无法确认授权真实性、适用范围、期限或当前已知撤销状态时，不得开始新的受限动作。具体授权表示和可靠时间校验由授权分册定义。

远端撤销消息尚未到达时，离线端无法据该消息更新本地判断。因此能力要在以下语义中明确选择：允许在规定离线授权范围和期限内续跑；或者要求执行前取得在线控制方确认。不能同时声明失联时完全自主与未送达撤销即时生效。

在线校验也不回滚已经发生的动作。取消/撤销到达后阻止适用的新动作，对已开始动作请求停止或核对实际效果；支持程度仍取决于执行能力。UI 应分别展示取消待送达、已受理和已停止，不将关闭窗口或 WebSocket 视为取消确认。

无任务 UI 交互按处理模块所在位置判断可用性：本地授权和能力足够的操作可本地完成；依赖远端的提交只能按契约排队或拒绝。已排队的表单提交不能显示为远端已处理，重连须重新核对等待项是否仍有效。

## 保留窗口与过期恢复

保留规则区分三个层次：

| 层次 | 至少保存什么 | 过期时必须避免什么 |
| --- | --- | --- |
| 消息补投 | 消息身份、逻辑流位置、必要载荷和确认位置。 | 游标过期后假装没有漏消息，或用新 message_id 把旧动作当作全新请求。 |
| 操作及等待项 | 稳定操作身份、受理/执行/效果信息、目标和有效状态。 | 短期消息或受理回执清理时顺便丢失仍需恢复的业务结果。 |
| 内部提交核对 | 提交身份、结果版本与必要回执。 | 提交结果不明时因为回执缺失就重复推进一次状态。 |

容量上限不能授权丢弃仍有恢复义务的可靠控制消息。容量不足时拒绝新受理或背压，并保留已受理任务的必要记录。敏感内容删除与最小恢复记录的关系由记忆和授权设计共同约束。

过期消息不能只靠“查不到”判断未执行。需要可验证的操作有效期或接纳窗口，在去重记录清理后仍能拒绝旧操作；窗口身份绑定和清理条件见下文。临时 UI 状态可取新快照，但不能以此跳过业务操作核对。

## 关键故障行为

| 情形 | 必须保持的行为 | 设计依据 |
| --- | --- | --- |
| 父任务在云端，端侧子任务断网 | 端侧只能在已获委派与有效离线授权内自主继续；父任务保留待核对的远端状态。 | 两个任务的推进权分开，离线授权限制续跑范围。 |
| 执行节点完成动作后立即重启 | 按原 operation_id 恢复执行记录并核对，不自动执行新动作。 | 持久化和效果核对沿用既定要求，保留契约决定可恢复期。 |
| 另一端在断连时发起取消 | 显示待送达；不能把本地受理误报为远端停止。 | 离线授权明确即时控制与自主执行的边界。 |
| 云端观察到设备失联 | 不能仅因超时就认为旧拥有者已失效并启动重复执行。 | 仅允许原拥有者恢复、协作移交或具备排他性证据的故障接管。 |
| 设备长时间离线后携带旧操作回来 | 核对保留范围及操作状态；过期不能自动重新执行。 | 接纳窗口及核对记录约束过期恢复。 |
| 同一等待项在两端被提交 | 由等待项负责模块核对状态，接受符合契约的提交；其他端获得已处理结果。 | 不由消息先到某个 UI 决定业务终态，沿用统一标识和交互契约。 |

以上为设计推演，尚未进行故障注入测试。

## 移交、状态与恢复算法

以下机制均已确认。拥有者世代、Worker 领取代次和接纳窗口是现有对象的控制元数据，不引入另一套任务/操作身份。

### 默认协作移交，故障接管须有排他性证据

参考实现支持原拥有者重启恢复和双方可协作的所有权移交。仅观察到失联或超时，不授权另一节点抢占同一任务。生产环境可以替换所有权管理 Adapter，但自动故障接管必须提供可验证的排他性和旧执行者隔离，不能只依赖心跳时间。

协作移交流程：

1. 源拥有者停止该任务的新调度，记录移交意图及目标。既有未完成操作须结束、明确停止或保留待核对记录，不能将它们消失在检查点之外。
2. 源端持久化任务状态、操作记录、待发送工作、有效等待项、适用的接纳窗口/去重水位和路由信息；目标端准备并持久化所需状态，但此时不能执行任务。
3. 源端在本地原子提交中封存旧拥有者世代，并记录发往唯一目标的激活凭据及待发送消息。只有封存已持久化后才允许发出激活凭据。
4. 目标端校验激活凭据、状态版本与授权，持久化新拥有者世代后开始恢复。源端和目标端重启均遵循已有封存/激活记录，不根据连接是否存活自行回滚。
5. 回执丢失时核对移交状态；源端封存后不得仅因目标未回包就自动重新激活。目标继续转交也须完成新的受控移交。

该流程在源端封存、目标端尚未确认激活的窗口可能暂时不可用，这是避免双拥有者的代价。目标永久丢失且源端无法证明其未激活时，参考实现保留待处理状态；不能把人工点击“重试”当作排他性证据。

同一拥有者内部多 Worker 通过持久化领取代次和提交前置条件竞争。旧 Worker 不能提交新任务状态；执行端在动作开始前也须校验适用资格。仅拒绝旧数据库写入无法撤回已经发生的外部动作。

因此，移交前若无法证明旧执行端已停止启动新动作，应等待其受约束执行资格失效并完成核对，或者暂停移交。外部能力不能检查世代或无法保证停止时，不声明无缝接管。迟到结果作为带来源的事实保留，由当前拥有者核对，不丢弃仍有价值的效果证据。

### 主状态、等待原因和控制意图分别表达

任务采用少量主状态：`QUEUED`、`RUNNING`、`WAITING`、`COMPLETED`、`FAILED`、`CANCELLED`。暂停、取消等控制意图单独保存，等待原因可以同时包含输入、远端连接、授权、子任务或效果核对，避免为各种组合不断增加状态。

| 维度 | 示例 | 约束 |
| --- | --- | --- |
| 主状态 | WAITING | 表示任务目前不能继续推进；不解释具体原因。 |
| 等待原因 | INPUT、DEPENDENCY、AUTHORIZATION、RECONCILIATION | 关联明确的等待项、节点、子任务或操作；允许多项并存。 |
| 控制意图 | RUN、PAUSE、CANCEL | 表达用户/策略希望发生什么；意图已持久化不等于执行端已实现。 |
| 控制进展 | 待送达、已受理、已落实 | 用于报告暂停/取消等意图的实际落实情况。 |

拥有者迁移是独立的管理阶段，不为每个迁移步骤改变用户任务身份或混入业务终态。执行类 Operation 继续使用协议已有的执行、结果和效果确认维度，不复制一套任务状态机。

终态须有相应证据：完成依据目标与结果；失败依据已确认的失败；取消依据需要停止的工作已按契约停止或完成处置。影响终态判断的外部效果不明时保留核对等待，不能为了结束 UI 进度而写入取消或失败。已经发生的副作用在取消后仍保留记录。

恢复旧任务沿用其持久化控制意图；重启不能清除暂停/取消请求或自动重新进入运行。终态后若有新的工作意图，应建立新任务或明确的后续操作，不静默重新打开旧任务。

### 按任务和流局部恢复，先核对再开放调度

恢复以受影响的任务、操作和流为单元。一个子任务或 UI 窗口失联不能阻塞整个节点所有无关工作；需要在线控制的操作仍遵守离线授权边界。

恢复步骤：

1. 恢复持久化状态，建立认证连接并协商协议；核对拥有者世代、有效领取资格、授权及控制意图。
2. 双方交换可靠流的已持久化连续接收位置和可补读范围。只确认已持久化前缀，乱序缺口之后的消息不能被当成前缀一并确认。
3. 按原 message_id 补投有效消息；接收端以持久化 Inbox 去重。逻辑操作按 operation_id 再次去重，转化出的状态变更及回复消息与消费标记在本地原子边界内提交。
4. 查询已受理操作，核对已发生但结果未知的动作。输入/取消/接管也按既有身份核对，不能重新创建一次用户意图。
5. 恢复 UI 快照、有效等待项和界面版本，处理旧 surface/过期交互；只有相关对象的前置条件满足后才开放其调度或提交。

接收记录与操作受理可以分两阶段持久化：第一阶段保存接收/去重记录并发出持久化回执；第二阶段将消息转化为业务变更。两阶段之间重启必须能扫描未处理 Inbox 继续，不能收到 PERSISTED 回执后永久漏掉业务处理。

对于任务运行，第二阶段应将 Inbox 消费标记、操作登记、RunStore 状态变更和回复 Outbox 纳入同一运行存储事务。记忆或独立 UI 模块若使用不同存储，需让目标模块按同一 operation_id 幂等受理并可查询结果，确认其受理后才标记完成转交；不能假设跨 Adapter 有隐式原子事务。

#### 有界清理后的旧请求识别

在操作身份内部绑定接纳窗口世代，表现仍为一个不透明 operation_id；不增加全局操作实体。接收方按受信发起作用域发放可本地校验的窗口，客户端可在有效窗口内离线生成带随机部分的操作身份。窗口不得通过重连或修改消息元数据随意重开。

查询既有操作时，先校验访问权限，再返回仍保留的结果；接纳新的操作时，校验其身份绑定的窗口和业务期限。已关闭的窗口即使去重明细已清理，也不能重新接纳首次到达的旧操作。更换窗口意味着新的业务操作身份，不能由传输层自动转换旧操作。

接收方持久化已关闭窗口的水位及必要例外；只有整个旧窗口不再接纳新操作，且相关操作/提交已无未履行恢复义务，才可清理去重明细。窗口水位是已有作用域的控制元数据，不能与 message seq、任务状态版本或拥有者世代共用一个含义。

窗口过期前已受理的长任务可以在其自身有效授权和期限内继续，窗口关闭不等于任务取消；尚未受理的离线新提交可能被拒绝。过期 UI 输入保留清楚的未提交/已失效反馈，不静默续期后自动执行。

#### UI 恢复一致性

等待项由其负责模块校验，已处理操作重试返回原结果，新操作竞争同一等待项按版本检查。独立 UI 交互不要求 task_ref。界面补丁失配时获取快照，末次临时增量丢失通过周期版本核对或可靠版本通告发现；旧 surface 或旧连接消息不能重新激活已关闭交互。

## 实现交接边界

状态转换、移交故障窗口、提交前置条件和恢复矩阵见 [恢复状态与故障检查表](04-recovery-state-and-failure-matrix.md)。该表将本分册行为细化为实现及故障注入依据。授权材料、可信时间和默认期限由授权分册细化；记忆内容、独立存储幂等和同步冲突由记忆分册细化。相应分册必须保持本票确认的运行语义。

离线授权、节点认证和时钟异常的参考机制已在 [授权生命周期](08-authorization-lifecycle-and-interfaces.md) 确定：原生节点使用 mTLS，有限授权绑定接收方和出示节点；依赖远端授权的离线重启默认重新核验，本地权威可在受信本机重新验证。不改变本册关于协作移交、未知效果和未送达撤销的边界。
