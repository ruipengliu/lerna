# 0011 M1 初始格式与停机恢复

- 状态：已采纳
- 日期：2026-10-06
- 影响：[数据与存储](../architecture/topics/data-and-storage.md)、[部署](../architecture/topics/deployment.md)、[持久工作](../architecture/core/durable/README.md)

## 背景

自动补建表后才检查用户身份，会先修改不属于本宿主的数据库。只检查传入命令版本，也不能阻止旧解释器领取另一版本保存的工作。M1 的第一次格式发布必须在自动业务恢复前建立明确边界。

## 决定

M1 支持格式版本 1、契约版本 1 和固定实现配置 `lerna-m1-v1`。初始格式标记保存用户、裁决域、本地持久档位、编译进宿主的迁移集合摘要及实际表结构摘要。空数据库的全部表、提交时钟、身份和标记在 `storage.bootstrap` 一笔事务中保存。任何步骤失败时不留下部分格式；提交回执丢失时重新打开并核验原标记。

打开已有数据库先只读检查标记、身份、版本和实际结构。SQLite 头部 `application_id=0x4c524e41`（LRNA）、`user_version=1` 与表内标记一起原子保存并核验。仅当没有任何表或索引，且 `application_id`、`user_version`、`schema_version` 都为零时才允许首次初始化；无用户表但有其他格式标记、系统表或曾经创建／删除结构的文件不算新库。头部标记和表内摘要不证明任意旧备份的连续性，也不能检测外部故意清除全部历史的文件。非空无标记、未来版本、摘要不匹配或身份不匹配时停止，不补建或修补表，不进入任何业务负责方的自动恢复。配置同步档位之后再次在初始化事务内检查，避免两个初始化者各自依据先前空库观察作决定。

进入恢复前检查保存的工作契约及待交接命令的原版本。领取批次在任何工作修改前核验全部选中工作；不支持时整批拒绝。推进已领取工作使用当前保存对象的版本，调用方持有的旧副本不能越过检查。原描述的编译器、编码器和解释规则必须仍受支持；不能重新编译旧描述、增强能力、换端点或创建替代动作。

已打开宿主的直接领取和已领取工作推进同样核验当前保存 Job 的完整消息树，包括原命令 Identity、真实 Session 和 Ref 的嵌套未知字段。M1 没有登记这些字段的安全未知扩展，发现未知语义时以 `UNSUPPORTED_FEATURE` 拒绝新领取或推进；整批领取不得留下部分领取，原提交和此前已接受的领取回执保持原值。保存目标命令的正文、凭据和诊断字段已经按原契约剥离，兼容检查只核验保存格式，不把它当作新提交重新校验非空正文，也不丢弃未知字段来继续。启动扫描不能替代这些 live 入口的检查。

正式取消和文件契约进入同一初始格式时，原取消范围、封闭意图、端点证明及原动作封闭标记都按各自类型检查，包括嵌套 Header 的未知字段；不能只检查待领取工作或跳过已有回执的意图。文件恢复编译器只核验原 `managed-file` 版本、固定协议与完整声明、描述摘要和原参数／能力／查询主体绑定，不读取文件内容来重编请求。共享装配按原适配器分派恢复检查，保留模型与模拟器的原实现检查。全部检查必须先于任一业务负责方恢复。

正式 014 非成功关闭迁移同样进入原子初始格式和编译摘要。资格副本按实际保存类型读取 `TaskClosing`、`TaskClosureIntent`、`TaskClosureSeal`、原动作封闭索引中的同一 `TaskClosureSeal`、`ExecutionFollowup`、`SettlementFollowup`，以及专用 `execution_followup_jobs` 中的原 `Job`。这些记录没有额外的关闭契约版本字段，不得虚构该字段；已有嵌套 Header、Job 契约版本及任何层级的未知字段使用同一检查。已经 CLOSED 或已有源回执不免除检查。拒绝必须先于任何负责方自动恢复，保留另一原 READY 工作的领取代次、原回执、预算和独立目标历史。

模型调用同样检查保存的 `ModelSettings` 原供应商、编码器和策略版本，包括尚未生成动作的准备责任。参考实现只支持 `reference`、`reference-model-v1` 与 `m1-v1`，模型名称和调用设置保持原值。已经封存的输入摘要、模型描述摘要和原动作绑定保持不变；检查不重新生成输入，不采样模型，也不因原模型输出已收集而跳过未知版本。

正式 016 有限推理推进记录加入同一原子初始格式。恢复前按实际类型检查 `reasoner_drivers` 当前记录、`reasoner_driver_versions` 全部不可变修订，以及已有 `proposal_requests`、`proposal_outcomes` 中的原引用和真实 Job Claim。禁用、被替代或已完成的历史仍须可理解，当前受支持记录不能遮住旧版本；这些记录没有另造的 Header 或契约版本字段。任务编排通过声明的只读历史端口，在任一负责方恢复之前核验原 driver 契约、固定 factory 实现与模型设置。原 driver 配置保留合法非规范化 JSON 和空 ViewPolicy；原 ModelCall 的已规范化设置单独核验。兼容读取不重查历史授权的当前有效期或旧 claim 租约，不重新编码、调用模型、改派实现、迁移或丢弃原证据。

SQLite 在首次读取结构或关闭连接时可能恢复热主日志、检查点 WAL；仅使用 `SELECT` 不能证明未知原文件没有改变。宿主先把主文件及实际存在的旁文件复制到私有资格目录，只在副本上让 SQLite 解析、恢复并核验格式、身份和保存契约。主文件不存在但任一 WAL、SHM 或主日志仍存在时，不算新库；拒绝并保留遗留文件的字节与存在性，不创建主文件，也不让 SQLite 忽略或清除孤立旁文件。结束资格检查后再次核验原文件集的存在性、大小、摘要和物理文件身份；变化时停止并要求重试原启动。只有已经识别的原文件集才开启原写连接，并再次核验逻辑格式。外部路径替换或不合作写者必须停止；资格副本不授予同时运行多个宿主的许可，不是备份或最新性证明。

上述逐字节不变承诺针对物理格式、身份及保存的未知契约拒绝。已识别的 SQLite 格式可以先进行 SQLite 自身的日志恢复；原模型、适配器和解释版本仍由各负责方的类型化只读检查核验，并在任何业务恢复前拒绝未知原实现。该拒绝保留全部原业务事实，不承诺已支持数据库的旁文件没有被 SQLite 检查点或重建。基础设施不得复制一套模型或适配器业务解释算法。

本次格式为首次受控发布。未标记的开发历史**不支持自动迁移**，即使包含本项目的表也不按空数据库处理。它可能包含原 P5、未知效果、费用及旧确认正文；必须停止旧进程和全部出口，保留原数据库及实际存在的旁文件，保留原二进制和外部目标／凭据绑定，供人工审核原责任。不得删除重建、复制正文来恢复权限或声称迁移已经执行。

正式 M1 参考 API 历史也在任何负责方恢复之前纯核验：读取所有原动作，包含未准备、已关闭 UNKNOWN、原发送历史与独立 QUERY，不按任务状态过滤。原 API 固定描述、账户/凭据引用、完整声明、参数和能力引用、尝试/发送/键/到期、查询主体及摘要必须由原解释器支持；不调用 Compile/CompileContext、内容读取、凭据解析或 HTTP，不重新授权或编码。QUERY 的 READ/query-v1/两个 false 标志保留原编译先设置的幂等机制、并发、参数绑定、保留期及拒绝到期键属性，不能因为最终 Idempotent=false 清空它们。过期的原键仍可读取；新发送继续通过原 P4/P5 门禁。

不兼容历史的公开验收同时核对原提交、交接和开始回执、全部原发送的观察和逐发送费用来源，以及已固定关闭的完整视图和 Result 字节。另一实际 READY 工作必须仍在代次 0；独立目标的请求、效果与账单计数不变。合法历史的原平台条目缺失时，启动仍可读取原记录；随后新出口明确返回 `CREDENTIAL_UNAVAILABLE`，不把当前凭据不可用误判成保存格式不支持。

恢复装配将显式 FileRoots、APIKeychainPath、APIRoots 同时传给单一 OpenWithOptions。最新停机副本只包含数据库文件组；原 API 目标、原平台凭据仓库和 TLS 信任根、FILE 命名空间是独立外部世界。凭据缺失是当前出口可用性错误，不把合法旧实现标成不兼容，也不为 UNKNOWN 重新发送。格式资格副本与受支持 SQLite 上的纯原实现资格不同：后者保证业务责任未推进，不承诺原 WAL/SHM 逐字节不变。

## 停机升级与备份操作

1. 停止接收新命令，等待所有同步调用返回，关闭全部工作者与数据库连接；原路径此后保持停止。
2. 将数据库和实际存在的 `-wal`、`-shm`、`-journal` 复制到空备份目录，记录每项存在性、字节数和 SHA-256。文件集必须一致；清洁关闭没有 WAL 时不声称验证过必要 WAL 缺失。
3. 升级前由目标二进制只读核验支持的标记和原实现配置。格式不兼容时停止；尚无受支持的版本间转换，不能直接执行 DDL 或恢复业务。
4. 只将这次最新停机副本复制到另一空恢复目录，并在 `Open` 前核验清单。保留原用户、负责域、回执、动作、尝试、发送与外部目标身份，恢复后核对原记录和目标实际计数。
5. 原路径不得与恢复路径同时运行。任意较旧备份、回滚或连续性不能证明时不开放出口；本清单摘要不证明备份最新，也不实现 M3 导入隔离。

数据库恢复不会回滚外部 API、FILE 根目录或平台凭据存储。恢复演练验证同一独立目标历史、原未知和费用责任、原回执去重及迟到事实；物理断电和介质永久丢失不在本次演练证明范围。

文件恢复使用 `RestoreBackupWithOptions` 显式传入原 `FileRoots`，默认 `RestoreBackup` 委托空选项；选项沿同一个 `OpenWithOptions` 装配入口传递。备份只复制数据库文件集，不复制、重建或回滚受管理根。验收保持原根及实际发布命名空间，先真实发布而丢失读回证明，再停机备份并恢复到另一空数据库目录；原未知、尝试、外部键、费用和文件版本保持，不自动再次发布。取消的原准入尚待交接时，同样恢复原范围、回执和封闭证明，不能为了补齐视图而创建另一动作或 Result。

014 已固定 FAILED 或 CANCELLED Result 的停机历史也保留原 UNKNOWN、封闭证明、原核对计划及执行和逐发送结算后续责任。演练先暂停原核对计划，再关闭来源全部连接并永不恢复来源；恢复到另一空数据库仍连接同一独立目标，不新增业务发送。指标查询只读取闭合任务的原事实和全部未完成分母；显式恢复原计划后的实际弱查询、原迟到账单和原迟到效果可以推进负责方事实与工作，不能改写固定 Result。指标不替代这些业务处理，也不把缺失完成时长报告为零。

受信备份工具只在调用方已经停止全部写者后复制四项文件，不通过打开数据库来备份。`Harness.CloseAndBackup` 先等待本宿主当前事务结束并关闭其全部存储连接，然后生成停机副本；另一个宿主或进程的停止仍是操作者前置条件，工具不证明任意外部进程已停止。清单记录实际核验过的用户、负责域、原格式摘要及存储环境，四项文件各自的存在性、大小和 SHA-256。复制后的每项重新核验并先同步文件再写清单；该文件复制不声称完成物理断电资格验证。

恢复工具只接受受支持的清单结构、固定四项文件及明确的身份；拒绝歧义重复字段、未知字段、多余文件、缺失的必要文件、大小或摘要不符、未知版本和非空目标目录。全部清单核验完成后才复制，在另一个空恢复目录再次核验，最后才允许目标宿主 `Open`。原来源此后不重新打开；目标宿主继续核验原数据库格式和实现版本。清单只证明这次文件集一致，不证明其是任意历史中的最新版本；使用较旧备份不属于本流程。

## 后果

结构或固定实现改变后，需要新的受审格式或显式停机迁移；不能靠相同版本号继续解释。只读业务查询保留原事实；不兼容工作拒绝推进，不把停止误写为未发生或已完成。

恢复参考 simulator／MODEL 历史时，同一版本字符串仍必须对应完整固定声明：效果、幂等、查询、撤销及并发维度，以及机制、参数绑定、账户范围、保留期和过期拒绝属性均精确匹配。封存描述的摘要有效也不足以证明它属于原动作；还须核对原动作、尝试、发送、目标、参数、能力、外部键、原有效期、查询主体及 MODEL 正文摘要的绑定。恢复检查使用与编译共享的纯固定声明规则，但不得调用 Compile、重建描述、续期或改写原记录；已经过期的原键仍可读取历史，是否允许新发送由原发送门禁裁决。
