- 状态：已采纳；下述固定平台与有限故障策略的验收已通过。
- 影响：[文件适配器](../architecture/adapters/file.md)、G1–G5、G8–G9、G11–G12。

## 决定

M1 只支持受信宿主配置的本机根。能力资源采用 `managed://根标识/目标标识`；根和目标都是单段名称，不接受调用者提供的绝对路径、任意 URI 或嵌套路径。受管理根以及祖先必须由部署权限隔离，所有写者遵守同一锁协议；不能保证此前提的路径不得启用。根的实际挂载资格独立于 SQLite 资格检查。

根别名首次获准使用时，受信原生执行在 P5 内捕获根与 `objects`、`commits`、`locks` 的设备号、inode、generation 和创建时间；内容治理先持久接纳不可变的 `ManagedFileRoot` 绑定，随后才允许命名空间变更。绑定跨进程恢复；任意目录身份变化都拒绝沿用旧别名，迁移必须配置新的根别名。绑定未确认时不创建锁或文件。

`ManagedFileRoot` 属于内容治理，因为它描述受控副本的位置和稳定资源身份，供原文件版本及清理责任使用。它不是内容发布、文件提交或效果证据。文件发布与原尝试效果仍仅由执行账本接纳和裁决；适配器不得据根绑定记录宣布文件已经创建。

根内预置并完整同步 `objects`、`commits`、`locks` 目录、根及其父目录；三个内部目录必须与根位于同一设备。每个目标使用 `locks/目标标识` 的独立稳定锁，锁文件不得删除或替换。不可变对象名和指针临时名绑定原用户、动作、尝试与发送，写入前登记持有责任；`commits/目标标识` 是唯一当前提交指针。历史归执行账本持有，不新增成功表。

对象写入、对象文件屏障、对象目录屏障、指针临时文件写入与屏障、指针替换、提交目录屏障按此顺序进行。每一道屏障必须独立成功；macOS 同时检查 `fsync` 与 `F_FULLFSYNC`，不允许普通同步回退。跨文件系统替换错误直接保留，不复制降级。最后读回完整对象与指针；读回匹配不得抵消失败的屏障。

路径访问从原生目录句柄逐段锚定，拒绝符号链接、硬链接与非普通文件。重新核验根和祖先绑定；允许的业务路径只有固定描述所指目标及本尝试登记的辅助资源。读取、核对和清理同样必须经过准入和 P4/P5。部署创建目录是宿主配置，不得成为动态外部文件访问的旁路。

发布前重新核验当前领取、控制、授权、内容和执行资格。覆盖当前提交前，必须有执行账本已持久接纳前驱可归因证据的证明；缺失时返回前驱交接受阻，由原核对责任通过独立准入查询前驱。后继写的观察不得伪装成前驱原写的观察。原尝试查询只读，不能恢复或重发旧内容。原写已确认不再迟到、但历史效果仍未知时可以收尾；显式核对请求仍可为该未知历史独立准入，补充原证据，原派发保持封闭。已知终态不因这种请求重新开放核对。

所有文件采用当前宿主用户、目录 `0700`、文件 `0600`。替换保留逻辑目标名，不继承旧 inode、ACL、扩展属性、时间戳或其他元数据。M1 不支持追加、任意覆盖、多文件事务、外部不合作写者、SAF、远程挂载和 TTL 回收。清理只处理核心明确指定且已解除引用的本尝试资源，未知提交的最后证据不得删除。成对删除可能部分完成，能力声明为 `PARTIAL_WRITE`，不声明幂等或原尝试查询保证。删除后目录同步失败仍保留清理责任，后续独立获准的清理可以核验缺席并完成屏障，但不能据此改写旧未知动作。

## 验证边界

实际原生 I/O 轨迹分别记录对象字节和目录命名空间，文件同步不能代替目录同步。每个真实切点重建掉电镜像，独立父进程以收到的确认和实际发布次数核验；去掉四道屏障的负对照必须暴露错误确认。联合恢复使用 SQLite 与原生文件的同一时间前缀，不能组合现实中不可能共存的存储状态。

验收是固定平台、有限故障策略下的协议证据，不是物理电源中断测试。平台未通过或屏障失败时不得声明掉电持久成功。

### 可重复的验收证据

`conformance/fault/file_test.go` 通过公开任务、内容、授权、账本与出口入口驱动实际本机文件：原观察丢失后的 A/B/C 交接、账本读取失败或回执未知、版本冲突、短写、读取、路径替换、符号链接、硬链接、特殊文件、撤销／取消／领取失效、同步与读回失败、原尝试只读核对以及受控清理。`content.file_root` 的提交前、提交后及回执丢失边界分别检查原根绑定与原回执，且原出口重放不创建锁、对象或指针。

`conformance/executor.Run` 接收公开 fixture 工厂，`conformance/fault/execution_adapter_test.go` 用它分别装配模拟 API 与真实文件目标。首次调用后保存独立目标计数，再核验许可重放后的计数完全不变；API 首次调用明确要求只收到一次请求。固定描述改变不调用目标，许可重放只产生一次外部发布，P5 后未知不重发，费用证据归属原发送。文件的零计费规则独立核验固定 `Nonbillable`、零上界与受信本机协议回报，不由文件效果成功推导费用为零。

原生存储套件以子进程真实系统调用完成轨迹为输入，父进程独立接收序列化回执和观察确认。当前 CREATE 轨迹包含 14 个已完成原生事件；0 至 14 的每个前缀分别应用 5 个未同步字节策略（丢失、全部保留、逆序、偶数写保留、部分写入）和 3 个未同步目录事件策略（丢失、全部保留、前半前缀），共 225 个有限镜像。inode 字节与目录名称分开保存；目录事件保留每次 rename 的原子性与先行 create 关系。任何可见当前指针都必须指向完整对象，确认点之后还必须保留当前指针。该覆盖不声称枚举所有硬件写入组合。

四个负对照分别在实际原生执行中省略对象文件、对象目录、指针文件、提交目录屏障；其错误成功确认均在丢失未同步状态的镜像中被父进程发现。故障注入只在 `fault` 构建可用，正常构建不能省略屏障。

联合套件逐一合并 SQLite 与原生事件前缀，包含零前缀、所有文件和数据库屏障及最终确认。接入正式追踪来源后的实测生产轨迹为 980 个 SQLite 事件与 14 个原生事件，形成 995 个共同切点；5 种字节策略下的全部 4975 个配对镜像已纳入完整验收并通过。联合套件校验 SQLite VFS 与生产 SQLite 的 source ID 相同，并记录每次原生完成时的 SQLite 序号及最终确认序号；使用单调共同前缀配对两类镜像。SQLite 镜像由真实恢复打开并查询原动作；原生镜像由独立纯模型核验名称、原动作身份、对象长度与摘要。此套件不把原生镜像重新物化到真实挂载，不声称模拟跨掉电后 inode 重新分配或实际断电。2026-10-06 在冻结树 `8ff205ed86702b86480c0fde8381907bac447bd7` 上完成普通全包 race 预检（220.979 秒）、全部非存储故障 race 预检（851.749 秒）以及未经裁剪的 `make check`（4456.104 秒，其中完整故障包 4185.892 秒）。最终检查同时覆盖原有 SQLite 掉电、首次启动、同步错误、负对照、P4 保存点和全部原生／联合矩阵；本结论仅限本 ADR 声明的平台元组、部署前提和有限恢复策略。

### 本地宿主配置

本地可执行程序通过可重复的全局选项 `--file-root 根标识=绝对路径` 装配 `OpenWithFiles`。它是部署宿主配置，不是执行命令或模型参数；命令正文只能引用已经固定的 `managed://根标识/目标标识`。根标识沿用单段名称规则，路径必须为规范绝对路径，空值、重复根标识和相对路径在打开数据库前拒绝。该选项不创建目录，也不在配置阶段读取或写入目标；真实路径、挂载、权限、原生身份仍在获准的 P5 文件使用边界核验。

每个进程固定映射；已持久绑定的根标识不能在重启时改指另一目录。文件迁移必须使用新的根标识和重新准入，不能凭新的 CLI 路径参数沿用旧资源权限。原 `execute START_JSON` 命令保持完整准入、领取、凭据和固定描述，不改写原动作、尝试或发送身份。本地 `--issuer` 沿用 M1 受信宿主身份配置边界；传入文件映射本身不授予调用权限。

### 原负责方追踪关联

根绑定以及文件资源登记、原观察关联和清理确认在内容治理的原事务内同时保存结构化来源事件。来源只包含原根／资源 `Ref`、任务、动作、尝试、发送、派生命令、内容引用和相关观察引用；不复制实际路径、根别名、native identity、文件正文或端点地址。根事件不能作为发布效果证明，清理观察保留其独立动作身份。原生错误只映射为固定错误码；操作系统错误中的路径和自由文本不得经效果解释的原因字段进入追踪。

来源提交之后，追踪接收方独立接纳原事件，内容治理独立保存原接纳回执，索引再独立推进。三步均使用原交接身份；追踪缺口或索引滞后不改写文件效果，也不触发文件重新发送。
