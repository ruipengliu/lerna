## 决定

取消不需要完成提议或核验轮次。任务编排在保存 `CANCELLING` 和新控制代次的同一裁决事务中，保存独立 `Cancellation`，固定原控制命令身份、控制代次和当时完整的准入清单，并为每项准入保存 `CancellationClosureIntent` 及持久待办。取消回执只证明控制及这些责任已经保存。

封闭通过 R7 交给原执行管理和原执行端点。恢复先查询原命令回执，再补交同一命令；源域保存原端点回执后才完成待办。出口的封闭与 P4、P5、实际 I/O 使用相同跨进程临界区。端点保存永久 `CancellationSeal`，包括准确准入、动作、端点及每个从未进入 P5 的发送引用。尚未接纳的动作也保存封闭标记；以后只能按原身份接纳为禁止执行。

P4 前取消阻止旧开始资格；P4 后、P5 前只有端点持久确认封闭胜出，才能产生内部未发送证明；P5 后封闭不消除效果、迟到可能性或费用。完整发送历史逐项处理：封闭新登记的发送不能清除旧发送的未知效果和费用。预算只按不可变端点证明释放其覆盖的预留。收尾查询按当前权限重新准入，仍归原动作负责方。

命令行分别显示已保存控制、未取得端点回执的封闭责任、核对责任及未知效果。即使端点已经封闭新发送，未知效果也继续可见。后续原始观察和账单沿原身份接纳，取消本身不产生新的外部补偿动作。

取消视图保存原意图和端点封闭证明的独立引用与内容。原准入尚未交接到执行管理时，端点可以先保存永久封闭标记并确认；此时 `Operation` 尚未产生，视图列出等待原动作记录的准确准入引用，同时呈现原回执和 `NoSendProven` 证明。这是已封闭原准入、尚待原交接产生动作记录的限定事实，不是动作效果记录，也不生成未知效果或动作版本。原交接到达后，视图显示原身份的禁止执行动作。真正的读取错误继续返回错误；已有动作引用的证明却无法读取原动作时，明确返回事实不可用。

按 [ADR 0006](0006-trace-source-handoff-local-mapping.md)，取消范围的 `CANCELLATION_SAVED` 和每项 `CANCELLATION_CLOSURE_REQUESTED` 与原控制命令同事务保存；`CANCELLATION_SEALED` 与原端点不可变证明同事务保存；`CANCELLATION_CLOSURE_ACKNOWLEDGED` 与原交接回执及待办完成同事务保存。源事件失败使原事实一起回滚。运行记录接纳、源回执确认与索引分别恢复，不能在业务源事务中调用运行记录接纳。

事件仅保留固定事件类型、原控制或封闭命令身份、原取消范围、意图、准入、任务、动作、尝试、发送及回执决定和结果引用。端点事件包含全部已封闭发送引用及原效果状态；历史发送仍沿原引用关联。正文、目标文本、端点地址、本机路径和原生身份不进入事件。记录覆盖完整不决定取消完成、效果或费用。

## 后果

取消封闭的权威依据是用户控制命令及其固定清单，不能伪造完成核验来取得封闭证明。与完成封闭共享底层记录规则，不共享业务裁决依据。任务继续保持 `CANCELLING`，非成功 Result 的固定由独立关闭协议负责。
