# ADR-0006：准入与真实启动执行授权和预算约束

模型需要知道剩余预算才能安排探索与核验，但提示词不能约束实际消费；准入后等待期间，授权或目标也可能变化。因此，Orchestrator 在准入事务检查准确行动、当前许可与预算并固定使用依据和预留，Executor 在真实发送前复核资源门禁、TaskGate、GrantUse、版本就绪与占用。任何执行路径，包括核验读取、程序 hostcall 和 Agent 委派，都遵守这些检查。

授权由受信主体授予，模型、Skill、插件和记忆内容不能自行扩权。同库授权与准入共同提交；远端授权先签发绑定准确行动、额度和截止时间的有限使用凭据，不能包装成跨库原子事务。一次性许可被消费后不因失败或取消而恢复未消费状态。

收费行动启动前必须按可执行上界预留，Snapshot 提供剩余预算和期限。子任务额度从根预算扣减，子侧尚未关闭消费前不能回收重用原分配；探索、核验与收尾分别有有限额度。用量按实际来源的累计修订结算增量，未知费用不得当零释放预留。

**取舍与代价。** 不依赖模型自报成本或一个中央调用提供跨节点瞬时撤销。已签离线窗口可能在期限内继续有效，必须公开撤销延迟；要求每次启动都核验当前许可的能力失联时等待。无可信费用上界的服务不能进入硬预算下的自动计费路径，用户批准估算数字不能代替该保证。

**重新评估条件。** 供应商硬限额、可强制的保守上界或在线核验能力取得证据后，可以扩大适用范围；时钟、隔离、收费或撤销依据不满足时应收紧能力。不得通过重命名操作、另建根预算或放宽估算绕开累计约束。
