# 非成功关闭与原责任保留

| 日期 | 状态 | 决定 |
| --- | --- | --- |
| 2026-10-06 | 已采纳 | 非成功关闭使用独立的可信关闭依据，封闭所有原动作后固定 Result；未知效果和费用由原负责方保存后续责任。 |

## 背景

完成核验只证明当前必要条件及动作收尾是否允许成功。失败和取消可以带着未知结束，不能伪造一个通过的核验轮次。任务控制已保存也不证明实际出口已经停止。关闭必须分别保留目标停止、端点封闭和原效果及费用责任。

## 决定

受信宿主或本地交互提交 `BeginTaskCloseCommand`，精确绑定当前任务修订与控制代次。`FAILED` 接受明确的无法完成、期限到达或用户停止原因；模型提议没有这项权利。`CANCELLED` 必须引用同任务已经保存的取消依据，且当前控制仍为 `CANCELLING`。不支持以任意字符串声明成功，也不接受用户承担风险作为未生效证据。

取消依据保存原停止控制、原准入范围及原端点封闭责任，不裁决后来接纳的输入。新的可信关闭命令独立固定当前输入、需求引用及版本、控制代次和全部历史准入；原取消回执或恢复不得自行创建这条关闭依据。取消之后接纳 ANSWER 或 MODIFY 时，旧的未决定关闭命令必须因任务修订过期而拒绝，可信调用方仍可用新命令身份和当前任务引用明确关闭。原取消代次不要求等于当前关闭代次，也不把当前输入写回原取消记录。已经保存关闭依据后，输入、需求和控制变更被关闭门禁拒绝。

取消关闭保留 `CANCELLING`，保存新的关闭控制代次，分别核验原取消范围及当前全部历史准入范围。保存关闭依据可以先于端点回执；最终固定 CANCELLED Result 必须等待两种范围各自的准确源回执、原端点封闭证明及实际准入交接，并保存所有原效果和逐发送费用后续责任。后来的合法收尾查询可以扩大关闭范围，不能据此改写原取消范围。记录或读取缺失、不兼容不能当作空范围或未发送证明。

公开关闭视图分别返回原关闭意图、准确源回执和端点证明。准入已经保存而原动作尚未交接时，视图列出准确的待交接 AdmissionRef；未发送 tombstone 不伪造 OperationRef、UNKNOWN或效果。证明已经引用动作但动作读取缺失时，或原负责方读取失败时，查询明确不可用。最终关闭继续等待实际原交接，不以视图空清单或端点 ACK代替它。

可靠条件否定与补建资格分别裁决。原阻断事实的跨域读取失败或回报不兼容时，仍保存 `REJECTED` 及缺口，但保存阻断事实不可用的等待原因，不产生继续请求，也不把它解释成原发送尚未开始。恢复重新核验原事实后只能登记一次继续请求。

任务编排保存独立 `TaskClosing`、全部历史准入清单、逐动作的准确封闭意图与持久工作，并永久停止目标推进。预算作为同一裁决事务的参与者，按原动作的全部逐发送预留及计费来源保存 `SettlementFollowup` 和等待工作。跨域封闭仍使用源意图、接收方原决定、源回执三步；实际封闭与 P4/P5 使用同一出口临界锁。

执行管理在原封闭事务保存不可变 `TaskClosureSeal`。仍有未知效果、迟到可能性或未收尾冲突时，同时保存 `ExecutionFollowup` 和明确等待的原责任工作，精确绑定原动作、原尝试、全部相关物理发送和原执行端点。已经存在的核对计划继续按原身份运行；没有查询能力或授权时明确等待，不生成替代动作或盲目重发。

关闭时的条件结论仍按已绑定当前输入的可信要求、原准入范围和权威效果证据核验；尚未处理的新输入使要求依据过期时保留 `UNKNOWN` 和输入缺口。关闭记录保存后，输入处理、要求替换及控制不能再改变它的固定依据；可靠未满足保留 `UNSATISFIED` 及其证据，证据缺失保留 `UNKNOWN`，不因非成功关闭而抹平两者。已有核对计划不因关闭而重建。原动作达到可靠终态、原费用结清后，对应持久待办由原负责方完成；未知、冲突、查询能力或授权不足时保存明确等待原因；后来新增的原证据冲突使原负责方的待办回到等待，不改写固定 Result。

受管理文件的原发布已停止迟到、但读回失败而效果仍为 `UNKNOWN` 时，失败或取消关闭保留原核对计划、尝试、发送和资源责任。关闭后仍可用原计划及当前有效的原查询授权，以收尾用途独立准入只读查询。查询读取原版本的当前指针或已接纳历史，不恢复旧内容，不覆盖后继文件；查询自己的动作、观察和计费来源保持独立身份。弱读取不能完成原执行后续工作，可靠原版本证据到齐后才由执行管理完成它。原写和各查询的零费用必须分别由固定的受信文件协议计费规则证明，不能从效果已知或文件没有变化推导。原固定 Result 和原逐发送结算后续记录不追加这些后来准入的查询，也不因其新证据改写。

全部准确封闭回执已保存，且原效果和预算后续责任可由其写入方核验后，任务编排固定 `FAILED` 或 `CANCELLED` Result。Result 列出关闭时的条件结论、全部动作、遗留未知和逐发送预留，不把未收尾的动作描述为已收尾。关闭后原回报和账单仍归原动作及发送，当前查询展示新事实，Result 的序列化字节和引用不变。

关闭依据、源意图及源回执、端点封闭、执行及结算后续责任、负责方工作状态和固定 Result 都由原负责方在保存事实的同一事务登记结构化源记录。继续请求的原核验记录关联新请求；固定 Result 关联原关闭记录及后续责任。源记录只含受控事件类型、原命令身份与引用，不含目标地址、正文或参数。采集、接收、源 ACK 和索引仍独立恢复；记录覆盖完整不证明业务已终结。

## 取舍

复用成功核验状态会把目标停止与条件满足混在一起，因此拒绝。仅保存未知清单缺少负责方的持久工作，因此拒绝。自动选择新端点或把未知改成失败违反 G1、G11，因此不支持。后续等待记录不承诺能取得外部终局证据；它保证责任和合法恢复入口没有随任务关闭丢失。

## 故障验收范围

FAILED 与 CANCELLED 使用同一个真实公共生产流程分别覆盖 P4 前、P4 后及 P5 后的关闭依据、接收方封闭、源 ACK、固定 Result 提交前崩溃、提交后崩溃和回执丢失。P5 后另覆盖原执行及结算后续工作完成的三种模式；每个结果都核验原封闭身份、独立目标实际调用和费用、晚到事实、重启及固定 Result 字节。取消分支还核验原 Cancellation 的准确 ACK 与端点封闭，不能用原取消矩阵代替当前关闭矩阵。受管理文件的两种非成功关闭分别保留原计划，经实际弱读取、重启和原历史读取完成原责任，原发布和后继文件始终不重放。
