# 长期保留最小去重与终态记录

取消可能先于原执行请求到达，随机操作标识本身不能证明该请求的最晚有效时间；删除全部记录也会使查询无法区分“从未存在”和“已回收”。因此长期保留获准的最小命令去重、操作取消及任务终结依据，完整正文和敏感材料按各自策略独立清理；只有拒绝旧标识对应的请求的依据仍存在时，才把操作记录合并为任务终态记录。

用户在 2026-09-26 的详细设计访谈中确认该选择。代价由权威账本的存储与备份承担，不承诺身份元数据的固定期限全量删除。可验证身份代际或不可延长的接纳期限能支持进一步回收，但会增加跨端发放、验证和恢复协议；出现必须物理删除全部身份的明确需求时再评估该替代方案。

具体规则见[共同调用契约](../architecture/protocol/README.md#3-命令回执与查询)与[执行设计](../architecture/execution/README.md)。
