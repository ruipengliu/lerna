- 影响：[API 适配器](../architecture/adapters/api.md)、[安全](../architecture/topics/security.md)、[执行管理](../architecture/core/ledger/README.md)

## 背景

只保存 URL 和适配器名称不能固定账户、认证方式或编译语义。恢复时加载新的默认版本，会改变原动作。预配置密钥也必须符合平台安全存储和受控注入的要求。

## 决定

M1 接入经过审查的 `lerna-reference-api-v1` 协议，使用真实 HTTP 请求和合成数据；它不是对任意供应商的可靠性认证。能力保存不可变 `ApiDescriptor`，绑定供应商、环境、描述版本、origin、账户、用户、凭据引用、资源、认证方式、媒体类型及编码版本。旧描述和解释器保留至所有原责任和迟到证据均能处理；没有该版本时明确拒绝，不自动升级。

输入是严格 JSON 对象：必填字符串 `value`，可选整数 `quantity`（0–1000000，默认 1）。未知字段、重复字段、非法 UTF-8 和非整数拒绝。编码按 `quantity`、`value` 顺序输出紧凑 JSON。调用描述保存原输入 SHA-256 和编码后正文 SHA-256；出口在 P5 之前重新编码并比较。外部键由执行管理在原尝试创建时固定。凭据引用和账户进入描述摘要，密钥字节不得进入摘要。

参考协议显式携带原尝试和发送身份；成功证据还必须匹配 origin 和账户。GET 查询原动作必须独立准入，使用原查询主体。HTTP 202、5xx、工具错误、无效正文以及被遮蔽的响应均保持未知。429 只保存等待建议，不证明原动作未发生。类别限定为 `RATE`、`CONCURRENCY`、`RESOURCE_CONFLICT`；其他值保留 `UNKNOWN`。Retry-After 以一次观察结束时间计算，下限 1 秒、上限 24 小时；非法值使用 1 秒，超限按 24 小时。等待保存到原动作及执行工作，到期领取仍必须通过重发、P4、P5 的当前门禁。

受信网络实现直接使用单连接 HTTP 编解码器，无连接池、代理、重定向、自动重试或令牌刷新。HTTP 只允许显式 loopback IP；HTTPS 验证主机名和证书链。测试信任根只由测试宿主显式装配。秘密仅在受信 I/O 的局部内存解析及注入；回显秘密的正文或允许采集的头字段丢弃并标记遮蔽，使用固定安全原因码。

M1 的已支持凭据部署为 macOS 明确指定的 file-based Keychain。生产宿主只打开已有仓库，不自动创建、解锁或提示。SecItem 查询固定 generic-password 类、服务、账户以及显式 keychain search list；服务和账户包含完整目标绑定。进程初始化关闭可选 Keychain UI，不能在并发请求内切换。其他平台明确拒绝。测试只创建隔离 Keychain 和合成项目，清理自己创建的资源。`SecKeychainCreate` 和关闭交互的 API 已弃用，使用范围仅为该受控部署；以后迁移 data-protection Keychain 需要落实签名、entitlement 和 app bundle。

平台项目的访问控制必须允许部署的宿主可执行程序；Keychain 已解锁不代表其他程序有权读取项目。生产读取不修改访问控制，拒绝交互时如实失败。CLI 验证仅在自身隔离仓库中新建合成项目，使用 `SecTrustedApplicationCreateFromPath` 和 `SecAccessCreate` 为测试创建者及指定已构建 CLI 设置精确允许列表，不使用“所有应用”访问列表，也不修改默认用户仓库。

[Apple TN3137](https://developer.apple.com/documentation/technotes/tn3137-on-mac-keychains) 说明 SecItem 默认使用 file-based Keychain；data-protection Keychain 的访问组需要签名授权。macOS 26.4 以后 Keychain 文件可能依赖文件外的保护熵。因此数据库恢复不宣称备份平台凭据，恢复必须仍可访问原平台仓库。不得修改系统保护来复制这些文件。

## 后果

原账户、origin、端点和版本保持稳定；密钥轮换可以替换同一精确平台项目中的字节，不能改绑账户。缺失、锁定或无权访问凭据时没有目标请求，P5 已开放的责任仍按未知保留。M1 不支持 OAuth、动态目录、任意头字段或任意 URL。

## 验证记录

2026-10-06，在 macOS 27.0.1 arm64、Go 1.27.1、CGO=1 上，正式基线 `6d5d043` 的完整实现通过原样 `make check`（`GOFLAGS=-v`、`BUF_BASE=6d5d043`），总计 6056.199 秒。完整已测试树为 `23a68d948d90d4a045efc1b8519c2aaf8409383b`；运行前后全部 697 个文件的内容与权限一致，验收元数据单独追加。原生 API 的 42 个来源故障组合、144 个限流唤醒组合、15 个参数来源组合及共享执行适配器一致性测试全部通过。

实际 CLI、默认 MODEL 与原生 API 的成功场景得到两次模型调用、一次 POST、一个目标业务记录和三笔账单，任务 SUCCEEDED、已结算 21、预留 0。FAILED 和 CANCELLED 场景各以一次模型调用产生真正 UNKNOWN 的 POST；关闭后先接收原账单，再释放外部业务队列，最后以独立 GET 恢复原查询计划。当前账务由 7/30 经 14/0 到 16/0，已固定 Result 和原模型责任保持不变。验证使用隔离 Keychain、合成凭据与参考协议服务；以上结论不扩大到任意供应商或其他平台凭据部署。
