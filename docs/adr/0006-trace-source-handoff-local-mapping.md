## 决定

基础关联的来源是事实负责方在原业务事务中保存的声明。各负责方必须实现自己的来源持久接口；源序号、结构白名单与业务写入一起提交。共用 SQLite helper 不改变归属：`source_trace_outbox`、`source_trace_streams` 按用户和负责方分区，写入必须持有对应的裁决域、执行管理域或内容域事务。不得从当前业务行回填历史事件，也不得在源事务内写运行记录域。

运行记录只接纳与源方保存的完整原命令一致的事件。核心生产者标签、对象引用或成功文本本身不构成来源证明。接纳事务独立保存结构事件和命令回执；源方随后在自己的独立事务保存原接纳回执。三个持久点之间均可中断，重启查询并继续原身份。同键不同载荷冲突，同键同载荷返回原回执。接纳不修改效果、费用、任务或 Result。

索引是接纳后的独立、可重复投影。查询默认仅用于 `DIAGNOSTIC`，M1 拒绝其他处理目的。完整性限定于返回的已知来源集合和截止向量：源提交水位、连续接纳水位、连续索引水位、未接纳积压、源方未保存回执数及缺段分别显示。调用方可固定已经报告过的截止水位；超过已知源提交上限的截止值拒绝，未知来源明确显示未知。缺少索引或接纳不得推导动作没有发生。查询不声称将来的事件已完整。

M1 的来源结构版本为 1，生产者实现语义版本为 `lerna-m1-source-v1`，本地诊断映射为 `lerna.m1.local.v1`。白名单包括用户与对象身份、版本、来源流与序号、受控事件类型／原因码、业务引用、原命令和内容引用。路径、目标地址、外部请求标识、正文、传输错误、属性字典和追踪头不进入来源队列或诊断存储。内容仍由内容治理控制；引用不是读取正文的授权。

本地投影保留 Lerna 事件语义，业务引用构成 Links 的映射边界。M1 不安装 OTel SDK，不声明未使用的标准 Schema URL，不启用 OTLP 或正文副本。以后接入外部投影时单独锁定标准版本、授权和出口路径；投影状态不得代替基础关联接纳。

## 后果

每项必要事实增加源方写入与跨域交接开销。诊断采集暂停时，源方责任保留，查询显示积压；恢复和重投不产生新的业务责任。基础关联全量，诊断细节可以省略，两者的完整性不得混淆。删除传播、外部导出和评测复用仍留在后续里程碑。
