# 0005 M1 计费来源与结算

| 日期 | 修订说明 |
| --- | --- |
| 2026-10-05 | 固定参考计费来源、不可变预算版本与结算证据。 |

- 状态：已采纳
- 影响：[预算](../architecture/core/budget/README.md)、G3、G10、G12。

## 决定

每次物理发送之前生成的 Send 名称是内部计费来源，引用版本保存当时的发送事实；供应商命名空间、账户、原生实例和费用项目组成外部别名。别名必须由受信出口的原始观察，或受信宿主导入的账单证据，绑定到已存在的 Send。核心检查原用户、任务、尝试、出口、计价依据和请求键；别名不得改绑。

参考计费规则 `reference-billing-v1` 只接受 USD_MICRO 整数、明确版本和明确的费用终结声明。没有终结声明时保留预留，不根据效果、HTTP 状态、取消或关闭猜测零费用。M1 接纳未知转为首次已知的迟到账单；相同来源版本的矛盾金额或别名冲突保存为待核对事实，不接纳新金额，并阻塞新准入；接纳冲突证据不表示接受其费用主张。不同版本的已知金额更正、退款和贷记明确返回不支持，完整版本差额留到 M2。同来源同版本同金额的重复投递不再记账。

预算、预留和结算事实在裁决域由预算唯一写入。预算版本永久保存；限额调整不删除原预留。用户与任务的投影是包含关系，一次费用只产生一条分录。真实费用超过上界仍接纳，展示缺口与上界失效并阻止新准入；显式增额不能恢复失效上界的可信性。M1 保留阻塞，不自动修复供应商计费约束。金额计算使用有溢出检查的整数。

可信的原执行管理封闭证明可释放从未发送的预留；不得伪造零用量回报，不返还授权次数或已消费发送次数。已进入 P5 的来源必须另有费用终结证据。

## 后果

即时回报在原 P7 接收事务中记账，并保留原回执。迟到导入通过同一预算裁决接口，原证据留在内容模块。历史回报和预算引用不变；查询当前投影与历史事实分开。M1 不支持多币种、聚合账单自动匹配、更正、贷记或退款。

## 后续重发边界

效果幂等不表示费用幂等。安全重发继续使用原 Attempt 和请求键，但新的物理 Send 必须拥有新的内部计费来源及足够的费用容量。M1 当前只准入一次发送；P4 检查已消费次数并创建该 Send 的来源，不允许借用原已结算来源免费再发。扩大次数上限时，必须同时扩展预留与来源绑定，不能只改 MaxSends，也不能用模型调用位置上限代替物理发送上限。
