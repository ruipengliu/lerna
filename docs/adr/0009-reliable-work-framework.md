# 共用接纳与有界工作模板，统一逻辑作业存储

多个领域都要处理原命令去重、领取接替和新增责任与旧完成竞争，但外部发送边界、业务成功和安全重试条件不同。2026-09-28 设计访谈确认：参考宿主提供可装配的接纳与有界工作模板，并统一逻辑 JobStore 契约；各模块保留业务裁决、多阶段短事务、外部效果核对及自己的本地事务范围和物理表布局，见[详细设计](../architecture/reliable-work.md)。

相比仅共享原语或算法，模板与存储契约减少各模块重复实现故障分支，代价是宿主要维护领域接口、存储适配及共用故障套件。将这些规则全部留给模块会降低公共接口约束，却需要每个模块独立证明相同并发保证；若多数模块最终必须绕过工作模板，应收缩模板，而不是增设通用业务状态机。框架不新增调度服务，不强制同库或同池，也不改变第三方协议的替换边界。

2026-10-02 实现范围确认：先交付内部公共库、真实 PostgreSQL/SQLite 适配及故障套件；默认开发宿主保持诊断装配，领域处理器与可信宿主门禁随切片接入。[实现与证据](../../.scratch/reliable-work/evidence.md)按此范围报告，不改变本决策的领域归属和公开替换边界。
