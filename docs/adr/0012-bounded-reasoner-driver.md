# 0012 由任务编排持有有限推理推进责任

| 日期 | 修订说明 |
| --- | --- |
| 2026-10-06 | 初版：配置、领取、实际动作和恢复共用任务编排的有限推进入口。 |

- 状态：已采纳
- 影响：[任务编排](../architecture/core/tasks/README.md)、[默认推理](../architecture/ports/reasoner/default.md)、[开发规范](../development.md)

## 背景

单次受信推理入口可以重放原模型结果，但只有它还不能消费已保存的 PROPOSE 待办。M1 需要从固定配置推进真实任务，并在重启后接续已经承接的责任。

## 决定

任务编排保存每个任务的 `ReasonerDriver`。受信宿主显式配置固定模型设置、模型能力和既有授权，以及可以执行的能力与既有授权映射。配置不是签发授权；所有准入、确认、预算、内容、控制与出口门禁仍由原负责方裁决。配置变更必须提供当前 driver 引用，历史版本保留。普通调用方不得配置或推进；未配置返回 `WAITING / CONFIGURATION_REQUIRED`，不领取或调用模型。

`AdvanceReasonerTask` 每次最多推进 8 个阶段（显式上限 16），没有后台循环。宿主启动仅恢复已保存且启用的 driver，使用同一个入口。读取 driver、任务或提议本身不建立新的责任。装配层只提供默认推理实现及原持久工作、执行管理和出口接口，决策归任务编排。

推进首先消费任务已有的原请求；没有请求才为这份显式责任建立一次初始请求。PROPOSE 必须通过持久工作的真实 CLAIM 获得，当前租约未到期时等待，不复用别的进程领取。请求和位置 0 已有回报时直接接续原回报；模型 UNKNOWN、拒绝、截断或非法输出均等待，不建立替代请求、调用位置或物理发送。

ACTION 必须匹配固定能力授权映射，经过原 Admit、R7 交接、执行工作 CLAIM、Prepare、凭证和出口开始门禁。恢复通过原提议找到原准入，原 P4/P5 保持不变。只有原执行为 SETTLED、已知效果为 APPLIED 或 NOT_APPLIED、LateEffect 为 RULED_OUT、没有证据冲突、原报告已交付，且现有 BlocksAdmission 不阻塞时，任务编排才按原动作与效果的固定命令身份建立下一唯一请求。未发送、发送后未知、待核对或事实不可用时等待；不得把继续思考当进展。下一请求的前置事实在同一裁决事务重查；事实尚未满足时只保存原 driver 的等待，不把下一请求身份固化为永久拒绝。下一请求重新构造真实快照，默认推理仍只进行单步计算。

QUESTION 和 REQUIREMENTS 只发布原治理内容并等待用户；无会话时明确等待。COMPLETE 进入原完成门禁；原 Result 才表示完成。外部已失效的请求不得被 driver 重新激活。已接受的新输入、需求或控制事实改变当前依据时，先接续任务编排已有且绑定当前依据的新请求；不存在时，由任务编排以该依据的固定命令身份建立唯一请求。创建前在同一事务核验当前 driver、任务依据与全部执行阻塞。只有规划代次变化不足以触发继续；旧 UNKNOWN 或尚未回报的模型责任不能因此创建新请求。

COMPLETE 的可靠否定证据与可靠满足证据都作为候选交给原完成门禁；模型的结论本身不裁决条件。当前核验拒绝后，driver 只接续该原核验保存的 `ContinuationRequestRef` 及其准确快照。原完成核验递增控制代次不构成用户接受新依据；原阻断事实不可用、继续请求尚未登记时等待原负责方恢复，不用普通依据变化入口产生替代请求。原负责方恢复后仍只产生一次准确关联的继续责任，新动作重新取得当前授权与确认。

原 P4 已存在、P5 尚未成立的入口可以被原完成封闭协议准确禁止发送。执行管理保存的原完成 seal 必须证明该准入、操作、端点及全部发送引用均已关闭且不曾可能发送，效果为 NOT_APPLIED、LateEffect 为 RULED_OUT；此时没有目标观察或费用回报是准确事实，不能为继续规划伪造观察，也不能将缺失观察的合法未发送封闭当作读取失败。没有这份原证明、未知效果或任何可能发送历史仍须等待。

取消被原控制事务接纳后，有限推进与宿主启动恢复都必须按当前 `CANCELLING` 等待，不新增模型调用、调用位置、准入、下一请求或目标发送。已经保存的模型调用、封存输入、提议回报和原动作准入继续沿原身份查询；取消范围包含这些原模型和目标准入。模型已实际调用时保留其原发送与费用，不能把端点封闭解释成模型未调用。尚未交接到执行管理的原目标准入可以先取得永久未发送封闭标记，原交接晚到后只产生原身份的禁止执行记录。控制回执、端点封闭 ACK 与最终 Result 分别展示；driver 不从取消 ACK 推导最终 `CANCELLED`。

可信当前关闭命令独立绑定当前任务修订、输入、要求和全部历史准入。准确原取消 ACK、关闭 ACK 和实际原交接到齐后，原关闭协议才固定 CANCELLED Result。driver 读取这个原 Result 后结束推进；原模型输入、调用位置、回报、已发送费用以及未发送动作的原封闭与预留释放均保持原身份。重启或重放不替换 Result，也不再次调用供应商或目标。

## 恢复与记录

driver 固定推理契约版本与实现版本；恢复在任何业务调用前核验全部已保存 driver 的版本，无法理解时停止。问题发布后保存原 `QuestionRef`，界面据此回答，不从文字猜测关联。配置、当前位置与等待原因各有版本，来源与任务编排保存事务一致。决定动作的命令身份由原 driver、请求、提议、准入或效果固定；并发或崩溃后的重入返回原决定。领取身份包含真实进程实例，过期后重新领取仍使用原请求与调用位置。等待授权、确认或预算时保留原责任，显式修复配置后继续经过当前门禁。不得自动签发 grant、确认批准、重发未知动作或隐藏 fallback。

新增记录及版本表纳入数据库格式检查与静止迁移边界。旧库是否支持由兼容门禁决定；不得为了启动 driver 删除原 P5、未知效果、费用或历史正文治理事实。

## 验证

公共测试边界为生产编译 CLI、同装配的 Harness/Tasks 公共配置和查询、独立真实目标计数。覆盖 READY PROPOSE 自动领取、原位置跨进程重放一次调用一次费用、实际动作后唯一下一请求、无配置与无权限零调用、UNKNOWN 不重发，以及当前授权和预算门禁。手动构造 CLAIM/run 命令的已有测试保留，但不代替生产自动推进证据。

完整否定及补建场景由默认 MODEL 真实产生 UNSAT 候选。另一个最小消费者竞争场景用公开完成生产者和真实原 P4 制造跨域开始回执读取失败；driver 已经持有该完成提议的原请求后再开始核验。该场景只验证原核验恢复与 driver 的请求接续次序，不声称手工提议具有 MODEL 调用或回报。

配置、下一请求决定和 driver 位置更新分别验证真实提交边界。下一请求已提交而 driver 仍指向原请求时，恢复必须重放该原决定并采用它保存的唯一请求，不能因规划代次已经变化建立替代请求。故障测试先通过公开负责方查询证明已提交的配置、请求、快照与 driver 位置，再启动恢复；提交前退出、提交后退出和回执丢失分别按真实提交事实判断，不用故障命中序号代替语义证明。

取消联合验证使用真实生产 CLI 配置与推进，并用公开 `AdvanceReasonerTask(limit=1)` 固定实际模型回报及 driver 已保存的原 `AdmissionRef`，在原目标 I/O 前提交真实 CANCEL。独立供应商账单、目标请求和效果计数，以及原控制／模型输入／回报／准入／端点证明／预算释放事实共同证明重放和重启没有新增调用。模型调用前取消另行验证所有调用、账单与目标计数均为零；最终非成功 Result 仍由独立关闭协议验收。
