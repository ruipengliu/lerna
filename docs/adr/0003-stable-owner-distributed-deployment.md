# ADR-0003：固定逻辑 owner，独立伸缩进程和 worker

命令去重、并发控制与完成判断需要可定位的权威，但服务进程必须能够故障接替。因此，Task 固定归属一个逻辑 Orchestrator owner；发现和负载均衡可以更换该 owner 的健康进程，不能在原请求未知时改投另一任务数据库。

生产首版按分布式方式装配，开发允许单进程或本机多进程。默认云端保存 Task 权威，设备保存本机执行、有限授权窗口和补传责任。设备若需独立承担目标，必须部署独立 Orchestrator 和自有 Task；网络断开不能触发对云端原 Task 的自动接管。

跨 owner 交接由发送方先保存原意图与投递责任，接收方独立保存接纳事实，再由发送方保存回执。丢回执时查询或重传原命令，不假设跨库原子提交。Operation 和 Delegation 必须在派发前登记 Task 侧责任，避免远端尚未接纳时被完成检查漏掉。

**取舍与代价。** 不把业务身份绑定到进程，也不允许调用方随意迁移权威。需要受信目录、owner 路由、分片容量管理和可恢复交接；某 owner 不可用时，原工作可能等待。扩容优先为新任务选择新 owner，或增加原 owner 的服务副本。

**重新评估条件。** 实测热点确需迁移时，另行设计保留原身份、停写、复制、旧写端隔离及映射代次切换的协议。第一版不提供自动在线跨分片任务迁移，重新创建 Task 不能代替迁移。
