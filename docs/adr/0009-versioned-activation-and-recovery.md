# ADR-0009：固定在途版本，分别管理安装、批准与就绪

插件升级可能改变参数、效果或数据格式，旧任务却仍需核对原行动。因此，InstallLock 固定制品与依赖，ReleaseApproval 保存有限范围的发布批准，InstanceReadiness 保存准确实例的当前就绪；安装、批准与可服务资格分别成立。Task 固定组件与策略清单，已准入 Decision 和 Operation 固定准确 Binding。

普通升级只改变新任务默认选择的 BindingHead，不自动停用旧 Activation。原 Task 可以在旧批准、就绪与 holder 有效时继续下一轮调用，且仍逐次准入；显式 deactivate 则封闭该 Activation 的所有新调用。已开始操作的查询和结算由可信旧实现或经过合同验证的接管器承担，无合格实现时保留等待与限制。

激活和回退必须比较稳定部署目标的 revision 与 generation；重启建立新实例身份并重新自检。迁移需要兼容声明、原责任 checkpoint、迁移记录及失败恢复路径。回退是一次新的激活，需要旧版独立有效批准及格式兼容，不能倒退已发生效果、撤权和费用。

**取舍与代价。** 不用“最新同名组件”解释旧记录，也不以 Go 热卸载为可靠性基础。默认内核和受信组件静态构建，第三方代码运行于受控进程、沙箱或远程服务。维护者需保留旧查询能力、holder、兼容数据和回退窗口；供应商内部模型版本不可固定时必须说明可重复性限制。

**重新评估条件。** 只有显式兼容与恢复证据才能允许迁移或回收旧版本。安全停用不能继续运行已知不可信代码，旧版批准过期或兼容性不满足时也不能自动回退；缺少路径时保留未结责任。

**依据。** [版本发布不改变在途工作的含义](../architecture/decisions.md#版本发布不改变在途工作的含义)、[插件从安装到可服务](../architecture/governance.md#插件从安装到可服务)、[在途版本升级与回退](../architecture/governance.md#在途版本升级与回退)。
