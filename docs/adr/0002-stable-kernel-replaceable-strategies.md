# ADR-0002：稳定任务语义，由可替换策略提出建议

更换推理、检索或协作算法不能改变目标、取消、权限和完成的含义。因此，Orchestrator 负责目标、提案采纳、行动准入和完成裁决；决策引擎只提出 Proposal，Executor 保存实际效果，Evaluator 提供逐条件判断。策略通过能力合同替换，不能直接改写其他负责方的权威事实。

默认使用单任务控制者组织有界 ReAct 循环，并保留规则决策作为确定性基线。每个 Decision 固定 Snapshot、策略、组件与限额，至多一次物理模型请求；多步决策必须有各自身份和预算。目标或控制修订过期的提案不得产生行动，已经发生的费用和效果照常保留。

成功必须基于覆盖原始要求的条件集合：全部必要条件具有当前有效判断，相关操作效果确定且不会迟到改变成果，子目标和委托按合同关闭。Orchestrator 在同一事务检查完整未结责任并固定 Result。模型最终文本、远端完成和条件平均分都不能替代这一步。

**取舍与代价。** 不让一个通用工具循环同时拥有提案、执行和完成裁决。代价是维护目标版本、结构化提案、责任登记与完成门禁；收益是应用控制语义不随算法替换变化。多 Agent、复杂检索与递归推理保持可选，以实验决定是否启用。

**重新评估条件。** 简单应用被迫理解大量内部状态时压缩应用接口；某扩展只有一种实现且没有真实替换需求时保留内部接口。能力可替换性必须由第二种实现验证，不能只靠默认实现自测。
