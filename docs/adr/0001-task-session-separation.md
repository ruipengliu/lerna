# ADR-0001：Task 与 Session 分离，终态与收尾分离

用户关闭界面后，目标仍可能需要推进，已发送的操作也可能继续生效。因此，Session 只组织输入与呈现，Task 保存目标与持续推进责任；Task 的终态与效果、费用、清理的关闭情况分别记录。应用无需维持一条永不结束的聊天请求来托管任务。

一段 Session 可以关联多个 Task。`succeeded`、`failed`、`cancelled` 均不可复活，并在终结时固定 Result；终态后的新增工作建立关联的新 Task。暂停或取消在 Orchestrator 控制事务提交时封闭新行动准入，同时保存传播与收尾责任；这不能证明远端已经停止。

**取舍与代价。** 不采用“回合结束即任务结束”或一个通用 done 状态。SDK 和界面必须区分输入已保存、目标已接纳、正式结果与未结责任；失败或取消后仍可能有费用更正和效果核对。一次性无副作用问答可以提供更窄的应用封装，保留底层含义。

**重新评估条件。** 若简单应用的接入负担过重，收缩应用接口；不能通过把界面状态当作业务状态来抹去已接纳责任。

**依据。** [目标与对话分离](../architecture/decisions.md#目标与对话分离)、[控制状态与恢复](../architecture/task-lifecycle.md#控制状态与恢复)、[应用接入方法](../architecture/contracts.md#应用接入方法)。效果关闭的含义见 [ADR-0005](0005-explicit-effect-uncertainty.md)。
