# 新任务由受信发现选定负责方，原命令固定目标

同一租户可以为新任务启用多个 Orchestrator，但命令去重范围包含逻辑服务。受信装配和发现从版本化映射选定目标，调用方在首次发送前持久保存原命令与该目标；网关校验连接、命令和目标一致，只解析健康进程。映射换版、网关更换和重试仍回原 Orchestrator。若调用方丢失原记录且受信目录无法定位，结果保持未知，不能把相同意图改投另一数据库分片。

没有采用网关在 `task.submit` 时首次选择数据库分片：现有 WSS 在业务帧之前已绑定逻辑服务，改选须增加服务端逐命令预绑定及新的发现／连接契约。当前选择把未结命令的耐久保存责任交给调用方和受信宿主，避免每次提交都依赖另一项跨分片写入；其代价是客户端本地记录完全丢失时不能保证自动找回未决提交。用户任务列表依赖在开放新任务归属前预登记的来源目录，但该目录不裁决 Task。
