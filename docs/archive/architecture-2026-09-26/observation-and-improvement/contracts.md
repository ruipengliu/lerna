# 契约与持久记录

[总览](README.md) · [观测](observation.md) · [评测](evaluation.md) · [改进](improvement.md) · [验证](validation.md)

本页是本模块逻辑契约的权威字段位置；评测接口尚无 SDK，发布交接的 JSON Schema 见扩展模块 [release 线合同](../extensions-and-runtime/contracts.md#wire)，运行实现未交付。复用接口仍以原模块为准；下文评测接口的版本 1 表示本地逻辑契约；跨端发布采用已注册的 `harness.release.*@1`。未识别的契约版本、动作和判分规则在接纳前拒绝。

<a id="handoffs"></a>
## 1. 直接交接

| 发起方 → 处理方 | 输入 → 输出与成功依据 | 持久责任和失败后继续者 |
| --- | --- | --- |
| 领域宿主 → 运行观测 | 获准提交后记录 → buffered／dropped／rejected；仅确认有限缓冲 | 领域继续保存正确性记录。观测负责有界导出，不请求业务重做；缺少采集适配只显示覆盖缺口 |
| 受信入口／改进管理器 → 评测执行器 | 固定计划、版本与预算 → accepted 及 run_id／拒绝 | 执行器提交计划、样本及后续责任；调用者超时查原命令，不新建 run |
| 执行器 → 环境适配器 | 原环境键、隔离规格与样本绑定 → 固定环境回执 | 适配器保存实例和关闭责任；执行器超时查原键，缺可查询／封闭能力拒绝计划 |
| 执行器 → 隔离任务核心 | 现有 Submit／ReadTask／ReadResult／ReadOperation／ApplyInput／Cancel → 接纳、正式状态与结果 | 核心保存任务事实；执行器保存外部调用键和样本关联，失败查原任务，不能自己写完成状态 |
| 执行器 → 效果判定器 | 固定评分请求、成果及证据 → 判定回执 | 判定器保存逐条件评分及规则绑定；执行器查原请求，冲突使报告不可用。必要取证由指定适配器承担 |
| 受信管理入口 → 改进侧 → 扩展管理器 | 精确批准、有限批次及原管理命令 → 逐目标管理回执 | 改进侧保存自动交接／核对责任；扩展保存批准绑定、激活及撤回门禁事实，不凭评测 pass 自行签发批准 |
| 各处理端 → 身份／来源权威 | 当前 UseIntent、使用键与完整来源 → 许可／拒绝／依据缺口 | 处理端落实用途与保留约束；BeginUse 未知查原键，无法确认不继续处理 |

已存在的核心接口不提供全部历史截图、完整执行轨迹或成本。因此首期独立测试环境及受信本地采集适配器必须提供评分所需事实；缺该适配不能把 ReadTask 的摘要当完整证据。生产全量分析及跨端私有数据导入分别受[依赖表](validation.md#dependencies)限制。

<a id="observation"></a>
## 2. ObservationRecord 与来源

| 字段组 | 约束 |
| --- | --- |
| `record_id`、`schema_version`、`producer_ref` | 生产者内唯一记录键、已安装版本及受信生产者；不接受客户端自报身份作为认证 |
| `scope`、`source_ref`、`source_revision` | scope 由宿主绑定用户／维护范围；来源权威、账本代次及修订可查。纯计时诊断可无领域修订，但标 diagnostic，不宣称事实已提交 |
| `correlations` | 获准 task、operation、work、decision、model_call、message、grant/use、endpoint/owner、run/case 关联；不存在的关联不能靠文本推断 |
| `trace_id`、`span_id`、`links` | 可选诊断上下文；按适配器格式验证，不能决定访问权限或幂等 |
| `kind`、`phase`、`outcome` | 安装目录内的有限枚举，区分送达、接纳、执行、核验和正式结果，不用单个 success 合并 |
| `observed_at`、`duration`、`clock_ref` | 时间、适用单位及测量时钟；跨时钟不能直接相减 |
| `source_bindings`、`use_basis_ref`、`retain_until` | 完整获准来源及本次使用依据、保留截止；引用与摘要同样受控 |
| `sampling_policy_ref`、`coverage`、`attributes` | 策略版本、完整／采样／缺口声明和有限允许字段；默认无正文、凭据及任意高基数标签 |

ContentBinding 统一固定受控内容引用、原始字节摘要、版本、生产者、来源闭包和保留条件；摘要复用扩展模块的 SHA-256 表示，不自定义内容相等规则。摘要匹配只能证明引用字节相同，不能证明来源可信、内容正确或当前获准。

<a id="plan"></a>
## 3. Dataset 与 EvaluationPlan

Dataset 是不可变样本清单，包含数据集 ID／版本／摘要、用途／来源、开发／验证／保留分组、枚举样本及每例输入／目标／预期资源／判据引用、业务 API 去重身份、任务类别与抽样权重。输入与保留答案分别保存，读取权限独立。每个样本的前置条件由受信适配器判定，不让候选选择是否进入分母。

| EvaluationPlan 字段组 | 接纳时必须固定的内容 |
| --- | --- |
| `plan_id`、`version`、`digest`、`contract_version` | 规范保存的不可变计划与摘要；变更新建版本，不能覆盖已运行计划 |
| `scope`、`goal_refs`、`dataset_ref` | 用户／维护作用域、C／A／V 目标、数据集精确版本及冻结样本列表 |
| `baseline`、`candidate` | 制品、描述文件、依赖锁、Skill／策略／模型配置及能力／驱动精确版本；没有候选时为单版本验收，不产出改善结论 |
| `environment_profile`、`isolation_profile` | 宿主／平台、模拟器／外部测试租户、镜像与初始快照、资源边界、取证和封闭能力；包括可比性预检规则 |
| `judge_profile`、`measurement_rules` | 已安装判定器、规则／量表、真值来源、语义模型配置、人工复核方法、计数与缺失处理、测量起止定义 |
| `comparison_policy` | 主要指标、改善方向和最小改善量、分层守护指标／退化界限、必需契约、最少样本和是否推断总体；统计方法、置信水平及发布适用条件 |
| `schedule` | 全部配对／重复种子、固定顺序生成方法、预检失败处理、热身与正式运行分离；受信输入脚本的触发、允许值、输入／取消／接管身份与期限。不可运行中择优提前停止或临场补答案 |
| `limits` | 每例／每 run 的期限、费用、模型调用、工具调用、业务重试组及其尝试、判分、查询及重投上限；收尾独立预留且仍有限 |
| `data_policy`、`authorization_refs` | 处理／保存／披露／来源约束、真实主体和接收方、保留期限；只固定要求，不冻结许可有效性 |
| `approval_policy_ref` | 可提交发布审查的规则版本；缺席只输出诊断报告，不能自动获得批准 |

<a id="environment"></a>
## 4. Environment 与评分记录

下列适配器归评测执行器内部，不能被候选直接调用。环境键为 `(scope, run_id, case_id, variant, repetition)`；同键始终指同一环境代次，不能超时后重分配以隐藏旧动作。

| 接口 | 输入 → 输出与原子责任 |
| --- | --- |
| `Environment.Prepare`／`Query` | 固定环境键、profile、初始快照 → 创建中／ready／rejected／quarantined 及实例关联；Prepare 先存创建责任，Query 沿原实例核对。ready 须包含当前隔离和真值读取依据 |
| `Environment.Observe` | 原环境代次、精确对象、观察规则及当前许可 → ContentBinding 与状态版本／缺口；只读路径不接受候选提交真值 |
| `Environment.Close`／`QueryClose` | 原关闭键、环境及任务关联 → 关闭责任／关闭证据；只有禁止旧写入、隔离在途执行且受管副本清理条件满足才可确认可销毁。外部效果另查原领域，关闭进程不证明外部无效果 |
| `Judge.Score`／`Query` | 原评分键、固定规则、成果及证据清单 → accepted／拒绝及 ScoreRecord；有成本取证先持久登记子操作，纯本地有界判定可同步提交 |

ScoreRecord 以 `(scope, run_id, case_id, variant, repetition, criterion_id, scoring_revision)` 唯一标识，保存原评分命令、规则与判定器版本、目标／成果／环境绑定、证据切点和引用、`pass/fail/unknown`、原因、保证类别及用量。人工补证生成新 scoring_revision 并引用旧记录；旧评分不覆盖。样本还保存独立 `contract_outcome` 和 `effect_outcome`，组内合并规则以[判分顺序](evaluation.md)为准。

评分请求先固定所有有成本子调用的身份再派发，同键重入只读取原结果或查原调用。格式无效也不允许在同一子调用键内重发模型请求；计划允许的修复／复判分别分配新尝试身份并计入总预算，保留旧失败。原调用结果未知时先核对，不另开付费副本；本地确定性函数重算仍须相同输入、版本及无副作用。

Report 固定 report_id／revision／摘要、计划及各评分引用、证据截止、冻结分母和各结果计数、分层指标／不确定性／配对四格、已知及未知费用、`pass/fail/inconclusive` 比较结论、限制和未决收尾引用。报告正文不可变；`usable/restricted/withdrawn` 适用性及其原因、来源关闭修订另存，读取和发布前检查当前值。run 的 `settlement_pending` 独立更新，不靠修改历史报告结算。

<a id="release"></a>
## 5. Candidate、ReleaseDecision 与 Rollout

| 记录 | 权威字段与限制 |
| --- | --- |
| Candidate | candidate_id、不可变摘要、种类、父版本、完整来源、生成任务／预算、预期改善、计划／报告及审查记录引用；进展由关联记录得出，不另保存可与报告或批准矛盾的总成功态，生成者不决定批准 |
| ReleaseDecision | 受信批准身份／权限依据、原决定键及修订、精确产物与描述摘要／配置、当前可用评测报告、用途／用户／端点／部署范围、批次和期限、预期替换绑定、监测要求及回退声明；声明明确支持的旧版本／依赖锁、适用数据格式、范围与窗口、验证依据和受阻处置，或明确不保证旧版恢复。决定为 approved／rejected，后续撤回另记修订；另固定独立 approval_id、真实批准权威、允许新激活的截止、活动版本新鲜度／离线使用上限及当前证明，不通过刷新旧事件延长资格 |
| Rollout | rollout_id、批准引用、有限批次与目标、每目标原管理命令／处置意图、预期及实际绑定、管理回执、监测窗口和样本、状态／blocker／暂停前阶段、停推及回退责任；停用结果与旧版恢复结果分别保存回执或缺口，目标未确认时保留 unknown，不用 stopped 等批次状态覆盖 |

这些记录保存改进侧审查、批准和持续跟踪；批准事件由真实权威提供且单调应用，不能自增范围或充当新批准。扩展侧安装、排空、激活与回退沿 [ActivationBasis 及管理命令](../extensions-and-runtime/contracts.md#approval)，自动化复用现有信任根。

<a id="interfaces"></a>
## 6. 本地管理接口与错误

除观测缓冲写入外，所有变更携带受信 RequestContext、作用域内唯一 `command_id`、完整规范意图、预期修订及绝对截止；同键同意图查询／重投返回原决定，同键异意图拒绝。派生子步骤在父账本固定键后调用。已接纳责任不因请求超时消失，新的主动动作仍受原截止与当前权限约束。

| 接口 | 输入 → 输出与成功含义 |
| --- | --- |
| `Evaluation.Start` | 精确计划 → accepted/run_id 或拒绝；计划、样本、额度预留与工作一次提交 |
| `Evaluation.Read`／`ReadCommand` | 原 run／命令 → 当前进度、报告引用和收尾缺口；无权／不存在采用不泄露存在性的拒绝 |
| `Evaluation.Cancel` | 原 run、预期修订 → 控制接纳；封闭新派发并保存已有任务处置责任，不保证外部停止 |
| `Evaluation.ReadReport` | 精确报告修订、用途和接收方 → 当前获准内容及适用性；缺证据或撤回不可投影为完整可发布报告 |
| `Improvement.Propose` | 固定产物和来源 → 候选回执；只接纳候选，不启用 |
| `Improvement.RecordDecision`／`WithdrawDecision` | 受信维护入口的批准／拒绝／撤回及预期修订 → 持久决定；普通模型主体拒绝 |
| `Improvement.PlanBatch`／`ReadRollout` | 批次及批准范围／原 rollout → 待交接计划／当前真实分项进度；在批准范围内自动交给扩展，扩批仍需人工决定 |
| `Management.AttachReceipt` | 原环境／任务／评分／管理键及可验证提供方回执 → 采纳／冲突；不接受自由文本覆盖事实 |
| `Management.ContinueReconciliation` | 原责任、有限新核对预算与当前许可 → 已安排原键核对；新预算不授权重做目标动作 |
| `Data.Close`／`ReadCleanup` | 本模块数据作用域、当前管理权限与预期修订 → 停用提交及分项清理进度；区分停止使用、载体清理和已披露 |

`ReadCommand=not_found` 的安全投影不证明原请求永远不会到达；依原截止关闭派发并核对，不换键重做。入口先验证请求尚未过期及数据／命令代次仍开放，再创建去重行，防止墓碑过期后旧命令重生。

| 本地错误／阻塞原因 | 调用方允许的下一步 |
| --- | --- |
| `invalid_contract`／`intent_conflict` | 修正版本或意图；若为不同意图须新计划／命令，原责任仍独立查询 |
| `not_authorized`／`source_restricted` | 停止该用途；通过受信入口取得适用许可或以新获准数据重建，不用后台身份绕过 |
| `dependency_missing`／`isolation_unavailable` | 接纳前拒绝；补实现并验证后新请求，运行后出现则保存 blocker 并有界关闭 |
| `quota_exceeded` | 未接纳则按 retry_after 等待；已接纳工作保留收尾配额，不删除失败样本腾空间 |
| `revision_conflict` | 读取当前状态，重新作出显式决定；禁止覆盖并发撤回 |
| `evidence_gap`／`recovery_gap` | 报告缺口，查询原事实或补证；不能合成成功或解除未知副作用 |
| `commit_unknown` | 沿原命令查询／同键恢复，是调用结果，不是未接纳的持久事实 |

<a id="storage"></a>
## 7. 原子边界、恢复与保留

控制记录复用宿主事务数据库，单机／云端沿[扩展存储方案](../extensions-and-runtime/contracts.md)装配；大证据使用按用户隔离的受控内容存储。网络、模型、任务执行和评分计算在事务外，提交前校验版本及领取资格。内容先耐久保存并校验摘要，按[共同交接](../content-and-provenance.md#publication)取得覆盖所需恢复期的有限保留依据，再提交领域引用与本模块责任。无领域引用的对象按已确认的有限保留期收敛；已引用内容不可提前作为孤立对象删除，来源关闭及强制到期仍按当前数据策略处理。

| 原子提交 | 同时保存 | 提交后动作 |
| --- | --- | --- |
| 接纳评测 | 命令决定、计划、全部样本键、预算预留、派发工作 | 准备环境、Submit |
| 样本派发 | 环境／任务／原操作键、固定截止、领取代次和派发资格 | 外部调用；提交未知先读本地原行 |
| 采纳证据／评分／候选 | 当前全部本地来源开放检查、完整依赖登记、唯一来源与修订、ContentBinding、结果记录、聚合／收尾工作 | 生成报告、查询或通知；关闭先提交的迟到正文不可用并安排清理 |
| 报告生成／本地发布决定 | 来源与报告当前可用性检查、固定报告／批准及完整依赖、run 进度、必要通知责任 | 按权披露或交接受信入口；不等待全部未知费用清零 |
| 取消／数据关闭／批准撤回 | 控制修订、禁止新交接依据、受影响对象及后续处置责任 | 原任务取消、载体清理、目标管理命令核对 |
| 批次计划／推广交接 | 当前批准、报告和来源开放修订检查，原管理命令、目标及下一步；派发资格标记为可能已提交 | 受信入口调用扩展并查询；没有跨库原子激活保证 |

同一 run、候选、批准和目标推广流按预期修订串行；同一目标不并行推进两个未核清批次。工作领取代次只限制本模块提交，不能凭租约过期认定外部进程停止。控制、核对和清理有独立扫描入口与预留容量，进程重启沿原行恢复，有限通知重投仍复用原通知键。

推广派发资格与 WithdrawDecision、报告失效和 Data.Close 在本地串行：关闭先提交则不能取得资格；资格先保存的命令即使实际发送尚无记录，也归入可能已提交并保留原键核对责任。实际发送前再查当前资格，已关闭则不再发送，但不据此推断旧发送从未发生。受信入口始终复用原键和绝对截止，查询缺记录不解除迟到提交可能；未证明旧命令封闭前不创建替代激活。

作用域只允许受信宿主的一位活动写者，接替须有当前 owner 与旧写入口隔离证明；缺失时只读诊断。恢复备份先核对当前身份、撤回、命令尾部及数据关闭依据，不能复活旧 approved 或 usable。保留策略分别覆盖诊断、证据、报告、命令墓碑、未决责任和备份；无法提供必要恢复保留的配置在接纳前拒绝。未决责任只能在有领域关闭依据时释放，正文按[数据规则](observation.md#data)到期清理后可只留获准最小元数据。
