# 验证、依赖与交付状态

[总览](README.md) · [决策机制](decision-policy.md) · [接口与模型运行](contracts-and-runtime.md)

## 1. 验证路径与证据边界

大脑验收先证明单轮提案、授权使用和调用恢复遵守契约，再检验实际任务效果。确定性假模型、假账单和有状态设备模拟器用于验证交接与故障分支，真实本地／云模型用于效果评测；替换与跨端部署另作互操作验证。

每项能力按项目 L1 至 L4 记录目标等级与实际证据。当前仓库尚无大脑参考实现，仅交付契约和验收设计材料；文档审查、静态检查和图示渲染不能证明模型质量、故障恢复或任务效果，也不足以认定 L2／L3／L4。原设计阶段已做的文档检查保留在本页末尾。

## 2. 启用依赖与缺席行为

以下依赖决定哪些场景可以进入验证。各接口已有设计，其提供方仍须交付实现并证明所列保证。

| 提供方 | 必须提供的输入／输出与保证 | 未提供时本模块行为 |
| --- | --- | --- |
| 任务核心／运行存储 | 固定 work／attempt／原领取、call_prepared、预算、可信事实、整体准入、关闭及迟到账务 | 不发起模型调用，不自建调度补偿。接口已设计，实现仍待验证 |
| 上下文组装器／内容服务 | 来源完整的固定快照、精确声明、结构化需求与累计进展；按[内容与来源合同](../content-and-provenance.md#bindings)取得获准字节、耐久引用、所需保留依据及绑定用途／接收方的当前证明 | 必需资料缺失则不生成相应提案；可选记忆缺失可继续并披露限制。内容引用未保存或所需保留不能成立时不充当可恢复事实 |
| 授权与宿主 | Evaluate／BeginUseSet／ReadUseSet（单项沿 BeginUse／ReadUse）、真实模型接收方与资源规范化、当前控制资格、受信用户确认、唯一受控发送入口 | 无当前使用资格不发送；确认或消费未知查原键；不能证明旧实例隔离时不接替发送 |
| 模型适配器与供应方 | 固定 profile 及实际容量域、保留份额、结构输出、原调用事实、可信用量及准确声明的查询／终止能力 | 不支持项标 none；未知费用和物理占位保留，硬预算保证缺失拒绝对应任务 |
| 能力与执行 | 精确版本、参数、效果和核对语义，实际内容获取，API／GUI 前提及事实 | 候选不足不编造声明；原操作未知不回退或重做 |
| 应用任务策略／效果判定器 | 支持目标类型、验收条件绑定、固定验证器与成果版本；开放语义评估的普通能力接口 | draft 时不准入目标行动；验证器缺失不建议成功，临时不可用等待，范围不支持则澄清／失败 |
| 记忆系统／扩展管理器 | 获准记忆、Skill／策略包固定版本与来源、停用与隔离能力 | 无记忆时只作当前任务决策；无隔离只启用受信内置策略，不动态加载未知插件 |
| 协作任务端点 | 受信 Agent 声明、父子结果关联、收缩许可、预算份额、可靠接纳／结果／取消 | 合同不完整就不提供 delegate 候选；不包装为不透明工具 |
| 端云与恢复 | 当前任务／授权／执行依据，获准数据交接和调用回执回送 | 同进程及 BS-P1 远程合同均已定义；缺跨端提供方依据则关闭该部署。离线默认关闭，显式有限窗口及全部本地能力／许可成立才开放 |

模型动作规范化器与受控出口由本模块适配器实现，使用身份、用途与消费规则沿身份契约。任务策略、语义评估器、记忆和协作端点由各自提供方交付；验收须覆盖实际交接。

## 3. 观测与问题定位

每轮保留获准读取的 work／attempt、输入与配置版本、能力候选精确键、选定行动及简短依据、证据缺口、结构校验结果、模型停止原因、准入／拒绝关联、已知用量和未知占用。操作、答案和验证结果通过引用关联，避免复制敏感正文。

这些记录应能定位处理停在哪一步，区分“未生成”“生成无效”“提案过期”“准入拒绝”“业务已接纳”“效果未知”与“任务完成”。耗时分别测排队、上下文组装、授权、生成、准入及等待外部结果。观测只消费提交后事实；日志丢失不影响核对和账务责任。

用户通过现有任务状态、输入请求和固定结果了解进度，通过身份管理入口恢复权限，通过执行管理入口核对原操作。模型账单或停止依据缺失时，由受信宿主调用 ReadCall／RequestStop 核对并回送核心；用户手填费用、模型声称“已停止”均不能释放占位。

核对预算耗尽后停止主动消耗，保留一次通知和原关联。用户本人可通过核心预算接口调整根／内部份额，或给终态原责任补收尾额度；这些操作不解除暂停，也不允许强制成功或重开终态。

## 5. V1／V2 与质量计分

质量评测沿用[执行方案的计分口径](../capability-and-execution/validation.md#tests)。1000 个 API 按不同业务 API 操作计覆盖数；90% 首次调用正确率同时考察能力、参数、对象、权限和实际结果；95% 有限重试任务成功率要求全部必需条件满足。结构正确率单独报告，不能替代首次调用质量。失败、未知、超时和预算耗尽均保留在冻结分母中，越权／坏参数集另测正确拒绝率。

V1 检查答案正确性、引用支撑、获取时间与时效约束，以及证据缺失和冲突时的行为，并设置有／无获准记忆的配对样本。V2 使用多个有状态模拟设备，逐一验证点击、滑动、输入、返回、中断及接管，核对模拟器真实状态和前后观察；模拟结果只覆盖模拟环境。V1／V2 分别出具报告，问答到保存的组合场景不能替代专项验收。

评测冻结目标集、供应方／模型 profile、采样参数、结构修复和业务重试上限、全任务时间与费用上限。模型 profile 的具体型号和容量依据数据策略、硬件及冻结评测配置。参考业务重试可复用执行方案“首次加最多两次新尝试”的待验证 profile；模型结构修复单独计数，未知副作用不能为提高通过率而重做。报告分层样本量、置信区间、p50／p95 耗时、已知费用及未知预留；策略版本之间使用同一冻结集比较。90%／95% 目标以实际结果认定。

策略、提示词、Skill 或 Agent 配置的优化产出带来源、版本和评测证据的候选，由改进管理器启用和回滚。插件或内核代码按 C9 产生可审查补丁，经维护者发布；大脑不能自行降低验证阈值。未知调用风险配额、多模型竞速及通用不可信插件仍未启用。

## 6. 远程调用与控制恢复

BS-P1 已采用，完整单轮协议见[远程调用](contracts-and-runtime.md#remote)，严格载荷见 [brain Schema](../endpoint-communication/schemas/brain.schema.json)。远端保存调用与回送记录，核心保留唯一任务裁决权；消息经网关 WSS 传输，输出通过获准内容通道保存。相较同步 RPC，远程增加接纳与回送账本，使断连后仍可恢复原调用，避免第二次生成。

身份 P1、执行 CE-P1／P2 和协作 CO-P1 由各领域提供，大脑沿用其权威。来源、准确声明、用量和控制已纳入线合同；提供方实现缺失时关闭相应部署。本地调用通过后，仍须另行取得下列远程与控制场景的运行证据。

| 用例及刺激／故障 | 预期可观察结果 |
| --- | --- |
| BS-28 远程接纳响应丢失并重投、查询 | 原 work／attempt 只有一次模型发送资格，恢复不新增自主任务循环 |
| BS-29 暂停与远程生成、结果回送竞争 | 旧提案不准入；迟到账单仍保存；恢复只启动新有效轮次，物理未知仍占额 |
| BS-30 observation 倒序、同修订异内容、记录清理 | 当前投影不回退；冲突保持缺口；查不到不重建发送 |
| BS-31 跨端缺来源／声明／预算／资格，离线窗口未批准 | 不发送模型，不能借调用已接纳绕过使用前复核 |
| BS-32 补证或增额时任务暂停，随后成功恢复 | 保存事实与预算但不解除暂停；全部条件复核后才正常完成 |
