# 全景与模块边界修订记录

[整体设计](../README.md) · [建模视图](../modeling-views.md) · [全景图](../diagrams/system-panorama.drawio.svg) · [系统验证](../validation.md)

本轮依据用户确认的优先级处理十项审查问题：先修正可执行契约与恢复缺口，再比较并落实结构调整，最后同步全景表达。范围为现行技术方案、协议 Schema、示例和静态校验器；未实现生产服务。各项完整规则继续在所属模块维护，本页记录决定及证据。

## 1. 契约与恢复修正

| 原问题 | 采用的修正与边界 | 权威文档及验收 |
| --- | --- | --- |
| 3．上下文缺口只靠文字反馈 | 大脑返回互斥于行动提案的结构化 ContextRequirement：目录候选、既有来源片段、验收条件绑定。核心保存原 work／attempt／输入关联、规范化去重及累计预算，Build 有界消费；获取外部新证据仍走 Operation | [核心推进](../task-kernel/decision-and-work.md)、[大脑合同](../brain-system/contracts-and-runtime.md)，TK-26／27、BS-33～35 |
| 4．记忆元数据与线合同不一致 | 四类记录明确 type_details、schema_version 和正文摘要；置信度区分 unknown、graded、numeric，并绑定签发方及依据。禁止把无依据的默认数值当成置信度 | [记忆合同](../memory-system/contracts.md)、[记忆 Schema](../endpoint-communication/schemas/memory.schema.json)，MS-02 |
| 5．删除依赖当前修订却缺管理发现入口 | 增加 ListMetadata 与 InspectCurrent；最小返回 ID、当前修订、存在／删除状态和检查时间，其他元数据逐项授权。正文不可读时仍可独立获准管理，再以当前修订条件删除；冲突后重新核对 | [管理合同](../memory-system/contracts.md#interfaces)、[交互入口](../application-and-interaction/interaction-contract.md)，MS-27 |
| 6．无关变更反复打断分页 | Search／ListMetadata 固定有限候选集合及查询切点；每页按当前位置检查当前权限和修订，跳过项形成累计 partial。无关写入不重开；旧正文不因快照恢复披露，期限及总额度不重置 | [分页机制](../memory-system/mechanisms.md#pagination)，MS-34／35 |
| 7．有序流缺口阻塞收尾 | 默认按独立恢复行为分流；已冻结的流不改身份。发现已知收尾关联被前序正文阻塞，立即持久唤醒原领域查询；查询成功不跨过旧流序号、不代替 ACK，也不新建业务操作 | [交付与恢复](../endpoint-communication/delivery-and-recovery.md)，EC-20／21 |

补全链同时推演“目录空页但可信游标前进”和“旧轮结果迟到”：前者只继续有限 Build，有新增可用材料才再调用大脑；后者保存事实而不消费新轮需求。管理链同时推演“正文已撤权且记录并发修改”：元数据授权独立成立，旧修订删除被拒绝，不借管理入口读取正文。

## 2. 结构取舍

| 原问题 | 比较与采用决定 | 主要代价与适用边界 |
| --- | --- | --- |
| 1．内部子事实经远程 Peer 回绕 | 比较维持全程转发、完全取消远程 Peer、保留配置接纳并本地观察。采用第三种：Peer 继续固定配置和子提交，核心创建子任务时共同保存父观察责任，直接读取同权威事实及用量 | 保留远程配置接纳所需交接；去掉结果推进对远端在线的依赖。迟到 Peer 回报按同一来源记录去重，外部独立 Agent 仍经 Peer。见[内部观察](../agent-coordination/delegation.md#internal-observation)，CO-28～30、TK-29 |
| 2．TaskPolicy／Verifier 扩展接口隐含 | 比较继续内嵌、不受限插件、受信本地有限扩展。采用显式 Describe／BindGoal／PlanVerification 和 VerifyLocal；安装锁定身份、版本、配置、格式及能力范围，核心保留准入和完成裁决 | 需要维护版本化策略及证据契约；不允许运行任意模型生成代码或隐藏远程副作用。外部验证走普通 Operation，旧任务不热切策略。见[策略合同](../task-kernel/storage-and-interfaces.md#task-policy)、[扩展贡献](../extensions-and-runtime/contracts.md#task-policy-contribution)，TK-28、ER-09 |
| 8．多来源单次授权逐项消费 | 逐项预检不能消除部分消费与并发撤权；补偿退款又会破坏既有 once 语义。采用同用户、同权威、同有限使用单元的 BeginUseSet，在现有事务内全部检查后原子消费，保存整组回执 | 集合有界且须保存完整原意图；成功后未发送、取消或失败仍不退款，发送前继续检查当前条件。跨权威不提供全局原子；必须预先允许部分消费代价，否则关闭该配置。见[集合消费](../identity-and-authorization/mechanisms.md#use-set)，IA-27～29 |
| 9．未知模型调用耗尽共享容量 | 比较超时释放、继续共用单池、固定资源池隔离。采用提供方／实例容量域、用户保留量及未知阈值；实际共用池的多个 profile 共用计数，原调用固定容量域版本 | 未知仍占位且持续保留核对责任；隔离限制影响范围，不保证同一故障池继续可用。只有独立资源及原请求允许时才切换域；要求长期可用性时仍须供应方可信终结能力。见[大脑运行合同](../brain-system/contracts-and-runtime.md)，BS-36 |

上述选择复用现有权威与存储边界，没有新增全局调度／事务服务。内部观察仍遵守父取消、预算归属和子任务独立状态；集合授权提交成功也不等于实际效果已经发生。集合答复丢失沿原集合查询或原样重投，历史回执与本次是否允许启动分别判断。

## 4. 协议联动

新增四个标准请求／响应类型：`authorization.begin_use_set`、`authorization.query_use_set`、`memory.list_metadata`、`memory.inspect_current`，均使用 `harness.` 前缀。Brain observation、记忆记录及分页结构同步严格 Schema；现行 v1 尚为设计草案，直接统一正文、注册表和示例，不保留未经发布的旧草案兼容分支。

三条领域示例补入补全往返、整组消费与查询、管理发现／条件删除／墓碑，以及四类记录和三类置信度。校验器增加集合成员及回执关联、查询路由、仅查询恢复链的不变性、需求 ID 唯一和记忆正文摘要检查。示例签名及证明仍是固定虚构数据，不构成真实授权证据。
