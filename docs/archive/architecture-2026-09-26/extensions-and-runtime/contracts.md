# 契约与持久记录

[总览](README.md) · [安装与隔离](installation-and-isolation.md) · [生命周期](lifecycle-and-recovery.md) · [验证](validation.md)

本页定义本地管理契约及 [release.schema.json](../endpoint-communication/schemas/release.schema.json) 的跨端管理映射；尚无运行 SDK 或安装器。现有目录、驱动、授权与协议声明以其所属文档为权威；跨端默认采用版本化 WSS 领域消息，制品字节沿受控 HTTPS 内容通道。

<a id="handoffs"></a>
## 1. 交接与成功含义

| 发起方 → 处理方 | 输入 → 输出、成功依据 | 持久责任与失败后继续者 |
| --- | --- | --- |
| 管理入口 → 扩展管理器 | 固定管理命令、获准版本及预期修订 → 接纳回执／拒绝 | 管理器保存意图、批准绑定及后续步骤后才能 accepted；入口超时查原 command_id |
| 改进管理器 → 扩展管理器 | 获准产物、评测依据和启用范围 → 同一管理命令流程 | 改进侧自动交接受信批准；扩展侧保存原键、精确范围与回退声明，激活前复核批准权威和当前修订，不接受模型自报批准 |
| 管理器 → 运行器 | 精确制品、锁定依赖、隔离配置及实例绑定 → 已准备／故障／未知 | 管理器先存步骤；运行器从宿主登记的原实例核对进程，重复不再创建副本；健康检查无生产副作用 |
| 管理器 → 能力目录 | [Register／SetAvailability](../capability-and-execution/catalog-and-contracts.md#interfaces) 的固定登记命令 → 发布回执 | 目录保存声明与发布状态；管理器先存原子步骤的命令键，超时查原命令，不重分配登记身份 |
| 运行器 → 领域宿主／授权 | 已绑定实例通道、原调用、范围 → 对应领域的调用结果 | 宿主构造 RequestContext，领域保存原业务事实；运行器退出不撤销已接纳责任 |
| 组装器 → 各组件 | [生命周期适配接口](lifecycle-and-recovery.md) → 已准备／受限／当前就绪依据 | 组装器存装配意图；业务账本仍由组件保存；依赖失效关闭相关入口并重查 |
| 恢复控制器 → 调度器／领域工作者 | 作用域、扫描批额及停止条件 → 扫描进展、缺口与后续时间 | 原工作仍在领域账本；通知丢失由有限周期重扫恢复，控制器不确认操作成功 |
| 管理器 → 原实现使用方 | 停用或排空意图 → 原引用、未决责任及关闭入口依据 | 使用方指目录、执行、大脑、协作等受信宿主；无完整依据则阻塞切换或清理，不能猜测无人使用 |

最后一项在首期由同一受信宿主对已组装组件逐一核对，闭合新引用入口后检查领域账本；无实现适配器时相关替换不可启用。它是组装所需的本地适配责任，不要求邻接模块新增网络 API。各领域仍按自己的控制、授权和持久格式提供事实。

<a id="package"></a>
## 2. 安装描述与依赖锁

PackageDescriptor 描述可安装制品，与[协议 extension manifest](../endpoint-communication/schemas/extension-manifest.schema.json)相互引用；后者只描述消息、附加项和视图。描述文件只提供数据，安装阶段不运行包自带脚本。首期选择独立 UTF-8 JSON 描述文件和 ZIP 制品，`digest` 为 ZIP 原始字节的 SHA-256，表示为 `sha256:` 加 64 位小写十六进制；批准记录另固定描述文件原始字节的同格式摘要。解包后固定各文件摘要并在装载时复查，不对不同 ZIP 编码做内容等价去重。格式选择是本次设计，机器可读 Schema 和打包器随 SDK 实施交付。

| 字段组 | 约束 |
| --- | --- |
| `package_id`、`package_version`、`digest` | 发布者控制的名称、精确版本及完整制品摘要；同 ID／版本对应唯一字节集。版本作为精确字符串比较，不据版本号推断兼容性 |
| `publisher_ref`、`provenance_ref` | 受信发布来源及审查链；宿主信任配置把发布者、命名空间和允许摘要关联，不能只验证下载来的自签名或自报名称 |
| `exports` | `component`／`driver`／`skill`／`agent_config`／`protocol_handler` 及本地入口、接口版本、内容摘要；同包可有多个导出，每个单独验收。核心保留命名空间仅宿主内置注册 |
| `dependencies` | 必需／可选依赖、允许的精确候选及接口要求；安装计划最终只选一个固定版本。可选缺席的行为必须显式声明，不能在运行时按网络搜索结果补齐 |
| `contract_refs` | 导出所用能力声明、Schema、Skill 来源、Agent 合同、TaskPolicy／Verifier 本地接口与格式、协议 manifest 及合法／非法／恢复用例的本地引用与摘要；禁止未固定的远程引用 |
| `host_requirements` | 支持的平台和架构、所需宿主接口、隔离能力、可读写持久格式集合及升级限制；包自报只作验证输入 |
| `resource_profile` | CPU、内存、进程数、临时盘、日志／IPC、调用数和字节的有限上限；网络、内容和凭据访问经宿主受控接口，声明不授予权限 |
| `retention_requirements` | 原实现查询／取消、重投窗口、待交接结果、私有数据及最小墓碑的保留要求；不允许持久化必要恢复依据的配置不得接纳对应能力 |

InstallationLock 保存解析结果，字段为宿主接口版本、完整制品及依赖摘要列表、每个导出的提供方、缺席可选项和相应行为、隔离配置摘要、验证集版本、目标平台、配置修订。引用闭包必须可离线校验，按稳定名称排序；缺失必需项、依赖环、名称冲突或接口不符时拒绝，首期不为循环依赖增加延迟装载机制。锁只描述精确内容，不含凭据明文。

语义示例：一个包同时提供文件驱动与“保存后读回”的 Skill；Skill 引用能力精确键，不能因此取得文件权限。此例只展示逻辑关联，不是可安装清单；发布时需补齐上表的全部字段和真实摘要。

```yaml
package_id: org.example.file-tools
package_version: "2.0.1"
exports:
  - kind: driver
    local_entry: drivers/file
    capability_ref: contracts/file-write-v1
    driver_revision: "file-impl-7"
  - kind: skill
    local_entry: skills/save-and-verify
    required_capabilities: ["file.write@1", "file.read@1"]
installation_lock:
  dependency_versions: {org.example.content-client: "1.2.0"}
  optional_missing: []
```

<a id="task-policy-contribution"></a>
### 任务策略与验证器贡献

TaskPolicy 和 Verifier 使用既有 `component` 导出接入[核心本地策略接口](../task-kernel/storage-and-interfaces.md#task-policy)，不增加线消息类型或公网提交字段。安装锁固定 `policy_id`、精确 `version`、`config_digest`、本地入口及接口版本，并固定关联 Verifier 的身份、版本、代码／配置摘要。相同精确绑定不能替换内容，配置变化产生新的 config_digest 和管理修订；宿主按受信目标路由选择策略，多个匹配必须有确定优先序，不交由模型挑选判据。

贡献声明须包含支持的目标类别、输入及 condition 格式／版本、允许的证据格式和生产者、成果版本关联、准确能力及其保证要求，以及各本地调用的时间、输入字节、输出大小与资源上限。安装验证 `Describe`、`BindGoal`、`PlanVerification` 和 `VerifyLocal` 的接口及负例；格式相同但保证不符、验证器缺席、隐藏联网／生成或超出有限执行约束时，不启用相关目标。代码信任与隔离仍按原组件批准流程处理，普通包安装不自动获得核心信任。

安装及替换只改变后续获准选择。任务接纳前，宿主按[引用登记规则](#storage)保留精确策略、验证器及配置；核心固定任务绑定并保存条件、证据与完成事实。旧任务不热切版本，排空、回收及安全撤回沿现有组件规则；扩展管理器不保存或修改任务运行事实，也不代替核心准入外部验证操作。策略接口的失败与等待语义以核心契约为准。

<a id="approval"></a>
## 3. 启用依据与作用域

ActivationBasis 是本地受信入口对发布、评测和安装授权的关联记录，不能由插件自行填充。它至少固定描述文件与制品摘要／配置修订、制品种类、发布来源、批准主体及回执、适用测试集与结论、适用用户／端点／用途、启用批次、有效期限、当前撤回状态和预期替换绑定。改变任一绑定须重新取得适用依据。

启用依据同时关联批准中的回退声明。声明支持回退时，须固定旧版本及完整依赖锁、适用范围与窗口、可处理的新版持久格式、制品保留责任、验证方法与结果引用，以及不能回退时的处置。验证覆盖新版写入后的当前账本由指定旧版读取、解释未决记录并继续支持的任务；缺少适用依据时不能按“支持回退”的批准接纳激活。发布只保证停用，或不可逆格式变化使指定旧版无法处理当前账本时，批准须明确不保证旧版恢复，并引用适用的迁移和失败处置方案。改变这一保证须重新批准，不能在激活步骤中静默降低。

C9 的改进产物沿[项目默认生效规则](../../../harness-project-goals.md)：Skill、执行策略和 Agent 配置须经过隔离评测再逐步启用；插件与内核代码须有维护者确认。发布批准不替代目标用户的安装权限、行动许可或当前授权；普通安装只能选已经获准发布的精确包。新增导出请求更多权限时，安装成功仍保持该导出不可使用，直到用户从身份模块的受信确认入口授予适用许可。

维护者选择并批准有限批次；管理器自动执行该批次、核对原命令、应用撤回及符合条件的预批准回退，不根据在线评分自动扩大范围或修改门槛。代码回退也要检查原版本仍获准、当前依赖与持久格式兼容；不能因“回到旧版”跳过这些检查。跨节点原交接与批准查询见[线合同](#wire)。

## 4. 管理接口、重复与取消

所有变更使用 `(management_scope, command_id)` 去重；scope 来自受信宿主，明确用户范围或部署维护范围，后者只能由维护主体使用。公共输入包括原命令 ID、动作及完整意图、目标绑定、预期管理修订、批准引用和绝对截止。命令意图保存规范值和摘要，同键异内容拒绝；业务 operation_id、安装 command_id 与启动 boot_id 是不同标识。

| 本地接口 | 输入 → 输出 | 对调用方的承诺 |
| --- | --- | --- |
| `Extensions.Prepare` | 制品、依赖选择、验证 profile → 安装回执及固定锁 | 成功只表示制品已验证并可靠保管；没有开放能力或取得用户权限 |
| `Extensions.Activate` | 已准备锁、批准依据、目标作用域与预期绑定 → 管理命令回执 | accepted 表示后续步骤可靠保存；succeeded 固定目标激活回执，当前健康另查 |
| `Extensions.SetAvailability` | 原绑定、停止新引用／安全停用意图、预期修订 → 对应发布权威和宿主门禁回执 | 驱动分别沿目录 draining／disabled；其余导出沿[发布落点](installation-and-isolation.md#activation)关闭新引用／使用。只有门禁实际应用才确认生效，离线目标不能报告已停 |
| `Extensions.QueryCommand` | 原 command_id、当前披露权 → 固定接纳决定、进度、步骤回执和缺口 | 只读；未知提交必须按此核对。记录缺失返回 recovery_gap，不推断从未发生 |
| `Extensions.Abort` | 新命令 ID、目标管理命令 → 封闭剩余步骤／已到不可撤回阶段／待核对 | 安装尚未启动的步骤可关闭；目录激活可能已生效时先查原步骤，已生效改走显式停用命令，不覆写原成功回执 |
| `Extensions.Remove` | 无新引用的原锁／绑定、保留策略 → 可回收清单与删除回执 | 只删除所有保留条件均满足的资产；存在未知责任则受限或拒绝，返回具体阻塞者 |
| `Runtime.EnsurePrepared`／`Inspect`／`Stop` | 原实例身份、锁、隔离配置与实例代次 → 进程准备、现状或停止依据 | 由管理器／组装器调用；重复先核对原受监督实例。Stop 不返回外部业务效果结论 |

QueryCommand 的固定接纳决定与可变进度分别保存。进度为 `pending`／`succeeded`／`failed`／`aborted`，`pending` 可带 blocker、next_check_at 和主动尝试剩余额度；进程间超时或提交未知是调用结果，不是“未接纳”的持久状态。`failed` 表示该管理目标不再主动推进，同时列出已生效步骤和仍待核对责任；不会撤销目录已有发布或业务效果。`aborted` 只在能够证明目标步骤未生效且剩余步骤永久封闭时成立。

管理命令到期停止新的激活步骤，不延长原截止；已经可能提交的步骤继续有限核对，不能过期改判失败无效果。主动核对耗尽后保留 pending 缺口并释放执行槽；合法迟到回执仍可接收。受信维护者可提交独立有界核对命令，附额度、期限及当前权限，沿原步骤查询，不赋予旧命令新的激活资格。取消与步提交按同一管理修订串行；已经发出的跨模块步骤必须先核对再判定可撤回性。

### 错误与调用方后续行为

| 本地原因 | 调用方行为 |
| --- | --- |
| `invalid_package`／`unsupported_contract`／`dependency_conflict` | 修正制品或装配计划后提交新意图；已有同键记录不改写 |
| `identity_conflict`／`revision_conflict` | 保留原记录；读取当前绑定，重新评审预期变更，不盲目覆盖 |
| `forbidden`／`approval_missing`／`isolation_unavailable` | 恢复适用批准或实际隔离能力；不自动请求更宽权限或降级沙箱 |
| `in_use`／`recovery_gap` | 列出原绑定、责任方和缺失证据；等待领域核对或有界受信处置，不能强制清除未知 |
| `overloaded`／`unavailable` | 仅在确定未接纳时使用；沿原键和期限有限重投。接纳后报告 blocker，提交未知走查询 |
| `expired` | 关闭尚未启动的变更，保留已发生步骤；新变更需独立批准和命令 |

这些名字是本地语义，不注册为 `core.*` 线错误；已有业务接口继续返回所属模块规定的错误。

<a id="storage"></a>
## 5. 存储、并发与保留

| 记录 | 关键内容及原子边界 |
| --- | --- |
| PackageRecord／InstallationLock | 制品身份、来源、完整锁、验证依据、保留原因；制品先耐久写入不可变存储，数据库再保存可引用记录。文件保存但事务失败只形成待回收孤立资产 |
| AssemblyRecord | 精确装配、部署维护范围、用户绑定、已接纳生命周期意图及修订；运行健康和扫描游标不是业务真相 |
| ManagementCommand／Step | 固定意图、接纳回执、状态、后续步骤、blocker、次数与期限；决定与后续步骤一起提交。每个跨模块步骤固定原目标命令和完整载荷，再调用处理方 |
| ApprovalView／ApplicationReceipt | 固定批准操作 approval_id、真实权威、批准修订、精确制品／批次、激活截止、持续使用截止、撤回修订和本地应用位置；应用门禁与回执同事务，旧事件不回退状态 |
| InstanceRecord | 用户、actor 映射引用、端点、导出、实现及配置、受监督进程身份／代次、隔离依据、当前管理资格；不能只用可复用 PID 定位实例 |
| RecoveryEvent | 原实例／锁、故障事件身份、恢复资格、首次故障时刻、固定截止、累计尝试、退避及稳定观察；与实例的未结束事件唯一关联，监督器重启不另建事件重置次数 |
| BindingReference | 本宿主登记的装配、任务配置、操作、消息处理与恢复引用及其领域依据；可从领域重建，缺一方完成证明不得据引用计数为零清理 |
| DeletionReceipt／CommandTombstone | 原命令、意图与关闭依据、获准最小回执和截止；清除制品或正文不允许原命令重新建立调用 |

默认复用宿主事务数据库，不新设安装服务集群：单机按现有模块的 SQLite 提交域，云端按已配置的 PostgreSQL 用户／部署分区。安装表与领域账本各自管理，跨边界使用固定步骤和回执，不声称跨库原子提交。数据库短事务保存控制行、命令和下一步；同一目标绑定通过预期修订串行；下载、解包、测试和进程操作均在事务外。SQLite 单机写事务可用 `BEGIN IMMEDIATE` 先取得写资格，忙冲突有界重试；提交响应丢失仍须核对原命令。[SQLite 事务文档](https://www.sqlite.org/lang_transaction.html)

同一管理作用域只允许一个有效管理写入者；多宿主接替依身份的活动 owner 和资源入口隔离依据。发现旧写入者是否停止不明时关闭相关新变更，不能凭租约超时或本地文件锁推出跨主机唯一性。数据库恢复旧快照须同时验证包和命令尾部、当前 owner、撤回与授权控制依据；证明不齐只开放检查入口，不从旧 active 记录重新发布能力。

配置引用不能仅靠异步上报计数：受信宿主在把精确配置交给任务、模型或消息处理器前，先用原使用身份在 BindingReference 保存保留资格，并与关闭新引用的管理修订串行；随后保存领域接纳回执关联。两者不能同事务时允许形成多余保留，不允许先使用后登记。领域提交未知保留该资格，只有取得原使用已经结束，或从未接纳且入口永久封闭的依据才释放。已有任务创建必要后继工作沿其既有长期引用，关闭新任务引用不提前阻止这些后继；纯语义能力引用不误计为具体驱动实现引用。

卸载清理先封闭新引用，再由各领域确认：无仍能产生效果的执行、无未知效果或未交接事实、无待处理消息依赖、无任务／模型／Agent 配置引用、无有效回退声明的制品保留责任、无原命令核对及保留窗口。所有条件分别满足才能删除；检查后至删除期间保持入口关闭，引用资格与清理标记串行。事务先保存不可再引用的回收计划，再删除文件并保存完成回执，崩溃后按原路径清单续做。正在 staging 的资产也有保留资格，不被孤立资产扫描误删。

包可以共享只读公开字节，用户安装绑定、私有 Skill、缓存、临时盘、命令和日志按受信用户隔离，不对私有内容作跨用户去重。强制删除用户内容时立即关闭后续使用，按当前许可保留最小控制记录；如果连防重放依据也不能保留，则先在不可回滚的权威处封闭原身份，缺少该能力时不提供可恢复模式。安全撤回的代码即使仍有引用也不得重新执行，只保留获准非执行证据并报告恢复缺口。

## 6. 批准后自动执行与跨节点管理线合同

[release.schema.json](../endpoint-communication/schemas/release.schema.json)定义 OI-P1／ER-P1／ER-P2 的版本 1；[示例](../endpoint-communication/examples/runtime-domain-flow.json)串起批准查询、逐节点准备／激活、撤回和回退。release 使用真实批准权威签发／查询的 proof_ref；事件投影不能自行增加范围、延长期限或生成新批准。

`approval_id` 是独立批准操作身份，所有消息的 scope 为 operation(approval_id)，不同于逐目标 `command_id`。实际查询操作也有自己的 envelope.operation_id；每个变更命令的 envelope.operation_id 必须等于载荷 command_id。改进与扩展分别保存原交接责任，消息 ACK 只证明交付。

| 消息（省略 harness.release.） | lane | 载荷与确认含义 |
| --- | --- | --- |
| query_approval | recovery | 固定 approval_id、真实 authority_endpoint、最低修订及范围摘要；返回精确制品、报告、批准目标／批次、激活截止、持续使用新鲜度／离线窗口和预批准回退依据 |
| approval | control | 权威的单调批准／拒绝／撤回投影；接收端核对真实 source 及证明后应用撤回门禁。approved 事件不创建激活命令 |
| apply | work | prepare／activate／rollback；固定 command_id、目标、预期绑定修订、批准权威／修订、精确制品、批次和绝对截止。prepare 只确认制品及锁已耐久准备，activate 才开放目标绑定 |
| disable | control | 只允许关闭新使用，不能借控制 lane 发送 activate；原已活动绑定、批准撤回及当前停用权限单独核对 |
| query_command | recovery | 原 approval_id／command_id／目标；返回固定接纳、实际阶段、准备、关闭门禁、绑定修订、回退状态及缺口 |
| command_fact | control | 目标提供同一命令的持久阶段回执，实际效果仍归业务领域；不得用汇总 succeeded 覆盖其他节点未知 |

制品按内容 ID、提供方、大小和摘要沿 HTTPS 取得，不允许从任意包内 URL 拉依赖；来源、完整锁与逐节点准备均按已有安装检查。每个目标独立推进，部分节点离线就保留未知，不换目标或新命令补做原激活，不要求跨节点原子发布。

预批准回退的目标制品、格式范围、验证报告及独立有效依据随原批准固定；主产物撤回后只开放已批准的纠正动作，不再开放新激活。回退时仍核对旧版信任、独立回退依据、当前格式与原责任；原回退依据本身被撤回或到期则只停用并报告。批准当前性、有效期和新使用门禁见[批准新鲜度](installation-and-isolation.md#approval-freshness)。运行实现未交付，Schema 成功不能证明跨节点及时停用或实际旧版恢复。
