# 示例 4 · 协作与端云

多 Agent 委派产生独立子任务；所有权移交改变同一任务的推进权。下面两节分别采用这两种配置，不把委派后的任务状态带入移交例。

## 1. 两个只读子任务核对资料

起点是父任务 T 已取得 E1《会议记录》和 E2《需求说明》，摘要 D 尚未形成。用户允许把所需内容或受控引用交给获准位置的子任务；父任务负责电脑保存、读回和手机交付。

父任务持久记录委派关系、收窄权限和预算预留。T1 核对资料导入，T2 核对摘要导出，各自由自己的内核接纳。接纳结果未知时按原关系查询，不因为回执丢失再创建一个子任务。

T1 返回资料导入已验收及对应来源；T2 返回摘要导出仍在联调、尚未验收及要求依据。父任务检查来源和适用范围，综合形成“整体尚未满足两项均通过验收”的判断，之后再安排 S、R 和交付。子任务使用了多少预算、是否还有未决责任分别核对，不能只看结果文本。

改变一个条件：T2 失联，父任务收到取消。父端阻止适用的新委派，保存对子任务的控制与查询责任；未知消耗不释放，也不能仅凭超时断言 T2 已结束。父任务终态取决于其所辖责任的收尾条件。机制见[多 Agent 协作](../main/03-coordination/03-agent-collaboration.md)。

## 2. 原文留端，先移交再断网

重新从 T 由云侧推进、尚未读取 E2、尚未生成 D 开始。没有在途外部动作，也没有未收尾子任务。E2 原文、内容索引与相关模型处理必须留在电脑；E1 与偏好 P@1 的获准副本已在电脑，仍满足来源、用途与新鲜度要求。P@1 要求先列待办、再列已完成。

双方在线时，目标电脑准备可恢复检查点及所需依赖；源端确认封存且旧执行者不能再启动新动作，目标确认持久激活后才恢复调度。检查点此时没有 E2 原文，传递内容遵守位置策略。结果未知查询原移交，不凭超时恢复源端推进。

移交完成后，电脑与云断开，且没有手机直连路径。电脑进程没有重启，持有足够额度和有效离线许可，也没有已生效的暂停或取消，本地模型、资料和工具齐备。电脑取得 E2，组装本地上下文，生成 D，经 S／J 保存，再执行 R 核验。文件可在本地完成，但手机交付仍须等待。

连接恢复时电脑仍是 Owner。先核对当前资格、控制、授权、消息与原效果，再将获准摘要、文件位置和受控来源引用经云侧转交手机。云获准暂存和转交，不因此获得 E2 原文、任意模型处理或长期记忆权限。取得手机呈现反馈后再判断完整交付。

改变一个条件：若本地模型不可用，或离线许可在适用规则下无法继续核验，则等待缺失条件，不能自动把 E2 发到云模型。离线重启的默认复核与本机授权权威的例外由[授权设计](../main/02-subsystems/06-identity-and-authorization.md)维护。移交、联合检索、记忆副本与重连机制见[端云协同](../main/03-coordination/04-edge-cloud-coordination.md)。

这两节演示职责差异，尚无运行证据；两台设备也不要求一定创建两个 Agent 或经过云端。
