# 示例 5 · 组装、升级与评测

这些工程例子使用相同摘要目标，但每节是一项独立实验。先固定已准入工作、实现版本和环境，再观察变化后的行为；模拟、迁移与模型质量提供不同证据。

## 1. 同机组装完整任务

开发机上运行同一用户的有状态模拟手机与电脑，保存 E1、E2 和实际模拟文件状态，默认使用 Go 与 SQLite。相关读取、处理、保存、读回与交付权限已经配置。先用脚本化大脑提供可重复提案，检查完整任务、等待与重启恢复。

模拟端应按契约保存状态，跨进程和端云路径分别通过真实协议与独立持久化边界。用内存函数直接返回成功，不能证明协议重连或文件耐久性。换成真实模型后，另测能力选择、参数和有界完成；前一步的可重复通过不代表模型质量。

组装依赖、就绪、启动关闭及支持范围见[开发组装](../main/04-engineering/01-implementation-and-technology.md)。

## 2. 已准入工作保持旧实现绑定

起点是 S 与依赖它的 R 已准入并绑定 v1，S 尚在运行。管理员计划激活 v2；本例 v1 与 v2 可以并存，v1 仍获准可用，也不涉及旧状态格式迁移。

扩展管理准备并验证 v2，提交激活修订，相关投影应用后，新选择才使用新绑定。在途 S 和已经准入的 R 继续沿 v1 核对与执行，不把同一次操作切到 v2。若发现 v1 风险并隔离它，旧绑定也不能绕过限制继续运行，应保留核对与处置责任。

回滚改变之后的选择，不回滚已经保存的文件或授权消费。跨节点激活不是全局原子操作，节点应用进展分别报告。依据见[实现升级](../main/02-subsystems/08-extensions-and-runtime.md#6-保存尚未结束时升级旧工作怎样继续)。

## 3. 派发前切换 SQLite 与 bbolt

重新从 S／R 已准入、S 尚未派发开始，此时没有外部作业 J。迁移需要保留任务、操作映射、预算、控制、工作、去重及恢复依据，不能只拷贝最终任务状态。

先停止适用的新工作并按契约进入静止边界，再导出、校验和导入目标后端，核对记录、版本及适用恢复条件。切换后沿原 S／R 继续，不重新决策创建第二批工作。双向迁移和失败切点分别验证，切换参考后端不等于取得生产 HA 证据。

完整步骤及不满足静止条件时的处理见[持久化替换](../main/04-engineering/01-implementation-and-technology.md#6-sqlite-与-bbolt-怎样带着原任务切换)。

## 4. 任务最终成功，首次选择仍然错误

重新在有状态模拟环境中使用真实模型。两份资料已取得，摘要 D 已生成；两项保存能力的声明均已进入输入，但没有编辑器会话，也没有 D 已成为编辑器当前文档的证据。模型先选“保存编辑器中的当前文档”，内核因前提不足拒绝；剩余预算内纠正后，才准入指定目录保存 S 与读回 R，并完成手机交付。

记录三个结果：首次选择错误，错误动作被阻止，整项任务最终成功。完整摘要是多步任务，不能直接充当单步首次调用主指标的一个样本；评分依据独立预期和环境效果，不以模型自报成功为准。

若提出改善声明呈现方式的候选，保持模型、任务、预算、权限及评分规则可比，进行配对评测和独立保留确认。教学演算中 100 项等额样本的基线 90%、候选 92%，来自修复 8 项和退步 6 项，净差 2 个百分点；它既没有覆盖完整千级目录，也没有提供统计改善或发布资格证据。完整口径见[评测、比较与发布](../main/04-engineering/04-evaluation-and-release.md)。

## 5. 把已有证据放回交付阶段

假设摘要通过、小型真实模型回归通过，仍须逐项核对独立替换、完整 API 集、联网问答、GUI、端云、恢复及受控改进证据。M1–M4 是交付阶段，L1–L4 是能力成熟度，不能凭一个示例通过就整体晋级。

恢复工作包可以另从“电脑保存已确认、内核报告未到”开始，指定注入切点、原操作核对、预算和结束依据。候选版本、环境、数据及未通过项一同交付；M4 技术资格不自动授予代码发布权限。步骤见[实施路线与能力验收](../main/04-engineering/05-roadmap-and-validation.md)。本组仍只有设计与教学演算，没有实际实现、迁移、评测或发布结果。
