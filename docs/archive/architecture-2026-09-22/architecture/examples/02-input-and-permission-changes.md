# 示例 2 · 输入、来源与权限变化

这四个分支分别改变决策依据、用户要求或授权。每节重新设定起点，不承接上一节的结果。资料含义和目标文件同[正常过程](01-task-lifecycle.md)，决定当前行为的条件在下面重新交代。

## 1. 获准偏好进入上下文，随后被删除

起点是 E1、E2 已取得，摘要尚未生成。用户此前另行授权保存并用于项目进展摘要的偏好 P@1：“先列待办，再列已完成”。这份偏好只改变组织方式，不增加事实依据。

下表是生成摘要前的一份内容示意，省略完整能力参数和协议字段。任务版本 `v7`、上下文 `C1` 均为教学编号，来源修订与任务版本分别跟踪。

| 输入部分 | C1 中选入的内容 |
| --- | --- |
| 目标与用户约束 | 整理项目进展，保存到电脑 `输出/项目进展摘要.md`，读回核对后在手机交付位置和结论来源；遵守本任务允许的处理、传递与保存范围。 |
| 当前运行事实 | 依据任务 v7：两份资料已取得，尚未保存摘要。后续执行结果必须来自内核纳入的事实。 |
| 必要证据 | E1 的完成与未完成事项，E2 的验收要求，以及对应的来源片段和版本依据。 |
| 适用记忆 | P@1：项目进展摘要按待办、已完成分组，先列待办；来源是用户明确表达，且已获准用于此类任务。 |
| 本轮可用能力 | 保存与读回所需的能力说明、准确版本及参数约束；候选选择策略在[规划与决策](../main/02-subsystems/03-planning-and-decision.md)展开。 |
| 预算与可用性说明 | 输入容量、输出预留、选入及裁剪原因、来源清单；本例必要资料已取得，存在缺口时在这里显式报告。 |

P@1 使本例的摘要先出现“待办：摘要导出仍在联调，需完成验收”，再出现“已完成：资料导入已验收”。两条内容继续分别引用 E1、E2；整体判断仍是“按本次资料，尚未满足交付要求”。偏好改变排列方式，不增加事实依据。

现在只改变一个条件：C1 已送入模型，保存尚未准入，用户发起获准删除，且本例的依赖复核能够访问记忆权威。

记忆权威提交删除并登记失效；通知帮助使用方尽早发现，模型返回后的来源复核仍然执行。内核发现 P 已删除，拒绝旧提案，组装不含 P 的 C2，再在剩余预算内请求决策并检查准入。E1、E2 的有效事实继续保留，删除偏好不表示用户指定了相反顺序。

可观察结果是旧依据不再驱动新动作，新的输入没有 P；“删除已提交”与缓存、索引、副本、备份是否清理分别报告。已经发给模型的数据不能通过本地删除撤回。机制和边界由[上下文与记忆](../main/02-subsystems/02-context-and-memory.md#5-记忆变化后已有上下文怎样处理)维护。

## 2. 生成期间追加“确认后再保存”

重新从摘要生成中、S／R 尚未准入开始，来源和许可有效。用户提出“先给我看，确认后再保存”。界面将补充要求绑定到原任务并保存转交责任；内核接纳后推进任务版本，原先直接保存的提案不能再按旧版本准入。

系统形成待确认摘要，呈现内容及其版本。用户回应绑定这份内容与有效等待项，内核核对后才准入保存及依赖读回。确认只同意当前内容，不增加保存或披露权限；若用户要求又改变，则按新的任务和内容版本重新判断。

若确认回应已经被业务接纳、界面却丢失回执，重连后查原操作并恢复显示，不要求再造一次确认。过程见[输入生效](../main/02-subsystems/05-interaction.md#application)与[显示恢复](../main/02-subsystems/05-interaction.md#surface)。若 S 已启动，本分支的前提不成立，新要求不能改写原 S 的输入。

## 3. 改存目录，需要新的一次写许可

重新从摘要已形成、原保存尚未准入，用户希望改存归档目录开始。归档目录存在，能力适用，读回已获准，签发方可用，策略允许该用户授予相应许可；缺少的仅是新目录的一次写许可。任务先正式接纳目标变化，使旧目标提案失效，新目标形成新的操作意图。

授权判定给出缺少的许可范围，交互将授权问题路由到有权批准的主体。批准后由有权签发者保存许可及回执，执行端核验后，把消费与原操作启动准备原子关联。签发重试查原签发，执行重试查原操作，不能增加使用次数。

批准、签发、消费与文件效果分别确认。内容确认不代替授权，改变目录也不能沿用旧操作身份。完整局部前提和事务边界见[许可签发](../main/02-subsystems/06-identity-and-authorization.md#issue)及[执行消费](../main/02-subsystems/06-identity-and-authorization.md#execute)。

## 4. 保存已启动，再撤销许可

重新从 S 已启动、外部作业 J 仍在进行开始。用户获准撤销启动许可；本分支另有有限许可允许必要的查询、取消和结果披露。

授权权威记录撤销，执行端收到并应用后阻止适用的新动作，并按原 S／J 请求停止或查询。已发生的文件效果不能靠撤销自动撤回，收到取消回执也不表示工具已经停止。原效果查清前保留核对责任及必要预算占用。

界面分别显示撤销记录、送达、应用和实际处置进度。离线端尚未收到撤销时只能按已声明的有限离线规则处理；需要即时核验的动作不能在离线时启动。规则见[撤销与离线](../main/02-subsystems/06-identity-and-authorization.md#revocation)。

以上均为教学分支，尚无运行结果。条件变化的共同关系见[任务控制与来源变化](../main/03-coordination/02-control-and-lifecycle.md)。
