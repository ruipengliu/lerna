# 任务过程与独立分支

本组文档将架构中的交接放进同一教学任务：综合手机《会议记录》和电脑《需求说明》，生成并保存《项目进展摘要》，读回核验后向手机交付位置与结论来源。先读正常过程，再从需要观察的条件进入分支。

| 示例 | 观察什么 | 与正常过程的关系 |
| --- | --- | --- |
| [示例 1 · 正常过程](01-task-lifecycle.md) | 接收、读取、上下文、决策、准入、保存、核验与交付。 | 一条完整时间线。 |
| [示例 2 · 输入、来源与权限变化](02-input-and-permission-changes.md) | 偏好参与后被删除、用户新增确认要求、改存目录与撤销。 | 每一小节从独立起点开始。 |
| [示例 3 · 外部效果与恢复](03-effects-and-recovery.md) | 回执丢失、进程故障、数据库切换、交付未完成。 | 按故障切点选择，不能混用核对依据。 |
| [示例 4 · 协作与端云](04-edge-cloud-and-collaboration.md) | 子任务核对、原文留端、所有权移交、离线与重连。 | 委派与移交是两套独立配置。 |
| [示例 5 · 组装、升级与评测](05-implementation-and-evaluation.md) | 在途版本绑定、存储迁移、真实模型计分与阶段判断。 | 工程实验各自固定初始状态和证据范围。 |

## 共同条件与对象

除分支明确改变的条件外，手机和电脑属于同一用户，设备及工具在线。读取资料、在允许位置处理、必要跨端传递，以及电脑指定目录保存和读回均已授权。异步保存工具可查询进展，并按其声明提供效果核对证据。

| 对象 | 本组示例的约定 |
| --- | --- |
| T | 完整摘要任务；设备有两台不意味着必须创建两个 Agent。 |
| E1 | 《会议记录》：“资料导入已验收；摘要导出仍在联调，尚未验收。” |
| E2 | 《需求说明》：“支持资料导入和摘要导出；两项均须通过验收。” |
| D | 本次摘要内容；目标文件是电脑 `输出/项目进展摘要.md`。 |
| S、R、J | 保存操作、依赖保存成功的读回操作、保存工具的外部异步作业。各自到相应阶段才产生。 |
| P@1、C1 | 部分分支使用的获准偏好修订与上下文快照；正常过程不要求长期记忆。C1 不同于验收能力编号。 |

摘要中的已完成事项与待办来自教学资料，整理任务没有实际验收产品。完成依据包括保存效果、实际内容核验、文件位置与来源的手机呈现反馈，以及在途工作和预算处置条件；工具接纳、文件保存和任务完成分别确认。

## 分支切换规则

每节明确起点、改变的条件、处理过程与可观察结果。生成期间删除偏好不会自动与新增确认要求同时发生；原文留端条件不能继承到允许云侧处理的生产恢复例；存储迁移从派发前开始，不能凭空出现外部作业 J。

局部机制仍在[架构正文](../main/README.md)完整解释。这里按具体条件演示，不另建通用状态或接口，也不以一条成功故事证明模型、GUI、生产性能或架构收益。精确规格见[契约参考](../reference/README.md)。
