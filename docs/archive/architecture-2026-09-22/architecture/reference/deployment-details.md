# 部署与存储：入口认证及用户隔离细则

本资料供实现生产入口与数据访问边界时查阅。Gateway 是受信代理，namespace 来自可信身份，route_epoch 表示归属路由修订，不是资源访问许可。

<a id="gateway"></a>
## A. Gateway 代理认证与入口

原生节点入口验证证书、登记、用户关联及原授权绑定；浏览器入口验证同源会话、Origin 和变更请求的 CSRF 保护，再由可信身份校验职责解析用户。两种入口互斥，节点认证失败不能退回浏览器身份。

获准签发方核验原始主体证明、代理资格及原授权限制，签发绑定 **Gateway 实际出示证书和目标服务**的更窄材料，保留原主体、用户范围、端点及操作关联。后端验证当前 mTLS 对端与持有者绑定，并在处理时复核动作、资源、期限和用途。换网关或证书后重新取得匹配材料，原操作身份不变；不支持该代理配置的节点走保留端到端认证的直连／透传路径。原授权语义见[2.6 身份与授权](../main/02-subsystems/06-identity-and-authorization.md)。

<a id="isolation"></a>
## B. 用户隔离逐层检查

| 位置 | 必须落实的边界 |
| --- | --- |
| 数据库与连接池 | 同域主键、唯一键及关联包含 `namespace`；每次写入校验本分区可写状态与路由世代。连接池总量覆盖全部服务副本，事务上下文来自可信身份，不遗留上一用户会话。 |
| 对象与下载 | 对象引用、元数据和下载许可绑定用户、资源与期限；不按客户端路径直接取内容，不用跨用户去重泄露存在性。 |
| 索引与缓存 | 候选搜索阶段限定获准范围，返回前复核来源和权限；缓存键、回填、失效和负缓存均保留作用域。 |
| 消息与界面 | 订阅、游标、重放及 Surface 单独授权；路由键不是访问许可，不向同用户全部窗口自动披露。 |
| Worker、扩展与观测 | 清理共享会话、缓冲和临时文件，隔离凭证与模型输入；默认诊断记录最小必要引用，正文调试与评测复用另需许可。 |

数据库行级安全可作为纵深防御：运行角色不应是表所有者或具有绕过权限，读与写入检查均覆盖用户范围；运维角色独立受控。应用仍承担资源与用途授权。内部跨用户调度只通过最小权限领取接口取得选定用户的工作，普通 API 不持有任意跨域查询能力。

<a id="postgresql"></a>
## C. PostgreSQL 事务隔离与领取实现

生产参考 Adapter 使用事务池时，不依赖跨事务会话状态。每个事务都从可信调用上下文局部设置 namespace，提交或回滚后不保留上一用户的作用域。共享公开目录单独提供只读视图，不能通过省略 namespace 将用户数据变成共享数据。

采用行级安全时，运行角色不得为表所有者、超级用户或具有 `BYPASSRLS` 权限；按需要启用 `FORCE ROW LEVEL SECURITY`，读策略与写入的 `WITH CHECK` 均约束当前用户范围。RLS 是纵深防御，不能替代应用对资源、用途和位置的授权。

领取工作与暂停／取消必须使用一致的锁定顺序或版本竞争规则，防止控制已经生效后继续取得旧资格。`SKIP LOCKED` 只是可选的领取实现手段，不替代状态、版本与领取代次校验。续租使用权威存储时间，不能依赖 Worker 本地时钟；存储或时间无法确认时停止签发新资格，已发外部动作仍按原操作核对。

<a id="data-families"></a>
## D. 数据族与访问路径参考

下表承接既有生产布局建议，用于说明索引和保留责任，并非已经发布的 DDL。具体表名、索引组合与分区粒度还需按负载验证；各 Store 的原子组不能为物理布局便利而拆散。

| 数据族 / 建议表族 | 主要键与读写路径 | 分布与索引 | 生命周期与恢复要求 |
| --- | --- | --- | --- |
| 当前任务 `task_current` | `(namespace, task_ref)`；按版本/owner 条件更新，按用户列任务 | Home shard；用户、状态、更新时间及稳定引用组成适用索引 | 活跃状态保持紧凑；历史正文外置，终态保留摘要及仍需核对的关联。 |
| 持久工作 `work_items` | 任务内局部工作键；ready 时间、优先级、领取代次/期限 | 与 RunStore 共事务；ready/待恢复状态的部分索引，选定用户后短事务领取 | 完成前不得归档唯一工作；过期领取进入核对，不重新创造动作。 |
| 操作/提交回执 | namespace、接纳窗口、operation_id；提交另按对象及 change_id 查询 | 各接纳权威内唯一索引；活跃账本不按日期拆散唯一性 | 语义摘要、接纳状态、结果引用和有效范围至少覆盖允许恢复期；关闭水位先持久化再清理明细。 |
| 执行与资源控制 | 原 operation_id；资源范围、控制版本、启动准备/效果 | 同一受控资源与启动原子组共分片；未决状态索引 | 启动和许可消费一起提交；未决效果保留至核对或明确处置。 |
| 用户及任务预算 | 用户账本、原额度分配、任务内预留/消费 | 用户归属分片；条件更新和分配唯一键 | 未知消耗不能归零；用户到任务的分配按原操作交接。 |
| 记忆与来源依赖 | collection/record 引用、revision；来源到派生对象的反向引用 | namespace 和集合内查询；按可见修订建索引 | 当前记录、墓碑、变更日志同事务；删除进度和派生清理单列。 |
| 授权与界面 | Grant/Policy revision；Surface revision、ActionRoute | 各自 Store 的局部原子组；等待项及原操作索引 | 权限/界面快照可恢复，业务等待项仍在其原权威消费。 |
| Inbox / Outbox | 流世代/seq、message_id、operation_id 和聚合修订 | 与对应业务原子组共库；待发送/未处理部分索引 | 可靠消费及连续水位持久保存；Kafka 保留期不能替代未结交接责任。 |
| 追加历史与诊断 | namespace、聚合引用、局部项次/时间；按对象和时间查 | 每个物理分片内按时间分区；具体粒度由体量/查询验证 | 到期前确认恢复、评测及隐私条件；正文不进入无界热表。 |
| 附件、截图、产物与归档 | 受控对象引用、内容摘要、版本、驻留策略 | 对象存储；元数据仍在所属 Store，下载独立授权 | 先暂存并验证再发布引用；孤儿清理、历史版本和备份删除分别推进。 |
