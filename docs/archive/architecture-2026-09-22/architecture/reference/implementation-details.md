## A. 拟议包组织与公共类型

以下是拟议包组织，名称尚未成为已发布 SDK。一个职责模块可以包含多个包，也不必拥有独立的 `go.mod` 或进程。

| 位置示意 | 对外保留什么 | 实现留在哪里 |
| --- | --- | --- |
| `domain/` | 稳定标识、领域值与错误语义。 | 不引入 SQL、网络连接或供应商类型。 |
| `runtime/` | 任务入口、运行契约，以及本模块消费的存储和调度接口。 | 状态转换、准入和恢复细节放所属实现包。 |
| 各系统包 | `brain/`、`memory/`、`execution/` 等公开必要接口。 | 各系统自己的算法、检查点、索引与驱动管理。 |
| `adapters/` | 提供满足接口的构造入口。 | SQLite、bbolt、模型、设备和协议实现分别组织。 |
| `cmd/` 与组装包 | 解析配置、选择实现、连接依赖、管理生命周期。 | 核心模块不反向导入启动入口。 |

可供外部开发者实现的接口和类型必须可导入，不能全部藏进 `internal/`；不需要对外承诺的协调逻辑可以放入内部包。生成的协议消息及客户端／服务端绑定另行组织，传输 Adapter 负责与领域类型转换，核心无须按网络报文形状编写业务逻辑。

<a id="bbolt"></a>
## B. bbolt 持久化与快照限制

bbolt 的文件事务只是实现手段。Adapter 还需完成条件更新、版本与资格检查、幂等回执、墓碑、水位及可靠交接；同一模块的一次原子提交必须落在同一文件事务内。一个文件由一个读写进程持有，其他进程按需经受控 gRPC Adapter 访问；默认组装仍可直接嵌入进程。

参考实现使用 `Update`，保持同步配置，事务内不调用模型、网络或设备。事务前有界排队；开始提交后，请求超时不证明未提交。持久化 I/O 出错时停止该单元新变更，受控恢复后核对耐久回执，不凭故障进程里的缓存报告成功。

长读、快照、索引重建、文件增长及排队都需要容量和时限，文件大小上限不等于进程内存上限。跨请求分页使用固定快照与变更边界；每页另开读视图不能冒充同一快照。索引未就绪时明确返回限制或执行有界扫描。原语、同步及平台限制的来源见[第二持久后端研究](../../research/harness-second-persistent-backend.md)。

## C. 依赖及首个支持范围

| 对象 | 已定基线或锁定入口 | 实现时要记录什么 |
| --- | --- | --- |
| Go | 最低 1.25.0。 | 经验证的具体补丁、构建环境、完整依赖图及 `go.mod`／`go.sum`。 |
| SQLite | 默认持久化；具体驱动与运行版本在实现时锁定。 | 事务、同步、文件系统及重启测试配置。 |
| bbolt | v1.5.0；完整提交见后端研究。 | 首个范围为 Linux amd64、本地文件系统；记录内核、挂载、同步、容量和已知问题核对。 |
| Wasm | wazero v1.12.0、显式 Interpreter。 | 首个范围为 Linux amd64；锁定宿主 ABI、可用接口和资源限制。 |
| MCP | Go SDK v1.7.0，目标协议 2026-07-28。 | stdio／Streamable HTTP 双角色；无状态 HTTP、严格版本及取消映射的适配，首期不启用 Tasks。 |
| A2A | Go SDK v2.5.0，协议 1.0，文字规范补丁 v1.0.1。 | HTTP＋JSON 双角色；媒体类型、结构化错误及独立对端证据。 |
| Skill 与生成契约 | 固定格式快照、内容摘要、Proto／Schema 和生成器。 | 每份资产的实际内容、兼容配置；规范版本与 SDK 版本分别保存。 |
