<a id="catalog"></a>
## A. 目录查询与修订

能力目录通过 `CapabilityService` 提供服务，内部以 `CapabilityCatalog` 接口隔离目录存储和检索实现。调用方用 `List` 逐页读取获准能力；分页游标记录下一页从哪里继续，只适用于绑定的授权视图和目录修订，失效后需要重新枚举。

`Search` 用于查找候选，并说明查询覆盖了哪些范围；`Describe` 用于取得指定版本的准确声明，版本不可用就明确报告。

目录缓存按授权视图和目录修订隔离，权限变化后重新过滤；缓存命中不免除当前授权检查。检索分数表达各实现自己的排序依据，不能跨实现直接当作可比置信度。

<a id="driver"></a>
## B. Driver 方法与事实边界

| Driver 方法 | 做什么 | 不能据此推断什么 |
| --- | --- | --- |
| `Start` | 接收原操作、固定版本、受控输入与执行资格，返回已知未开始、进行中或完成等事实。 | 返回一个作业号不表示文件已经保存。 |
| `Inspect` | 依据原操作及已保存的外部关联，查询或核对现有工作。 | 查询不能暗中重新执行保存。 |
| `Cancel` | 请求停止并提供能够确认的状态；不支持时明确说明。 | 请求被接受不表示已经停止，也不撤销已发生效果。 |

<a id="validation"></a>
## C. 模拟环境与独立验证

| 验证层面 | 所需证据与边界 |
| --- | --- |
| API 契约与替换 | 两种外部接口形态不同的有状态后端，由独立 Adapter 映射到同一代表性能力契约并复用测试。第二种不必复制完整千级目录；两个相同实例不算独立替换。 |
| 手机 GUI | 多个独立设备状态，结构树与图像／坐标两类驱动；覆盖点击、滑动、输入、返回、前提失效、再观察和效果核验。 |
| API／GUI 协同 | 共享业务状态的组合对象验证 API 优先、适用切换、防重复和跨路径接管；两种路径本身不等于同一契约的独立实现。 |
| 故障与恢复 | 注入提交前后崩溃、启动回执或作业号丢失、重复和乱序报告、取消竞态、接管后重启及旧 Worker；证据不足时保持未知。 |
| 跨节点与数据限制 | 使用实际多进程 gRPC、WebSocket 验证故障，分别持久化状态；私有截图、输入和日志不从禁止的出口离端。 |
| 实际质量 | 真实模型另测选能力、填参数、理解图像及任务完成；脚本化大脑只能证明相应契约与状态处理。 |

测试判定器可读取模拟环境内部业务状态，核对最终内容及重复变更次数；大脑只能读取正式接口允许的观察。图像驱动不能暗取测试专用控件答案。模拟环境无需完整模拟手机操作系统，也不证明真实 Android、iOS 平台已获支持；未来真实 Adapter 另行声明并验证范围。

<a id="resource-control"></a>
## D. 资源控制接口

`GetResourceControl` 查询获准可见的控制意图、落实进展和局部版本。`RequestResourceControl` 以稳定操作、资源范围、预期版本及授权提交 `TAKEOVER` 或 `RESUME`；原请求重试返回原接纳回执，新请求才按当前版本竞争。针对单次调用的接管入口，也要落实到对应资源范围。
