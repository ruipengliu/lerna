# 端云协同：可靠流与跨节点验证细则

本资料供实现可靠连接、保留窗口和跨节点测试时查阅。任务权威、消息接收位置和记忆修订各自管理，任何一个都不能替代其他资格。

验证矩阵沿用正文的摘要任务 T：S 在电脑保存摘要，J 是对应的外部作业，R 在保存效果确认后读回文件。数据驻留分支中的 E2《需求说明》原文只允许留在电脑；其他位置仅能取得该分支明确允许的输出。

## A. 连续接收、窗口与有限保留

可靠流按发送方向记录**已持久化的连续接收前缀**。例如已保存第 41、43 条，但第 42 条缺失，只能累计确认到 41；这里的数字仅作顺序演示。乱序消息可以有界暂存并请求补投，不能跨过缺口确认。心跳、临时事件和无需重放的回执不占用这条可靠序号空间，各流也不承诺全局顺序。

`PERSISTED` 只说明接收记录已落盘。接收模块还要扫描未处理 Inbox，将操作登记、状态变化、消费标记和回复 Outbox 在自己的原子边界中提交；不同存储模块之间沿原操作幂等转交并核对，不假设跨库事务。基础交接过程见[2.1 任务运行内核](../main/02-subsystems/01-runtime-kernel.md)。

| 有限保留的对象 | 过期或容量不足时的边界 |
| --- | --- |
| 消息补投记录 | 超出保留范围就明确报告缺口，以快照和原操作核对恢复；关闭旧流、记录恢复边界后再建立新位置。 |
| 操作与内部提交核对记录 | 至少覆盖仍允许恢复或重试的生命周期；消息日志清理不能连带删除尚需履约的结果依据。 |
| 操作接纳窗口 | 决定旧操作还能否首次受理；关闭水位持久化且恢复义务结束后才清理明细，旧 ID 不能因“查不到”再次首次执行。 |

接纳窗口规定旧操作最晚何时还能首次受理，并绑定受信发起作用域和操作身份。**关闭水位**记录哪些旧窗口已经不再接纳新操作；即使操作明细后来被清理，处理端仍据此拒绝把旧请求当成新操作执行。只有关闭水位已持久保存，且相关恢复义务已结束，才可清理明细。

重连不重开窗口，传输层也不能把过期请求换成新 ID。窗口关闭不取消已接纳的长任务，其继续执行仍受自己的授权、控制和期限约束。**可否首次接纳**与**可否执行**是两项检查，不能共用一个到期判断。

有界队列已满时应背压或拒绝新受理，不能静默丢弃已受理工作所需的可靠控制。优先调度不能消除已经排队字节的阻塞，因此大块传输还要限制分块；任务、操作与流分别恢复，某个窗口或设备失联不应阻塞整个节点的无关工作。

## B. 跨位置验证矩阵

| 验证方向 | 必须观察到的结果 |
| --- | --- |
| 位置与替换 | 本地、云侧协调和端云组合沿用共同契约；能力缺失有明确反馈，不固定某系统只能部署在云侧。 |
| 移交故障窗口 | 在准备、封存、激活及回执处重启或丢包，T 始终只有一个有效推进方；旧 Worker 不能提交或越权启动新动作。 |
| 离线条件 | 本地能力齐备时完成 S／R；远端依赖、许可到期、时间异常及离线重启分别按声明边界等待或受控恢复。 |
| 消息与清理 | 重复、乱序、Inbox 落盘后重启、队列满及窗口过期不漏掉已受理工作，不将旧操作变成新动作。 |
| 真实结果与交付 | 文件内容实际变化且独立读回；重连沿原 S／J 核对，手机呈现反馈与本地保存分别取证。 |
| 数据驻留与出口 | 云数据库、索引、模型请求、消息、日志和缓存没有禁止外发的 E2 内容；只出现获准投影，受控引用不能越权取全文。 |
| 联合检索与提取 | 原文在本地影响结论，有限输出可用；离线不伪造零命中，不泄露隐藏存在性，提取及保存不超出授权。 |
| 记忆与控制收敛 | 修订冲突、快照重建、删除、撤销及暂停取消在恢复后仍有效；实际应用、待传播和无法核对分别呈现。 |
