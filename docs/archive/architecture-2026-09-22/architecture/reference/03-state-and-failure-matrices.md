## 1. 怎样从一个故障找到应核对的记录

故障表的第一列同时给出初始条件和注入点，第二列给出允许的处理及条件不足时的去向。每行的编号只用于文档与用例追溯，例如 `EXE-03`；它不是操作 ID、错误码或新协议字段。编号不因新增用例重排，含义改变时另建条目并保留替代关系。

沿用[摘要任务](../examples/README.md#example-task)：T 是任务，S 是保存操作，J 是电脑上的异步作业，R 是读回操作，D 是《项目进展摘要》。以下分支中 S／R 已准入，电脑已持久保存 S／J 关联，但云侧没有收到保存接纳回包；R 仍等待保存确认，当前授权、控制和预算允许核对。

1. 定位 [EXE-03](#exe-03)：原作业关联已保存，回包丢失。
2. 选择核对入口：云侧向电脑执行模块查询原 S；必要时安排 Reconcile，由该模块沿 J 调用 Driver.Inspect。
3. 按证据选择分支：J 仍运行则等待；效果不明则保留核对责任；确认保存成功且当前条件满足后，继续原 R。
4. 排除禁止结果：不得新建一次保存、把超时直接写成失败，或跳过读回就宣布交付。
5. 收集证据：关联 T、S、J 和原 R，比较执行记录、实际文件、结果交接及手机交付记录。界面显示“运行中”不足以证明续跑。

其他行各自从其第一列的条件开始。例如“启动回包连同 J 一起丢失”是另一故障窗口，不能套用本例已有 J 的前提。状态图可配合[任务状态图](../diagrams/04-task-state.html)阅读；本篇的转换表补足并发条件和持久责任。

<a id="common-rules"></a>
### 1.1 所有矩阵共同适用的条件

每条故障行都继承下列条件。行内未重复列出授权、资格或预算时，也不能省略检查；“允许恢复”只在这些前提仍成立时适用。

| 共同条件 | 查表时必须保留的含义 |
| --- | --- |
| 当前资格 | 身份、namespace、目标权限、用途与数据位置有效；状态提交还检查当前权威、预期版本及适用领取代次。 |
| 后续工作 | “条件满足后继续”包含当前控制、依赖、来源、预算、硬期限及适用耐久屏障；恢复不自动续期、增权或清零用量。 |
| 原身份 | 转交和核对同一意图保持 operation_id；同一内部提交保持所属 Store 的 change_id。新查询使用新消息身份，指向原操作。 |
| 重复与新操作 | 当前结果披露授权检查后，先核对已有操作及语义；只有真正的新操作才应用首次接纳、版本和等待项条件。 |
| 未知结果 | 一次查询未找到、回执过期或一次调用超时，都不足以证明未执行；须核对覆盖范围及旧请求是否仍可能生效。 |
| 原子边界 | 各 Store 只对自己的原子组负责。跨组保存交接责任，沿原操作查询；外部动作在事务外。 |
| 证据与披露 | 表中“核对证据”指获准取得的权威记录、实际效果和受控引用；诊断日志只是辅助，已删除或禁止披露的正文不因恢复重新返回。 |
| 等待与升级 | 自动核对有次数、期限和处置预算上限；耗尽后保留明确待处理责任。人工处置也不能把未知效果改写成未发生。 |

字段位置及原子组见[附录 01](01-data-model.md#atomic-retention)，具体查询入口见[附录 02](02-api-and-message-catalog.md#delivery-recovery)。

### 1.2 先分清是哪一种状态

主任务、外部执行、交付和管理流程分别报告自己的事实。相同的“完成”字样可能指不同对象，核对转换前须先确定当前记录的维度和确认方。

| 维度 | 已有取值或精度 | 由谁确认 |
| --- | --- | --- |
| Task 主状态 | QUEUED、RUNNING、WAITING、COMPLETED、FAILED、CANCELLED。 | 当前任务内核经 RunStore 提交。 |
| 等待与任务控制 | 等待原因可并存；INPUT、DEPENDENCY、AUTHORIZATION、RECONCILIATION 是示例。控制意图为 RUN／PAUSE／CANCEL。 | 等待归所属分支；任务内核保存控制来源和落实进展。 |
| 工作进展、内部提交 | 已登记、领取、下一次检查等为行为阶段；提交有确认、拒绝／冲突、未知等确定性。 | 所属 Store；没有统一 Work 或 CommitStatus 完整枚举。 |
| 消息与业务回执 | PERSISTED 表示持久接收；ACCEPTED 表示业务接纳。 | 接收方与业务处理模块分别负责。 |
| 执行事实 | 阶段、结果、效果三个维度，见[执行表](#execution-states)。 | 执行模块保存 Driver 及目标证据。 |
| 交互与呈现 | 等待有效、消费、撤销等为业务阶段；PresentationStatus 是呈现报告契约。 | 等待项归业务模块，显示修订归 SurfaceStore。 |
| Owner 管理 | ACTIVE、PREPARING、SEALED。 | 所有权记录；与任务主状态分别表达。 |
| 授权、扩展、发布 | 按签发／消费、准备／激活、评测／启用等阶段表达，无统一英文状态全集。 | 各管理模块保存决定，接收节点另报应用事实。 |
| 评测与放行 | 运行：QUEUED、RUNNING、WAITING、COMPLETED、CANCELLED；gate_result：PASS／FAIL／INCOMPLETE。 | EvaluationStore 保存运行与判定，Evolution 决定发布。 |
| 生产恢复 | DETECT、CONTAIN、ESTABLISH、RECONCILE、RESUME、VERIFY 为参考运维阶段。 | RecoveryController 协调；业务状态仍归原模块。 |

### 2.1 任务主状态转换

下表的转换均需成功提交；数据库不可写时只能展示最后确认版本及陈旧性。等待原因按分支保留，有其他可推进分支时任务仍可 RUNNING。

| 当前状态 | 触发与必要条件 | 后续状态及持久责任 |
| --- | --- | --- |
| 不存在 | Submit 首次获准，原子保存任务、操作回执和待处理工作。 | QUEUED；原操作重复提交返回同一任务。 |
| QUEUED | 控制允许运行，当前 Owner／Worker 有资格，存在可执行工作。 | RUNNING。 |
| QUEUED／RUNNING | 所有可调度工作均受输入、依赖、授权或核对条件阻碍。 | WAITING，保存全部有效等待原因及恢复入口。 |
| WAITING | 至少一项工作条件满足，控制为 RUN，取得有效领取资格。 | QUEUED 或 RUNNING；其他分支的等待仍保留。 |
| 任意非终态 | PAUSE 已接纳。 | 阻止新工作；仍有在途时可 RUNNING，停稳后 WAITING；另报暂停落实。 |
| 暂停中／已停稳 | 新恢复操作获准，解除指定暂停来源。 | 按 CANCEL 优先、其后有效 PAUSE、最后 RUN 重算控制；恢复不解除取消。 |
| 任意非终态 | CANCEL 已接纳。 | 停止新增目标工作，传播取消；按在途与核对情况保持 RUNNING 或 WAITING。 |
| 任意非终态 | 目标、必需结果及交付满足，所辖工作处置完成，完成提交赢得版本检查。 | COMPLETED，保存证据；迟到取消说明任务已完成。 |
| 任意非终态 | 已确认目标无法完成，必要在途处置结束，关键效果已核清。 | FAILED，保留原因及已发生效果。 |
| 非终态且取消处理中 | 应停止工作已停止或处置完成，关键效果已核清。 | CANCELLED，保留实际影响与控制落实结果。 |
| 任一终态 | 迟到回复、重启、重复请求或新输入。 | 保持终态；合法查询返回原结果，新增目标另建任务。 |

取消先持久化后不得再追加完成目标的新动作；若取消生效前既有工作已经完成，内核核对充分证据后仍可记录 COMPLETED，并说明取消未阻止完成。关键效果未知时继续核对，不按消息到达顺序选择终态。

### 2.2 工作领取与提交阶段

| 当前阶段 | 推进条件 | 后续责任 |
| --- | --- | --- |
| 决策工作待处理 | 条件领取并持久预留生成额度。 | 使用该次提交后的任务版本组装输入，事务外调用模型。 |
| 已生成完整提案 | 校验结构、来源、能力和预算；原子复核任务版本、控制与资格。 | 准入时共同保存操作映射、依赖、工作和回执；拒绝时结算已知用量。 |
| 提交结果未知 | 以原 change_id 查询所属 Store。 | 确认前不派发、不为同一意图另行生成操作。 |
| 工作已持久登记 | 扫描到期候选，重新校验并领取。 | 只在有效代次下处理；通知丢失仍可发现。 |
| 本轮需等待外部条件 | 保存等待对象、下次检查或其他可恢复入口。 | 与本轮完成更新共同提交，主动释放 Worker；外部占用继续保留。 |
| Worker 崩溃／租约失效 | 新领取者取得合法代次。 | 先查原提交、操作及在途效果，再决定后续工作。 |
| 结果已确认 | 当前权威幂等消费结果，检查依赖。 | 原子保存任务变化与后续工作；旧处理者不能覆盖。 |

### 2.3 运行故障矩阵

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="run-01"></a>**RUN-01** Submit 已提交；丢失创建回包并重复提交。 | 核对原创建操作，恢复同一 T 及工作。 | 多建任务；任务存在却无待处理责任。 | 创建回执、task_ref、任务与工作记录。 |
| <a id="run-02"></a>**RUN-02** 两个 Worker 竞争同一工作；旧领取者迟到提交。 | 仅有效代次推进；旧效果证据交当前负责者核对。 | 旧代次覆盖新状态；据写入拒绝认定无外部效果。 | 领取代次、提交前提及执行记录。 |
| <a id="run-03"></a>**RUN-03** 已保存下次检查与本轮完成；丢失唤醒通知。 | 扫描到期原工作，条件领取并核对原操作。 | 必须等旧租约超时才正常轮询；重建保存动作。 | 原工作、下次检查时间、领取与查询记录。 |
| <a id="run-04"></a>**RUN-04** 生成额度已预留，模型返回前进程退出。 | 先核对准入情况；确无准入且额度允许时重新生成。 | 丢失输出被执行；未知模型用量归零。 | 原生成预留、准入查询、供应商可得用量。 |
| <a id="run-05"></a>**RUN-05** 模型输出仅有半截参数，或完整提案尚未准入时中断。 | 恢复／重新生成并重新校验；保持草稿身份。 | 流式参数触发动作；草稿直接成为正式结果。 | 输出完整性、准入记录、执行端启动记录。 |
| <a id="run-06"></a>**RUN-06** 提案基于旧版本；正式输入或结果先推进任务。 | 拒绝旧提案，基于当前事实重新决策，结算原用量。 | 自动覆盖新要求；为减少冲突隐藏事实更新。 | 输入基线、当前 state_version、拒绝及预算记录。 |
| <a id="run-07"></a>**RUN-07** 准入提交可能成功；回执丢失。 | 查原 change_id；成立则恢复原映射，不成立须有充分确认。 | 查一次未找到就重新规划；确认前派发。 | 提交回执、语义摘要、原 S／R 与工作。 |
| <a id="run-08"></a>**RUN-08** 有限批次含非法动作／依赖；尝试准入。 | 拒绝该批运行记录；获准修正仍受原预算限制。 | 非法批次半数准入；模型自行扩大额度。 | 提案校验结果、原子组及预算差额。 |
| <a id="run-09"></a>**RUN-09** 合法批次已准入；其中一项外部动作明确失败。 | 保留已发生效果，阻止依赖其成功的后续工作。 | 宣称外部动作一起回滚；抹去已完成事实。 | 依赖图、各操作结果及效果。 |
| <a id="run-10"></a>**RUN-10** 暂停／取消与领取、完成提交并发。 | 按版本与控制检查确定接纳顺序，再核对在途事实。 | 控制后新增目标动作；仅因取消受理写 CANCELLED。 | 控制提交、启动登记、完成证据及落实进展。 |
| <a id="run-11"></a>**RUN-11** 预算或硬期限耗尽，仍有未知效果。 | 停止新目标工作；仍接纳合法控制，用有限处置额度核对，不足则显式等待。 | 目标预算封死控制入口；重启延长时限；伪造终态。 | 原期限、已用／未结预留、控制接纳与处置工作。 |
| <a id="run-12"></a>**RUN-12** 任务已终结；迟到报告或旧输入到达。 | 按当前权限保留必要事实／返回原结果，维持终态。 | 自动重开旧任务或重新执行已完成步骤。 | 终态版本、原操作回执、迟到事实来源。 |

### 3.1 从接收到业务处理的阶段

| 当前阶段 | 推进条件 | 后续责任 |
| --- | --- | --- |
| 准备发送 | 意图／业务变更与 Outbox 一起提交。 | 投递原消息；未确认交接的载荷仍可恢复。 |
| 接收消息 | Inbox 保存原消息、来源、指纹、流位置和待处理标记。 | 可回复 PERSISTED；扫描器仍须找到未处理项。 |
| 同一 Store 内业务处理 | 原子保存去重、状态、Inbox 消费和回复 Outbox。 | 可报告业务接纳，后续执行另行确认。 |
| 跨 Store 转交 | 目标以同一操作身份接纳，发送方核对其结果。 | 确认后完成转交标记；短暂投影滞后可恢复。 |
| 可靠流出现缺口 | 有界暂存乱序消息，补投缺口。 | 仅推进已持久化连续前缀。 |
| 缺口已不可补投 | 按快照／原操作核对，持久记录旧流恢复边界。 | 关闭旧流后建立新位置；业务未决责任继续保留。 |

PERSISTED 回执丢失可从接收记录重建，不递归要求它自己的持久确认。临时事件、心跳和无需重放的回执不占可靠流序号，避免产生无法补齐的假缺口。

### 3.2 交付故障矩阵

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="msg-01"></a>**MSG-01** Inbox 已持久接收并回复 PERSISTED；业务处理前退出。 | 扫描未处理 Inbox，按原操作继续准入。 | 回执已发却永久丢失业务处理责任。 | Inbox 未处理标记、扫描结果、业务回执。 |
| <a id="msg-02"></a>**MSG-02** 同库消费消息时在事务任一点中断。 | 查原提交；状态、消费标记和回复共同成立或共同不成立。 | 已消费但状态未改；状态已改却无回复责任。 | 原子组、提交回执、重启后记录。 |
| <a id="msg-03"></a>**MSG-03** 跨库目标已接纳；发送方标记转交完成前退出。 | 查询或补交同一操作，补齐转交与投影。 | 换操作 ID 再写一次；假定两库共同提交。 | 两侧原操作关联、目标回执、待转交记录。 |
| <a id="msg-04"></a>**MSG-04** Outbox 已发出；对端回执丢失。 | 补投原消息，对端按原消息及操作去重。 | 重新构造一次业务意图；递归确认链无界增长。 | message_id、Inbox、操作回执及交付位置。 |
| <a id="msg-05"></a>**MSG-05** 同一操作 ID 改了目标、期限或输入，或被送往错误权威。 | 拒绝身份冲突／错误路由，必要时转回原权威。 | 两个模块分别首次接纳同一 ID 为不同含义。 | 受信窗口、接纳权威、固定语义摘要。 |
| <a id="msg-06"></a>**MSG-06** 可靠流缺一项，后续消息先到。 | 有界缓存并补读；缺口前连续位置保持。 | 越过缺口累计确认；按到达顺序覆盖新事实。 | 单向流位置、缺口、持久接收前缀。 |
| <a id="msg-07"></a>**MSG-07** 断流后原补投范围过期。 | 快照与原操作核对，记录旧流关闭边界。 | 假装原序列连续；把无法重放等同业务未发生。 | 可补读范围、快照版本、未决操作清单。 |
| <a id="msg-08"></a>**MSG-08** 可靠队列已满；又有新输入或结果到达。 | 未接纳前明确背压／拒绝；已接纳责任持久保留并限流。 | 静默丢重要结果；删除未履约记录腾空间。 | 接纳边界、积压水位、保留载荷与拒绝记录。 |
| <a id="msg-09"></a>**MSG-09** 无共同协议版本、缺必需能力或收到非法类型。 | 按固定契约拒绝；原已接纳工作仍沿原记录恢复。 | 默默降低必需语义；解析失败触发新副作用重试。 | 协商结果、编码拒绝、原操作查询结果。 |

## 4. 执行事实、资源接管与 GUI

**正文：** [2.4 能力与执行](../main/02-subsystems/04-tools-and-devices.md)。**设计依据：** [执行与资源契约](../../archive/architecture-v1/07-execution-contracts-and-validation.md)、[执行事实维度](../../archive/architecture-v1/12-data-path-and-protocol-semantics.md)。

<a id="execution-states"></a>
### 4.1 执行的三个维度

| 维度 | 正式取值 | 如何随证据变化 |
| --- | --- | --- |
| 阶段 phase | NOT_STARTED、IN_PROGRESS、FINISHED、UNKNOWN。 | 依据可靠启动与进展事实更新；准备后崩溃且发送不明，不能推断 NOT_STARTED。 |
| 结果 result | SUCCESS、FAILURE、UNKNOWN。 | 按能力契约记录调用结果；结束或返回成功仍需另查效果。 |
| 效果 effect | NOT_APPLICABLE、UNVERIFIED、CONFIRMED、CONTRADICTED。 | 按适用性和实际核对证据报告；不能为收尾强行改成 CONFIRMED。 |

这三个集合不组成一条线性状态链，现有基线也未穷尽全部组合。能力实现须说明适用组合、结果依据和不可核对范围。已确认完成不被迟到的“处理中”覆盖；相互矛盾的终局证据保留来源，进入核对。

| 当前阶段／控制 | 推进条件 | 后续责任 |
| --- | --- | --- |
| 已接纳，尚未准备调用 | 当前资格、授权、输入位置、资源控制和额度有效。 | 先持久保存“已准备，可能发出”，再事务外调用。 |
| 已准备，调用结果不明 | 核对原提交与原操作；具备有效外部幂等或充分未执行证据才允许安全重发。 | 无法确定则保留未知，安排有界核对。 |
| 已获外部作业 J | 持久保存 S／J 关联及查询责任。 | 沿 J 查询／接收受控回调；Worker 更换不重新 Start。 |
| 效果已确认 | 保存结果、证据与报告 Outbox。 | 补交原结果，依赖方幂等消费。 |
| TAKEOVER 已接纳 | 与该范围新启动登记串行化；先登记的动作列入在途。 | 拒绝新冲突动作；停稳或处置完成后报告接管落实。 |
| RESUME 获准 | 控制版本、未决动作及当前任务条件满足。 | 重新观察并决定后续动作；保留任务自身暂停／取消。 |

### 4.2 执行故障矩阵

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="exe-01"></a>**EXE-01** 接纳或启动准备提交结果未知；外部调用尚未确认可发。 | 查 ExecutionStore 原提交，确认持久责任及当前资格后处理。 | 用 RunStore 回执替代执行提交；未知时先发调用。 | 执行 change_id、准备记录、适用耐久确认。 |
| <a id="exe-02"></a>**EXE-02** 已准备调用；目标可能生效，启动回包及 J 丢失。 | 按原幂等键／可证明业务关联核对；安全重发仅限声明有效的保证。 | 据未记录 J 判断未执行；新建同义动作。 | 原 S、目标幂等范围与期限、业务效果。 |
| <a id="exe-03"></a>**EXE-03** S／J 关联已保存；接纳回包或查询回包丢失。 | 查询原 S，执行模块沿 J 核对；确认依赖后继续原 R。 | 重启即再次 Start；仅凭超时判保存失败。 | S／J 关联、原作业状态、效果及结果交接。 |
| <a id="exe-04"></a>**EXE-04** 目标只给随机作业引用；该引用丢失且无其他核对能力。 | 保持效果未知，记录能力缺口，进入有限核对／有权处置。 | 宣称可自动恢复；切换 API／GUI 重做。 | 能力声明、丢失窗口、无法核对原因。 |
| <a id="exe-05"></a>**EXE-05** 保存效果和报告已持久化；报告未交完时退出。 | 从原 Outbox 补交，接收方幂等更新依赖。 | 再保存 D；把报告丢失变成动作失败。 | 效果证据、报告修订、Outbox 与消费记录。 |
| <a id="exe-06"></a>**EXE-06** 已确认完成后收到旧进度，或收到矛盾终局报告。 | 旧进度不倒退事实；矛盾证据另行核对并保留来源。 | 最后到达者直接覆盖终局事实。 | 来源身份、报告修订、两份终局证据。 |
| <a id="exe-07"></a>**EXE-07** 作业完成与取消并发，或 Driver 声明不可取消。 | 记录取消接纳与实际结果，跟踪仍在途工作。 | 把 Cancel 返回当作已停止；提前释放占用。 | 取消回执、J 最终状态、资源与效果记录。 |
| <a id="exe-08"></a>**EXE-08** 幂等键已过期；查询未找到原写入。 | 检查查询覆盖及旧请求是否可能迟到；不足则保持未知。 | 将“未找到”作为安全重做的唯一证据。 | 外部保留范围、幂等有效期、旧请求处置证据。 |
| <a id="exe-09"></a>**EXE-09** 同资源 API／GUI 启动与用户接管并发。 | 控制范围内串行裁决，先启动者纳入处置，后启动者受阻。 | 只停当前 GUI 调用，另一路继续改同一资源。 | 资源映射、控制版本、启动登记与在途集合。 |
| <a id="exe-10"></a>**EXE-10** 接管已接纳后重启；旧 Worker 或旧 RESUME 迟到。 | 恢复接管状态；拒绝旧资格／版本，核对迟到效果。 | 重启解除接管；恢复资源时清除任务取消。 | 接管回执、当前控制版本、任务控制来源。 |
| <a id="exe-11"></a>**EXE-11** GUI 动作前界面变化、弹窗或人工改动使观察过期。 | 拒绝失效前提或报告驱动竞态限制；重新观察。 | 继续旧截图坐标；为重试改写原操作参数。 | 观察时间／版本、动作前提、新观察与效果。 |
| <a id="exe-12"></a>**EXE-12** GUI 追加输入可能生效但回执丢失。 | 核对原动作与实际字段；证据不足保持未确认。 | 重复追加；用成功提示证明恰好写入一次。 | 输入模式、原动作、字段变化及关联证据。 |

资源控制只覆盖声明的 Harness 路径；外部人工或第三方写入通过观察与版本冲突反映。Driver 没有通用 Resume，脚本／作业内部的断点恢复能力须独立声明并验证。

## 5. 等待项、正式输入与界面恢复

**正文：** [2.5 应用与交互](../main/02-subsystems/05-interaction.md)。**设计依据：** [UI 契约](../../archive/architecture-v1/03-ui-interaction-contracts.md)、[SurfaceStore 与 ActionRoute](../../archive/architecture-v1/12-data-path-and-protocol-semantics.md#4-补齐独立-ui-的状态权威与存储)。

### 5.1 业务等待与显示分别推进

| 当前阶段 | 触发与条件 | 后续事实 |
| --- | --- | --- |
| 等待项有效 | 所属 Task、Authorization 或登记应用模块接受合法新回应。 | 原子消费等待项并保存业务结果；不同新操作不能重复消费。 |
| 等待项被消费／撤销／过期 | 原回应重试或新回应到达。 | 原操作查询原结果；新输入明确已处理／失效，不绑定新等待点。 |
| UI 尚无该操作路由 | 新 SubmitAction 的事件、Schema、权限和适用版本有效。 | SurfaceStore 固定规范化意图、原身份、目标和映射版本，保存转交责任。 |
| 路由已保存，业务未确认 | 原操作转交／查询目标模块。 | 业务接纳后补齐 UI 投影；路由存在本身不证明业务已接纳。 |
| 显示状态有新修订 | 补丁 base_revision 匹配，或取得当前快照。 | 原子应用显示更新；Renderer 通过 PresentationStatus 报告其状态。 |
| Surface 关闭 | 界面关闭决定生效。 | 保留原业务及核对责任；新窗口用新键或明确新世代。 |

这些是阶段规则，没有新增 Interaction 枚举。独立表单可没有 task_ref；UI 自有偏好可由登记的 SurfaceStore 业务处理，其他等待项仍归原模块。普通任务确认、授权批准和后续保存分别使用其正式契约。

### 5.2 交互故障矩阵

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="ui-01"></a>**UI-01** ActionRoute 已保存；转交目标前 UI 进程退出。 | 扫描原路由，按固定目标和版本转交同一操作。 | 依赖原内存订阅；生成新的提交身份。 | 路由、规范化摘要、待转交工作。 |
| <a id="ui-02"></a>**UI-02** 业务已消费输入；UI 更新投影前退出。 | 查询原业务操作，恢复结果显示。 | 因等待项已关闭把原重试误判为新非法输入。 | 业务回执、等待项消费、Surface 修订。 |
| <a id="ui-03"></a>**UI-03** 原操作未决；事件映射升级或原窗口关闭后再次查询／重试。 | 当前鉴权后沿原路由恢复；新界面只呈现获准结果。 | 按新事件定义重新解释旧输入或重绑目标。 | 原映射／Schema 版本、目标、输入摘要。 |

| <a id="ui-05"></a>**UI-05** 新点击引用已撤销或过期等待项。 | 拒绝失效输入，展示当前有效状态。 | 自动续期；把旧回答用于新问题或增权。 | interaction_id、有效期、消费／撤销记录。 |
| <a id="ui-06"></a>**UI-06** 补丁基版本不符，或连接不断但末条临时增量丢失。 | 缺口时取快照；周期版本核对或可靠版本通告发现末条遗漏。 | 盲套补丁；只能等待下一条消息暴露问题。 | 当前修订、版本核对／通告、恢复快照。 |
| <a id="ui-07"></a>**UI-07** 重连后旧端点连接／Surface 世代消息迟到。 | 校验端点路由和世代；保留必要业务证据。 | 打开失效界面、串发到另一窗口或重复建任务。 | 认证端点、连接世代、surface_ref 及原任务。 |

## 6. 记忆修订、上下文与删除传播

**正文：** [2.2 上下文、记忆与证据](../main/02-subsystems/02-context-and-memory.md)、[3.4 端云协同与离线运行](../main/03-coordination/04-edge-cloud-coordination.md)。**设计依据：** [数据生命周期](../../archive/architecture-v1/05-memory-data-and-lifecycle.md)、[驻留与联合检索](../../archive/architecture-v1/05-edge-cloud-memory.md)。

### 6.1 修改、删除与同步阶段

| 当前阶段／维度 | 触发与条件 | 后续责任 |
| --- | --- | --- |
| 当前有效记忆修订 | Correct／Delete 首次接纳，预期修订匹配。 | 集合内原子保存新修订／墓碑、操作回执、变更与失效通知。 |
| 删除权威已提交 | 本地普通访问、索引与派生使用受删除决定约束。 | 阻止新使用，异步清理内容；保留获准的最小恢复元数据。 |
| 删除副本传播中 | 各节点实际应用，或按契约退出旧同步世代。 | 分别报告已应用、待应用、不可联系／移出管理；后者不等于已清理。 |
| 派生及备份处理 | 来源依赖已失效，按声明范围清理或重建。 | 混合摘要先整体失效；报告控制范围和备份生命周期。 |
| 上下文已组装 | 模型发送前、返回后、新行动／答案发布前复核适用来源。 | 已知失效则重组／等待；在途效果按原操作处置。 |
| 副本接受增量 | 视图与游标有效。 | 本地应用与游标同事务保存，再报告应用进度。 |
| 视图／游标失效 | 权限、范围改变或历史不可接续。 | 当前获准快照替换该视图，清除残留，隔离未提交意图。 |

删除的权威提交、本地使用、副本传播及派生／归档是不同维度。来源修订也独立于任务版本；任务版本未变仍可能需要重组上下文。在线核验和有限新鲜度范围见原契约，不承诺跨节点全局原子删除。

### 6.2 记忆与来源故障矩阵

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="mem-01"></a>**MEM-01** 两节点基于同一记录修订纠正／删除。 | 最多一个符合版本条件的提交成立；另方重读后形成新意图。 | 按时钟先后无条件覆盖；同 ID 改内容再提交。 | 预期／实际 revision、原操作回执。 |
| <a id="mem-02"></a>**MEM-02** 修改已提交，回包丢失；当前记录后来又被纠正或删除。 | LookupOperation 返回获准历史受理状态，另报当前内容可用性。 | 当前快照无记录就再 Put；回执复现被删正文。 | 原操作、当前修订／墓碑、披露检查。 |
| <a id="mem-03"></a>**MEM-03** 删除已清理输入正文；旧载荷补交时已无法可靠比较。 | 拒绝该补交并指向原操作查询，保留最小状态。 | 为去重保留禁存正文；仅凭 ID 宣称语义一致。 | 清理水位、比较依据可用性、原操作状态。 |
| <a id="mem-04"></a>**MEM-04** 检索／模型生成期间依赖来源被纠正、删除或收紧用途。 | 检查时发现失效则停止发布旧答案／准入提案；重组或等待。 | 沿旧摘要继续新行动；删除历史动作事实。 | 来源依赖、修订、Validate 与准入／发布记录。 |
| <a id="mem-05"></a>**MEM-05** 端侧用户要求删除，但集合权威离线。 | 可先抑制本地使用，正式修改显示待提交，重连核对原意图。 | 显示全局已删除；窗口过期自动换身份提交。 | 本地抑制、待提交操作、权威及传播进度。 |
| <a id="mem-06"></a>**MEM-06** 副本应用变更及推进游标时退出。 | 从共同持久位置重放；应用与游标保持一致。 | 已确认接收消息就冒充副本已应用。 | 本地修订、应用游标、消息接收位置。 |
| <a id="mem-07"></a>**MEM-07** 同步游标过期或分页快照不可接续。 | 从一致边界重建当前视图，清除残留并隔离本地未提交修改。 | 混合不同快照页；把待提交草稿并入权威快照。 | 快照边界、视图世代、增量起点及本地意图。 |
| <a id="mem-08"></a>**MEM-08** 同步权限收缩，但记录正文没有新修改。 | 旧视图失效；接收端应用后清理失去资格的字段／记录。 | 只等普通修改事件发现权限变化；扩大投影覆盖提交。 | 策略修订、视图失效、各副本实际应用。 |
| <a id="mem-09"></a>**MEM-09** 必要来源离线或上下文容量不足。 | 使用获准且足够新鲜的已有材料，或报告部分覆盖／等待／不足。 | 把不可达当零命中；删掉必要约束后继续执行。 | 可披露覆盖范围、来源新鲜度、容量检查。 |
| <a id="mem-10"></a>**MEM-10** 私有资料仅限端侧，但本地检索／模型能力不可用。 | 返回能力不足或等待，保持位置与出口限制。 | 自动调用云模型／向量化；经日志、消息或参数外发。 | 各处理位置、出口记录、受控测试载荷检查。 |

墓碑、旧副本和旧备份的清理条件另见[保留边界](#retention)及 [OPS-12](#ops-12)。删除不能撤回已经发生的外部披露；完成报告须说明可控制范围。

## 7. 身份、许可消费与撤销

**正文：** [2.6 身份与授权](../main/02-subsystems/06-identity-and-authorization.md)。**设计依据：** [授权生命周期](../../archive/architecture-v1/08-authorization-lifecycle-and-interfaces.md)。认证、签名和离线配置见[附录 02](02-api-and-message-catalog.md#compatibility)。

### 7.1 授权按决定、消费和应用分别记录

| 当前阶段 | 推进条件 | 后续责任 |
| --- | --- | --- |
| 请求授权判定 | 身份、祖先限制、资源、用途、位置、期限与资格可核验。 | 返回允许／拒绝／需要输入；纯判定不消费单次许可。 |
| 等待用户批准 | 有权回应匹配原等待项和有效版本。 | AuthorizationStore 原子保存消费等待项、回应回执及签发结果。 |
| 准备签发／分配额度 | 策略及管理版本有效，预留和接收方绑定成功提交。 | 交付固定材料；提交未知先查原提交。 |
| 接收方准备使用 | 材料、实际出示者及当前条件有效。 | 消费与原动作启动／业务提交原子关联；独立预留方案保留交接责任。 |
| 消费或材料交付未知 | 核对原操作与接收方是否仍能使用。 | 保留占用；只有旧资格不可再用且历史用量核清才回收。 |
| 权威接纳撤销 | 原子记录撤销、修订及通知。 | 各接收方应用后停止新受限工作，再处置在途与派生数据。 |
| 离线许可到期／时间不可信 | 新动作前检查不通过。 | 停止新受限工作，重新核验；已有动作仍需获准核对。 |

授权记录没有统一的状态枚举。签发、实际消费、权威撤销和接收端已应用分别取证。批准也不清除任务取消、资源接管或预算限制。

### 7.2 授权故障矩阵

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="auth-01"></a>**AUTH-01** 签名已生成；授权提交冲突或结果未知。 | 核对原提交，只有当前有效且已提交材料可交付。 | 先发未确认材料；换操作再次签发同一份额度。 | 原签发操作、策略修订、提交与发送记录。 |
| <a id="auth-02"></a>**AUTH-02** 两个 Worker／重复请求竞争同一单次许可。 | 原操作只绑定一份消费；不同意图按授权条件拒绝。 | 重连再次消费；先 Evaluate 后无记录地执行。 | 接收方绑定、消费账本、启动／业务原子组。 |
| <a id="auth-03"></a>**AUTH-03** 上游已预留授权额度；下游接收或消费回执丢失。 | 保留上游占用，查询原交付与消费。 | 超时就返还额度再发给另一端。 | 原分配、接收方资格、实际消费及未结算量。 |
| <a id="auth-04"></a>**AUTH-04** 单次读取已消费；恢复时原结果无法取得。 | 返回不可恢复或当前允许的原状态。 | 用原许可重新读取更新后或范围外的内容。 | 原读取修订／结果引用、消费记录、当前权限。 |
| <a id="auth-05"></a>**AUTH-05** 权威已撤销；通知尚未到达离线执行端。 | 需要在线核验授权的工作等待；有限离线许可仅在原有效条件内使用。 | 报告所有端已撤销；承诺离线端即时停止。 | 权威修订、节点应用游标、离线范围和期限。 |
| <a id="auth-06"></a>**AUTH-06** 策略／撤销同步缺口已过期。 | 重新取得获准一致快照，原子保存应用及游标。 | 清空旧撤销列表后放行；持久接收冒充已应用。 | 快照边界、受信密钥来源、实际应用位置。 |
| <a id="auth-07"></a>**AUTH-07** 有限离线运行中发生回拨、休眠异常或过大偏差。 | 停止依赖时间判断的新动作，重新建立可信时间。 | 用消息时间戳或连接存活自动延长资格。 | 时间锚点、单调经过时间、异常及重新核验。 |
| <a id="auth-08"></a>**AUTH-08** 依赖远端有限许可的进程离线重启。 | 默认等待可信时间和授权重建；本地权威按受信本机条件另行核验。 | 持久化剩余时长即证明远端许可仍有效；默认依赖云才能本地运行。 | 授权权威位置、重启记录、新执行资格。 |
| <a id="auth-09"></a>**AUTH-09** 批准与任务取消并发，或旧批准回应迟到。 | 原回应查原回执；新回应核对等待版本，执行继续受任务控制。 | 批准使取消失效；旧确认授予更大范围。 | 授权等待项、签发回执、任务控制版本。 |
| <a id="auth-10"></a>**AUTH-10** 认证或签名材料的一项必需绑定被替换／失效。 | 接入及处理端拒绝；不回退到其他认证配置。 | 信任自报用户、错误受众／证书持有者或未受信密钥。 | 登记状态、实际对端、材料验证及拒绝记录。 |
| <a id="auth-11"></a>**AUTH-11** 派生请求扩大资源／期限，或祖先授权已撤销。 | 签发与实际使用均检查整条限制，无法证明收缩则拒绝。 | 子授权隐藏父级限制；执行授权冒充签发权限。 | 委派链、选择器包含关系、当前撤销状态。 |
| <a id="auth-12"></a>**AUTH-12** 凭证解引用目标错绑、解密失败或主密钥缺失。 | 拒绝／等待受信恢复，错误信息不含秘密。 | 向错误账号发凭证；回退明文或把秘密送入模型／日志。 | Broker 绑定、受控错误、出口检查。 |
| <a id="auth-13"></a>**AUTH-13** 凭证／节点证书轮换中断，旧材料仍被未决工作引用。 | 查轮换记录，保留必要旧解密能力；出示证书变化时重绑验证材料。 | 提前删必需旧密钥；复制旧证书绑定给新出示者。 | 密钥版本、未决引用、轮换及撤销记录。 |

## 8. 多 Agent 控制传播与预算结算

**正文：** [3.3 多 Agent 协作](../main/03-coordination/03-agent-collaboration.md)、[2.3 规划、决策与模型调用](../main/02-subsystems/03-planning-and-decision.md)。**设计依据：** [协作与预算](../../archive/architecture-v1/06-decision-admission-and-collaboration.md)、[暂停来源与传播](../../archive/architecture-v1/12-data-path-and-protocol-semantics.md#3-补齐任务暂停恢复和子任务控制)。

### 8.1 委派、暂停来源和收尾

| 当前阶段／事实 | 触发与条件 | 后续责任 |
| --- | --- | --- |
| 父任务准备委派 | 固定目标、必需性、依赖、权限、预算、期限和验收条件。 | 父事务保存原委派操作、预留和交付工作。 |
| 委派已交付，子接纳未知 | 向固定接纳方查询原委派操作。 | 关联唯一子任务；父预留保持。 |
| 某暂停来源 ACTIVE | SELF 作用于本任务；默认 SUBTREE 逐层传播根来源和修订。 | 子控制有自己的稳定操作身份；父子各自提交。 |
| 同来源变为 CLEARED | 有权恢复明确指定原暂停，沿原范围传播。 | 较旧 ACTIVE 不能复活；其他来源、资源接管和取消保留。 |
| 合并有效控制 | 已接纳取消优先，否则任一有效暂停为 PAUSE，其余为 RUN。 | RUN 后仍检查输入、依赖和执行条件。 |
| 子结果已确认 | 父核对来源、覆盖和目标要求。 | 必需失败阻断依赖；可选失败按原验收条件判断。 |
| 父准备终结 | 所辖工作已完成、明确未启动或停止并处置，关键效果已核清。 | 记录真实终态、部分成果与已发生影响。 |
| 额度待回收 | 接收方已不能继续使用且历史消耗可核对。 | 回收确认剩余量；用量未知则保守占用／未结算。 |

### 8.2 协作故障矩阵

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="col-01"></a>**COL-01** 子任务已接纳委派；父未收到子引用。 | 查原委派操作，补齐原父子关联。 | 创建替代子任务；向第二端重复分配同份额度。 | 委派回执、唯一子 task_ref、父预留。 |
| <a id="col-02"></a>**COL-02** 子任务执行中失联；父仍有独立分支。 | 相关依赖／核对等待，其他合法分支继续，保留关联。 | 失联即 FAILED 并级联终结；超时视为已停止。 | 子最后确认状态及陈旧性、依赖图、在途工作。 |
| <a id="col-03"></a>**COL-03** 必需子任务明确失败。 | 停止依赖其成功的工作，按条件继续独立分支并收尾。 | 临时改成可选；默认回滚已发生效果。 | 原必需性、失败证据、依赖与处置记录。 |
| <a id="col-04"></a>**COL-04** 可选子任务明确失败。 | 保留缺口，按原验收条件判断是否可交付。 | 因为可选就自动宣告父完成；隐藏缺失部分。 | 原验收条件、子失败与父判断依据。 |
| <a id="col-05"></a>**COL-05** 父接纳 SUBTREE 暂停；某个既有委派的接纳结果尚未知。 | 核对原委派，将暂停来源传给确认存在的子任务。 | 丢掉未决委派；暂停期间另建自主子任务。 | 父控制、原委派、逐子传播工作。 |
| <a id="col-06"></a>**COL-06** CLEARED 先于同来源旧 ACTIVE 到达子任务。 | 持久保存关闭修订，拒绝旧暂停复活。 | 按消息到达顺序恢复过期暂停。 | 根来源、单调控制修订、关闭记录。 |
| <a id="col-07"></a>**COL-07** 父解除自己的暂停；子仍有独立暂停或失联后代。 | 只解除对应来源；逐层分别汇报接纳和实际落实。 | 清空子所有暂停；后代未回应却报告全树已落实。 | 子来源集合、传播回执、后代实际状态。 |
| <a id="col-08"></a>**COL-08** 父取消后，子已接纳取消但外部动作不可停止。 | 保留处置和效果核对，待真实收束后判终态。 | 子悄悄脱离父继续；取消消息送达即父 CANCELLED。 | 两层取消操作、外部效果、父收尾条件。 |
| <a id="col-09"></a>**COL-09** 子离线消费额度，结算回包丢失。 | 原预留保持，核对历史消耗及剩余使用资格。 | 租约到期或取消发出就退回余额／并发槽。 | 父分配、子消费、未结算量和资格失效证据。 |
| <a id="col-10"></a>**COL-10** 有权主体降低预算或缩短期限，远端额度仍未结算。 | 持久接纳合法调整，阻止超限新工作并处置旧工作。 | 抹掉已用量；修改父账面即视为收回远端额度。 | 调整回执、原分配、在途与处置预算。 |
| <a id="col-11"></a>**COL-11** 子把父完成作为必要依赖，形成不可满足循环。 | 拒绝已能识别的循环；无法完整探测跨运行时依赖时，按期限和无进展规则停止推进。 | 无限委派／空转；为破环重复执行未知动作。 | 依赖关系、检测范围、无进展和预算记录。 |
| <a id="col-12"></a>**COL-12** 多个子结果包含相互冲突的结论。 | 保留不同来源，进行获准核验或请求澄清。 | 多数票／最近回包直接成为真值。 | 各子证据、冲突范围、验证及父判断依据。 |

补偿是新的业务操作，需能力声明、当前授权、独立身份及效果核验。其结果不能覆盖原失败或取消中已经发生的事实。

## 9. Owner 移交与离线恢复

**正文：** [3.4 端云协同与离线运行](../main/03-coordination/04-edge-cloud-coordination.md)。**设计依据：** [拥有权规则](../../archive/architecture-v1/04-edge-cloud-and-recovery.md)、[八个移交窗口](../../archive/architecture-v1/04-recovery-state-and-failure-matrix.md#协作移交的故障窗口)。

### 9.1 源端与目标端分别记录管理阶段

| 当前管理阶段 | 推进条件 | 后续阶段及责任 |
| --- | --- | --- |
| 源端 ACTIVE | 获准启动移交，固定唯一目标，停止新调度与资格签发。 | 源端 PREPARING；既有工作仍须核对。 |
| 源端 PREPARING，目标准备中 | 目标持久保存检查点版本、确切字节摘要和适用恢复记录。 | 目标仍无业务执行权；源端检查旧资格不能再启动新动作。 |
| 源端 PREPARING | 检查点一致，排他性条件满足。 | 源端原子保存 SEALED、唯一目标、新世代和激活 Outbox。 |
| 源端尚未封存 | 确认封存未成立，且未发有效激活凭据。 | 可安全取消准备并恢复源端合法调度。 |
| 源端 SEALED，目标已准备 | 目标验证受信激活、源／目标、世代、检查点版本和摘要。 | 目标持久提交新世代 ACTIVE 后才启动工作。 |
| 目标 ACTIVE | 激活回执交接与路由更新。 | 源端保持 SEALED；重复激活返回同一结果，不再增加世代。 |

owner_epoch 不因重连、Worker 更换或数据库主备切换而增加。移交一个父任务不自动移交其子任务；委派关系、结果路由、预算和窗口水位必须随适用检查点恢复。参考故障模型假定持久状态未回滚，旧备份与身份克隆另见[生产恢复](#operations)。

### 9.2 移交故障矩阵

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="own-01"></a>**OWN-01** 尚未准备移交，旧世代 ACTIVE；源进程退出。 | 原拥有者凭持久记录恢复，Worker 重新取得资格。 | 另一独立副本仅凭心跳丢失接管。 | 原 owner_ref／epoch、管理阶段、持久范围。 |
| <a id="own-02"></a>**OWN-02** 源已 PREPARING，目标尚未准备；连接中断。 | 继续准备；确认未封存且未发激活后可安全取消准备。 | 目标超时自激活；核对前直接恢复源新调度。 | 源准备记录、目标、激活决定是否成立。 |
| <a id="own-03"></a>**OWN-03** 目标已准备，源尚未封存；一端重启。 | 恢复原检查点与准备关系，继续移交或安全中止。 | 将目标准备记录当作执行许可。 | 双端准备状态、版本与内容摘要。 |
| <a id="own-04"></a>**OWN-04** 源封存提交结果未知。 | 查原 change_id；未知期间源不调度，也不发激活。 | 两端各自尝试运行；再建另一移交目标。 | SEALED／目标／新世代／Outbox 原子组。 |
| <a id="own-05"></a>**OWN-05** 源已 SEALED；激活消息未送达。 | 从原 Outbox 补发给唯一目标。 | 等待过久就把源改回 ACTIVE。 | 源封存证据、原激活载荷和投递进度。 |
| <a id="own-06"></a>**OWN-06** 目标收到激活；目标提交结果未知。 | 查询目标原提交；确认 ACTIVE 前不启动 Worker。 | 先运行再补激活记录。 | 目标提交回执、受信凭据、检查点绑定。 |
| <a id="own-07"></a>**OWN-07** 目标已 ACTIVE；激活回执丢失。 | 重复激活返回原结果，源恢复路由更新。 | 再增一次世代；源因无回包复活。 | 目标新 epoch、原回执、源 SEALED。 |
| <a id="own-08"></a>**OWN-08** 源封存后目标永久不可达，无法证明其未激活或失效。 | 参考实现保持待处理；其他接管需独立排他性证据。 | 以人工点击或新目标名称代替排他性证明。 | 原封存／目标、已知资格及证据缺口。 |
| <a id="own-09"></a>**OWN-09** 准备移交时旧执行端不可达，仍可能启动原获准动作。 | 等待有限资格可证明失效并核对，或暂停移交。 | 仅凭本地时钟／旧库写栅栏推断外部已停止。 | 旧执行范围、期限、可信失效与效果记录。 |
| <a id="own-10"></a>**OWN-10** 检查点准备后，冻结期间收到迟到结果。 | 保存可恢复收件责任；版本变化须重备一致检查点，封存后转目标核对。 | 偷改源权威却激活旧快照；丢弃迟到效果。 | 收件记录、检查点版本、目标消费结果。 |

### 9.3 离线与重连矩阵

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="off-01"></a>**OFF-01** 当前 Owner 断网，本地能力、资料与有限授权仍满足。 | 在原范围、预算、期限及资源资格内继续；依赖远端的分支等待。 | 断连即迁移 Owner；一般离线许可扩成新的共享资源控制权。 | 本地权威、许可、分配额度与分支依赖。 |
| <a id="off-02"></a>**OFF-02** 离线期间完成部分工作；随后重连。 | 先认证及资格核对，再补流、核对原操作、恢复有效等待和界面。 | 一连通就全量派发；清除期间暂停、撤销或未知效果。 | 当前策略、原操作、流前缀、控制及 UI 快照。 |
| <a id="off-03"></a>**OFF-03** 离线新操作尚未受理，重连时接纳窗口已关闭。 | 明确拒绝过期首次接纳；已有操作仍查保留记录。 | 传输层自动换 ID／续窗口后执行旧意图。 | 窗口绑定、关闭水位、受理确定性。 |

## 10. 扩展激活、旧绑定与运行器

**正文：** [2.8 扩展与运行保障](../main/02-subsystems/08-extensions-and-runtime.md)。**设计依据：** [扩展生命周期](../../archive/architecture-v1/09-extension-ecosystem.md)、[激活与运行器](../../archive/architecture-v1/09-extension-contracts-and-activation.md)。固定配置沿用[附录 02](02-api-and-message-catalog.md#compatibility)，本篇不调整版本或资源参数。

### 10.1 从准备到清理的阶段

| 当前阶段 | 推进条件 | 后续责任 |
| --- | --- | --- |
| 导入／准备 | 必需资产、摘要、依赖和精确锁定结果齐备。 | 提交可验证记录；未引用暂存资产按保守规则清理。 |
| 验证 | 精确资产、配置、运行器与声明测试满足条件。 | 保存对应证据；激活前再次检查当前信任与权限。 |
| 候选实例就绪 | 准备完成，预期管理版本匹配。 | 本地原子提交激活修订、贡献绑定及通知；实例启动在事务外。 |
| 本地激活已提交 | 目录、Skill、Renderer 等读取同修订或投影已应用。 | 才允许使用完整新绑定；跨节点逐一报告应用。 |
| 停止接纳新工作／停用 | 正常排空或风险隔离决定获准。 | 保留旧实例、原操作及核对通道；实际停止另报。 |
| 请求回滚 | 旧锁定结果仍受信，权限、依赖和持久状态兼容。 | 经新的 Activate 管理操作应用；不兼容则隔离等待。 |
| 准备删除资产 | 已停用，无在途、恢复或允许保留的依赖引用。 | 清理可删除资产；业务记录和水位按各自生命周期处理。 |

这些中文阶段不是新定义的英文枚举。固定到某次决策或已准入操作的版本保持原绑定；后续尚未固定的工作才选择已激活配置。

### 10.2 扩展故障矩阵

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="ext-01"></a>**EXT-01** 准备时发现摘要冲突、依赖缺失／循环或越界资产。 | 拒绝该准备结果；只清理确认无引用的暂存内容。 | 暴露半套贡献；改取未锁定远端最新版本。 | 资产摘要、依赖锁定、拒绝与引用记录。 |
| <a id="ext-02"></a>**EXT-02** 验证环境请求真实账号，或运行器不能落实必需限制。 | 拒绝／标记不支持，使用获准测试能力验证。 | 自检借用用户凭证；受限模式自动转受信执行。 | 测试配置、宿主入口、权限和能力声明。 |
| <a id="ext-03"></a>**EXT-03** 候选实例已启动，激活提交失败或未知。 | 明确失败则隔离／停止候选；未知查原提交再处理。 | 实例先接正式工作；未知时另起激活意图。 | 原激活操作、管理修订、实例接纳记录。 |
| <a id="ext-04"></a>**EXT-04** 激活已提交，某目录／UI 类型投影未应用。 | 补交原通知，投影追到相应修订后使用新绑定。 | 新旧贡献混用；以通知已发证明已应用。 | 激活修订、各投影实际位置。 |
| <a id="ext-05"></a>**EXT-05** 跨节点只有部分激活，另一节点离线。 | 逐节点报告；旧版本只在仍获准且兼容的范围内运行。 | 管理指针变化即报告全局升级完成。 | 每节点锁定结果、实际激活与协作兼容检查。 |
| <a id="ext-06"></a>**EXT-06** 新版已激活；旧 S／J 未决时重启。 | 沿原能力、Driver、Schema 和外部关联恢复。 | 原操作改绑新版；旧计划文字重新当动作执行。 | 原固定绑定、持久资产引用、原 J。 |
| <a id="ext-07"></a>**EXT-07** 停用／风险隔离后仍收到旧实例或外部 Agent 的结果。 | 阻止适用新工作，核对旧效果并记录实际停止能力。 | 卸载即宣称远端停止；丢旧结果后新建替代动作。 | 停用意图、实例／远端状态、原操作证据。 |
| <a id="ext-08"></a>**EXT-08** 新版已迁移持久状态，旧版不兼容；请求回滚。 | 保持隔离并等待获准兼容处置。 | 回放旧库覆盖新事实；强行激活旧版。 | 状态格式、兼容声明、回滚拒绝／等待原因。 |
| <a id="ext-09"></a>**EXT-09** Wasm 已登记子动作；guest 或宿主进程中断。 | 先核对中断前已登记的子动作；纯计算仅在声明和预算允许时重算。 | 盲重跑脚本重复副作用；宣称自动恢复 guest 栈。 | 子操作、预算、guest 尝试与实际效果。 |
| <a id="ext-10"></a>**EXT-10** Wasm 准备、start 段或调用触发资源／时间限制。 | 按锁定配置有界失败，传递下游期限，取消后不复用 guest。 | 以 guest 内存限制承诺宿主 RSS；宣称可强杀任意 Go 回调。 | 各阶段限额、取消记录、宿主回调和下游状态。 |

外部协议无幂等、句柄过期及取消限制仍按 [EXE-02](#exe-02)、[EXE-04](#exe-04)、[EXE-07](#exe-07)、[EXE-08](#exe-08)核对；具体版本、绑定与方向另记录互操作证据。

## 11. 观测、评测运行与改进发布

**正文：** [4.4 评测、比较与发布](../main/04-engineering/04-evaluation-and-release.md)。**设计依据：** [评测与发布契约](../../archive/architecture-v1/10-evaluation-contracts-and-release-gates.md)。下表保留状态与放行行为，样本、预算、统计方法和阶段阈值已由[附录 05](05-validation-profiles-and-traceability.md)集中整理，沿用既定配置。

### 11.1 评测运行与判定分别变化

| 当前运行状态 | 推进条件 | 后续事实 |
| --- | --- | --- |
| QUEUED | 原计划、授权、预算与样本清单已持久化，取得合法调度条件。 | RUNNING，按原样本工作交付隔离任务。 |
| RUNNING | 必需依赖或设施暂不可用，当前无法推进。 | WAITING，保留样本、原任务及未结额度。 |
| WAITING | 依赖恢复且当前条件允许。 | 恢复原评测运行，先查原样本操作；不复制真实动作。 |
| 运行或等待中 | 本次评测收束，样本事实、缺口和在途处置已整理。 | COMPLETED；gate_result 仍可为 PASS、FAIL 或 INCOMPLETE。 |
| 任意非终态 | Cancel 接纳。 | 停止新样本并请求停止在途；实际收束后才 CANCELLED。 |
| COMPLETED／CANCELLED | 查询、迟到证据或设施重测请求。 | 保留原运行与尝试；重测另建运行记录，重新评分保留判读版本。 |

| gate_result | 依据 | 限制 |
| --- | --- | --- |
| PASS | 固定计划下证据完整，适用门槛满足。 | 不自动授予发布权限或证明生产改善。 |
| FAIL | 被测行为／效果未满足计划条件。 | 未输出提案、耗尽预算或效果无法确认等被测失败仍计原分母。 |
| INCOMPLETE | 独立判定器／测试设施故障或必要证据缺失，无法完成规定判定。 | 保留设施原因与原分母，不能删掉缺证据样本后宣告通过。 |

评测运行没有沿用 Task 的 FAILED。上表是既有阶段行为的整理；各状态与 gate_result 的最终完整编码组合仍需实现 Schema 约束。

### 11.2 候选发布阶段

| 当前阶段 | 推进条件 | 后续责任 |
| --- | --- | --- |
| 已提出候选 | 固定精确资产、配置、来源、比较计划和权限。 | 进入隔离评测，保留每次候选反馈。 |
| 隔离评测 | 适用绝对门槛、可比较改善及独立保留确认成立。 | 取得发布资格；报告仅绑定这份候选与基线。 |
| 具备发布资格 | 当前证据、政策、权限及依赖仍有效；代码类取得维护者确认。 | 原子保存阶段意图和 Outbox，交接 ExtensionManager。 |
| 试运行 | 持久分组、客观真值、样本／时间及阶段门槛均满足，目标实际应用可确认。 | 按固定配置逐步扩大，最终全面激活。 |
| 等待／停止扩大 | 样本或证据不足、应用未知；达到最长观察边界仍不足。 | 待评估；不自动晋级，不凭证据不足断言质量退化。 |
| 已确认违规／门槛不通过 | 依预先固定的保护和回滚规则处理。 | 停止适用新路由，处置在途，请求兼容且获准的回滚。 |
| 全面激活 | 继续固定监测窗口。 | 新违规立即处置；证据缺口与已确认退化分别记录。 |

阶段意图、每节点实际应用与在途任务绑定各自保存。常规记忆更新沿用记忆契约；发布回滚不撤销旧操作或真实效果。

### 11.3 观测与评测故障矩阵

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="obs-01"></a>**OBS-01** 同批持久观测重复交付，或载荷伪造来源。 | 按受信来源位置去重，拒绝身份不符的事实。 | 重复计数；按载荷自报身份接纳审计事实。 | 实际节点／模块身份、源位置与接纳位置。 |
| <a id="obs-02"></a>**OBS-02** 投影落后或来源历史已清理，诊断查询无记录。 | 分别报告接纳位置、应用位置及不可恢复缺口。 | 无日志推断无动作；诊断投影覆盖业务状态。 | GetCoverage、原业务记录、投影修订。 |
| <a id="eval-01"></a>**EVAL-01** 样本任务已接纳，评测端关联回包丢失。 | 查原交接操作，继续原任务与尝试。 | 新建样本挑最好结果；借重放再发真实动作。 | 计划／样本键、尝试号、原任务与操作。 |
| <a id="eval-02"></a>**EVAL-02** 独立评分器故障或必需判分证据缺失。 | 保留 INCOMPLETE 与原样本分母；可获准重判或独立重测。 | 删除缺失项缩分母；用采样成功片段代替样本。 | 原计划、证据覆盖、设施错误、判读版本。 |
| <a id="eval-03"></a>**EVAL-03** 被测实现耗尽预算或不能确认目标效果，设施能判定其未成功。 | 计入被测失败，未知效果继续按执行契约核对。 | 以“缺证据”为由排除被测失败。 | 被测轨迹、预算、固定判定条件与原分母。 |
| <a id="eval-04"></a>**EVAL-04** 评测取消时仍有样本动作在途。 | 停止新样本，核对原任务的停止、迟到结果和效果。 | Cancel 返回即释放所有占用／标记全部已停止。 | 取消意图、样本任务、效果与额度结算。 |
| <a id="eval-05"></a>**EVAL-05** 比较时预算、评分器、目录或环境改变；或推断条件不成立。 | 返回不可直接比较／推断不可用，保留固定集事实。 | 临时换统计方法或主指标后宣称改善。 | 两计划、配置差异、配对与统计适用性。 |
| <a id="eval-06"></a>**EVAL-06** 候选、基线、授权或关键来源在发布前变化。 | 重新核对资格；失效证据不支持新的发布。 | 旧报告批准另一份资产；为核验恢复已删正文。 | 候选摘要、基线、证据依赖和当前权限。 |
| <a id="eval-07"></a>**EVAL-07** 阶段意图已提交，激活回执丢失。 | 查原激活操作，逐节点补齐应用进展。 | 再发一项激活；把阶段意图当全节点完成。 | Evolution Outbox、原激活、节点实际版本。 |
| <a id="eval-08"></a>**EVAL-08** 试运行达到观察期限，样本／真值或节点应用证据仍不足。 | 停止扩大并转待评估，保留覆盖缺口。 | 时间一到自动晋级；把未知应用算作成功样本。 | 持久分组、客观标签、时间和实际应用。 |
| <a id="eval-09"></a>**EVAL-09** 发布期间确认禁止披露、重复写入或状态破坏。 | 立即停止适用新路由，处置在途；按规则请求回滚。 | 用质量均值或节省成本抵消违规；删失败记录。 | 违规证据、路由停止、旧操作及处置结果。 |
| <a id="eval-10"></a>**EVAL-10** 完整阶段／监测窗口未达质量或代价门槛。 | 停止扩大并请求回滚；不兼容按 [EXT-08](#ext-08)隔离。 | 把未达标说成证据不足；强启已撤销信任的旧版。 | 固定门槛、完整报告、回滚目标兼容性。 |

评测运行结束、目标达标、可比较改善、生产稳定分别需要证据。验收报告不得把这些结论合并成一个“成功”。

## 12. 生产恢复、迁移与备份

**正文：** [4.2 部署、存储与规模扩展](../main/04-engineering/02-deployment-and-storage.md)、[4.3 故障恢复与运行保障](../main/04-engineering/03-reliability-and-recovery.md)、[4.1 技术选型与开发组装](../main/04-engineering/01-implementation-and-technology.md)。**设计依据：** [分布式恢复](../../archive/architecture-v1/14-distributed-recovery-and-operations.md)、[用户分片迁移](../../archive/architecture-v1/13-distributed-deployment-and-storage.md#用户分片迁移)、[同机后端迁移](../../archive/architecture-v1/11-specialized-validation-and-handoff.md#同机停写迁移及恢复验证)。

以下生产条目用于声明支持相应拓扑的 Adapter 和部署配置，不把集群变成单机必需依赖。数据库高可用负责角色与隔离，各业务模块负责原提交、原操作与效果。

### 12.1 恢复协调的参考阶段

| 当前阶段 | 转入后续阶段所需结果 | 条件不足时 |
| --- | --- | --- |
| DETECT 检测归并 | 故障范围及影响得到足够信号支持。 | 保留怀疑／继续有界检测；单次心跳不足以接管。 |
| CONTAIN 限制影响 | 受影响新入口受控，必要控制、结果接收与核对责任可保留。 | 按范围背压，不扩大影响到健康业务。 |
| ESTABLISH 建立权威 | 当前可写分区、旧资格隔离、合法领取与耐久条件可证明。 | 保持不可写／不可新派发，升级处置。 |
| RECONCILE 核对事实 | 原提交、效果、来源、授权、控制、固定版本及未结额度可判定。 | 未决对象继续等待，不阻塞无关健康对象。 |
| RESUME 分批续跑 | 当前条件允许，资源容量和公平份额满足。 | 保持退避／缩减放量，控制与核对使用有界保留份额。 |
| VERIFY 核验退出 | 原任务有实际推进，缺口与未知事项收敛或明确隔离，旧资格被拒绝。 | 保存进展与下次检查；超限后显式等待并告警。 |

这些是管理阶段。恢复控制器重启仍沿原范围、策略修订、领取代次和游标推进；它不直接改业务终态，不代替 HA 管理器提升数据库。

### 12.2 设施与续跑故障矩阵

本表的“聚合”指任务、记忆集合或 Surface 等需要分别保持消息顺序的业务对象。

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="ops-01"></a>**OPS-01** 任务原来 RUNNING，权威数据库突然不可写。 | 展示最后确认版本及陈旧性；恢复后逐项核对。 | 伪称 WAITING 已提交；批量 FAILED／重置 QUEUED。 | 最后提交、数据库可写性、恢复后原工作。 |
| <a id="ops-02"></a>**OPS-02** 事务本地可见，同步确认未知；扫描器读到后主库故障。 | 未确认耐久前不派发；切换后查原提交并建立屏障。 | 裸查询可见即发外部动作；把未知提交算作已确认耐久。 | 原 change_id、复制确认、扫描领取与实际派发。 |
| <a id="ops-03"></a>**OPS-03** LookupCommit 找到原记录；后续耐久确认再次未知。 | 保留核对责任；同一当前权威下确认语义／版本及耐久条件。 | 任意其他库写入充当屏障；角色变化后复用旧内存标记。 | 当前权威、记录版本、确认事务及派发屏障。 |
| <a id="ops-04"></a>**OPS-04** 数据库切换后一次查询未找到原提交。 | 核对旧请求不能再提交、恢复覆盖及当前条件；不足继续等待。 | 自动重放整份业务意图；从读副本缺记录推断未接纳。 | 新权威、原提交身份、覆盖与旧写入隔离。 |
| <a id="ops-05"></a>**OPS-05** 拟提升数据库，但仲裁、候选完整性或旧主隔离任一条件缺失。 | 该分片保持不可写，取得证据后按 HA 规则处理。 | 强制提升落后副本；删 Pod／改地址代替隔离证明。 | 仲裁、候选耐久范围、旧主不能有效写入的证据。 |
| <a id="ops-06"></a>**OPS-06** 新主已工作，旧主恢复连接。 | 按新时间线重建／同步并验证，再作为合格成员加入。 | 旧写入口直接重新开放；顺带更换任务 Owner。 | 时间线、重建记录、写栅栏与路由。 |
| <a id="ops-07"></a>**OPS-07** 恢复控制器退出，或其管理记录不可用。 | 有记录则新代次接手；管理依据不可用时停止新的破坏性切换／迁移。 | 控制器另造业务权威；丢失原恢复阶段责任。 | 管理记录、代次、扫描游标、模块未决工作。 |
| <a id="ops-08"></a>**OPS-08** 消息代理不可用，Outbox 积压增长。 | 保留原交接，扫描本地工作，限制扩大接纳。 | 代理不可用即丢工作；缩短保留期删除唯一载荷。 | Outbox 年龄／体量、保留记录、恢复补投。 |
| <a id="ops-09"></a>**OPS-09** 某条消息反复处理失败，阻塞同一聚合的后续消息。 | 隔离失败消息并保存原因；受影响聚合补齐缺口或从快照恢复，其他聚合继续。 | 跨过缺口确认；随机分流后仍宣称顺序一致。 | 原载荷引用、聚合版本、缺口和隔离记录。 |
| <a id="ops-10"></a>**OPS-10** 缓存清空或索引损坏／滞后。 | 限流回源，按当前获准快照和增量重建，报告覆盖。 | 从缓存恢复额度／所有权；重建复活删除内容。 | 权威修订、权限和删除水位、投影位置。 |
| <a id="ops-11"></a>**OPS-11** 对象上传失败或唯一正文引用不可读。 | 保留暂存和恢复责任，获准重试并校验后再发布引用。 | 发布缺失正文；未履约内容当孤儿删除。 | 暂存记录、对象版本／摘要、引用与清理判断。 |
| <a id="ops-12"></a>**OPS-12** 恢复旧备份，缺少其后的动作、额度、撤销或删除。 | 隔离恢复，核对后续权威／外部证据；证据不足范围禁止新执行／披露。 | 重花旧余额、重放未知写入、恢复被删正文。 | 各 Store 一致点、原操作、最新可得水位及缺口。 |
| <a id="ops-13"></a>**OPS-13** 旧区域／节点身份副本与恢复端可能同时运行。 | 先证明旧身份及执行资格失效，建立唯一范围后开放。 | 复制数据库产生新 Owner；假定恢复端天然更新。 | 区域／身份隔离、执行资格、路由和窗口记录。 |
| <a id="ops-14"></a>**OPS-14** 可用区或 Cell 故障，剩余容量／同步条件不足。 | 隔离影响，按范围等待、降级或背压，健康 Cell 继续。 | 无限制分散原任务到空副本；静默降低原耐久承诺。 | 故障范围、存活容量、仲裁与业务交接。 |
| <a id="ops-15"></a>**OPS-15** 大量积压与新流量同时恢复，磁盘／WAL 或供应商额度逼近上限。 | 公平分批、有限探测、按水位收紧；核对与控制保留有界份额。 | 无限重试；删恢复记录制造队列清空；热点挤尽其他用户。 | 每用户等待、恢复份额、资源水位、已用及未结额度。 |
| <a id="ops-16"></a>**OPS-16** 模型／工具依赖限流或暂不可用。 | 归并依赖故障并退避；获准回退仍遵守位置、预算及未知效果规则。 | 每个任务持续探测；隐藏 SDK 重试；重启清用量。 | 依赖状态、下次检查、真实调用和费用记录。 |
| <a id="ops-17"></a>**OPS-17** Gateway 退出引起大量重连，旧连接消息迟到。 | 抖动重连、重新认证，建立新连接世代，沿游标和原操作恢复。 | 旧会话继续取得新资格；重连重新提交业务。 | 端点／连接绑定、当前披露权限、原流与操作。 |

RPO 的无丢失声明只覆盖经验证故障模型中取得规定耐久确认的写入；未知提交、外部效果与跨区域异步丢失窗口单独报告。RTO 须指定业务恢复终点，不能仅以实例就绪或积压清空计数。

### 12.3 用户分片与同机后端迁移

| 迁移阶段 | 用户分片迁移 | 同机 SQLite／bbolt 迁移 |
| --- | --- | --- |
| 准备与静止 | PREPARE／QUIESCE：固定唯一目标、新 route_epoch；全部相关原子组停写并取得边界。 | 停止新准入及后台写入；达到持久切点后导出逻辑包。 |
| 目标校验 | 目标只校验检查点、摘要、权限及恢复引用。 | 未开放目标校验格式、摘要、跨模块引用和恢复计划。 |
| 唯一活动决定 | 源 SEALED 后，目录 CAS 绑定唯一目标；目标验证封存证据才 ACTIVATE。 | 共同维护屏障下持久更新唯一活动配置与启动代次，旧进程失去写资格。 |
| 开放与核验 | VERIFY／CLEANUP：恢复交接，旧路由拒绝／重定向，保留恢复期后清理。 | 先核对原操作、资格和效果，再恢复获准工作。 |
| 回退 | 目标产生新写入后，回退是新的迁移。 | 重新停写并反向迁移；切换前失败才可按原记录恢复源库。 |

两种迁移均不自动转移端侧 Owner，不扩大数据驻留范围。主密钥不进入通用导出包；外部操作和迟到结果继续沿原身份核对。

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="mig-01"></a>**MIG-01** 已停前台调度，但 Memory、UI 或后台结果写入尚未停稳。 | 暂停导出／切换，取得全部适用原子组稳定边界。 | 前台停了就宣称全范围静止。 | 各 Store 写屏障、检查点及未交接记录。 |
| <a id="mig-02"></a>**MIG-02** 目标仅部分导入，或摘要／引用／文件同步校验失败。 | 保持目标未开放，按原迁移记录修复或中止。 | CopyFile 返回即耐久完成；部分目标承接业务。 | 逻辑包版本、摘要、引用、文件及目录同步结果。 |
| <a id="mig-03"></a>**MIG-03** 用户源分区封存提交未知。 | 查原封存决定；未知期间源、目标都不新增写资格。 | 超时自动解封；只改目录而旧分区仍可写。 | 源栅栏、原提交、目标及 route_epoch。 |
| <a id="mig-04"></a>**MIG-04** 目录已绑定目标，目标激活或回执未知。 | 查原目录与激活记录，向同一目标恢复交接。 | 改绑第二目标；旧路由缓存绕过存储写栅栏。 | 目录版本、唯一目标、封存／激活记录。 |
| <a id="mig-05"></a>**MIG-05** 目标已产生新写入；请求回到源库。 | 重新停写并反向迁移最新事实。 | 直接启用陈旧源快照。 | 目标新写入、反向迁移记录、唯一活动决定。 |
| <a id="mig-06"></a>**MIG-06** 冻结期间可靠输入／迟到结果到达。 | 纳入明确持久缓冲与交接，或未接纳前返回暂不可用。 | 复制边界后漏写源记录；承诺不可重放通知必不丢。 | 接纳边界、缓冲／Outbox、目标消费。 |
| <a id="mig-07"></a>**MIG-07** 同机后端活动配置切换未知，旧进程可能存活。 | 查迁移及启动记录，确认共同屏障和旧进程隔离后开放。 | 两个不同文件锁代替单一活动配置。 | 配置提交、启动代次、旧进程与写入口隔离。 |
| <a id="mig-08"></a>**MIG-08** 数据复制完成，但旧执行端资格或外部效果尚未核清。 | 保留原操作核对；执行资格未隔离前不重新签发。 | 数据迁移成功即宣布动作未执行或安全重做。 | 原执行资格、外部关联、效果与恢复工作。 |

## 13. 关闭水位与恢复记录清理

**正文：** [2.2 上下文、记忆与证据](../main/02-subsystems/02-context-and-memory.md)、[2.5 应用与交互](../main/02-subsystems/05-interaction.md)、[3.4 端云协同与离线运行](../main/03-coordination/04-edge-cloud-coordination.md)、[4.3 故障恢复与运行保障](../main/04-engineering/03-reliability-and-recovery.md)。**设计依据：** [接纳窗口与清理](../../archive/architecture-v1/04-recovery-state-and-failure-matrix.md#接纳窗口与记录清理)、各模块生命周期；字段索引见[附录 01](01-data-model.md#retention)。

### 13.1 各水位只回答自己的问题

| 记录／位置 | 允许清理或结束这一阶段的条件 | 清理后仍须保证 |
| --- | --- | --- |
| 可靠消息与流前缀 | 履行交付责任，或按契约显式结束补投窗口并记录替代恢复边界。 | 独立操作核对责任仍在；新流不伪装补齐旧缺口。 |
| 接纳窗口与操作明细 | 先持久化关闭水位，确认相关操作／提交无剩余恢复义务，再清理明细。 | 旧窗口不能首次接纳；窗口关闭不取消已接纳长任务。 |
| 提交回执、消费与预算记录 | 原提交及外部影响可判定，相关恢复／结算义务已完成。 | 不能重新消费许可或花费旧余额；过期查询明确边界。 |
| 暂停来源关闭修订 | 满足控制恢复窗口，且过期接纳仍可拒绝。 | 迟到旧 ACTIVE 不复活已解除暂停。 |
| 删除墓碑与同步世代 | 受控副本已应用，或旧副本世代已持久关闭且重返必须重建。 | 旧副本不能上传复活被删记录；仅保留获准元数据。 |
| 旧扩展／Schema／恢复材料 | 无在途、恢复或允许保留的依赖引用，或已明确处置。 | 原操作仍能按声明范围核对；不无限保存禁存内容。 |
| 诊断／评测资料 | 按自身期限和来源政策清理，报告关联证据资格变化。 | 不借诊断 TTL 清理业务权威记录；失效证据不再支持新发布。 |

消息序号、窗口关闭水位、来源修订、同步游标和 Owner 世代不可混用。接纳窗口规定能否首次受理，授权规定能否执行，业务期限规定还能否新增目标工作；三者分别检查。

### 13.2 清理故障矩阵

| 初始条件与故障点 | 允许的恢复 | 禁止的结果 | 核对证据 |
| --- | --- | --- | --- |
| <a id="gc-01"></a>**GC-01** 窗口关闭水位已提交，操作明细清理中退出。 | 核验持久关闭水位，先确认无剩余恢复义务，再继续清理。 | 先清理后核对义务；先删明细后补关闭；重连水位归零。 | 关闭回执、剩余义务、清理进度。 |
| <a id="gc-02"></a>**GC-02** 接纳窗口已结束，但原任务／操作尚未完成。 | 当前授权允许时查询并继续原责任；旧窗口不接新操作。 | 仅因窗口结束删除核对记录或取消长任务。 | 原接纳、授权／期限、在途与保留记录。 |
| <a id="gc-03"></a>**GC-03** 旧回执明细已依法清理；旧 ID 再次到达。 | 返回过期／不可恢复边界，阻止首次接纳。 | 查无明细就当新操作执行。 | 窗口关闭水位、恢复保留边界、拒绝记录。 |
| <a id="gc-04"></a>**GC-04** 墓碑拟清理，尚有未应用删除的离线副本。 | 等待应用，或持久关闭旧同步世代并要求重返重建。 | TTL 到期即删墓碑，仍允许旧副本直接上传。 | 副本应用位置、世代关闭、重建结果。 |
| <a id="gc-05"></a>**GC-05** 暂停来源关闭记录已按规则清理；旧暂停消息迟到。 | 通过保留的恢复边界拒绝过期接纳。 | 来源明细不存在就重新建立旧 ACTIVE。 | 来源修订、关闭窗口／水位、拒绝结果。 |
| <a id="gc-06"></a>**GC-06** 请求 Remove 旧扩展，但持久操作仍引用其实现或 Schema。 | 拒绝／等待删除，或先完成获准兼容处置。 | 仅凭进程引用计数为零删除；卸载同时清业务事实。 | 持久引用、原操作、兼容及处置记录。 |
| <a id="gc-07"></a>**GC-07** 恢复责任仍在，但其敏感载荷已被要求删除。 | 分离最小事实与内容，禁止继续使用并处置受影响工作。 | 借恢复无限保留正文；删正文同时抹去动作历史。 | 删除决定、受控最小记录、缺失材料与处置结果。 |

## 14. 怎样把矩阵变成可执行用例

把一行故障矩阵转为用例时，先固定初始记录，再证明故障确实发生于指定提交或调用窗口，最后同时断言允许结果和禁止结果。每行先单独运行，再按适用范围叠加控制和故障。允许结果包含有依据的等待、明确拒绝与受控失败；验证目标是保持事实和责任准确，不要求每次注入后都完成原目标。

### 14.1 固定初始条件与注入位置

| 用例记录项 | 实施时必须补齐 |
| --- | --- |
| 追溯 | 本篇编号、正文／契约入口、用例修订；同一行的变体独立记录注入字段和位置。 |
| 环境 | 精确实现、Store／Driver／协议绑定、拓扑、声明能力、故障模型及恢复范围。 |
| 初始快照 | 原任务／操作／内部提交引用、版本、Owner、领取资格、控制、预算、窗口、已发生效果。 |
| 可重复切点 | 在指定持久提交、外部调用、应用游标或确认回包前后暂停；用夹具证明实际落在该窗口。 |
| 允许与禁止断言 | 指明哪些条件允许续跑、哪些只可等待；按该行及共同条件检查无重复、无失责、无越权。 |
| 观察证据 | 保存前后权威记录、原操作关联、模拟后端实际状态和获准消息轨迹；缺口必须显式列出。 |
| 有界结束 | 固定重试、退避、租约、处置预算、停止条件及最终观察期；未知不因测试超时变成未执行。 |

同机多进程、独立持久状态和有状态模拟端可验证大部分契约；协议故障需要实际 gRPC／WebSocket 链路。真实模型质量、真实平台支持及生产高可用分别取得其适用环境的证据，固定成功桩不能代替效果判定。

### 14.2 组合注入仍保持原身份

| 基础故障 | 需要叠加的适用条件 | 共同观察点 |
| --- | --- | --- |
| 提交未知、Worker 重启、结果交接 | 正式输入、暂停／取消、授权或来源失效、旧 Worker 迟到。 | 原身份和已完成步骤保留；新动作按当前条件检查。 |
| 子任务失联、离线恢复、Owner 移交 | 原期限届满、额度未知、其他暂停来源、接管与第二次中断。 | 不级联虚假终态，不重复分配，不出现两个合法推进者。 |
| 数据库切换、迁移和旧备份恢复 | 删除／撤销晚于快照、旧身份存活、同步确认未知、可靠输入迟到。 | 先建立可信权威和耐久依据，未决范围不新执行／披露。 |
| 扩展升级、发布与证据清理 | 旧操作未决、目标部分离线、状态格式不兼容、来源失效。 | 原绑定可恢复，逐节点应用可见，失效报告不继续放行。 |
| 队列满、重连与恢复积压 | 健康用户流量、慢消费者、单区剩余容量与资源上限。 | 控制和核对有界可用，各用户无失责或恢复饥饿。 |

连续性用例先固定故障前任务全集，并按可核对性、耐久性、权限、期限和预算划定可续跑子集。报告全集的完成、取消、真实过期、未知及丢失数量，另记原任务首次有效推进和最终交付；不能事后剔除失败者，也不能将重新领取算作业务推进。

### 14.3 实现与验收仍需补齐的内容

| 尚需补齐 | 本附录已给出的边界 |
| --- | --- |
| 最终状态类型和完整组合校验 | 正式取值、已定转换条件与禁止推论；Work、Interaction、授权和管理阶段未擅自变成封闭枚举。 |
| 注入夹具与独立判定器 | 故障切点、允许／禁止结果和证据方向；具体暂停钩子、断链方式及效果查询依实现提供。 |
| Adapter 支持范围 | 不同幂等、核对、取消、时间、耐久与隔离能力分别验证；无法支持时明确能力缺口。 |
| 冻结的验收 profile | 已确认参数保持来源基线；尚待基准的恢复水位、退避和时间目标须先确定再正式验收。 |
| 覆盖与运行报告 | 故障编号可由附录 05 关联能力、配置和报告；未执行、受阻、失败及通过按实际证据填写。 |

这些矩阵覆盖既定的必需故障窗口与跨模块断言，尚未穷尽所有状态组合或任意外部系统的失败方式。实现须补齐自身适用组合，运行验收由实际实现与演练完成；静态文档检查不提供这些运行证据。
