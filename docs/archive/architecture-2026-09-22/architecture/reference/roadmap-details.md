# 实施验收：独立替换证据细则

本资料用于核对 M3 的独立替换范围。相同实现的多份配置、内存替身或两层包装不构成独立替换；实际报告须绑定候选、环境和共同测试。

## A. 按替换对象核对证据

| 验证范围 | 必需证据与边界 |
| --- | --- |
| Brain 与 Model | 两种实际决策策略分别通过 Brain 契约；模型 Adapter 的结构化输出、位置与能力差异另报。更换模型供应商不能直接算作更换 Brain。 |
| Memory 与持久 Store | 记忆访问／组织有独立实现；SQLite 与 bbolt 分别承担所选完整配置的持久提交、快照、重启和迁移。更换数据库不能代替记忆策略替换。 |
| Execution 与设备 | Execution 整体替换和局部 Driver 替换分别验证；两种独立 API Adapter、结构树／图像观察驱动接受共同测试，模拟设备保持独立业务状态。 |
| 信息获取 | 搜索和内容获取分别有替代 Adapter，取得的来源、时间、失败及缺口可核对；实际联网单列。 |
| 原生协议与 UI | 进程内、实际 gRPC 与 WebSocket 跑共同业务及各自故障用例；包含多模拟端、多 Surface、自定义类型／事件、无任务交互、快照恢复与重复输入。 |
| 外部生态 | MCP 的 stdio／Streamable HTTP、A2A HTTP＋JSON 的入站与出站分别验证，使用独立对端或一致性夹具；Skill、脚本执行、Wasm 限制与 Renderer 兼容分别取证。 |
| 观测、评测与改进产物 | 不同组件能接入统一记录与评测，评分器替换说明可比较范围；改进产物在兼容组件中使用，授权与发布边界继续成立。 |
