# 故障恢复：控制器、阶段与高可用配置细则

本资料供恢复协调、存储 Adapter 和故障注入实现者查阅。生产参数是待锁定和验证的起点，不能替代耐久性、旧主隔离及原任务连续性的证据。

恢复矩阵沿用正文的摘要任务 T：S 保存摘要 D，外部作业 J 完成实际保存，R 在保存效果确认后读回文件。发生故障后继续核对这些原有对象，不能通过另建任务或操作绕过未知结果。

## A. 恢复控制器阶段与接手

| 恢复阶段 | 本阶段必须取得的结果 |
| --- | --- |
| 检测与归并 DETECT | 结合就绪状态、复制、积压年龄与用户错误定位范围；单次心跳超时只形成怀疑，同范围事件归并。 |
| 限制影响 CONTAIN | 摘除故障入口，限制受影响用户、分片或 Cell 的新工作；保留可用的控制、结果接收与核对入口。 |
| 建立权威 ESTABLISH | 证明当前可写分区、旧资格隔离及合法领取条件，数据库接管与端侧 Owner 接管分别判断。 |
| 核对事实 RECONCILE | 查原提交和操作，核对权限、来源修订、控制、固定版本、效果与未结额度。 |
| 分批续跑 RESUME | 保留已完成步骤，恢复原在途工作和仍有效的等待；后续工作逐项满足准入与派发条件。 |
| 核验退出 VERIFY | 原任务确有推进，交接无未处理缺口，旧资格被拒绝，未知事项收敛或明确隔离；持久记录阶段结果。 |

这些是运维阶段，不新增公共任务状态。控制器以故障范围和代次条件接纳工作，多副本竞争领取；自身退出后，接手者继续已有阶段，各模块也仍能从业务 Store 找到未决责任。管理记录不可用时停止新的破坏性切换或迁移；其他业务按自身条件判断能否继续。

<a id="stages"></a>
## B. 原工作各阶段恢复矩阵

| 故障时的阶段 | 恢复动作 | 必须保留的限制 |
| --- | --- | --- |
| T 已接纳，尚未调度 | 重新领取原工作，读取当前任务与依赖。 | 不要求用户重新提交；已终结任务不重开。 |
| 模型正在生成，提案尚未确认准入 | 先查原准入提交；确认未准入后，按当前上下文和剩余预算重新生成。 | 丢失输出不可执行，未知用量继续占用；不保证新输出相同。 |
| S／R 已准入，S 尚未派发 | 保留原操作、固定输入、实现版本与依赖；满足领取和耐久条件后派发。 | 激活新版本不改写在途绑定；资格与来源失效时先处理。 |
| 已登记启动准备，请求可能发出 | 执行模块查原提交，再用原 S 查询或核对目标。 | 没有发送回执不等于未执行；仅在可证明安全时重试。 |
| J 正在外部运行 | 电脑执行模块沿 J 有界查询或接收受控回调。 | Worker 重启不重新 `Start`；Driver 没有通用 `Resume`。 |
| 保存效果已确认，报告未交完 | 从 Outbox 补交原结果，Core 幂等合并并重新判断 R 的条件。 | 不再次保存 D，不把迟到的“处理中”覆盖到完成事实。 |
| 等待输入、授权或子任务 | 恢复原等待项、界面和子任务关系，核对期间到达的消息。 | 不创建替代子任务，不把旧回答绑定到新等待项。 |
| GUI 在动作之间中断 | 先核对原动作，再检查控制权并重新观察界面。 | 不沿旧截图坐标继续点击，不换 API／GUI 绕过未知效果。 |

## C. 高可用参数与旧主隔离

沿用《部署、存储与规模扩展》的自托管参考配置：每个数据库分片一主两备跨三个可用区，PostgreSQL 与 Patroni 管理复制和角色，独立的 etcd 仲裁组保护领导权。建议验证同步模式、严格同步、一个同步副本及业务同步提交；对应参数起点为 `synchronous_mode=on`、`synchronous_mode_strict=true`、`synchronous_node_count=1`、`synchronous_commit=on`。

同步条件不足时阻塞相应新写入；失去仲裁、候选不完整或无法隔离旧主时保持不可写。旧主隔离要求证明它不能继续接受有效写入，不能仅删除 Pod 或修改服务地址。采用 Linux watchdog 时要求 `mode=required` 并验证超时与安全余量；独立主机隔离或托管替代同样需要故障证据。[Patroni watchdog 说明](https://patroni.readthedocs.io/en/latest/watchdog.html)解释了进程暂停等情况下的隔离条件。


首个自托管验证建议使用三个 etcd 成员，每个可用区一个；各 Cell 的仲裁组独立，共享控制数据库采用独立 HA 组，避免把单个仲裁或数据库切换扩成所有 Cell 的共同故障。参考环境为能够落实主机隔离的专用 Linux 节点或 VM。具体版本、仲裁、watchdog 与隔离配置必须锁定并进行故障演练；这一拓扑仍是生产参考建议，不构成部署完成或可用性承诺。
