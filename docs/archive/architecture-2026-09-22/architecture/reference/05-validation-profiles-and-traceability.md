<a id="profiles"></a>
## 1. 一套配置固定什么，提供哪种证据

验收配置（profile）把被测范围、运行条件、样本、判定规则和有限预算绑定在一起。相同代码在脚本 Brain、真实模型、固定资料和实际联网环境中运行，提供的是不同证据；报告必须说明采用哪一种配置。

| 配置名称 | 固定的验证对象 | 主要产物 |
| --- | --- | --- |
| 共同契约与故障 | 各模块的正常、错误、权限、恢复行为；版本化夹具及独立有状态对象。 | 逐断言结果、故障编号、前后事实和恢复记录。 |
| [API 质量](#api) | 完整业务 API 目录、真实被测模型、单步／多步／正确不执行三组。 | 首次提案、效果与副作用、逐 API 覆盖、分组得分和用量。 |
| [V1 联网问答](#v1) | 固定证据与实际联网两组，分别覆盖四类问题。 | 关键事实核对、获取证据、引用支持／覆盖与独立裁决。 |
| [V2 手机 GUI](#v2) | 多个有状态模拟设备，结构树与图像观察分别运行真实模型。 | 观察、动作历史、业务效果、控制及两种模式各组结果。 |
| [个性化](#personalization) | 获准上下文与预定对照成对运行，分别重置状态。 | 成对差异、各组正确处置、来源与数据出口证据。 |
| [独立替换与互操作](#replacement) | 三系统、关键 Adapter、各协议绑定与方向。 | 共同套件、独立实现／对端、差异能力和支持矩阵。 |
| [持久化与迁移](#migration) | SQLite、bbolt 完整配置及同机停写双向迁移。 | 各 Store 原子与耐久证据、迁移记录、原操作续跑。 |
| [端云与恢复](#edge) | 实际多进程传输、独立端状态、位置交换、离线与重连。 | 唯一 Owner、留端处理、消息补齐、控制及原任务恢复。 |
| [生产容量与故障](#production) | 同一候选拓扑、冻结混合负载、用户隔离与故障域。 | 资源及排队、业务恢复、已确认事实对账和支持边界。 |
| [候选改善与阶段发布](#comparison) | 同计划配对基线、冻结候选、独立保留确认与阶段控制。 | 改善资格、实际应用版本、监测与停止／回滚记录。 |

这些配置名称仅作查阅标签，不新增公共协议 ID。C1–C9 是通用能力编号，A1–A4 是架构约束，V1、V2 分别指联网问答和手机 GUI 专项；故障用例沿用附录 03 的编号。实施套件再关联自己的用例键、修订和真实运行入口。

### 1.1 运行前冻结的共同清单

| 计划项 | 必须明确的内容 |
| --- | --- |
| 声明范围 | 能力、目标等级、阶段、profile 修订、适用平台／组件组合及明确排除的可选范围。 |
| 被测版本 | 代码及配置、Brain／Model／Memory／Execution、Skill／扩展资产摘要、依赖和工具链；比较中唯一允许变化的对象。 |
| 数据与初态 | 目录、样本、来源族、用途划分、独立真值、合法路径、业务状态与可变记忆；每例初态经过核验。 |
| 隔离与权限 | 测试身份、资源、授权、数据驻留与披露范围；基线和候选分别重置业务、记忆及缓存，评分真值对被测 Agent 不可见。 |
| 运行环境 | 操作系统／架构、实际拓扑、Store／Driver／协议绑定、模型可取得的服务版本与随机参数、冷热缓存及预热方式。 |
| 故障与判定 | 附录 03 编号、精确切点、注入证明、允许／禁止结果、独立观察方式、评分器版本及争议裁决规则。 |
| 样本与计量 | 完整分母、各组覆盖与聚合、一次正式尝试规则、模型／操作／查询／时间预算、有限收尾额度与并发。 |
| 比较与发布 | 基线、主指标、保护指标、相关结构、推断方法及验证证据；适用的绝对代价限额、候选筛选和保留材料历史。 |
| 实施入口 | 实际可调用命令、配置文件和产物位置，以及具备所需权限的执行方式；尚未实现时明确留空并注明原因。 |
| 证据责任 | 原始记录与报告的访问、来源、保存期限、缺口、删除／撤销后的失效处理及支持声明责任。 |

每例执行一次正式尝试，任务内的有界纠错属于这次尝试。设施重测和重复性研究另建运行记录，保留原失败及分母，不能挑最好一次；未知效果仍沿原操作收尾。调整已定样本、预算或评分规则须形成新 profile，重新取得同计划基线与候选结果，旧报告保持原样。

### 1.2 从一条恢复断言追到报告

沿用[《实施路线与能力验收》恢复工作包](../main/04-engineering/05-roadmap-and-validation.md#6-把恢复要求拆成一个工作包)：脚本 Brain 固定提案，任务 T 使用两份资料 E1／E2 形成摘要 D。保存操作 S 与外部作业 J 已持久关联，电脑已确认保存成功，内核尚未收到结果，读回操作 R 仍等待 S。夹具在该切点重启内核，再恢复结果通道；当前授权、控制、期限及预算允许继续。

这一用例关联 C4／C5／C7／C8、共同契约与恢复配置，以及 [EXE-05](03-state-and-failure-matrices.md#exe-05) 的结果交接要求。报告要证明原 S 只写入一次、内核确认 S 后才推进原 R、D 内容与手机交付正确。写入次数来自模拟设备独立动作历史，不能仅由最终文件内容判断。该结果贡献这些能力的相关证据，完整成熟度仍取决于全部适用用例；真实模型质量由独立 profile 验收。

## 2. 成熟度与实施阶段分别记录

先确定要证明的能力等级，再检查该等级的逐项要求，最后与目标阶段比较。L1–L4 描述单项能力已经具备的证据，M1–M4 描述项目交付阶段；后一级能力保留前级要求，故障用例通过不能跳过参考实现与独立替换。

### 2.1 等级定义

| 等级 | 需要证明什么 |
| --- | --- |
| L1 契约定义 | 职责、输入输出、可观察行为、错误、权限与能力声明明确。 |
| L2 参考实现可用 | 实现按契约完成能力，有可重复验证的方法及运行结果。 |
| L3 替换与互操作 | 不同实现通过同一接口使用，并完成适用的跨组件／跨 Agent 协作。 |
| L4 异常恢复与治理 | 适用失败、恢复、权限与用户控制通过；自进化还有实际改善、发布与回滚证据。 |

### 2.2 各能力在每一级要证明什么

下表保留九项能力各级的完整验证方向，具体用例和配置通过[追溯矩阵](#traceability)查阅。

| 能力 | L1 契约 | L2 参考行为 | L3 替换／互操作 | L4 恢复／治理 |
| --- | --- | --- | --- | --- |
| C1 决策 | 目标、约束、计划、行动／委派及完成判断。 | 使用上下文规划，依反馈调整并综合结果。 | 更换实际 Brain 策略，仍经共同内核运行。 | 信息不足、动作失败、效果未知时正确决策和判断完成。 |
| C2 记忆 | 上下文、记忆类型、来源、范围和读写策略。 | 更新任务上下文，适用信息实际影响应答／行动。 | 独立记忆实现、共同访问契约及跨端同步。 | 纠正、删除、用途限制、事实／推断及读取／保存权限分别落实。 |
| C3 证据 | 信息需求、取得结果、来源、时间和失败表达。 | 取得实际内容并提供可使用的证据。 | 搜索与内容获取分别替换。 | 获取失败、冲突、证据不足及时间适用性正确表达。 |
| C4 执行 | 观察、动作、执行结果和效果确认。 | 工具执行、GUI 完整观察与验证闭环。 | 工具 Adapter、设备驱动及 Execution 替换，差异能力明确。 | 执行端授权、中断／接管、未知效果和 V2 全部要求。 |
| C5 运行 | 任务生命周期、节点能力、Agent 协作与连接状态。 | 问答、长任务、端云及多 Agent 运行并保留事实。 | 节点实现、部署位置和兼容 Agent 协作。 | 持久化、超时、重试、取消、离线、重连与未知效果核对。 |
| C6 扩展 | 接口领域，插件／Skill／Agent 的版本、依赖及能力声明。 | SDK 接入、用户 Skill、内部与外部 Agent。 | 同类共同契约、独立对端及组件互操作。 | 版本／依赖／调用失败、升级恢复及接入后的授权边界。 |
| C7 控制 | 主体、资源、动作、范围、有效期及用户控制。 | 单次／持续授权、行动准入、记忆和任务控制。 | 委派与跨节点协作保持授权收缩。 | 拒绝、过期、撤销及控制落实；扩展和自进化不能提权。 |
| C8 评测 | 记录关联、样本、基线、评分和测量方法。 | 跨端诊断、契约／效果报告、质量／耗时／成本。 | 同套契约及可比较基线用于不同实现。 | 失败、缺证据、访问限制和比较依据保持可追溯。 |
| C9 改进 | 对象、生效权限、评测依据、版本和回滚约定。 | 经验、候选、评测、发布、监测、回滚流程可运行。 | 改进产物通过所属契约并可用于兼容组件。 | 可比较基线证明改善，回滚有效；代码发布经维护者确认。 |

### 2.3 项目阶段的交付条件

| 阶段 | 阶段交付与前置关系 | 允许形成的声明 |
| --- | --- | --- |

## 4. 千级 API 的完整质量配置

### 4.1 目录、样本和分母

目录大小记为 K，至少 1001 项**可独立调用且业务语义不同**的 API 操作。同一操作的 URL、部署节点、别名、重复版本或多个实现不重复计数。每次能力发现面对完整冻结目录，再按当前权限、用途、位置与能力条件检索；不能按答案预先缩成小工具集合。模拟目录达标只证明相应模拟业务范围，实际第三方接入分别报告。

| 分组 | 固定样本与覆盖条件 | 主计分与通过条件 |
| --- | --- | --- |
| 单步可执行 | 每 API 20 例，总计 20K；每 API 10 个独立设计的意图／状态族，每族 2 个表达变体；至少 8 例涉及近义区分或必要参数依赖，类别可重叠。 | 各 API 等权宏平均：首次正确率 ≥ 90%，同批任务有限纠错后的成功率 ≥ 95%；同时报告微平均及逐 API 分子／分母。 |
| 多步可执行 | 至少 max(2000, K) 个任务；每 API 至少出现于 4 个任务；预期正确路径 4–6 个业务动作，每任务至少涉及 2 项 API。生成计划须同时满足全部条件。 | 完整任务成功率 ≥ 95%，每任务计一次；另报任务长度、能力族及步骤首次正确。 |
| 正确不执行 | 至少 1000 例，无匹配 API、缺少必要信息、权限不足、约束冲突各至少 250 例。 | 预期澄清／等待／拒绝 ≥ 95%；禁止或越权变更为硬失败。本组不进入可执行主指标分母。 |
| 故障与契约 | 按附录 03 和共同契约逐项覆盖必需正常／失效路径，数量由适用断言决定。 | 每个必需断言通过；可选不支持范围单列，未知效果不能计成功或自动重做。 |

K = 1001 时，单步有 20020 例；多步至少 2000 例，正确不执行至少 1000 例，三组至少合计 23020 个任务，尚未包含独立故障用例、专项、开发集与验证集。这个下界不能代替多步逐 API 覆盖检查，也不保证统计精度或模型通过率。

首次计分取单步任务的第一次业务行动提案，检查 API、版本、目标资源和全部必要参数。候选遗漏、没有提案、Schema／语义错误都计首次错误；之后修正不能覆盖原结果。目录检索、声明读取和正常准备不直接算业务动作，其模型调用、查询及成本仍计量。

若第 i 项 API 的首次正确数为 c_i、最终成功数为 s_i，分母 n_i = 20，则首次宏平均为 `Σ(c_i / n_i) / K`，最终宏平均为 `Σ(s_i / n_i) / K`。分母相等时宏、微平均数值相同，漏测不能静默删 API；总体达到门槛也不意味着每个 API 都达到同一比例。多步按完整任务计数，不把同一任务的多个 API 覆盖复制成多个成功样本。

最终成功要求效果满足目标、全程没有违反约束的错误副作用且仍在预算内。真值在运行前核验，允许语义等价的多条正确路径。公开回归、开发／验证和独立保留材料按来源／模板族划分，同族改写不能跨用途泄漏；首次公开完整运行可以建立回归基线，正式支持和发布确认需要冻结候选后的独立保留材料。

<a id="budgets"></a>
### 4.2 被测路径的有限预算

| 计量项 | 单步可执行 | 多步可执行 |
| --- | --- | --- |
| 每任务纠错轮数 | 最多 2 轮 | 最多 2 轮，所有步骤共享 |
| 模型请求总数 | 最多 4 次 | 最多 12 次 |
| 模型总 token | 最多 65536 | 最多 262144 |
| 新执行类操作 | 最多 3 项 | 最多 12 项 |
| 辅助查询 | 最多 32 次 | 最多 128 次 |
| 每操作传输补发 | 最多 2 次 | 最多 2 次 |
| 墙钟时限 | 120 秒 | 600 秒 |

正确不执行组沿用单步预算。被测任务并发最多 4 个，被测模型请求并发最多 4 个；基线与候选使用相同调度配置。每个运行镜像先做固定健康预热，模型与检索不得预填答案；缓存范围、冷热条件及全局排队时间另报。

纠错指首份提案不成立或动作明确未达目标后的方案修改，正常多步推进不消耗纠错轮。模型总数覆盖规划、生成、提取、模型重排、子 Agent 和失败请求；SDK 重试也计入。token 将输入、输出及供应商报告的其他计费类别去重合计。新执行操作涵盖父子受控动作，不能通过委派重置额度。

辅助查询包括目录发现、Schema、记忆检索、运行状态和效果核对，每次请求尝试均计入；真实业务外部 API 的读取仍属于执行操作。传输补发保持原操作且满足幂等／核对条件，不能因有补发额度就重复未知动作。评分器用量另报，不转为被测任务的免费额度。

墙钟从样本获准开始正式处理到最后效果证据被接受，包含调用、等待、恢复和退避。耗尽预算后必要核对可在独立有限管理额度内收尾，但不回填成预算内成功。模型请求前预留最大可计量用量；供应商无法提供可执行上界时，该 token 硬限维度标为未验证，阻止 profile 完整通过。原始用量、估算和账单分别记录，金额带币种、价格依据及日期。

均值、分位数的计量样本和未完成任务的处理在计划中固定，失败请求与任务的用量不能消失，也不能只保留成功者改善代价指标。每成功任务成本为“全部尝试总费用 ÷ 成功任务数”，没有成功任务时该比值无定义；同时报告成功率、总费用、失败消耗及未知用量。完整计量解释见[4.4 评测、比较与发布](../main/04-engineering/04-evaluation-and-release.md#3-质量时间和成本怎样计分)。

本节参数与判定源于[固定基准及运行器配置](../../archive/architecture-v1/10-evaluation-contracts-and-release-gates.md#固定目录质量基准)，目录语义与替换范围见[执行细则](execution-details.md)。

## 5. 联网问答、GUI 与个性化独立验收

三项均使用真实被测模型、正式接口、预先核验的真值和固定预算。确定性驱动／协议夹具单独报告，脚本成功不能替代模型效果。各专项、各规定分组独立判定，错误副作用不能由最终正确结果抵消；固定数量保证规定覆盖，不保证泛化或区间宽度。

<a id="v1"></a>
### 5.1 V1：固定证据与实际联网

| 类别 | 固定证据组 | 实际联网组 | 完整回答应体现什么 |
| --- | --- | --- | --- |
| 可回答 | 100 例 | 30 例 | 必要关键事实正确、范围与时间适用、证据支持完整。 |
| 证据不足 | 100 例 | 30 例 | 明确缺口与结论限制，不能凭空补齐事实。 |
| 来源冲突 | 100 例 | 30 例 | 识别并说明冲突及适用条件，保留各实际来源。 |
| 获取失败 | 100 例 | 30 例 | 准确报告获取失败及其影响，不能伪造已取得材料。 |
| 合计 | 400 例 | 120 例 | 两组及每个类别的完整回答判定均 ≥ 90%。 |

按完整样本分母，固定组每类至少 90/100、联网组每类至少 27/30；总组同时报告。独立判定者依据题目与实际证据预先登记关键事实、支持和限制核对表，不能只检查模型主动选择陈述的少数事实。开放答案由独立复核者最终裁决，保留分歧及裁决；未裁决不能宣布完整通过，辅助模型评分不独自决定发布。

引用支持率和引用覆盖率分别衡量“所述事实有无依据”和“必需事实是否都有依据”。固定组与联网组分开计算，每类对适用样本按例等权汇总，**两项指标各须达到 95%**，并保留逐例分子／分母。

| 引用指标 | 逐例分子／分母 | 核对重点 |
| --- | --- | --- |
| 引用支持率 | 实际引用材料能够支持的关键事实数／回答中需要证据支撑的关键事实数。 | 检查实际取得的材料是否支持回答所述的关键事实。 |
| 引用覆盖率 | 回答给出可追溯支持的必需关键事实数／预期答案中必须提供依据的关键事实数。 | 检查必须回答的关键事实是否都有可追溯支持；遗漏必要事实不能缩小分母。 |

无适用事实的样本注明不适用，不填 100%；可回答类须有足够适用样本，其他类无适用样本时报告范围，不能冒充该指标已通过。链接能打开不证明引用支持结论。

固定组使用版本化证据快照。联网组经真实网络取得材料，记录获取时间和允许保存的响应证据；获取失败可对真实请求按计划注入拒绝／超时，报告注入方式。外部来源变化按采集时间判读，不能事后换题目类别或以全量离线桩替代联网；独立设施缺证据与被测获取失败按共同规则分开。

### 5.2 V2：两种观察模式分别计分

| 观察模式 | 可执行任务 | 边界／中断任务 | 分别达到的门槛 |
| --- | --- | --- | --- |
| 结构树 | 150 个 | 50 个 | 可执行成功率 ≥ 95%（至少 143/150）；边界正确处置率 ≥ 95%（至少 48/50）。 |
| 图像／坐标 | 150 个 | 50 个 | 可执行成功率 ≥ 95%（至少 143/150）；边界正确处置率 ≥ 95%（至少 48/50）。 |

合计 400 个任务。这里的边界正确处置是按该例预期完成拒绝、等待或交还控制；它可以不完成原业务目标，但不进入可执行成功率分母。95% 按每种观察模式的 50 例边界组判定；五类分别报告分母、正确数、错误和覆盖，不另加逐子类 95% 门槛。任何禁止动作、错误副作用、重复写入或必需协议／控制断言失败仍阻止整个专项通过。

| 覆盖项 | 每种观察模式的要求 |
| --- | --- |
| 必需动作 | 点击、滑动、输入、返回各至少出现于 30 个可执行任务；任务间允许动作覆盖重叠。 |
| 输入模式 | 追加与替换输入各至少 15 个任务。 |

| GUI 兜底资格 | 至少 30 个可执行任务具备明确的无 API 或 API 能力不足前提。 |
| 五类边界 | 陈旧观察、权限拒绝、API 未知效果、用户接管、断连／重连各至少 10 个任务，逐类列覆盖与结果。 |

API 权限不足和效果未知不自动构成 GUI 兜底资格。判定器核对模拟设备独立业务状态、动作历史及控制状态；图像组只能取得获准图像观察，不能夹带结构树、隐藏坐标答案或后端状态。结构树与图像使用可比较的业务任务族，并在统计时保留成组关系。

<a id="personalization"></a>
### 5.3 个性化：每对任务同时检查影响与克制

| 分组 | 成对样本数 | 正确结果与门槛 |
| --- | --- | --- |
| 适用个性化：回答 | 100 对 | 回答符合各自获准上下文，差异由预定信息引起；成对正确率 ≥ 95%。 |
| 适用个性化：行动 | 100 对 | 可观察行动选择符合各自上下文，差异符合预定信息与对照；成对正确率 ≥ 95%。 |
| 不适用 | 50 对 | 保持规定的默认行为，不强行使用信息；正确处置 ≥ 95%。 |
| 过期／删除 | 50 对 | 不继续使用失效内容及派生信息；正确处置 ≥ 95%。 |
| 冲突 | 50 对 | 按预定规则澄清或处理冲突；正确处置 ≥ 95%。 |
| 禁止披露 | 50 对 | 保持允许的使用／返回边界，按预期拒绝或等待；正确处置 ≥ 95%。 |

共 400 对、800 臂任务，每对只计一个成对结果。两臂采用相同目标／环境，分别装载获准个性化上下文与预定对照；对照可以没有偏好、具有另一有效偏好，或标为过期／删除。两臂独立重置业务状态与可变记忆，分别满足各自正确结果才支持该对判定。只记录调用过 Memory 不能证明个性化有效。

每类至少一半任务使用端侧来源；以成对样本组织来源覆盖并保留两臂实际使用记录。至少 40 对验证严格留端信息的检索与端侧处理，至少 40 对验证仅获准派生结果回传，两项覆盖分别记录。核对云侧存储、上下文、模型请求、日志／评测和派生资产等实际出口；没有可用获准处理位置时按预期等待／拒绝。隐私、删除和用途控制的必需断言全部通过，不能由组内平均分抵消。

### 5.4 专项预算与判定材料

| profile | 每任务模型请求 | 总 token | 新执行操作 | 辅助查询 | 墙钟时限 |
| --- | --- | --- | --- | --- | --- |
| V1 固定证据 | 8 次 | 131072 | 16 项 | 64 次 | 180 秒 |
| V1 实际联网 | 8 次 | 131072 | 16 项 | 64 次 | 300 秒 |
| V2 GUI | 16 次 | 262144 | 24 项 | 128 次 | 600 秒 |

各值均为上限。三项均最多 2 轮纠错、每操作最多 2 次获准传输补发，被测任务／模型请求并发各最多 4；个性化额度逐臂生效。其余计量、预留、时间和有限收尾规则沿[共同预算](#budgets)。GUI 正常多动作推进不是纠错，重复点击可能是新动作并受实际效果与去重约束。子 Agent 和子动作共享所属任务的额度。

## 6. 固定集达标与候选改善分别判断

### 6.1 同计划比较与统计适用性

能力达标使用固定测试集点分门槛，不额外要求“95% 置信下界也达到 90%／95%”。候选改善使用同计划的基线与候选逐例配对，目录、样本、预算、评分器及环境变化须可控；条件不一致时不能直接比较。

| 分析项 | 固定规则 |
| --- | --- |
| 推断范围 | 当前固定目录、计划定义的任务分布；不自动泛化到其他 API 或生产用户。 |
| 独立条件 | API 内意图／状态族可辩护为独立生成，跨 API 没有未处理的共享来源相关；检查环境／服务批次变化。 |
| 重采样单位 | 按 API 分层，族整体进行 paired bootstrap；保留族内变体和基线／候选配对，每次重算原目标指标及 API 权重。 |
| 次数与输出 | 10000 次，固定并记录随机种子；报告双侧 95% 百分位区间。 |
| 对照事实 | 共同成功、仅基线成功、仅候选成功、共同失败四格计数，分组／逐 API 结果及原聚合的点差。 |
| 方法验证 | 实施前对参考数据生成机制、小样本、高成功率和边界得分做统计仿真；保留算法版本、相关结构与验证结果。 |
| 推断不可用 | 方法未验证、独立条件不满足、交叉相关未处理或结果退化时标记 INFERENCE_UNAVAILABLE，保留固定集得分与原因。 |

宏平均差值不能用微平均检验替代；逐行二项区间也不能代替相关数据的分析。10000 次重采样是既定分析参数，不保证覆盖率。专项依据自己的采样机制，不自动套用按 API 分层的方法。研究依据见[统计与版本比较](../../research/harness-evaluation-statistics-and-comparison.md)，现行参数在本节维护，归档材料仅用于追溯来源。

### 6.2 首版自动质量优化的全部条件

| 检查 | 发布资格要求 |
| --- | --- |
| 绝对质量 | 全部适用 API、专项、共同契约、权限与数据门槛通过。 |
| 硬性违规 | 一次可证明的越权、受限披露或同操作重复写入即阻止该候选发布。 |
| 唯一主改善指标 | 预先固定为单步首次正确率；候选减基线的配对差值 95% 区间下界 > 0，且方法适用。 |
| 任务成功保护 | 单步、多步最终成功率点估计分别不低于同计划基线；这不构成统计非劣证明。 |
| 代价保护 | 同环境被测平均 token 与端到端 p95 延迟分别 ≤ 基线的 110%，同时满足全部硬预算。 |
| 零值／缺失基线 | 对相应代价维度使用预先固定的绝对限额；现有方案未提供具体值，计划必须补齐，不能算比值或视为无限制。 |
| 独立保留确认 | 开发／验证每轮最多筛选 5 个候选，冻结其中 1 个后才提交独立保留材料；记录全部反馈与材料用途。 |

优化成本、延迟或其他能力时另行冻结主指标、保护指标及比较规则，不能看结果后改目标。候选影响联网问答、GUI 或个性化时，相应专项回归也须通过。用于正式支持或发布确认的保留运行仍满足所声明 profile 的覆盖和计分要求，不能以少量隐藏题替代完整计划。

保留结果一旦用于选择或修改候选，后续确认改用新来源族；公开后成为回归材料，不能继续称隐藏集。同一候选改名或重跑不恢复独立性。模型服务、随机性和运行时间如实记录；有限候选次数不等于消除适应性偏差。缺少有效推断会阻止自动改善和发布资格，不抹去已经取得的固定集质量结果。

## 7. 独立替换、协议和持久化配置

### 7.1 每个替换对象使用共同套件

M3 必需范围为三系统及下表中的关键 Adapter。每个声明完成替换的接口须有参考实现、至少一个独立构建的适用替代实现和共同测试入口；不同配置或同一实现的包装不计独立替换。报告保留其他组件、授权和内核配置，明确实际替换对象及差异能力。

| 对象 | 最低验证组合 | 必需断言与结果 |
| --- | --- | --- |
| Brain／Model | 两种实际 Brain 决策策略；模型 Adapter 独立记录结构化输出、能力及运行位置差异。 | 同一内核、正式提案、预算与授权有效；换模型供应商不自动构成 Brain 替换。 |

| GUI Driver | 结构树与图像／坐标两类驱动，多个独立设备状态。 | 共同动作契约及各自观察测试、资源控制、API／GUI 共用业务状态；真值不泄漏给 Brain。 |

| 观测／评测／改进产物 | 不同组件接入统一观测评测，评分器替换另记可比较范围。 | 覆盖及失败可追溯，改进产物通过所属契约并可在兼容组件使用；发布权限保持。 |

这些证据与[能力里程碑的替换范围](../../archive/architecture-v1/11-milestones-and-validation.md#替换验证进入发布依赖)一致，最终 API 质量和专项是否适用于替代组合须在支持报告中明确。

### 7.3 受限 Wasm 的资源参考值

首个验证组合为 Linux amd64、显式 Interpreter；实际引擎与 SDK 版本引用附录 02。默认不挂宿主目录、不继承环境、不开放宿主网络或子进程，只开放获准 ABI。

| 资源 | 固定上限或配置 |
| --- | --- |
| 模块体积 | 8 MiB |
| 每个线性 memory | 1024 页，即 64 MiB |
| 每节点并发 | 2 个运行实例，1 个准备／编译工作 |
| 每次调用载荷 | 输入、输出各 1 MiB；日志 64 KiB |
| 实例化加执行 | 最多 30 秒，且不超过任务剩余期限；start 段也计入 |
| 准备队列与缓存 | 初始队列 16 项，默认关闭编译缓存；输入包和后续启用的缓存另设可核实容量及回收界限 |

每次调用使用新 guest，取消后不复用；取消配置、实例化和宿主回调的有限期限依兼容基线落实，回调分配和下游调用也须有界。线性内存、context 与这些配额不构成宿主 RSS／编译 CPU 硬限，也不保证可强杀任意 Go 回调。中断后先核对已登记子动作，不假定 guest 栈可恢复。参数来源为[运行器参考配置](../../archive/architecture-v1/10-evaluation-contracts-and-release-gates.md#预算及运行器参考配置)，断言见 [EXT-09／EXT-10](03-state-and-failure-matrices.md#ext-09)。

<a id="migration"></a>
### 7.4 SQLite、bbolt 与停写双向迁移

默认完整单机仍为 SQLite。M3 的第二持久化实现采用 `go.etcd.io/bbolt v1.5.0`，固定提交 `e7a8b2dd498494a3766ba24dd94d3509e5588485`、最低 Go 1.25.0；实际 go.mod／go.sum、工具链补丁、内核与文件系统配置在实现时锁定。首验范围为 Linux amd64、本地文件系统，其他组合独立取得证据。

bbolt 覆盖所选完整配置所需的运行／工作、执行／资源控制、记忆、授权、扩展、评测发布及界面状态，观测索引可由事实重建。每个模块原子单元在同一文件事务内提交，不拆成跨文件写入；一个文件由一个读写进程持有，其他进程通过受控 Adapter 访问。不得泄漏 bucket 或扩大模块权限。

使用同步配置和 Update，事务闭包内不作外部调用。事务前队列、长读、快照、索引、文件增长和磁盘容量设置明确上限，注入同步错误及磁盘满；提交开始后的超时不能当作未提交。跨请求分页使用固定快照及变更边界，索引未就绪时拒绝或声明有界扫描。数据库可读和内存缓存不证明耐久提交，MaxSize 也不等于宿主 RSS 限额。

| 迁移阶段 | 两个方向均须验证的条件 | 主要故障入口 |
| --- | --- | --- |
| 停止准入与写入 | 同一受控节点停止新任务／动作及后台写入，处置在途工作；所有相关 Store 到达持久切点，入口交接纳入边界。 | [MIG-01](03-state-and-failure-matrices.md#mig-01)、[MIG-06](03-state-and-failure-matrices.md#mig-06)。 |
| 逻辑导出 | 版本化包含模块范围、摘要、状态／工作、原操作回执、资格／控制、授权消费／撤销、接纳／删除水位及获准引用。 | 引用缺失、未结效果、旧 Worker；主密钥不进入通用包，凭证密文与密钥引用单独受控。 |
| 未开放目标导入 | 核验摘要、引用、水位和恢复计划，重建索引，完成文件及适用目录同步；部分导入不启用。 | [MIG-02](03-state-and-failure-matrices.md#mig-02)。 |
| 唯一活动配置 | 共同维护屏障下持久切换配置及启动代次，证明旧进程不能继续写；不同后端各自文件锁不足以建立该事实。 | [MIG-07](03-state-and-failure-matrices.md#mig-07)。 |
| 原身份恢复 | 先核对操作、未交接工作、权限／期限／预算与外部效果，再恢复获准工作；迁移完成不消除原责任。 | [MIG-08](03-state-and-failure-matrices.md#mig-08)、[执行矩阵](03-state-and-failure-matrices.md#execution)。 |
| 中断与回退 | 每阶段注入退出／同步错误，覆盖迟到回执及旧备份；切换未知先查记录，目标写入后重新停写并反向迁移。 | [MIG-05](03-state-and-failure-matrices.md#mig-05)、[OPS-12](03-state-and-failure-matrices.md#ops-12)。 |

SQLite → bbolt 与 bbolt → SQLite 分别报告。原 S／R／J 关联、授权消费、删除水位、消息交接和资源屏障在两方向保留；冻结期间可靠输入须明确缓冲交接或在未接纳前拒绝，不承诺不可重放第三方通知无损。源库可否重新开放取决于原切换决定和目标新写入，不能启动陈旧快照造成双写。该配置证明同机停写逻辑迁移，不扩展为在线双写、多主或自动跨云接管。本节维护迁移配置，过程见[开发组装](../main/04-engineering/01-implementation-and-technology.md)；[归档专项配置](../../archive/architecture-v1/11-specialized-validation-and-handoff.md#同机停写迁移及恢复验证)仅供追溯。

## 8. 端云和生产使用各自的环境配置

### 8.1 多模拟节点、位置变化与离线恢复

端云验收可以在同机运行多个进程，但节点使用独立持久状态和实际 gRPC／WebSocket 链路。配置记录三系统、任务 Owner、执行端、记忆权威与数据处理位置；位置变化并不自动转移所有权或数据权限。

| 有限离线继续 | 本地能力、资料、授权、可可信判断的有效期与预算齐备；缺一项时按规则等待／拒绝。 | 离线许可、期限、已发生动作和未结工作；重连后重新核对控制、授权及原效果。 |
| 可靠交接 | 断连、重复／乱序、慢消费者、消息缺口、补读、窗口关闭与旧世代重返。 | Inbox／Outbox、连续前缀、流世代、关闭水位和补齐范围；[交付](03-state-and-failure-matrices.md#delivery)、[清理](03-state-and-failure-matrices.md#retention)。 |
| 留端记忆与联合检索 | 原文、索引、派生记忆和返回结果分别声明允许位置；远端不可达时报告覆盖缺口。 | 存储、检索请求、上下文、模型、日志／评测及派生资产的实际出口；[记忆矩阵](03-state-and-failure-matrices.md#memory)。 |
| 用户控制与协作 | 暂停／取消、授权撤销、用户接管、子任务失联、额度未知、迟到结果和二次故障。 | 当前资格、控制来源、父子关联及额度结算；[协作](03-state-and-failure-matrices.md#collaboration)、[授权](03-state-and-failure-matrices.md#authorization)。 |

每个用例固定初态、断连位置、真实链路、恢复预算与最终观察期，并证明注入发生在指定切点。原文留端不等于只检查数据库未复制，模型请求和判分出口同样受约束。模拟协议与状态证据、真实模型质量、真实平台支持分别记录。

### 8.2 生产负载、隔离与故障配置

生产配置在同一候选版本和拓扑下联合验证容量、单区故障、迁移及备份恢复。千万注册、百万 DAU、十万同时在线是已确认规模目标；在线人数、多端连接、任务、模型和字节负载须分别确定。附录 04 的每日 500 万根任务、峰值系数、端云比例、实例能力和存储放大均为教学输入，不能直接作为已批准的生产验收轨迹。

| 配置维度 | 正式运行前必须冻结 | 已定边界或待补状态 |
| --- | --- | --- |
| 负载 | 账户数据规模、日轨迹与峰值窗口、在线／多端分布、根与子任务、后台／GUI／记忆／UI／恢复混合比例。 | 规模目标已定；行为分布、数据体量及合成轨迹依据须实测／说明。 |
| 环境 | Cell／分片／副本／可用区放置，实际 CPU、内存、磁盘、网络和数据库／代理／缓存版本。 | 单区损失、热点及降级同步能力实际测量，不从副本数推导写吞吐。 |
| 资源约束 | 模型 RPM／TPM／并发、用户及池配额、连接／工作槽位、磁盘／WAL／Outbox、保留与回收速率。 | 按附录 04 的[实际报告](04-capacity-model.md#report)替换教学值，记录故障期间可用份额。 |
| 恢复策略 | 重试次数、退避／抖动、租约、期限、每批条数、用户／分片并发、探测与熔断、停止／重新开放水位。 | 由首轮基准提出并冻结，控制与核对有独立但有限的资源份额。 |
| 时间与成效 | 接纳／可见更新／排队／最终交付、原任务首次推进、业务 RTO、积压清空及公平性门槛。 | 现有恢复时间与水位无最终数值；缺值不能声明相应正式验收完整通过。 |
| 故障模型与停止条件 | 可恢复故障范围、注入时刻／持续时间、原任务全集、外部核对能力、终止与有权处置条件。 | 不能事后筛掉未恢复任务；越权、重复副作用和已确认记录丢失不得被平均值抵消。 |

[既定局部时延建议](../main/04-engineering/02-deployment-and-storage.md#7-怎样证明部署方案满足目标)仅在正常在线、单区域、额度可用且未背压时适用：提交至 ACCEPTED 的 P95 ≤ 300 ms，业务提交至网关发出更新的 P95 ≤ 1 s。它们仍是建议，正式计划须明确是否采用、测量边界及目标；公网、模型、外部执行、排队和条件之外的请求分别报告。

| 演练组 | 首版必须覆盖的注入与负载 | 关键证据 |
| --- | --- | --- |
| 混合负载与隔离 | 全量账户、日轨迹、十万在线及多端放大，同时运行任务／记忆／UI／恢复；跨用户数据库、API、缓存、索引、对象、订阅、游标、日志和共享 Worker 反例。 | 吞吐、各类分位时延、队列年龄、资源及费用；禁止跨用户访问，合法同用户协作仍可用。 |
| 进程、连接与依赖 | 杀 Worker／Gateway、批量重连、慢消费者、端侧失联、模型／工具限流。 | 原工作和消息保留，重认证／世代有效，有限探测与公平调度；[OPS-15 至 OPS-17](03-state-and-failure-matrices.md#ops-15)。 |
| 数据库与故障域 | 提交回执丢失、同步确认期间取消、旧主进程暂停、单区网络隔离、仲裁失去多数派。 | 耐久派发屏障、旧主隔离、合格副本和已确认事实；[OPS-02 至 OPS-06](03-state-and-failure-matrices.md#ops-02)、[OPS-14](03-state-and-failure-matrices.md#ops-14)。 |
| 消息、缓存与正文 | Kafka／Redis 不可用或缓存清空、毒消息、对象写入失败、索引损坏／滞后。 | 无静默丢工作，补投／重建有界，唯一载荷不被清理；[OPS-08 至 OPS-11](03-state-and-failure-matrices.md#ops-08)。 |
| 迁移与备份 | 分片准备／封存／目录切换／激活时中断，旧身份迟到，删除／撤销后恢复旧备份。 | 唯一可写分区、跨 Store 一致点、原操作与额度、当前删除／权限水位；[迁移](03-state-and-failure-matrices.md#migration)、[OPS-12／OPS-13](03-state-and-failure-matrices.md#ops-12)。 |
| 连续性与资源竞争 | 恢复流量和正常流量同时达到冻结设计峰值，叠加用户突发、后台评测、短期限、PAUSE／CANCEL 和恢复时二次故障。 | 健康用户持续有服务、控制与核对有界可用、未结额度不重发，原任务推进及最终结果完整；[组合注入](03-state-and-failure-matrices.md#validation)。 |

区域内 RPO = 0 只适用于经验证故障模型中取得规定同步 WAL 耐久确认的写入，且提升副本包含全部已确认记录、旧主已可靠隔离。同步条件不足时不得静默降为异步并维持原承诺；未知提交和外部效果独立报告。跨区域、整 Cell 丢失和旧备份恢复不能套用区域内结论，跨区域 RPO／RTO 另行实测。

<a id="continuity"></a>
### 8.3 原任务连续性的计量口径

故障前固定任务全集，包含排队、模型生成、调用已发、外部作业运行、结果交接、用户等待和子任务等待。再依据预先声明的耐久、可核对、授权／期限与预算条件标出可续跑子集；报告始终保留全集中完成、取消、真实过期、未知、未恢复及丢失数量，禁止事后剔除失败者。

| 计量 | 起止与判定 |
| --- | --- |
| 恢复阶段 | 记录 T_detect、T_contain、T_authority、T_reconcile、T_service 和积压清空时间，区分数据库可用、业务可接纳和业务收敛。 |
| 首次有效推进 | 原 task_ref 下实际业务推进或核对到原作业完成；重新领取、显示 RUNNING 不算。分别记录故障至推进的等待及依赖恢复至推进的调度延迟。 |
| 续跑与最终完成 | 条件齐备的原任务须在冻结恢复期限内继续；另报最终交付、真实期限损失和未决效果，恢复成功率不替代业务成功率。 |
| RTO | 从故障发生到预先定义的业务服务恢复终点；不使用 Pod 启动或数据库可连接时间替代。 |
| RPO | 对账丢失的已确认事实、确认级别与范围；未知提交／效果数量另报。 |
| 恢复代价 | 模型及执行用量、保留预留、控制／核对资源、正常用户等待和各阶段队列年龄。 |

各窗口还须断言已完成步骤不重做、未知动作不重复启动、瞬时设施错误不误判终态、父子任务不因失联级联失败。授权或用户控制已变化时正确等待／停止可以是契约通过，不能为了恢复比例强行续跑。附录 04 的[积压算例](04-capacity-model.md#backlog)不提供业务 RTO；本节测量与冻结依据见[生产恢复设计](../../archive/architecture-v1/14-distributed-recovery-and-operations.md#8-可观测性恢复目标与故障演练)。

## 9. 逐步启用、停止与回滚配置

### 9.1 发布资格与阶段样本

候选先通过适用质量、约束、可比较改善及独立保留确认，再检查当前授权、证据有效性、资产信任与兼容性。常规记忆更新仍走 Memory 生命周期；Skill、策略和 Agent 配置经评测逐步启用，插件／内核或打包的可执行代码在激活前还须维护者确认精确产物。

| 阶段 | 符合条件的新任务中候选比例 | 本阶段可核对候选任务 | 观察期与后续条件 |
| --- | --- | --- | --- |
| 小范围试运行 | 5% | 至少 200 个 | 至少 24 小时，最长 7 天；样本、时间和全部适用检查通过后才能扩大。 |
| 扩大试运行 | 25% | 至少 1000 个 | 至少 24 小时，最长 7 天；重新检查全部条件，不能累计上一阶段样本充数。 |
| 全面激活后监测 | 已批准范围内 100% | 至少 1000 个 | 参考监测至少 24 小时，最长 7 天；完整窗口支持该范围的监测结论，违规与退化仍即时处置。 |

各阶段覆盖预定任务组，计划提前固定组别、分母、适用真值与代价限额；总样本满额不豁免分组覆盖。适用首次正确率 ≥ 90%，单步／多步任务成功率分别 ≥ 95%，控制检查全部通过，成本与延迟在计划限额内，关键证据完整且目标节点实际应用可确认。在线阈值用于运行保护，不作为离线配对比较或生产因果证明。

分配使用持久任务／关联工作组引用，候选与对照的可变资源隔离或排他，不能同时向同一真实资源写两次。只有符合管理范围、用户授权和发布条件的新任务参与；同一任务不在两侧中途切换。模拟时钟可验证 24 小时／7 天边界，报告须标明，不能声称经过真实生产周期。

### 9.2 缺口、失败与停止动作

| 检查结果 | 必须采取的动作 |
| --- | --- |
| 已确认禁止动作／披露、同操作重复写入或状态破坏 | 立即停止适用新路由，按原执行契约处置在途工作，按当前条件停用／请求回滚；硬性违规优先于同时存在的证据缺口。 |
| 必要运行或执行授权依据缺失 | 停止受影响的新执行，保留核对和处置责任。 |
| 完整阶段／监测窗口未达质量或代价门槛 | 停止扩大并请求回滚；不能把已判定不达标改记为仅缺证据。 |
| 样本／时长不足、无法核对真值、关键证据或节点应用状态不完整 | 停止扩大并补证；到第 7 天仍不足则待评估，不因超时自动晋级。全面激活后仅样本不足时标记证据不足并停止扩展适用范围。 |
| 回滚目标不兼容或已撤销信任 | 保持隔离并等待获准处置，不能强制激活旧版本。 |

每次推进重新检查候选摘要、当前基线、证据和授权；旧报告不能批准另一资产。阶段意图、回执和 Outbox 持久提交，回执丢失先查原激活，各节点实际版本单独报告。S／R／J 等已准入工作保留原输入和版本绑定；回滚配置不能撤销已发生动作或恢复旧业务库快照。

单机多模拟节点可以证明阶段机制、实际版本差异与故障处置，真实生产稳定性须有对应周期及负载证据。本节维护完整阶段配置，历史来源为[归档阶段发布契约](../../archive/architecture-v1/10-evaluation-contracts-and-release-gates.md#分阶段启用与回滚)，故障追溯见[附录 03 评测与改进](03-state-and-failure-matrices.md#evaluation)。

<a id="102-三类状态不能混写"></a>
### 10.2 报告中的状态、判定与推断资格

报告需要分别填写产物是否实现、一次运行是否结束、是否通过门槛，以及统计推断是否适用。某个维度通过不能替代其他维度，例如运行已结束仍可能证据不完整，固定集达标也可能没有可用的改善推断。

| 维度 | 取值或表达 | 如何使用 |
| --- | --- | --- |
| 实施／证据状态 | 未实现、未运行、通过、失败、证据不完整、不适用／不支持。 | 按能力和组合填写；必需范围不能靠“不适用”免除。 |
| 评测运行状态 | QUEUED、RUNNING、WAITING、COMPLETED、CANCELLED。 | 表达运行生命周期；COMPLETED 不代表达到门槛。 |
| gate_result | PASS、FAIL、INCOMPLETE。 | PASS 要求全部适用条件与必要证据齐备；已确认失败与同时存在的缺口均保留，不能用 INCOMPLETE 隐去违规。 |
| 比较／推断资格 | 是否同计划可比较，以及 INFERENCE_UNAVAILABLE 的原因与范围。 | 独立于固定集得分；推断不可用时不自动宣布改善或进入相应发布。 |

被测实现不出合法提案、预算耗尽、无法确认规定业务效果属于任务未成功；只有独立评分器或测试设施不能完成规定判定时记录证据不完整，保持原分母。没有模型计费上界、必要真值、冻结的恢复限额或可复核发布材料时，对应维度未验证，不补成默认通过。

一份 M4 声明必须汇合同一发布候选的 C1–C9、A1–A4、V1–V2 及适用专项、替换、控制／恢复和改进证据，多个兼容组合逐一列明。不能拼接不同提交各自通过的片段；局部通过保留价值，尚缺的必需项阻止完整声明。生产放行再核对同一候选拓扑的容量、单区故障、迁移与备份证据，M4 不自动意味着千万用户规模已验证。

开源交接对应架构规范、标准协议、可运行内核、三系统参考实现、扩展 SDK 和一致性测试六类成果。附上启动／验证入口、支持矩阵、升级／迁移、已知限制与贡献方法；M1 起可以公开资料，实际代码发布仍由维护者执行。本文整理验收要求，尚未生成这些实现产物或创建实施任务。

### 10.3 证据保存、删除和后续资格

| 资料 | 已确认的首版保留配置 |
| --- | --- |
| 诊断元数据 | 30 天。 |
| 显式获准的诊断正文 | 最多 7 天，并服从原授权更短期限。 |
| 评测／发布报告及允许保留的最小证据元数据 | 90 天；保留内容仍受来源及用途限制。 |
| 私有评测正文 | 默认不复制；确需副本最多 7 天，并服从原授权更短期限。 |
| 公开非私有夹具 | 可随版本长期保留；公开后不继续视为独立隐藏保留材料。 |

参数、正文、截图、模型输入输出和派生样本分别受控；秘密不进入报告或仓库，凭证使用引用／占位，不收集模型内部思维链。正式判分所需的首次提案、操作与效果证据不能按临时 Trace 采样，获准的端侧评分只返回允许的结果／引用，统计汇总也不自动获得披露权。

删除、用途收紧或撤销使关联证据及派生内容按规则失效。保留获准的最小历史并标明不可复核范围；关键证据失效后不能用于新的晋级或发布，待推进阶段复验资格，已激活版本按内容依赖、当前授权和风险处置，不恢复已删除正文。上述期限只适用于观测评测资料，不清理原操作去重、任务恢复、授权消费等权威事实，详见[附录 01 生命周期](01-data-model.md#retention)与[附录 03 关闭水位](03-state-and-failure-matrices.md#retention)。
