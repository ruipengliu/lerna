<a id="identity"></a>
## A. 设备登记与认证边界

身份管理可在单机完成；外部身份平台通过可替换的验证接口接入。下表前四项建立设备信任，后四项约束连接使用与恢复，连接成功本身不能替代信任核验。

| 环节 | 必须完成的检查 |
| --- | --- |
| 首次安装 | 从本地受信管理入口建立管理员与信任根。 |
| 新设备申请 | 提交公钥和目标用户范围；加入请求短期且一次性。 |
| 管理员批准 | 核对后登记并交付证书，私钥留在设备。 |
| 设备核对 | 验证经受信路径取得的信任根；自动发现或连接成功只提供待核对线索。 |
| 原生节点连接 | 使用双向 TLS（mTLS）互相认证。 |
| 浏览器连接 | 同源 HTTPS 登录与服务端会话确认用户；建立 WebSocket 时检查会话和来源。 |
| 连接持续／恢复 | 持续检查节点与会话是否失效，包括长连接和恢复连接。 |
| 认证失败 | 节点认证失败不能退回浏览器身份；默认直连不信任代理自报的用户头。 |

字段与认证配置见[附录 02](02-api-and-message-catalog.md#identity-configuration)，生产网关代理身份见[4.2 部署、存储与规模扩展](../main/04-engineering/02-deployment-and-storage.md)。

<a id="issuance-failures"></a>
## B. 签发、回应和提交的异常

签名内容固定到本次申请和预期策略。申请变化或提交冲突均可使已签材料失去交付资格。

| 条件 | 处理 |
| --- | --- |
| 用户拒绝 | 关闭相应等待项。 |
| 申请已变化，旧回应到达 | 旧回应失效，不能签发新范围。 |
| 同一回应重试，或管理回包丢失 | 沿原操作核对原回执。 |
| 材料已签好，提交版本冲突 | 不发送旧材料。 |
| 提交结果不明 | 先核对原提交，不重新签发或启动。 |
| 签发私钥不可用 | 等待恢复，不退回未签名许可。 |
| 批准与暂停／取消交错 | 分别保留事实；许可签发不解除任务控制。 |
| 策略硬性禁止，或无有权回应者 | 拒绝申请，不能反复询问绕过限制。 |

<a id="consumption"></a>
## C. 消费与验证材料

### 不同业务模块怎样记录单次消费

单次许可的消费记录必须能找回原业务结果。可纳入业务事务时一起提交；不能一起提交时，先持久预留，交接结果不明期间继续占用额度。

| 模块 | 原子绑定或恢复要求 |
| --- | --- |
| 保存执行 | 许可消费、启动准备和恢复工作同事务提交；外部工具调用在事务外。 |
| 记忆变更 | 消费与业务提交绑定。 |
| 单次读取 | 披露前保存原操作、读取修订和结果引用；重试恢复原获准结果。 |
| 原读取结果无法恢复 | 明确报告，不能凭旧许可重读更新后的内容。 |
| 无法把消费纳入业务事务 | 先持久预留；交接不明时保持占用。 |

### 代理、轮换和期限

| 材料维护 | 规则 |
| --- | --- |
| 普通网络透传 | 保留端到端认证和原操作。 |
| 另一节点代理出示 | 有权签发方生成绑定新出示者和接收方的收缩材料；保留原发起关系及同一次保存的业务含义，默认不支持任意代理链。 |
| 节点换证 | 重绑依赖旧证书的材料。 |
| 签发密钥轮换 | 仅允许有限重叠验证期；旧材料仍受原期限与撤销限制。 |
| 信任根更新 | 经受信管理路径进行。 |
| 期限配置 | 许可、证书、会话、离线窗口、时钟偏差、轮换重叠期均由获准配置给出有限值，并校验相互关系；缺少必要期限时不启用对应功能。 |

签名格式、受信密钥映射、证书绑定及配置见[附录 02](02-api-and-message-catalog.md#identity-configuration)。授权对象与消费记录见[附录 01](01-data-model.md#authorization)，管理与组件接口见[附录 02](02-api-and-message-catalog.md#authorization-service)。

<a id="time"></a>
## D. 离线时间与重新核验

本节检查的是开始新受限工作的资格。时钟异常可以使该资格失效，但已经发出的动作仍须在适用权限和预算内核对，不能据此断言动作没有发生。

| 证据或异常 | 处理要求 |
| --- | --- |
| 在线核验 | 记录时间锚点与本进程最晚执行时间；结合单调经过时间、时钟不确定性及可检测异常检查期限。 |
| 时钟回拨、休眠异常或偏差使时间不可信 | 停止新受限工作；重新建立可信时间和授权状态；已发出动作继续受控核对。 |
| 时钟信任前提 | 信任节点操作系统与签发方时钟；宿主受控时无法保证抵抗时间篡改。 |
| 替代实现支持远端许可离线重启续用 | 必须提供可信时间及防回滚证据。 |
| 恢复连接 | 获准快照绑定视图与修订边界，接续连续变更；视图或游标失效则重新取快照。 |
| 同步密钥 | 仅从既有受信更新流程取得，普通同步不能自行建立信任。 |
| 旧备份恢复 | 先隔离、重新核验，再恢复适用工作。 |

完整端云过程见[3.4 端云协同与离线运行](../main/03-coordination/04-edge-cloud-coordination.md)。

## E. 策略管理

```text
管理入口接收策略变更：
  检查主体权限、资源范围、预期修订
  按原操作去重
  提交不明时核对原提交

查询策略：检查披露范围，不泄露隐藏资源
```

能力说明、网页、模型输出和 Skill 文本不能直接修改策略。

<a id="credential-storage"></a>
## F. 凭证保存与轮换

| 环节 | 参考实现与恢复要求 |
| --- | --- |
| 凭证保存 | 使用节点的 SQLite 加密存储凭证。 |
| 主密钥供应 | 从独立受限位置取得，不进入凭证库、普通任务配置或日志。 |
| 替代供应方式 | 操作系统凭证设施、人工解锁或外部密钥管理；实现声明支持范围。 |
| 轮换过程 | 记录版本，逐条重新加密，支持断点恢复。 |
| 清理旧密钥 | 数据迁移及允许的备份保留处置完成后，再清理不再需要的密钥。 |
| 第三方令牌续期结果不明 | 按提供方契约核对。 |

加密方案保护数据库单独泄漏等情况。主密钥与密文同时泄漏，或宿主执行进程被控制时，无法提供同样保障；加密也不自动阻止合法旧记录回滚。

算法、密钥供应、内存使用及轮换配置见[附录 02](02-api-and-message-catalog.md#credential-configuration)。

<a id="verification"></a>
## G. 验证矩阵

验证观察实际允许／拒绝、原操作恢复和已发生效果。审计日志提供线索，不能单独证明权限已经落实。

| 验证对象 | 注入或检查 | 必须取得的证据 |
| --- | --- | --- |
| 可信身份 | 伪造代理主体、错误 Origin、失效会话、节点禁用、恢复连接。 | 实际拒绝；不退回较弱认证。 |
| 范围与材料 | 错误签发者、算法、接收方、证书绑定、未知限制、扩大委派、上级撤销。 | 错误材料与扩大范围被拒绝；派生材料不能隐藏上级撤销。 |
| 一次许可 | 双执行者、重复提交、跨端重放、交付未知、签发冲突、提交中断。 | 次数不增加；冲突材料不交付；中断可核对。 |
| 批准与任务控制 | 迟到／重复批准、取消与签发交错。 | 分别记录事实；授权成功不解除任务控制。 |
| 撤销及在途效果 | 记录、接收、应用；通知丢失、游标过期、已发生或未知写入。 | 各阶段可区分，传播可恢复，真实效果保留。 |
| 离线与时间 | 窗口到期、时钟异常、离线重启、旧备份恢复。 | 遵守有限保证；分别验证本地权威和远端许可。 |
| 数据与凭证 | 用途限制、纠正／删除、目标错绑、密文替换、主密钥缺失、轮换中断、秘密出口。 | 数据处理被触发，凭证与秘密出口受到实际约束。 |
| 替换与隔离 | 身份、判定、授权存储及凭证供应替换；受信／不受信扩展。 | 复用共同契约；分别声明环境与隔离证据。 |

当前尚无认证、密码互操作、离线时钟或安全实验结果。本页列出应取得的证据，不表示已经完成验证。
