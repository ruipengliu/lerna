## A. 删除标记、同步资格与备份恢复

若某个副本在删除期间离线，它可能仍保存偏好 P@1。重连时，系统需要认出这是已删除的旧内容，避免再次接纳。因此，清理正文后仍保留必要的**删除标记（墓碑）**和**同步水位**：前者记录哪个修订已删除，后者记录副本已经应用到哪里。这些元数据也受访问与保留规则约束。

清理墓碑前，需要确认相关受控副本已应用删除。对于仍未应用删除的旧副本，须先持久关闭其**同步世代**，也就是结束那一轮同步资格，并要求它重返时重新构建副本。满足这些条件后才可清理，不能只按时间删除。

副本用**游标**记录接下来从哪个位置读取变更。游标失效后，副本须从权威端提供的当前快照重建相应视图，清除旧视图残留。本地尚未提交的修改意图单独隔离，不能混入快照。旧备份恢复也先隔离，核验最新删除水位和同步资格后再开放使用；无法取得可信的新状态时继续隔离。完整同步过程见[3.4 端云协同与离线运行](../main/03-coordination/04-edge-cloud-coordination.md#6-重连后任务事实和记忆怎样收敛)。

## B. 接口职责与默认存储

| 边界 | 调用方需要依赖的行为 |
| --- | --- |
| Memory | Query/Get 有界读取；Put/Correct/Delete 受控修改；LookupOperation 核对原操作。指定修订须精确返回或明确不可用，旧回执也按当前权限与删除状态过滤。 |
| ContextAssembler | Assemble 按任务事实、用途和预算组装，返回来源及裁剪、冲突、缺失信息；Validate 复核快照。二者不推进任务或隐式写记忆。 |
| MemoryStore | 本地原子更新记录、回执和变更，提供有界读取及快照、变更恢复；内部 Adapter 不能成为扩展绕过授权的入口。 |
| MemorySync | 管理获准同步视图和应用进度；正式修改仍走 Memory 的变更契约。引用被同步不表示正文也获准同步。 |

查询结果还要说明本次获准范围是否查完、是否存在可见但不可用的来源，以及新鲜度是否满足用途。例如，“完整范围内零命中”允许判断此次查询没有找到匹配内容；“只查到一部分”仍留下缺口。对无权主体不能暴露记录究竟存在、被删除还是不可见。

默认 SQLite 保存记录、允许保留的修订、来源依赖、操作回执和变更水位。小内容可直接存储；大内容先在受控内容存储暂存并确认可读，再发布引用，未引用内容按策略清理，悬空引用显式报缺失。派生索引可以异步重建，但命中后仍由 Memory 复核当前可见性。
