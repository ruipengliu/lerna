# 多 Agent 协作：控制传播与验证细则

<a id="control"></a>
## A. 控制来源与逐目标可靠交接

父端在本地事务中保存根控制来源、控制修订及传播工作。向每个子任务发送控制时，分别分配并保存一项目标明确的子操作。例如，把同一个暂停来源传给两个子任务，需要两项不同的子操作：它们引用同一来源，但各自保持稳定身份和固定目标，重复交付时沿用原操作。

子端校验委派链和权限，在自己的事务中去重、保存来源并继续传播。每层分别报告待送达、已接纳和实际落实；只有相关后代均停稳或完成处置、关键效果不再未知，才可报告全树已落实。

<a id="validation"></a>
## B. 协作验证矩阵

| 验证入口 | 需要观察到的行为 |
| --- | --- |
| 正常串行与并行委派 | 子目标、必需性和依赖明确；各任务独立推进，父按来源汇总，子完成不直接决定父终态。 |
| 提交与关联恢复 | 父提交不明、子已接纳但回执丢失、双方重启和重复交付都恢复原委派，不生成重复子任务。 |
| 权限与数据范围 | 输入、处理位置、结果披露及后续动作分别校验；子不能使用更宽权限绕过父约束。 |
| 预算与期限 | 重复接纳不重复授额，父子并行不增加总量；未知消耗和仍运行的并发槽位不提前释放。 |
| 控制传播 | 覆盖 SELF／SUBTREE、子独立暂停、乱序解除、未知旧委派和失联后取消；逐层区分接纳与落实。 |
| 结果与收尾 | 覆盖冲突、部分结果、失败依赖、迟到完成、处置预算不足及不可停止工作；不以超时伪造终态。 |
| 内部与外部 Agent | 同一协作要求按实际能力验证；外部对端的幂等、查询、取消及证据缺口明确记录。 |
| 实际效果 | 在可比较任务、模型、输入和预算下记录质量、耗时与成本；与单 Agent 对照，未实测不宣称收益。 |
