## A. 清单、资产与依赖

参考清单 `harness-extension.json` 描述来源与摘要、入口、提供和依赖的接口、权限请求、处理位置、运行限制及状态恢复兼容范围。Skill 可由导入器生成伴随管理记录，无需修改原 `SKILL.md`。清单属于 Harness 的包管理约定，权限请求仍须由授权模块判定。

同名同版本却内容不同，应拒绝覆盖；多个实现提供同一能力时显式选择，不按安装顺序抢占。必需依赖缺失、循环或冲突时不能激活；可选依赖缺失则撤去相应贡献。需要并存旧版本时使用固定引用和独立运行上下文。静态检查可以不启动代码，行为验证只在获准测试环境使用受控数据与能力。

多个来源存在同名 Skill 时显式消歧，内容冲突不能通过拼接正文解决，须明确作用域与优先关系。未知可选元数据可以保留，但不自动取得执行含义。

## B. 传输、编码与外部协议

同一个保存契约可能在进程内直接调用，也可能穿过网络。调用方式负责传递契约，不能改变 S 的身份、授权或成功标准。

| 原生调用位置 | 既定绑定与编码 |
| --- | --- |
| 同一进程 | Go 领域 Interface；通过同一用例执行准入与行为检查。 |
| 同一部署侧、不同进程 | gRPC，提供具名方法及适用的双向流。 |
| 端侧与云侧 | WebSocket 全双工通道，以 Protobuf 二进制消息及信封交付；开发期同机模拟也验证该绑定。 |

固定结构以 `.proto` 为唯一结构来源，覆盖方法、公共错误、信封与流消息。动态工具参数、Skill 和 UI 扩展载荷使用已登记的 JSON Schema，绑定类型、版本和摘要；受校验的 UTF-8 JSON 字节装入固定消息。调试 JSON 是阅读视图，内部数据库或框架对象不能直接变成公开协议。

原生契约按主版本和明确能力集协商。破坏行为兼容的变化升级主版本，新增可选行为按能力启用；缺少必需语义时拒绝。能解析字段、协议版本相同、拥有操作权限是三件事。未知必需 UI 类型明确报错，收到类型声明不自动下载 Renderer 或解析任意远程 Schema。

同一全双工连接中的控制、结果和必要输入持久交接；明确标为临时的进度可以合并或丢弃，重连取快照。各流有自己的顺序与缺口，队列、并发和分块有界，满载时返回背压并为控制消息保留预算；大产物用受限分块或获准引用。逻辑优先级不能消除已经排队的传输字节造成的阻塞。游标恢复和旧连接失效在[3.4 端云协同与离线运行](../main/03-coordination/04-edge-cloud-coordination.md)展开。

外部协议则使用自己的标准绑定。下表是已确认的项目适配目标，实际支持按版本、方向、绑定和可选能力分别取得证据。

| 外部入口 | 项目中的适配范围 | 不可据此推导的保证 |
| --- | --- | --- |
| MCP | 目标 `2026-07-28`；stdio、Streamable HTTP；客户端导入外部工具／资源，服务端暴露显式选择的能力／资源。 | 双角色不等于连接内任意双向 RPC；首期关闭 Tasks，资源读取不自动变为长期记忆。 |
| A2A | 目标协议 `1.0`，HTTP+JSON；客户端委派，服务端经 Harness 入口受理；映射 Message、Task、查询及取消。 | 幂等、流式和推送按对端能力启用；取消可能失败，远端终态不能重开，contextId 不代表共享内部上下文。 |
| Agent Skills | 兼容已锁定的内容格式快照；导入名称、描述、正文与关联资产。 | 格式不提供完整安装事务、隔离或执行授权；A2A AgentSkill 与此内容包分别处理。 |

Adapter 的输入、输出、资源暴露和订阅都按实际主体与处理位置授权。外部端点若无法满足所需权限粒度或数据限制，应拒绝不相容操作；内核存储、任意状态写入和原始凭证不因接入协议而公开。

协议目标、规范快照、SDK 版本和局部补丁分别锁定。SDK 的默认行为未必满足本项目的契约，Adapter 仍须补齐版本校验、取消映射和错误解析，并逐项验证。

例如，MCP 请求取消可以结束连接等待和临时处理，但已持久接纳的业务操作仍沿自己的生命周期继续。业务取消须另经相应契约发起，并核对实际停止情况。HTTP 模式、握手限制、A2A 媒体类型与错误处理等精确配置集中在[附录 02](02-api-and-message-catalog.md#compatibility)；锁定 SDK 本身不表示这些适配要求已经实现。

## C. 受限 Wasm 与中断恢复

受限 Wasm 默认不继承宿主目录、环境、网络或子进程能力；内存页、资产体积、并发、时间、输入输出及宿主回调均有有限配置。数据和子调用经受控宿主接口检查，真实子动作另记操作与预算，Brain 实现不能借此绕过行动准入。

实例化的 start 段也可能执行代码，加载和编译须另设限制。每次调用使用新实例，取消后不复用；调用期限与资源检查同时覆盖宿主入口。guest 内存限制不等于宿主 RSS 限制，取消不能强杀任意 Go 回调；需要更强保证时使用已验证的独立后端，限制不足则拒绝运行。

参考方案不保存 Wasm 执行栈作透明续跑。中断后先核对已登记子动作；纯计算仅在声明允许且预算足够时重算，有副作用的脚本不能盲目从头再跑。普通 Skill 内容可导入，与其脚本能否执行分别报告。运行器、SDK 和资产的完整锁定及配置见[接口附录的兼容配置](02-api-and-message-catalog.md#compatibility)，不新增开发期必需的云服务或容器集群。

默认不依赖 guest 的模拟时间或确定性随机源作授权、到期或密钥判断，这些判断由宿主负责。需要真实时间或随机数时，使用明确登记的受控入口。

## D. 接入与升级验证矩阵

| 验证入口 | 需要取得的证据 |
| --- | --- |
| 原生调用等价 | 同一用例通过 Go、gRPC、WebSocket 得到一致业务事实与错误；分别注入传输特有故障。 |
| 消息与兼容 | 字段演进、动态 Schema、未知必需能力、重复交付、回执过期、断流和背压均按契约处理。 |
| 外部互操作 | MCP／A2A 的两个方向分别与独立对端验证；覆盖严格版本、媒体类型、工具失败、无幂等、取消失败及可选能力缺失。 |
| Skill 与运行器 | 内容加载和脚本执行分离；资产越界、依赖冲突、超额、start 段、无限循环及宿主回调限制有实际拒绝与恢复记录。 |
| 激活与升级 | 激活前后崩溃、未知提交、投影延迟、部分节点应用、旧版本工作、隔离后迟到结果与迁移失败不丢事实。 |
| 授权与数据 | 管理、发现、执行、推送及受限内容出口分别校验；安装、自检、升级和回滚不自行增权。 |
| 接入后的效果 | 契约兼容与实际任务效果分别评测；千级 API 不靠别名或重复版本充数，沿用首次正确率至少 90%、有限重试成功率至少 95% 的目标与既定计分配置。 |
