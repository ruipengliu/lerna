<a id="catalog-boundary"></a>
## 1. 先分清查的是哪种接口

提交用户目标与写入任务状态属于不同边界。应用调用原生服务，由所属模块检查并处理；实现模块时再使用其消费的组件接口；Store 接口承接所属模块的持久化责任。下表用于确定自己应查哪一类入口。

| 目录类型 | 用途 | 边界 |
| --- | --- | --- |
| 原生服务方法 | 应用、节点或获准管理端通过正式用例提交请求。 | 进程内、gRPC、WebSocket 映射相同业务语义；每次调用仍检查当前权限。 |
| 可替换组件接口 | 消费模块调用 Brain、Model、Driver、Store 等实现。 | 按组件声明组装；可导入的 Go 接口不自动成为远程 RPC，也不向普通插件开放存储写入。 |
| 消息与事件 | 表达请求、响应、事实、呈现、交付和流控。 | 消息名不必对应独立服务方法；例如 `SurfacePatch` 经既有通道发送，`DescribeUI` 可通过协商交换。 |

原生契约仍分为**任务协作、能力调用、记忆访问、端云连接**四个基础领域，另有 UI 交互与呈现契约组。Authorization、Extension、Observation、Evaluation、Evolution 的管理入口归任务协作领域；11 个服务不表示 11 类协议或 11 个部署进程。

方法表中的“调用方”描述角色，实际权限还取决于可信主体、资源、用途、位置和当前状态。未列为公共方法的内部动作，不因出现在时序说明中就获得远程入口。依据见[协议分工](../../archive/architecture-v1/03-contracts-and-protocols.md)、[原生目录](../../archive/architecture-v1/03-contract-message-catalog.md)。

<a id="call-rules"></a>
## 2. 所有入口共用的调用规则

### 2.1 身份、版本与重试

方法表省略重复的认证上下文、可信 `namespace`、适用授权和大小限制。每个请求仍须携带或从受信绑定取得这些信息；查询和重放也不例外。

| 规则 | 调用方与接收方必须保持什么 |
| --- | --- |
| 可信作用域 | namespace 由认证身份绑定；受信代理保留原发起关系。普通载荷不能自报另一用户或覆盖认证上下文。 |
| 变更身份 | 一次固定逻辑意图使用一个 `operation_id`；种类、目标、业务期限和语义输入不可在重试时改变。同一 ID 对应不同语义返回身份冲突。 |
| 查询关联 | 查询用新的 `message_id`，在载荷中引用目标任务／操作；不为查询伪造新的变更身份。核对可更新已知事实，但不能暗中重新执行目标动作。 |
| 消息身份 | 原消息原样补投保持 `message_id`；重新构造请求、新查询、新回复各用新消息身份。同一业务操作继续沿用原 operation_id。 |
| 原操作优先核对 | 先检查当前认证及结果披露权限，再查已知操作并核对语义；只有真正的新操作才应用首次接纳、当前版本及等待项条件。 |
| 版本前提 | 按具体方法检查任务、记录、策略或控制版本；不额外规定所有方法都带同一种 `expected_version`。冲突后重新读取，改变意图须用新操作。 |
| 转交与派生 | UI、网关和 Adapter 转交同一意图保持操作身份、固定路由及受信发起关联；新委派、新控制子操作或后续执行才创建自己的操作并关联来源。 |
| 期限与资格 | 业务期限、RPC 等待超时、接纳窗口、授权期限及 Worker 租约各自校验；其中一项失效不自动证明动作未发生。 |
| 结果披露 | 旧回执也受当前权限、删除和用途限制；可返回获准状态或引用，不能复现已禁止披露的正文。 |

同一 namespace 中的操作身份必须有唯一接纳权威，不能按服务名另建互不相知的同 ID 操作。内部 `change_id` 只用于所属 Store 的原子提交核对，不进入公共业务信封。作用域、独立版本及保留规则见[附录 01](01-data-model.md#identity-version)。

<a id="results-errors"></a>
### 2.2 返回值分别证明什么

下表是不同事实维度，不是一条要求所有调用逐项经过的统一状态机。

| 返回或报告 | 已知事实 | 后续仍需判断 |
| --- | --- | --- |
| `PERSISTED` | 接收端已持久保存必要消息、去重依据和待处理责任。 | 业务是否获准并接纳。 |
| `ACCEPTED` | 所属模块已完成业务准入及本地持久提交。 | 何时取得资源、是否开始、效果是否满足要求。 |
| 执行阶段 | `NOT_STARTED / IN_PROGRESS / FINISHED / UNKNOWN`。 | 结束与成功、效果确认分别报告。 |
| 执行结果 | `SUCCESS / FAILURE / UNKNOWN`。 | 由证据支持的效果状态及任务交付条件。 |
| 效果核对 | `NOT_APPLICABLE / UNVERIFIED / CONFIRMED / CONTRADICTED`。 | 本操作之外的依赖、读回和整体任务条件。 |
| 控制或管理进展 | 取消／接管／激活等已受理、待送达或实际应用的进展。 | 相关在途动作是否已处置、目标节点是否真正完成应用。 |
| `PresentationStatus` | Renderer 报告已应用某显示版本，或呈现失败／不支持。 | 用户是否正式回应，以及目标业务是否处理成功。 |

领域错误保留稳定 `code`、可安全展示的说明、结果确定性、关联引用及建议恢复动作。建议不是 SDK 自行重试副作用的许可。

| 错误类别 | 含义 | 调用方下一步 |
| --- | --- | --- |
| `INVALID_ARGUMENT` | 输入或字段组合无效。 | 修正请求；若改变原操作语义，形成新意图。 |
| `UNSUPPORTED_VERSION`、`MISSING_CAPABILITY` | 版本或必需能力不满足。 | 选择经声明支持的组合；不降低必需语义。 |
| `UNAUTHENTICATED`、`PERMISSION_DENIED` | 身份未建立或当前权限不足。 | 经受信流程补足身份／权限；不披露隐藏资源。 |
| `VERSION_CONFLICT` | 新变更依据的状态已过期。 | 读取当前版本后重新判断，不能无条件覆盖。 |
| `IDENTITY_CONFLICT` | 同一操作身份被用于不同语义。 | 核对调用意图和身份使用，不覆盖原记录。 |
| `RESOURCE_EXHAUSTED` | 队列、额度或其他有界资源不足。 | 结合接纳确定性、期限和预算退避；保留可靠交付责任。 |
| `OUTCOME_UNKNOWN` | 提交或外部效果不能确定。 | [查询或核对原操作](#delivery-recovery)，不自动新建同一动作。 |
| `CURSOR_EXPIRED`、`RECEIPT_EXPIRED` | 需要的恢复位置或回执已超出保留范围。 | 重取快照并核对可用记录；过期不能转成首次接纳。 |
| `UNAVAILABLE`、`DEADLINE_EXCEEDED` | 服务不可用或本次等待结束。 | 区分明确未接纳与可能已生效；状态码本身不足以决定重做。 |

领域失败还需表达输入失效、覆盖不完整、预算不足、需用户输入、凭证不可用等模块事实；已有语义不统一补造成新的公共错误枚举。gRPC status 表达 RPC 层结果，领域错误通过类型化响应或约定错误详情承载；WebSocket 保留相同领域含义。可能生效的请求因传输中断丢失回包时，按未知结果处理。

<a id="native-services"></a>
## 3. 原生服务方法目录

以下覆盖既定原生目录中的全部方法，每个方法独立一行。先选业务对象对应的服务，再判断本次是在提交新变更、查询原结果还是请求控制；不能因回包丢失就重新走新建入口。公共错误见[上一节](#results-errors)，输入中的“操作身份”均遵循[共同规则](#call-rules)。查询只返回当前权限内可见的结果，不提供任意读库能力。

<a id="task-service"></a>
### 3.1 TaskService：提交与控制任务

调用进入任务内核，由当前有资格的任务权威处理。新建目标、给已有任务补充信息、回答一个等待项分别使用不同方法。

| 方法 | 调用方 | 输入要点 | 返回什么 | 条件与恢复 |
| --- | --- | --- | --- | --- |
| `Submit` | 应用、获准委派方 | 操作身份、目标、输入引用、约束；委派附父任务和授权关系。 | 任务引用、持久接纳结果。 | 重投返回原任务；子任务唯一接纳，父子不共用一次事务。 |
| `Get` | 获准应用、父任务或管理端 | 任务引用。 | 可见快照、状态版本、结果引用。 | 读取当前任务权威；无法取得时明确等待／不可用。 |
| `ProvideInput` | 用户输入处理端或获准应用 | 操作身份、任务引用、`interaction_id`、正式输入。 | 等待项消费结果及任务进展。 | 原子检查当前等待项；新输入不得回答失效等待点，原重试查原结果。 |
| `SubmitUpdate` | 获准用户／应用 | 操作身份、任务引用、追加或修改目标的意图、预期任务版本、内容及来源。 | 接纳结果、新任务版本。 | 不增权、不加预算、不重开终态；旧提案失效，既有动作事实仍保留。 |
| `AdjustLimits` | 有调整权限的控制方 | 操作身份、任务引用、预期任务版本、预算／期限变更。 | 原管理回执与更新结果。 | 不清除已用或未结算额度，不解除暂停／取消，不扩张远端离线配额。 |
| `RequestPause` | 有控制权限的用户／管理端 | 操作身份、任务引用、预期任务版本、原因、`SELF / SUBTREE`。 | 暂停接纳结果及可查询进展。 | 默认 SUBTREE；保存来源和传播工作，在途与子任务停稳另报。 |
| `RequestResume` | 有控制权限的用户／管理端 | 新操作身份、任务引用、预期任务版本、`target_pause_operation_ref`。 | 指定来源的解除结果。 | 沿用原暂停范围；其他暂停、等待、接管和取消继续有效。 |
| `RequestCancel` | 有取消权限的请求方 | 本次操作身份、任务引用、原因。 | 取消请求接纳结果。 | 实际停止与已完成分别报告，保留在途和未知效果。 |
| `LookupOperation` | 原请求方或获准恢复方 | 原任务操作的身份及作用域。 | 接纳情况、关联任务和可见结果确定性。 | 不提供任意 RunStore 查询；一次查不到不能证明旧请求不会再提交。 |

委派复用 `Submit` 与任务查询／控制，不新增一个绕过内核的远程执行入口。来源：[原生目录](../../archive/architecture-v1/03-contract-message-catalog.md)、[决策与协作](../../archive/architecture-v1/06-decision-admission-and-collaboration.md)、[暂停与恢复](../../archive/architecture-v1/12-data-path-and-protocol-semantics.md#3-补齐任务暂停恢复和子任务控制)。

<a id="capability-service"></a>
### 3.2 CapabilityService：发现、执行与资源控制

`GetInvocation` 查询执行记录，`Reconcile` 触发按既有关联核对事实；两者都不能被实现为再做一次原动作。

| 方法 | 调用方 | 输入要点 | 返回什么 | 条件与恢复 |
| --- | --- | --- | --- | --- |
| `List` | 大脑的获准检索端、应用 | 能力范围、分页条件。 | 可见摘要、目录修订、下一页位置。 | 游标绑定授权视图和修订，不泄露不可发现项。 |
| `Describe` | 能力选择与准入模块 | 能力引用、准确版本。 | 完整声明、参数 Schema、位置和恢复能力。 | 版本不可用时明确报告，不静默返回另一版。 |
| `Search` | 大脑的获准检索端 | 目标、资源类型、必要能力、用途、允许位置、候选／时间预算。 | 获准候选、目录修订、覆盖情况。 | 零匹配、不可达、索引滞后及预算耗尽分别表达。 |
| `Invoke` | 内核或获准独立应用 | 执行操作身份、固定能力版本、参数、授权引用、可选任务引用。 | 接纳句柄或执行报告。 | 执行端再准入并持久登记；接纳不证明效果，任务引用可缺省。 |
| `GetInvocation` | 内核、原调用方或恢复方 | 原执行操作引用。 | 已保存的执行阶段、结果、效果及证据引用。 | 快照不冒充最新外部状态；操作名保留，不另建 invocation_id。 |
| `Reconcile` | 获准执行恢复方 | 原执行操作、可用核对证据。 | 核对后的事实或明确限制。 | 经固定 Driver／外部关联核对；不能核对则保留未知。 |
| `RequestCancel` | 有取消权限的调用方 | 本次取消操作身份、目标执行操作、原因。 | 取消接纳及后续进展。 | 取消和目标操作身份独立；实际停止不由受理回执推断。 |
| `RequestTakeover` | 有接管权限的用户／应用 | 本次操作身份、目标执行操作、原因、预期资源控制版本。 | 接管受理及落实进展。 | 解析到明确资源范围；转交同一接管意图保持身份。 |
| `GetResourceControl` | 获准用户、内核或执行方 | 类型化资源引用。 | 控制意图、落实进展、局部版本。 | 查询不取得控制权，也不证明所有外部写入已停止。 |
| `RequestResourceControl` | 有资源控制权限的用户／应用 | 操作身份、资源范围、`TAKEOVER / RESUME`、预期控制版本、授权引用。 | 控制接纳结果和进展。 | API／GUI 共用适用范围；在途处置后才报落实，恢复不解除任务控制。 |

来源：[执行接口与资源控制](../../archive/architecture-v1/07-execution-contracts-and-validation.md)。Driver 的核对、取消和幂等能力按准确声明判断，方法存在不保证每个外部目标具备同样能力。

<a id="memory-service"></a>
### 3.3 MemoryService：读取与修改记忆

读取返回获准内容与修订，修改形成新的业务意图；修改结果不明时查询原操作。同步副本使用下一节的接口，不能借同步直接覆盖正式记忆。

| 方法 | 调用方 | 输入要点 | 返回什么 | 条件与恢复 |
| --- | --- | --- | --- | --- |
| `Query` | 上下文组装或获准应用 | 范围、用途、查询、接收位置、允许结果形式、新鲜度及分页限制。 | 获准投影、来源修订、覆盖与新鲜度。 | 未查询范围不记为零命中；计数、片段和覆盖信息也按权限过滤。 |
| `Get` | 获准读取方 | 记录引用、所需修订、用途与位置条件。 | 指定内容投影或不可用结果。 | 指定旧修订不能返回最新版冒充；引用不授予读取权限。 |
| `Put` | 有保存权限的应用／提取流程 | 操作身份、集合、新记录内容或引用及适用前提。 | 创建结果、记录和修订引用。 | 默认创建；读取或提取许可不自动包含长期保存许可。 |
| `Correct` | 有纠正权限的用户／流程 | 操作身份、记录、预期修订、精确变更意图。 | 新修订及原操作回执。 | 冲突后重新判断，不自动覆盖；部分字段投影不作全量记录提交。 |
| `Delete` | 有删除权限的用户／流程 | 操作身份、记录引用、预期修订。 | 权威提交、本地使用、副本及派生／归档进展。 | 记录级删除不暗含无限批量范围；离线副本未联系不能记为已清理。 |
| `LookupOperation` | 原请求方或获准恢复方 | 原记忆操作引用。 | 历史接纳／提交与当前可见结果。 | 内容后来删除不等于从未提交；回执不返回已禁止披露的正文。 |

<a id="memory-sync-service"></a>
### 3.4 MemorySyncService：获准副本的恢复

| 方法 | 调用方 | 输入要点 | 返回什么 | 条件与恢复 |
| --- | --- | --- | --- | --- |
| `OpenView` | 获准同步接收方 | 集合、记录／字段范围、用途和位置。 | 绑定范围、策略及世代的同步视图。 | 仅对允许复制的数据开放；就地查询不默认建立云端副本。 |
| `ReadSnapshot` | 视图接收方 | 视图引用、分页位置。 | 一致边界上的快照页及接续位置。 | 页间不混合不同状态；过期或范围变化时重建视图。 |
| `ReadChanges` | 视图接收方 | 有效视图与变更游标。 | 该视图的有界增量和下一位置。 | 本地应用和游标原子推进；不按业务记录编号缺口猜测丢消息。 |
| `GetStatus` | 获准同步管理／接收方 | 视图及相关范围。 | 可见同步进展、缺口或失效情况。 | 消息持久化位置不替代副本应用位置，未联系副本单列。 |

同步修改仍走 MemoryService。离线非权威修改保留为待提交意图，不能混入权威快照；副本应用位置可经既有通道报告，不在此补造新 RPC。来源：[记忆数据与生命周期](../../archive/architecture-v1/05-memory-data-and-lifecycle.md)、[端云检索与驻留](../../archive/architecture-v1/05-edge-cloud-memory.md)。

<a id="interaction-service"></a>
### 3.5 UserInteractionService：界面与正式用户动作

| 方法 | 调用方 | 输入要点 | 返回什么 | 条件与恢复 |
| --- | --- | --- | --- | --- |
| `GetSurface` | 获准 UI Adapter／Renderer | `surface_ref`。 | 权威呈现快照、revision、有效等待项引用。 | 可无 task_ref；本地草稿不覆盖服务端权威快照。 |
| `GetActionResult` | 原提交端或获准恢复方 | 原用户操作引用。 | 已保存的转交进展及可见业务结果。 | 必要时核对固定目标；UI 投影滞后不代表业务未处理。 |
| `SubmitAction` | 用户输入端或获准应用 | 操作身份、Surface／组件、登记事件、输入、适用预期版本、可选等待项。 | 转交接纳、校验反馈及后续业务结果。 | 持久保存 ActionRoute；原重试沿原映射查询，不因界面关闭重新解释。 |
| `EmitUIEvent` | 已协商的 UI 事件发送端 | Surface／组件、登记事件类型、临时数据。 | 按事件契约处理的反馈。 | 只用于声明不产生业务变更的事件，通常没有 operation_id；不能承载正式确认。 |

SubmitAction 转交 `ProvideInput`、`SubmitUpdate` 或授权／应用处理器时保留同一操作身份。业务等待项只在所属模块消费；已登记的 UI 自有偏好操作才可由 SurfaceStore 接纳。具体呈现消息见[第 7 节](#ui-messages)，来源：[UI 契约](../../archive/architecture-v1/03-ui-interaction-contracts.md)、[独立 UI 恢复](../../archive/architecture-v1/12-data-path-and-protocol-semantics.md#4-补齐独立-ui-的状态权威与存储)。

<a id="authorization-service"></a>
### 3.6 AuthorizationService：策略与许可管理

| 方法 | 调用方 | 输入要点 | 返回什么 | 条件与恢复 |
| --- | --- | --- | --- | --- |
| `IssueGrant` | 有签发权限的主体 | 操作身份、明确范围、预期策略修订；交互批准附有效等待项。 | 授权引用及可披露验证材料。 | 原子记录批准、授权和必要预留；提交确认后才交付材料。 |
| `DeriveGrant` | 有派生权限的主体 | 操作身份、子范围、父授权及预期修订、适用策略前提。 | 收缩后的授权引用和材料。 | 证明子范围受全部祖先约束；无法证明则拒绝。 |
| `RevokeGrant` | 有撤销权限的主体 | 操作身份、目标授权、预期修订。 | 权威撤销及传播进展。 | 接收方应用另报，撤销不抹去已发生效果。 |
| `GetGrant` | 获准查询方 | 授权引用。 | 可见状态、修订及撤销进展。 | 查询权限不等于可披露全部材料或可使用授权。 |
| `UpdatePolicy` | 对该范围有管理权的主体 | 操作身份、策略范围、预期修订、变更。 | 更新结果及原回执。 | 子范围不能放宽上级强制限制。 |
| `GetPolicy` | 获准查询方 | 策略引用。 | 可见策略及版本。 | 响应不泄露隐藏资源或不可见范围。 |
| `LookupOperation` | 原管理方或获准恢复方 | 原授权管理操作引用。 | 原接纳／提交及可见结果。 | 先检查当前查询权限；操作 ID 不充当签名材料下载凭据。 |
| `ReadSnapshot` | 获准策略／授权接收方 | 受控视图和分页位置。 | 一致快照边界、可见记录及接续位置。 | 视图受范围限制，不是远程任意读库。 |
| `ReadChanges` | 获准策略／授权接收方 | 受控视图和连续变更游标。 | 策略、授权、撤销等有界变更。 | 失效时重取快照；应用与游标原子保存，普通同步不创建信任根。 |

连接认证、授权判定、签发与实际消费是不同调用。单次许可在实际执行／业务模块按原操作消费，不能把 `IssueGrant` 成功解释为动作已执行。来源：[授权生命周期与接口](../../archive/architecture-v1/08-authorization-lifecycle-and-interfaces.md)。

<a id="extension-service"></a>
### 3.7 ExtensionService：扩展的准备、验证与激活

| 方法 | 调用方 | 输入要点 | 返回什么 | 条件与恢复 |
| --- | --- | --- | --- | --- |
| `Prepare` | 获准扩展管理端 | 操作身份、管理范围、预期版本、来源／资产。 | 准备进展和精确锁定引用。 | 导入不执行安装钩子；全部必需资产就绪才提交可验证记录。 |
| `Validate` | 获准扩展管理端 | 操作身份、范围及版本前提、精确锁定结果、运行配置、测试集。 | 该组合的验证记录。 | 行为测试只在获准环境执行；通过不等于激活。 |
| `Activate` | 有激活权限的主体 | 操作身份、精确锁定结果、目标节点范围、预期管理版本。 | 本地激活提交及各节点应用进展。 | 当前信任与权限复核；投影应用后才暴露绑定，旧工作保持原版本。 |
| `Disable` | 有停用权限的主体 | 操作身份、版本／范围、预期管理版本、排空或风险隔离意图。 | 停止新路由及在途处置进展。 | 请求停止不等于实际停止；保留核对通道和未知效果。 |
| `Remove` | 有删除权限的主体 | 操作身份、版本／锁定引用、管理范围、预期版本。 | 资产删除结果或受阻原因。 | 先处置在途及恢复引用；不删除所属业务事实、消费或撤销水位。 |
| `Get` | 获准管理／查询方 | 扩展引用与节点范围。 | 可见版本、验证、激活与应用进展。 | 管理端状态不冒充离线节点已切换。 |
| `LookupOperation` | 原管理方或获准恢复方 | 原扩展管理操作引用。 | 接纳、提交及可见原回执。 | 激活未知先核对；回滚通过获准的 Activate 选择旧锁定结果。 |

来源：[扩展契约与激活恢复](../../archive/architecture-v1/09-extension-contracts-and-activation.md)。精确资产、清单和锁定字段见[附录 01](01-data-model.md#extension)。

<a id="observation-service"></a>
### 3.8 ObservationService：诊断记录与覆盖

| 方法 | 调用方 | 输入要点 | 返回什么 | 条件与恢复 |
| --- | --- | --- | --- | --- |
| `Ingest` | 获准节点／模块 | 来源绑定、信号批次、适用来源位置及项次。 | 接纳进展与缺口反馈。 | 持久来源去重；临时信号可按声明采样，不凭载荷自报来源接纳审计事实。 |
| `Query` | 获准诊断方 | 受控筛选、分页、来源范围。 | 可见诊断投影。 | 游标绑定授权视图和投影修订；不能修改业务权威。 |
| `GetCoverage` | 获准诊断方 | 来源及查询范围。 | 接纳位置、投影位置、采样／丢失与不可恢复缺口。 | 没有记录不证明没有动作；正式评测证据不能因诊断采样被丢弃。 |

Ingest 是事实接收，按来源记录去重，不统一套用新业务变更的操作身份要求。

<a id="evaluation-service"></a>
### 3.9 EvaluationService：隔离评测与比较

评测服务管理计划、样本运行和比较结果。运行结束只说明流程收尾，是否通过仍读取报告判定；候选启用由下一节的改进服务管理。

| 方法 | 调用方 | 输入要点 | 返回什么 | 条件与恢复 |
| --- | --- | --- | --- | --- |
| `Start` | 获准评测管理端 | 操作身份、不可变计划、版本前提、预算及授权。 | 评测引用与接纳结果。 | 持久交接隔离样本任务；重启查询原任务，不复制真实执行。 |
| `Cancel` | 有取消权限的主体 | 本次操作身份、目标评测、预期版本。 | 取消意图与收尾进展。 | 停止新样本，在途任务及迟到结果按原身份收敛。 |
| `Get` | 获准查询方 | 评测引用。 | 状态、逐例结果、报告及证据完整性。 | 运行结束与 PASS／FAIL／INCOMPLETE 分开，保留全部尝试。 |
| `Compare` | 获准评测／发布方 | 两个运行、相同计划；形成持久比较时附操作身份和版本前提。 | 比较结果或不可比原因。 | 不同评分器、预算或不受控环境变化不得直接比较；不得挑最好尝试。 |
| `LookupOperation` | 原管理方或获准恢复方 | 原评测管理操作引用。 | 原接纳／提交及评测关联。 | 结果未知先查询，不能换身份重跑并覆盖原样本。 |

<a id="evolution-service"></a>
### 3.10 EvolutionService：候选与阶段发布

| 方法 | 调用方 | 输入要点 | 返回什么 | 条件与恢复 |
| --- | --- | --- | --- | --- |
| `Propose` | 获准改进流程／维护者 | 操作身份、精确候选内容与来源、预期版本。 | 候选引用及登记结果。 | 登记候选不授予发布权限。 |
| `Evaluate` | 获准候选管理端 | 操作身份、候选、固定评测计划、版本及授权前提。 | 评测交接和关联。 | 经 Evaluation 运行隔离评测，不另造无限执行循环。 |
| `Promote` | 有相应发布权限的主体 | 操作身份、候选／阶段、预期版本、证据及当前资格。 | 阶段意图和目标节点应用进展。 | 固定任务／工作组分配；代码发布另验维护者对精确资产的确认。 |
| `Halt` | 有停止／回滚权限的主体 | 操作身份、目标阶段、明确停止或回滚意图、预期版本。 | 停止扩大及适用回滚进展。 | 回滚另验当前兼容性和授权，不回放旧业务数据库。 |
| `Get` | 获准查询方 | 候选或发布范围。 | 资格、阶段意图和节点实际版本。 | 提交阶段不等于全部节点激活，也不证明质量改善。 |
| `LookupOperation` | 原管理方或获准恢复方 | 原候选／发布管理操作引用。 | 接纳／提交、交接及可见原结果。 | 核对原激活与绑定，旧操作不改用新实现。 |

观测、评测和发布来源：[评测接口与发布判定](../../archive/architecture-v1/10-evaluation-contracts-and-release-gates.md)。完整样本、预算和数值门槛归附录 05；本目录不把计划参数重写为协议默认值。

<a id="connection-service"></a>
### 3.11 ConnectionService：协商与双向消息

| 方法 | 调用方 | 输入要点 | 返回什么 | 条件与恢复 |
| --- | --- | --- | --- | --- |
| `Negotiate` | 已建立可信身份的节点／端点 | 主版本、必需／可选能力及版本、消息和队列限制。 | 连接配置或明确不兼容结果。 | 实现支持与本次准用分别声明；配置过期需重新协商。 |
| `Exchange` | 已协商且获准的双方 | 双向订阅、通知、应用回执、流量额度及适用交互消息。 | 独立双向消息流。 | 发送返回不证明持久接收；流断开不取消任务，推送范围须有授权与订阅／委派依据。 |

gRPC 具名 RPC 承载请求响应，Exchange 承载双向交互和推送；不要求把全部 unary RPC 再封入流。WebSocket 双方经统一信封发起同样的操作，具体恢复见[第 6 节](#delivery-recovery)。

<a id="component-interfaces"></a>
## 4. 可替换组件接口

本节供实现组件和组装系统时查阅。已由原生服务表描述的方法族仅列映射；只确定了行为而未固定方法名的接口明确保留该精度。

### 4.1 决策、执行、授权与治理

| 组件／方法 | 消费方 | 输入输出与必须保留的行为 |
| --- | --- | --- |
| `Brain.Decide` | 任务内核 | 输入版本化任务、受控上下文、能力和预算，输出完整提案或领域失败；不直接执行动作、写记忆或改任务终态。 |
| `Model.Generate` | Brain | 输入内容、模态、Schema 和生成限制，返回临时增量、完整结果及可得用量；取消有界，供应商工具调用只作为输出。 |
| `ContextAssembler.Assemble / Validate` | 内核／决策流程 | 组装并复核来源、用途、位置和预算，返回快照、依赖及截断／冲突／缺失信息；不隐式保存长期记忆。 |
| `CapabilityCatalog.List / Search / Describe` | 能力选择与准入模块 | 与能力服务的目录方法保持同一发现、版本及覆盖语义；索引和排序器留在实现内部。 |
| `ExecutionDriver.Start / Inspect / Cancel` | 执行协调器 | Start 接受原操作、固定实现、参数与资格；Inspect 核对原目标关联；Cancel 请求停止。可选能力不足显式报告，Driver 不持有任务终态。 |
| `Memory`、`MemorySync` | 上下文及同步使用方 | 分别实现 MemoryService、MemorySyncService 的相应方法；读取、保存与复制权限各自成立。 |
| `IdentityVerifier.Authenticate` | 受信接入层 | 将连接／会话验证为认证上下文，失败不退回自报主体；不是新增的公共登录 RPC 名称。 |
| `Authorizer.Evaluate` | 各业务准入及数据出口 | 返回允许、拒绝或需输入，以及限制、策略／撤销修订和适用窗口；判定不代替实际消费与业务提交。 |
| `GrantAuthority.Issue / Derive / Revoke / Get` | 授权管理用例 | 实现签发、收缩、撤销与查询；验证范围和修订，原操作恢复不重复签发。 |
| `CredentialBroker.Use` | 受信 Driver／出口 | 按目标、账号、用途和驱动身份提供受限凭证使用；原始密钥不返回 Brain、普通插件或日志。 |
| `UIStateManager.SubmitAction / GetActionResult` | UI 服务 | 固定输入路由、持久转交并查询目标结果；Surface 投影不自行判定业务成功。 |
| `ExtensionManager` | 扩展管理入口 | 实现 Prepare、Validate、Activate、Disable、Remove、Get、LookupOperation；与 ExtensionService 映射同一管理意图。 |
| `ExtensionRuntime.Prepare / Start / Inspect / Stop` | 扩展管理与组装方 | 准备获准运行环境，启动并检查真实状态，请求停止；停止返回不等于在途工作结束。 |
| `Observation`、`Evaluation`、`Evolution` | 对应管理入口 | 实现各自服务中的同名方法，分别保存诊断、评测和发布事实，不互相改写权威。 |
| `Evaluator.Score` | 隔离评测模块 | 输入固定评分规则、获准真值及指定证据，输出判读、依据和评分器版本；被测 Agent 无权取得真值或任意改分。 |
| Scheduler 策略、Worker 机制 | 内核 | 选择合格工作、唤醒与处理；不能绕过准入或拥有第二份任务终态。本地方法见[内核接口规格](../design/01-runtime-kernel-contracts.md#ports)。 |
| Renderer、信息获取及主密钥供应接口 | 所属宿主模块 | 按已声明能力处理呈现、来源获取或密钥提供；具体 SDK 方法未定，不能据此补造公共 RPC。 |

来源分别为[运行内核](../../archive/architecture-v1/02-runtime-and-state.md)、[决策](../../archive/architecture-v1/06-decision-admission-and-collaboration.md)、[记忆](../../archive/architecture-v1/05-memory-data-and-lifecycle.md)、[执行](../../archive/architecture-v1/07-execution-contracts-and-validation.md)、[授权](../../archive/architecture-v1/08-authorization-lifecycle-and-interfaces.md)、[扩展](../../archive/architecture-v1/09-extension-contracts-and-activation.md)、[评测](../../archive/architecture-v1/10-evaluation-contracts-and-release-gates.md)及[UI 状态](../../archive/architecture-v1/12-data-path-and-protocol-semantics.md)。

<a id="42-store-方法不能被统一改名"></a>
### 4.2 各 Store 的提交与恢复接口

选择 Store 实现时，应先核对所属原子组、版本与执行资格、可核对提交、恢复责任和保留边界。各 Store 的方法及核对键仍有差异，不能只提供同名的读取和写入函数就宣布满足持久化契约。

| 存储接口 | 已定方法或行为 | 提交与恢复边界 |
| --- | --- | --- |
| `RunStore` | `Load / Commit / LookupCommit / ListRecoverable` | 单项任务状态、准入、预算、工作、Outbox 和回执；核对任务、原 change_id、Owner／Worker 资格。 |
| `WorkStore` | `ListNamespaces / ScanDue / Claim / Renew`；完成更新经 `RunStore.Commit`。 | 与 RunStore 属于同一持久化单元；用户枚举限宿主授权范围，扫描只得候选，处理前受约束领取。签名与恢复领取模式见[本地接口](../design/01-runtime-kernel-contracts.md#ports)。 |
| `ExecutionStore` | `Load / Commit / LookupCommit / ListRecoverable` | 操作／资源事实、控制版本、消费与准备、外部关联、工作及报告 Outbox；不包住外部动作。 |
| `MemoryStore` | `Read / Scan / Commit / LookupOperation / ReadChanges / ReadSnapshot` | 原子更新记忆、操作回执及同步变更；使用 LookupOperation 按原记忆操作核对提交结果。 |
| `SurfaceStore` | `Load / Commit / LookupCommit / ReadChanges / ListRecoverable` | 界面版本、ActionRoute、回执及转交／发布责任；等待项消费属于目标业务模块。 |
| `AuthorizationStore` | `Load / Commit / LookupCommit / ReadSnapshot / ReadChanges` | 本权威范围的策略、授权、预留／撤销、管理回执和通知；实际业务消费在对应处理端。 |
| `ExtensionStore` | `Load / Commit / LookupCommit / ListRecoverable` | 本节点管理范围的资产、验证、激活修订、绑定、节点进展和 Outbox；不承诺全局原子升级。 |
| `EvaluationStore` | `Load / Commit / LookupCommit / ListRecoverable` | 评测、样本调度意图／回执及恢复工作；真实样本任务经持久交接运行。 |
| `EvolutionStore` | `Load / Commit / LookupCommit / ListRecoverable` | 候选、阶段、固定分组、发布意图与 Outbox；节点激活和业务效果独立核对。 |
| 观测、内容与生产支撑存储 | 所属模块的受控读取、写入和恢复行为；完整方法名未定。 | 投影可重建，正文引用先就绪再发布；共享底层数据库不扩大原子组。 |

已有 `LookupCommit` 的 Store 按自己的作用域核对原提交；查询结果不明时不能越过提交边界派发新效果。生产实现还须满足[耐久派发条件](../main/04-engineering/03-reliability-and-recovery.md#4-数据库恢复后什么条件下才允许派发)。完整原子组见[附录 01](01-data-model.md#atomic-retention)，不能仅凭多种 Store 同在一个 SQLite 文件里就合并事务。

## 5. 绑定、编码与协商

### 5.1 同一业务契约怎样经过不同绑定

| 位置／用途 | 绑定 | 映射要求 |
| --- | --- | --- |
| 同进程 | Go 领域 Interface | 进入相同用例与检查；不要求领域参数接收完整网络信封。 |
| 同一部署侧跨进程 | gRPC 具名服务、unary RPC 与适用双向流 | 固定请求响应由 Protobuf 定义；调用关联已协商配置，领域类型显式转换。 |
| 端侧与云侧 | WebSocket 全双工 | 每条二进制消息包含一个 Protobuf Envelope；帧分片由传输库重组，同时限制重组长度。 |
| 人工调试 | ProtoJSON 阅读视图 | 遵守对应类型映射，不新增另一套生产 JSON 线协议。 |
| MCP／A2A | 各自的标准绑定 | Adapter 映射业务语义，不把原生 gRPC／WebSocket 报文称作标准协议。 |

开发期即使端与云在同机，也按声明验证 WebSocket 绑定；这不固定记忆、大脑或执行的部署位置。

### 5.2 Envelope 的语义字段组

| 字段组 | 已有名称 | 适用规则 |
| --- | --- | --- |
| 协议 | `protocol_major` | 与业务协商配置一致；bootstrap 自身使用单独的固定结构。 |
| 消息关联 | `message_id`、`reply_to` | 回复引用原请求消息；不同回复各有 message_id，不能只按 reply_to 去重。 |
| 业务作用域 | `namespace`、适用 `operation_id`、可选 `task_ref` | 与可信身份一致；查询目标操作放在方法载荷，不假装本次查询是新变更。 |
| 流位置 | `stream_id`、`seq`、`delivery_class` | 两个方向独立；可靠、临时和无需重放的回执不能混用可靠序号空间。 |
| 调用条件 | `deadline`、`authorization_ref` | 业务期限与本次 RPC 等待分别管理；授权材料放具名受保护载荷／上下文。 |
| 可选诊断 | `trace_id`、`causation_ref` | 仅关联追踪，不参与授权或业务去重。 |
| 互斥主体 | `request / response / event / receipt / flow_control / hello / welcome / resume` | 每条消息选择一种；请求、响应和事件可含登记的具名扩展载荷。 |

`interaction_id`、Surface／组件、目标操作、版本及外部关联按方法放入相应载荷；连接身份由绑定上下文提供，无需每条重复携带 connection_id。主体身份与代理关系来自受信验证，原始第三方凭证不得放入普通信封、任务或追踪载荷。

### 5.3 行为类别与消息主体分别理解

下列“命令、查询、事实、流、委派”描述交互含义，不额外增加五种 Envelope 顶层载荷。

| 行为 | 典型方法／消息 | 关联与返回语义 |
| --- | --- | --- |
| 命令 | Submit、Invoke、SubmitAction、取消／接管及管理变更 | 稳定 operation_id；持久接纳、落实和实际效果分别报告。 |
| 查询／核对 | Get、LookupOperation、GetInvocation、Reconcile | 新请求消息引用既有对象；结果带当前可见事实、确定性或恢复限制。 |
| 事实与通知 | 任务更新、调用报告、最终结果、授权失效、节点应用进展 | 验证来源并按所属版本／位置消费；接收事实不直接改写其他模块权威。 |
| 流式内容 | 临时 token、进度、呈现增量、大产物分块 | 按可靠性类别、序号、大小和额度处理；需要判分／审计的内容先成为应保存证据。 |
| 委派 | 带父任务关系的 Submit，后续状态与结果 | 本地委派操作、子任务和远端句柄分别关联；权限收缩，子任务结果仍需父方综合。 |

### 5.4 编码规则

| 对象 | 固定规则 |
| --- | --- |
| 固定消息 | `.proto` 是结构唯一来源；需要区分缺省和零值时显式 presence，互斥载荷用 oneof，删除字段保留编号。 |
| 动态内容 | UTF-8 JSON 字节，绑定 `schema_id`、`schema_version` 和内容摘要；固定结构不另维护一套等价 JSON Schema。 |
| Schema | 参考方言 JSON Schema 2020-12；关键字、格式验证与正反例由固定夹具约束，调用时不任意联网解析远程 `$ref`。 |
| 数字 | 精度敏感整数使用 Schema 约束的十进制字符串；小整数限定双方可精确表达的范围。 |
| 缺失与对象 | 缺失、零值、null 分别校验；JSON 对象拒绝重复键。 |
| 时间与二进制 | 固定时间用 Protobuf 时间类型；JSON 时间含时区且启用验证。大二进制内容用授权引用或受限分块。 |
| 未知内容 | 结构能解析不等于可执行；未知操作、必需类型或必需能力明确拒绝。 |
| 大小与语义摘要 | 限制消息、重组、动态载荷和队列；去重比较定义的语义内容，不假设任意 Protobuf 序列化字节天然规范化。 |

### 5.5 建立连接时协商什么

| 顺序 | 协商或检查 | 不满足时 |
| --- | --- | --- |
| 1 | 受保护通道、实际对端与可信主体绑定。 | 拒绝；不把节点名或连接建立当作认证。 |
| 2 | 固定 bootstrap 的 Hello／Welcome；gRPC Negotiate 提供等效语义。 | bootstrap 不兼容直接拒绝，无须先猜业务主版本。 |
| 3 | 共同主版本、必需／可选能力及其版本；包含适用 UI 类型／事件。 | 缺必需项拒绝，可选项仅按双方允许组合启用。 |
| 4 | 消息／分块尺寸、待确认窗口、队列及流量限制、心跳和记录保留范围。 | 必需限制未达成一致则拒绝，不使用无限值。 |
| 5 | 操作范围、原逻辑流与已确认位置、记录保留及当前权限。 | 配置失效重新协商；缺口按快照与原操作恢复规则处理。 |

配置引用可通过 gRPC 绑定上下文或必要 metadata 关联，连接恢复不赋予任务所有权。参考能力集还须表达暂停／恢复等后来补充的方法；旧端不支持时明确报告，不能用取消冒充暂停。协议主版本、能力版本和调用授权分别校验。依据：[协议方案](../../archive/architecture-v1/03-contracts-and-protocols.md)、[消息目录](../../archive/architecture-v1/03-contract-message-catalog.md)。

<a id="delivery-recovery"></a>
## 6. 消息交付与原操作恢复

### 6.1 持久责任怎样交接

| 阶段 | 保存或处理什么 | 可以对外报告什么 |
| --- | --- | --- |
| 发送准备 | 所属业务提交同时保存待发消息／Outbox。 | 本地意图已提交；尚不能推断接收方已收到。 |
| 接收 | 持久保存 message_id、来源、语义校验依据、流位置及待处理标记。 | `PERSISTED`；未处理 Inbox 必须能在重启后被扫描。 |
| 同 Store 处理 | 操作去重、业务更新、等待项变化、Inbox 消费和回复 Outbox 一起提交。 | 提交确认后报告业务接纳或结果。 |
| 跨 Store 转交 | 固定同一 operation_id、路由与意图，转交后核对目标结果。 | 分别报告持久转交与目标接纳；不承诺跨模块事务。 |
| 结果交接 | 发送方保留事实和回复责任，接收方按原操作／报告修订消费。 | 已接收与已纳入业务分别确认。 |
| 清理 | 消息补投窗口按契约结束；操作去重／核对明细须先保存关闭水位，并确认无剩余恢复义务后清理。 | 关闭接纳窗口不解除既有操作的核对责任；超出保留范围明确报告过期。 |

### 6.2 不同不确定性，使用不同核对入口

先确定缺少的是哪一层确认：消息是否接收、本地事务是否提交、业务是否接纳，还是外部效果是否发生。下面的入口只解决对应层次的问题；例如找到提交回执不能直接证明文件已经写入。

| 遇到的情况 | 核对入口／恢复动作 | 必须保留的判断 |
| --- | --- | --- |
| Task.Submit／更新／控制的回包丢失 | TaskService.LookupOperation；已知任务可继续 Get。 | 任务快照不一定能证明某一次操作是否接纳。 |
| Invoke 的接纳或执行结果丢失 | CapabilityService.GetInvocation，必要时 Reconcile。 | 执行记录、Driver 与原外部关联一起核对；查询不启动另一份保存。 |
| 记忆或管理变更结果不明 | 所属 Memory／Authorization／Extension／Evaluation／Evolution 的 LookupOperation。 | 原接纳状态与当前对象状态分别返回。 |
| UI 已提交，界面仍未更新 | GetActionResult 核对固定目标，GetSurface 补齐呈现。 | 不因新界面或新事件版本重建输入意图。 |
| 内部 Commit 返回不明 | 所属 Store 的 LookupCommit；MemoryStore 按其 LookupOperation 契约。 | 保持内部提交／业务操作各自核对键，不暴露通用远程读库。 |
| 游标、回执或外部句柄过期 | 获准快照、保留的原操作记录及可用效果证据。 | 查不到不是未执行证明；无法确认就保留恢复限制。 |
| Owner 移交回执丢失 | 核对持久准备、封存、唯一目标与激活记录。 | 源端封存后不自行恢复；沿[所有权协议](../main/03-coordination/04-edge-cloud-coordination.md#2-在线时怎样把-t-移交到电脑)恢复，不新增未定 RPC 名称。 |

记录核对允许后续补投原请求，但只有确认相应接纳与执行条件仍允许时才进行。一次“查不到记录”不能代替已关闭窗口、隔离旧请求或目标幂等保证。

### 6.3 流与背压的最低约束

| 消息类别／问题 | 交付和恢复要求 |
| --- | --- |
| 可靠命令、必要输入、最终结果和关键通知 | 发送前持久化，接收后持久确认，允许重复交付；原操作去重与外部效果核对仍必需。 |
| 明确声明为临时的进度／预览 | 可合并或丢弃；可恢复状态用快照补齐，并通过周期版本核对或可靠版本通告发现末次更新丢失。不能据此丢弃正式输入或必要评测证据。 |
| 大产物 | 授权引用或有界分块，限制大小、并发和积压；保留控制消息发送预算。 |
| 可靠序号缺口 | 每方向只确认持久化的连续前缀；有界暂存乱序消息，不能越过缺口累计确认。 |
| 无法补齐旧流 | 明确恢复边界，核对快照／操作并关闭旧流后建立新位置；不能假装原序列连续。 |
| 回执丢失 | 原消息补投可重建 PERSISTED；回执无需无限递归确认，也不占用同一可靠序号空间。 |
| 慢消费者与队列满 | 公平调度、有界缓冲和背压；逻辑优先级不能消除已排队字节的阻塞。 |
| 重连或连接关闭 | 重新鉴权、核对配置和保留范围；断流不自动取消任务，也不证明授权已经撤销。 |

来源：[恢复状态与交接边界](../../archive/architecture-v1/04-recovery-state-and-failure-matrix.md)、[数据链路补充](../../archive/architecture-v1/12-data-path-and-protocol-semantics.md)。操作明细、关闭水位、业务期限与授权期限的关系见[附录 01 的恢复记录](01-data-model.md#recovery-records)；完整故障组合归附录 03。

<a id="ui-messages"></a>
## 7. UI 消息与自定义类型

本节描述 Harness／接入应用向用户呈现内容的协议。操作第三方应用的点击、滑动和输入继续属于设备执行能力。

### 7.1 核心消息与方向

下表列消息和语义名称，正式服务方法见[3.5](#interaction-service)；消息名称不逐一对应新的 RPC。

| 消息／语义名称 | 方向或载体 | 主要内容与处理条件 |
| --- | --- | --- |
| `DescribeUI` | 能力发现／Negotiate 交换 | 类型、事件、Schema、限制及降级能力；不另建握手。 |
| `SurfaceSnapshot` | 状态服务 → Renderer，或 GetSurface 返回 | Surface、revision、组件内容及有效等待项；保持可恢复快照或获准来源引用。 |
| `SurfacePatch` | 状态服务 → Renderer | Surface、base_revision、revision、变更；基版本匹配才原子应用。缺口取快照，可丢弃状态流另靠周期核对或可靠版本通告发现末条补丁丢失。 |
| `RequestInteraction` | 所属业务经 UI → 用户端 | 呈现、输入 Schema、interaction_id、期限、可选任务／操作关联；等待项在业务模块权威保存。 |
| `SubmitAction` | UI → 登记处理入口 | 正式输入和稳定操作身份；变更或回答经持久转交，允许无任务、无等待项的应用操作。 |
| `EmitUIEvent` | 已登记方向 | 非业务变更的临时遥测／实时事件；按协商处理，不能夹带正式动作。 |
| `ActionResult` | 处理端／UI 状态服务 → 请求端 | 原操作的校验、转交和业务结果；字段错误与未完成分别表达。 |
| `InteractionState` | 所属业务经 UI → 获准端点 | 原等待项的有效、已处理或失效进展；不是 Renderer 自行消费等待项。 |
| `PresentationStatus` | Renderer → 呈现管理方 | 已应用版本、呈现失败或不支持；不证明用户看到、理解或同意。 |
| `CloseSurface` | 已登记的显式界面动作 | 关闭显示容器；任务和业务等待项如何处理另按明确契约。 |
| `DismissInteraction` | 已登记的显式交互动作 | 表达放弃／关闭等待交互的意图，由所属业务检查权限及有效性；不默认取消整个任务。 |

凡动作会改变正式业务或消费等待项，仍须按 SubmitAction／目标业务契约可靠处理。收到一种消息类型不授权端侧下载并执行代码。

### 7.2 类型与事件登记

| 声明项 | 必须明确什么 |
| --- | --- |
| `type_name / type_version` | 有归属的类型名与版本，例如 `org.example.ui.chart`；组件与事件可独立演进。 |
| `schema_ref / payload` | 固定 Schema 标识、版本和摘要；受校验数据，大内容采用授权引用或受限块。 |
| `supported_events` | 事件名称、参数、允许方向、处理模块及是否产生业务变更。 |
| `delivery / persistence` | 可靠提交、可合并状态或临时事件；哪些内容必须能跨断连恢复。 |
| `required_features / fallback` | 必需能力与已声明的语义等价降级；缺确认能力不得用文本显示冒充用户提交。 |
| 实现与权限绑定 | Renderer／处理器、允许调用方与位置；登记不授予业务权限。 |

对话、表单、卡片／结果面板、弹窗、通知／导航、多模态及自定义 UI 均通过核心消息和类型登记表达，不规定像素、CSS 或平台控件类。未知必需类型拒绝；只有声明可忽略且不承担关键行为的装饰性内容可忽略。原 ActionRoute 固定输入、映射和 Schema 版本，升级不重新解释旧操作。

来源：[UI 交互契约](../../archive/architecture-v1/03-ui-interaction-contracts.md)、[SurfaceStore 与路由恢复](../../archive/architecture-v1/12-data-path-and-protocol-semantics.md#4-补齐独立-ui-的状态权威与存储)。

### 8.3 运行配置

| 配置 | 准入和支持边界 |
| --- | --- |
| 进程内扩展 | 仅受信实现共享宿主；接口约束不提供恶意代码隔离。 |
| 独立进程 | 生命周期与通信独立；文件、网络、进程及系统调用限制需实际宿主机制支持，不能只凭“另一个进程”宣称隔离。 |
| 受限 Wasm | 默认不挂宿主目录、不继承环境、不开放宿主网络或子进程；内存页、模块体积、并发、执行时间及输入输出均有界。其他引擎／平台分别验证。 |
| Wasm 取消与实例 | 显式 `WithCloseOnContextDone(true)`，实例化与调用传入有限期限；start 段也可能执行。每次调用使用新 guest，取消后的实例不复用；加载／编译另限资产大小与并发。 |
| Wasm 宿主与恢复 | 仅开放清单及角色允许的 ABI，回调有界且传递期限；guest 限制不等于宿主 RSS 上限或强杀 Go 回调。默认不保存执行栈，中断后核对已登记子动作，不盲目重启有副作用脚本。 |

<a id="identity-configuration"></a>
### 8.4 身份认证与授权材料配置

本表集中固定认证方式、材料格式及期限约束。申请、签发、消费和撤销的运行过程见[2.6 身份与授权](../main/02-subsystems/06-identity-and-authorization.md)，字段见[附录 01](01-data-model.md#authorization)。

| 配置 | 固定要求与失效检查 |
| --- | --- |
| 初次信任与节点登记 | 本地受信管理入口建立管理员及信任根；加入请求一次性、短期，绑定节点公钥和目标 namespace，管理员核对后登记并交付证书。节点验证经受信路径取得的信任根，私钥留在所属节点；自动发现、连接成功和自签证书不能自动建立登记。 |
| 原生节点 | gRPC／WebSocket 使用 mTLS，核对证书链、目标身份、受信登记、密钥版本及失效状态。长连接和恢复的 TLS 会话仍检查当前节点资格；默认直连不信任代理自报的用户头。 |
| 浏览器 UI | 同源 HTTPS 登录与服务端不透明会话；WebSocket 升级同时验证会话和允许的 Origin。Cookie 使用 Secure、HttpOnly 及适用的 SameSite，状态变更校验 CSRF。登出、到期或用户禁用后不再接受新受限操作，已建立连接仍检查失效。 |
| 管理登录与身份替换 | 受信 CLI 生成一次性短期登录码，经同源登录换取会话；登录码不放入 URL，也不作为长期 API 密钥。注册、登录、会话换取及失效入口限制速率并检查重放；外部身份平台通过 `IdentityVerifier` Adapter 映射相同主体语义。 |
| 认证入口与主体绑定 | 原生节点与浏览器入口采用明确互斥的认证配置，mTLS 失败不得退回浏览器身份。原始主体、代理执行者和节点分别保留，节点证书不能用于自报任意用户；进程内认证上下文由受信宿主构造，普通参数不能覆盖。 |
| 跨节点材料格式 | 采用受限 JWS／JWT，参考算法固定 ES256，明确 Harness 类型及版本。符合 JOSE 的实现处理编码和验证，Go 的 ASN.1 签名字节不能直接作为 JWS 签名；具体依赖版本在实现时锁定并做互操作测试。拒绝无签名、算法混用、未知必需限制及超限载荷，不依据不可信请求切换算法。 |
| 签发者、接收方与出示者 | 校验 `iss / sub / aud / iat / nbf / exp`、授权引用、主体及代理关系、全部祖先限制和当前撤销。密钥编号只查受信签发者／公钥映射，材料中的远程地址不建立新信任根。将 `cnf.x5t#S256` 与当前已验证的 mTLS 出示证书摘要比较，单纯验签不算通过。 |
| 转发与证书轮换 | 普通透传保持端到端认证；需要代理出示时，由有权签发方生成绑定新出示者及接收方的收缩材料。受信 Gateway 配置须显式登记，绑定网关证书和后端 audience，保留原发起关系；换证书／网关重新绑定，业务操作身份和期限保持。默认不支持任意代理链。 |
| 签发密钥与信任根 | 私钥只由获准签发方持有；签发私钥不可用时不得退回未签名许可。轮换使用有限重叠验证期，旧材料仍受原期限及撤销约束；信任根通过受信管理路径更新。 |
| 有限期限与离线 | 会话／证书／授权、最大离线窗口、允许时钟偏差和轮换重叠期由获准配置给出有限值并校验关系。缺少必要值不启用相应功能；在线核验建立时间锚点与本进程截止点，计入时钟不确定性。远端许可离线重启默认重新验证，剩余时长文件不能延续资格。 |

签名不加密内容，也不承担去重。材料仅包含必要且获准披露的范围与引用；入口保存已验证的出示关系，后续本地恢复按原操作复核当前资格，不假设旧 TLS 连接仍存在。一次许可的预留、消费与未知交接仍遵守[2.6 身份与授权](../main/02-subsystems/06-identity-and-authorization.md#一次许可怎样只用在这次保存上)的处理端提交规则。

<a id="credential-configuration"></a>
### 8.5 凭证保存与轮换配置

| 环节 | 参考配置与约束 |
| --- | --- |
| 密文与主密钥 | 使用节点的 SQLite 保存 AES-GCM 认证加密密文，主密钥由独立受限文件注入，支持无人值守启动。主密钥不进入凭证库、普通任务配置或日志，密钥与密文各自留在获准位置。 |
| 加密与绑定 | 使用成熟实现，落实 nonce 唯一性及每密钥用量限制；附加认证数据绑定从受信上下文取得的凭证引用、主体、目标服务及格式版本。引用替换或跨账号搬移应校验失败；引用本身仍需授权。 |
| 使用与出口 | `CredentialBroker.Use` 按服务、账号、用途及 Driver 身份提供必要使用能力。大脑、Skill 和普通消息只传受控引用；仅受信 Driver 或受控出口取得使用能力，原始秘密不进入模型、索引、普通载荷或错误文本。 |
| 轮换与恢复 | 保存密钥版本，逐条重新加密并可断点恢复；迁移及允许的备份保留处置完成前，保留读取旧数据所需的密钥。第三方令牌续期按提供方契约核对不明结果，不无限重试；合法旧记录回滚另依赖持久版本及恢复核验。 |
| 不可用与诊断 | 凭证缺失、过期或主密钥不可用时，暂停依赖它的新调用，其他独立工作可继续。诊断只含受控引用和原因；解密后仅在受信执行路径必要的生命周期内使用，不承诺通用运行时可可靠擦除全部内存副本。 |
| 主密钥供应替换 | 可以接入操作系统凭证设施、人工解锁或外部密钥管理，各实现声明实际支持范围；这些方案不成为单机参考部署的必需外部服务。 |

默认方案保护文件访问控制和数据库单独泄漏等场景。主密钥与密文同时泄漏或宿主执行进程被控制时，不提供同样的保密保障；认证加密不自动防止合法旧记录回滚。运行环境与扩展信任边界见[2.6 身份与授权](../main/02-subsystems/06-identity-and-authorization.md#扩展运行在什么信任环境中)。

完整基线与来源见[扩展运行器及 SDK 配置](../../archive/architecture-v1/09-extension-contracts-and-activation.md)、[身份与验证材料](../../archive/architecture-v1/08-authorization-lifecycle-and-interfaces.md)、[生产代理](../../archive/architecture-v1/13-distributed-deployment-and-storage.md)。已有[协议来源复核](../../research/harness-protocol-source-check.md)、[SDK／格式快照](../../research/harness-extension-sdk-and-skill-snapshots.md)及[运行器边界研究](../../research/harness-extension-runtime-boundaries.md)保存固定版本依据；本篇不以查阅文档替代实际互操作证据。

<a id="message-examples"></a>
## 9. 两条消息示例

示例只展开需要查接口的交接。资料、任务 T、摘要 D、保存 S、外部作业 J 和读回 R 沿用[连续示例](../examples/README.md#example-task)。下面的消息短名仅用于阅读，实际身份由可信 SDK／入口按作用域生成。

<a id="save-example"></a>
### 9.1 保存已经开始，接纳回包却丢失

起点：S／R 已准入，电脑保存 Driver 支持原作业核对；本例中 J 已成功取得并持久关联到 S。原有权限仍有效，结果查询记录尚在保留期内。丢失的是电脑到内核的业务接纳回包，不是外部 J 的首次关联。

| 步骤 | 从哪里到哪里 | 方法／消息及关联 | 当前能确认什么 |
| --- | --- | --- | --- |
| 1 | 内核 → 电脑能力服务 | 请求 m1：Invoke，操作 S，任务 T，固定保存版本，D 与输出位置。 | 内核已持久保存原 S 的发送责任。 |
| 2 | 电脑接收端 → 内核 | 指向 m1 的 PERSISTED。 | 消息已持久接收；还不能证明业务接纳。 |
| 3 | 电脑执行模块 → 内核 | 接纳响应 m2，reply_to=m1，关联 S；此回包丢失。 | 电脑实际已接纳并按启动契约保存 S／J；内核仍需核对。 |
| 4 | 内核 → 电脑能力服务 | 新查询 m3：GetInvocation，目标为原 S。 | 查询不新建保存操作，也不将 m3 写成另一业务变更。 |
| 5 | 电脑能力服务 → 内核 | 响应 m4，reply_to=m3，报告 S 正在进行及已知关联。 | 原 S 已接纳且未确认完成；内核继续等待。 |
| 6 | 获准恢复方 → 电脑执行模块 | 必要时 Reconcile 原 S；Driver.Inspect 查询 J。 | 取得原作业效果证据，或保留未知／能力限制。 |
| 7 | 电脑执行模块 → 内核 | 可靠报告原 S 的 FINISHED／SUCCESS／CONFIRMED 及证据。 | 内核正式纳入事实后，按依赖与当前资格推进独立的 R。 |

消息身份可以变化，保存身份保持：

```text
原样补投 m1                 → 仍是消息 m1、保存 S
重新构造同一 Invoke 请求 m5 → 新消息 m5、仍是保存 S
查询请求 m3                → 目标是 S，查询本身没有新保存身份
用户取消保存               → 新取消操作 K，目标仍是 S
```

这些是关联示意，不是新的序列化格式。不能仅因超时、GetInvocation 暂时查不到或本地没有发送完成标记就再次写文件。若 J 的首次关联也丢失，需按目标支持的原幂等键／业务关联核对；不具备该能力则保留未知。完整启动边界见[2.4 能力与执行](../main/02-subsystems/04-tools-and-devices.md#2-一次保存怎样开始等待并报告)。

<a id="confirmation-example"></a>
### 9.2 用户确认，经 UI 转交给任务

这是独立分支：用户此前已要求“确认后再保存”；新摘要 D 已生成，任务 T 正等待正式输入 I，保存 S 尚未准入。手机 Surface 已显示包含 I 的有效版本，用户有回答权限。

| 步骤 | 从哪里到哪里 | 方法／消息及关联 | 当前能确认什么 |
| --- | --- | --- | --- |
| 1 | Renderer → UI 呈现管理方 | PresentationStatus，报告已应用的 Surface revision。 | 端侧报告显示成功；没有消费 I，也没有创建用户同意。 |
| 2 | 手机输入端 → UI 服务 | SubmitAction：操作 U、Surface／组件、确认事件、输入及 I。 | 一个正式确认意图进入检查。 |
| 3 | UI 状态模块 → SurfaceStore | 按版本保存 U 的 ActionRoute 与待转交责任。 | 已固定目标、原输入及映射；目标任务尚未必接纳。 |
| 4 | UI 服务 → TaskService | ProvideInput：同一 U、T、I 和规范化输入。 | 跨模块转交保持操作身份，不分配第二个“确认操作”。 |
| 5 | 内核 → RunStore | 原子核对 I 并保存消费结果、任务变化和后续工作。 | U 已正式处理；不表示摘要已经保存。 |
| 6 | TaskService → UI 状态模块 | U 的业务结果；UI 再保存新投影并发布快照／补丁。 | 可以显示确认已处理；Surface revision 与任务版本各自变化。 |
| 7 | 手机重连后的查询 | GetActionResult(U)，并按需 GetSurface。 | 回包丢失也沿 U 原路由核对，不用新映射重新消费 I。 |

后续 S 是新的保存意图，待内核准入后独立执行；U 与 S 不合并。若另一个新操作争答同一 I，目标模块按当前等待项裁决；U 自己的合法重试则查询原结果，不因 I 已消费而被当成新输入。等待项消费、UI 显示与文件效果是三个不同提交边界，完整过程见[2.5 应用与交互](../main/02-subsystems/05-interaction.md)。

## 10. 一致性验证索引

下表是需要落实的验证项。它检查结构及可观察行为；完整逐窗口断言归附录 03，样本、预算和发布门槛归附录 05。

| 验证范围 | 至少检查什么 | 证据应说明什么 |
| --- | --- | --- |
| 结构与编码 | presence／oneof、字段演进、整数精度、null、重复键、未知类型、大小和 Schema 资源集。 | 各 SDK 对同一正反例有相同接受／拒绝结果。 |
| 绑定等价 | 进程内、gRPC unary／适用双向流、WebSocket 下的同一用例。 | 业务事实、权限与领域错误一致；传输特有失败单列。 |
| 协商与能力 | 无共同版本、缺必需项、可选项关闭、配置过期、UI 能力不足。 | 明确拒绝或按已协商组合运行，没有隐式降低必需语义。 |
| 身份与授权 | 自报用户、代理错绑、重复请求时权限变化、签名受众／出示者不符、单次消费。 | 接入、业务处理与结果披露分别检查，秘密不进入普通消息。 |
| 原生交付 | 原消息重复、新消息同操作、回执丢失、收发重启、序号缺口及窗口过期。 | 不重复首次接纳；未处理 Inbox 可发现，旧身份清理后仍不能复活。 |
| 执行与控制 | 启动回包丢失、效果未知、取消与完成竞态、接管与新启动竞争。 | 沿原操作核对，接纳与落实分开，已发生事实不被覆盖。 |
| UI | 自定义组件、无任务表单、多窗口、补丁失配、连接不断时末条增量丢失、路由升级、重复提交与多端竞答。 | 显示、正式提交、业务消费分别取证；版本核对能发现遗漏，旧重试保持原路由。 |
| 记忆与同步 | 修订冲突、删除后的回执、快照分页、视图变化、游标失效和副本应用。 | 查询与复制不越权，消息持久化不冒充应用完成，被删内容不复现。 |
| 委派与所有权 | 子任务唯一接纳、控制来源乱序、预算交付不明、封存后激活回执丢失。 | 父子独立提交，未知占用不重复分配，旧 Owner 不恢复派发。 |
| 扩展与发布 | 激活提交未知、投影未应用、在途版本、停用、回滚不兼容及旧资产引用。 | 新绑定完整应用才使用，旧操作沿原实现恢复。 |
| 观测与评测 | 来源伪造、投影缺口、判定器缺证据、比较条件变化及阶段通知丢失。 | 诊断不改业务事实，INCOMPLETE 不冒充通过，节点实际应用单列。 |
| 流控与负载 | 大分块、慢消费者、双向同时写、队列满、控制与数据竞争。 | 内存与队列有界，可靠责任不静默丢弃，无协议死锁。 |
| 外部互操作 | MCP 工具失败、严格版本与回退、A2A 媒体／错误、无幂等、句柄过期及取消失败。 | 按规范版本、SDK／补丁、绑定、方向和可选能力记录独立对端证据。 |
| 组件替换 | Brain、Model、Memory、Execution／Driver、Store、传输与 Renderer 的独立实现。 | 共同契约保持；模拟、耐久性、真实平台和能力效果各按实际范围声明。 |

编译成功、Schema 合法、固定成功桩或 Adapter 自连都不能单独证明上述兼容。协议支持声明至少关联精确资产／工具链、配置、平台、方向、能力组合、测试结果和已知限制。运行验收入口见[4.5 实施路线与能力验收](../main/04-engineering/05-roadmap-and-validation.md)。

## 11. 逻辑目录到实现规格还差什么

内核本地 Go 接口和关键类型、WorkStore 方法、运行消息端口与 SQLite DDL 已在[详细设计](../design/01-runtime-kernel.md)固定为实现基线。它们不是原生网络 SDK；本表继续跟踪其余模块、跨语言资产与实际运行支持的缺口。

| 尚需落盘的资产 | 已固定的依据 | 实现时补足 |
| --- | --- | --- |
| 原生 `.proto` 与 SDK | 方法语义、信封字段组、错误、版本与身份规则。 | 精确类型、字段编号、presence／oneof、请求响应映射、错误详情、包路径及生成产物。 |
| bootstrap 与兼容配置 | 稳定协商入口、主版本、必需能力、有界限制和恢复语义。 | Hello／Welcome 的具体结构、能力标识、配置引用编码及各限制的有效取值。 |
| 动态 Schema 与语义摘要 | 登记资源集、版本／摘要绑定、JSON 规则、同身份同语义。 | 各类型 Schema、规范化字节与摘要算法配置、跨语言正反例；不能默认序列化字节唯一。 |
| 组件与宿主 ABI | 本篇列出的接口责任及原子边界。 | 尚未命名方法的最终签名、Wasm 宿主 ABI、Renderer／获取／密钥接口、资源限制与错误映射。 |
| 管理与恢复端口 | 身份登记、所有权移交、存储迁移和生产恢复的已定行为。 | 所需管理调用的具体 Schema、受信入口与夹具；不能补造通用强制接管或任意读写接口。 |
| 工程锁定与支持报告 | 固定协议、SDK、运行器和格式基线。 | 生成器、校验器、JOSE 等实际依赖版本、补丁／传递依赖、兼容结果及升级记录。 |

这些实现选择须保持[项目目标](../../harness-project-goals.md)和[设计硬约束](../main/01-system/01-purpose-and-scope.md)，不得削弱授权、原操作核对、持久责任或独立替换要求。本附录成文完成的是目录整理，运行与互操作证据仍由实际实现提供。
