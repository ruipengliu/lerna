# 01C 任务运行内核：验证与实施

本篇把[主设计](01-runtime-kernel.md)的不变量转成可执行验收要求。当前交付为文档、Go 接口声明及 SQLite DDL；没有 Core、SQLite Adapter、bbolt Adapter 或故障注入运行结果。静态规格检查与后续业务验收分开记录。

<a id="matrix"></a>
## 1. 正常路径与故障窗口

每项用例固定 namespace、Task、原操作、预算、时钟、依赖与故障点，独立读取持久记录及模拟设备实际状态判定。进程内成功返回不能代替重开文件后的事实。下列 RK 编号补充原[RUN 故障矩阵](../reference/03-state-and-failure-matrices.md)，不替换原编号。

| 用例 | 条件与注入 | 必须观察到的结果 | 不变量 |
| --- | --- | --- | --- |
| RK-01 创建去重 | 两个入口用同一创建操作、各自拟分配不同 Task；丢第一个回包。 | 只有一个任务和原创建回执，另一入口返回同一 Task；不同内容明确冲突。 | K1、K5 |
| RK-02 提交断点 | 在状态、操作、Work、预算、Outbox、回执每次写入后故障。 | 重启后全部存在或全部不存在；未知先核对，未耐久不派发。 | K1、K7 |
| RK-03 领取竞争 | 两 Worker 领取同一 Work，旧 Worker 租约失效后提交。 | 仅一个有效代次；旧提交拒绝，迟到事实可由受控入口保留。 | K2 |
| RK-04 正常等待 | 保存返回外部作业，持久后丢唤醒并退出 Worker。 | 工作通过扫描发现；无需等旧租约到期；沿原 S／J 核对，无新保存。 | K6、K7 |
| RK-05 决策唯一 | 多个唤醒、并发 Claim DECIDE、生成期间多条输入。 | 一轮 ACTIVE、一次预留、后续需求合并；正式事实照常接纳，旧版本输出不能准入。 | K3、K4 |
| RK-06 退休竞争 | 旧准入 Commit 与恢复 RETIRE 同时争用当前权威。 | 准入先赢则恢复原操作；退休先赢则迟到准入永久拒绝。不得两者都成功。 | K2、K4、K7 |
| RK-07 失联用量 | 退休时旧调用费用未知，余额足够／不足分别执行。 | 足够则另预留一轮；不足等待；旧输出不执行，迟到用量只结算一次。 | K4、K9 |
| RK-08 更新先赢 | S 已准入且 HELD，目标更新提交后旧 Worker 准备派发。 | 旧领取失败，S/R 冻结；未被复核的工作不自动放行。 | K2、K5 |
| RK-09 派发先赢 | PREPARE_DISPATCH 提交后，在实际发包前／后更新目标。 | 两个分支都按 MAY_HAVE_SENT 核对，不能 DROP 或释放未知预留。 | K5、K6 |
| RK-10 复核批次 | KEEP、DROP、未提及、重复项、错摘要、跨任务和新动作混合。 | 合法批次整体接纳；非法批次全部拒绝；KEEP 身份／参数／依赖不变且不重复预留。 | K1、K5 |
| RK-11 依赖失败 | 前置操作失败或被 DROP，后继仍被 KEEP。 | 后继继续阻塞；不得读取旧文件冒充已保存结果；新依赖需要新意图。 | K5、K8 |
| RK-12 暂停与取消 | 多来源暂停、解除乱序、取消与完成竞争、子任务失联。 | 保留来源关闭修订；取消优先；受理不冒充停稳；终态依证据裁决。 | K8、K9 |
| RK-13 人工处置 | 核对额度耗尽；重复升级通知；提交材料并申请追加额度。 | 原等待显式保留，一次通知事件；材料消费不清除效果未知；获准追加只改指定处置维度。 | K7、K9 |
| RK-14 可靠结果 | Inbox 保存后崩溃；应用前／中／后退出；报告重复或乱序。 | 未消费记录可发现；事实、消费及后继共同提交；用量按唯一项／累计修订结算。 | K1、K7 |
| RK-15 事务错误 | BEGIN BUSY、COMMIT BUSY、IOERR、磁盘满、context 取消。 | 明确回滚和未知分别返回；活跃事务连接不复用；未知不驱动第二次业务动作。 | K1、K7 |
| RK-16 权限／时钟 | 预检后撤权、授权过期、墙钟回拨／前跳、重启。 | 处理端重新检查；时间不可信则停新目标领取；旧租约与授权不因回拨复活。 | K2、K6、K9 |
| RK-17 Owner 移交 | PREPARING／SEALED／目标激活各点断连，源收到迟到报告。 | 源封存后不推进任务；目标唯一激活；原 S、控制、未知占用与交接责任不丢。 | K2、K7、K9 |
| RK-18 清理与旧备份 | 清理明细后重放原请求；恢复较旧备份而外部效果已发生。 | 关闭范围拒绝旧身份复活；恢复先核对外部事实、删除和授权水位，不直接派发。 | K5、K7、K9 |
| RK-19 公平与背压 | 一个用户洪峰、长模型调用、消息积压及低磁盘空间。 | 其他用户及控制／处置获得份额，所有队列有界；可靠责任不静默丢弃。 | K6、K9 |
| RK-20 终态与交付 | 保存成功但读回失败／手机未交付／关键效果未知，分别运行。 | 不提前 COMPLETED；终态后输入和迟到旧提案不重开任务。 | K8 |

## 2. 分层验证，证据不能互相替代

| 层次 | 测试入口和观测 | 通过后能说明什么 |
| --- | --- | --- |
| 规格静态检查 | Go 声明编译；空库执行 DDL；外键、唯一性、非法状态、不可变意图与原子回滚样例。 | 文档资产可解析且选定数据库约束生效，不证明完整业务语义。 |
| 纯规则合同 | 固定快照、命令、时间与 ID，比较受约束变更；覆盖 K1–K9 的决定条件。 | 状态判断确定、非法分支被拒绝；不证明耐久性。 |
| SQLite Store 合同 | 临时文件数据库、两个竞争连接／Worker、真提交与重开；通过公共 Store 接口。 | 原子组、条件更新、回执、读取一致性和领取符合合同。 |
| 进程故障 | 子进程写库，按持久化窗口 kill／重启；设备模拟器保持独立状态。 | 在所列进程故障下原工作恢复且无重复效果。 |
| 同步与系统故障 | 锁定 OS／文件系统／SQLite／驱动，注入 I/O 和断电等声明范围故障。 | 该故障模型下耐久确认成立，不能外推到失效同步的硬件。 |
| 完整任务 | 脚本 Brain＋有状态电脑／手机，再接真实模型；从实际文件、证据、交付与账本判读。 | 组装或模型质量在各自用例范围成立；两种证据分报。 |
| 替换合同 | 独立 bbolt Adapter 运行同一 Store 及任务故障用例，双向停写迁移。 | 脱离 SQL 仍保持语义；两份 SQLite 配置不能冒充独立替换。 |

性质检查至少覆盖：终态单调、操作意图不可变、预算预留守恒、同一决策／工作有效资格唯一、重复输入的幂等性、暂停来源集合合并，以及任意合法执行交错不产生“状态有了但责任丢了”。测试从对外接口观察；不以每个内部辅助函数一个测试代替合同。

## 3. 性能与恢复 profile

建立用户数、每任务 Work 数、依赖边数、消息大小、模型延迟与故障积压维度。分别记录领取延迟、事务等待／持续时间、版本冲突率、决策废弃率、每任务已知／未知用量、控制落实延迟、恢复吞吐、WAL 大小和队列年龄。

有限参数及关系已由[配置合同](01-runtime-kernel-storage.md#configuration)规定。实现阶段先冻结一份开发 profile，跑小型可重复基准，再记录支持 profile 的实际数值与测量范围；本文不拍定生产租约、退避或吞吐门槛。正式评测的既有预算、墙钟口径和阶段门槛继续遵守[验收配置](../reference/05-validation-profiles-and-traceability.md)，不能因本设计增加故障场景而放宽。

比较默认调度与替代调度时使用相同输入、权限、预算、设备初态与故障窗口。测恢复时同时记录持续到达负载；积压清空不代表所有未知效果都已核清。记录版本及配置摘要，结论只适用于实测组合。

## 4. 实施顺序与退出条件

1. 将 Go 规格移入实际公开包，落实封闭命令 Schema、规范化正反例和错误映射；锁定 SQLite 驱动与运行版本。
2. 实现纯规则、统一资格检查、预算／控制／依赖合同，先通过正常和竞争分支。
3. 实现同一持久化单元的 Commit、Lookup、Claim、Renew 和 Inbox／Outbox；在文件库完成 RK-01–03、05–10、14–16。
4. 接入有界 Scheduler／Worker、脚本 Brain、有状态执行模拟器和交付端，完成全部 RK 用例及正常保存／读回／交付。
5. 接入真实模型、Owner 移交与独立 bbolt Adapter，验证既有 M2／M3 适用范围；生产部署和完整能力质量按 M4 及生产 profile 单列。

代码存在、接口编译、DDL 成功不构成 M1–M4 达标。SDK／Protobuf／完整动态 Schema、执行与身份等其他子系统详细设计、驱动实际错误语义、耐久故障、生产容量和真实模型质量仍需交付证据。实现发现与本设计不同的行为时，应先修改规范与相应用例，再扩大支持声明。

## 5. 本次文档资产的验证入口

从仓库根目录运行：

```sh
python3 scripts/architecture/check-runtime-kernel-spec.py
npm run build --prefix scripts/architecture
npm run check --prefix scripts/architecture
```

规格检查器在内存 SQLite 执行 DDL，并用小型正反例检查它确实表达的约束。Go 声明在临时目录独立编译，记录实际工具版本；无第三方依赖。文档检查覆盖链接、锚点和生成阅读页一致性。每项结果应与运行验收状态分别报告。

2026-09-22 的本次校验结果：13 项规格检查通过，使用 Go 1.26.1 和 Python 所带 SQLite 3.45.1；该 SQLite 仅用于内存 DDL 检查，不是选定的运行依赖。全库 234 个文档／图示源的链接检查、68 页生成阅读页的一致性检查均通过。四篇新增阅读页在 1440 与 390 像素宽度下完成浏览器检查，无页面脚本异常或页面级横向溢出，窄屏表格保留独立横向滚动。这些结果不包含 RK 运行故障矩阵、真实模型或文件存储耐久测试。
