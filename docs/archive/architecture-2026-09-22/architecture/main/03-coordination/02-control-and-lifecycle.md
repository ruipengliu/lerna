# 3.2 任务控制与来源变化

任务在等待、模型生成或外部执行期间，用户可能追加要求、暂停或取消，权限也可能撤销，来源可能删除。这些变化作用于不同对象，不能用一个“已停止”状态合并。系统需要记录变化的权威事实，并由实际处理位置决定哪些工作还能继续。

## 1. 先确定改变了哪项依据

| 变化 | 正式依据由谁维护 | 对处理的直接影响 |
| --- | --- | --- |
| 用户补充任务目标或回应任务所属等待项 | Core 与运行存储。 | 正式接纳后推进相关任务版本，旧提案按新事实重新判断。 |
| 任务暂停或取消 | 内核的控制意图、来源与落实进展。 | 阻挡适用的新工作；在途动作继续停止、核对和处置。 |
| 设备接管 | 执行系统在共同资源控制范围内维护。 | 约束使用该资源的相关任务；任务恢复不能直接解除设备接管。 |
| 权限撤销 | 授权权威保存撤销，处理端保存接收和应用事实。 | 在实际使用资源前重新判断，已启动效果另行核对。 |
| 来源纠正或删除 | 记忆或对应来源权威与依赖记录。 | 阻止已知失效依据的新使用，派生内容失效或清理。 |

显示层报告操作受理及落实进度。按钮隐藏、连接关闭或界面文案改变，都不能替代上述业务提交。

## 2. 用户输入怎样影响正在进行的决策

UIStateManager 将输入绑定到任务、等待项或具体业务对象，持久保存原路由和转交操作。任务目标与任务所属等待项由内核接纳后更新任务事实及后续工作；授权等待项由授权模块消费，独立应用输入由其业务模块处理，不必创建任务。若模型仍按旧版本生成，返回提案必须通过当前版本及其他准入检查，不能因为已生成就执行。

例如，摘要正在生成、保存尚未准入时，用户追加“先确认，再保存”。内核接纳这一要求后，旧保存提案失去原版本依据；后续应先形成待确认内容，用户确认绑定对应内容版本。内容确认不增加写入或披露权限。完整输入与显示过程由[应用与交互](../02-subsystems/05-interaction.md#application)维护。

若保存已经启动，再来的要求不能改写原操作输入。系统阻止适用的新动作，并根据原效果决定后续处置；不能把已发生效果伪装成尚未执行。

## 3. 暂停、取消和恢复分别完成什么

暂停按来源保存，恢复只解除指定来源；其他暂停、等待或取消继续生效。有效取消优先于暂停。主状态可能仍为运行或等待，因为系统还在落实停止或核对已发动作；只有相应终态条件成立才提交终态。

执行端收到控制后，先落实对新动作的约束，再按契约请求停止和核对已启动动作。收到取消回执不代表外部已停，租约过期也不证明旧调用终止。设备接管后的恢复需要重新观察资源状态，不能沿用接管前的屏幕或控制资格。

控制受理、送达、应用、实际停止及效果核对分别报告。离线节点尚未收到远端变化时，界面应显示待送达；需要即时远端核验的动作本来就不能离线启动。离线窗口、重启与本地授权权威的规则见[身份与授权](../02-subsystems/06-identity-and-authorization.md)及[端云协同](04-edge-cloud-coordination.md)。

## 4. 来源变化如何阻止旧依据继续使用

来源修订与任务版本分别校验。生成期间一条记忆被删除，即使任务版本未变，包含该来源的上下文也可能失效。内核与组装器在适用边界核对依赖，拒绝已知失效提案，从当前仍获准输入重新组装；持续变化时有界重试后等待。

删除决定、阻止新使用、本地清理、副本传播和备份清理分别确认。混合摘要中含有失效来源时，先使整体派生物失效，再从仍有效来源重建；离线副本重返不能复活已删除内容。保留必要删除标记、水位与关闭旧同步资格的条件由[记忆细则](../../reference/memory-details.md#replicas)维护。

已发给外部模型的数据不能通过本地删除撤回；已发生动作仍保留最小核对事实，受控敏感载荷按生命周期清理。没有覆盖全部模块的全局原子撤回，需要最新状态的用途须在线核验，离线使用须暴露有限窗口。

## 5. 怎样检查变化确实生效

验证要选定变化切点并观察各方依据：例如模型已开始但未准入、执行已准备但是否发出未知、外部已完成但报告未到。分别核对旧提案是否拒绝、新动作是否被阻挡、原效果是否查清以及界面是否准确报告。

这些检查组合已有组件义务，不增加一套集中控制状态机。精确状态与切点见[故障矩阵](../../reference/03-state-and-failure-matrices.md)，具体确认、撤销与来源删除过程见[独立条件分支](../../examples/02-input-and-permission-changes.md)。
