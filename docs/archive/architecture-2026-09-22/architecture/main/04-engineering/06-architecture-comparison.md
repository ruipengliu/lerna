# 4.6 架构主张的比较与验证

<a id="架构主张的比较与验证"></a>

本篇说明怎样检验[四条架构主张](../01-system/06-key-decisions.md)。这些比较是待执行的验证设计；不能用机制存在、图文完整或某个中间指标替代业务质量与运行证据。

## 先冻结可比较的条件

对照实现、版本、任务集、目录、模型、权限、数据驻留、故障模型、资源预算和比较门槛在运行前固定。过期、取消、失败、未知、无输出及设施事故分别报告，不能删去困难任务或故障等待改善数字。统计条件与样本、预算仍由[验收配置](../../reference/05-validation-profiles-and-traceability.md)维护。

## 每条主张怎样被检验

| 主张 | 试验与强对照 | 共同报告 | 不支持主张时的处理 |
| --- | --- | --- | --- |
| H1 连续性与等待资源 | 同一任务集比较业务检查点方案和持久工作流。在准入提交、执行准备、外部接纳、效果保存、内核合并处分别注入故障。固定未决工作量，再增加历史长度。 | 原任务续跑及完成、重复副作用、重做步骤、恢复模型费用、首次有效推进、槽位与内存、提交和 WAL 量、是否扫描全部历史。 | 修正检查点和核对能力；强对照更经济时，不把自建视为恢复优势。 |
| H2 质量与决策成本 | 固定其他条件，逐项替换召回、上下文、记忆与规划触发，再测最终组合。完整目录须能装入模型输入才可作对照，并纳入成熟检索与工具路由。 | 候选覆盖、近义误选、缺参、首次错误归因、单步及多步质量、错误副作用、全部尝试费用、成功任务成本及延迟。 | 按失败环节改进；质量下降不能用 token 下降抵消，无协作收益则保持单 Agent。 |
| H3 端云与替换 | 预先区分本地齐备、依赖云模型、依赖云工具三组，组合断网、端进程重启和重连。在相同数据与权限限制下替换 Model、Store、Driver。 | 本地可完成比例、获准传输字节、端侧资源、恢复冲突、适配改动和契约及业务质量。 | 缺依赖时等待或缩小支持范围；不要求本地自主的配置可采用云端 Owner。 |
| H4 隔离与容量 | 用具备 HA、配额和异步队列的共享池作强对照，固定总资源及故障余量，叠加热点、历史增长、单区／Cell 故障、恢复积压和新流量。 | 实际受影响用户与请求、健康用户延迟、有效恢复能力与新到达率、积压清空、成功任务成本及迁移停顿。 | 先解决瓶颈和共享依赖传播；规模不需要时不增加 Cell 或跨区主动多主。 |

H2 的选择正确性可拆为 `P(C) × P(S|C) × P(A|C,S)`：C 表示正确能力进入候选，S 表示选对能力与目标，A 表示参数正确。这是失败归因方式，不能用中间概率替代端到端验收。记忆策略至少比较无记忆、有效经验和错误经验的配对条件，防止只测成功经验；压缩还要核对关键事实保留与重建成本。

## 根据证据决定后续工作

先跑通完整执行与恢复，再做质量归因和策略比较，随后验证端侧断网与替换，最后在同一生产候选配置中组合负载和故障。恢复收益不承诺常数时间，未知外部效果没有统一时限，多个并行动作也可能同时未确认。

H1／H3 的契约不成立时，该实现不能交付；H2 未达既定质量时继续修正策略；H4 收益不足以抵消成本时选择更简单部署。报告同时记录自建或适配模块、必须维护的故障用例、迁移步骤、告警与人工处置成本。尚无实际比较结果，本篇不作优势达标声明。
