# 26：可靠端云调用与恢复

本票在 25 的认证 WebSocket 上增加 `reliable.v1`。沿用原能力调用、接纳窗口、执行资格与效果核对；无新增第三方依赖。实现是有限安装配置，队列满明确拒绝或等待，恢复证据不足保留 UNKNOWN。

## 接入

Host 两端在 Required 或 Optional 中提供 `reliable.v1`。受信 Resolve 返回精确匹配当前节点证书、主体与目标的 Binding，并提供：

- `Execution`：已有授权能力服务。只为可靠消息开放 Invoke；普通查询通道仍拒绝变更。
- `Journal`：`NewJournal(authority, stablePeerScope, config)`。与 RunStore 使用同一授权存储的原子提交，独立 ExecutionStore 按原 operation_id 幂等交接。作用域绑定命名空间、主体、对端和本地安装，连接 nonce 不成为持久作用域。
- `Disclose`：每次输出及每个应用分块重新检查当前权限和来源/目的地策略。成功调用回执在发送时另行核对原执行授权。
- `Retain`：检查请求及节点绑定的授权材料能否在该节点持久保存。存储与披露是不同权限；没有该检查不协商可靠能力。

SDK `CapabilityClient.Invoke` 可直接使用 Peer。Exchange 在等待业务回执前保存原请求意图；调用超时不撤销已保存意图。需要恢复原消息结果的调用者保留请求的 message_id，通过 `Peer.Result` 获取持久业务回复。SDK 再次调用时会产生新消息身份，但 operation_id 保持；执行服务负责业务去重及语义冲突。

调用身份、受控输入引用及单次执行材料由目标权威的现有端口准备。参考验证预先分配两端各自的有限工作和节点绑定材料，再经真实 WebSocket 接纳调用；没有复制权威秘密或把认证连接当作任务执行授权。实际运行仍由受信 Worker 调用现有 Run/Recover，传输不会直接调用 Driver.Start。

## 持久语义

`WSReliable` 的 generation/position 是可靠流位置；Envelope.seq 仍是连接内各类消息的序号。每个方向有独立可靠位置，心跳、临时进度和持久化回执不占该空间。

发送意图就是持久 Outbox 中的原请求。接收方保存原消息、来源作用域、指纹、位置与未消费状态后，才回 PERSISTED。乱序记录可暂存，但累计回执只覆盖连续落盘前缀。未发送位置的伪造确认被拒绝。PERSISTED 不表示已授权执行、已执行或效果已确认。

接收方扫描未消费请求，经当前授权后交给 Execution.Invoke。未知受理结果仍查询/重交同一操作；执行服务保留原回执，外部效果未知时不会被传输重新启动。确认受理后，消费标记和业务回复在同一提交保存。回复的披露依据独立保留于 Outbox，移除 grant material；请求正文消费后清除，保留消息指纹供重复校验。因此关闭接收流不会破坏另一方向未交付回复的依据。

`Journal.Complete` 的本地回调共享 RuntimeTransaction，可将任务状态、消费与回复一起提交；`WorkPort.ConsumeExecutionIn` 复用原执行报告消费规则。回调可重试，禁止外部 I/O 或嵌套存储调用。独立执行存储在回调外按原操作接纳，再提交交接；进程退出不会制造跨库原子性假象。

每次新连接持久领取递增 session；原连接及其他进程持有的旧 session 不能继续提交或发送。断开连接不会取消业务操作。恢复和启动仍受当前节点、执行授权、任务资格、控制意图与原窗口约束。

## 过期与清理

重连交换 RESUME 连续位置并补投原消息。消息超出补投期限或用尽发送预算后，先持久关闭原发送流，将剩余操作关联转为恢复记录，清除业务请求/授权材料，再通过 CLOSE 协商新流。接收流关闭同样先保存边界；未消费旧请求转为操作核对，不再首次执行。

`Peer.Recover` 及有限周期恢复循环查询原操作的公共快照。返回每条结果前重新检查披露条件；远端快照向原权威查询，缓存不形成长期授权。KNOWN 只表示取得原操作快照，快照自身的 UNKNOWN/IN_PROGRESS 仍是未解决效果；后续查询继续刷新。无法读取或预算耗尽不推断未执行。

`Journal.Clean` 只清理已经取得终态且效果非 UNKNOWN 的恢复快照。可靠流世代水位继续保留；业务操作记录、窗口关闭水位和剩余恢复义务仍由业务权威管理。关闭接纳窗口不取消已受理长任务；未受理旧操作在原窗口关闭后被拒绝，运输层不会自动换操作身份。

对象级接收保存/披露拒绝原子保存摘要处置和通用失败回复，消费前后均可隔离该对象，健康对象继续处理。发送方对不能披露的载荷保存 omitted_sha256 处置，只发送原身份、位置和原载荷摘要。接收方据此填补可靠位置且不执行处置；若原消息此前已保存，则保留原业务处理。处置不是业务取消，原效果仍需核对。原载荷尝试与处置尝试分别持久计费、各受 Attempts 限制；未尝试的后续消息不扣预算。全节点身份失效仍关闭连接。

## 有限配置

Journal 配置必须与已保存配置一致。最多 16 个稳定对端作用域；每个作用域 1–256 条业务收件/发件/恢复记录合计，4 KiB–1 MiB 载荷预算，乱序距离 1–32，发送与恢复核对尝试 1–3 次，补投期限 1 秒–24 小时。同一恢复记录对应的省略处置使用独立有限控制元数据，不重复占用业务记录槽位；仍受字节上限约束。整个持久分区最多 4 MiB，受底层快照上限进一步限制。接收处理尝试同样持久计费。

参考配置为 64 条、256 KiB、乱序距离 8、总尝试 3 次、补投期限 1 分钟。WS 原有消息、分块、连接、队列、I/O 与连接寿命限额继续生效。恢复扫描大小受记录数限制，每轮使用连接 I/O deadline；周期核对每秒一次，连接最长寿命有界。包括 KNOWN 非终态在内，每次恢复核对均使用同一持久 Attempts 预算；耗尽后保留 UNKNOWN 等待状态，不返回旧缓存快照，也不因重启恢复额度。调用者显式读取 Result 时另外查询原权威，确保当前权限允许读取原回执。

存储保留策略与补投期限分别检查：转为恢复记录时去掉请求正文和授权材料；仍需保留的最小操作关联及公共快照受宿主来源策略约束。本实现不提供任意应用数据的通用跨节点许可。

## 验证

运行 `scripts/verify-reconnect.sh`。原始环境、模块清单、生成一致性、构建、静态分析、专项及受影响竞态回归输出位于 `build/reconnect`；脚本保留每阶段结果并在任何失败时非零退出。

专项覆盖：原子提交失败回滚、重启恢复连续前缀、重复身份与语义冲突、有限队列/确认/重试、真实调用、旧连接隔离、关闭接纳窗口、原操作快照恢复及撤权、非终态后续更新、健康对象隔离、Inbox 写入失败无回执。实际独立进程分别在 Inbox 落盘、独立执行存储受理、外部效果发生后退出；两端重新启动，两个方向均独立核对目标变更次数。

额外覆盖接收保存前后拒绝、发送队列撤权、持久 PAUSE/CANCEL 与执行资格过期时健康对象仍可完成；模拟时钟仅用于期限边界，进程退出、网络和 SQLite 提交实际执行。最终配置及原始结果见 [验证报告](evidence/26-reconnect-report.json)，审查与修复见 [审查记录](26-reconnect-review.md)。

范围限制：参考目标是私有 SQLite counter，实际网络是本机真实 mTLS WebSocket；不表示公网移动网络、生产设备或外部 API 的 exactly-once 保证。未开放所有变更方法、任务所有权迁移或完整 UI/记忆同步。专项进程/存储证据不代表模型质量或全系统验收。
