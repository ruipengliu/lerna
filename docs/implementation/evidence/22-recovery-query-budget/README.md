# 答案进程恢复的原任务查询预算

复现命令：

```sh
go test -race ./profiles/fetchcheck -run 'Test(EvidenceAnswerRecoversAcrossProcessExit|ResearchContentQueries|EvidenceBrain)' -count=1 -v
```

实际通过（19.332 秒），相关 vet 通过。子进程在模型响应后或答案 Save 后直接退出 76；父进程重开真实 SQLite/Content，恢复 Port 不调用模型。

| 同任务窗口 | 子进程前查询 | 重开后、恢复前 | 恢复后 | 原额度 |
| --- | --- | --- | --- | --- |
| response | 7 | 13 | 14 | 32 |
| content | 7 | 16 | 27 | 32 |
| content_revoked | 7 | 16 | 28 | 32 |

未保存响应不能恢复正式结果；已保存结果沿原身份完成。撤权窗口首次 LOOKUP 失败，仍额外消耗 1 条查询；恢复显式公开测试策略后重用同一答案。每个窗口实际 HTTP 总数为 1，模型已知请求 1、未知保留请求 1/token 2560；原行动事实和回执不变，仅查询列表追加，既有前缀保持。

完成后的测试观察者使用独立授权读取答案及证据，不能以已终结任务资格继续发起工作查询。两个独立答案任务的旧恢复窗口继续通过，但它们没有 Actions 查询额度，本记录不冒称其查询已纳入该计量。

本次使用一个实际获取行动和本地协议模型，不是完整多轮搜索/跨端或真实模型评价。行动宿主内部、获取结果账本等剩余查询接入仍待完成。
