# 22 票后建观察作用域的来源期限

首次搜索偶发进入 WAITING/reconciliation，最外层执行错误为 nil。仅重复运行成功不能证明修复：答案重开路径的 20 个子例中复现 1 次（整个命令 78.264s）；带临时驱动诊断的 20 次单页路径又复现多次（67.468s）。

诊断记录真实搜索驱动 Start 在约 0.4 秒内返回 fetch denied，Inspect 同样被拒，上下文没有 deadline 或取消错误。执行器将未知观察报告给 Core，后者进入等待核对；没有证据支持通过增加超时解决。

原因是宿主初始化来源策略时固定了绝对期限，而 acquisitionQueries 每次创建观察作用域都重新计算“当前时间加 10 分钟”。初始化与构建作用域只要跨过一个 Unix 秒，证据 PUT 的保存期限便超过原来源授权。撤权检查正确拒绝了这个请求，但参考宿主构造出了不合法期限。

真实 Core/SDK/SQLite/HTTP 回归 later_scope 在创建宿主后推进已有可控时钟 2 秒，不等待实际调度。修复前稳定进入 WAITING（1.392s）；修复后连续 3 次 race 通过（5.684s）。没有 mock 自有业务模块。

宿主现在保存一份 evidenceConfig。初始化及恢复时，期限取当前启动上限与已持久化规则期限的保守最小值；随后获取作用域和研究证据视图沿用该配置，不重新滑动期限。每个消费者仍分别创建有限长度缓存，不共享正文或旧权限。每次实际 Content 操作继续检查当前来源策略，撤权不会被配置快照覆盖。

临时 DEBUG-search22 驱动包装已删除，执行器和超时配置没有修改。原最小循环和答案重开路径的重复回归、相邻授权及实际进程恢复回归仍在运行，本记录尚不宣告它们通过。原 64 次查询上限、多来源预算失败及 22 票其他未完成验收仍保留。

后续验证：单失败路径及可回答/获取失败答案重开的组合连续 10 轮 race 通过（共30个验证路径，126.304s）；授权撤回、缺失策略、SDK获取作用域、WAITING及获取/搜索实际进程恢复组合通过（22.099s）。相关 vet 和 diff 检查通过，DEBUG-search22 在源码中无残留。Standards和Spec独立增量静态审查均无新增可操作发现。完整冻结组合及全仓门禁不在这些通过结论内。

期限修复后的完整冻结组合仍失败（20.734s）：HTTP冲突行动阶段55次、固定回放冲突54次、冲突答案重开55次；部分失败的两种顺序均为52次。它们在答案阶段耗尽原64次查询预算，分别报告 fetch unavailable、INPUT_INVALIDATED 或 QUERY_BUDGET_EXCEEDED。该轮没有首次搜索WAITING，但不因此将组合验收标为通过。实际模型质量、全仓门禁及原票其他条件仍未完成。
