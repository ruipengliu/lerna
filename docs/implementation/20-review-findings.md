## P2 修复边界（待实现）

原需求审查者已复核下述边界符合 20 要求：保持现有精确 Delete 及其原操作恢复；新增从持久来源屏障驱动的逐修订清理，擦除仍依赖失效来源的历史/当前 Memory 修订，保留已纠正成独立来源的修订。该路径可接 SourceCleanupWorker，但不能把旧 Delete 的 unknown/conflict 改报 committed。

实施与验证须覆盖：

- 在与 Put/Correct 共同的提交边界复查永久来源屏障，防止失效来源在清理后重新落盘。
- 历史正文移除后，修订编号和当前头部仍保持单调；不能用剩余正文行的 MAX 使 Query 回退。
- 被擦除原操作保留可核对事实，清除正文比较材料；引用、Get、Query、上下文不得重新释放旧内容。
- 消费者事件明确精确被擦除的 Memory 修订，不能将独立来源的新修订及其派生产物一起清理。
- 擦除后、通知前或确认前退出，重启仍可发现原清理工作并继续投递。

已保存的失败测试目前限定旧 Cleaner 的返回值；新路径落地时应改为实际来源清理入口与正文/独立修订/原操作状态的边界断言，不要求旧 Delete 伪造已提交。这是对实现路径的调整，不放宽实际清理要求。
