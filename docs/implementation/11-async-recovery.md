# 11：异步调用与未知效果恢复

在原执行协调上增加 AsyncPolicy/AsyncDriver、受信进度入口、持久恢复调度和独立取消操作。固定异步能力返回的关联先存入 Execution 分区，再按原操作 Inspect；模拟业务目标使用独立 SQLite 作业记录，由独立 Complete 操作推进，查询不会执行动作。

Capability SDK 提供 RequestCancel/GetCancel。取消记录与原调用分开，受理、可能发送、请求返回、实际停止与未能阻止完成分别表达。Task CANCEL 通过预先保留的取消身份交接，恢复不能创建无限新的取消操作。Cancel 请求可能已发送时只核对，不重新发送。

恢复调用 `Service.Recover(ctx, limit)`，每次最多 16 项，调用方安排后续轮次。持久轮转游标避免空闲或预算耗尽的前缀记录饿死后续工作。持久 NextCheck、LeaseUntil、Generation 和 Checks 限制频率及竞争；业务额度与核对/取消处置额度不同。租约失效允许有界只读核验恢复，不授予新的业务 Start。迟到核验仍可保存原证据，旧代次不能清除新代次的租约。单个进程内不配合退出的调用继续占住本地槽位。

可信 ProgressPort 由宿主绑定来源，公共消息不能指定自己的来源权威。重复版本与摘要重放不增加报告，迟到进度不覆盖已知效果。矛盾终局保留证据引用和来源，标记 ConflictingEvidence，阻止新业务启动。进度入口与 Driver/Inspect 共用有限本地 I/O 槽位，忙时拒绝接纳，由调用方保留未交付事实。当前参考实现保持显式待核对，不提供自动消解矛盾的管理接口。Task 已终态时保留后续冲突事实，不静默重开任务。目标保存完成时间，Core 核对该时间与控制接纳截止及目标更新版本；先完成后收到取消可以记录未能阻止完成。

Outbox 先交接原操作最新累计结论，再幂等核对较旧修订，避免已持久冲突被队列中的旧成功覆盖。原报告仍在执行记录中保留。一致的后续终局修订允许幂等消费；与终局不一致的事实必须携带明确冲突状态。Core 已消费与执行侧确认分别提交，丢确认只重放原报告。

参考配置为 32 个调用、32 个取消、每调用 8 份报告/16 份证据、64 份 Outbox、4 次主动核验、最多一次 Cancel 发送、1 秒 I/O、1 秒轮询间隔、3 秒核验租约和 1 分钟恢复窗口。目标最多 64 个作业；未知不清理去重记录、不退款或重做。参考句柄是有界非秘密随机定位符，不对外序列化；敏感凭证型句柄不属于该适配器支持范围。

本票使用本地二进制协议、真实授权及受控内容；没有实际 gRPC/WebSocket 推送部署、共享资源接管、真实业务 API、设备或付费模型调用。随机句柄丢失且目标不支持关联恢复时明确保留 UNKNOWN。

go test ./profiles/asynccheck ./profiles/executioncheck ./tasks ./sdk

原键查询保证失效通过目标 ExpireLookup 模拟，目标历史仍供独立判定，恢复路径不能借过期重建作业。否定查询使用目标 Fence：先保存原操作的拒绝记录，使迟到 Start 也无法改变资源；单纯查无记录没有该保证。

旧版本升级样本由实际 `fa498ce` 编码器在目标已变更、效果尚未回存时产生，保留独立目标和完整测试 authority 编码。样本中的随机测试登录/窗口校验材料仅对应合成离线测试权威，不含真实服务凭证或签名私钥。升级后原操作可查询、重放接纳、核验、交接，原许可不改变、目标只变更一次。异步策略使用新固定能力配置；不把已有同步调用的版本切换为异步。

具名 profile 覆盖 15 项契约检查和 8 个真实子进程退出/重开边界。另有集成回归覆盖正常异步完成、取消进展、控制截止、策略冻结、迟到进度、首次启动前任务取消、原许可身份隔离、恢复轮转、进度并发和旧编码升级。同步原有 profile 继续运行。
