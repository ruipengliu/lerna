# 22 票：豆包搜索总结直接回答

用户于2026-09-13明确要求直接利用豆包搜索接口总结回答，不再默认拉取原始全文。本决定替代本票此前“公网必须抓取原网页正文才能验收”的要求；历史结果按当时标准保留，不改成通过。来源登录、快照及页面抓取可达性不再是该模式必备条件。

宿主选择 AnswerFromSearch，公网CLI默认开启。豆包请求 NeedSummary=true、NeedContent=false，读取 WebResults.Summary。真实API探针已确认该字段存在；Summary为空时不将Snippet冒充总结，保持发现记录并回答信息不足。搜索成功后Core直接进入答案阶段，不生成候选网页获取操作，URL仅作来源标识，不会授予访问或登录权限。

每条非空Summary构成一个独立、稳定的响应视图：原ContentRef#summary-index。它不是新增Content对象；父ResponseRef及ResponseSHA256、候选URL/标题/索引、搜索响应时间均保留。Body为原Summary精确文本，引用字节范围与摘要绑定此文本。两条来源可独立表达冲突。所有当前授权、处理位置、撤权、lineage及恢复仍沿原受控搜索响应检查。答复须标明基于搜索服务总结，搜索返回时间不冒充网页发布时间，也不声称亲自读取原网页。

SearchMaxResults宿主可选1..4，零值兼容旧4条；模式、结果数与超时绑定原能力描述符及运行清单，恢复不能改变原操作含义。AnswerOutputTokens公网默认4096，仍受原任务总预算及独立8192字节答案界约束。旧直接抓页及固定资料路径保留，不能把其历史验收条件套回新模式。

新验收要求：一次真实豆包搜索总结请求，零候选网页请求，正式答案引用Summary，独立核对语义、来源及时效表述；缺总结、冲突、搜索失败均如实表达。历史全仓catalogcheck失败仍是独立未完成项，修改业务路线不豁免它。
