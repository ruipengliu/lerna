# 22 票参考装配的查询计量清单

当前检查点：研究 SDK 执行读取接入、任务内长度事实复用及逐项完成判断计费。此清单用于定位剩余工作，不是完整计量验收通过报告。

计量单位为消费方调用边界，不是 SQL 语句数。Core.Actions.Queries 是任务级总记录，ContentQueries 与 OutcomeQueries 是其子集。Core 为扣费、资格、控制和租约所做的内部状态核对不递归计作业务数据查询；它们仍受原任务期限与各自 I/O 上限约束。

| 路径 | 当前处理 | 剩余核验 |
| --- | --- | --- |

## 执行读取的实际入口

Execution 的可选 RequestContent 传递原请求，fetchoutput.WithQueries 经 ChargeExecutionQuery 核对完整原 ActionBinding。研究 CLI 的获取与搜索 SDK 服务现已绑定原 ActionPort；固定回放沿用实际配置的 target，不回退为默认 HTTP 驱动。

正常 SDK 测试的四次 Content 查询为接纳 READ、运行 READ、保存输入 GET 与已获取证据 GET。任务自身成功 PUT 返回的有界输入长度由 RememberInput 记录，WithContent 保留长度并重新绑定当前消费端口。错误提示必须由实际 READ 拒绝，不能返回部分 JSON；零值和超限提示不缓存。没有可用长度时仍先 GET。

WAITING 关闭重开测试现累计七次：原接纳 READ、重开后运行 GET/READ、保存的两个 GET，以及驱动恢复的 LOOKUP/READ。此次新执行成功 Complete 的终结事实在同作用域内经当前资格核对后复用；新作用域没有旧缓存，仍计费读取 Outcome。驱动证据 PUT 已返回的长度省去重复 GET，当前 READ 检查保持。执行查询和驱动检查共用显式恢复的精确起点，原请求、资格和额度保持；尚未新增子进程崩溃实验。
