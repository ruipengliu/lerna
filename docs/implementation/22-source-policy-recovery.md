# 22 票当前来源策略的持久化恢复

继答案交接禁止恢复权限之后，本增量消除宿主关闭重开时重新安装默认规则的行为。原22票要求撤权、用途、处理位置和期限在恢复后继续生效；空规则集表示全部撤权，不表示需要初始化。

contentpolicy 增加消费方 RuleStore 接口和 Persistent 策略视图，既有内存 Policy 保持可用。RuleStore 负责首次初始化、读取当前版本及原子替换完整规则；sqlitecontentpolicy 提供无外部服务的 SQLite 实现。规则和单调版本持久化，单份规则序列化上限1MiB，仍受256条规则及既有结构检查约束；数据库采用当前仓库的私有文件检查、WAL和同步落盘配置，每次操作限时一秒。

NewPersistent 仅用于首次初始化，已有行不被默认值覆盖。OpenPersistent 只加载既有有效策略，缺失或损坏时失败，不授予默认权限。参考宿主首次引导使用前者，携带已有身份的恢复使用后者；数据库丢失后即使创建了空文件也不能恢复默认权限。

每次 Check/Revision 读取当前存储快照，因此另一实例的撤权不会被旧内存规则遮蔽。版本不随进程重启重置，原期限不会因恢复延长。策略存储读属于当前授权解析，不是读取来源正文或新查询结果；它仍有I/O期限，不作为无成本访问。

## 验证进展

真实任务取得证据、撤权后关闭重开的反例先失败（0.734s），证明旧宿主恢复了来源权限。策略文件丢失的反例又发现恢复默认权限（0.143s）；区分初始化与恢复加载后，新错误路径暴露既有命名返回值导致清理空指针的问题，已通过捕获已分配宿主修复，未吞掉原错误。

双 SQLite 连接用例核对第二次默认初始化不覆盖已有规则、另一消费者立即看到撤权、版本变化及重开版本保持。原账户/任务/Content/SDK/HTTP链路验证撤权策略版本不变、模型零调用、无发布结果；恢复缺失策略必须返回错误。当前相关 race 与原获取/搜索进程恢复组合正在运行，尚未以此宣称完整验收。

本增量只持久化当前完整来源规则及版本，不提供策略历史、操作者审计、策略更新的授权管理界面或通用生产配置迁移。原公开参考数据库若没有来源策略存储，恢复会明确失败，不能静默迁移为默认授权。多来源查询预算失败、未定位的交接波动、实际模型与全仓验证等原22票剩余条件继续保留。


修复清理后，跨实例持久化及实际交接/WAITING/获取搜索进程恢复的race组合通过：sqlitecontentpolicy1.078s、fetchcheck11.089s。缺失与实际损坏数据库的定向race通过（1.316s），证据答案进程恢复及正向答案重开选择组合通过（11.052s），vet/diff通过。Standards与Spec独立增量静态审查均无actionable findings，未替代最终整票验收。
