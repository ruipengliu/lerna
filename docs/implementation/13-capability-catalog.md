# 13：千级能力目录与准确版本执行

本票提供同一完整目录中的 1008 项模拟业务 API，以及 SDK 的 List、Search、Describe 和准确版本执行路由。检索、权限、版本准入与实际业务效果分别验证。这里的规模证明不代表 1008 家供应商、1008 个并发任务，也不代表模型已达到首次正确率 90% 或有限纠错成功率 95%。

## 运行与可替换边界

```sh
go run ./cmd/contractcheck -profile capability-catalog-v1 > build/capability-catalog-report.json
make verify
```

入口不读取 `.env`，不需要模型、外部数据库或真实设备。具名 profile 对完整目录逐项执行，并为每个准确描述符输出独立结果；另外覆盖查询、权限、版本、共享资源控制与真实 SQLite 子进程中断。`make verify` 保留 01–12 的验证并加入本票。

`catalog` 定义消费方使用的 Store、Authorization、Ranking、VersionLock 和 Executor 接口。SQLite 目录、授权批量视图、本地 Protobuf 绑定和执行路由各在独立适配器内。默认 Ranking 使用本地关键词；替换实现通过 WithRanking 注入，必须遵守上下文期限和数据披露边界。领域接口不接收 SQL、数据库连接或供应商客户端。

`executionrouter.Resolver` 由受信宿主提供有限、已认证的命名空间会话。请求不携带任意后端地址或宿主令牌；未知命名空间拒绝。参考组装放在 `profiles/catalogcheck`，按固定业务类型装配真实授权、Task/Worker、受控内容、签名许可、Execution 与独立业务目标。它是串行本地参考宿主，不是网络多租户调度器。

## 冻结清单与独立计数

业务定义位于 `adapters/execution/simworkflow/definitions.csv`：28 个分类、168 个业务类型。每行明确业务类型、数量字段、约束字段、验证条件、计量单位及 reserve/credit 会计方向。`definitions.go` 为每类提供六个有明确前后状态的操作；输入、输出 Schema 及描述符摘要由冻结代码确定。profile 保存定义摘要及逐 API 描述摘要，提交版本固定生成规则。

计数单位是“业务类型上的操作契约”。例如采购订单的 ordered_units/approved_units/vendor_verified、休假申请的 leave_hours/leave_balance_hours/coverage_confirmed、客户发票的 receivable_cents/delivered_value_cents/tax_validated 分属不同业务类型和独立状态。它们共享工作流引擎，但使用不同业务字段、单位及效果合同。多个订单实例、同一 API 的别名、实现副本或版本都不增加 K。

| 操作 | 状态前提与业务规则 | 效果 |
| --- | --- | --- |
| draft | 记录不存在；数量、约束均为 1–1000 | 保存业务数量、约束和验证条件，创建草稿 |
| submit | 草稿；验证条件为真；业务数量不超过约束 | 进入已提交状态 |
| authorize | 已提交；账本变化后在 0–2000 内 | 按业务类型 reserve/credit 数量，进入已授权状态 |
| reject | 已提交 | 拒绝记录，不改变账本 |
| withdraw | 已授权；逆向变化满足账本边界 | 显式撤回并反转会计效果 |
| archive | 已拒绝或已撤回 | 归档，保留原记录 |

每次变更核对准确记录版本；稳定操作身份和请求指纹存入独立目标数据库，原操作可核对且重复 Start 不重复修改。withdraw 是用户显式选择的业务操作，不是执行器对未知结果自动补偿。无外部供应商、GUI、异步业务取消或隐藏重试保证。

完整覆盖的判定材料在 `fixture.go` 内：每个操作使用独立记录、指定起始状态、字面量预期终态和账本值。它不调用驱动的状态迁移逻辑推导答案。数量 3、基准 1000 下，reserve 的 authorize 应得到 997，credit 应得到 1003，withdraw 恢复 1000。authorize/reject 等记录在同一业务类型中共享账本；直接目标测试另验证同一记录跨 draft/submit/authorize 的连续迁移。

检索输入只有公开业务文字、分类、资源类型和需要的特征，不包含预期能力引用或判定真值。每次调用时完整 1008 条目录均存在；Search 实际扫描 1008 个获准摘要、加载 0 个 Schema，然后 Describe 准确候选，再经正式 SDK Invoke、Worker Run、独立目标核验和 Outbox 交接。每项历史记录持续保留。

## 查询、隐私和预算

List 分页返回摘要，包含用途、位置、资源、前提、副作用、不支持条件和执行保证。Search 返回有界候选及可披露匹配依据；Describe 仅接受准确 namespace/name/version/implementation/implementation_version/digest，不替换为最新版本。完整 Schema 只在 Describe 或实际执行组装时加载。

查询先读取有限权威摘要，再用同一当前授权视图按资源、用途及真实处理位置过滤。只有获准条目进入索引读取和 Ranking。查询的 Budget 计入获准候选文档工作量，隐藏条目不挤占候选预算或产生公开计数。元数据授权检查有独立固定上限，不承诺 Budget=1 意味着物理只读取一行。

声明保存受信来源 kind/key/revision，查询来源由已认证宿主绑定。独立 contentpolicy 先检查查询 process，再按声明来源检查 process/discover/disclose；目录访问获准仍不能越过来源拒绝。数据策略修订、有效期和进程重开后的规则摘要共同进入游标视图；撤回后恢复同一规则也会使旧游标失效。Describe 先加载准确摘要并检查权限与来源策略，再加载完整 Schema，返回前复核。

授权适配器合并相同资源/用途/位置检查，使用真实策略和本地授权；授权视图包括主体、策略修订及过期边界。结果返回前再核验一次视图。撤权或无法确认授权时不披露旧候选；无跨请求候选或 Schema 缓存。查询和声明正文只在已获准本地执行，调用者指定位置不能把真实位置改成云侧。

分页游标是带认证加密的有界状态，绑定命名空间、主体、授权视图、查询条件、目录修订和最后位置。密钥持久保存，原始排序位置不外露。篡改、换主体、改条件、目录修订或撤权后重放拒绝。Describe 对缺失引用和无权引用均明确失败，避免用错误类型查询隐藏条目是否存在。

| 限制 | 参考值 |
| --- | --- |
| 活跃声明 / 保留历史声明 | 2048 / 4096 |
| 单声明 / 单输入或输出 Schema | 64 KiB / 16 KiB |
| 权限过滤前摘要读取 | 最多 4096，参考目录最大 2048；超出明确失败 |
| 获准文档扫描预算 | 查询配置上限 2048；结果只报告获准扫描数 |
| 摘要页 / 搜索候选 | 最多 64 / 32；返回摘要正文合计另限 64 KiB |
| 查询文本 / 特征条件 | 2048 字节 / 最多 8 个、每个 128 字节 |
| 游标 / 查询时限 / 并发槽 | 4096 字节 / 1 秒 / 4 |
| 索引重建 | 每批 1–64 条，按目录修订分批推进 |
| 参考执行驻留 | 1 个业务运行会话，含 6 个准确执行服务；独立发现会话 |
| 每业务持久容量 | 6 个执行分区；每分区 32 操作、8 报告、64 Outbox 项；既有总执行 4 MiB 限制 |
| Task / 签名授权 / 内容 | 每业务 100 Task、64 签名记录、64 内容记录、2 MiB 内容 |
| 独立业务目标 | 每类 64 条记录、64 条操作；账本 0–2000 |

回调式索引、排序和执行适配器必须协作遵守 context；本地适配器采用有界 SQL、批次和循环，不启动隐式模型或无限重排。取消或 I/O 超时失败关闭；不会以“完整无匹配”掩盖失败。底层授权、受控内容和执行自身期限仍适用。

## 权威目录、索引和准入顺序

SQLite 权威声明和可删除索引分表保存。受信导入先校验声明及 Schema，并由宿主提供必需的 ImplementationCheck 确认准确实现可调用，再在单次事务中替换活跃集合。相同准确版本不能改内容或换摘要；旧声明保留。参考宿主仅接受冻结业务引擎确实支持的描述符。来源可用性单独变更并推进目录修订。

重建按有限批次暂存索引，完整覆盖后才公布 index_revision。INDEX_MISSING、INDEX_STALE、INDEX_REBUILDING、INDEX_PARTIAL、INDEX_CORRUPT 和 INDEX_UNAVAILABLE 表达不同索引限制；SOURCE_UNAVAILABLE、SCAN_BUDGET、RESULT_BYTES 等表示来源或工作量限制。索引失效时可在预算内扫描权威摘要；即使权威扫描完整，也保留索引限制，不宣称索引正常。真正无匹配需要获准覆盖完整且无来源或预算截断。删除索引表后 Rebuild 可重新创建和完成；已知内容损坏可先 InvalidateIndex 再分批重建。

新 Invoke 经 Admission.WithVersion，在目录的 IMMEDIATE 事务持锁期间完成真实 Execution 的持久准入；目录发布/撤回必须获得同一写锁。准入先完成，则保留原描述符、许可、输入和报告；撤回先完成，则新操作拒绝，Driver 不发送。实际 Driver Run 在目录锁释放后执行，并继续受当前权限、Worker、Task、资源控制和预算约束。

已存在操作先经真实 GetInvocation 检查所有权和当前读取权限，再按原 Executor 重放。已准入后的撤回不改写旧 Schema、未知结果或报告。只读核对和取消路由在同一命名空间的最多 32 个受信准确服务中查找原记录，不依赖易丢失的内存 operation 映射。

168 类业务各有预先固定的命名空间、授权权威和目标数据库；同类六个入口共享一个资源控制范围和目标围栏。目录查找不创建新的权威划分，也不按答案裁剪服务或清空旧记录。关闭会话只释放句柄；再次打开加载原 Task、许可、输入、执行记录及业务效果。未知效果和 TAKEOVER 会同时阻止同范围其他 API。错误命名空间不能把同一目标映射到另一权威。

Execution 的既有 Format 2 编码和上限没有修改；没有把既有 local 命名空间在线拆分或转换。旧 10/11 实际编码升级及 12 共享资源控制测试继续由全量回归验证。新的业务命名空间从创建时即固定，在线迁移和动态增加资源参与者仍不在本票范围。

## 验证证据

真实子进程中断覆盖导入事务中途、索引批次中途、版本门控内准入前、准入后及业务效果后。导入/重建使用实际存储循环、SQLite 事务和编码；子进程在已定位的取消检查点直接退出，不用模拟成功回执代替崩溃。重新打开后核验目录完整性、索引覆盖、准确执行记录和业务版本，重复恢复不得重复效果。

实施过程先验证 SDK 摘要/准确描述，再通过隐藏条目预算失败测试修正过滤顺序；模拟目标、完整目录 SDK 闭环和索引修复均经过失败到通过的定向循环。完整 profile、全量检查和双轴代码审查结果以本票最终归档证据为准；开发阶段中间通过不替代最终候选验证。

全量回归发现既有 RunCancel 在通知调用者后才释放执行槽位，紧接着的 Recover 核对可能错误地遇到 busy 并停在 WAITING。修复将槽位释放放到完成通知之前；原失败测试在修复后连续 60 次通过，未扩大重试或取消预算。
