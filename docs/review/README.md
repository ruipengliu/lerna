---

整体上建议保留现有事实归属、裁决域共置与 R7。当前更值得做的是统一“什么时候对象固定、什么时候取得行动资格、什么事件使资格失效”这三件事。R2-05 的准备后准入、R2-06 的具体前缀准入可以采用同一条原则：尚未确定的请求保留为候选；固定具体输入并完成当前检查之后，才成立不可变的动作责任。这比为每种模型、工具和批量计划分别增添例外更容易实现和验收。

建议修改顺序：先对齐命令身份与确认消费类型；再补输入接纳和核验轮次的失效规则；然后统一模型输入准备与有限计划绑定。上游契约改动后再同步模块流程和端到端场景，并用同一组并发、回执丢失与崩溃历史检查所有入口。无需因为这轮评审增加新的核心模块或第二套事实存储。

结论限于设计覆盖：分布式正确性的主要规则已经进入方案；生产接管协议与系统级故障验收尚未完成。现有并发、分区、时钟变化和恢复测试条目是验证要求，不能当作测试通过记录。无需为“支持分布式”拆开任务、会话、授权和预算；它们按用户共置，恰好减少了必须协调的边界。
