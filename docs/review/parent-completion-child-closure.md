# R4-02 父任务完成核验需要稳定的子任务收尾范围

| 日期 | 修订说明 |
| --- | --- |
| 2026-10-04 | 第四轮评审：复核祖先控制检查与父任务完成门禁的交界。 |

- 状态：评审建议，未采纳
- 优先级：P1
- 解决阶段：M4 开放内部委派之前
- 涉及：G2、G4、C5；任务编排、动作账本、出口闸门
- 基线：`0a21f22`

父任务核验已有“覆盖所有子任务后果”的要求，但没有给出稳定该范围的协议。建议 M4 先采用较小方案：全部直接子任务关闭且其递归收尾依据齐备后，父任务才进入完成核验。必要子任务还必须满足父任务要求的达成证据。

R3-03 已处理“父取消后、通知到达前，旧子动作开始”的问题。本项关注父任务正常完成时的范围稳定，不重复该意见。

## 2 事件顺序与推断

考虑父任务 P 和可选子任务 C。P 的必要条件已有证据，C 仍为 `OPEN / ACTIVE`。

| 顺序 | 事件 |
| --- | --- |
| 1 | P 开始核验；当前读到的 C 没有未收尾动作。 |
| 2 | P 固定自己的动作清单和子任务标识清单。 |
| 3 | C 基于自己的当前快照申请动作 A。P 仍为 `ACTIVE`，祖先控制代次未变。 |
| 4 | 若“祖先控制范围”只检查生命周期、控制和代次，A 可以准入并通过 P4；P 使用第 1 步的子任务视图作出成功判断。 |

**推断：**按上述解释，父核验漏掉了清单固定之后新增的子动作。即使成功事务再次读取 C，若没有同时封闭后续准入，也只是移动了竞争窗口。

还有另一种解释：父冻结自动阻止所有后代的目标准入。这样能挡住第 3 步，却产生另一条需要处置的路径：若必要子任务尚未完成，父核验等待子任务证据，子任务又因父冻结无法完成目标。4.7 没有为这种等待规定释放或推迟父核验的分支。

这两条是文档缺少具体协议导致的实现分歧，不是断言现有实现已经误报成功。上游 G2 已禁止漏掉后果；本项补的是满足该要求的状态转换。

## 3 具体修改方案

建议先约束父核验的开始条件，避免引入递归的冻结与解冻协议。

1. 父任务在进入 `VERIFYING` 前，必须确认所有直接子任务已关闭。未满足时登记等待子任务，保持允许其合法目标推进，不先持有完成冻结。
2. 每个子任务提供由任务编排持有的递归收尾依据：固定 Result、子任务关系范围、准确动作及交接集合、全部账本的 `SETTLED` 依据。孙任务等按同样规则汇总。单独的 Result 不够，因为失败或取消可以遗留未知。
3. 必要子任务按父条件的固定规则提供达成证据；可选子任务允许非成功关闭，但其后果仍须收尾。父核验不得自动把仍在运行的可选子任务视为“放弃”；需要停止时，另走明确的取消及收尾流程。
4. 父任务在同一裁决事务中检查子任务关系和收尾依据的修订，设置本轮冻结并禁止新增子任务。依据变化时拒绝提交成功，重新检查。
5. 普通子任务准入必须检查本任务及祖先是否已关闭。祖先非成功关闭后只允许有原责任来源的收尾；控制代次的比较继续用于挡住此前已准入的旧动作。

建议把“全部子任务关闭”作为 M4 的明确能力限制。以后确需父核验与运行中的子任务并行，再设计递归冻结、动作集合固定和解除协议，并验证活性；不提前把两套协议一起实现。

## 5 验收场景

- 可选子任务仍在运行且暂时没有动作，父任务提议完成：父任务必须等待，不得凭空清单成功。
- 必要子任务还需要一个目标动作：父等待不得冻结这个动作；子任务完成并收尾后父任务可以继续。
- 子任务已取消关闭，但有 `UNKNOWN / MAY_OCCUR` 动作：父任务不得成功；核对责任仍归原账本。
- 父核验与创建子任务并发：创建先成立则纳入前提检查；核验先成立则拒绝创建，不遗漏新子任务。
- 孙任务存在未收尾动作、子任务非成功关闭：父任务仍等待；重复或迟到的旧收尾依据不能覆盖新修订。

以上为设计反例和建议验收历史，尚未运行验证。
