# R4-01 释放冻结后，仍须阻止未确认封闭的旧动作与替代动作并行

| 日期 | 修订说明 |
| --- | --- |
| 2026-10-04 | 第四轮评审：核对 R3-02 简化方案中封闭尚未确认的窗口。 |

- 状态：评审建议，未采纳
- 优先级：P1
- 解决阶段：M1 开放核验拒绝后继续执行之前
- 涉及：G1、G4、G11；任务编排、动作账本、出口闸门
- 基线：`0a21f22`

建议保留“`REJECTED` 总是释放冻结”，同时把“旧清单尚未完成封闭”登记为独立等待。没有阻断性未知效果，不足以证明可以建立替代动作。尚未开始的旧动作可以处于 `NOT_APPLIED`，同时仍有合法的开始资格。

这不是要求恢复第三轮原意见中的“拒绝后继续持有冻结”。问题在于简化后的普通准入门禁没有承接封闭尚未确认的责任。

## 2 事件顺序与推断

按第三轮允许“不等待封闭确认就拒绝并继续”的解释，构造以下历史。授权和预算都足够，目标创建操作不幂等。

| 顺序 | 事件 |
| --- | --- |
| 1 | 动作 A 已准入并被账本接纳，尚未到 P4。账本中 A 为 `NOT_APPLIED`，派发仍开放。 |
| 2 | 推理过早提议完成。轮次 n 固定包含 A 的清单，发出封闭请求；请求在到达账本前被延迟。 |
| 3 | 核验发现目标对象尚不存在，轮次 n 被拒绝并释放冻结。A 还不是效果未知的动作。 |
| 4 | 新规划提交补建对象的动作 B。条件、输入和控制代次未变，B 通过现有普通准入检查。 |
| 5 | A 在封闭请求到达前通过 P4、P5，并完成创建。它的回报被延迟。B 随后也执行创建。 |
| 6 | 旧封闭请求和回报到达。下一轮虽然可以枚举 A、B，却已经无法阻止两次创建。 |

**推断：**仅检查当前效果是否未知，不能覆盖“当前未发送、以后仍可发送”的旧责任。下一轮动作覆盖只能发现问题，不能保护下一轮开始前的外部效果。

如果 4.7 的本意是所有封闭回执都到达后才能进入任何第二阶段分支，上述历史会被阻止。但这又与第三轮明确删除该前提的处理决定冲突。文档必须选择一种顺序，不能让实现自行猜测。

## 3 具体修改方案

建议由任务编排在现有等待事项中登记“等待旧清单封闭确认”，关联轮次、准确动作集合、各账本交接和缺少的回执。无需新增服务。

1. 开始核验时，固定清单并登记封闭待办及等待事项。`REJECTED` 仍在同一事务中释放冻结、保存缺口。
2. 允许新规划和必要的准备工作，但补齐该任务目标的新动作必须等待旧清单取得权威处置。M1 采用整份旧清单等待，不提前设计动作冲突分析。
3. 收到各账本封闭回执后，逐项区分：从未开放出口且已封闭；已经开始、仍需核对；已经收尾。缺回执、交接不明或仍可能产生相关效果时，不建立替代动作。
4. 任务编排必须把等待解除、检查原动作的最新收尾依据、允许后续准入按现有事务规则排序。通知只负责唤醒；恢复时查询原交接。
5. 等待独立于轮次终态。用户修改可以替代提议、处理新输入；旧封闭责任仍保留。旧回执只更新自己的等待项，不释放后来轮次的冻结。

只在 `REJECTED` 时递增控制代次不是完整替代方案：旧动作可能已通过 P4、尚未进入 P5。仍须确认执行端点的封闭结果，不能把控制变化当成未发送证明。

## 5 验收场景

- 延迟封闭请求，复现上表。冻结必须释放，但 B 不得在 A 的处置未明时开始；恢复原交接后可以继续。
- A 已过 P4、未到 P5时拒绝核验。分别让封闭和 P5 胜出，验证一个分支禁止发送，另一个保留原责任并阻止替代。
- 封闭已提交但回执丢失。查询原交接后解除对应等待，不重复动作、不重开派发。
- 等待期间接纳新输入，再收到旧轮次回执。新输入可处理；旧回执不得释放新轮次冻结。

以上是设计状态机推导，尚无运行缺陷或故障测试结果。
