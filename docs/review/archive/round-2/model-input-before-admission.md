# 模型输入准备与模型出口准入需要统一时序


模型调用的准入顺序在架构中有两种写法。建议采用“先准备并固定实际输入，再由核心准入并执行”的路线，并把准备过程的受控读取与模型出口分开。这样既保留推理的可替换性，也能兑现请求摘要、内容来源和预算依据的精确绑定。

---

定位：[任务编排 §3.2、§4.1](../../../architecture/core/tasks/README.md)将“请求提议”的成功定义为模型调用已准入，创建流程先准入模型、再登记推理请求。[推理接口 §3](../../../architecture/ports/reasoner/README.md)第 128 行的 `Propose` 接收核心已准入的模型句柄；第 135 行再次限制句柄只能调用已准入出口。但同篇 §4 第 161–163 行的顺序是：固定推理请求，工作者组装视图并执行 R4 检索，最后才准入模型。两种顺序不能同时作为完整执行协议。

反例：初始快照是 A，推理实现按 R4 合法检索到 B，再把 A+B 送给模型。若模型动作已按 A 准入，实际内容清单、请求摘要、外发目的和费用依据都可能发生变化。正确的出口检查会拒绝这次调用；如果实现为了跑通而让“已准入句柄”接受任意补充输入，则会把先准入变成一张范围不明的通行证。文本没有说明哪一个阶段冻结什么，因此两类实现都有可能出现。

---

修改方案：把一次提议请求拆成明确的准备与生成阶段，不增加新的事实负责方。

1. 任务编排持久登记提议请求、快照和规划代次，只授予准备所需的有限读取范围。此时没有模型发送资格，也不宣称模型动作已准入。
2. 推理的准备逻辑构造候选模型输入；宿主捕获全部实际读取，登记模型输入及来源，固定模型、参数、工具声明、输出上限、允许的协议转换和规范化摘要。需要嵌入或远程检索时，核心另行准入那些调用，不能藏在准备过程里。
3. 核心对这个确定的调用描述执行授权、内容、预算和任务版本检查，生成模型动作及出口凭据。费用上界不能证明时明确等待或拒绝。
4. 通过账本和出口闸门发送固定请求；结果登记为派生内容；推理解析并回报提议。重试、补充材料或换模型都是新的明确调用决定。

准备不代表可以无授权读取或保存。只能瞬时使用的原文按现有内容规则处理；没有保存许可就不为了恢复持久复制。崩溃后无法重建相同输入时，结束原准备并建立新准备代次，不修改旧动作的载荷。

---

接口有两种可行表达。M1 建议由可信默认实现提供显式 `PrepareModelInput` 和解析回报两个本地步骤，模型调用由核心执行；第三方推理接入时可以扩展为核心提供的受限请求接口。若继续保留单个 `Propose` 接口，其句柄必须被定义为“向核心提交一个具体模型调用、等待核心准入结果”的受控接口，不能同时称作已经获准发送的凭据。两种表达择一落实，所有阶段仍由现有持久工作、任务、内容、授权、预算与账本持有记录。

修改落点包括任务的“请求提议”成功语义、推理请求的阶段与 `model_operation_refs` 何时写入、`Propose` 参数、推理主流程，以及分层和整体方案中的首次模型调用时序。既有 R7、外部效果责任、费用记账都不需要改动。

---

AWS Step Functions 的[参数处理文档](https://docs.aws.amazon.com/step-functions/latest/dg/input-output-inputpath-params.html)明确区分输入筛选、参数构造和结果处理。它不是本项目的授权模型，但支持把“产生实际请求”单列为一个阶段，而不是把它隐藏在已获准的调用内部。本建议的安全判断来自本项目自己规定的固定载荷与逐次准入要求。

验收时让 R4 增加一项受限内容、改变模型视图长度，并在准备后撤销其中一个来源；模型出口必须在准入前看见完整输入，并在撤回后拒绝发送。分别在准备完成、准入提交、发送记录和回报提交后重启：最多恢复原动作，不重复预留或发送。再验证准备失败、输入不能持久保存、供应商状态引用失效的路径，确保它们有明确结束或等待状态。本轮没有运行模型或供应商调用，这些是待实现的验收历史。


定位复核补充：推理接口中 `Propose` 的接口行实际是第 **130** 行；“只能调用核心已准入的模型出口”的限制在第 **136** 行。真正说明“准备之后才准入”的流程仍是第 **161–163** 行。修改时需要同时对齐接口和流程，不能只移动示意步骤。

---

分层复核补充：准备阶段内部还需要分开“策略提出材料选择”和“受信宿主封存实际输入”。任务编排固定必要事实及版本，策略可建议排序、摘要和补读；受信宿主验证必需项没有被裁掉，捕获全部实际读取与固定配置，经受审查的供应商编码实现固定完整请求，再提交准入。不能只接受插件自报的一份输入摘要。

这可以作为任务编排与执行宿主之间的内部流程，不必新增顶层 ContextCompiler 服务，也不为推理另建一套有权裁决效果的 ModelCall 账本。物理模型请求继续是已有动作与尝试；模型输出的内容发布使用原发布身份恢复，不能因内容存储失败就重新生成。

增加两个接口验收：替换推理策略并故意遗漏未知动作，宿主必须拒绝封存；固定编码后让适配器追加 metadata、媒体或工具定义，出口必须拒绝与已准入描述不符的请求。只能瞬时处理的材料仍按保存许可处理，封存可验证描述不等于强制持久保存原文。
