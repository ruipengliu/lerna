# R4-05 从未开放出口的动作需要核心内部收尾证明

| 日期 | 修订说明 |
| --- | --- |
| 2026-10-04 | 第四轮评审：核对原始观察规则与未发送动作收尾的兼容性。 |

- 状态：评审建议，未采纳
- 优先级：P2
- 解决阶段：M1 账本收尾契约定稿之前；M4 开放第三方执行适配器前复验
- 涉及：G1–G3、G6；核心契约、动作账本、出口闸门、执行接口
- 基线：`0a21f22`

第三轮为外部终局证据建立了可信来源，但“强结论只能基于实际 I/O 原始观察”的规则写得过宽。从未开放出口就被封闭的动作没有外部观察，也不需要向目标查询。建议明确区分核心内部封闭证明与目标系统的终局证明。

## 1 文档事实

| 位置 | 已写规则 |
| --- | --- |
| [动作账本 2.1](../../../architecture/core/ledger/README.md#21-关键字段) | 效果证据字段要求：强结论 `NOT_APPLIED`、`RULED_OUT` 只能基于可信出口固定的原始观察，并由受信解释规则判定。 |
| [动作账本 2.3](../../../architecture/core/ledger/README.md#23-收尾依据) | 原始观察在实际 I/O 处登记；没有受信解释规则的能力按最保守处理。 |
| [动作账本 2.2、4.4](../../../architecture/core/ledger/README.md#44-取消与执行的竞争) | 封闭先于出口开放，且没有其他开放过的出口时，效果为 `NOT_APPLIED`，迟到可能性为 `RULED_OUT`。封闭还可以先于意图接纳。 |
| [核心契约 2.5](../../../architecture/core/contracts/README.md#25-状态模型) | 从未发送的动作可以直接 `SETTLED`。 |
| [预算 2.4](../../../architecture/core/budget/README.md#24-状态转换) | 账本证明出口没有发生且以后不会发生，才可释放未使用的预留。 |

下游的证据约束与既有内部封闭分支没有明确划界。R3-06 要防范的是插件伪造目标系统事实；它没有理由禁止账本证明自己从未开放出口。

## 2 事件顺序与推断

1. 动作 A 已准入、预算已预留。交接给账本后，工作者尚未开放出口。
2. 用户取消。账本通过条件写入先封闭 A，随后拒绝任何开始或发送请求。
3. A 从未访问目标，没有目标响应，也没有实际 I/O 原始观察。
4. 按 4.4，账本能生成 `NOT_APPLIED / RULED_OUT` 并收尾；按 2.1 的无例外措辞，这份强结论却缺少唯一被允许的证据种类。

**推断：**两条规则会导向不同的证据校验器。严格套用 2.1 会让合法的未发送动作无法收尾或释放预留；随意放开“适配器说没发”又会破坏第三轮的信任边界。需要的是可核验的内部证明类型，不是放宽插件权限。

## 3 具体修改方案

建议在账本的收尾依据中明确两条受信路径：

| 路径 | 证据与允许结论 |
| --- | --- |
| 核心内部封闭 | 原账本的完整尝试及发送记录、准确封闭范围、封闭修订、与出口开放竞争的结果。证明没有任何发送进入可能发送窗口，且旧工作者及迟到意图都不能再打开出口后，可以给出 `NOT_APPLIED / RULED_OUT`。 |
| 外部终局核验 | 至少一次发送可能发生时，按第三轮规则使用可信出口的原始观察和受信解释规则；不能用记录缺失、超时或插件声明代替。 |

核心内部封闭证明只能由原账本产生，并按 R7 交付。账本连续性无法证明、发送记录有缺口、P5 已成立或封闭竞争结果不明时，必须保持未知。

P4 已返回开始回执但 P5 尚未成立的情况，必须由执行端点持久确认封闭胜出，禁止该回执随后打开发送窗口。仅有裁决域取消记录不构成内部封闭证明。

对“封闭先到、意图后到”的情况，保存准确动作身份的封闭记录；迟到意图只接下责任，不获得执行资格。证明范围不能泛化为该任务未来所有动作，也不能由“查询时尚无记录”推导。

无需为未发生的 I/O 伪造原始观察，也无需为了证明未发送而额外发出一个外部查询。

## 5 验收场景

- 从未开始的动作被封闭：不调用目标即可收尾并释放未使用预留。
- 封闭先于意图接纳：迟到意图不得执行；重复交接返回同一责任和证明。
- P4 已成立、P5 与封闭竞争：只有封闭胜出且原账本确认时可走内部路径。
- P5 已成立但测试目标实际未收到请求：仍保持未知，不得以“观察到零请求”替代证明。
- 插件伪造“从未发送”的回报，或端点账本存在连续性缺口：拒绝内部强结论，原责任保留。

这是证据类型的文档冲突，不是已有运行死锁的报告。
