# R4-04 记忆替代必须区分旧记录比较与当前事实依赖

| 日期 | 修订说明 |
| --- | --- |
| 2026-10-04 | 第四轮评审：推演记忆修订检查对记忆更新自身的影响。 |

- 状态：评审建议，未采纳
- 优先级：P2
- 解决阶段：M2 开放记忆合并与纠正之前
- 涉及：C2、G8、G9；内容治理的记忆记录、记忆策略及默认实现
- 基线：`0a21f22`

当前修订检查必须继续保护旧答案和旧行动。但记忆更新需要读取旧条目作为比较对象。若这次读取也登记为“当前依据”，新修订会因替代旧修订而立即失效。建议用已有的“历史视图”表达明确的比较读取，并另外保存更新提交所需的预期修订。

## 2 事件顺序与推断

1. 记忆 M 的当前修订为 r1，值为“出差偏好直飞”。
2. 用户明确纠正为“出差优先高铁”。默认更新流程读取新输入及当前条目 M/r1，用于比较并生成 r2。
3. 宿主按普通当前检索路径登记依赖 `(M, r1, 当前依据)`。由于实际处理过 r1，不能直接省略该来源。
4. 核心核验预期修订 r1 后采纳 r2，M 的当前修订变为 r2。
5. 发布或读取 r2 时，联合检查发现其当前依据依赖 r1，而 M 当前已为 r2，因而拒绝。

**推断：**先发布再切换当前指针，只把拒绝推迟到下一次读取；先切换再发布，则发布当场被拒绝。两种顺序都不能解决依赖类型错误。若实现选择不读取旧条目的纠正短路径，可以避开该例，但默认设计仍明确支持读取旧条目比较的更新路径。

这与 R3-05 要阻断的“旧偏好继续参与订票”不同。修订 r1 在这里是被比较、被替代的旧记录，不能继续充当“现在仍然偏好直飞”的依据。

## 3 具体修改方案

建议区分两种检查，复用已有对象：

1. **更新提交检查。**核心为本次记忆更新工作固定目标 M、预期当前修订 r1、可信纠正输入和比较读取范围。提交时按预期修订竞争，r1 已变化则拒绝并重新准备。这项条件只保护本次更新提交，不作为 r2 永久的当前事实依赖。
2. **比较来源检查。**明确纠正工作中，被替代条目的比较读取由核心绑定为历史视图，固定系统记录视图和准确修订。它仍是完整的治理来源，继续约束授权、处理目的、删除和保存期限。
3. **新陈述依据检查。**新值必须有可信纠正输入或其他合格来源。其他真正作为当前事实使用的记忆，仍登记为当前依据，不得随比较读取一起降为历史视图。
4. **M2 的保守范围。**先支持明确纠正和可判定的替代路径。需要模型从旧值继续推导、无法区分比较与当前事实使用的合并，保留为候选或等待复查，不用“全部改标历史”强行发布。

如果一次计算先按当前依据读取 r1，之后才提出改为纠正工作，不得事后改写其依赖。核心必须建立具有明确比较用途的新工作，再按正确类型读取。这样既解决新修订自失效，也保留 R3-05 的防绕过规则。

## 5 验收场景

- r1 被明确纠正为 r2。r2 可作为当前依据交付；r1 派生的旧订票提议仍被拒绝。
- 两个工作都以 r1 为预期修订：至多一个采纳，其余返回冲突，不以历史读取绕过并发检查。
- 更新还依赖另一条记忆 N 的当前修订；N 在生成期间被纠正：发布仍必须拒绝。
- 删除作为比较来源的 r1 正文：依赖它的 r2 仍按治理关系停止使用，不能因历史类型逃避删除；需要保留新值时从允许的输入重新生成。
- 普通行动计算尝试自报历史比较、或事后改变依赖类型：核心拒绝。

本项是默认更新流程与修订检查之间的设计缺口，尚未用实现验证。
