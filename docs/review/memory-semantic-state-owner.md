# 记忆纠正的权威状态需要明确归属

第二轮 R2-09，建议 P2，在 M2 记忆写入与纠正接口定型前处理。现有方案正确地把算法与治理分开，但语义状态的接纳仍多次写成“核心发布”或“受控发布”。需要把当前有效的记忆版本、明确纠正、冲突和替代关系落实到一个命名的写入方，避免策略替换改变用户已经纠正过的事实。

---

定位：[记忆接口 §2.2、§2.4](../architecture/ports/memory/README.md)第 71、87 行定义替代关系与语义状态；§3 第 113 行规定用户纠正通过核心入口；§4.1 的 P6 和并发说明要求版本检查后发布。[默认记忆实现](../architecture/ports/memory/default.md)第 27 行将用户纠正写成新版本替代旧偏好，第 81 行要求条目及发布记录由核心原子维护。已有保护方向，不能说方案把这些权力交给了插件。

剩余问题是：[内容治理](../architecture/core/content/README.md)明确不判断真假，它提供的接口主要是内容版本、使用与清理；记忆策略只负责候选和排序。哪一个核心处理器维护“这个稳定记忆标识当前采纳哪一版”“旧断言是否退出当前检索”“哪些派生判断需要复查”，尚未像任务和动作那样明确。

反例：用户将“工作日愿意乘飞机”纠正为“工作日优先高铁”。旧偏好仍可合法保留用于历史查询，也没有被删除；旧偏好派生出的推荐规则仍在索引里。如果实现仅检查内容未撤回和有读取权限，就不能据此判断它是否还能参与当前个性化。内容治理合规、语义已经过时，是可以同时成立的两个状态。

---

修改方案：先在现有内容模块内部明确一个受信的记忆记录子模块，不新增独立数据库或远程服务。它维护稳定记忆身份、当前修订、适用区间、采纳依据、冲突／替代关系与需复查状态；内容治理继续维护准确内容、治理来源、用途和清理；策略只提出提取、合并、纠正候选及检索排序。

这里维护的是“系统按什么依据采纳了什么陈述”，并非核心自动证明世界事实。用户纠正自己的偏好可以形成明确替代；外部事实互相冲突时保留来源归因，不能一律以用户说法覆盖证据。

为已有记忆写入流程明确内部命令：接纳候选、按预期修订纠正、标记冲突或需复查、按有效时间查询当前／历史状态。删除和限制仍调用内容治理，避免第二套墓碑和清理协议。是否需要本人逐条确认由保存授权和风险策略决定，不把所有自动记忆更新改成手工批准。

一次纠正共同提交新条目版本、旧版的当前适用性变化、原命令回执、变化记录和派生影响待办。索引异步更新；交付端在返回前核验记忆语义修订与内容治理状态，旧索引不能继续把被替代的偏好当作当前偏好。明确依赖旧断言的派生项先阻止作为当前有效依据交付，后续按范围复查或重建；历史视图依然遵守当前读取许可。

策略替换只能重建投影和提出新候选，不能重置用户纠正、恢复被删除的身份，或把冲突条目悄悄变成确定事实。派生来源和历史证据仍按保留策略处理，不因“语义记录”获得无限保存权。

---

修改落点：layers 的事实归属表、内容治理的内部职责与接口、记忆接口的状态写入方、默认记忆的纠正流程，以及存储的记忆权威记录和投影关系。正文里的“核心登记”继续用于治理元数据；涉及当前语义状态时明确写成对应的记忆记录处理器。

验收至少覆盖：旧提取结果晚于本人纠正到达；纠正成功但索引仍落后；历史合法可读而当前检索必须排除旧偏好；派生推荐依赖被替代的断言；两个纠正并发；替换策略并重建索引；来源被删除后尝试恢复旧记忆。通过条件是原纠正与语义状态保持，不要求不同检索算法的排序完全一致。

这是把已有设计意图落实到具体 Module 和 Interface，不是要求恢复一个同时拥有字节、权限、账本和算法的“大记忆系统”。
