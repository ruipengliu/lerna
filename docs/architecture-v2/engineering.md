# 工程与验收：先贯通一条能恢复的任务链

[入口](README.md) · [协议](protocol.md) · [部署](deployment.md) · [未闭合边界](open-boundaries.md)

最早交付应让用户提交报告目标、获准保存文件、独立读回并看到完成依据；终止进程后仍能查询同一个任务和操作。这个切片会迫使公共事务、授权、内容和恢复机制真正配合，比先实现九个完整模块更能检验架构。

本章描述待实现工程。仓库当前的设计、Schema 和静态用例不等于已有数据库、设备或模型运行证据。

## 1. 仓库按稳定边界组织

采用单仓，Go 初期单 module；公开面收敛在 api、runtime 和 sdk/go，内部领域和存储布局不成为第三方扩展 API。TypeScript SDK 与 Web 在 pnpm workspace 分别构建，SDK 不依赖 React。

| 位置 | 责任 |
| --- | --- |
| api | 公开领域值类型与组件 ports，不导出数据库行或生成 Proto |
| runtime | 嵌入与装配入口，注入默认或替换组件 |
| sdk/go、sdk/ts | 原命令、查询、输入及恢复的客户端组合 |
| internal 的九个领域目录 | 按事实 owner 实现入口、规则、store port 与处理器 |
| internal/durable、host | 事务与工作模板；配置、时钟、容量和生命周期 |
| internal/wire、transport、storage、adapters | 严格协议、WSS／gRPC、两种数据库、内容及外部服务适配 |
| cmd、web、tests、dev、packaging | 运行入口、参考应用、验收、开发装配与制品 |

领域规则依赖 ports 和持久原语，存储及网络适配器由装配入口注入。同库需要共同裁决就显式传同一 Tx，目录分开不强制 RPC。逻辑记录按共同写入、查询、保留和竞争决定是否拆表，不为每个名词建立一套服务或状态机。

生成 DTO、方法映射和 SDK 类型来自同版机器契约，CI 检查重新生成无差异。生成器不足以表达的关联规则手写，但仍由同一契约校验；不能手改生成文件形成第二份定义。

## 2. 工程依赖与接入条件

以下沿用原工程选型，具体版本和平台组合在建立工程时经编译及运行测试固定，本次文档整理没有安装或验证依赖：

| 范围 | 既有选择及代价 |
| --- | --- |
| Go 宿主与内部 RPC | Go、net/http、grpc-go、官方 Protobuf；严格字段扫描仍需单独实现 |
| WSS 与 JSON | coder/websocket、严格 JSON 解析、jsonschema/v6；校验须发生在重复键或数字信息丢失前 |
| PostgreSQL | pgx/v5、sqlc、显式 SQL；实际锁序与执行计划可审查 |
| SQLite | modernc.org/sqlite、database/sql、独立 sqlc 查询；WAL、FULL、外键与单写队列分别验收 |
| 迁移 | goose，两种方言独立迁移；工具版本表不代替业务 migration_id 与恢复责任 |
| Web／浏览器 SDK | React、TypeScript、Vite、React Router；IndexedDB／idb 保存原提交 |
| 前端验证 | 严格解析后用 Ajv；Vitest、React Testing Library、Playwright 验证真实交互 |
| 观测与平台 | slog、OpenTelemetry；开发静态配置，生产适配公司平台 |

原工程文档的 Go 1.27、PostgreSQL 18 等是参考版本选择，不能据此宣称依赖组合已兼容。两种数据库共享领域规则，各自实现 SQL、迁移、领取和故障检查；SQLite 通过不能替代 PostgreSQL 多 worker 竞争证据。

模型已选火山方舟 OpenAI 兼容 Chat Completions，openai-go/v3 负责编码与传输；固定 profile、处理地点和凭据，明确关闭透明重试。一轮 Decision 至多一次发送，截断、拒绝或非法提案交回任务处理，不在适配器中偷偷修复再调用。可变模型别名和 SDK 兼容标签不证明版本、费用上界或原调用可查询。

搜索使用豆包 Custom 独立 WebSearch，正文另由获准 HTTP 获取。搜索结果是候选，不能把片段当作已读全文；异常、截断、时间和实际范围随内容保留。当前 profile 不启用模型内置联网工具，以维持逐行动准入和效果记录；额外交接成本由联网任务集衡量。

开发固定测试身份仅开放受限本机入口，生产发现 dev 身份即拒绝启动。生产身份适配器接公司认证，认证不代替 Grant 和确认。缺公司平台不阻塞本地切片；缺真实凭据则相应接入保留未验证，回放不冒充真实调用。

## 3. 四阶段交付，每步都有退出依据

| 切片 | 实际交付 | 退出依据 |
| --- | --- | --- |
| 1.1 契约与工程入口 | 公开端口、生成与严格校验、最小 CLI／SDK、首装路径 | Go／TS 复用同版正反例，非法原始编码不会先被宽松解码吞掉 |
| 1.2 持久基础与信任根 | PG／SQLite、Tx、Command、JobStore、时钟、报告导入和有限批准 | 真实数据库接纳、旧领取、完成竞争和提交未知；首装及重启不绕过批准 |
| 1.3 首条文件任务 | 固定回放或规则 Brain、目标条件、Grant、Content、受管文件和独立读回 | 丢答复、取消、撤权及进程退出后恢复原身份；原根丢失不换空目录 |
| 1.4 真实模型与费用 | 方舟适配、提案、用量、累计更正、交回 outbox | 无隐藏重试，未知调用保留成本责任，迟到账单在任务终态后仍入原账 |
| 1.5 Web 与本机多进程 | TS 持久恢复、Surface、预览输入；独立网关、应用、worker、执行宿主 | 刷新、断连、丢唤醒、内部重绑与两个以上进程竞争 |
| 2 专项任务与资源控制 | 联网取证、至少三台状态独立模拟手机、词法 Memory、API 广度与公平限额 | 真实来源、独立设备真值、接管与旧观察、来源关闭和固定质量集 |
| 3 替换与端云组合 | Brain／Memory／Executor 各第二种独立实现，至少一个异构语言组件；双向端云与协作 | 同契约互操作、未知效果、原安装组合恢复、离线时间与额度反例 |
| 4 改善与最终规模 | 完整评测、批准、逐目标发布、独立旧批准回退；最终质量和容量 | 冻结分母、正式证据资格、全成本，以及公司平台故障剩余容量 |

首轮不要求自动经验精炼、程序化 cell、动态发现、Session 分支或不可信插件。静态装配仍固定准确版本、当前批准和真实 ready。首装所需最小 Evaluation／Extensions 属于阶段一，不能推迟到阶段四才补信任根。

生产开放是独立门槛：冻结首发能力和负载，验证角色分工、当前身份、同步耐久、旧主隔离、内容介质、时钟、排空及剩余容量。较小首发负载不取消最终规模目标，也不能从本机多进程结果推导三可用区保证。

## 4. 用可数的主线约束复杂度

四类请求在固定输入、历史、回放与配置后量出真实代价：A 直接回答；B 读取一个文件后回答；C 冷恢复原工作；D 生成报告、保存并独立读回。原方案的特定回放基线中，A 为 1 个 Decision、0 个 Operation，B 为 2／1，D 为 3／2。C 的状态重建不新增模型或工具请求，必要核对和恢复后的合法续行另计；不能把 C 的全部成本填成零。

这些数字成立于受限目标模板和固定回放，不包含新增覆盖推理或其他未确定处理的工作，也不是数据库事务数量。D 的三轮是生成／保存、提出读回、读回后答复；改为有限 Plan 自动提出后续行动属于另一组实验，须另报实际 Decision 数。

应分别统计逻辑记录、SQL、事务提交、sync、字节、WAL 和实际物理 I/O。Brain 的四个持久阶段、Executor 的三个效果阶段是成功边界，不能直接称为四次或三次总存储开销。授权、费用、内容、领取、续租和清理都计入。

比较静态装配、有限 Plan、分层模型、上下文裁剪、记忆、Skill 发现、程序化工具及子 Agent 时，保持授权、独立效果和完成条件，记录全任务质量及总成本。省掉检查后测出的速度不证明同保证下改善。

## 5. 证据分层交付

静态 Schema、关联向量和图文检查回答结构是否一致；状态模型回答特定不变量能否维持；真实数据库、文件与进程实验回答提交与恢复是否实现；真实模型、设备和跨端测试回答适配效果；公司平台实验回答故障与规模。较低一层通过不替代上层。

最终质量目标是至少 1000 项语义不同 API、首次正确率 ≥90%、有冻结预算和有限重试下成功率 ≥95%，以及既定用户规模。按任务族、样本来源及独立单位报告，失败、未知、超限和取消依冻结口径保留；质量门槛与统计及改善门槛分别判定。

验收优先覆盖无法用 happy path 发现的缝隙：提交后丢答复、发送前后崩溃、旧 worker 迟到、新责任覆盖旧完成、条件全通过但漏目标、缺陷登记与完成竞争、取消先于执行到达、文件替换后退出、批准撤回与重开竞争、晚到账单和旧备份复活。
