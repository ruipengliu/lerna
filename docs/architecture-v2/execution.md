# 执行：让每次行动都有可以核对的身份

[入口](README.md) · [前一环：任务准入](task-control.md) · [授权与预算](authorization-and-budget.md)

保存报告和点击手机上的“创建提醒”，都可能在动作发生后丢失答复。Executor 的价值在于保留这两种可能：动作尚未发生，或者已经发生但本端还不知道。它把未知交还任务，同时继续寻找能绑定原动作的证据。

## 1. 固定要做什么，再决定这一次能否发送

Capability 描述业务语义、参数和结果 Schema、效果类别、查询与重复规则、权限及限额；Binding 把它绑定到准确的执行端、目标、驱动和配置。目录搜索只产生候选。真正准入时固定二者的准确版本，不能把同名工具当作可互换的实现。

所有会改变金额、收件人、正文、路径、筛选或用途的模板和 hook，都在 Orchestrator 准入前执行。准入保存最后意图、规范资源身份、原 Operation 和派发责任。Executor 收到 Invoke 后重验同一意图；驱动只做已声明的传输编码。需要改变业务参数时，回到原任务形成新候选，并处理旧操作的责任。

一次操作经过四个交接点：

| 交接点 | 保存的事实 | 此时能说什么 |
| --- | --- | --- |
| Orchestrator 准入 | 原操作、最终参数、绑定和派发 job | 任务允许尝试这一行动 |
| Executor 接纳 | 同一 Invoke、原回执、执行 job | 执行端已承担责任 |
| 实际发送 | Attempt、当前控制、许可、资源与期限检查 | 这一物理尝试获准进入目标入口 |
| 效果归并 | 原目标凭据、效果、用量和后续核对责任 | 已取得证据支持的效果事实 |

网络调用不放在数据库事务内。启动准备必须先落盘；准备后崩溃且无法证明未发送时，操作进入可能已发送的核对路径。Executor 的这个缝隙与 [Brain 的发送标记](brain.md)不同，不能共用一个“prepared 就能重发”的模板。驱动隐式重试须关闭或完整纳入物理尝试记录。

## 2. 执行结束和效果核清是两件事

`execution_state=closed` 表示不再发送目标动作，仍允许查询与收尾。`effect` 记录声明效果：`not_started`、`unknown`、`applied` 或 `not_applied`；`may_apply_later` 说明是否仍可能迟到生效。

例如提醒服务接收了创建请求，却没有返回。关闭本地发送过程不能清空服务端队列。只有能绑定原操作的目标凭据才支持 `applied`；只有确认没有发生且不会再发生，才支持 `not_applied` 且 `may_apply_later=false`。

| 效果类别 | 丢答复后的恢复 |
| --- | --- |
| `read_only` | 在剩余授权、期限和预算内有限重取；记录每次成本和实际取得的内容版本 |
| `target_idempotent` | 先查原操作；目标仍保证固定键、同意图和有效保留窗口时，才用原键重放 |
| `no_idempotency_guarantee` | 确证未生效且不会迟到，原操作仍允许执行时才可获准重试；否则只核对 |

HTTP 超时、5xx、取消请求以及暂时查不到，都不足以支持“未执行”。换 API、GUI、设备或驱动是新行动，Orchestrator 必须判断会不会重复原效果。补偿也需要新的操作和授权。

自动核对受次数、预算、退避和绝对期限约束。耗尽后保存未知与所需证据，停止频繁轮询，等待恢复事件或获准的一次核查。任务可以带未解决效果失败或取消；迟到事实和账务入口继续存在。用户可提供原目标回执，普通口头认可不能把未知外部效果变成已确认。

## 3. 控制必须到达实际入口

Executor 按 `(orchestrator_id, task_id)` 保存 TaskGate。它接受更高控制修订，较低修订不覆盖当前事实，同修订异内容冲突。任务终态不能被后来到达的运行快照复活。

实际发送须同时满足任务仍允许运行、目标修订匹配、无操作取消墓碑、控制和 Grant 窗口未过、原期限有效、资源占用与安装资格有效。Job 租约只说明谁可以回写工作进度，不能替代其中任何条件。

暂停与启动在执行端的持久入口串行裁决。暂停已经到达时，即使 worker 尚未读队列，也不能凭缓存继续发送；暂停还未传播到远端时，原有限启动窗口内仍可能发生动作。控制回执因此区分已保存、各入口已实施，以及原有在途动作。跨端即时停止不在承诺范围内。

同目标恢复可继续尚未启动的原操作，但不能重发未知写入。目标修订会封闭旧目标的未启动操作；旧目标已经发送的动作继续按原身份核对。刷新控制凭据使用新命令且重新检查当前决定，原命令查询不会延长窗口，也不延长 Operation 或 Grant 的期限。

取消可以早于 Invoke 到达。执行端为未知操作保存最小取消墓碑，使迟到 Invoke 也无法启动。任务终态、取消与命令去重的最小身份长期保留，完整正文可以按策略清理。查不到完整历史时返回 `gone`，不能据此重建可执行身份。

## 4. 第一种写驱动为何限定为受管目录

受管文件驱动把恢复问题限制在可以验证的范围内：一个租户专属根、一个受信文件 owner，OS 权限或隔离排除其他写者和硬链接别名。路径规范化为根内相对段；读写从根句柄逐段打开且不跟随符号链接，在实际入口核验句柄、文件身份与当前许可。无法兑现这些条件的目录不启用这套可恢复写保证。

保存报告时，原 Operation 固定路径、预期版本或不存在条件、来源 ContentRef、输入摘要和驱动版本。随后按同一路径排他执行：

1. 持久保存 journal，绑定操作、尝试、旧文件身份、目标摘要和临时文件名。
2. 在同目录独占创建临时文件，写完、校验并持久化；再把临时文件的实际身份写入 journal 并持久化。
3. 在文件 owner 的入口锁内复查控制、来源许可和目标预期版本，执行同文件系统原子替换，并持久化父目录。
4. 保存原效果和后续交付责任；在结果核清前保持路径独占和 journal。

单独一次 `rename` 没有版本比较。替换后进程退出，恢复者先隔离旧发送者，再检查原 journal、目标身份与摘要、目录持久状态。目标就是记录的临时文件才有依据确认原写入；只有字节相同并不足够。若目标仍是旧版本且旧发送者已不能再替换，才可确认未生效。旁路写入、身份不稳定或存储保证不足时保留未知并隔离后续写入。

读取也须从同一已打开句柄取得有界字节，核对前后身份、大小和摘要，避免把并发修改的混合字节当成一个版本。需要 ContentRef 时先在获准保存用途下提交实际字节，再返回引用。

这条链适合首个可验证驱动，代价是不能直接覆盖任意用户目录、网络盘或编辑器共同写入的目录。这些目标需要独立驱动合同和平台实验。

## 5. GUI 多了一项持续占用的责任

GUI 动作既依赖任务控制，也依赖设备资源代次和准确观察。观察需固定截图、前台窗口、焦点、视口和 UI 修订，并有有限有效期；动作前重新核验。截图读取与控制设备使用各自所需的授权，持有设备不自动允许披露画面。

设备 owner 为互斥域保存占用及 `control_epoch`，人工接管使旧控制失效。未知写动作还可能迟到时，资源保留在途写入口约束；一张新截图或 Job 租约到期都不能证明旧点击已经不会发生。只有覆盖原 Attempt 的可信停止或效果证据，才能允许可能冲突的后续写入。

本地设备由稳定资源身份和 OS 排他机制约束，不能用容器内部路径冒充整个宿主唯一性。恢复时先恢复旧发送者隔离与在途事实。没有目标侧隔离旧控制的能力时，不承诺跨宿主自动接替 GUI 控制。

## 6. API 数量之外，还要验证包装器的语义

导入 OpenAPI 生成结构只是接入起点。维护者还须补齐业务效果、幂等作用域、查询证据、权限、实际请求数及费用上限。路径、参数位置、单位、空值、分页和响应选择器由固定驱动解释；凭据在执行位置注入。网络范围检查必须约束实际连接、重定向和下载，不能只校验最初 URL 字符串。

能力结果须说明实际覆盖的页、筛选、字段、观察时间和截断。HTTP 成功、空列表或输出 Schema 合法，不能证明已经“搜全”或“没有结果”。任务验证使用这些具体范围判断证据是否足够。千级目录验收也应分别测量召回、选对、准入和实际效果，而非只统计方法名称。

## 7. 程序化工具是可选执行方式

第一条路径把有限脚本编译成已有 Plan 步骤，每步仍由原任务准入。交互代码单元则需要更强合同：父 Operation 固定代码、环境版本和输出；每次宿主调用以稳定调用位置和输入摘要映射到原 Task 的操作、Decision 或委派。没有这层恢复与准入合同，就只运行隔离的纯计算，不开放旁路工具 SDK。

代码环境默认无网络和秘密，显式限制根目录、CPU、内存、时长、宿主调用数与日志。取消关闭新调用，已有子操作继续核对；收到终止请求不等于实际进程已退出，因此物理容量不能立即释放。检查点只允许有界的声明式数据，不反序列化可执行对象。

复用环境可减少启动成本，但要单独保存环境身份、代次、配置、当前使用者和未终结调用。默认串行使用，独立域并行需另有证据；重启后的新实例不能被旧回调更新。公共 host-call、环境查看和销毁合同尚未冻结，属于[待决能力](open-boundaries.md)。

实现时优先保留少量领域入口：ExecutionStore 接纳原操作，GateStore 管控制，FactStore 合并效果，驱动负责准确目标入口与证据。工作领取和条件回写复用[持久工作框架](durable-work.md)，效果重试规则仍留在本模块。精确能力字段和驱动反例见[原执行契约](../architecture/.draft/execution/README.md)及[实现说明](../architecture/.draft/execution/implementation.md)。
