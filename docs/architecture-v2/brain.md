# Brain、固定输入与模型调用

[入口](README.md) · [任务控制](task-control.md) · [内容与记忆](content-and-memory.md)

Brain 的产出是一份可解释来源的下一步提案。它不拥有任务循环，也不直接执行模型建议的工具。Orchestrator 固定这轮输入和 Decision 身份，Brain 保存判断、可选模型调用、输出与费用，Orchestrator 再决定是否采用。

## 从已知阶段选择判断路径

Brain 共用输入检查、输出校验和恢复机制。S1 表示规则或固定答案类型的快速判断角色，S2 表示开放理解、综合与重规划角色，名称本身不保证速度或正确率。

Orchestrator 按任务阶段和固定 TaskPolicy 选定 ModelProfile，不额外用一次模型请求作路由分类。陌生阶段保留通用模型路径。

| 路径 | 适用条件 | 产出与失败处理 |
| --- | --- | --- |
| 确定性规则 | 已覆盖目标、全部约束、能力、绑定、事实适用性和动作限额 | 代码构造 Proposal，零模型请求；未覆盖可进入已选模型，规则冲突或无效产物等待策略修复 |
| 固定答案类型模型，可选 | 有准确有限候选、问题类型、阈值和映射，已通过适用评测 | 一次物理请求选择已有候选；答案不能直接证明效果或条件通过 |
| 通用模型 | 需要开放理解、冲突处理、正文综合或计划修订 | 至多一次物理请求；提案仍经 Orchestrator 准入 |

typed_decision 的不可变规格固定候选构造、Choice／Score／布尔等答案结构、模型、问题模板、阈值、并列规则、Proposal 映射和限额。候选身份进入实际输入，输出只能映射到本轮候选；confidence 仍是派生判断，阈值需要适用样本证据。

只有未发送的 unsupported 或结构合法但不满足接纳条件的拒判，才按固定策略允许一次定向升级。首次准入固定决策链根，同目标阶段的候选变化、补上下文、失败和重启沿用原链；新通用 Decision 及已消费升级额度共同保存。格式或版本错误走有限修复；权限、控制和依赖缺失交原负责方处理；结果未知沿原调用恢复。

已有计划的参数回填由代码完成，不为简单取值再造 S1 Decision。固定答案路径只有在适配、费用、恢复、升级和独立评测齐备后启用，普通开放理解不会默认被一项打分模型替代。

## 快照先保存事实，再选择材料

SnapshotAssembler 从 Task 的原目标、显式约束、当前控制和全部未结意图重建权威部分，再取得能力、证据和获准正文。摘要提供辅助材料，不能成为目标、权限、金额、收件人或原效果的唯一记录。

组装步骤为：固定依赖修订；读取原事实并记录投影水位和缺口；按用途取得准确字节；按策略选择近期事实、片段、摘要及历史；核算输入大小；在条件事务复查依赖，保存 Snapshot、Decision 身份、预留和派发责任。

默认先裁去无关历史、重复内容和低相关可选记忆，再缩短可裁证据片段。硬约束、当前控制、未知效果以及本轮使用的完整能力契约保留。必需输入放不下时返回 context_incomplete，而不是删掉关键限制后继续。

需要新摘要时，另准入有界处理；使用模型就建立独立 Decision，记录许可、成本和产物。摘要绑定准确来源、策略和覆盖范围。已经读取后才裁掉的材料仍属于实际处理来源；无法再取得的临时原文不能由模型猜补。

## 最后编码决定实际披露范围

ModelAdapter 完成包装指令、插件变换和诊断计划后，才固定可发送编码。核验范围包括 messages、工具声明、输出 Schema、图片或 URL、metadata、缓存路由字段和日志接收方。每项材料必须可关联到获准来源或受信固定配置。

实际处理来源与最终外发来源分别记录。输出继承本轮实际处理来源的限制交集，不只继承 Proposal 引用的 evidence_refs。例如模型读过本地限定资料，即使最终只列公开来源，也不能据此将输出任意发送到云端。

顺序是取得字节与来源、完成变换、核验用途和接收方、检查模型及传输大小、固定编码与摘要、取得使用回执、保存发送门禁，再从唯一出口发送同一编码。门禁后的 hook、SDK 和遥测不能另添材料或改接收方。凭据只在获准适配器注入，不成为模型上下文或普通日志。

禁止持久保存的材料只能走部署已验证的临时路径，最小记录仍需允许保存身份、摘要、用途和可能发送事实。最低记录也不获准时，该路径不能开放。具体时间和出口前提见[部署](deployment.md#clock-adapter)。

## 一次 Decision 的持久阶段

| 原阶段 | 已保存什么 | 中断后的继续方式 |
| --- | --- | --- |
| 接纳 | decision_id、准确输入摘要、配置与处理责任 | 读取原记录，同键异输入冲突 |
| ModelCall 准备 | 至多一个 model_call_id、固定请求依据及费用责任 | 没有 send_started 时，核验当前条件后可进行原首次发送 |
| send_started | 最终编码、用途与发送门禁，表明请求可能越过入口 | 查供应方原调用；不透明重发原物理请求 |
| 输出终态 | 原输出或错误、用量、正文发布关联及后续账务 | 查询原结果和原保存，不重新推理来补一次丢失的答复 |

这些阶段有真实时序依赖，准备与可能发送分别提交。阶段内部可合并本域事实和 Job 更新；阶段数量不能换算为 SQL 或 fsync 数量。

如果 send_started 已提交但实际没有发送，恢复也不能仅凭新进程的内存证明这一点。能查询供应方原请求时核对；不能查询时保留 provider_result_unknown 与费用责任。TaskPolicy 可以在剩余期限、预算与相应限制允许时准入新的 Decision，但那是新的可能计费调用，不是原调用免费重试。

本地并发槽在实际调用退出后释放；连接关闭不证明供应方已停止计算。远端物理并发、发起速率、费用上界、查询和取消能力各自声明。缺少供应方可核验停止或最终账单时，不从客户端状态推导这些保证。

## 提案与正文一起恢复

新正文以固定 publication 身份发布到 Content，保存准确引用后才放入 Proposal。字节已存而 content.put 答复丢失时，沿原上传与发布查询；保存失败时保留产物及合法恢复缺口，不能再调一次模型“生成同一份”。

输出经过严格格式、提案种类、版本和引用检查。非法结构可以在原累计额度内由新 Decision 修复，原调用和费用仍保留。行动绑定准确能力；有限计划检查版本、无环依赖和参数映射。模型的“成功”“批准”或工具调用文本都没有独立裁决效力。

ModelProfile 固定提供方模型、版本依据、处理位置、输入输出范围、价格与最大费用声明、超时及恢复能力。参考接入使用方舟兼容 Chat Completions 的适配路径，关闭 SDK 与代理隐藏重试；实际模型支持范围由工程验收确定。

## 哪些优化需要单独证明

压缩、固定答案路由、Skill 选材和经验提炼都可能减少某处 token，也可能增加读取、模型轮次和误判。比较要固定任务、候选、权限、模型和提示预算，记录完整质量、物理请求、时延、费用及恢复行为。没有净收益证据时保持可复现基线。

通用子问题委派和自动经验转流程仍有单独交付边界，不把可存储的配置当作已经具备的自治能力。已存在的有限计划和规则路径按自身验收使用。
