# 范围与建设目标

项目交付面向个人智能应用的开源 Harness、默认组件、SDK 和参考 CLI/Web，使用户提交自然语言目标后，在授权和预算内获得可解释结果。能力目标与实际交付证据分别管理，当前状态见 [review](review.md)。

## 功能范围

下列编号跟踪需求；各模块定义行为，验收文档固定判定方法。

| 编号 | 必需能力 | 负责模块 |
| --- | --- | --- |
| C1 | 理解目标、形成条件、规划、选择行动、补充信息、重规划和完成判断 | [编排](orchestrator.md)、[Brain](brain.md)、[验证](verification.md) |
| C2 | 事实／偏好／推断／经验记忆，来源时间范围，端侧提取，个性化、纠正、限制和删除 | [Memory](memory.md) |
| C3 | 可替换搜索和正文获取，实际来源与获取时间，冲突和证据缺口 | [执行](execution.md)、[Brain](brain.md) |
| C4 | API 优先，适用时 GUI；能力声明、观察、动作、反馈和后验核对 | [执行](execution.md) |
| C5 | 长任务、持久调度、期限、有限重试、暂停取消、跨端及委派恢复 | [编排](orchestrator.md)、[协作](collaboration.md) |
| C6 | 插件、Skill、内部／外部 Agent，可独立于任务存在的框架无关 UI | [扩展](extensions.md)、[交互](interaction.md) |
| C7 | 主体、资源、行动、用途、范围、期限和额度；预授权自动工作及撤权、接管 | [授权](authorization.md) |
| C8 | 跨端诊断、版本固定、质量／时延／成本计量、独立效果判断 | [评测](evaluation.md) |
| C9 | 获准经验形成候选，隔离比较，受信发布，分批启用及可核查回退 | [评测](evaluation.md)、[扩展](extensions.md) |

用户可拥有多个端点、任务和 Agent。长期保存、读取到上下文、处理、同步与披露是独立用途；摘要仍受来源限制。Plugin 提供组件代码，Skill 提供知识与流程，Agent 持有目标和循环，安装或加载不产生业务权限。

## 架构要求

三系统独立替换和端云可变位置通过同版契约证明，不能只用模型供应商替换或同实现换地址代替。

| 编号 | 约束 |
| --- | --- |
| A1 | Brain 提案、Memory 信息、Executor 效果和 Orchestrator 生命周期职责分开 |
| A2 | Brain、Memory、Executor 各有默认实现及可替换接口，替换不改变任务、权限和完成语义 |
| A3 | 三系统可分别本机或远端部署，任务 Orchestrator 固定；离线行为受已具备依赖和授权限制 |
| A4 | 输入输出、错误、权限、版本与恢复共同定义，独立实现用同套一致性与互操作验收 |

## 量化目标与专项

建设目标通过冻结样本和完整负载验证，计数口径只在[验收](validation/README.md)和[容量](capacity.md)定义。

| 目标 | 要求 |
| --- | --- |
| API 能力 | 至少 1000 项通过适用验收的不同语义业务操作 |
| 调用质量 | 首次正确率至少 90%，有限安全重试后任务成功率至少 95% |
| 最终服务规模 | 千万注册、百万日活、十万同时在线，并验证任务、写入、模型、内容和恢复负载 |
| V1 联网问答 | 实际取证、正确性、引用、时效、冲突与不足处理 |
| V2 手机 GUI | 至少三个独立有状态模拟设备，覆盖观察、点击、滑动、输入、返回、中断和接管 |

## 保证与限制

这些数字限定建设和验收范围，不能推导任意任务质量或真实设备平台支持。开放任务允许质量评估或用户验收，其依据强度由[验证](verification.md)定义。默认先交付内置与审核插件，不可信代码及真机平台在对应隔离和能力证据齐备后开放。

## 取舍

通用任务能力覆盖较广，代价是质量判断不能全部机械验证。业务需要更强客观保证时，可用固定 TaskPolicy 收紧目标类型与验证器范围。功能阶段决定建设顺序，不删减上述最终目标；退出条件见[工程方案](engineering.md)。
