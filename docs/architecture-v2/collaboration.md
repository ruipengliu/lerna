# 委派：增加执行者，保留一个父目标

[入口](README.md) · [任务推进](task-control.md) · [授权与预算](authorization-and-budget.md)

两个版本的资料调查可以并行委派，最终比较和保存仍属于父目标。Delegation 记录这次责任交接：交给谁、允许做什么、分配多少预算、子目标在哪里，以及结果与费用是否已经核清。

## 1. 先区分内部子任务和外部 Agent

同一 Orchestrator 内的子任务在本地事务中共同保存 Delegation、唯一 child Task、预算分配及首个 job。这时 delegate 的 `applied` 可以证明子任务已经建立。

外部 Agent 或另一个 Orchestrator 属于远端交接。父方先保存固定创建命令和唯一映射责任，`applied` 只证明本地已承担创建责任。远端须支持幂等接纳和按原身份查询，才可接收承诺恢复的副作用工作；缺少这项能力时，仅允许边界明确的有限咨询。

远端 Brain 不等于远端 Task。只把单轮推理部署到别处，不会转移原任务的裁决权。

## 2. 子目标与权限从父目标中收窄

委派固定子目标、Agent 配置、来源历史与准确安装组合。深度、活动子数和总预算都有上限，委派图不能形成循环。子权限取父方允许范围与 Agent 配置的交集，不能从子任务描述推导额外权限。

父方先预留 allocation，接收方在这份分配内记录实际消费。跨 Orchestrator 只用 strict 费用上限，即使父任务接受过本地 estimate 也不能继承该例外。子报告可用时先展示报告，费用未知则继续占用原分配。

子方终结后，父方消费准确报告修订一次。父方自己的完成条件仍要验证；两个子任务各自成功，不证明比较完整或最终报告已经保存。某一子方失联不阻塞其他可读结果，也不算该项成功。

## 3. 暂停与取消沿原映射到达子方

祖先暂停影响子目标的有效控制，不改写子任务自身控制意图。所有实际执行点分别确认；外部 Agent 不支持暂停时，必须显示它仍可能运行，不能用本地 phase 代替停止事实。

创建与取消在父方串行裁决。取消先于创建且能证明尚未发送时，不再创建；已经可能发送时，保存查询原创建结果及向原子目标传播控制的责任。父 Task 可以先终结，未停止的子动作和账务仍列入未决范围。

给子方补充答案绑定准确请求及版本，并保存唯一转交命令。普通回答不能扩大原目标或预算；需要扩大时走原控制与修订规则。旧目标的报告和取消不能影响后来独立建立的新目标。

## 4. 展示 phase 由原事实推导

Delegation 的便捷 phase 没有独立写入权。优先判断已有 Closure 则为 `closed`；存在需要核对的事实缺口则为 `reconciling`；已知唯一子映射为 `active`；否则为 `preparing`。

正常等待账单、例行查询或已确认暂停并不自动构成缺口。原 owner 不可达时返回不可确定，不能把查不到映射当作一个空委派。

SDK 可在原接口上组合读取、有界等待和有限批量读取。“有结果”“子目标终结”和“委派封闭”检查不同事实。客户端停止等待或 deadline 到达，仅释放本地等待资源；取消子目标需要独立业务命令。

## 5. 封闭之后，迟到账单仍归原委派

接收方提供可信关闭与用量证据后，父方才结算和释放未用 allocation。关闭不改写子任务发生过的效果；超出分配的可信费用须完整记录并处理违规，不能把账单截在上限。

后续更正费用沿原关闭证明和来源修订追加，接收方持久交回，父方重新读取并只归并累计差额。扫描既检查未封闭委派，也检查已 closed 但未交付的账务 outbox；按 phase 过滤全部工作会漏掉这部分责任。

冷恢复读取原委派映射、TaskPolicy、InstallLock 和行动绑定，再核对当前控制与资格。原组合失效时停止相关新行动，保留获准的原记录查询；没有安全查询实现则报具体缺口，不能换一个最新 Agent 重做来掩盖未知。

## 6. 复用子会话与并行收益都需另外证明

复用会话可以节省上下文和初始化成本。已有子 Task 未终结时，补充同目标继续原请求或修订；旧目标完成后再提出新目标，则先检查旧责任是否阻碍新行动，再建立新的 Delegation、Task 和 allocation。历史可以获准引用，旧一次性许可与预算不能继承。

默认每个复用子会话至多一个活动目标。通用 child.send／reuse、跨父复用与分支协作尚缺公共合同；不能只凭稳定会话 ID 宣称这些能力成立。关闭或归档子会话也不会删除原子任务的恢复责任。

是否委派由任务需要决定。评测应固定总成本，分别比较单 Agent、独立并行子目标和强顺序依赖任务，计入汇总、等待、失败与清理。只保留表现最好分支，或忽略汇总回合，会夸大并行收益。准确接口与冷恢复用例见[原协作契约](../architecture/.draft/collaboration/README.md)和[实现说明](../architecture/.draft/collaboration/implementation.md)。
