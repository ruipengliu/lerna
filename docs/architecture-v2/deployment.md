# 部署与恢复：让原责任换进程继续

[入口](README.md) · [持久工作](durable-work.md) · [工程与验收](engineering.md)

逻辑 owner 可以跨多次进程重启存在。部署的职责是找到它的原账本、隔离旧写者、恢复当前控制，再让健康进程继续；增加一个副本不会改变任务归属，也不会证明外部旧请求已经停止。

## 1. 开发单体与生产分工使用同一领域代码

开发先用一个进程、SQLite 和本地不可变内容库，再用本机 PostgreSQL 与多个进程验证交接。公司平台不是本地开发前置条件。

生产从首次上线就分开以下角色，复用公司已有的部署、发现、负载均衡、数据库、对象存储、密钥与观测能力：

| 角色 | 主要负载 | 扩展边界 |
| --- | --- | --- |
| 网关 | WSS、认证转交、有限队列和内部绑定 | 连接、内存、带宽及重连峰值 |
| 应用入口 | 命令、查询、当前准入和回执 | 原 owner 的数据库分片与短事务 |
| 工作池 | 决策、派发、核对、清理和发布 | 按类别隔离，控制与收尾保留容量 |
| 执行宿主 | 实际工具、文件根、设备与代码隔离 | 目标资源唯一性及旧发送者隔离 |

一个分片可承载多个 Orchestrator。新任务扩容通过受信映射把后续目标放到新负责方，旧任务和原去重记录仍留在原逻辑服务。整个存储分片可在停写、隔离旧写者、校验完整切点的维护窗口搬迁，本方案不承诺在线重分片。

用户来源目录在新归属或披露扩张生效前预登记，保证应用知道应查询哪些来源。它负责列表覆盖，不成为任务接纳的第二个裁决者。

## 2. 默认中间件只保存一套持久责任

业务、命令回执、jobs 和最小关闭身份在原 PostgreSQL 分片共同提交。worker 有限扫描到期索引，短事务领取；NOTIFY 由提交后的独立发送器发出，只加速唤醒。通知失败不回滚业务，监听恢复先 LISTEN 再补扫。

不先加入 MQ、Kafka 或 Redis 作为另一份工作真相。只有扫描、扇出或路由已成为实测瓶颈，才比较新增中间件的总成本；即使采用通知总线，也先让它定位原 job。替代持久 jobs 需要另行解决双系统提交与恢复。

内容和制品字节使用准确版本的耐久存储，元数据在原 owner。词法索引、显示汇总与缓存均可重建，不能裁决授权、余额或原命令是否接纳。当前身份、Grant 和关闭状态不能用任意 TTL 的 allowed 缓存替代。

生产连接池只连平台已确认写主。租户上下文每个事务设置并核验，不能继承前一个租户的 session 状态；LISTEN 等会话型用法与事务池分开。所有池、管理保留和监听连接共同计入数据库预算。

## 3. RPO=0 的范围与恢复前提

生产目标是单地域三个可用区，在单可用区故障下保留已确认账本，并在 60 秒内恢复原 Orchestrator 的控制与权威查询。参考配置让提交等待至少一个异区同步候选持久化 WAL。

这项保证要求数据库平台在提升前隔离旧主、证明选中候选包含全部已确认历史，并在重新开放同级写入前具有第二份耐久副本。无法证明就停止写入，不能为了 RTO 自动降为异步提交。应用不自行选主。

恢复顺序是：确认写权威与记录完整 → 恢复关闭、撤权、原回执和未决工作 → 开放控制与核对 → 检查内容及剩余容量 → 逐步接纳新任务。恢复不需要扫描所有历史或等待所有无关未知效果结束，而按活动索引和责任类别有界继续。

目标文件根是另一个故障域。首个受管根可以只有单区存储；它失联时多区应用仍可查询账本，但该根停止新写，原效果保持未知。ContentStore 的跨区副本不等于目标文件字节的跨区接管能力。后者另需证明句柄路径、原子替换、目录持久化、路径独占及旧写者隔离。

全地域故障默认走加密备份与连续历史恢复，不启用同一 Orchestrator 双地域可写。缺历史时只读诊断，不能重新启动旧备份中的任务、许可或设备动作。

## 4. 有限许可窗口需要平台执行机制

Grant、控制、批准及实例租约都依赖有限期限。ClockAdapter 提供可信 UTC 区间、覆盖允许暂停的经过时间和本机信任代次。部署必须证明以下三个量，而不是只提供一个“当前时间”函数：

| 参数或能力 | 为什么必要 |
| --- | --- |
| UTC 误差上界 ε 与样本有效期 | 接收方能保守判断签发方截止尚未到达 |
| 经过时间速率误差 ρ，覆盖允许的休眠／VM 暂停 | 停止的本地时钟不能把窗口无限延长 |
| 检查到实际发送／披露入口的最大间隔 κ | 线程不能检查通过后暂停很久，恢复即用旧许可发送 |

远端实际入口要求本地 UTC 上界加签发者 ε 与 κ 仍早于 start_before，同时满足原先固定的本地经过时间截止，取较早者。回拨、重复回执和较窄的新时间区间都不能延长原截止。

参考进程租约长度 L=15 秒、续约间隔 5 秒仅是待测初值。若数据库时钟误差为 ε_db，续约请求发起时本地读数 m₀，则本地最迟停止点不晚于：

```text
m₀ + (L − 2ε_db − κ) × (1−ρ)，其中括号必须为正
```

请求往返已经消耗窗口，不能从收到回复再计时；续约回复还须早于上次已承认截止。数据库在实际裁决时读取当前时间，不能用长事务开始时刻延长租约。

**尚缺的平台交付**是 κ 如何由实际入口执行，以及暂停／时钟变化如何在旧业务线程恢复前使信任代次失效。仅在后台线程醒来后检查，不能支持这个保证。本版保留所需性质和失败行为，不指定未经验证的内核或进程隔离实现；对应路径在取得平台证据前不能宣称成立。

主库提升若缺少时差证据，暂停相关租约续约与回收，隔离旧持有者，或在可信经过时间恢复后等待完整最大窗口及余量。先证明旧实例失效，再回收它的槽位；已关闭 boot 不能被迟到续约复活。这部分也计入 RTO。

## 5. 连接扩容与业务扩容分别计量

每条 WSS 固定一个逻辑服务。网关失效需要外部重连，应用失效主要需要内部流重绑，二者负载不同。在线登记绑定具体进程 boot、连接和绑定代次，旧清理必须条件匹配，不能删除新实例记录。

默认发现适配器取得平台实际实例地址，有限 LIST／watch 与缓存期限保证新分配有依据。短 Call 复用连接组，长 EndpointChannel 按后端剩余流槽使用有界池；服务端另检查全局流上限。发现新增副本只影响新调用和新流，已有长流靠轮换、排空或故障重绑迁移。

连接满额、身份核验失败或发现过期时有界失败，保留原业务查询。控制、回执交回和核对保留流槽及数据库连接，避免普通长流占满后无法停止它们。具体队列和重绑限额沿[协议](protocol.md)，不能靠默认 HTTP/2 行为推定容量。

## 6. 将用户规模展开为实际负载

最终目标包含千万注册、百万 DAU 和十万在线用户。原方案用于首轮容量建模的假设如下，均待实测：

| 假设 | 推导负载 |
| --- | --- |
| 百万 DAU，每人每天 5 个任务，峰均比 5 | 每日 500 万任务，平均约 57.9／秒，峰值约 290／秒 |
| 每任务 4 次模型调用，平均占用 8 秒 | 峰值约 1,160 次调用／秒、9,280 个模型在途 |
| 每任务至少 20 次业务提交 | 约 5,800 次提交／秒；领取、续租、授权和恢复另计 |
| 十万在线，每人 2 个会话／设备，各连接 1 个服务 | 20 万 WSS；30 秒心跳约 6,667 组／秒 |
| 每任务保存 200 KiB | 每日约 0.95 TiB 原始内容，副本、索引及截图另计 |

500 新任务／秒持续 15 分钟是另列压力场景，不是已兑现能力。它意味着至少 10,000 次业务提交／秒、45 万新任务，不能与包含查询的 API QPS 混用。

各池分别以实测单副本能力和失去一个可用区后的剩余容量决定副本数。恢复积压 B、持续到达 λ、可兑现处理 μ 只有在 μ>λ 时才可清空，约需 B/(μ−λ)。外部配额、数据库热键和设备占用分别测量，盲增 worker 可能加重瓶颈。

跨分片总配额先用受信保守份额，份额之和不得超过同单位总额。父子 allocation 不能代替独立任务之间的用户总额限制。估算模式仅限制新承诺，仍不保证实际支出硬上限。

## 7. 保留、备份与排空也是交付成本

最小命令去重、取消和终态身份长期增长。仅按每天 500 万任务，一年就约 18.25 亿任务身份，命令和操作另计；必须测索引、WAL、副本、备份及重建空间。时间分区清理不能删除最后的身份依据。

磁盘保护水位先停止新接纳，并为回执、控制和收尾预留实际空间。连取消决定都无法耐久保存时，只能报告不可用或未知，不能返回“取消已保存”。可先清理临时上传和无引用字节。

备份绑定数据库切点、内容版本、安装清单、关闭身份、放置与来源目录、授权权威集合及凭据恢复依据。旧备份恢复先核对后续关闭与撤回；目录完整性不足时列表保持 partial，并停止依赖它的新归属或披露扩张。SQLite 用在线备份或停写一致快照，不单独复制活动主库文件。

按角色排空：网关停新握手并分批关闭外连接；应用停新接纳并移交内部流；worker 停领取并保存下一责任；执行宿主停新发送并核对在途。超过退出期限可以结束进程，未知效果仍由原账本承担。迁移由独立管理动作取得互斥锁，不由所有副本启动时竞跑。

生产验收分别报告接纳、控制与查询可用性，初始目标各 ≥99.9%；同地域提交 p95≤300ms、p99≤1s；控制／核对领取等待 p99≤2s、普通推进 p95≤5s。接口超时后来查到已接纳，原接口样本仍失败，业务接纳事实另记。具体负载、故障前提和观测口径保留在[生产方案](../architecture/.draft/deployment-production.md)与[存储方案](../architecture/.draft/storage-and-middleware.md)，本版没有新增容量实测结论。
