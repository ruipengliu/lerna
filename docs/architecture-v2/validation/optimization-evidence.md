# 模块优化：预期效果、对照与验收

[架构入口](../README.md) · [系统验收](README.md) · [评测与发布](../evaluation/README.md) · [调研来源及原编号](../../research/ai-report-2026-09-project-implications.md)

2026 年 9 月 28 日确认采用九模块的 24 项优化方向。本页将其落实为建设与验证要求，完整行为规则仍在所属模块。目标是让完成声明有依据、长任务少丢约束、工具结果与实际效果可核对，并用同口径证据决定哪些策略值得启用。当前交付是方案修订；运行实现、真实故障实验和收益测量均未完成。

保留九模块事实归属、固定 Orchestrator，以及[开发与生产验收](README.md#5-建设顺序与退出条件)的边界：开发先验证本机多进程恢复，首次生产上线前另验公司平台的实际故障保证。新增内容复用内部记录、能力输出 Schema、受控内容及现有评测／发布流程；本轮不增加公开协议方法或自由字段。语义覆盖报告、能力专属输出、Skill 材料和实验配置仍须由实现者固定准确内容版本及接入测试，不能把本页概念表当成已发布 wire schema。

## 1. 采用范围与实施前提

采用范围分为三类：

| 类别 | 含义 |
| --- | --- |
| 落地 | 实现既有设计的默认行为，并取得运行证据 |
| 增补 | 规则已写入所属模块，仍需实现和验收 |
| 实验 | 采用验证方向，候选取得证据后才启用 |

确认方向不等于确认某种压缩算法、特定 Agent 数量或降低成本比例。P0 是首批完整任务流程及测量重点，P1 随基线和能力开放推进；隔离、授权、来源和恢复前提始终先于依赖它们的能力。

实施与实验须满足以下前提：

- 真实任务：具备权威存储、准入及原效果恢复能力。
- 成功提交：具备完整目标、目标覆盖核验和必要证据。
- 对照实验：具备独立真值、费用依据、数据用途和隔离环境。
- 改善发布：具备正式评测资格及批准。

缺少相应前提时，不启动依赖它的任务或对照，不提交依赖它的成功，也不将实验候选作为改善发布。既有未决操作、费用和清理责任继续由原 owner 保存与核对。

## 2. 预期效果与计分方式

以下为预期改善方向，不是当前测得的结果。安全与恢复反例要求全部适用用例满足契约且无必需 unknown；自然语言质量、选择和成本改善按冻结计划取得足够证据，不能把少量用例全过推广为任意任务可靠。项目 90% 首次调用、95% 有限重试成功率、1000 项语义 API 和最终容量继续单独验收。

| 效果 | 必须同时报告的指标 | 不允许的替代结论 |
| --- | --- | --- |
| 完成声明更可信 | 独立参考下的真实成功率；错误完成数／全部声明完成数；错误完成数／全部参考未满足数；覆盖漏项数与受影响任务数 | 自报完成增加不等于真实成功增加；两个错误率分别给分母 |
| 长任务更稳定 | 按长度／压缩次数分层的约束违例、来源或时间混淆、未知操作丢失、真实成功率及恢复一致性 | 单轮摘要更短不证明多轮更可靠 |
| 工具更可控 | 静默语义缺陷检出率、正常响应误报率、非预期重复效果数、核对时长与截止仍未知的比例 | 超时或空回读不能当成「确定未执行」 |
| 记忆更有效 | 同任务加入／纠正／禁用记忆前后的配对效果、错误经验采用率；停止新使用与逐持有者清理分别计时 | 记忆命中率升高不证明个性化改善，删除回执不证明全副本清除 |
| 总体效率更好 | 全部冻结样本费用／独立确认成功数，端到端时延分布，全部模型请求及 token，失败／返工／核对费用，建设维护与评测成本 | 不只统计成功样本的账单；不拼接双跑质量与单跑成本 |
| 接入与维护更容易 | 按同类变更记录接入工时、可定位失败比例、定位用时、回归检出及实际发布／恢复结果 | 写了诊断分类或有批准记录不证明缩短工时或实例 ready |

分母为零时指标标为不适用并展示计数，不填零错误率或零成功成本。

样本、相关组、未知和缺失证据保留原位置；若真值不足，相应质量结论为 inconclusive，不排除难例。

账单未结给已知费用、保留上界／未知部分及最终性，不能提前断言省费。错误拒绝按独立参考满足但被判 fail 的数／参考满足数报告，unknown 单列；验证器更换的敏感性按预先指定的第二判断分别给出，不择优取分。

更严格核验可能先降低表面成功率，并增加读取和评估费用。只要减少错误完成并满足预定质量验收条件，这与设计目标一致；是否值得付出代价，仍须按任务类别及用户目标比较。任何候选若收益不确定，保留原配置也是有效实验结论。

## 3. 贯穿场景与组合故障

基准场景为「取得指定版本的一手资料，比较指定维度，附来源，保存到授权位置并读回」。两臂使用相同完整目标、资料初始版本和独立环境，真值通道由评测维护者掌握。覆盖检查、报告质量、文件效果和读回分别判断；主观质量与客观效果采用各自规则。向下表注入故障时保留完整入口及原命令／对象标识，不能直接修改最终状态制造通过。

| 用例／前置与刺激 | 预期可观察结果及继续责任 |
| --- | --- |
| OPT-01：条件集合故意漏掉读回且已登记条件全 pass；覆盖评估准入后崩溃并重复领取；另测目标修订／缺陷登记与完成竞争 | 完整目标比对留下缺口，Orchestrator 不成功且持久唤醒补全；固定检查身份只关联一个原 Operation，核验不伪造 Decision，不绕过准入检查。补条件形成新 goal_revision，旧行动／报告不套用；缺陷先提交即阻止完成，成功记录固定准确覆盖版本；UI 展示同修订映射与限制。完整合法对照仍可完成 |
| OPT-02：长任务至少三次触发裁剪，穿插目标修订、相互冲突材料和原未知写入；最终编码额外增加包装长度 | 硬约束、当前 owner 事实、来源和原操作不丢；Brain 超窗不发送；新摘要作为独立有界工作计费。Orchestrator 保存输入缺口并继续原核对，不能靠清除未知腾出窗口 |
| OPT-03：大目录中放入同名不同提供方、虚构工具、旧 Schema、停用绑定和适用但未召回能力 | 实际解析与物理发送可查；错误成员不发送，合法固定绑定可在搜索不可达时按自身资格使用；Evaluation 分开统计召回、选择及准入，不把合理拒绝归成传输故障 |
| OPT-04：真实驱动漏页、忽略过滤、丢关键字段、返回旧缓存或零测试；也提供真正完整／合法空集对照 | 输出报告保留范围、时间和缺口；用目标独立真值检出静默错误；Orchestrator 不用部分材料证明完整要求，也不把合法空集一概判错。Executor 保留准确结果与原效果 |
| OPT-05：保存已生效但答复丢失，暂时读不到；远端子报成功却有晚到写；父取消并迟到账单 | 原 Executor／协作核对同一操作与子映射，未知期间不换 API／GUI／Agent 重做；Task 保持取消，UI 展示未确认停止和原核对入口；真实费用沿原来源追加。另以 GUI 旧点击滞留及 SDK 隐式重试检查物理次数 |
| OPT-06：同设备先关闭后打开、同范围偏好被明确纠正、同文不同来源、inference 与 fact 相似；查询 partial | Memory 保留时间、范围、性质与各来源，旧修订不作当前偏好；整理后仍可识别冲突和 partial。对同一准确引用的冗余命中允许去重，不能靠全部禁用记忆规避质量比较 |
| OPT-07：local_only 来源派生摘要、经验、索引、模型输出及 UI 缓存；关闭后丢通知、扫描重启、离线和旧备份恢复 | 相关 owner／holder 阻止新使用并恢复原清理责任；禁止云处理不被摘要解除；按既定窗口列出离线及物理残留。未确认持有者不显示全部删除，源原文自然到期与用户关闭来源分别验收 |
| OPT-08：网页／历史伪造授权、Skill 扩权、子 Agent 索取父权限；隔离平台通过 DNS、重定向、子进程访问受限目标 | 只有真实 Grant／消费记录产生资格；未许可动作在实际入口被阻止，合法范围仍能工作。实际凭据、文件、网络及资源隔离失败时关闭相应执行路径，由平台负责方修复 |
| OPT-09：请求版本与下载字节不同、展开后替换、依赖漂移、半包及重启；Skill 正例／负例／缺前提样本 | 安装锁定清单只对应核验过的真实产物，错误制品不 ready；实际加载版本可查。Brain 诊断区分不该触发、应触发但未加载、加载却无收益；无授权时 Skill 不形成越权 |
| OPT-10：计划前提失配、字段缺失、前项质量 fail／效果未知；新配置撤回，旧批准有效或失效两种分支 | Orchestrator 分别回 Brain、保留补证或核对责任，未知不重复；Extensions 只在旧版当前批准及兼容成立时恢复，否则停用并展示缺口。回退不清账本及旧费用 |
| OPT-11：单因素后组合实验；人为设置取消难例、重复来源跨数据子集、选择后泄露、重命名申请和未结账单 | Evaluation 保存全部逻辑样本、物理尝试、暴露及成本；不能重置分母或正式次数；被污染的证据不支持改善批准。合法开发／选择运行仍可产出探索结论 |
| OPT-12：分别植入理解遗漏、包装器丢字段、传输失答复、评分器误放行／误挡及 UI 夸大 | 诊断可定位已证实环节及未知部分，促成因素不被一个标签覆盖；评分用独立参考，不由被测模型自判真值；无正文权限时缺失明确，通用日志不存受限输入 |

以上新增组合用例与既有 SYS、模块故障实验共同运行。有限计划、来源关闭和安装更新不是替代原未知操作的入口；缺口必须有 owner、原命令／对象标识、继续条件及期限，不能只记录一句「人工处理」。允许的人工动作沿原受信入口补材料、补许可、提供可核验证据、修订目标或结束任务。

## 4. 候选实验与启用条件

每项实验先在固定模型及任务类别内比较；确需改变模型时作为另一因素单独记录。基线与候选均使用已经通过适用契约检查的授权、恢复和完成机制。对照的完整记录、独立环境和发布条件沿[Evaluation](../evaluation/README.md#component-comparison)，不另造实验服务。

| 编号 | 基线与候选 | 主要区分点／退化反例 |
| --- | --- | --- |
| X-01 上下文 | 规则裁剪 → 从获准原文抽取 → 独立获准摘要 | 长任务质量与完整费用；多轮压缩、时间冲突、目标修订、必要材料超窗；不把递归摘要当权威事实 |
| X-02 记忆 | 已提取经验 → 按当前任务读时整理；必要时另测按进展检索 | 个性化与错误经验使用、读取／存储／处理成本；原文到期、local_only、纠正与部分查询 |
| X-03 选择 | 准确目录＋现有规则／检索 → 限定 Skill 选择策略 | 召回、选对、加载时机和实际任务收益；正负触发、同名工具及依赖缺席；不预设新增路由模块 |
| X-04 规划 | 当前规则优先的 Brain 路径 → 同模型的提示或提案粒度调整 | 覆盖漏项、补证轮数、任务质量和全部成本；若包含固定答案类型判断，则独立报告模型替换因素和升级成本 |
| X-05 协作 | 单 Agent → 有限并行独立分支；强顺序任务另分层 | 总成功成本、端到端时延、重复工作和未决子责任；等待、汇总与清理不得从成本剔除 |
| X-06 计划 | 每步依据当前快照决策 → 已固定前提和退出规则的有限计划 | 稳定任务复用量与构建／维护／失配成本；环境变化、前项 fail、未知旧步骤及批准撤回 |

开始前必须固定任务总体、来源组、样本量、模型／提示及全部配置摘要、初始状态、主要收益指标、最小实用改善量、逐类退化界限、费用／延迟上限、停止规则和正式尝试预算。参数当前没有项目实测，实施时在看到该轮结果前冻结；未冻结则不能启动用于改善宣称的比较。安全契约一旦失败便不批准候选，其余不确定结果按 inconclusive 处理。

候选通过选择并冻结后，沿未暴露独立测试集的正式确认、受信批准及逐目标激活启用。只有相应任务类别采用该候选，未覆盖类别保持原配置。监测触发已冻结的退化边界时停止扩批，由配置负责方关闭后续新使用，Extensions 核验旧版独立批准及兼容性后回退；无法安全恢复旧版则停用并保留缺口。

配置回退用于之后的新任务；活动任务只可使用原清单／TaskPolicy 预定且当前合法的分支，否则等待或结束，不能因全局指针恢复旧版便在任务中混用策略。上下文例子见[压缩退化处理](../brain/implementation.md#context-optimization)。在途 Decision、Operation、委派和账单始终沿其原版本继续。

## 5. 建设顺序与退出证据

这是优化项在既有四阶段中的依赖顺序，不改变生产部署或容灾建设。

| 工作包 | 覆盖项与提供方 | 退出条件 |
| --- | --- | --- |
| A：最小可信闭环 | ORC-01、BRN-01、EXE-01～03、COL-01、UI-01／02、SEC-01、EXT-01、EVA-01／02；各原 owner 提供实际记录，Evaluation 提供独立真值 | 研究—比较—保存—读回可运行；OPT-01、03～05、08／09 的首批适用路径及 12 通过。需要的子委派先取证后启用；独立真值、费用和多副本恢复证据均可查 |
| B：长任务与材料 | ORC-02、MEM-01、EVA-03；Orchestrator 组装，Memory 保留语义，Brain 验最终输入 | OPT-02、06／07 及 X-01 形成同口径报告；默认裁剪满足契约，候选是否采用由结果决定 |
| C：选择性复用 | BRN-02／03、MEM-02、COL-02、ORC-03、EXT-02／03；各模块候选进入原 Evaluation 与发布流程 | X-02～06 分别给出收益／退化／不确定结论；选定候选有正式依据和实际激活／回退证据，未采用项保留基线 |

每个工作包交付实现／配置版本、静态契约结果、实际调用与目标证据、失败继续记录、独立质量结论及完整成本。文档完成、构造样例通过和运行验收分别登记；任一必需运行证据缺席仍是待实施，不能因方案已确认而标为能力已具备。
