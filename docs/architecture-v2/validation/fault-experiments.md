# 故障实验与独立断言

故障实验从真实命令入口驱动两端持久记录和目标系统，按原业务身份验证恢复；网络 ACK、构造 JSON 或最终 UI 文案不能代替目标真值。执行结果集中于 [review](../review.md)，判定口径归[验收规则](README.md)。

## 测试装配与固定屏障

实验分别使用真实 SQLite、PostgreSQL 和本机多进程装配；跨区、时间和隔离能力在实际平台重复对应实验。Agent 只能使用正常观察入口，测试控制器持有独立只读真值。

| 适配器 | 必需能力 |
| --- | --- |
| ProcessHarness | 强制退出、原数据重启、实际 boot 身份及租约观察 |
| StorageFaults | 提交前、提交后答复前、磁盘或存储写失败；不修改提交事实 |
| NetworkProxy | WSS/gRPC/HTTPS 延迟、丢答复、重复和分区，保留原字节与发送次数 |
| SimulatedTarget | 原动作日志、版本文件、独立手机状态与接管代次 |
| ClockHarness | UTC／经过时间变化、信任代次、主机／VM 暂停和主库换钟 |
| EvidenceReader | 原 command/task/operation/use/job 与目标真值、准确摘要 |

固定屏障为 before_commit、after_commit_before_reply、after_peer_reply_before_record，另加领取提交、实际不可撤回入口、before_finish。并发实验显式交换事务提交顺序，不用随机睡眠代替覆盖；没有到达预定断点的运行不能计通过。

每份报告记录 experiment_id、精确版本／配置／初始数据、授权预算、实际断点、原身份、两端修订、目标证据、费用及残留。运行前冻结阈值，禁止看到结果后补门槛。

## 系统行为矩阵

每项至少覆盖适用的三种提交屏障，分别读回接纳方、处理方与目标事实。编号用于复现定位，业务规则仍由链接模块唯一维护。

| 用例 | 刺激 | 必需断言 |
| --- | --- | --- |
| SYS-01 接纳 | 同 submit 并发，提交后失答复、重启；同键异摘要对照 | 唯一 Task／回执／首 job，冲突不覆盖，未提交不显示已接纳 |
| SYS-02 写入未知 | 文件真实写入后杀 Executor，重复原请求 | 原 operation 可核对，无第二次非预期写；无查询能力保持 unknown |
| SYS-03 取消迟效 | 原写可能发生时取消，再收到成功及费用 | Task 保持 cancelled，效果和费用继续归并，目标不重开 |
| SYS-04 完成依据 | 质量高分、未知设备效果、用户接受同时存在 | 验收不覆盖未知效果，必要条件按最弱合法依据汇总 |
| SYS-05 修订 | 模型和动作在途时改目标 | 旧建议不准入，原效果／费用继续核对 |
| SYS-06 输入 | 两端回答冲突，消费后丢 UI 回执 | 业务一次消费；失败端刷新，原命令可查 |
| SYS-07 单次授权 | 多行动竞争 once，使用答复丢失 | 只一个绑定动作消费，查原 use 不二次扣额 |
| SYS-08 离线撤权 | 本地全权威断网；远端 lease 撤回到期 | 本地独立任务继续；远端按窗口停止，不虚报全局即时撤回 |
| SYS-09 跨方预算 | allocation 已接纳失答复，子仍可能收费 | 预留不重复、不提前归还 |
| SYS-10 用途限制 | local_only 资料派生摘要再欲传云 | 原文和派生物出口均受限制，合法本地对照可运行 |
| SYS-11 删除恢复 | 关闭来源，端点离线，再从旧备份启动 | 新使用封闭，残留可查，缺关闭历史不重新开放 |
| SYS-12 个性化 | 加入、纠正、禁用同一偏好 | 行为变化有来源，失效依据不继续采用 |
| SYS-13 替换 | 三系统分别换实现及部署位置，断连重连 | 状态、权限、原身份和恢复一致，质量差异另报 |
| SYS-14 GUI 接管 | 观察后界面变更或用户接管，再发旧动作 | 旧版本／代次拒绝，已发生效果仍可查 |
| SYS-15 外部 Agent | 原创建成功失答复，父取消 | 同一远端任务映射；无原查询能力不开放有副作用委派 |
| SYS-16 版本切换 | 排空中有未知操作；新版退化、旧格式不兼容 | 未核清阻止切换；不可恢复时停用，账本不回滚 |
| SYS-17 过载 | 单租户洪峰、提供方超时、空间触保护水位 | 接纳／队列有界，其他租户与控制／收尾有份额 |
| SYS-18 开放目标 | 新能力有准确声明与效果契约，无专用任务流程 | 可规划和评估，完成依据不抬升为机械真值 |
| SYS-19 协议恢复 | 提示缺口、ACK 丢失、重绑、gRPC deadline、异摘要 | 原查询恢复，冲突不改事实，通道不裁决效果 |
| SYS-20 改善治理 | 多候选、反馈后修改、撤批准和离线节点 | 尝试历史保留，污染集无正式资格，逐节点状态可查 |
| SYS-21 祖先控制 | 子远端排队，父暂停后首次发送或重试 | 有效控制到入口后两种启动均封闭，父恢复不解除子自身暂停 |
| SYS-22 API 去重 | 同操作多版本、账号和包装 | 语义数量仅一项，支持矩阵单列 |
| SYS-23 指标分层 | 点估计达标但样本不足、相关重复或类别退化 | 比例／统计／改善分开，重复不增独立 n |
| SYS-24 费用边界 | 估算超额、提供方破单次上界、接收方超 allocation | 实际费用全额归并，原因可并存或待查，封闭受影响新计费 |
| SYS-25 暴露扇出 | 一暴露影响超过 100 项，分页中断后再启动 | 原暴露即时阻止新正式使用，唯一影响 job 完整恢复 |
| SYS-26 GUI 在途 | 旧点击留目标队列，释放短锁、取得新观察 | 原可信结束前无第二次自动写，接管不抹去旧效果 |
| SYS-27 目录竞态 | 新映射中并发开户／共享，目录或权威失联 | 预登记屏障成立，列表 partial 和缺口准确 |
| SYS-28 视图扩权 | 外部 Grant 对旧 Memory 扩权，无 Memory 变化 | 旧 pull 不称全集；重新 open 可发现，撤权仍逐页检查 |
| SYS-29 终态补账 | 原结算 done 后累计费用上调，丢回复并超过交回期限 | 持久交回、原来源主动查询、只追差额；特殊后继命令不重开任务或 use |
| SYS-30 生成正文 | content.put 已提交 Brain 未记账时重启；关闭来源／坏摘要／无许可 | 原草稿与上传恢复准确引用，不能重新生成掩盖未知 |
| SYS-31 条件先采纳 | 同提案改条件、行动、完成、计划，条件提交后失答复并暂停 | 仅一次新目标／控制修订，其余建议失效；相同条件不额外决策 |
| SYS-32 有限计划 | 生成→检查→写入，前操作未创建，重启及 pass/fail/unknown/错版本 | 唯一实例化，准确输出和全部 pass 才放行；depends_on 结束不替代质量 |
| SYS-33 旧批准回退 | 撤新版后分别测旧批准有效、撤回、失联、证据失效和格式不兼容 | 仅有效独立旧批准恢复，后续 use/reopen 仍核旧批准 |
| SYS-34 离线补账 | reconciled 后可信上调，报告未知期间再来账单，查询 applied/not_found/gone | 串行累计；仅过期且权威 not_found 可换报告命令；不重释余量或消费一次授权 |
| SYS-35 预览 | 下载失败、摘要不符、版本变更、取阅后撤权和直接调用 preview_refs | Renderer 准确呈现才开放；owner 独立核权限版本；引用不证明阅读 |
| SYS-36 唯一评测运行 | 同 plan 同／异 run 并发，分批恢复，再失去正式资格 | 一个逻辑 run、完整 sample/arm 分母，原环境尝试恢复，新启动封闭 |

## 关键竞态的执行方法

竞态实验必须给出互斥顺序和独立事实，以下步骤补充矩阵中不能只凭终态判断的场景。

### 接纳、效果与终态

先固定 submit 和候选字节，在 after_commit_before_reply 读取 Task、回执、预算和首 job 的同次提交，再退出进程。原库重启后并发查询／重投同请求，最后以异摘要对照，读取唯一约束与真实目标动作数。before_commit 分支确认没有半份接纳。

文件写入实验在目标已持久保存而 Executor 未记最终效果时退出。保持 Orchestrator 的原预留与 poll，提交取消并延迟传播，再恢复原 Executor 核对。断言任务终态、目标版本变化、费用和每项未决责任；无原查询驱动的正确结果可以是持续 unknown。

取消先到实验先保存尚未见过的 operation 墓碑，经过完整回执清理期后投原 Invoke 和新 command_id／同 operation_id。任务终结并合法合并局部索引后再次投递。全部启动被拒，原回执清理为 gone，同命令异输入冲突，最后取消依据始终存在。

### 证据与完成竞争

固定候选 A 及检查操作，分别在候选、准入、归并和 verify job 提交屏障退出，恢复同一检查。再固定 B 并让 A 的 pass 迟到；B 不能采用 A 的结论。目标修订、缺陷登记与完成分别交换提交顺序，比较原 ConditionResult、当前适用性、gate 和 Result。

普通退役只影响新检查，可信且命中范围的缺陷先提交则阻止活动任务完成，成功先提交则保留 Result 并另记缺陷说明。组合判断检查全部组成依赖，而非只查汇总器。评估运行失败、质量 fail、无结果、无实现和冲突分别设置，不合并成同一种失败。

### Memory 水位与内容发布

同一 Memory owner 的 T1 取得事务 head 后暂停，T2 修改另一对象；T2 应等待该 head，另一 owner 独立推进。分别让 T1 提交、回滚、退出，验证业务、变化项和 head 原子一致。索引应用后、checkpoint 前崩溃的重复应用不跳项。

view.open 在一致快照事务中固定集合及 head，页间产生新增、修改、删除、撤权和清理。初始集合加后续变化完整，分页不维持跨请求长事务，旧集合不延长披露。

跨库 content.copy 注册后分别关闭源、本地核对后再发布、先发布再核对。读取双方 copy、当前控制记录、Memory 引用和清理责任；关闭在接收端提交前可阻止发布，尚未查得远端关闭的分支按有限窗口收束，不声称跨库原子关闭。较低修订迟到不得重新允许使用。

### 绑定、目录与集合

B 产生 Delivery，A 持连接，关闭所有通知并退出 A；保持网关，让更高绑定先提交、低代及旧清理迟到。检查原 request_seq 至多一答复、外 connection_id／限额／高水位不变、没有第二个外 Ready、Reply 未持久 ACK 可重交。

首次订阅前就创建对象且客户端不知道 ID，随后注入内部重绑、窗口过期、缓冲满、页间变更和权限扩缩。六类集合均能从各自列表枚举，先取水位、建立缓冲、读完整快照、合并后续变化；缺口未覆盖不能宣称恢复完成。

新任务映射只登记一半时并发开户、共享和列表。再让 Task／Grant 恢复到 T2 而目录停在 T1，包含空预登记及另一个 Grant owner。缺少完整权威覆盖就只能 partial，不能仅枚举既有 Task 推定目录完整。

## 公共框架矩阵

FW 用例先分别验证两种真实数据库适配器，再覆盖每个领域实际物理映射；领域目标真值仍独立保留。

| 用例 | 刺激 | 必需断言 |
| --- | --- | --- |
| FW-01 接纳原子性 | 同原命令并发、提交前后退出、新命令指旧对象 | 一项业务责任，原键和业务键去重都成立 |
| FW-02 多阶段准备 | copy 登记后失答复，来源关闭或恢复发布 | 内部准备不冒充 applied／未登记 accepted，也不报 not_found |
| FW-03 领取接替 | W1 过期、W2 接替，旧返回及领取提交未知 | 旧受保护事务拒绝，无确认领取不执行，可信事实可独立归并 |
| FW-04 新责任竞争 | r+1 与旧 done／waiting 交换顺序，同事务再 Raise | 新责任 ready 且较早到期，Claim 观察值不刷新，不靠补扫修复正常丢工作 |
| FW-05 发送边界 | Brain 与 Executor 各在准备和实际入口退出 | 按各自证据恢复，Executor 不能借 Brain 无 send_started 的条件重发 |
| FW-06 停止与资源 | 断请求、停宿主、阻止外调用退出、关闭通知 | 已接纳工作仍可扫描；本地槽不提前释放，控制有容量 |
| FW-07 终态与清理 | done 后更高账单，合法清理后重建 job | 不重置原费用／尝试，重建用新 job_id，旧 Claim 拒绝，目标不重开 |
| FW-08 事务与隔离 | 过期 Tx、跨租户、嵌套提交、真实 expected_revision 冲突 | 非法句柄拒绝，领域冲突不自动改版本；同步终决和查询不造空 job |
| FW-09 成本 | 稳态、失答复、接替、全丢通知、历史增长 | 实测事务／请求／WAL／扫描和最老责任；分别给出恢复净余量 |

所有模块按其关键责任接入：Task/verify/settle、Decision/call/publication、Operation/attempt/control、Memory/copy/index、Grant/use/lease、Input/Surface 投影、委派、prepare/activation/reopen、sample/exposure/release。一个 JobStore 通过不能证明全部领域成功条件。

生产实验在冻结硬件、区间延迟、复制配置、实例数、数据分布、提供方配额和负载下执行。故障前后分别报告 p50/p95/p99、吞吐、拒绝、WAL、锁／池等待和最老责任。

| --- | --- | --- |
| PROD-01 单区 | 确认提交后隔离主区 | 旧主隔离、完整候选、第二耐久副本；原回执／费用／关闭完整，分段 RTO |
| PROD-02 旧 worker | 已可能发送的 W1 暂停，W2 接替后恢复 W1 | 旧代次不能提交，原效果查询，无重复非幂等作用 |
| PROD-03 洪峰 | 一租户十倍输入并持续提供方超时 | 其他租户、控制及收尾仍有份额，拒绝进入 SLO |
| PROD-04 集中重连 | 原在线规模断连，叠加查询／镜像 | 握手、快照、投递有界，先恢复当前控制 |
| PROD-05 字节故障 | 上传后未引用退出；库可用而内容不可读 | 孤儿清理、准确版本核对，缺字节阻止依赖步骤 |

| PROD-23 映射换版 | 原提交失答复后换映射又回退，份额失效 | 原任务可查，新目标未具份额拒绝，旧命令不转投 |
| PROD-24 聚合分页 | 同时间多源，页间新源／扩权／撤权、来源失联 | 稳定排序，旧游标明确失效，partial 准确，无全局快照宣称 |
| PROD-25 冷缓存 | 应用／网关／切网分别故障，叠加单区及旧槽 | 认证、额度、绑定、回执、快照放大可量化，回源有界 |
| PROD-26 满额发布 | 关旧 socket 后释放未知，新连接先到；强杀对照 | 正常主动条件释放，暂拒抖动重试，崩溃才租约回收 |
| PROD-27 压力 | 500 新任务／秒持续 15 分钟，四类负载 | 全部写入、WAL、锁／池、最老 job、下游限流和 μ−λ |
| PROD-28 目录发布 | 半预登记并发开户／共享，漏权威及旧备份 | 完整登记前不开放，恢复不足持续缺口 |
| PROD-29 真实超额 | 估算超额、两类违约、终态账单和交回过期 | 同来源修订只计差额，费用全保留，原因不混淆 |
| PROD-30 暴露扇出 | 超过单页影响，投影中断，新环境／样本／重试 | 原暴露同步挡新许可，原 job 分页全覆盖，在途窗口单列 |
| PROD-31 GUI 在途 | 旧写滞留，释放短锁并新观察／接管 | 未可信结束不再自动写，旧效果仍归原操作 |
| PROD-32 文件根 | 原根区失联，恢复账本但只有空根或未验共享盘 | 停该根新写、保持 unknown；经全部介质与隔离证明才跨区接管 |

时间实验观察最后出站帧、旧 boot、额度回收和绑定，而非只检查续约线程。新主时差超界时隔离或等待完整窗口及余量，过程计入 RTO。数据库提升不能以降低同步级别换通过。

容量另加载一年及更长规划期的最小终态记录、深宽任务树、大量历史效果和缺陷依赖；记录真实执行计划、扫描／返回比、锁、WAL、vacuum、备份与重建空间。完成核验不得按公开数组上限截断未结集合；分页以扫描键推进，不能因过滤后空页反复扫描原区间。

## 优化组合矩阵

基准目标为“取得指定版本资料、比较指定维度、附来源、保存并读回”，两臂使用独立同初始状态环境。X 对照与统计规则见[验收](README.md#优化对照)。

| 用例 | 注入与观察 |
| --- | --- |
| OPT-01 目标漏项 | 已登记条件全 pass 但漏读回；完整目标覆盖阻止错误完成，补条件新修订，UI 同版本呈现 |
| OPT-02 长上下文 | 至少三次裁剪，夹目标变化、冲突和未知写；硬约束不丢，最终编码超窗不发送，摘要计费 |
| OPT-03 能力语义 | 同名不同提供方、虚构工具、旧 Schema、停用和未召回；错误不发送，召回／选择／准入分开归因 |
| OPT-04 输出范围 | 漏页、忽略过滤、丢字段、旧缓存、零测试，加入合法空集对照；不把 partial 当完整证据 |
| OPT-05 交接效果 | 写成失答复、读暂不可见、子成功有晚写、父取消补账；不换 API／GUI／Agent 重做未知 |
| OPT-06 记忆冲突 | 先关后开、偏好纠正、同文异源、推断似事实、partial；保留时间范围性质与冲突 |
| OPT-07 来源收束 | local_only 派生多种缓存与副本后关闭，丢通知、离线和旧备份；逐 holder 停用及残留可查 |
| OPT-08 权限边界 | 网页／历史伪授权、Skill 扩权、子索父权限；DNS／重定向／子进程绕出口；合法对照不误挡 |
| OPT-09 制品材料 | 请求与下载不同、展开后替换、半包、依赖漂移；Skill 正负触发和缺前提；准确加载版本可核对 |
| OPT-10 计划回退 | 计划失配、前项 fail／unknown、旧批准有效／无效；对应重决策、补证或停用，不清旧账 |
| OPT-11 完整实验 | 删除难例、来源组跨集、选择后泄露、换申请及未结费用；分母／尝试不重置，污染不发布 |
| OPT-12 归因 | 理解漏项、包装丢字段、失答复、评分误放／误挡、UI 夸大分别注入；事实定位且保留未知 |

## 安装与评测的交接补充

安装和评测实验除了公共框架断言，还须直接观察真实制品、当前实例和隔离环境。

| 交错 | 必需观察 |
| --- | --- |
| 跨库 holder 预登记与 dispose | 先登记未发送 holder、再关闭引用入口；未知接纳保留引用，dispose 不按超时释放；反序时新引用拒绝 |
| 宿主猝死，旧 ready 行保留 | read/list 不回旧 ready=true；恢复同代际但取得新 reopen 依据，不重迁移 |
| 旧管理 worker 与停用／重开竞争 | 旧 Claim 不能重开入口或覆盖新责任，当前代际及实例逐派发检查 |
| 普通工作池满、受管组件未 ready | 独立有限管理池仍能诊断、停用和恢复 |
| 报告 A 正常反馈，来源组与未封存 B 重叠 | A 保持既有封存依据，B 新正式启动被原暴露门禁阻止，影响分页无截断 |
| 环境创建／样本启动许可与暴露竞争 | 共用来源组锁序裁决；先暴露不发新许可，已有有限许可单列在途窗口；实际提供方核验启动依据 |
| 两实验臂重启／重试 | 原 environment_key 唯一恢复、两臂环境独立，物理尝试不新增 sample/arm 分母 |
| 样本和影响扫描旧 worker 返回 | 原记录和后继责任保留，过期 Claim 不完成新批次，不提前宣称目标全部停用 |

## 保证与限制

测试结论只覆盖达到的故障点、平台和冻结配置。隔离负例必须操作真实文件、凭据、网络及进程边界；构造一个拒绝记录不能证明平台隔离。共用框架、领域状态、真实效果、统计质量和最终容量分别出具证据。
