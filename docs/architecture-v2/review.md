## 1. 设计基线与独立阅读

方案保留 C1–C9、A1–A4、联网问答 V1、模拟手机 V2，以及 API 数量、调用质量和最终服务规模目标。建设顺序从本地完整闭环开始，再取得替换、端云、改进与容量证据；分阶段交付不等于降低最终目标。

独立读者未取得设计讨论历史，仅依据本目录、目标要求和仓库文档规范复述主线并推演异常。复述得到的关键分工如下：

- Task Home 保存目标、控制、预算和完成决定；大脑提供绑定输入快照的提案，执行端保存实际启动与效果事实。
- 同宿主以短事务共同保存决定与后续工作；远端通过原命令回执、查询和持久交接恢复。网络响应、模型结论及界面提示均不能单独证明外部效果。
- 每任务固定 Home，共享资源由其 owner 裁决。失联时不自动接管同一任务；离线使用远端权限与额度必须预先划定窗口和范围。
- 开放任务可以采用质量评估或用户验收，但必要外部效果必须核清。取消终止新的目标工作，既有操作的效果与费用仍须收尾。

正常链路覆盖目标接纳、获准取证、报告生成、版本化保存、模拟手机操作及完成发布。异常链路重点推演写入答复丢失、取消后效果迟到、目标修订、用户验收竞争、远端控制乱序和批准撤回；逐项检查发起者、裁决者、持久事实、成功边界与恢复责任。

## 2. 发现与修正

| 发现 | 已落实的规则 | 复核范围 |
| --- | --- | --- |
| 远端执行端缺少完整的控制传播与启动门禁，取消可能先于执行请求到达 | 增加持久 TaskGate、Home 控制快照、修订单调检查和取消墓碑；原命令重放不延长启动窗口，终态不能重开 | [执行设计](execution.md)的暂停、恢复、旧目标和取消先到场景；E-09 至 E-11 |
| 父任务暂停可能遗漏已在远端排队的子操作 | 子任务自身控制意图与对外有效控制分开；祖先改变时，同事务更新后代控制修订和传播责任。父恢复不能解除子自身暂停 | [任务运行](task-runtime.md)、[协作](collaboration.md)及 SYS-21；首次发送和安全重试都检查有效门禁 |
| 用户验收的运行时权威接口未同步请求版本与一次消费约束 | 验收绑定 request、request_revision、候选摘要及 goal_revision；消费、验收决定和后续验证工作同事务保存 | [交互](interaction.md)与[任务运行](task-runtime.md)；旧候选、并发回答和答复丢失 |
| 零离线窗口被误用于在线批准，导致在线激活可能立即失效 | 在线 ApprovalUse 使用独立的有限 start_before；离线继续另需显式非零租约。重放保持原截止时间，已知撤回立即阻止新使用 | [评测](evaluation.md)与[扩展](extensions.md)；EV-09、EV-10 及激活、继续运行、撤回竞争 |
| 跨模块错误名称不一致，使调用方恢复动作不确定 | 统一公共 forbidden、dependency_unavailable、gone 等错误；领域错误沿共同结构声明下一步动作 | [共同契约](contracts.md)及调用方错误表 |

上述问题均已修改相关正文、接口和用例，并经语义复核。剩余依赖是实现与运行证据，不再以未定义的控制行为或未说明的成功边界留给实现者猜测。

## 4. 可复现入口与后续证据

从仓库根目录执行示例检查：

```sh
python3 -m pip install -r docs/architecture-v2/validation/requirements.txt
python3 docs/architecture-v2/validation/validate.py
```

校验器同时检查 JSON Schema 和跨字段关系。示例中的内容引用为构造数据，检查通过不证明实际正文存在、权限有效或外部动作已经发生。完整 wire schema、SDK、默认组件和互操作套件属于参考实现交付。
