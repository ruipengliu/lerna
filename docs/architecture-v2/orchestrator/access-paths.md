# Orchestrator 访问路径与有界查询

[实现与事务](implementation.md) · [验证生命周期](verification.md) · [存储与中间件](../storage-and-middleware.md) · [运行验证计划](../validation/fault-experiments.md#storage-access)

本页供存储实现和性能评审使用，说明接纳、推进、完成及收尾分别读取哪些权威记录、在哪个事务提交，以及怎样限制访问范围。先确认有限边界，再查阅八条访问路径，最后按完成核验与性能实验检查实现。

实现复用 PostgreSQL 本地事务、持久 jobs 和当前投影。完整字段与唯一约束见[持久对象](implementation.md#data-flow)；表的数量本身不决定查询成本。下文的批次表示逻辑读写集合，不是已测得的 SQL 次数。具体 DDL、SQL、执行计划和容量结果均待实现验证。

准入、完成、控制、去重和费用归并使用权威事务。正文按准确 ContentRef 在事务外取得，事务内只比较固定引用、修订及当前资格；外部查询与调用不占持锁时间。展示投影可以由副本或缓存提供，但不能据其「没有记录」裁决没有未决责任。

## 1. 有限边界与计量单位

下列符号只用于描述实现配置，不增加线协议字段。装配在开放相关新工作前给出有限值，结合任务容量与故障剩余容量校准；未配置或无法兑现边界时，不接纳依赖该能力的新工作。已有未结记录不得截断或删除，原责任保留，恢复工作按有限批次继续。

| 符号 | 含义及已有约束 | 耗尽后的行为 |
| --- | --- | --- |
| `R`、`U` | 当前目标条件数、任务计价单位数；公开 Schema 分别最多 100 | 拒绝越界输入，不能截断条件或费用单位 |
| `A`、`T` | 准入需核对的祖先数、一次控制影响的活动子树规模；初始委派深度为 4，活跃子数为 8，具体口径归[资源上限](../deployment-production.md#56-初始资源上限与改选-mq-的边界) | 新子创建须同时满足深度、活跃子数、用户及事务容量限制；不得把原子控制拆成漏覆盖的分页提交 |
| `L_action`、`L_fact` | 一轮准入行动数、一次归并事实数 | 拆为后续有限轮次；每项保持原行动或事实标识 |
| `L_check`、`L_delegation`、`L_effect` | 一个任务当前需核验的检查记录（含当前目标覆盖报告及组合检查全部有界依赖）、未结受管委派和未决效果数 | 新准入不超出可处理集合；已存在的超界或不完整集合阻止成功提交，保留核对责任 |
| `L_defect` | 一次核验所选准确实现／规则命中的缺陷记录处理预算 | 缺陷登记照常保存；核验读不全则保留缺口，不能截断后采用旧 pass |
| `L_executor` | 一项任务已绑定、需要控制传播的执行端数 | 新绑定前检查容量；已有逐端责任不能因分页或列表裁剪遗漏 |
| `L_scan`、`L_page` | 每轮应用层候选扫描上限、每批返回／处理上限，`L_page ≤ L_scan` | 保存最后扫描键并让出调度份额；列表可不足一页，核验不能把一页结束当作全部通过 |
| `L_query_ms`、`L_bytes` | 单次数据库查询期限、事务外输入读取字节预算 | 查询中断则本次判断未完成；保留原 job，有限退避，不以超时证明无记录 |

`Task.open_effects` 等公开数组的 100 项限制是消息结构约束，不能证明底层责任已经列全。内部投影必须覆盖完整未结集合。消息无法承载时，应在接纳前限制新增责任，不能先截断再宣称已核清。

活跃子数上限也不限制一项长期任务曾创建的历史子任务总数。因此，公开数组和活跃子数上限都不能证明历史扫描成本有界。

`L_scan` 限制应用消费的候选条目，不限制数据库实际扫描行数。索引页、被过滤行、旧行版本及锁跳过都可能增加实际工作，单靠 `LIMIT` 不能证明查询成本有界。

数据库查询还须设置有限期限。运行报告分别记录候选数、实际扫描行数、返回数、锁行数和字节量，并通过执行计划及负载实验检查成本是否随历史增长而放大。

## 2. 八条访问路径

所有键均含 `tenant_id`，表中省略这一共同前缀。表名是参考实现的逻辑映射；未结效果和子委派投影的持久责任归[实现篇](implementation.md)。同库关联使用明确的主键集合、半连接或分组后关联，不能将多个一对多明细直接联成大乘积。

| 路径 | 权威对象与关联键 | 逻辑读写批次及关联方式 | 所需键或索引访问条件 |
| --- | --- | --- | --- |
| 接纳 | `command_receipts`／`closed_identities` 按原服务及命令；策略接受事实按主体与准确策略；新 `tasks`、`task_requirements`、`budget_balances`、`jobs` 按 task_id | 原命令标识查重 1 组→当前资格与容量 1 组→Task、条件、预算、首 job、回执共同写入 1 组。重复命令直接返回原结果 | 命令去重与终态索引唯一键；接受事实准确键；任务、条件、单位与作业记录唯一键 |
| 候选准入 | `tasks` 祖先链、准确快照／计划；`decision_consumptions`、`plan_step_admissions` 或受信核验原检查；`operation_intents`、预留、绑定和 jobs | 任务及固定依赖 1 组→候选消费与预算 1 组→本轮意图、预留和派发责任共同写入 1 组。三类候选身份互斥，每项沿原键准入 | task_id／父链；decision_id、计划步骤键或原核验检查键；operation_id、计费绑定、作业记录唯一键 |
| 事实归并 | `received_facts` 按 `(owner, object_id, revision)`；原 intent／委派、`condition_checks`、当前效果投影、预留与 Task | 来源和关联对象 1 组→当前投影及费用累计值 1 组→新事实、适用性、差额、Task 修订与后续 job 共同写入 1 组；批内按来源键归组，不逐项回查全历史 | 来源修订唯一键；原 operation／delegation 映射；`(task_id, goal_revision, requirement_id)` 的当前检查访问；原计费来源绑定 |
| 完成核验 | `tasks` 当前 goal_revision；`task_goal_coverage` 当前修订；`task_requirements` 与当前所选 `condition_checks`；`evaluator_evidence_gates`／`evidence_defects`；未结子委派／效果投影；`task_results` | 任务、目标及当前覆盖记录 1 组→所选覆盖／条件实现门禁及命中缺陷 1 组→条件、子委派、效果分别 1 组集合读取→固定 Result、终态及收尾责任共同写入 1 组；条件先按准确版本及原缺陷核验再汇总，各集合分别判断 | `(task_id, goal_revision)` 的当前 coverage_revision；`(task_id, goal_revision, requirement_id)` 的当前 check_id 关联；准确 evaluator_ref 的 gate；按实现／规则及影响范围筛选缺陷；父 task_id 下的未结委派与未决效果；task_id 的唯一 Result |
| 控制传播 | `tasks` 父链及受影响活动子树、`task_executor_bindings`、逐端控制与 jobs | 祖先／子树 1 组→受影响任务的端绑定 1 组→有效控制修订与逐端责任共同写入 1 组；从真实父链取集合，不采信请求提供的祖先清单 | 父任务下活动子任务访问；`(task_id, executor_id)` 唯一绑定；控制作业记录键 |
| jobs 领取与恢复 | `jobs` 活跃状态、due_at、稳定 job_id；未决领域对象与其 `(task_id, kind, object_id)` 作业记录 | 领取为到期候选 1 组＋条件更新 1 组，随即提交；恢复每页领域对象 1 组＋作业记录集合核对 1 组＋缺失作业记录补建 1 组；不逐对象单独查作业记录 | 数据库分片／工作类别／可领取状态、due_at、稳定键的活跃访问；作业记录唯一键；各领域未结状态及分页键 |
| 列表查询 | `tasks` 按 Orchestrator、created_at、task_id；共享查询记录及当前披露资格 | 候选页 1 组→资格核验 1 组→返回至多一页。具备批量接口的权威按集合核验；只有逐对象接口时，调用次数受扫描与调用预算约束并单独计量，不假设存在批量 RPC | `(orchestrator, created_at, task_id)`；查询身份／主体／过滤摘要绑定。其他过滤是否需索引由真实查询分布和计划决定 |
| 账务结算 | 原 `budget_reservations`／`budget_allocations`、`budget_balances`、来源费用修订、correction intent／outbox、incident、jobs | 事务外取得原来源当前账单→原绑定与余额 1 组→累计差额、来源修订、事故及后续责任共同写入 1 组。每次结算一个原计费项或 allocation，不跨来源相加后丢失身份 | reservation／allocation 唯一键、原计费来源绑定、`(allocation_id, usage_revision)`、task_id／unit 余额键及作业记录键 |

这些键说明必须能定位什么，不等于已经提供物理索引 DDL。实现须为每行登记实际 SQL 数、往返次数、查询计划、索引及触发行数；应用层循环若使同库查询数随对象数逐项增长，应先合并为集合读取。外部逐对象核验保留其真实调用成本，不能借「集合处理」隐藏网络放大。

| 路径 | 返回／处理集合上界 | 事务、锁范围与热点 |
| --- | --- | --- |
| 接纳 | 单任务、`R` 条条件、`U` 个单位及有限首责任；原命令去重记录与终态记录均为点查 | 1 次接纳事务；原命令、容量记录、新任务及预算／作业记录。同原命令并发串行，容量计数可能成为租户热点 |
| 候选准入 | `A` 个祖先、`L_action` 个候选；每候选涉及不超过任务 `U` 单位及已声明的有限依赖 | 1 次准入事务；祖先→余额→意图／门禁→作业记录。同 Task、祖先和余额是串行点 |
| 事实归并 | `L_fact` 项来源事实及其有限关联；新增作业记录数受该批关联对象上界约束 | 1 次归并事务；按既定锁序更新 Task、预算、投影及作业记录。不同来源写同一 Task 仍会竞争 |
| 完成核验 | `R` 条当前条件、至多 `L_check` 条当前核验记录及其不同实现 gate、`L_defect` 条命中缺陷、`L_delegation` 项未结委派和 `L_effect` 项未决效果 | 1 次完成事务；Task→实现 gates 的共享读锁→条件及其余领域行→后续作业记录。缺少完整性依据或超界时不提交成功；高频缺陷登记对热门实现的锁等待须单独测量 |
| 控制传播 | `A` 个祖先、`T` 项受影响活动任务，每任务至多 `L_executor` 项绑定及对应责任 | 1 次控制事务；根到叶、同层稳定 task_id，业务行后锁作业记录。锁与写入放大随 `T × L_executor` 增长，须在新子创建／绑定前兑现容量 |
| jobs 领取与恢复 | 每轮候选至多 `L_scan`，返回／处理至多 `L_page`；恢复各领域有独立有限页及稳定前进键 | 领取事务只锁 job；回写另起领域事务，最后锁作业记录。恢复不能持领取锁再反向锁祖先；同热作业记录竞争及跳过锁的成本单列 |
| 列表查询 | 候选至多 `L_scan`，返回至多 `L_page`，包括已删除／撤权项在内的最后扫描键决定前进位置 | 有界只读查询，不长期锁任务；每页及披露前核验资格。大租户、过滤低命中和跨来源查询分别计成本 |
| 账务结算 | 一个原计费项／allocation，最多 `U` 个单位；证据正文受 `L_bytes` 约束 | 原命令／祖先→余额→allocation／原来源及关联行→作业记录；跨 owner 各有本地提交，不存在跨库事务。同 Task 单位余额和父 allocation 为热点 |

全局锁顺序以[实现篇锁定顺序](implementation.md#21-锁定顺序)为准，表中只强调各路径的范围。查询期限触发、锁等待超限或事务回滚后，原命令身份及 expected_revision 不改变；数据库重试不重复事务外调用。

## 3. 完成核验不遍历历史

完成核验先点查当前目标的覆盖记录及其输入摘要、缺口和实现门禁，再读取当前条件及适用检查；覆盖报告属于 L_check 总预算，不遍历历史覆盖修订。随后引用准确成果、规则、评估实现和证据；旧目标、旧候选与已失去适用性的检查留作历史。检查结果的生成、失效和后续责任按[验证生命周期](verification.md)处理。一次评分通过不能使未知效果、证据冲突或未满足的客观条件消失。

未结效果和子委派集合的完整性来自领域事务：操作／子委派接纳时登记，事实归并时更新，只有对应效果或目标责任已核清时才移出；相关 Task 修订与后续 job 同时保存。已终结子任务仍有未知效果时，其原委派或效果责任继续留在集合中。纯账务未结可以继续结算，不被错误归为目标未完成。

最终事务锁定 Task 并复核这些当前集合。新建子任务、准入行动及对该任务当前条件或效果的归并，与同一 Task 门禁串行，防止「读到没有未决项」后又插入一项。投影只有在完整覆盖已提交责任时才能作为空集合证明；迁移、重建或状态核对发现覆盖缺口时，保存 verify／恢复责任，补齐前不能发布成功。异步展示缓存不具备这个证明效力。

可信缺陷的登记先于任务投影生效。登记事务独占锁定准确实现的 evidence gate，共同提交原缺陷与分页影响责任，不锁整批 Task。

完成事务先锁 Task，再按稳定实现键为所选 gates 取得共享读锁，直接读取命中准确规则／范围的原缺陷。不同任务的读锁兼容，但登记与完成互斥；不能只相信尚未被影响工作更新的 applicability。

缺陷先提交时，命中证据不再支持完成。完成先提交时，原 Result 保持不变，后续通过 `result_evidence_notices` 关联说明。缺陷查询无法完成或范围无法确定时，保留 unknown。本地门禁仅覆盖本地事务范围内已受信登记的缺陷；远端未交回缺陷的限制见[核验持久化](implementation.md#condition-storage)。

历史子任务只在审计或有界恢复时分页读取。完成热路径按当前未结集合检查内部子是否终结、外部目标是否封闭、效果是否核清；已结项的终态保留记录独立保存。不得在每次 verify 中重新扫描全部历史子任务、全部 received_facts，或逐子查询后再逐操作读取形成 N+1。也不得仅为减少联表把条件、委派和效果拼成一个多重关联结果；分别取得有界集合并按原对象标识核验即可。

## 4. 从访问设计取得性能证据

先实现上述访问路径并测量，再决定是否增加索引、调整数据库分片或表分区、合表或增加其他投影。当前没有目标规模的执行计划和压测结果。扩大内部树会增加祖先控制及完成事务成本；先按现有有限容量接纳，不能仅增加进程后承诺同任务热点消失。

[访问路径实验](../validation/fault-experiments.md#storage-access)要求固定八条路径的 SQL 与配置，覆盖普通与大任务树、单任务热点、租户倾斜、历史关闭身份增长、低命中列表、恢复积压及单区故障。基线 290 新任务／秒与额外 500／秒场景沿[公共容量假设](../deployment-production.md#capacity)，不得把查询 QPS 混作任务到达率。验收同时检查事务不变量、延迟与吞吐、扫描／写入放大、WAL、维护和恢复成本；静态文档检查不替代运行证据。
