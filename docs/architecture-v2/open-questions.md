# 待决问题

本页只列需要补充选择或冻结契约的缺口，不把已确认的限制改写为新的要求。相关分支保持所属文档的保守行为，不能由实现者静默新增协议或增强保证。

## 需要明确的设计接口

每项选择都应连同影响的方法、状态机、示例和验收更新；问题关闭前不据未定义接口声明互操作。

| 编号 | 缺口与影响 | 可选处理及决定前行为 |
| --- | --- | --- |
| Q-01 Memory 恢复 active | [Memory](memory.md) 的 needs_review／disabled 可在新依据下恢复，但公开方法只有 create、replace、restrict、delete，缺少明确恢复入口 | 明确现有 replace 是否承担审核与恢复，或增加受信管理动作及协议。索引／重启不得自行复活记录 |
| Q-02 候选材料格式 | [Memory](memory.md) 的候选正文、覆盖／支撑检查及可选索引缺口，需要精确内容格式、解析器版本与正反例 | 作为能力版本固定内部格式，或在确需互操作时扩充协议；不向封闭 JSON 信封添加自由字段 |
| Q-03 激活意图的竞争裁决 | [扩展切换](extensions.md#排空与提交)已区分意图接纳与活动代际提交，但未明确跨越排空阶段的竞争占用事实。仅锁接纳事务的目标行，不能阻止两个意图随后都被接纳 | 选择接纳时保存排他占用并定义释放／接管条件，或允许多个意图接纳、在代际提交时裁决；同时冻结冲突如何通过原回执或 Activation 呈现。决定前只保留“同一旧代际至多一个切换成功”，不承诺接纳即取得唯一切换资格 |

## 有需求或实验依据后再选择

以下方向有明确成本，当前不引入额外公共协议。它们不阻塞已定义分支的实现。

| 方向 | 重新评审的触发条件 |
| --- | --- |
| 跨域缺陷与历史说明 | 当前本域 gate 只串行已受信导入的缺陷；高保证远端用途缺当前契约时不启用。若向第三方开放，冻结可信查询、传播范围／时效及独立 notice 的访问权限，不能借安装批准推导 |
| 跨域估算接受证明 | 当前仅受信本地事务内核验 TaskPolicyRegistry；第三方登记、撤回和接受证明需另定，allocation 与 OfflineLease 保持 strict-only |
| 通用 S2→S1 子问题委派 | 当前只用受信固定阶段；需另定有限模板、规格版本、输入／候选绑定、派生答案及完成依据，不隐藏在 instruction 或 assumptions |
| 自动退款／贷记 | 当前累计更正只上调，退款另行对账；自动化须定义可审计负向事件及父子传播，不能降低累计量冒充现有更正 |
| 历史 as-of／区间 Memory 查询 | 真实任务需要结构化时间语义；当前保留时间及来源，不承诺任意时点全集 |
| 远端付费嵌入、生成式重排、多跳关系 | 当前词法／本地有界编码器无法满足冻结质量目标，且净收益覆盖调用、治理和维护成本 |
| 经验自动转 Skill 或有限计划 | 需要明确候选格式、独立比较、受信发布及计划前提／退出，材料引用本身不产生流程资格 |
| 默认生产使用反馈采集 | 明确保存许可、准确加载版本和独立结果关联后再设计；离线实验不自动授权采集用户行为 |
| 远端离线授权跨重启 | 有防回退存储、可信时间和实例独占证据后扩展；当前窗口不因重启续期 |
| 镜像独立离线读取 | 需要接入有限离线副本的明确产品场景和验收；基础镜像按原 owner 在线读取裁决 |

受信 Renderer 的预览边界、跨库内容关闭的有限窗口、Memory 视图需重新 open 才覆盖外部扩权、固定任务 Orchestrator、单故障域文件根均是已确认选择，分别见所属模块「保证与限制」。它们不在本页重新请求批准。
