# 能力评测的统计与版本比较：事实核对

访问日期：2026-09-09。对应问题：核实能力评测的统计与比较方法。

范围：核对二值结果的统计区间、千级 API 的分组采样、候选与基线比较以及保留集复用风险。本文仅做资料研究；未运行模型评测、统计仿真或样本量计算，也未选择评测平台及 Go 统计库。

项目已确定超过 1000 项不同业务 API、首次调用正确率至少 90%、有界任务成功率至少 95%。本文不改变这些目标，不把统计置信度、每 API 门槛、重试额度或样本数补写成已获接受的要求。

## 1. 二项比例区间有采样假设

**来源事实。** NIST 的原始研究明确：固定成功概率下，独立、二值的重复试验成功数服从二项分布。对某批观察结果计算出比例，尚不足以证明该批结果符合这个模型。[NIST：Pass-Fail Testing: Statistical Requirements and Interpretations](https://nvlpubs.nist.gov/nistpubs/jres/114/3/v114.n03.a05.pdf)

NIST 给出 Wilson 比例区间，并说明失败数或样本量很小时普通对称正态近似可能不准确，可考虑基于二项分布的精确区间。换成“精确”算法仍然没有消除二项采样假设。[NIST：Confidence intervals](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)

**项目推论与候选方法。**

- 先声明估计对象：当前固定用例集的得分、固定 API 目录下新任务的表现，或更广泛的 API 总体表现。三者不是同一个统计对象。
- 对来自预定同一任务分布、可合理视为独立的二值试验，可报告成功数、分母、Wilson 区间及所用置信水平；需要保守的小样本二项区间时可选精确方法。区间水平、一侧或两侧及方法应在看结果前固定。
- 固定配额覆盖不同 API 时，各 API 的成功概率可不同，整体不应直接当成同一参数的独立二项样本。若每次独立地从固定混合分布抽取 API 和任务，则可能形成同一边际成功概率的试验；这仍需具体采样机制支持。
- 同一模板的改写、同一业务状态派生任务、连续共享记忆的会话、共用故障时间窗都可能相关；修改随机种子本身不证明独立。
- 置信区间反映所声明采样机制的不确定性，不能证明用例覆盖充分、裁判正确、生产分布一致或逐 API 全部达标。有限用例集上的确定性得分可直接报告；没有可辩护的随机采样模型时应标注推断不适用。

“点估计达到 90% / 95%”与“指定置信水平的单侧下界也达到对应目标”是不同验收规则。后一条通常更严格，是待对齐的发布政策，不能由研究报告暗中替换已有目标。

## 2. 千级 API 覆盖与聚合应分别记录

以下为本项目的指标设计候选，公式是定义，不是文献为 Harness 验证的效果结论。

设固定目录有 K 项不同业务 API，API i 的有效测试数为 n_i，成功数为 s_i：

| 汇总 | 定义 | 回答的问题与局限 |
| --- | --- | --- |
| 逐 API 覆盖 | 每项 API 的 n_i、模板族数、状态类别、错误分类 | 是否实际测到该项；很少样本不构成精确质量证明。 |
| 微平均 | 全部 s_i 之和 / 全部 n_i 之和 | 此用例构成下每个测试机会的成功率；多测某些 API 会改变其权重。 |
| 宏平均 | 各 API 的 s_i / n_i 等权平均 | 当前目录每项 API 等权的平均表现；n_i 为零时不能静默删掉该项。 |
| 预定加权平均 | 各 API 成功率按预先声明权重合成 | 特定使用分布下的表现；权重来源和版本必须可追溯。 |

每 API 样本数相等时宏、微平均相同；不相等时它们可以支持不同结论。应先决定哪一个承载 90% / 95% 主指标，其他用于诊断，不能看完结果再选最高者。总体达到目标不等于每项 API 均达到目标；若要求逐项推断，还会引出多重比较和更多采样需求。

多 API 的组合任务在“任务成功率”中只算一个任务结果。可为参与的 API 记录覆盖或步骤结果，但不能将一个成功任务复制成多个独立任务成功样本。首次调用的计分单元与任务计分单元应各有明确定义及关系；一次任务内部的纠错、重试和原样补发都不是新的独立任务样本。

## 3. 保留分组结构的统计候选

**来源事实。** Cameron 与 Miller 的研究按“组间独立、组内可相关”处理分组数据；整簇 bootstrap 重采样整个组，以保留组内结构。论文强调簇数少、组不均衡等条件可使常规近似或 bootstrap 推断不可靠，不能仅凭总观察数很大排除问题。[作者稿：A Practitioner’s Guide to Cluster-Robust Inference，II.F、VI](https://faculty.econ.ucdavis.edu/faculty/cameron/research/Cameron_Miller_JHR_2014_July_09.pdf)

**项目推论。** API 是业务覆盖维度，不必然就是独立统计簇。相同来源模板跨多个 API 生成题目时，按 API 分组仍可能遗漏跨 API 相关性。应保留 API、原始意图/模板族、环境实例、会话或批次等关系，并按生成和执行机制判断独立单元，而非仅选择最方便的字段。

可实施的两类候选：

1. **固定当前目录的表现。** 保留全部 API 及固定聚合权重；若每个 API 内有足够独立产生的模板族，可在各 API 内按模板族整体重采样，保留该族改写及重复运行，再重算目标指标。该方案以目录固定、所选族结构合理且跨层关系得到处理为前提；不能直接适用于跨 API 共享模板形成的交叉结构。
2. **把 API 当作来自更广总体的样本。** 只有 API 抽样机制及组间独立性可解释时，才考虑以 API 整簇重采样，并保留其中配对及内部记录。它包含 API 组成变化，不能据此声称是固定完整目录的同一精度分析。

层次或交叉关系复杂、可独立重采样的单元不足时，应报告分组结果及推断限制，补充采样设计或专门分析；不得把普通逐行 bootstrap 自动升级为“已校正相关性”。上述候选尚未针对本项目的生成器、难例分布及高成功率边界做覆盖率仿真；没有已核实的通用最少簇数或每 API 样本常数。

## 4. 候选与基线需要逐例配对

**来源事实。** Westfall 等的原始论文从独立同分布的二元配对向量出发推导 McNemar 检验；检验利用两系统结果不一致的配对数，检验两个边际成功概率是否相同，并讨论多个比较的家族错误率控制。[Multiple McNemar Tests，§2–3](https://pmc.ncbi.nlm.nih.gov/articles/PMC2902578/)

作为实现核对，statsmodels 的官方接口提供精确二项计算和大样本卡方近似两种选项；这只是算法实现证据，不代表选定 Python 依赖或满足本项目分组假设。[statsmodels：mcnemar](https://www.statsmodels.org/stable/generated/statsmodels.stats.contingency_tables.mcnemar.html)

**项目候选。** 在相同用例、初始模拟状态、目录、裁判规则及固定预算下运行基线与候选；隔离或重置可变记忆、业务状态和缓存，保留模型、策略及环境版本。随机性需要记录，并说明采用独立重复还是预先配对的随机种子；不能挑选对候选有利的运行与基线比较。

报告四格计数：共同成功、仅基线成功、仅候选成功、共同失败，以及候选减基线的差值。独立的二值配对可考虑 McNemar；相关的配对仍须按真实簇结构分析。做配对重采样时，同一用例的两个结果必须一起保留，不能分别重采样两列。比较宏平均时也必须每次重算宏平均，不能用微平均检验冒充。

差值、区间与检验回答不同问题：显著改善不代表已达到 90% / 95%；未显著变差也不等于证明等效或非劣。非劣界值、最小收益及显著性门槛属于新的政策决策。若报告多个 API、多个指标或多个候选的统计显著性，应提前界定比较族及校正方案；逐项未校正区间不能包装成全目录同时保证。

## 5. 保留测试集经反复反馈也会被调优

**来源事实。** Dwork 等证明并举例说明：依据同一保留集的反馈不断选择分析或模型，会对保留集本身过拟合。其可复用保留集方法使用受约束的信息发布和明确的数学假设；简单保密题面、只返回总分或采用固定哈希并不自动获得该理论保证。[Generalization in Adaptive Data Analysis and Holdout Reuse，§1、§4–5](https://arxiv.org/abs/1506.02629)

**项目候选。**

- 区分公开开发/回归集与发布候选冻结后才使用的保留评测材料；测试集可在报告后公开，但公开后应视为可学习的回归材料，不继续宣称未接触。
- 按原始来源、模板族及其派生关系划分数据；只拆改写文件名或换随机种子不能阻止同源内容同时进入调优和保留部分。
- 记录候选及版本、提交次数、接触到的总分/分项/失败细节、调优输入和评测集版本。自进化训练、记忆挖掘、检索缓存和 Skill 生成也在这一边界内。
- 一旦结果用于选择或修改候选，将后续比较标明为适应性评测；需要独立确认时按预定规则补充新来源保留材料。只重跑同一批或重算其置信区间不能恢复未使用状态。
- 首版可采用有限候选、预先冻结方案及独立确认，暂不承诺实现可无限复用的私有保留集算法。新材料数量、查询额度、多候选控制方式仍需项目决策。

## 6. 方案层现在可固定什么

研究支持先固定报告与接口必须携带的信息：计分单元、成功/失败/不可评估及原因、固定分母政策、API 与模板分组关系、采样/聚合规则、模型和目录快照、预算、逐例配对、区间方法及适用性、候选筛选与保留集使用历史。

缺失数据、超时、系统故障的处理应预先声明并完整报告；不能在见到失败后以“无效样本”名义静默缩小分母。基础设施事故可另建可追溯重测运行，但不得覆盖原记录。这是防止选择性报告的项目设计建议，不是本文替用户裁定所有故障都必须计作模型错误。

仍待对齐：主指标采用哪种聚合、样本与模板族构成、置信水平是否只作报告或参与发布、候选比较及保留集使用政策。具体样本量应根据所需精度或检验效能、预期差异、分组结构及成本确定；本文没有给出能保证 Harness 通过目标的采样常数。
