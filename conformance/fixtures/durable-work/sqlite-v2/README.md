# Real v2 SQLite input with an unfinished Claim

Generated by the same immutable v2 writer and harness as
[the PostgreSQL fixture](../pg-v2/README.md), using Go1.27.1 and go-sqlite3 1.14.52
(SQLite3.53.4), the exclusive single writer, WAL/FULL, foreign keys on,
busy_timeout100ms and a 3s transaction bound. The clock and r1 Claim/r2 work
scenario are identical. `database.sqlite` is the actual complete file after
closing the writer, including original receipts, Job identity, live Claim,
input bytes and applied migration checksums. Tests copy it to a fresh owned
local file before applying forward migration; they do not alter this source.

The generation source and all fixture artifacts are frozen by SHA256SUMS.
The writer's temporary local files and historical source were under a registered
`/workspace` overlay directory and removed after export. Reproduction uses
`scripts/generate-durable-v2-fixtures.sh NEW_OUTPUT_DIRECTORY` as described in
the PG README. Normal tests read the frozen file and need no historical Git
checkout. This proves the stated file/Claim upgrade behavior, not power loss,
physical termination or production durability.
